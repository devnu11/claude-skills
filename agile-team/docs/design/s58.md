# s58: The Customer Proxy's sandbox can reach the local service it is asked to accept

Story: `.team/stories/s58.md`. Developer: `developer-cli`.

## Why the Proxy gets "connection refused"

`sandbox._sandbox_section` builds Claude Code's `sandbox` settings with
filesystem rules only. With no `network` key, the macOS (Seatbelt) sandbox
lets a sandboxed Bash command connect to nothing on loopback. So the Proxy's
`curl http://127.0.0.1:8799/…` exits 7, although the runner started the
service and probed it (from outside the sandbox) a moment before. The
liaison reproduced it on m53: `"network": {"allowLocalBinding": true}` makes
the same curl get 200; `"network": {"allowedDomains": ["127.0.0.1",
"localhost"]}` does not help.

## Rules

| # | Rule | AC |
|---|---|---|
| N1 | **A delivery that serves locally gets local networking.** The delivery table already says which kinds run a service: `DeliveryKind.start is Start.BACKGROUND` (today only `web`; the `dashboard` delivery is `kind = "web"`). That is the one source; no new field on `DeliveryKind` and no list of kind names. A new table maps the start mode to the `network` section: `NETWORK_BY_START = {Start.BACKGROUND: LOCAL_SERVICE_NETWORK}`, `LOCAL_SERVICE_NETWORK = {"allowLocalBinding": True}`. | AC1 |
| N2 | **Everything else keeps the filesystem-only section.** For a kind whose start is not in `NETWORK_BY_START` (`package`, `script`, `library`, `harness`, `manual`), `_sandbox_section` has no `network` key at all (not an empty dict). Its other keys (`enabled`, `autoAllowBashIfSandboxed`, `allowUnsandboxedCommands`, `filesystem`) are unchanged for every kind. | AC1 |
| N3 | **A fresh copy each time.** `_sandbox_section` puts a new `dict` in `network`, never the module constant itself, so a caller that edits the settings (the e2e test removes the key) cannot change `LOCAL_SERVICE_NETWORK`. | AC1, AC2 |
| N4 | **Only `allowLocalBinding`.** Do not add `allowedDomains`, `allowUnixSockets` or any other network key. They were tried (no effect) or would widen the sandbox. The Playwright MCP server is not affected: it runs outside the Bash sandbox. | AC1 |
| N5 | **Verified end to end on macOS.** An e2e test runs the bundled claude CLI with the real `os_sandbox_settings` and a sandboxed `curl` to a live local service: 200 with the setting, exit 7 without (see "E2E test"). It is skipped on every platform except `darwin`, with the reason in the skip. Linux (bubblewrap) is not verified: its sandbox has its own network namespace, and `allowLocalBinding` is documented for macOS. The docs say so. | AC2 |
| N6 | **Docstring says what is verified.** The `os_sandbox_settings` docstring drops "Not verified end to end in the spike" and says what the e2e test verifies (exact text below). | AC3 |
| N7 | **Service lifecycle (checked, unchanged).** The e2e gate's `Trial.liveness` starts the service, probes it and stops it **by design**: a gate must not leave a process running. The Proxy step does not reuse it. `Runtime.plan()` → `_attach_delivery` → `prepare_fn` starts a fresh one (stale stop, layout, presentation copy, start, probe; s26). From there to the Proxy's curl, nothing stops it: `plan()` stops only when its own set-up raises, `_take_off` only emits the start event and records `in_flight`, and `_execute` stops it in its `finally`, **after** `collect` (the Proxy's whole session) returns or raises. No code change. A unit test pins the order (test checklist). | AC4 |

## Changes per module

### `agile-team/runner/agile_team/sandbox.py`

Constants, next to `MCP_SERVERS` (after `DELIVERY_KINDS`, because `Start` is
defined above it):

```python
LOCAL_SERVICE_NETWORK: dict[str, Any] = {"allowLocalBinding": True}
NETWORK_BY_START: dict[Start, dict[str, Any]] = {Start.BACKGROUND: LOCAL_SERVICE_NETWORK}
```

`_sandbox_section(config: Config, prepared: Prepared) -> dict[str, Any]`:
same four keys as today, merged with `_network(prepared)`:

```python
return {
    "enabled": True,
    ...
    "filesystem": {...},
    **_network(prepared),
}
```

New private helper:

```python
def _network(prepared: Prepared) -> dict[str, Any]:
    """The ``network`` key for a delivery that serves locally; nothing for the rest."""
    network = NETWORK_BY_START.get(prepared.kind.start)
    return {"network": dict(network)} if network else {}
```

`os_sandbox_settings(config, prepared)`: signature and body unchanged. New
docstring (exact):

```python
"""Claude Code settings for the Proxy's OS sandbox.

The sandbox denies reading the repo except the allowed paths and, for a
delivery that serves locally (``NETWORK_BY_START``), allows reaching it on
loopback. ``tests/e2e/test_proxy_sandbox_e2e.py`` runs the bundled claude
CLI with these settings on macOS (Seatbelt): a sandboxed ``curl`` gets 200
from a live local service, and exits 7 when the ``network`` key is removed.
The Linux (bubblewrap) sandbox is not verified end to end.
"""
```

Module docstring: no change needed.

### `agile-team/runner/agile_team/dispatch.py`, `presentation.py`

No change (N7).

## E2E test: `agile-team/runner/tests/e2e/test_proxy_sandbox_e2e.py`

The real CLI runs a sandboxed Bash command only when a model asks it to. To
keep the test free, offline and deterministic, it points the CLI at a
**scripted model**: a stdlib `http.server.ThreadingHTTPServer` on a free
loopback port, started in a thread by a fixture. The CLI process itself is not
sandboxed (only its Bash commands are), so it reaches the scripted model.

- **Platform:** `pytestmark = pytest.mark.skipif(sys.platform != "darwin", reason="allowLocalBinding applies to Claude Code's macOS (Seatbelt) sandbox; the Linux bubblewrap sandbox is not verified (s58)")`. No other skip. A missing bundled CLI is a failure, not a skip.
- **CLI:** `Path(claude_agent_sdk.__file__).parent / "_bundled" / "claude"` (the binary the runner launches).
- **Service:** a second `ThreadingHTTPServer` on a free loopback port answering `GET /` with 200 `ok`, running in the test process (outside the sandbox).
- **Settings:** the real thing. Build a `configured` repo (`tests/conftest.py`) with a `web` delivery whose `url` is the service's `http://127.0.0.1:<port>/`, then `prepared = sandbox.layout(config, delivery)` (no prepare command runs) and `settings = sandbox.os_sandbox_settings(config, prepared)`. The negative case uses `copy.deepcopy(settings)` with `["sandbox"]["network"]` deleted. Write each to a JSON file in `tmp_path`.
- **Command:** `[cli, "-p", "probe the service", "--settings", <file>, "--allowedTools", "Bash", "--output-format", "json", "--max-turns", "3"]`. Run it with `subprocess.run(..., cwd=prepared.workdir, timeout=120, capture_output=True)`.
- **Environment:** `ANTHROPIC_BASE_URL=http://127.0.0.1:<model port>`, `ANTHROPIC_API_KEY=test`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, and `HOME` and `CLAUDE_CONFIG_DIR` both under `tmp_path`. Pitfall: the real home must never be read or written (charter).
- **Scripted model, `POST /v1/messages`:**
  - Request has a `tool_result` block in any message: record its text and reply with a text `done`, `stop_reason: "end_turn"`.
  - Request offers a tool named `Bash` and has no `tool_result`: reply with one `tool_use` for `Bash` with input `{"command": CURL, "description": "probe the service"}`, `stop_reason: "tool_use"`.
  - Any other request (the CLI's side queries carry no `Bash` tool): reply with a text `ok`, `end_turn`.
  - Answer as SSE (`message_start`, `content_block_start`, `content_block_delta` (`text_delta` or `input_json_delta`), `content_block_stop`, `message_delta`, `message_stop`) when the body has `"stream": true`, else as one JSON message. `POST /v1/messages/count_tokens` answers `{"input_tokens": 1}`.
- **`CURL`:** `curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://127.0.0.1:<service port>/; echo " exit=$?"`.
- **Asserts:**
  1. With the settings: the CLI exits 0, the model recorded exactly one tool result, and it contains `200 exit=0`.
  2. Without the `network` key: the recorded tool result contains `exit=7`. This shows the sandbox was active, so test 1 cannot pass by running curl unsandboxed.

If the bundled CLI cannot be driven this way (it refuses the scripted model
or needs a call the list above misses), the tester adds the missing endpoint
to the scripted model. They must not skip the test for that reason. If that
fails, they return `blocked`, naming the call.

## Test checklist

Unit (`agile-team/runner/tests/test_sandbox.py`):

- [ ] `web` delivery (`sandbox.layout(c, Delivery("dash", "web", url="http://127.0.0.1:8799/"))`): `os_sandbox_settings(...)["sandbox"]["network"] == {"allowLocalBinding": True}` (N1, AC2's pinning test).
- [ ] Every kind in `DELIVERY_KINDS` whose `start` is not `BACKGROUND`: `"network" not in settings["sandbox"]` (N2). Parametrise over the table, so a new kind is covered.
- [ ] Filesystem keys are unchanged for `web` (the `denyRead`/`allowRead` assertions of `test_os_sandbox_settings` hold for a `web` delivery too) (N2).
- [ ] Changing the returned `network` dict leaves `sandbox.LOCAL_SERVICE_NETWORK == {"allowLocalBinding": True}` (N3).
- [ ] `os_sandbox_settings.__doc__` does not contain `Not verified` and names `test_proxy_sandbox_e2e` (N6).

Unit (dispatch, existing Proxy plan tests, e.g. where `prepare_fn` is faked):

- [ ] The Proxy step's `Prepared.stop` is not called before the fake `query_fn` starts, and is called once after it returns. Use a fake `Prepared` (or spy) that records the call order (N7).
- [ ] Same when the fake `query_fn` raises: `stop` is called once, after the query began (N7).

E2E (`agile-team/runner/tests/e2e/test_proxy_sandbox_e2e.py`): the two
asserts above. They are skipped off macOS with the stated reason.

Gates: coverage stays at 95%+, `ruff check` and `ruff format` clean.
