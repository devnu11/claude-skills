# s86 Story dependencies as data

Story: `.team/stories/s86.md`. Developer: `developer-cli`. No new runtime
dependency (PyYAML is already one, through `roles.split_frontmatter`).

## Shape in one paragraph

A story's dependencies are a `depends_on` list of story ids. The **story file's
frontmatter** is where they are written down, by the PO. **`state.json`**
(`StoryState.depends_on`) is the runner's validated copy, and the only thing the
router, the priority log and the snapshot read. The copy is loaded from the files
at three points: `agile-team start`, the PO's `start_sprint`, and the PO's
`open_story` (for the new story). Every load is validated as a whole graph:
a list that isn't a list of ids, a self-reference, an unknown id or a cycle
is refused with the stories named, and nothing changes. The router never runs
a step of a story whose dependencies aren't all done. While the sprint is
stuck, the stall line says `waiting on s1`. A reorder is never refused for
dependencies. Every `priority` event records the warnings the move caused, and
the Backlog tab shows each story's dependencies and a warning on any story
ranked above one it depends on.

## Rules

| # | Rule | AC |
|---|---|---|
| DP1 | **Field.** A story file's YAML frontmatter may have `depends_on`, a list of story ids. A missing key means `[]`. `StoryState` gains `depends_on: list[str]` (default `[]`), so an older `state.json` still loads. Duplicates are dropped, keeping the first (`dict.fromkeys`). | AC1 |
| DP2 | **The file wins.** For every story in `state.stories` that is not done and whose file `<stories_dir>/<id>.md` exists, a load sets `depends_on` to the file's list. A story with no file keeps its state list, and a done story is never reloaded. | AC1 |
| DP3 | **Load points.** (1) `cmd_start`, after `make_runtime` and before `_run`, in every start mode. (2) `start_sprint`, after its existing refusals pass and before `_begin_sprint`. (3) `open_story`, for the new story only (DP6). Nothing else reads the files. An edit to a file mid-sprint takes effect at the next start or `start_sprint`. | AC1, AC4 |
| DP4 | **Validation**, in this order; the first refusal wins (`priority.first_refusal`): (a) **shape**: the file's `depends_on` is not a list of strings, or its frontmatter does not parse → `NOT_A_LIST`. (b) **self**: a story lists itself → `SELF`. (c) **unknown**: a listed id is not in `state.stories` → `UNKNOWN`. Done stories are known, and a dependency on a done story is satisfied. (d) **cycle**: the graph has a cycle → `CYCLE`. The graph is every story's state list, with the loaded lists replacing theirs (`merged`). | AC1 |
| DP5 | **Refused means unchanged.** On a refusal no story's list changes and nothing is saved. `cmd_start` raises `CliError(START_REFUSED…)`, so the run does not start. `start_sprint` returns `refused(<text>)`, so the sprint does not begin. On success every loaded list is applied and the state saved. | AC1 |
| DP6 | **`open_story` accepts `depends_on`** (a list; missing or empty means `[]`). The checks, after the duplicate-id and delivery ones: the argument is not a list of strings → `NOT_A_LIST` naming the new id. The story's file exists and its frontmatter is bad → `NOT_A_LIST`. The story's file exists and its list differs from the argument (after dedup, order-sensitive) → `MISMATCH`. Then DP4 (b)–(d) on `{**graph_of(stories), id: given}`, with the new id counted as known. On success the story is opened with `depends_on=given`, and the `story-opened` event's data gains `"depends_on": given`. | AC1, AC4 |
| DP7 | **Cycle text is deterministic.** Walk depth-first from each story id in `priority.natural` order, following each list in its own order and skipping ids that aren't in the graph. Remember fully explored ids. The first time a step reaches an id already on the current path, the cycle is the path from that id onward plus that id again, joined by `" -> "`. Example: `{s1: [s2], s2: [s3], s3: [s1]}` gives `s1 -> s2 -> s3 -> s1`. | AC1 |
| DP8 | **Waiting.** `waiting_on(story, stories)` is the story's listed ids, in list order, whose story is missing or not `DONE`. | AC2 |
| DP9 | **Routing.** `Router._movable` also requires `not dependencies.waiting_on(story, stories)`. This applies to every step of the story, not only its first, so a dependency added later stops a started story too. `_repeat_work`, `_scribe_work` and the boundary are unchanged. The PO's own `run_role` is not checked: the PO may still run a step by hand. | AC2 |
| DP10 | **Skip reason.** `_why` becomes `_why(story, stories)`: a hold first (unchanged: `held (…)`), then `WAITING` when `waiting_on` is non-empty, then the status texts as today. The STALLED hand-over reads e.g. `s2 at design: waiting on s1`. | AC2 |
| DP11 | **Inversion.** In a queue (`Priority.queue`, so done stories are absent), story `A` is **above** a dependency `D` when `D` is in `A.depends_on` and `D` comes after `A` in the queue. `above(story, queue)` lists those `D` in `depends_on` order. It is `[]` when the story is not in the queue. | AC3 |
| DP12 | **Moves are never refused for dependencies.** `Runtime.reorder` adds `"warnings"` to every `priority` event's data (PO tools, `start_sprint` and dashboard requests alike). These are the `WARNING` texts for each inversion in `after` that was not in `before` (`warnings(Moved(before, after), stories)`), in `after` order. `[]` when none. The other data keys are unchanged. | AC3 |
| DP13 | **Snapshot.** Each story dict gains `"depends_on"` (the state list), `"waiting_on"` (DP8) and `"dependency_warnings"`: the `WARNING` text for each `above(story, queue)` id, where `queue` is the one `_position` uses. Done stories get `[]` for the last two. | AC3 |
| DP14 | **Backlog tab.** Every row with a non-empty `depends_on` shows `depends on s1, s2 (done)`. An id that is not in `waiting_on` gets ` (done)`. Each `dependency_warnings` text shows as a warning pill `⚠ <text>`. Both groups (Current sprint and Backlog) show them. A `priority` timeline entry with warnings appends ` · ⚠ <w1>; <w2>` to its meta and takes tone `warning`. | AC3 |
| DP15 | **Migration of the files** (PO's scope, `.team/stories/**`). For each row of table M, set the frontmatter `depends_on` and delete the "Depends on …" sentence from the body. Write the key only when the list is non-empty, as a block list. A still-open dependency's reason from the old sentence becomes a YAML comment on its item (`  - s31  # hooks`). Done dependencies are dropped, reason and all. Other prose stays. | AC4 |
| DP16 | **Migration pin.** An e2e test reads the real `.team/stories/*.md` bodies (after the frontmatter). Every file whose body matches `(?i)\bdepends\s+on\s+s\d+` must be in `HISTORY` (done stories, left as written). Each table M story's `dependencies.declared` list must equal the table. | AC4, AC5 |

### Texts (tests may assert them exactly)

`dependencies.py`:

- `NOT_A_LIST = "depends_on must be a list of story ids: {ids}"`
- `SELF = "a story cannot depend on itself: {ids}"`
- `UNKNOWN = "depends_on names unknown stories: {pairs}; open them with open_story first"`. Each pair is `"{story} on {dep}"`, ordered by story (`natural`), then by list order, and joined by `", "`.
- `CYCLE = "depends_on has a cycle: {cycle}"` (DP7)
- `MISMATCH = "{story}'s file has depends_on [{file}], not [{given}]; pass the same list, or fix the file"` (lists joined by `", "`)
- `WAITING = "waiting on {ids}"`
- `WARNING = "{story} is above {dependency}, which it depends on"`

`{ids}` is always the ids in `natural` order, joined by `", "`, except in `WAITING`, which keeps list order.

`cli.py`: `START_REFUSED = "story files: {refusal}; fix depends_on in {folder}"`, where `{folder}` is `config.STORIES_DIR`.

## Known limits

- An edit to a story file's `depends_on` mid-sprint is not seen until the next start or `start_sprint`. The snapshot shows the state list.
- `start_sprint` does not warn when a listed story depends on one outside the sprint. The sprint then stalls with `waiting on sN`, and the PO is handed that.
- A dependency on a cancelled (held) story waits forever. The PO edits the file.
- `depends_on: null` and a bare `depends_on:` are `NOT_A_LIST`, not `[]` (DP4 a). A story file that is not UTF-8 raises out of `system.read_text` and is not refused. Both are deliberate and documented in protocol.md.
- The s40 `wait` reason (Stories tab) does not include dependencies; `waiting_on` covers the Backlog tab and the stall line. Follow-up for the PO if wanted.
