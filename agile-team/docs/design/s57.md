## AC2: the rules each module is checked against

These rules are now in `guidelines.md` ("Shape of code" and "Names") and the
code reviewer's `## Checklist`:

- SOLID and KISS. DRY, but AHA: don't build an abstraction until the second
  real use shows its shape.
- Functions do one job, in about 8 lines, with at most 2 parameters besides
  `self`. Constructors and factories are exempt.
- No boolean parameters or flags; use an enum.
- No code in the global scope (ADR-0071).
- Tables over branching.
- The repo's `.claude/CLAUDE.md` and the team charter.
- Names (AC6, AC8, AC9): see the next section.

In s57, AC2 is met for the code this story changes. The follow-ups meet it
module by module.

## Naming rules (AC6, AC8, AC9; ADR-0074)

- **Verbs.** A function or method is named with a verb: `get_boundary_fields`,
  `build_tests_passed_event`, `log_turn`, `is_held`. Only an accessor
  `@property` is a noun. A function that only returns a value and has no better
  verb is `get_<noun>`. Classes, enum members, constants and fields stay nouns.
  Dunder methods and `test_*` functions are already fine.
- **Whole words.** No single letters or abbreviations (`b`, `rt`, `e`, `s`,
  `Out`). An acronym is fine when it is better known than its expansion (`PR`,
  `CI`, `SHA`, `MMIO`, `PCI`).
- **No alias-only variables.** `rt = self.runtime` goes; write
  `self.runtime.x`. A local that only renames something is kept only when it
  makes the code much easier to read (for example, a value narrowed from
  `Optional` and used many times), and then it has a whole-word name.
- These are a judgement call for the reviewer, not an AST check.
