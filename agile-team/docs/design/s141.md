# s141: The PO can bring one commit from main into the running sprint (cherry-pick)

Story: `.team/stories/s141.md`. ADR: ADR-0072
(`.team/adr/0072-main-picks-mid-sprint.md`); ADR-0041 amended.
Requirements: REQ-051 (AC1, AC5), REQ-052 (AC2, AC5), REQ-053 (AC3, AC5),
REQ-054 (AC4, AC5), REQ-055 (AC6).
Developer: `developer-cli`.

## Why

Mid-sprint the team branch never takes anything from main (s108: the START
sync changes nothing; main comes in only at the sprint-end rebase). A fix that
lands on main mid-sprint (a test fix, a charter rule) then waits a whole
sprint. A **pick** brings exactly one main commit onto the team branch as a
`git cherry-pick -x` commit, between steps, with no merge and no hash rewrite.
The sprint-end rebase drops it again because main already has its patch.

## Rules

- **K1 Two ways to ask, one queue.** `agile-team pick <commit> --reason
  "<text>"` (the human or the liaison) and the PO tool
  `pick_from_main(commit, reason)` both run the K3 checks at once and, when
  they pass, queue one file `.team/run/picks/p<N>.json` through
  `numbered_queue.NumberedQueue(folder, "p", ".json")`. Neither touches the
  working tree, the index or any branch: only `git fetch` and read-only git.
  The queued commit is the **full resolved sha**, never the ref the asker
  typed. The PO can't veto, reorder or cancel a queued pick: no tool reads or
  changes the queue. The CLI works in any run state; a stopped or halted run
  applies the pick at its next `start`.
- **K2 Request file.** `{"commit": "<40 or 64 lowercase hex>", "reason":
  "<text>", "origin": "liaison" | "product-owner", "at": <float>}`. All four
  fields are required (`request_files.Fields`: `STRING`, `STRING`, `STRING`,
  `NUMBER`). A file that fails to read or parse, an `origin` that is not an
  `Origin` value, or a `commit` that is not full hex is a
  `request_files.BadRequest` and is settled as `refused` (K5) with its reason.
- **K3 Checks, in order; the first refusal wins and nothing is queued or
  changed.** They run at the ask (CLI, PO tool) and again when the runner
  applies the pick (K4), with a fresh fetch each time:
  1. blank reason (after `strip`): `REFUSALS[Refused.NO_REASON]`;
  2. no upstream: `Upstream.missing()` (it fetches `<remote>`; `SYNC_OFF`,
     `NO_REMOTE`, `FETCH_FAILED`, `NO_TARGET`) → `NO_UPSTREAM` with that text;
  3. not a commit: the value is empty, starts with `-` or holds whitespace,
     or `git rev-parse --verify --quiet <commit>^{commit}` fails → `UNKNOWN`.
     Otherwise its output is the full sha used from here on;
  4. not on main: `git merge-base --is-ancestor <sha> <remote>/<branch>`
     exits non-zero → `NOT_ON_TARGET`;
  5. parents (`git rev-list --parents -n 1 <sha>`, words after the first):
     two or more → `MERGE`; none → `ROOT`;
  6. already on the team branch: `Git.is_ancestor(sha)` (an ancestor of HEAD)
     → `ON_BRANCH`; else `git cherry HEAD <sha> <sha>^` printing a line that
     starts with `- ` (an equal patch is on the team branch) → `SAME_PATCH`.
- **K4 Apply at the next safe point.** Each router tick, after the story
  intake (s135) and before anything is delivered to the PO, `Picker.apply`
  settles every pending pick (an id not in `state.picks`) in number order.
  Picks wait while a sprint boundary is open (`state.boundary is not None`,
  every hold included). Between steps no role is running and the checkout
  guard has just passed, so no step's diff, gate or commit range sees the
  pick as its own. Settling one pick:
  1. a `BadRequest` → `refused` with its reason;
  2. the K3 checks again → `refused` with the refusal;
  3. a dirty tree (`Git.changed_paths()` not empty) → `failed` with
     `DIRTY`, nothing run;
  4. `before = git.head()`, then `git.attempt(*PICK_ARGV, sha)`:
     - exit 0 → `applied`: the new HEAD is the pick, one commit on top of
       `before` (no existing hash changes). `Runtime.record_checkout()` runs
       before the state is saved;
     - non-zero with conflicted files (`git diff --name-only
       --diff-filter=U`) → `git cherry-pick --abort`, then `conflict` with
       the files;
     - non-zero, `CHERRY_PICK_HEAD` present and nothing staged (`git diff
       --cached --quiet` exits 0) → `git cherry-pick --abort`, then
       `refused` with `SAME_PATCH` (the patch came out empty);
     - any other non-zero → `git cherry-pick --abort` (its own failure is
       ignored), then `failed` with git's output, stripped;
     - after every non-applied outcome, if `git.head() != before` the runner
       runs `git reset --hard <before>`. The branch is always left where it
       was;
  5. record `state.picks[p<N>]` (K6) and save, emit one `main-pick` event
     (K7), post one liaison note (K8) and add one hand-over line (K9).
- **K5 Outcomes.** `Outcome(StrEnum)`: `APPLIED = "applied"`, `REFUSED =
  "refused"`, `CONFLICT = "conflict"`, `FAILED = "failed"`.
- **K6 State.** `RunState.picks: dict[str, str]`, request id →
  `applied <new sha12>`, `refused: <why>`, `conflict: <file>, <file>` or
  `failed: <why>`. An old `state.json` without the key loads `{}`. The
  picked sha is **not** a remapped field (`rewrite.REMAPPED` is unchanged): the
  record is a log, and the sprint-end rebase drops the commit (K10).
- **K7 Event.** `EventKind.MAIN_PICK = "main-pick"`, role = the pick's
  `origin` value (`liaison` or `product-owner`), story `None`, data
  `{request, origin, commit, reason, outcome, sha, files, why}`. `commit` is
  the queued sha; `sha` is the new commit's full sha on `applied`, else
  `null`; `files` lists the conflicted files (else `[]`); `why` is the
  refusal or failure text (else `""`).
- **K8 The liaison is told** every outcome through
  `runtime.relay.post(Note("update", text, []))` with `POSTED[outcome]`.
- **K9 The PO is told after, never asked first.** When at least one pick
  settled in a tick, `Picker.apply` returns `Pass([Trigger.MAIN_PICK],
  lines, [])`, one `HANDED[outcome]` line per pick, and the router returns it
  as the tick's hand-over (after clearing a waiting reason, as `_deliver`
  does). A CLI pick is therefore applied with no PO turn before it. The PO's
  own picks get the same hand-over. `MAIN_PICK` is not in `QUIET_AFTER_PO`.
- **K10 The sprint end drops the pick (AC3).** No code change is expected:
  the END rebase (`REBASE_ARGV`: git drops a commit whose patch is upstream,
  and `--empty=drop` drops one that comes out empty) and the review build
  (`Rebuilder.unmerged`: `--cherry-pick --right-only`; an empty cherry-pick is
  skipped) already leave it out. `rewrite.pair` maps the dropped pick to the
  last kept copy before it. The K10 tests pin all of this. If one fails, fix
  `upstream.py` or `stack.py`, not the test.
- **K11 Commit message.** The pick keeps main's author and message, plus the
  `(cherry picked from commit <sha>)` line from `-x`. It carries **no**
  `CO_AUTHOR` trailer: it is main's commit, not Claude's (ADR-0072).
  `git_ops`' module docstring says so. Hooks are off for it, as `--no-verify`
  is for every runner commit.
- **K12 Mid-sprint, main reaches the team only by picks.** The START sync
  still changes nothing (s108). Nothing else merges or rebases main into the
  team branch between boundaries.

## Texts (`agile_team/main_picks.py`; tests may assert them exactly)

`{short}` = sha[:12], `{target}` = `<remote>/<branch>`, `{subject}` =
`Git.subject(sha)`, `{files}` joined with `", "`.

```python
class Refused(StrEnum):
    NO_REASON = "no_reason"; NO_UPSTREAM = "no_upstream"; UNKNOWN = "unknown"
    NOT_ON_TARGET = "not_on_target"; MERGE = "merge"; ROOT = "root"
    ON_BRANCH = "on_branch"; SAME_PATCH = "same_patch"

REFUSALS: dict[Refused, str] = {
    Refused.NO_REASON: "a reason is required: say why the team needs this commit now",
    Refused.NO_UPSTREAM: "cannot pick from main: {why}",
    Refused.UNKNOWN: "'{commit}' is not a commit here (after fetching {remote})",
    Refused.NOT_ON_TARGET: "{short} is not on {target}; only a commit on {target} can be picked",
    Refused.MERGE: "{short} is a merge commit; pick the commits it brought in, one at a time",
    Refused.ROOT: "{short} has no parent; it can't be picked",
    Refused.ON_BRANCH: "{short} is already on the team branch",
    Refused.SAME_PATCH: "{short}'s change is already on the team branch",
}
DIRTY = "the working tree has changes ({paths}); nothing was picked"
QUEUED = 'queued {id}: {short} "{subject}" from {target}; the runner picks it at the next safe point and tells the PO'
TOOL_NEXT = "The runner applies it at the next safe point between steps and hands it to you as main-pick."
HANDED: dict[Outcome, str] = {
    Outcome.APPLIED: 'main-pick {id} ({origin}): picked {short} "{subject}" from {target} as {new}: {reason}. Plan around it; nothing to approve',
    Outcome.REFUSED: "main-pick {id} ({origin}): not picked: {why}",
    Outcome.CONFLICT: 'main-pick {id} ({origin}): {short} "{subject}" conflicts with the team branch in {files}; nothing changed. It reaches the team at the sprint-end rebase',
    Outcome.FAILED: "main-pick {id} ({origin}): {short} not picked: {why}; nothing changed",
}
POSTED: dict[Outcome, str] = {
    Outcome.APPLIED: 'Picked {id}: {short} "{subject}" is on the team branch as {new}; the PO was told.',
    Outcome.REFUSED: "Pick {id} refused: {why}",
    Outcome.CONFLICT: 'Pick {id} ({short} "{subject}") conflicts with the team branch in {files}; nothing changed. It reaches the team at the sprint-end rebase.',
    Outcome.FAILED: "Pick {id} ({short}) failed: {why}; nothing changed.",
}
```

On a `refused` whose commit never resolved (a `BadRequest`, `UNKNOWN`), the
`{short}` and `{subject}` fields are not used by those texts.

## Changes per module

### `agile_team/main_picks.py` (new; the request, the checks, the texts)

```python
PICK_ARGV = ("-c", "core.hooksPath=/dev/null", "-c", "core.editor=true", "cherry-pick", "-x")
FULL_SHA = re.compile(r"^[0-9a-f]{40}([0-9a-f]{24})?$")
SHORT = 12

class Origin(StrEnum):
    LIAISON = "liaison"
    PO = "product-owner"

class Outcome(StrEnum): ...            # K5

@dataclass(frozen=True)
class Pick:
    """A queued pick; ``id`` is empty until queued."""
    id: str
    commit: str
    reason: str
    origin: Origin
    at: float = 0.0
    def to_json(self) -> str: ...      # K2 keys
    @classmethod
    def from_json(cls, rid: str, text: str) -> Pick | BadRequest: ...  # K2

@dataclass(frozen=True)
class Ask:
    """What an asker typed: a commit (sha or ref) and the reason."""
    commit: str
    reason: str

@dataclass(frozen=True)
class Verdict:
    """The resolved full sha (empty until resolved) and the refusal (empty: go ahead)."""
    sha: str = ""
    refusal: str = ""

@dataclass
class PickCheck:
    """K3 over one ``Upstream`` (its ``git`` is the team checkout)."""
    upstream: Upstream
    def verdict(self, ask: Ask) -> Verdict: ...
```

`verdict` walks K3 as a table of one-job private steps, each taking the
`Verdict` so far and returning a refusal text or `None`
(`_reason`, `_upstream`, `_resolve`, `_on_target`, `_parents`,
`_on_branch`). Each step is under 8 lines; the `{remote}` and `{target}`
fields come from `upstream.settings.remote` and `upstream.target`.

### `agile_team/picking.py` (new; the queue and the applier)

```python
PICKS_DIR = "picks"                    # under config.run_dir
REQUEST_PREFIX, REQUEST_SUFFIX = "p", ".json"

@dataclass(frozen=True)
class Picks:
    """The pick request files under the run directory."""
    run_dir: Path
    @property
    def folder(self) -> Path: ...                        # run_dir / "picks"
    def queue(self, pick: Pick) -> Pick: ...             # K1: at = system.now(), publish, id set
    def all(self) -> list[Pick | BadRequest]: ...        # number order; unreadable → bad_request
    def pending(self, settled: Mapping[str, str]) -> list[Pick | BadRequest]: ...

@dataclass(frozen=True)
class Settled:
    """How one pick ended."""
    outcome: Outcome
    sha: str = ""                     # the new commit on APPLIED
    files: tuple[str, ...] = ()       # CONFLICT
    why: str = ""                     # REFUSED, FAILED
    def state_text(self) -> str: ...  # K6

@dataclass
class Picker:
    """Applies pending picks between steps (K4) and builds the PO's hand-over (K9)."""
    runtime: Runtime                  # TYPE_CHECKING import from .dispatch
    def apply(self) -> Pass | None: ...
```

Mirror `sharing.Shares` for `Picks` and `sharing.Sharer` for the applier.
Private helpers, one job each: `_settle(pick) -> Settled`,
`_cherry_pick(sha) -> Settled` (K4.4), `_undo(before)`,
`_record(pick, settled) -> str` (state, save, event, liaison note; returns
the hand-over line), `_fields(pick, settled) -> dict[str, str]` (the text
fields). `subject` is read with `Git.subject` only for a resolved sha; use
`""` when it fails (`GitError`).

### `agile_team/handover.py`

- `Trigger.MAIN_PICK = "main_pick"`. No `HANDOVERS` row: the Pass carries its
  own lines.

### `agile_team/router.py`

- `Router.picker: Picker = field(init=False)`, set in `__post_init__`.
- `_tick`: move the six appliers into `_apply_queues(self) -> Pass | None`
  (desk, sharer, intake, **picker**, clerk, reverter, in that order; it
  returns the picker's Pass). `_tick` then starts
  `if picked := self._apply_queues(): self._end_wait(); return picked`,
  right after the `checkout_moved` check. Everything after is unchanged.

### `agile_team/po_tools.py`

- `Tools.pick_from_main(args) -> dict`: `PickCheck(runtime.upstream).verdict(Ask(commit, reason))`
  with `commit`/`reason` read as strings (`""` when missing or not a string).
  A refusal → `text_result(refused(text))`. Otherwise queue
  `Pick("", verdict.sha, reason.strip(), Origin.PO)` with
  `Picks(config.run_dir).queue` and return
  `text_result({"status": "queued", "pick": id, "commit": sha[:12], "subject": subject, "next": TOOL_NEXT})`.
  It emits no event (the `main-pick` event comes when the pick settles).
- `SCHEMAS["pick_from_main"]`, placed after `request_story`:
  ```python
  "pick_from_main": (
      "Bring one commit that is already on main (<remote>/<branch>) onto the team branch now, "
  ```

### `agile_team/cli.py`

```python
def cmd_pick(args: argparse.Namespace) -> int:
    """Queue one commit from main for the team branch (s141); the runner picks it between steps."""
Command("pick", "bring one commit from main onto the team branch (cherry-pick, between steps)",
        cmd_pick,
        ((("commit",), {"help": "a commit on <remote>/<branch> (sha or ref)"}),
         (("--reason",), {"required": True, "help": "why the team needs it now"})))
```
The row goes right after `share`. `cmd_pick` builds `Git(config.repo)` and
`Upstream(git, config.upstream)`, runs `PickCheck.verdict`, raises
`CliError(refusal)` on a refusal (exit 1, nothing queued), else queues
`Pick("", sha, reason.strip(), Origin.LIAISON)` and prints `QUEUED`.

`status_report` gains `"queued_picks": [p.id for p in Picks(run_dir).pending(st.picks)]`
and `"picks": st.picks`.

## Test checklist (AC5)

Unit (FakeSystem; a stub `Git`/`Upstream` returning scripted git results):
- [ ] `Pick.to_json`/`from_json` round trip; a bad `origin`, a short or
      upper-case `commit`, a missing field and bad JSON each give a
      `BadRequest`.
- [ ] `PickCheck.verdict`, one test per refusal, in K3 order with the exact
      `REFUSALS` text: blank reason (no git call at all), sync off / fetch
      failed, unknown commit (and `-x` without any git call), not on the
      target, merge commit, root commit, ancestor of HEAD, same patch
      (`git cherry` `- `). A good pick returns the full sha and no refusal.
- [ ] `cmd_pick`: prints `QUEUED` and writes `p1.json` with the full sha and
      `origin: liaison`; each refusal exits 1 and writes nothing.
- [ ] `Tools.pick_from_main`: queues with `origin: product-owner` and returns
      `queued`; a refusal returns `refused` and queues nothing.
- [ ] `Picker.apply`: does nothing while `state.boundary` is set; settles in
      number order; a `BadRequest` is `refused`; a second pick of the same
      commit is refused at apply (`ON_BRANCH`); a dirty tree is `failed`
      with `DIRTY` and runs no cherry-pick.
- [ ] `status` shows `queued_picks` and `picks`.
- [ ] `SCHEMAS["pick_from_main"]` takes `{commit, reason}`, and
      `roles/product-owner.md` names `pick_from_main` and says picks are
      never for whole sprints of work (AC4).
- [ ] `Trigger.MAIN_PICK` is not in `QUIET_AFTER_PO`, and `handover.prompt`
      lists each picked line.

E2E (real git, `tests/e2e/`, `set_git_identity`, a bare remote for main):
- [ ] **A pick at a safe point**: main gets commit C; queue it with
      `agile-team pick C --reason …`; one `Picker.apply` on a runtime over the
      team repo. `git rev-list --count` grew by one, `HEAD^` is the old head,
      the new commit's message ends with `(cherry picked from commit C)`, every
      older hash is unchanged, `state.picks["p1"] == "applied <sha12>"`, and
      `record_checkout` saw the new HEAD.
- [ ] **Each refusal** with real git: a sha not on `origin/main`, a merge
      commit, a commit already on the team branch (ancestor), a commit whose
      patch was picked before; each leaves HEAD and `git status` unchanged.
- [ ] **A conflict**: the team changed the same line as C. The outcome is
      `conflict` with the file listed, HEAD equals the old head, `git status`
      is clean, no `CHERRY_PICK_HEAD`, and the hand-over and the liaison
      note name the file.
- [ ] **The event**: one `main-pick` event with `commit`, `reason`, `sha`
      (the new sha), `outcome: applied`, role `liaison`.
- [ ] **The rebase drops the pick (AC3)**: team commits T1, pick of C, T2;
      main moves on with D. `Upstream.rebase_onto(old)` gives `rebased`;
      `<target>..HEAD` holds T1' and T2' only (no commit naming C);
      `moved[pick] == moved[T1]`. The same with T1 editing a line next to C's
      change (so the patch-ids differ, and `--empty=drop` drops it).
- [ ] **The review branch carries it once**: `Rebuilder.unmerged` over that
      team branch leaves the pick out, and `build` of the sprint's entry gives
      a branch whose `<target>..branch` holds the team commits only.
- [ ] **A CLI pick with no PO turn (AC4)**: queue a pick with
      `agile-team pick`, then run one `Router.advance()` alone (no PO query
      runs inside a router pass). When it returns, the pick is on the branch,
      and the Pass's `kinds` are `[Trigger.MAIN_PICK]` with the applied
      line. The PO is only told afterwards, through that Pass.
