# s138: Runner hold and refusal texts stop telling roles to edit story files

Text-only story. No new module, no state, event or snapshot change, no ADR (it
applies s135's rule "only the runner writes story files" to three texts that
predate it). Requirements: REQ-104 (AC1, AC3), REQ-105 (AC2, AC3), REQ-106 (AC4).

Developer: `developer-cli`.

## Rules

- **R1 A role-facing text names the action the role may take.** A hold or
  refusal that reaches a role (the PO through a `gate_hold` hand-over) never
  says to edit, or fix, a story file. It says only the runner writes story
  files and names the tool or person that acts: `continue_story`, `ask_user`,
  devops, the liaison's `story amend`. The words match
  `roles/product-owner.md` lines 57–63 and protocol.md "Only the runner
  writes story files".
- **R2 The start refusal names who changes `depends_on`.** No command changes
  `depends_on`: `story amend` refuses a changed list (`story_drafts.DEPENDS_DIFFERS`,
  s135), and the docs (protocol.md, "Load points") give the fix to the human.
  `START_REFUSED` reaches whoever ran `agile-team start` (the human, the
  liaison, or an unattended job), never a role. So it says that `story amend`
  can't change the list and gives the human's steps and commands: edit the
  file, `git commit`, `agile-team accept-checkout` if needed, `agile-team start`.
  **Ruling on AC2's wording:** "names the command that changes depends_on" is
  met by naming those commands. Adding a runner command that rewrites
  `depends_on` would be new behaviour, and the story's notes say to reword only
  (see open question in the handoff).
- **R3 Siblings.** `suite_runs.BAD_SUITE_RUNS` also reaches the PO as a gate
  hold (`gates.py:783`) and says "fix the story file's frontmatter", so it
  changes too. Out of scope, because they reach the human or liaison and not a role:
  `shares.REFUSALS[Refused.STORY_FILE]` (the `share` command) and
  `story_drafts.CANNOT_REWRITE` (the liaison's `story amend` intake).
- **R4** Placeholders stay the same, so no caller changes: `STORY_FILE_HOLD`
  keeps `{refusal}`; `START_REFUSED` keeps `{refusal}` and `{folder}`
  (`cli.py:461` is unchanged); `BAD_SUITE_RUNS` keeps `{story}`, `{most}`, `{value!r}`.

## Changes per module

### `agile_team/story_spec.py` (AC1)

```python
STORY_FILE_HOLD = (
    "the story file must be fixed before acceptance:\n{refusal}\n"
    "Only the runner writes story files. If the config lost the environment, route the "
    "fix to devops and continue_story once it is in; if the ACs are wrong, ask the human "
    "with ask_user, and the liaison sends new ACs with story amend"
)
```

The callers (`gates.py:505`, `:965`, `:1052`) are unchanged.

### `agile_team/cli.py` (AC2)

```python
START_REFUSED = (
    "story files: {refusal}; story amend cannot change depends_on, so the human fixes it: "
    "edit depends_on in the story's file in {folder}, git commit it, then agile-team start "
    "again (agile-team accept-checkout first if start halts on the moved checkout)"
)
```

### `agile_team/suite_runs.py` (R3)

```python
BAD_SUITE_RUNS = (
    "story {story}'s suite_runs must be a whole number from 1 to {most}, not {value!r}; "
    "only the runner writes story files: ask the human with ask_user for a valid suite_runs"
)
```

### Docs (done in this design step)

- `reference/protocol.md`: the Proxy-step row and the "Fixing an environment"
  paragraph give the new hold text. The "Load points" row and the paragraph
  after the draft checks give the new start refusal.
- `docs/customer/review-stack.md` (AC4): "the team opens a bug story" now
  says the PO asks the liaison for a bug story, the liaison writes it, and the
  runner opens it first in the next sprint (s136 R4: `--sprint next`).

## Design review (round 1)

The three constants match this design word for word, with their placeholders
(R4), so the code and the design agree. Notes from the code review:

- F1: a test parametrized over the texts should give short ids
  (`ids=["hold", "suite_runs"]`) so a rewording doesn't change them. This is
  a suggestion, not a rule of this story.
- F2: `story amend` doesn't change `suite_runs` either, so the human edits
  the file, as with `depends_on`. R3 accepts `ask_user` as the PO's action.
  A hold text that says so would be a follow-up story.
- F3: review-stack.md's AC4 paragraph is reflowed (done at design review).
- F4: the E2E items above belong to the e2e step.
