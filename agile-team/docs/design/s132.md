# s132: fullcheck._result takes the test run, not loose values

Story: `.team/stories/s132.md`. Requirements: REQ-032 (AC1, AC2). ADR: none
(a refactor inside one module; no new boundary, format or dependency).
Developer: `developer-cli`.

## Problem

`fullcheck._result(check, ran, judging, pending="")` takes four parameters,
breaking the house rule (at most two). Its two callers in `_run_one` take
apart a `test_reports.TestRun` (or a bare `(code, output)` pair) into `ran`
and `pending`. The judges it calls, `_exit_why` and `_coverage_why`, take
three parameters `(code, output, judging)` for the same reason.

## Rules

| # | Rule | AC |
|---|---|---|
| R1 | Judging a run is a method of `Judging`: `Judging.result(check, run)`. It takes the `FullCheck` and the `test_reports.TestRun`, and nothing else. The module-level `_result` is removed. | AC1 |
| R2 | Every check yields a `TestRun`. A check with `built is None` runs its command through `judging.run` and wraps the result as `TestRun(code, out, None, {})`. A built check uses `test_reports.run(check.built, judging.run)` as today. | AC1 |
| R3 | The judges take the run and the judging: `_exit_why(run, judging)` and `_coverage_why(run, judging)`. `JUDGES` is typed `dict[Judge, Callable[[test_reports.TestRun, Judging], str]]`. | AC1 |
| R4 | Behaviour is unchanged. `why` is `TIMED_OUT_WHY` when `run.code == TIMED_OUT`, else the judge's text. `tail` is `gates.tail(run.out)`. `pending` is `pending_tests.counts_text(run.skipped, run.report or junit.Report())`. For a plain run that is `counts_text({}, junit.Report())`, which is `""`, the old default. | AC2 |
| R5 | No existing test changes. `TIMED_OUT_WHY`, `FullCheck`, `Judging(run, required)`, `CheckResult`, `CheckReport`, `full_checks` and `run_checks` keep their names, fields and signatures. | AC2 |

## Changes: `agile-team/runner/agile_team/fullcheck.py`

The imports stay as they are (`test_reports`, `junit`, `pending_tests`,
`gates`, `TIMED_OUT`, `CommandRunner` are already imported).

### `Judging` gains one method

```python
@dataclass(frozen=True)
class Judging:
    """The runner bound to the tree being checked, and the coverage required."""

    run: CommandRunner
    required: float

    def result(self, check: FullCheck, run: test_reports.TestRun) -> CheckResult:
        """The check's outcome from its run: why it failed, its tail and pending counts."""
        timed_out = run.code == TIMED_OUT
        why = TIMED_OUT_WHY if timed_out else JUDGES[check.judge](run, self)
        pending = pending_tests.counts_text(run.skipped, run.report or junit.Report())
        return CheckResult(check, run.code, why, gates.tail(run.out), pending)
```

`CheckResult` and `JUDGES` are defined later in the module. That is fine:
the method uses them only when it is called, and `from __future__ import
annotations` covers the annotation.

### Running a check

Replace `_run_one` and delete `_result`:

```python
def _plain_run(command: str, runner: CommandRunner) -> test_reports.TestRun:
    code, out = runner(command)
    return test_reports.TestRun(code, out, None, {})


def _test_run(check: FullCheck, judging: Judging) -> test_reports.TestRun:
    if check.built is None:
        return _plain_run(check.command, judging.run)
    return test_reports.run(check.built, judging.run)


def _run_one(check: FullCheck, judging: Judging) -> CheckResult:
    return judging.result(check, _test_run(check, judging))
```

`run_checks` is unchanged.
