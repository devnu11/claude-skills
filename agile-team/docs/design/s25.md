# s25: Ledger each PO query's own cost

Developer: **developer-cli**. The change is in runner Python: `ledger.py`,
`state.py` and `po_tools.py`. In this design step the Architect has already
updated `reference/protocol.md` (ledger), `docs/customer/dashboard.md` and the
index in `architecture.md`. `SKILL.md` and the README row do not describe
cost accounting, so they do not change.

Story: `.team/stories/s25.md`. Evidence, finding and the one-off correction:
[`../adr/ADR-004-po-cost-deltas.md`](../adr/ADR-004-po-cost-deltas.md).

## The problem in one line

`ResultMessage.total_cost_usd` is a running total for the **session**
(ADR-004). The PO resumes one session query after query, and
`PoRun._record` ledgers that running total every time. So each PO entry
also counts all the PO's earlier queries in that session.

## Rules

| # | Rule | AC |
|---|---|---|
| C1 | **Own cost.** For a PO query, `own = reported − base` when `reported ≥ base`, and `own = reported` otherwise. `reported` is the query's raw `total_cost_usd`, before `Providers.cost_of`. `base` is the running total last seen for the session that the query resumes. It is `0.0` when the query resumes nothing, or resumes a session other than the one stored. | AC2 |
| C2 | **Baseline in state.** `RunState.po_cost: SessionCost \| None = None` holds `(session, reported)` from the last PO query that returned a result. It is saved in `state.json` with the ledger entry, so a new process (`start --resume`) keeps the baseline. | AC2 |
| C3 | **Order in a PO turn.** Collect the query, take the own cost (C1), update `po_cost`, then apply `runtime.priced`, then settle, then record. The provider rule applies to the own cost. `po_cost.reported` always stores the **raw** figure, so a PO on a `billing = "free"` provider still has the right baseline if it moves back to Anthropic. | AC2 |
| C4 | **No result, no change.** When a query yields no `ResultMessage` (`StepResult.session_id is None`, cost `0.0`), the turn's cost stays `0.0` and `po_cost` is left as it was. | AC2 |
| C5 | **Persisted together.** Nothing saves state between taking the own cost and `_record`. `_record` writes the ledger entry and then saves `state.json`, as it does today. If the turn crashes in between (for example in `settle_po`), neither is written. The next query's delta then covers the lost query. | AC2 |
| C6 | **Legacy seed.** If `po_cost` is `None` (a `state.json` from before s25) when a PO query returns, the baseline is `SessionCost(state.po_session, ledger.last_cost(PO))`. Before s25, each PO ledger entry held the running total, so the last one is the baseline for the session being resumed. On a fresh state, `po_session` is `None`, so C1 gives `base = 0.0`. | AC2, AC3 |
| C7 | **Role steps unchanged.** Only `po_plan` sets `Launch.resume`. Every role step runs in a fresh session, so its `total_cost_usd` is already its own cost. `Runtime.record_cost` does not change. A test pins `plan.options.resume is None` for a role step. | AC2 |
| C8 | **Readers unchanged.** `budget_status`, `spend_by_role`, `long_running_roles`, the budget checkpoint in `record_cost`, `cli.status_report` and the dashboard snapshot all read `ledger.jsonl`. With C1 they show real spend, and none of them changes. The ledger line format does not change (no new field), so `dashboard/fixtures/snapshot.json` does not change. | AC2 |
| C9 | **No rewrite.** Nothing rewrites existing ledger lines. ADR-004's correction note gives the overcount in entries written before s25. | AC3 |

### Worked examples (C1)

| Stored `po_cost` | Query resumes | Reported | Ledgered (Anthropic) | New `po_cost` |
|---|---|---|---|---|
| `None`, fresh state | `None` (kickoff) | 1.00 | 1.00 | `("s", 1.00)` |
| `("s", 1.00)` | `"s"` | 1.50 | 0.50 | `("s", 1.50)` |
| `("s", 1.50)` | `"s"` | 1.50 | 0.00 | `("s", 1.50)` |
| `("s", 1.50)` | `None` (fresh session after a handoff renewal) | 0.30, session `"t"` | 0.30 | `("t", 0.30)` |
| `("s", 5.00)` | `"s"` | 0.20 (counter restarted) | 0.20 | `("s", 0.20)` |
| `("s", 2.00)` | `"u"` (saved by a `ResultError`, never ledgered) | 0.90, session `"u"` | 0.90 | `("u", 0.90)` |
| `None`, `po_session = "s"`, last PO ledger entry 7.00 | `"s"` | 7.40 | 0.40 (C6) | `("s", 7.40)` |
| any | any | no `ResultMessage` | 0.00 | unchanged (C4) |

The `"u"` row shows why the stored session matters. The query that hit
the error is in `"u"`'s running total. It was never ledgered, so ledgering
the full 0.90 pays for it.

## Changes by module

Every function stays under 8 lines, with at most 2 parameters (besides
`self`) and no flags.

### `ledger.py`

```python
@dataclass
class SessionCost:
    """The running ``total_cost_usd`` Claude Code last reported for one session."""

    session: str | None = None
    reported: float = 0.0

    def own_cost(self, resumed: str | None, reported: float) -> float:
        """The part of ``reported`` that one query spent (C1).

        ``resumed`` is the session the query resumed (``None`` for a fresh one).
        A fall below the stored figure means the counter restarted.
        """
        base = self.reported if resumed is not None and resumed == self.session else 0.0
        return reported - base if reported >= base else reported
```

`Ledger.last_cost(self, role: str) -> float` (new): the `cost_usd` of the
last entry whose `role` is `role`, or `0.0` when there is none. Docstring:
"The most recent cost ledgered for ``role``; 0.0 if it has none."

Module docstring: add one sentence saying that a resumed PO query records
only its own share of the session's running total (`SessionCost`, ADR-004).

### `state.py`

- `RunState.po_cost: SessionCost | None = None`, added as the **last** field.
- `from_json`: `data["po_cost"] = _nested(SessionCost, data.get("po_cost"))`.
  `_nested` already returns `None` for a missing key. Older files load with
  `None`.
- Import `SessionCost` from `.ledger`. `ledger` imports nothing from the
  package, so this creates no import cycle.

### `po_tools.py` (`PoRun`)

`_turn` becomes:

```python
async def _turn(self, turn: PoTurn) -> StepResult:
    plan = po_plan(self.runtime, turn)
    raw = await self._collect(plan)
    result = self.runtime.priced(plan, self._own_cost(turn, raw))
    self._settle()
    self._record(plan.role.model, result)
    return result
```

New methods:

| Method | Spec |
|---|---|
| `_own_cost(self, turn: PoTurn, raw: StepResult) -> StepResult` | Docstring: "``raw`` with only this query's cost; remembers the session's running total." If `raw.session_id is None`, return `raw` (C4). Otherwise `known = state.po_cost or self._seed_cost()`, `own = known.own_cost(turn.resume, raw.cost)`, `state.po_cost = SessionCost(raw.session_id, raw.cost)`, and return `replace(raw, cost=own)`. Do not save here (C5). |
| `_seed_cost(self) -> SessionCost` | Docstring: "The baseline for a state.json written before s25 (C6)." Returns `SessionCost(state.po_session, self.runtime.ledger.last_cost(PO))`. |

`_record`, `_collect` and `_settle` do not change. `replace` comes from
`dataclasses`. Import `SessionCost` from `.ledger`.

### Not changed

`dispatch.py` (`collect`, `_Drain`, `priced`, `record_cost`),
`providers.py`, `insights.py`, `cli.py`, `dashboard/*` and the snapshot
fixture all stay as they are (C7, C8).

## Test checklist (for the Unit Tester)

`conftest.FakeQuery` returns the same `cost` and session `"sess"` on every
call. A test that drives two or more PO turns resuming `"sess"` now gets
`0.0` for the second and later PO entries, because the running total did
not move. Where an existing test asserts a later PO entry's cost, that
assertion is a **contract change** (C1), not a weakened test. Update it, and
name it in your handoff. For the new tests, use a fake that returns a list
of running totals, one per call (for example `[1.0, 1.5, 2.25]`) on one
session.

1. `SessionCost.own_cost`, one parametrized case per row: fresh
   (`resumed=None`) → reported; same session → delta; other session →
   reported; equal → `0.0`; drop → reported; default `SessionCost()` with
   `resumed="s"` → reported.
2. `Ledger.last_cost`: no file → `0.0`; returns the last matching role's
   cost when other roles' entries come after it.
3. `RunState`: round trip keeps `po_cost` as a `SessionCost`; JSON without
   `po_cost` loads `None`.
4. **Resumed session deltas (AC4):** three PO turns on one session report
   running totals 1.0, 1.5 and 2.25. The PO's ledger entries are 1.0, 0.5
   and 0.75 (use `pytest.approx`). `state.po_cost == SessionCost("sess",
   2.25)`, and `budget_status(...)["spent_usd"] == 2.25`.
5. **Across processes:** `state.json` holds `po_cost = ("sess", 2.0)` and
   `po_session = "sess"`. A new `PoRun` resumes the session and gets a
   running total of 2.4. The entry is 0.4.
6. **Fresh session after a handoff renewal:** `po_cost = ("sess", 5.0)`. A
   turn with `resume=None` reports 0.3 with session `"new"`. The entry is
   0.3 and `po_cost == ("new", 0.3)`.
7. **Legacy seed (C6):** `po_cost` is `None`, `po_session = "old"`, and the
   ledger has PO entries 3.0 then 7.0 with a role entry after them. A
   resumed turn reports 7.4. The entry is 0.4.
8. **Drop (C1):** `po_cost = ("sess", 5.0)` and a resumed turn reports 0.2.
   The entry is 0.2.
9. **No result (C4):** a query that yields no `ResultMessage` ledgers 0.0
   and leaves `po_cost` unchanged.
10. **Free provider (C3):** the PO is on a `billing = "free"` provider. The
    entry is 0.0, and `po_cost.reported` is the raw running total.
11. **Checkpoint reflects real spend (C8):** budget 4, `manager_every_pct`
    25 (a checkpoint every $1). The PO reports running totals 1.0 then 1.5
    (entries 1.0 and 0.5), then a role step costs 0.6. `manager_due` holds
    exactly `budget checkpoint at $2.10`. (Under the old behaviour, the
    ledger would have held 2.5 before the step, and the entry would read
    `$3.10`.)
12. **Role steps (C7):** a role step's `plan.options.resume is None`, and
    its ledger cost equals its reported cost.

Coverage stays at 95% or more; ruff check and ruff format are clean.

## Out of scope

- Ledgering a PO query that ends in an error result (s10). When s10 records
  partial PO spend, it must go through `SessionCost.own_cost` and update
  `po_cost` in the same way.
- Budget checkpoints for PO entries. Today only `record_cost` (role steps)
  checks them. A PO entry that crosses a checkpoint is not flagged until a
  later step crosses the next one. That is unchanged, and a candidate
  follow-up.
- Rewriting or annotating old ledger lines, or a dashboard correction for
  them (AC3: the ADR note covers it).
