# s186 design: acceptance-environment commands don't see the runner's venv

ADR: [0091](../../../.team/adr/0091-one-module-hides-the-runner-venv.md) (amended by s186).
Requirements: REQ-232 (AC1), REQ-233 (AC2). Developer: `developer-cli`.

## Cause

`sandbox.sandbox_env` (`sandbox.py:367`) starts from `dict(system.environ())` and only
prepends the environment's `bin` dirs to `PATH`. The runner runs under
`uv run --project agile-team/runner`, so that copy holds `VIRTUAL_ENV=<runner>/.venv` and
a `PATH` that has `<runner>/.venv/bin`. `Prepared.env` is built from it once, in
`sandbox.layout` (`sandbox.py:506`), and every acceptance command uses it:

- the prepare command of a foreground kind (package, script, …): `Preparer._run_blocking`
  → `sandbox.run_shell` (`sandbox.py:346`);
- the start command, i.e. the prepare command of a background kind (web), which the
  runner spawns and probes: `Preparer._serve` → `Preparer._start` (`sandbox.py:441`).
  The config has no separate `start` key; "start command" in the story means this;
- the Customer Proxy's own launch: `Runtime._sandbox_launch` (`dispatch.py:828`), which
  then goes through `hide_runner_venv` (`dispatch.py:302`).

s174 put the rule in `runner_venv.get_command_environ` but left this caller out.

## Rules

| # | Rule | AC |
|---|------|----|
| R1 | **Same base as s174.** `sandbox_env` starts from `runner_venv.get_command_environ()`, not `system.environ()`. So prepare and start get no `VIRTUAL_ENV` key and no directory of the runner's venv on `PATH`; every other variable is the runner's (ADR-0091, REQ-199's rule). | AC1, AC2 |
| R2 | **Filter first, then prepend.** The environment's `bin` dirs (`root / b` for each `b` in `environment.bin`, in order) are put in front of the already-filtered `PATH`. They are never filtered, even if one sits in a venv (e.g. `venv/bin`, the documented example). Empty parts are still dropped (an unset `PATH` gives just the `bin` dirs, or `""`). | AC1, AC2 |
| R3 | **One environment for prepare, start and the Proxy.** Nothing else changes: `Prepared.env` stays the one dict for all three. The Proxy's launch goes on through `hide_runner_venv`, which sets `VIRTUAL_ENV=""` again for the SDK's merge (#55) and re-applies the same `PATH` filter, a no-op here. | AC1 |
| R4 | **Why AC2 follows.** With no inherited `VIRTUAL_ENV`, `uv venv {sandbox}/venv && uv pip install --python {sandbox}/venv …` targets the named venv and `uv` has no mismatching `VIRTUAL_ENV` to warn about; with `bin = ["venv/bin"]` first on `PATH` and the runner's `bin` gone, a start command's bare `python` is the environment's. No code beyond R1–R2 is needed. | AC2 |

## Changes per module

### `agile-team/runner/agile_team/sandbox.py`

- Imports: `from . import runner_venv, stages, system` (`runner_venv` imports only
  `system`, so there is no cycle).
- `sandbox_env` keeps its signature; only its first line and docstring change:

```python
def sandbox_env(environment: Environment, root: Path) -> dict[str, str]:
    """``get_command_environ()`` with the environment's ``bin`` dirs first on PATH."""
    env = runner_venv.get_command_environ()
    path = [str(root / b) for b in environment.bin] + [env.get("PATH", "")]
    env["PATH"] = os.pathsep.join(p for p in path if p)
    return env
```

`get_command_environ` already returns a fresh dict, so the copy test still holds.

Nothing else changes: `layout`, `run_shell`, `Preparer._start` and
`dispatch._sandbox_launch` keep reading `prepared.env`.
