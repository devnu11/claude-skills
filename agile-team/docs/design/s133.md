# s133: Share requests are validated on load, confined to the design folder, and carry their story

Story: `.team/stories/s133.md`. ADR: ADR-0062, amended by s133
(`.team/adr/0062-liaison-shares-files-by-hash.md`).
Requirements: REQ-033 (AC1, AC4), REQ-034 (AC2, AC4), REQ-035 (AC3, AC4).
Developer: `developer-cli`.
Builds on `design/s120.md` (rules S1 to S12). This file changes S6, S4 and S9
and closes the s120 review findings F2, F3 and F4. F5 (one queue helper) stays
out of scope.

## Why

The s120 review found three gaps (`design/s120.md`, "Design review"):

- **F2.** S6 checks a listed path only with `startswith("<docs>/design/")`.
  `agile-team/docs/design/../../.team/run/liaison/x` passes, and then reaches
  the Proxy's read globs and its OS sandbox.
- **F3.** `Share.from_json` does not check field types. A request with
  `"story": 7` loads, and `story_refusal` then raises `TypeError` in the
  router. A request that does not parse is skipped silently on every tick and
  is never settled.
- **F4.** `brief_section` works out the story id from the first file's name
  (`_story_of`), although its caller knows the id.

## Rules

- **C1 Resolve, then check (AC1).** `listed_of` resolves every listed path
  before it checks it. The resolved form is the repo-relative POSIX path of
  `system.resolve(repo / path)`, taken relative to `system.resolve(repo)`.
  So `.`, `..`, symlinks and an absolute path are all resolved. It is `None`
  when the result falls outside the repo. An item passes only when **both**
  hold:
  1. its resolved form equals the path as written (the path holds no `.`,
     `..`, empty segment or link anywhere along it, and is not absolute), and
  2. `PurePosixPath(path).parent == PurePosixPath("<docs>/design")`. The
     file sits directly in the design folder, which is where S3 always
     puts it.

  Otherwise the item is a problem:
  `{file}: shared item {n}: path {path} resolves to {resolved}; a shared file must sit directly in {design}`.
  `{resolved}` is the resolved form, or `a place outside the repo` when that
  is `None`. `{design}` is `<docs>/design/`. A path that is not a string is
  `{file}: shared item {n}: path must be a string`. The other S6 problems
  (not a list, not a mapping, sha256, listed twice) are unchanged, and are
  still checked in the same order: path, then sha256, then duplicate.
- **C2 Only checked paths go on (AC1).** Problem items never reach
  `Listed.files`. So `Listed.paths()`, which feeds `dispatch._order` →
  `sandbox.Order.shared` → `proxy_read_globs` and `_allowed_reads`, the
  brief section and `check()`'s hashing, holds only paths that pass C1, and
  each of those already is its own resolved form. As in s120, a problem holds
  the story at `acceptance` with the story-file hold text. That hold is the
  "refused with a reason" of AC1. `sandbox.py` and `dispatch._order` do not
  change.
- **C3 `with_entry` stays lexical.** `with_entry` still reads the list with
  `Where("", "")` ("any path"), and it does no resolving and no I/O. Its
  caller builds the path with `target_of`, from a story id and name that
  `story_refusal` already accepted.
- **C4 A request file is validated on load (AC2).** `Share.from_json` returns
  a `Share` or a `BadRequest`, and never `None`. It checks, in this order,
  and the first problem wins:
  1. the text is JSON: `not JSON ({error})`, where `{error}` is the
     `json.JSONDecodeError`'s `msg`;
  2. it is a JSON object: `not a JSON object`;
  3. each field of `REQUEST_FIELDS`, in table order (`story`, `name`,
     `sha256`, `data`, `at`). A missing one is `missing field '{field}'`. A
     value of the wrong type is `field '{field}' must be {word}`. `story`,
     `name`, `sha256` and `data` must be `str` ("a string"). `at` must be an
     `int` or `float` but **not** a `bool` ("a number"). Extra keys are
     ignored;
  4. `data` is strict base64 (`base64.b64decode(..., validate=True)`;
     `binascii.Error` or `ValueError`): `field 'data' is not base64`;
  5. the SHA-256 of the decoded bytes equals `sha256`:
     `field 'sha256' does not match the data`.

  The `BadRequest.reason` is `bad request file {rid}.json: {problem}`.
  `Shares._read` turns an `OSError` into a `BadRequest` with the problem
  `cannot read it ({strerror})`. The story id and the file name are not
  checked here: `story_refusal` still checks them at settle time (S2 items 1
  to 3, unchanged).
- **C5 A bad request is settled once (AC2).** `Shares.all()` and
  `Shares.pending()` return every numbered request file as a `Request`
  (`Share | BadRequest`), in number order, and none is dropped. On a
  `BadRequest`, `Sharer.apply`:
  1. records `state.shares[<id>] = "refused: <reason>"` and saves the state;
  2. emits one `share` event: role `liaison`, story `None`, data
     `{request: <id>, path: None, sha256: None, commit: None, outcome: "refused", reason: <reason>}`;
  3. writes nothing, commits nothing and tells nobody.

  The id is then in `state.shares`, so it never comes back as pending.
  Nothing on this path raises. `status`'s `queued_shares` lists the ids of
  pending `Request`s of both kinds.
- **C6 The story id is passed in, never derived (AC3).** `brief_section`
  takes the story id from its caller through a `Brief(story, role)` parameter
  object, which keeps the two-parameter rule. `_story_of` is deleted. No code
  works out a story id from a file name.

## Changes per module

### `agile_team/shares.py`

New imports: `functools`, `Callable` (next to `Mapping` from
`collections.abc`) and `from pathlib import Path, PurePosixPath`.

```python
NOT_STRING = "path must be a string"
OUTSIDE = "path {path} resolves to {resolved}; a shared file must sit directly in {design}"
OUTSIDE_REPO = "a place outside the repo"

BAD_REQUEST = "bad request file {file}: {problem}"
NOT_JSON = "not JSON ({error})"
NOT_OBJECT = "not a JSON object"
MISSING_FIELD = "missing field '{field}'"
WRONG_TYPE = "field '{field}' must be {word}"
NOT_BASE64 = "field 'data' is not base64"
HASH_MISMATCH = "field 'sha256' does not match the data"
UNREADABLE_REQUEST = "cannot read it ({error})"

@dataclass(frozen=True)
class FieldKind:
    """The types a request field accepts, and how a refusal names them."""
    types: tuple[type, ...]
    word: str

STRING = FieldKind((str,), "a string")
NUMBER = FieldKind((int, float), "a number")   # bool is refused explicitly
REQUEST_FIELDS: dict[str, FieldKind] = {
    "story": STRING, "name": STRING, "sha256": STRING, "data": STRING, "at": NUMBER,
}

@dataclass(frozen=True)
class BadRequest:
    """A queued request file that failed C4; settled as refused, never applied."""
    id: str
    reason: str      # BAD_REQUEST, already formatted

Request = Share | BadRequest     # module-level alias, after both classes

class Share:                     # unchanged fields
    @classmethod
    def from_json(cls, rid: str, text: str) -> Share | BadRequest: ...   # C4

def bad_request(rid: str, problem: str) -> BadRequest: ...   # BAD_REQUEST with file f"{rid}.json"

def _as_written(path: str) -> str | None: ...   # returns path; the Where default

@dataclass(frozen=True)
class Where:
    file: str
    design_dir: str                                   # "" accepts any path, unresolved (C3)
    resolve: Callable[[str], str | None] = _as_written  # C1: repo-relative resolved form, None outside

def resolved_path(repo: Path, path: str) -> str | None: ...   # C1, via system.resolve (I/O)

@dataclass(frozen=True)
class Brief:
    """Whose brief a section is for: the story and the role."""
    story: str
    role: str

def brief_section(found: Listed, brief: Brief) -> str: ...   # S9; story from brief.story (C6)
```

Notes for the developer:

- Split `from_json` into small helpers, each under 8 lines. For example:
  `_loaded(text) -> dict | str` (steps 1 and 2: the object, or the problem
  text), `_field_problem(raw, field) -> str | None` (step 3, one field;
  `type(value) is bool` fails `NUMBER`), and `_decoded(raw) -> bytes | str`
  (step 4). Then `from_json` builds the `Share` and checks step 5. A helper
  that returns "value or problem text" is fine. Problems become
  `bad_request(rid, problem)` in `from_json` only.
- `float(raw["at"])` stays, so an `int` `at` loads as a float, as it does
  today.
- `resolved_path(repo, path)`: `root = system.resolve(repo)`,
  `full = system.resolve(repo / path)`. Return
  `full.relative_to(root).as_posix()` when `full.is_relative_to(root)`, else
  `None`. An absolute `path` makes `repo / path` that same absolute path,
  which is intended: it resolves outside the repo, or to some other place.
- `_item_problem(item, where, seen)`: the path check moves to
  `_path_problem(path, where) -> str | None`. It returns `NOT_STRING` for a
  non-string and `None` when `where.design_dir == ""`. Otherwise it applies
  C1 with `where.resolve(path)`. `design_dir` is stored with its trailing
  `/`, so compare parents with `PurePosixPath(where.design_dir)`.
- `listed_of` builds
  `Where(file, f"{docs}/design/", functools.partial(resolved_path, config.repo))`.
  `check()` is unchanged: it hashes
  `found.paths()`, which pass C1.
- Delete `_story_of`. `brief_section` formats `BRIEF_HEAD` with
  `story=brief.story` and looks up `BRIEF_NOTES[brief.role]`.

## Test checklist (AC4)

Unit tests (the real file system under the scratch repo, as
`tests/test_s120_shares.py` does). The symlink test needs real links
(`os.symlink`), and `FakeSystem.resolve` does not follow links.

- [ ] C1 `..`: a story listing
      `<docs>/design/../../.team/run/liaison/x` gives the OUTSIDE problem,
      with its resolved form named. `listed_of(...).files` is empty and
      `paths()` is `()`.
- [ ] C1 absolute: `/etc/passwd` gives the OUTSIDE problem with
      `a place outside the repo`. An absolute path *into* the repo's design
      folder is refused too, because it is not in resolved form.
- [ ] C1 symlink: `<docs>/design/s1-link` → a file outside the design folder
      gives the OUTSIDE problem, naming the link's target. A link inside the
      folder to a file inside it is refused as well (not in resolved form).
- [ ] C1 nested: `<docs>/design/sub/s1-x` is refused (parent is not the
      design folder). A plain `<docs>/design/s1-x.html` still passes.
- [ ] C1 non-string path gives `path must be a string`.
- [ ] C2: with one bad item and one good one, the Proxy's `proxy_read_globs`
      and `_allowed_reads` hold only the good path. The acceptance gate
      HOLDs, with the problem line in the reason.
- [ ] C3: `with_entry` still appends to and replaces in a list whose paths
      are not under the design folder (no regression).
- [ ] C4, one test per problem: not JSON; a JSON array; each missing field;
      each wrong type: `story` as a number, `name` as `null`, `sha256` as a
      list, `data` as a number, `at` as a string, and `at` as `true` (the
      bool case); bad base64; a hash mismatch. Each gives a `BadRequest`
      whose `reason` is the exact text. An `int` `at` loads.
- [ ] C4: an unreadable request file (the read raises `OSError`) gives a
      `BadRequest` with `cannot read it (…)`.
- [ ] C5: `Sharer.apply` on a bad `f1.json` and a good `f2.json`. `f1` is
      `refused: bad request file f1.json: …`, with one `share` event (story
      `None`, outcome `refused`, the reason), no commit and no tell. `f2` is
      applied. A second `apply` emits nothing more, and `pending` is empty.
      A request with `"story": 7` no longer raises.
- [ ] C5: `status`'s `queued_shares` lists a pending bad request.
- [ ] C6: `brief_section(found, Brief("s7", "architect"))` names `s7`, even
      when the file name starts with another id, for example
      `docs/design/s1-x.html`. `_attach_shares` passes `plan.story.id`.
      Other roles, and no files, still give `""`.

Existing tests whose assertions change, each because of a rule above:

- `test_all_skips_other_names_and_bad_files`: `f9.json` holding `garbage` is
  now a `BadRequest` in `all()` (C5, REQ-034). Other names are still skipped.
- `from_json` tests that assert `None` for tampered `sha256` or bad base64
  now assert the `BadRequest` reason (C4, REQ-034).
- S6 problem-text tests that expect `path must be a string under …` now
  expect `NOT_STRING` or `OUTSIDE` (C1, REQ-033).
- `brief_section(listed, role)` calls take a `Brief` (C6, REQ-035).
