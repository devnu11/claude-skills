# s100 (A6c): a story timeline, like TeamCity's

Story: `.team/stories/s100.md`. Plan context: `.team/run/liaison/plans/tool-flow.md`
(sections "A6c" and "Readability"). Builds on s83 (Backlog tab), s96/s97 (snapshot
`steps`, awake time), s98 (`po-turn`), s99 (`runner-stage`). No new ADR: it follows
the s98 pattern (an append-only run file, read into one snapshot section) and the
s96 pattern (the page derives views from raw snapshot data). No new dependency.

Developer: **developer-gui** (the page is most of the work; the two small Python
changes in `live.py` and `dashboard/snapshot.py` follow s98's `tools.jsonl` shape).

## What changes, in one paragraph

An expanded Backlog row gains a **Timeline** section. One SVG draws a story's
life on one time axis, from `story-opened` to done (or to now). It has one row
per role that ran a step, in pipeline order, then a `PO` row and a `runner` row.
Steps are bars coloured by outcome. Bounces draw thin arrows to the row of the
next step, and Manager rulings are diamonds. Every gap between bars is
explained in a `waits` row and shaded: asleep, a question to the human, a hold,
other work, or idle. A header totals work, runner, PO, waiting and asleep. A
Story/Sprint toggle draws every story of the sprint as groups. The axis zooms
and pans and follows "now" until the human pans. The only runner change is
that the heartbeat now records **where** each sleep it counts happened:
`.team/run/sleeps.jsonl` and the snapshot's `sleeps` section. Done stories get a
folded **Done** group on the Backlog tab, so their timelines can be opened, and
each Board card links to its story's timeline. A node-harness test measures
every timeline text's rendered size and contrast, and the Flow chart's too.

## Rules

| id | rule |
|---|---|
| TL1 | **Where.** `storyDetails` (Backlog expanded row) renders `timelineHtml(view, story)` after the spend/links line and before the events list, under a `Timeline` heading. Nothing else on the row changes. |
| TL2 | **Range.** `from` = the story's first `story-opened` event `at`. With none, it is the earliest `at` of the story's events and steps. With nothing at all, the section reads `No recorded activity for this story yet.` (`note` text) and draws no SVG. `to` = for a done story, the `at` of its last `gate` event with `data.story_status === "done"` (with none, its last event's `at`); for any other story, `now`. `running = story.status !== "done"`. |
| TL3 | **Now.** `tlNow(view)`: `view.generated_at` in a replay (`data.cursor !== Infinity`), else `clockNow(view)`. Every model and view function takes `now` explicitly (`ctx.now`), never reads a clock. |
| TL4 | **Rows (AC1).** A story group's rows are: every role with a step of the story (`view.steps`, `story === id`, role not `product-owner`) or a ruling mark (TL9), ordered by `roleRank` (the `RING_ORDER` prefix rank the Flow chart uses; ties by name). Then `PO`, then `runner`. Those two are always present, even when empty. |
| TL5 | **Step bars and outcome (AC2).** Each step of the story is a bar on its role's row, `[step.at, step.ended_at ?? now]`. Its verdict event is the first event with `story === id`, `kind` in `VERDICT_KINDS` (`gate`, `test-dispute`, `escalation`), `at >= step.ended_at`, and `at <` the story's next step's `at`. Its outcome comes from `OUTCOMES[data.verdict]`. With no verdict event, it comes from `STEP_STATES`: `running` when `ended_at` is null, `killed` when `seconds` is null, otherwise `ended`. |
| TL6 | **Runner bars.** Each `runner-stage` event with `story === id` is a bar on `runner`, `[data.started_at, at]`, outcome `ok` (`--axis`) when `data.code` is 0 or null and `data.raised` is null, else `failed` (`--critical`). `during` stages (runner tools) are drawn too; the tooltip says `during the step; counted in work`. |
| TL7 | **PO bars.** A PO turn is a `po-turn` event, `[data.opened_at, at]`. It **touches** story `id` when some event in that window has `story === id` and a kind in `PO_TOUCH_KINDS`, or is a `message` event whose message (`view.messages`, same `id` as `data.message`) lists `id` in `stories`. Touching turns are bars on `PO`. |
| TL8 | **Bounce arrows (AC2).** For a step whose verdict is in `ARROW_VERDICTS` (`bounce`, `return`), the arrow runs from `(verdict.at, its row)` to `(next.at, next.role's row)`, where `next` is the story's next step. With no next step yet there is no arrow; the bar's tooltip says `back to <data.now_at>`. A same-row arrow is a curve above the row. The stroke is `--serious`, 1.25 px, with an arrowhead marker. An arrow whose `[verdict.at, next.at]` does not meet the window is not drawn. Bars, marks, sleeps and arrows sit inside a `clip-path` group over the plot (`x = LABEL_W`, `width = PLOT_W`), so a partly visible arrow keeps its true curve and is cut at the plot edge. Row labels, the group header and the now line stay outside the clip. |
| TL9 | **Ruling marks (AC2).** Each `ruling` or `fault` event with `story === id` is a diamond on the row of its `role` (the Manager). The tooltip reads `ruling: <data.ruling> — <data.reason>` or `fault: <data.fault> — <data.reason>`. |
| TL10 | **Gaps (AC3).** `busy` = the union of the group's bar intervals (TL5–TL7), clipped to `[from, to]`. The gaps are `[from, to]` minus `busy`. Each gap is cut at every endpoint of every wait interval inside it. Each piece takes the **first** kind in `WAIT_KINDS` that has an interval containing the piece's midpoint; with none, it is `idle` (`nothing recorded`). Adjacent pieces with the same kind and label merge. |
| TL11 | **Wait intervals.** `asleep`: each `view.sleeps` row → `[to - slept, to]`. `question`: each `view.messages` item with `kind === "question"` that lists `id` → `[m.at, answer.at ?? now]`, labelled `question <m.id> to you`. `hold`: each verdict event (TL5 kinds) of the story whose verdict is in `HOLD_LABELS` → `[e.at, the story's next step-start at ?? now]`, labelled `<HOLD_LABELS[verdict]>: <first line of data.reason, ≤ 60 chars>`. `other`: every step with `story !== id` (`[at, ended_at ?? now]`, key `story ?? role`), every `runner-stage` with `story !== id` (key `story ?? "runner"`), and every PO turn that does not touch `id` (key `PO`). Its label is `other work: <keys>`, listing the distinct keys of the intervals containing the piece's midpoint in first-seen order: at most 3, then `+N`. A key in the story's `depends_on` reads `<key> (dependency)`. |
| TL12 | **Sleep band.** Every sleep interval (TL11 `asleep`) that meets the window is also drawn as a hatched band over the group's rows, so sleep **inside** a bar shows too. |
| TL13 | **Totals (AC3).** `work` = Σ over the group's steps of `seconds` (finished), or `max(0, now - at - (slept ?? 0))` (running); a killed step counts 0. `runner` = Σ `data.seconds` of its runner stages with `data.when !== "during"`. `po` = Σ `tool_s + model_s` of its touching turns (`waiting_s` is a step's time, already in work). `waiting` = Σ of its non-`asleep` gap pieces, with a breakdown (question, hold, other, idle) in the tooltip. `asleep` = the measure of the union of sleep intervals clipped to `[from, to]`. Each value is shown with `fmt.span`. |
| TL14 | **Sprint scope (AC1).** The toggle `TL_SCOPES` (`Story`, `Sprint`), styled like the Flow chart's `.seg`, is kept per expanded story. `Sprint` is disabled (title `not in a sprint`) when `story.sprint` is null. In Sprint scope the groups are: first a `Sprint N` group with the steps and runner stages that have `story === null` and lie inside the sprint's window (`inSprint(view, N)`; no waits, no PO row); then one group per story with `sprint === N`, in `view.stories` order. Each group has a header row (`<id> · <title>`, the title cut at 80 chars). The model range runs from the earliest group `from` (and the sprint's `sprint-start` at) to the latest group `to`. Totals: work and runner are summed over the groups; `po` over the **distinct** touching turns; `waiting` over the story groups (story-time); `asleep` once over the model range. |
| TL15 | **Window (AC4).** Per story, `ui.tl[id] = {scope, span, end}`, which defaults to `{scope: "story", span: null, end: null}`. `span` null means fit. `end` null means following now. Let `right = range.running ? range.to + span·FOLLOW_PAD : range.to`. The window is `[right - span, right]`, with `span = state.span ?? (range.to - range.from)` but at least `MIN_SPAN_S`. **Zoom** in halves `span` and out doubles it; once `span` reaches the full range it becomes null. Zoom keeps `end`. **Fit** sets both to null. **Pan** by `s` seconds: `end = (end ?? right) + s`, clamped to at least `range.from + span`. Once it reaches `right` it becomes null, which is following again. **Now** sets `end` to null. Buttons pan by half a span. The wheel zooms with ctrl or meta held (deltaY < 0 is in). With shift held, or when `|deltaX| > |deltaY|`, it pans by `delta / PLOT_W × span`. A plain vertical wheel scrolls the page. |
| TL16 | **Live (AC4).** The section is re-rendered on every snapshot (as the whole Backlog is). A `now` line (`--accent`, 1.5 px, label `now`) is drawn when `range.running` and `now` lies inside the window. A running step's bar ends at `now`. A done range has no now line. `renderBacklog` keeps each `[data-tl-plot]` element's `scrollLeft` across the re-render (narrow screens scroll the SVG natively). **Wheel vs native scroll:** over the plot, a sideways or shift wheel is the TL15 pan and takes precedence over native scrolling, even on a narrow screen. Native sideways scrolling is still available through the scrollbar and touch drag, since touch fires no wheel events. |
| TL17 | **Done stories reachable.** The Backlog tab adds a folded third group, `Done` (`doneStories(view)`: `status === "done"`, in `view.stories` order, no move handles). Folded, it shows `Done <n>` and a `show done stories` button (`data-show-done`, toggles `ui.showDone`). `backlogGroups` is unchanged. |
| TL18 | **Board link.** `storyCard` adds `<a class="tl-link" href="#backlog" data-timeline="<id>">timeline</a>`. A click calls `openTimeline(id)`, which expands the row (loading its file as `toggleRow` does), sets `ui.showDone` for a done story, calls `showTab("backlog")`, and then calls `scrollIntoView({block: "start"})` on its `[data-expand]` row. |
| TL19 | **Sleep record (runner).** When `Pulse._count_sleep` counts a sleep (gap > `SLEEP_GAP_BEATS × beat_s`), the beat appends one line to `.team/run/sleeps.jsonl`: `{"from": <previous beat wall>, "to": <this beat wall>, "slept": <gap - beat_s>}`, each value rounded to 1 decimal. It is written outside the pulse lock, and `OSError` is suppressed, as for `turns.jsonl`. No other line is written. |
| TL20 | **Snapshot `sleeps`.** A new section after `tools`: the valid rows of the last `SLEEPS_TAIL_BYTES = 262_144` bytes of `sleeps.jsonl` (`read_tail`), sorted by `from`. A valid row has numeric `from`, `to` and `slept` (`step_times.number`, so not bools), with `from <= to` and `0 <= slept <= to - from`. Each row is shipped as `{"from", "to", "slept"}`. `live.SLEEPS` joins `RUN_FILES`, so the file is watched. `asOf` (replay) keeps the rows with `to <= cursor`. |

### Readability (AC-R)

| id | rule |
|---|---|
| TR1 | **One text table.** Every piece of text the timeline renders comes from `tlText(kind, body, attrs)` (SVG `<text>`) or `tlSpan(kind, body, attrs)` / `tlButton(kind, attrs, body)` (HTML). Each one carries `data-text="<kind>"` and an inline `style` taken from `TL_TEXT[kind]`: `font-size:<px>px;fill:var(<ink>)` for SVG, and `font-size:<px>px;color:var(<ink>)` for HTML. No timeline text gets its size or colour from a class. |
| TR2 | **Scale 1.** The SVG's `width` attribute equals its `viewBox` width (`TL_WIDTH = 960`), and so does its height. Its container scrolls sideways (`overflow-x: auto`) instead of scaling. So the rendered size is `TL_TEXT[kind].px`. |
| TR3 | **Limits.** Every `TL_TEXT` size is ≥ 12. Every `TL_TEXT` ink is `--ink` or `--ink-2`, never `--muted`: `--muted` on `--surface` is about 3.6:1 in the light theme. All text sits on `--surface`, and the SVG draws a `--surface` background rect first. Bars carry no text, only `<title>` tooltips. A wait's label sits in the `waits` row above its 4 px coloured strip, never on a shade. |
| TR4 | **Fitting a label.** A wait label is drawn only when its piece is at least `label.length × CHAR_EM × px + 6` wide (`CHAR_EM = 0.6`); otherwise it lives only in the piece's `<title>`. Row labels are cut to 20 chars, which fits `LABEL_W` at 13 px. |
| TR5 | **Flow chart.** It stays at natural size: `FLOW_FONT_PX` ≥ 12, `MERMAID_OPTIONS.flowchart.useMaxWidth === false`, `#flow { overflow-x: auto }`, `.flow svg { max-width: none }`. Adding nodes widens it, and it scrolls sideways. `idleClassDef` text changes from `--muted` to `--ink-2` (6.9:1 on `--surface-2` in light, 8.8:1 in dark). Dimming stays colour-only (FL1–FL2). |

Shades: a gap piece's shade over the group's rows is `fill="var(<colour>)" fill-opacity=".10"`. Its
strip in the `waits` row is 4 px at full colour. The sleep band is the hatch pattern
`tl-<group>-sleep` (2 px `--ink-2` stripes at `fill-opacity=".25"`, rotated 45°). These are
plain SVG rects, not Mermaid nodes, so FL1's opacity ban does not apply.

## Changes per module

### `agile_team/live.py`

```python
SLEEPS = "sleeps.jsonl"

@dataclass(frozen=True)
class Sleep:
    """One sleep the heartbeat counted (TL19): the beat gap and the seconds left out."""
    start: float   # previous beat's wall time
    end: float     # this (late) beat's wall time
    slept: float   # gap less one beat

    def line(self) -> str:
        """``{"from", "to", "slept"}`` as one JSON line, each rounded to 1 decimal."""
```

- `Pulse._count_sleep(self, now: float) -> Sleep | None` returns the counted `Sleep`, or `None` when the gap is
  not a sleep. Its `slept_s` behaviour (AW2) is unchanged.
- `Pulse._beat`: `self._log_sleep(self._count_sleep(system.now()))`, then `self.write()` as now.
- `Pulse._log_sleep(self, sleep: Sleep | None) -> None`: appends `sleep.line() + "\n"` to `run_dir / SLEEPS`
  with `system.append_text` under `suppress(OSError)`. With `None` it does nothing.

## Known limits

- **Sleep before s100 is not shaded.** `sleeps.jsonl` starts when s100 ships. Older gaps, including the 10-12
  evening that the plan's verification names, show as `idle` (`nothing recorded`) or `other`. No clocks
  recorded then can place them.
- **A running PO turn** has no bar until its `po-turn` event is written at the turn's end.
- **Boundary holds** (sprint boundary) are not a story's `hold` wait. They show as `other` (runner) or `idle`.
- Wait-label width is estimated (`CHAR_EM`), not measured. A label that might not fit goes to the tooltip.
- `waiting` in Sprint scope is story-time summed over stories, not wall time. The tooltip says so.
- **SVG ids repeat across open timelines** (review m5). `tl-<group>-clip`, `-sleep` and `-arrow` are unique
  within one SVG, but two expanded rows that draw the same group (Sprint scope) repeat them. Their content is
  identical, so nothing renders wrong. The fix is to prefix them with the expanded story's id the next
  time `index.html` is touched, together with moving `storyGroup`'s displaced doc comment back to its
  function (review m4).
