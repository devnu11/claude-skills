# s123: a devops fix at a boundary stores trigger text as the boundary hold

ADR: [0054](../../../.team/adr/0054-boundary-hold-is-an-enum-and-bad-state-values-are-dropped-at-load.md).
Developer: `developer-cli` (runner Python, as for s29 and s108).
The t70 rule applies: the unit-tester writes the failing tests first.

## Rules

| # | Rule | AC |
|---|---|---|
| H1 | `BoundaryHold` gains `FIX_HANDOVER = "fix_handover"`, the last member. | AC1 |
| H2 | `BoundaryRunner.after_fix(report)` sets `b.hold = BoundaryHold.FIX_HANDOVER` when `handover.triggers(report)` is not empty, and `None` when it is empty. Nothing else in `after_fix` changes: `halted` still changes nothing, a `review_conflict` is still recorded, and `rounds`, `failure` and `note` update as before. It never calls `handover.hold_reason`. | AC1 |
| H3 | The triggers are handed to the PO by the router's existing `_step` → `Pass` path, as for any step. Do not change it. `continue_boundary` already clears any hold that is not in `AFTER_REVIEW`, so it releases `fix_handover` without a change. | AC1 |
| H4 | `STALL_HINTS[BoundaryHold.FIX_HANDOVER] = "answer the devops fix's handover, then continue_boundary(note) to rerun the stage"`. | AC1 |
| L1 | `state.from_json` never raises because of `boundary.hold`. A stored hold that is not a `BoundaryHold` value loads as `None`. | AC2 |
| L2 | That drop adds `LoadFault("boundary.hold", <bad value as str>, BAD_HOLD)` to `RunState.load_faults`, unless an equal entry is already there. The list is persisted with the state. | AC2 |
| L3 | `cmd_start` calls `runtime.report_load_faults()` right after `make_runtime`. It emits one `fault` event per entry, with no role and no story, and data `{"fault": "state", "field", "value", "reason"}`. Then it empties the list and saves. With an empty list it does nothing and does not save. | AC2 |
| L4 | Read-only loads (`watch`, `status`, the dashboard, `health`) never emit or save. They show no hold. | AC2 |
| L5 | `Boundary.__post_init__` stays strict. Building a `Boundary` in code with a bad hold still raises. Only loading from JSON is lenient. | — |

Why L2 persists the list: `cmd_start` runs `checkout.Guard.on_start` and
`_recover` before `make_runtime`. Both load the state and may save it. If the
dropped value lived only in memory, that save would erase it and no fault
would ever be emitted. Because the list is persisted, the fault survives the
save and is emitted exactly once, by `report_load_faults`.

## Changes per module

### `agile_team/boundary.py`

- `class BoundaryHold(StrEnum)`: add `FIX_HANDOVER = "fix_handover"` after `ERROR`.
- `STALL_HINTS`: add the H4 entry next to the `CI_FAILED` entry.

### `agile_team/boundary_runner.py`

- `after_fix`: replace `b.hold = handover.hold_reason(report)` with
  `b.hold = fix_hold(report)`.
- New module-level function:

  ```python
  def fix_hold(report: dict[str, Any]) -> BoundaryHold | None:
      """``fix_handover`` when the fix's report raises a handover trigger, else ``None``."""
  ```

  Body: `return BoundaryHold.FIX_HANDOVER if handover.triggers(report) else None`.
- Replace the `after_fix` docstring with one line. The shipped one is accepted
  at design review:

  ```python
          """A devops fix is back: record any resolution, count the round, hold on handover, rerun."""
  ```

  Every docstring in this design must fit in 100 characters together with its
  indent. Ruff's E501 has no exemption for docstrings.

### `agile_team/state.py`

- Imports: add `BoundaryHold` to `from .boundary import …`.
- New constants:

  ```python
  BOUNDARY_HOLDS = frozenset(BoundaryHold)
  BAD_HOLD = "not a valid BoundaryHold; the hold was dropped"
  ```

- New dataclass, placed before `RunState`:

  ```python
  @dataclass(frozen=True)
  class LoadFault:
      """A stored value that loading dropped, for one ``fault`` event at start (ADR-0054)."""

      field: str
      value: str
      reason: str
  ```

- `RunState`: new field `load_faults: list[LoadFault] = field(default_factory=list)`, the last field.
- `from_json`: compute the faults from the raw boundary before `_boundary` runs:

  ```python
  raw = data.get("boundary")
  data["load_faults"] = _load_faults(data.get("load_faults"), raw)
  data["boundary"] = _boundary(raw)
  ```

- New helpers. Each one has a single job:

  ```python
  def _bad_hold(data: dict[str, Any] | None) -> list[LoadFault]:
      """A ``LoadFault`` for a stored boundary hold that is not a ``BoundaryHold``; else ``[]``."""
      # hold = (data or {}).get("hold"); [] when falsy or in BOUNDARY_HOLDS;
      # else [LoadFault("boundary.hold", str(hold), BAD_HOLD)]

  def _load_faults(stored: list[dict[str, Any]] | None, boundary: dict[str, Any] | None) -> list[LoadFault]:
      """The stored load faults plus any new one from ``boundary``, without duplicates."""
      # kept = [LoadFault(**f) for f in stored or []]
      # return kept + [f for f in _bad_hold(boundary) if f not in kept]
  ```

- `_boundary(data)`: build with `"hold": _known_hold(data.get("hold"))`, where

  ```python
  def _known_hold(hold: Any) -> str | None:
      """``hold`` when it is a ``BoundaryHold`` value, else ``None``."""
      return hold if hold in BOUNDARY_HOLDS else None
  ```

  Watch out: `None in BOUNDARY_HOLDS` is `False`, so an empty hold still loads
  as `None`. A non-string value such as a list is unhashable and raises
  `TypeError` on `in`. Guard it with `isinstance(hold, str) and …`, both in
  `_known_hold` and in `_bad_hold`, so a list or a number is also dropped and
  recorded. A falsy hold (`None`, `""`, `0`, `[]`, `{}`) means "no hold". It
  loads as `None` and adds no fault. This was confirmed at design review.

### `agile_team/dispatch.py` (`Runtime`)

- `asdict` and `EventKind` are already imported.
- New method:

  ```python
  def report_load_faults(self) -> None:
      """Emit one run-level ``fault`` event per value dropped at load, then clear and save."""
      faults = self.state.load_faults
      if not faults:
          return
      for f in faults:
          self.emit(EventKind.FAULT, fault="state", **asdict(f))
      self.state.load_faults = []
      self.save()
  ```

  The house rule says functions stay under 8 lines. Splitting out the loop
  as `_emit_load_faults(faults)` is fine.

### `agile_team/cli.py`

- `cmd_start`: insert `runtime.report_load_faults()` directly after
  `runtime = make_runtime(...)`, before `_load_dependencies(runtime)`.

### Not changed

`handover.hold_reason`: `dispatch.note_step` still uses it for `StoryState.hold`,
which is free text. `router.py`, `po_tools.continue_boundary`, the snapshot
(`str(b.hold)` already renders `fix_handover`), `index.html` and `watch.py`
do not change either.

## Docs (architect, this step)

- `reference/protocol.md`, **Failures** paragraph: a fix that hands over holds
  `fix_handover`, its triggers go to the PO, and `continue_boundary` reruns the
  stage. An unknown stored hold is dropped at load and reported once as a
  `fault` event.

## Test checklist

Unit tests (unit-tester, written first and failing before the fix):

- [ ] `after_fix` with a report that raises `stopped` and `questions`
      (e.g. `{"role": "devops", "status": "blocked", "open_questions": ["q"]}`)
      leaves `b.hold is BoundaryHold.FIX_HANDOVER`. A save followed by
      `state.load` of the same run dir round-trips it without error (AC3).
- [ ] `after_fix` with a clean `done` report and no questions leaves `b.hold is None`,
      `rounds + 1`, `failure is None`.
- [ ] `after_fix` with `status == "halted"` changes nothing (existing behaviour kept).
- [ ] `fix_hold` returns `FIX_HANDOVER` / `None` for a triggering / quiet report.
- [ ] `stall_hint(BoundaryHold.FIX_HANDOVER)` names `continue_boundary`.
- [ ] `continue_boundary` on a `fix_handover` hold clears it and keeps `rounds`
      (it is not in `AFTER_REVIEW`).
- [ ] `RunState.from_json` of a state whose `boundary.hold` is `"stopped, questions"`
      loads without raising, with `boundary.hold is None`, other boundary fields kept,
      and `load_faults == [LoadFault("boundary.hold", "stopped, questions", BAD_HOLD)]` (AC3).
- [ ] The same with a non-string hold (e.g. `["x"]`): it is dropped and recorded, with no `TypeError`.
- [ ] A valid stored hold (`"ci_failed"`) loads as `BoundaryHold.CI_FAILED` with no load fault.
- [ ] `to_json` → `from_json` keeps `load_faults`. Loading a file that already
      lists the fault and still has the bad hold does not duplicate it.
- [ ] `Runtime.report_load_faults` with one fault emits exactly one `fault`
      event (story `None`, data names `"stopped, questions"`), empties the list
      and saves. A second call emits nothing.
- [ ] `report_load_faults` with no faults emits nothing and does not write `state.json`.
- [ ] `cmd_start` on a run dir whose `state.json` holds the bad value starts
      (the existing start-test harness) and the events log has one `fault`
      event naming it, even though `_recover` saves first (AC2).
- [ ] `watch` and `status` on that run dir run without raising and write no
      event (AC2).
- [ ] `Boundary(Edge.END, 1, hold="bogus")` still raises `ValueError` (L5).

Existing tests that compare a whole `to_json()` output or the field list of
`RunState` need the new `load_faults: []` key. That is a schema addition
(ADR-0054), not a weakened assertion.
