# s161: Design names follow the house rules

Story: `.team/stories/s161.md`. ADR: ADR-0089 (new), ADR-0074 (amended).

## Why

s159 and s163 added 43 `# house-rules: allow` comments to
`agile-team/runner/agile_team/`, with reasons like "name fixed by the s159
tests", "name fixed by the design" and "s163 design name". The designs chose
the names, the tests used them, and the developer waived the rule. This story
renames them all (s159's 31 and s163's 12: AC1 covers every comment with such
a reason, and AC2 would fail the other 12). It also makes house-rules refuse
the excuse, and makes the architect name things by the rules from the start.

### The query rule sees more changes (AC1)

Some methods change state but have no arguments: `drain`, `deliver_news`,
`hand_over_idle`. The query-property heuristic couldn't see their change, so
renaming alone would not clear them. The heuristic learns two cases, both of
which only remove false findings:

- **Q1.** A tuple or list assignment target is unpacked:
  `queued, self._queue = self._queue, []` writes `self._queue`. Starred items
  were already handled by `read_root_name`.
- **Q2.** A method changes `self` when it calls, on `self` itself
  (`self.<m>(…)`), a method of its own class that changes `self`. This
  repeats until nothing more is added. The method may be private, may change
  `self` directly, and the calls may run several levels deep. Example:
  `deliver_news` → `self._deliver` → `self._clear_wait()` (`clear`) and
  `self.runtime.save()` (`save`). Calls on another object (`self.runtime.x()`)
  stay as today: only the existing mutating-verb test applies to them.
- **Q3.** Findings that go away leave stale baseline entries. The toolchain's
  fix command (`house-rules baseline`) drops them. Commit the shrunk
  `.house-rules-baseline.json` with the step (REQ-113).

### suppression-excuse (AC2)

- **E1.** A new house-rules rule `suppression-excuse` (default fail,
  `Limits(0, 0)`) reports each suppression whose reason only says that tests,
  a test file or a design fixed the name. It sits in `RULES` right after
  `suppression-reason`. Like that rule, it makes one finding per file, at the
  first such line (symbol `<suppressions>`, the details merged). Its message
  is `suppression excuses a name instead of giving a reason: {detail}`, with
  detail `line <n>: <reason>`. The finding carries the file, the line and the
  rule id, and the message lists each matching reason. The suppression still
  suppresses the rule it names, as a reasonless one does today.
- **E2 (amended after acceptance).** "Only says" means fullmatch, and it
  stays fullmatch. A bounded search would refuse a real reason that names
  the tests on the way to a real point, such as `name fixed by the tests; it
  mirrors git's verb`, and AC2 says *only*. The grammar in E3 covers the
  ways of saying it instead. The reason is cut at its first `#` (a chained
  comment such as `# expect:`), stripped, and stripped of any trailing run of
  `.`, `;`, `:`, `!` and spaces (so `fixed by the tests. ;` is cut too):
  `reason.split("#", 1)[0].strip().rstrip(".;:! ")` (design-review: the code's
  form, kept over the earlier `.rstrip(".;:!").strip()`). A pattern must
  then match all of it, ignoring case. `name fixed by the tests; it mirrors
  git's verb` passes because it says more.
- **E3 (amended after acceptance).** The defaults are a grammar, not a phrase
  list. An excuse names a **source** (tests, a test file, a design), a
  **fixing verb** and the **name**, in one of four forms. Acceptance found
  that the first version knew only the passive form and a few active verb
  forms, so "a test fixes the name" and "test file fixed the name" got
  through.
  - **Source:** a word whose part is `test`, `tests`, `design` or `designs`.
    The part may be joined to the rest of the word only by `_`, `.`, `/`
    or `-`, never by a letter. So `test_router.py`, `s159-tests` and
    `design/s159.md` are sources, and `latest`, `pytest`, `testing` and
    `designed` are not. A `file`, `files`, `suite`, `suites`, `doc` or
    `docs` may follow. **Subject:** an optional determiner, one optional
    qualifier word (`s159`, `e2e`, `unit`), then the source.
  - **Fixing verb:** a word that starts with one of the stems `fix`, `choos`,
    `chos`, `set`, `nam`, `us`, `expect`, `requir`, `giv`, `gave`, `pick`,
    `pin`, `want`, `need`, `demand`, `dictat`, `call`, `tak`, `took`,
    `assert`, `check`. That covers every tense (`fix`, `fixes`, `fixed`,
    `fixing`). The stems sit between a subject and an object, so a broad stem
    such as `us` can't make a sentence about something else match.
  - **Object:** an optional determiner, one optional qualifier word, then
    `name`, `names`, `it`, `them`, `this` or `that`.
  - **Lead-in:** any number of `kept`, `because`, `since` and `as` before a
    form ("kept because the s159 design chose it").
  - **The four forms:** *active*, subject + optional auxiliaries (`has`,
    `have`, `had`, `do`, `does`, `did`, `will`, `would`, `must`, `already`,
    `still`) + verb + object; *passive*, optional object + optional
    auxiliaries (`is`, `are`, `was`, `were`, `been`, `being`, `as`) + verb +
    `by`, `in` or `from` + subject; *noun*, subject + optional `'s` or `'` +
    `name(s)`; *bare*, `per`, `from` or `by` + subject.

  In `config.py` these are module constants made of raw strings and
  `rf`-strings over the other constants. `rf`-strings are constant
  expressions, not calls, so the no-global-code rule holds. Don't put a
  `{n,m}` quantifier in an `rf`-string: its braces would be read as fields.
  The grammar uses only `?` and `*`.

  ```python
  EXCUSE_DETERMINER = r"(?:the|a|an|this|that|these|those|its|their|our)"
  EXCUSE_WORD = r"[\w./-]+"
  EXCUSE_SOURCE = (
      r"[\w./-]*?(?<![a-z])(?:tests?|designs?)(?![a-z])[\w./-]*"
      r"(?:\s+(?:files?|suites?|docs?))?"
  )
  EXCUSE_SUBJECT = rf"(?:{EXCUSE_DETERMINER}\s+)?(?:{EXCUSE_WORD}\s+)?{EXCUSE_SOURCE}"
  EXCUSE_VERB = (
      r"(?:fix|choos|chos|set|nam|us|expect|requir|giv|gave|pick|pin|want|need"
      r"|demand|dictat|call|tak|took|assert|check)[a-z]*"
  )
  EXCUSE_OBJECT = (
      rf"(?:{EXCUSE_DETERMINER}\s+)?(?:{EXCUSE_WORD}\s+)?(?:names?|it|them|this|that)"
  )
  EXCUSE_LEAD = r"(?:(?:kept|because|since|as)\s+)*"
  EXCUSE_ACTIVE_AUX = r"(?:(?:has|have|had|do|does|did|will|would|must|already|still)\s+)*"
  EXCUSE_PASSIVE_AUX = r"(?:(?:is|are|was|were|been|being|as)\s+)*"
  DEFAULT_EXCUSES = (
      rf"{EXCUSE_LEAD}{EXCUSE_SUBJECT}\s+{EXCUSE_ACTIVE_AUX}{EXCUSE_VERB}\s+{EXCUSE_OBJECT}",
      rf"{EXCUSE_LEAD}(?:{EXCUSE_OBJECT}\s+)?{EXCUSE_PASSIVE_AUX}{EXCUSE_VERB}"
      rf"\s+(?:by|in|from)\s+{EXCUSE_SUBJECT}",
      rf"{EXCUSE_LEAD}{EXCUSE_SUBJECT}(?:'s|')?\s+names?",
      rf"{EXCUSE_LEAD}(?:per|from|by)\s+{EXCUSE_SUBJECT}",
  )
  ```

  They match, among others: *active* "a test fixes the name", "test file
  fixed the name", "the s159 tests use this name", "the design named it",
  "the e2e tests expect it", "tests require the tool name", "the tests pin
  this name", "kept because the s159 design chose it"; *passive* "name fixed
  by the tests", "name fixed by the s159 tests", "tool name fixed by the s163
  design", "named by test_rewrite.py", "name fixed by a test file", "as named
  by the design", "name used in test_router.py"; *noun* "s163 design name",
  "the design's name", "the tests' name"; *bare* "per the s159 design".
  Known edge: "pytest test name" is refused (noun form). A reason that only
  names who chose the name is an excuse. A real reason says why the rule
  misreads the code.
- **E4.** A repo adds patterns with a new settings key, `excuses` (a list of
  regex strings). They extend the defaults and never replace them. A repo
  that wants none disables the rule (`disable = ["suppression-excuse"]`). A
  value that is not a list of strings, or a pattern that does not compile, is
  a `ConfigError` naming `excuses`.
- **E5.** No other suppression changes. A suppression with any other reason
  is listed as today, and `suppression-reason` is unchanged.
- **E6 (round 3).** A line suppression can't silence `suppression-reason`
  or `suppression-excuse`. Otherwise `allow verb-name, suppression-excuse --
  name fixed by the tests` would waive the rule again. `checker.UNSUPPRESSIBLE`
  (`frozenset({"suppression-reason", "suppression-excuse"})`) names them, and
  `RuleRun.findings` ignores line suppressions for those rules. Only
  `disable` in the settings turns them off. (The code landed in 2dcea79.)

  yields `Measure(SUPPRESSIONS, s.line, 1, f"line {s.line}: {s.reason}")` for
  each suppression with `module.settings.is_excuse(s.reason)`.
- A `Rule("suppression-excuse", "A suppression gives a reason, not \"tests or
  a design fixed the name\": fix the name.", Limits(0, 0),
  check_suppression_excuses, "suppression excuses a name instead of giving a
  reason: {detail}")` goes after `suppression-reason`.
- Q1: `list_targets(node)` returns each written target unpacked through the
  new `def list_target_leaves(target: ast.expr) -> list[ast.expr]`
  (``a, (b, c)`` → `[a, b, c]`, for `ast.Tuple | ast.List`, recursively).
- Q2: `check_query_properties` computes
  `changing = list_changing_methods(module.tree)` once and skips sites whose
  `qualname` is in it. New helpers:
  - `def list_changing_methods(tree: ast.Module) -> frozenset[str]`: the
    qualnames of the methods (sites with a `receiver`) whose own body
    `mutates_self`, then grown by `extend_changing`.
  - `def extend_changing(sites: list[FunctionSite], changing: frozenset[str])
    -> frozenset[str]`: adds every site for which `calls_changing` holds,
    until nothing is added. Use a loop bounded by `len(sites)` passes, not
    unbounded recursion.
  - `def calls_changing(site: FunctionSite, changing: frozenset[str]) -> bool`:
    some name in `list_self_calls(site)`, prefixed with the site's class path
    (`site.qualname` up to its last `.`), is in `changing`.
  - `def list_self_calls(site: FunctionSite) -> set[str]`: the `attr` of every
    `ast.Call` in `walk_own_body(site.node)` whose `func` is
    `ast.Attribute(value=ast.Name(id=site.receiver))`.
