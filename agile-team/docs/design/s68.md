# s68: The implement gate runs the suite once

**Developer:** `developer-cli`. **Module:** `agile-team/runner/agile_team/gates.py`
only (plus tests, and `reference/protocol.md`, which this design already updated).

## Problem

`Checks.tests_green_and_covered` runs `commands["test"]` (through `green()`),
then `commands["coverage"]`. Each full run takes about 4 minutes, so the gate
takes 7 to 9 minutes. The coverage run already runs every test, so its exit
code proves green or red. The first run is wasted.

## Rules

| # | Rule |
|---|---|
| C1 | At implement → quality, the gate calls `self.run` **exactly once**, with `self.commands["coverage"]`. It never runs `commands["test"]`. |
| C2 | Timeout (`timed_out(code, out)` is not None): return that outcome. The text is unchanged. |
| C3 | Exit 0: return `self._coverage_outcome(parse_coverage(out))`, unchanged. That gives pass `coverage {pct}%`, bounce `coverage {pct}% is below {req}%`, or bounce `could not read a coverage total`. |
| C4 | Non-zero exit, `parse_coverage(out)` is a number **below** `required_coverage()`, and `tests_failed(out)` is False: this is a coverage shortfall that stopped the run (pytest-cov `fail_under`). Return `self._coverage_outcome(pct)`, which bounces `coverage {pct}% is below {req}%`. |
| C5 | Every other non-zero exit bounces `tests fail:\n{tail(out)}`. This is the same text `green()` gives today. A non-zero exit **never passes**: the `&&` chain in this repo's command may have stopped before the second suite ran. |
| C6 | `tests_failed(output)` is True when any pattern in `TEST_FAILURES` matches. The patterns are data, so adding a tool takes one row. |
| C7 | `green()` stays as it is, on `commands["test"]`. `pass_tests_refusal` still uses it. Its bounce text comes from the shared constant `TESTS_FAIL` (DRY with C5). |
| C8 | `bounce_to`, the round counting and the gate event shape are unchanged. Only the number of commands run changes. |

Why C4 needs "no failing test": pytest-cov prints its total and the
`FAIL Required test coverage … not reached` line even when tests failed. A
low total alone does not mean the tests passed. Unknown tools fall to C5,
which is the safe side: the bounce text keeps the output tail.

Known consequence (accepted): a repo with `.team/baseline.json` debt *and* a
coverage command whose own `fail_under` is above that baseline now bounces
`tests fail` (C5). Before, it passed, because the coverage exit code was
ignored. The fix is in that repo's config: drop the command's `fail_under`
and let the gate's threshold judge. This repo has no baseline file and its
threshold is 95 = `fail_under`, so it is not affected.

Out of scope: the boundary full checks (`fullcheck.py`) still run `test` and
`coverage` as separate checks. A follow-up story could merge them the same way.

## Changes in `agile_team/gates.py`

Constants, next to the other bounce texts:

```python
TESTS_FAIL = "tests fail:\n{tail}"
TEST_FAILURES: tuple[re.Pattern[str], ...] = (
    re.compile(r"\b[1-9]\d* (?:failed|errors?)\b"),  # pytest/cargo/jest summaries
    re.compile(r"^--- FAIL:", re.MULTILINE),          # go test
)
```

`[1-9]` matters: a summary such as `0 failed` must not count as a failure.

Module function:

```python
def tests_failed(output: str) -> bool:
    """Whether the output names a failing or erroring test (``TEST_FAILURES``)."""
```

`Checks` methods:

```python
def green(self) -> Outcome:            # body unchanged except: TESTS_FAIL.format(tail=tail(out))

def tests_green_and_covered(self) -> Outcome:
    """One coverage run proves green and gives the total (s68 C1–C5)."""
    code, out = self.run(self.commands["coverage"])
    if timeout := timed_out(code, out):
        return timeout
    if code == 0:
        return self._coverage_outcome(parse_coverage(out))
    return self._failed_run(out)

def _failed_run(self, out: str) -> Outcome:
    """Bounce a non-zero coverage run: shortfall text when only the total fell short (C4), else tests fail (C5)."""
```

`_failed_run` may use a small helper (e.g. `_short_only(self, out) -> float | None`)
to stay under 8 lines. `_coverage_outcome` is unchanged.

No other module changes. `Pipeline.evaluate`'s `"implement"` gate entry still
points at `self.checks.tests_green_and_covered`.

## Test checklist (unit-tester)

Fake runner as in `tests/test_gates.py` (`"T"` = test, `"C"` = coverage),
with a recorded `calls` list.

1. **C1 / AC3:** green, covered run → PASS `coverage 96.0%`, and `calls == ["C"]`.
   Pin this on a failing run too (calls `== ["C"]`).
2. **C3:** exit 0 `TOTAL 80%` → bounce `coverage 80.0% is below 95.0%`.
   Exit 0 with no total → `could not read a coverage total`.
3. **C4 / AC2:** exit 1 with `TOTAL … 80%`, `FAIL Required test coverage of 95% not reached`,
   `200 passed` → reason exactly `coverage 80.0% is below 95.0%`.
4. **C5 / AC2:** exit 1 with `1 failed, 10 passed` and `TOTAL 80%` → reason starts
   `tests fail:\n` and holds the tail. The same for `1 error` and for `--- FAIL: TestX`.
5. **C5:** exit 1 with `TOTAL 99%` (no failure marker) → `tests fail` (never passes).
   Exit 1 with no total → `tests fail`.
6. **C5 baseline:** with `baseline_coverage=90`, exit 1 with `TOTAL 93%` → `tests fail`, not a pass.
7. **C6:** `tests_failed` is False for `0 failed`, `0 errors` and `Coverage failure`.
   It is True for `2 failed` and `1 error`.
8. **C2:** coverage exit 124 → the timeout bounce (`tests/test_s43.py` already covers
   this; drop its `"T"` entry if the fake needs it, but keep the assertion).
9. **C7:** `green()` failing still gives `tests fail:\n…` (pins the shared constant).

Existing tests that encode the old two-run contract must move to the new one.
This is not a weakening:
- `tests/test_gates.py::test_green_gate`: `red = pipeline({"T": (1, "boom")})` becomes
  a coverage run that fails, e.g. `{"C": (1, "boom")}`, still asserting `"boom" in reason`
  and `bounce_to == "implement"`.
- `tests/pipeline_helpers.py::PipelineRunner`: `failures` must make the implement
  gate's **coverage** command (`"pytest --cov"`) fail (`1, "boom: assertion failed"`)
  instead of the test command.

Coverage stays at 100%; ruff check and format clean.
