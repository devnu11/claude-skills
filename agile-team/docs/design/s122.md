# s122: The PO adds a story to the running sprint without restarting it

Story: `.team/stories/s122.md`. ADR: **ADR-0055** (new), **ADR-0016** amended.
Developer: `developer-cli`. It also adds one row to `dashboard/index.html`'s
`TIMELINE`.

Today the only way to add work mid-sprint is a new `start_sprint` (s3 B5). That
opens sprint N+1, runs the start boundary, and queues a Manager turn and a PO
renewal. s122 adds `add_to_sprint(stories, reason)`, which adds stories to sprint N
in place. A restart while the sprint still has unfinished stories now needs a reason.

## Rules

| # | Rule | AC |
|---|------|----|
| SA1 | `add_to_sprint(stories, reason)` is a PO tool (a `SCHEMAS` row). Ids are deduped, keeping order. On success every listed story gets `sprint = state.sprint`. Unchanged: `state.sprint`, `state.goal`, `state.status`, `state.boundary` (stays `None`), `manager_due`, `po_renew_due` and `upstream` (so the review branch `team/sprint-<N>` is the same). | AC1 |
| SA2 | Placement is `prioritise`'s rule: the new `order` is `runtime.priority().with_first(ids, stories.values())`, i.e. the listed ids first in the order given, then every other unfinished story in its old place. It never pulls (`Pull()`), so existing pulls are kept (`repulled(Pull(), …)`) and started stories still rank first by the group rule. The change goes through `Tools._reorder` with `Change.SPRINT` and the reason, so one `priority` event is logged as today (dashboard label "sprint order"). There is no human-order check (B17): the reason is required anyway and is logged in that event. | AC1 |
| SA3 | **Refusals.** Checked in this order; the first one wins. Nothing is saved, no event is emitted, and no story changes. (1) a boundary is pending: the existing `SPRINT_REFUSAL_BOUNDARY` text. (2) no open sprint (SA4): `NO_OPEN_SPRINT`. (3) `priority.order_refusal(ids, stories)`: empty list, unknown, done or cancelled ids (existing texts). (4) a listed story already has `sprint == state.sprint`: `ALREADY_IN_SPRINT`. (5) a listed story's `depends_on` names a story that is not done and is neither in the sprint nor in this call: `dependencies.UNMET`. (6) a blank `reason`: `ADD_NEEDS_REASON`. | AC2, AC1 |
| SA4 | **Open sprint.** `RunState.sprint_open()` is `self.sprint > 0 and self.upstream.closed < self.sprint`. Once the end boundary has closed sprint N (`upstream.closed == N`, set by `BoundaryRunner._close`), nothing can join it, because its review entry is already built. | AC2 |
| SA5 | **Dependencies** use the lists in state (loaded at start, `open_story` and `start_sprint`). `add_to_sprint` does not reload the files, so a refusal changes nothing. "Met" means `dependencies.waiting_on` is empty after removing the ids in the sprint and the ids in this call. A dependency that is in the sprint but not done is allowed, and the router waits for it (DP9). | AC2 |
| SA6 | **Event.** On success, exactly one `sprint-add` event (`EventKind.SPRINT_ADD`, role `product-owner`, story `None`) with data `{"sprint": N, "stories": ids, "reason": reason}`. It is emitted before the `priority` event of SA2. | AC4 |
| SA7 | **Result:** `{"status": "added", "sprint": N, "stories": ids, "order": <queue after>}`. | AC1 |
| SA8 | **Visible like the others.** No change is needed for the Board or the PR: the Board shows stories with `sprint === run.sprint` (s121), and the end boundary's `StackEntry.stories` (`BoundaryRunner._entry`) takes every story with `sprint == b.sprint` when it is built. That list is what the PR body shows (`_body`). The tests pin both. The Activity tab gains a `sprint-add` row (see index.html below). | AC4 |
| SA9 | **Restart reason.** `start_sprint(goal, stories, reason)`: while `state.unfinished_in_sprint()` is non-empty and `reason` is blank, it is refused with `RESTART_NEEDS_REASON` and nothing changes. This check runs after the unknown-id check and before the CI-bug check (`_bug_first`). A blank reason is fine when the current sprint has no unfinished stories (all done, or sprint 0). When given, the reason is added to the `sprint-start` event data as `"reason"`. When blank, the key is left out, so the existing payload is unchanged. Nothing else in `start_sprint` changes. | AC3 |
| SA10 | **Docs and prompt.** The PO role file, `SKILL.md`, `reference/protocol.md` and the customer doc describe `add_to_sprint` and the restart rule (texts below). | AC3, AC6 |

## Texts (constants)

In `po_tools.py`:

```python
NO_OPEN_SPRINT = "no sprint is open to add to (none started, or sprint {sprint} has ended); use start_sprint"
ALREADY_IN_SPRINT = "already in sprint {sprint}: {ids}"
ADD_NEEDS_REASON = "add_to_sprint needs a reason: say why these stories join sprint {sprint}"
RESTART_NEEDS_REASON = (
    "sprint {sprint} still has unfinished stories ({ids}); use add_to_sprint to add work, "
    "or give a reason for starting a new sprint"
)
```

In `dependencies.py`:

```python
UNMET = (
    "depends_on not done and not in the sprint: {pairs}; add those stories in the same "
    "call, or add this one once they are done"
)
```

`{ids}` is joined with `", "` in list order. `{pairs}` is `"s5 on s3, s5 on s4"`: for each listed id in order, each unmet dependency in its `depends_on` order.

```python
    """Put ``ids`` in the current sprint; nothing else changes (SA1)."""
```

### `agile_team/dependencies.py`

```python

    """The stories, and the ids that count as being in the sprint (SA5)."""

    stories: dict[str, StoryState]
    members: frozenset[str]

def unmet_refusal(ids: list[str], scope: Scope) -> str | None:
    """SA5: ``UNMET`` naming each dependency of ``ids`` that is not done and not a member."""
```

The function uses `waiting_on(scope.stories[i], scope.stories)` for each `i`. Callers pass known ids only (refusal 3 runs first).

### `agile_team/po_tools.py`

```python
@dataclass(frozen=True)
class Addition:
    """The arguments of one add_to_sprint call."""

    ids: list[str]
    reason: str
```

`Tools` methods:

| Signature | Job |
|---|---|
| `async def add_to_sprint(self, args: dict[str, Any]) -> dict[str, Any]` | Build `Addition(list(dict.fromkeys(args.get("stories") or [])), args.get("reason", ""))`. Refuse with `refused(...)` via `_add_refusal`, else return `text_result(self._add(addition))`. |
| `def _add_refusal(self, add: Addition) -> str \| None` | `priority.first_refusal([...])` over SA3 (1)–(6), in that order. |
| `def _boundary_refusal(self) -> str \| None` | The pending-boundary text, extracted from `_sprint_refusal` (which now calls it). Same wording. |
| `def _open_sprint_refusal(self) -> str \| None` | `NO_OPEN_SPRINT` unless `state.sprint_open()`. |
| `def _in_sprint_refusal(self, ids: list[str]) -> str \| None` | `ALREADY_IN_SPRINT` for the listed ids in `state.sprint_ids()`. |
| `def _unmet_refusal(self, ids: list[str]) -> str \| None` | `dependencies.unmet_refusal(ids, Scope(stories, frozenset([*state.sprint_ids(), *ids])))`. |
| `def _add(self, add: Addition) -> dict[str, Any]` | `state.add_to_sprint(ids)`, `save()`, emit `SPRINT_ADD` (SA6), then `self._reorder(Reorder(Change.SPRINT, order, None, add.reason))`, where `order = runtime.priority().with_first(ids, stories.values())` is computed **after** the add. Return the SA7 dict with `order` taken from the reorder result. |
| `def _restart_refusal(self, reason: str) -> str \| None` | SA9: `RESTART_NEEDS_REASON` when `state.unfinished_in_sprint()` is non-empty and `reason` is blank. |

`start_sprint` now builds one value and passes it on:

```python
@dataclass(frozen=True)
class Sprint:
    """The arguments of one start_sprint call."""

    goal: str
    ids: list[str]
    reason: str
```

- `_sprint_refusal(self, sprint: Sprint) -> str | None` checks, in order: boundary (`_boundary_refusal()`), empty, unknown, `_restart_refusal(sprint.reason)`, `_bug_first(sprint.ids)`. Then `load_dependencies()` runs as today.
- `_begin_sprint(self, sprint: Sprint) -> None` works as today. The `sprint-start` data gains `"reason"` only when `sprint.reason.strip()` is non-empty (SA9).

## Test checklist (new file `tests/test_s122_add_to_sprint.py`)

Build the runtime and tools the way `tests/test_po_tools.py` does. Use `start_sprint` to make sprint N, then let the boundary finish or clear `state.boundary` as those tests do.

1. **Keeps the sprint (SA1):** s1 is in sprint 1 and s2 is in the backlog. After `add_to_sprint(["s2"], "why")`: `state.sprint == 1`, `goal` and `status` are unchanged, `boundary is None`, `manager_due` and `po_renew_due` are unchanged, `upstream.team_branch` is unchanged, and `stories["s2"].sprint == 1`. No `boundary` or `sprint-start` event is emitted.
2. **Placement (SA2):** with s1 started (has `commit`) and s3 not started in the sprint, adding s2 gives order `["s2", …]`, and the queue still has s1 before s2. `state.pulled` is unchanged. One `priority` event with `change == "sprint"` and the reason.
3. **Refusals (SA3)**, one test each, asserting the exact text and that the state file bytes, the events log and `state.order` are unchanged: boundary pending; no open sprint (sprint 0, and `upstream.closed == sprint`); empty list; unknown id; done id; cancelled id; already in the sprint; unmet `depends_on` (s2 depends on s4, which is in the backlog and not done); blank reason. Two allowed cases: s4 listed in the same call, and s4 already in the sprint but not done.
4. **Refusal order:** a pending boundary with a blank reason gives the boundary text.
5. **Event (SA6):** exactly one `sprint-add` event with data `{"sprint": 1, "stories": ["s2"], "reason": "why"}`, emitted before the `priority` event.
6. **Restart rule (SA9):** with unfinished s1 in sprint 1, `start_sprint(goal, ["s1", "s2"])` with no reason gives `RESTART_NEEDS_REASON` and changes nothing. With a reason it opens sprint 2, and the `sprint-start` data has `"reason"`. With every sprint story done, no reason is needed and the data has no `reason` key.
7. **PR (SA8):** after `add_to_sprint`, mark both stories done and run the end sync (model it on `tests/test_s108_follow.py::test_the_end_sync_only_adds_the_entry_and_follows_nothing`). The new `StackEntry.stories` holds the added story, and `BoundaryRunner._body(entry, "")` lists its line `- s2: <title>`.
8. **Board (SA8):** the snapshot's stories for the added story have `sprint == run.sprint`, the key the Board filters on.
9. **Schema:** `"add_to_sprint"` is in `SCHEMAS` with args `stories` and `reason`, and `start_sprint`'s args include `reason`.
10. **Pure helpers:** `dependencies.unmet_refusal` (pairs order, members excluded, done deps ignored); `RunState.sprint_open`, `sprint_ids`, `unfinished_in_sprint`.
11. **Activity (e2e, `tests/e2e/test_s122_activity_e2e.py`, modelled on `test_s112_activity_page_e2e.py`):** a seeded `sprint-add` event renders a row "stories added" to "sprint N", with the reason and the story ids.

**Existing tests:** tests that call `start_sprint` again while the sprint still has unfinished stories (for example the s3 carry-over tests) now pass a `reason`. SA9 makes their old calls a refusal. This changes the call's arguments, not what the test asserts.
