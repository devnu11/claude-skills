# s104: Flow chart labels pile up top-left; empty boxes; unused roles drawn

Bug story. One page file (`dashboard/index.html`), one snapshot function
(`dashboard/snapshot.py`), the fixture. No new dependency, no ADR, no new
event kind or state field.

## Cause (leading hypothesis: the developer confirms it)

Only Story scope breaks (t42). The one thing Story scope does differently is
**which nodes get the `idle` class**. Story scope dims every role that has not
touched the story in focus (`touchedFocus`), so almost all boxes are dimmed.
Sprint and Run scopes dim only roles with no events at all, and that is just
`developer-db`, whose box is empty **in every scope** (t43). The running box
(architect) is never dimmed, and it is the one box that renders.

`flowSource` emits `classDef idle opacity:0.55`. Mermaid 11 compiles a classDef
into SVG CSS (`.idle > *`, `.idle span`), so the opacity lands on the
`g.label` and on the HTML `<span>` inside the label's `<foreignObject>`.
WebKit (Safari, which the human uses on macOS) puts HTML with opacity < 1
inside a foreignObject on its own compositing layer. It then paints that layer
at the SVG's origin, not at the foreignObject's place. The result is an
empty box with its label at the top-left, as reported. Blink paints it
correctly, which is why this can pass in Chrome.

Two smaller faults also hit the reported view:
- **Tiny text**: `.flow svg { max-width: 100% }` and Mermaid's default
  `useMaxWidth: true` shrink the whole SVG to the column's width.
- **Zero stats**: a role with no data in the scope shows `0 · $0.00 · 0 min`
  rather than saying it is idle (AC2).

The developer confirms the cause in a browser if one is available and names
it in the handoff (story requirement). If the real cause is something else,
the developer fixes that cause too, says what it was, and FL1–FL9 still hold.

## Rules

- **FL1 No compositing styles on nodes.** No `classDef` line in `flowSource`
  contains `opacity`, `filter`, `transform` or `mix-blend-mode`. This holds
  in every scope.
- **FL2 Dim by colour.** The `idle` class only recolours the node:
  `classDef idle fill:<--surface-2>,stroke:<--grid>,color:<--muted>`, with
  the values read through `cssVar`. Which nodes are dimmed does not change:
  Story scope dims roles that have not touched the focus, Sprint and Run
  dim roles with no stats, and the active node is never dimmed.
- **FL3 Same structure in every scope.** The scope changes only the stats text
  and which nodes carry `idle`. The node set, ids, groups and edges don't
  depend on the scope. This is already true, so keep it.
- **FL4 Idle text.** If a role has no totals in the scope (`ctx.totals[name]`
  is undefined) and no open step (`openStep(view, name)` is undefined), its
  stats segment is `idle`, so the label reads `<name><br/><model> · idle`.
  Otherwise the stats segment is today's `tokens · $ · time`. The
  `↩ N bounced` line and the running/live lines are unchanged. The PO box
  is unchanged too: `—` in Story scope, tokens and $ otherwise.
- **FL5 Natural size, scroll sideways.** Mermaid is initialised with
  `flowchart: { useMaxWidth: false }`, so the SVG carries its own pixel width
  and height and is drawn at scale 1. `themeVariables.fontSize` is
  `FLOW_FONT_PX` (16, Mermaid's default) + `"px"`. The CSS rule becomes
  `.flow svg { max-width: none; display: block; margin: 0 auto; }`, and
  `#flow { overflow-x: auto; }` stays as it is, so a wide chart scrolls.
  Rendered label size is 16 px × 1, which is at least the pre-sprint-30
  size (16 px scaled down) and at least 12 px (AC3).
- **FL6 Drawing doesn't depend on the tab being visible.** Nothing reads the
  layout of `#flow` or `#tab-flow` before or during drawing. Mermaid measures
  text in its own temporary element under `document.body`. Showing a hidden
  tab redraws only if the memo key changed. No resize handler is added,
  because a natural-size SVG doesn't reflow (AC1 resize).
- **FL7 `used` on each role (AC5).** Each snapshot `roles[]` entry gains
  `"used": bool`. A role is used when any of these holds:
  (a) a step in the repo's pipeline (`config.gates.steps`) routes to it
  through `gates.STEP_ROLES`. The generic `developer` stands for the
  repo's developer roles: the set of every story's `developer` and
  `po_developer` that is not None, or `{"developer"}` when that set is empty.
  (b) It has at least one `step-start` event in `events.jsonl`.
- **FL8 The chart draws only used roles.** `ringRoles` keeps a role when
  `r.used !== false`, so a role without the key (old replays) is still drawn.
  The PO node is always drawn. Every lookup that goes through `ringRoles`
  (`roleNodeId`, `EVENT_EDGE`, halo) sees the same set.
- **FL9 First step shows the box.** A role becomes used with its first
  `step-start`. The next snapshot changes `flowSource`, so the memo key
  changes and the chart redraws with the new box. No extra code is needed.

## Changes per module

### `agile-team/runner/agile_team/dashboard/snapshot.py`

Import `STEP_ROLES` beside `StoryStatus`: `from ..gates import STEP_ROLES, StoryStatus`.

```python
GENERIC_DEVELOPER = STEP_ROLES["implement"]  # "developer": stands for the repo's developer roles

def _assigned_developers(state: RunState) -> frozenset[str]:
    """Every story's developer and PO-chosen developer that is set (FL7a)."""

def _routed_roles(files: RunFiles) -> frozenset[str]:
    """Roles the repo's pipeline steps route to; `developer` → the assigned ones, or itself if none (FL7a)."""

def _stepped_roles(events: list[dict]) -> frozenset[str]:
    """Roles with at least one `step-start` event (FL7b)."""

def _used_roles(files: RunFiles) -> frozenset[str]:
    """`_routed_roles | _stepped_roles` (FL7)."""

def _roles(files: RunFiles) -> list[dict]:
    """Enabled roles, each with `used` (FL7)."""
    # {**role, "used": role["name"] in used} for each found role
```

`_role` is unchanged, and so is its other caller `_configured_model`. In
`_routed_roles`, a pipeline step missing from `STEP_ROLES` routes to
nothing. Use `.get`. The generic developer is replaced only when it is
routed, so a pipeline without `implement` adds no developer roles.

### `agile-team/runner/agile_team/dashboard/index.html`

- CSS line `.flow svg { … }` → `.flow svg { max-width: none; display: block; margin: 0 auto; }` (FL5).
- New constants near `MERMAID_URL`:
  ```js
  const FLOW_FONT_PX = 16;
  const MERMAID_OPTIONS = { startOnLoad: false, securityLevel: "strict", theme: "base", flowchart: { useMaxWidth: false } };
  ```
- `/** Mermaid's initialise options for the theme colours `vars` (FL5). */ function mermaidConfig(vars)` returns `{ ...MERMAID_OPTIONS, themeVariables: vars }`.
- `themeVars()` gains `fontSize: \`${FLOW_FONT_PX}px\``.
- `drawFlow`: `mermaid.initialize(mermaidConfig(vars))`.
- `/** The dimmed class: colour only, never opacity (FL1, FL2). */ function idleClassDef()` returns
  `` `classDef idle fill:${cssVar("--surface-2")},stroke:${cssVar("--grid")},color:${cssVar("--muted")}` ``.
- `flowSource`: replace the literal `"classDef idle opacity:0.55"` with `idleClassDef()`.
- `/** A role's stats for the scope, or "idle" when it has none (FL4). */ function statsText(view, ctx, name)`.
  `nodeLabel` uses it in place of its `total` local.
- `ringRoles(view)`: filter `view.roles` by `r.used !== false` before mapping to names (FL8).

Nothing else changes. `flowClassLines`, `touchedFocus`, the halo and the
dots stay as they are.

## Known limit

The node harness has no layout engine and Mermaid is loaded from a CDN, so
no unit test can measure label and node bounding boxes. AC4 is pinned at the
cause (FL1, FL2, FL5), on the hidden-then-shown path. The geometric check is
done by the customer proxy in a browser.
