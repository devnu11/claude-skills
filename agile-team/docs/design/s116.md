# s116 design: the dashboard fixture is rebuilt from source sections

Story: [.team/stories/s116.md](../../../.team/stories/s116.md).
Requirement: [REQ-006](../requirements/REQ-006.md) (s116/AC1, AC2, AC3).
ADR: [ADR-0061](../../../.team/adr/0061-dashboard-fixture-built-from-source-sections.md).
Developer: `developer-cli`.

## The bug

`scripts/make_dashboard_fixture.py` has two halves that no longer fit
together:

- A seeded random "fake run" generator (lines 1–528). Its output is used only
  when `snapshot.json` has no `upstream` key, and the committed file has had
  one since s29. So the generator is dead code.
- `starting_point()` + `add_live()`. These read the **existing**
  `snapshot.json`, keep only the events with `at <= CURATED_END`, and
  regenerate the "live tail" (the events after `CURATED_END`, `turns`,
  `heartbeat`, `health`, `tools`, `generated_at`).

Since then, several stories have hand-edited the fixture:

- curated events after `CURATED_END`: `e87b`, `opinion-o1..o3`,
  `opinion-act-a1`, `e101s1..s3`, `e101c`, `e102`, `e104`, `e105`;
- fields added to the live events: `rate`, `mono`, `step`;
- a heartbeat at `version` 2 with `mono`, `slept`, `stages` and `rate`.

A rebuild would drop or revert all of these (s114 review, D1). The script
can't rebuild the fixture, so people hand-edit it.

## Rules

| # | Rule | AC |
|---|---|---|
| R1 | The fixture's source is **one JSON file per top-level snapshot key**, in `agile-team/runner/scripts/dashboard_fixture/<key>.json`. Each file holds that key's value exactly as the fixture has it: `generated_at.json` holds the bare number `1791473160.0`, and `events.json` holds the whole list. | AC1 |
| R2 | The script **never reads** `snapshot.json`. The output depends only on the section files and `SECTIONS`, so what the existing file holds doesn't matter. Nothing is filtered by time: `CURATED_END`, `add_live`, `starting_point`, the live generators and the random fake run are all deleted. | AC1 |
| R3 | `SECTIONS` (a tuple in the script) fixes the top-level key order. The `*.json` files in the source directory must be exactly `SECTIONS`. If a section is missing or a file is unknown, the build fails with a `FixtureSourceError` that names every missing and every unknown file. Nothing is written in that case, so a new key can't be silently dropped. | AC1 |
| R4 | Output text is `json.dumps(snapshot, indent=1)` with the stdlib defaults (`ensure_ascii=True`, separators `", "`/`": "`) and **no trailing newline**. That is the committed file's current format. The fixture is pure ASCII today. | AC2 |
| R5 | No randomness, clock or environment input. Two runs give byte-identical files. | AC2 |
| R6 | **This story does not change the fixture's content.** After the developer seeds the sections from the current `snapshot.json` (see "Seeding"), a rebuild must leave `snapshot.json` byte-identical (`git diff` empty on it). If a format detail makes the bytes differ, the parsed JSON must still be equal (`json.loads(old) == json.loads(new)`), and the rebuilt bytes are committed. | AC1, AC2 |
| R7 | Changing the fixture from now on means editing `scripts/dashboard_fixture/<key>.json` (and `SECTIONS` for a new or removed key), then running the script. Never hand-edit `snapshot.json`. The script's docstring, `docs/guidelines.md` and `reference/protocol.md` say this; the architect has already updated the two docs. | AC3 |

## Module: `agile-team/runner/scripts/make_dashboard_fixture.py` (rewritten)

Replace the whole file. Stdlib only (`json`, `sys`, `pathlib`, `typing`). It
has no module-level side effects, so tests can import it. House rules apply:
a docstring on every function, at most 8 lines and 2 parameters each.

Module docstring (AC3, word for word or close):


## Data: `agile-team/runner/scripts/dashboard_fixture/*.json` (new, 23 files)

There is one file per `SECTIONS` name, with nothing else in the directory.
Each file's format is `json.dumps(value, indent=1) + "\n"`. That format only
makes the source easy to read; the output doesn't depend on it.

### Seeding (once, in the implement step)

Split the current `snapshot.json` into the 23 files with a one-off command
(not committed; do not add a `split` mode to the script, because it would
invite the hand-edit-then-split workflow R7 forbids). Then run the script on
the fixture and check R6. Before seeding, re-read `snapshot.json` from the
branch tip. Another story in the dashboard sprint may have changed it, and
whatever it holds at that moment becomes the source.

- `reference/protocol.md`, Dashboard section: the same rule, next to "The
  contract is …".
- `docs/architecture.md`: the story index row.

## Tests: `agile-team/runner/tests/e2e/test_dashboard_fixture_e2e.py` (new)

These are e2e tests: they read real files and run the script as a process.
Unit tests may touch no real file (s71), and the section files are not
package data. Load the script with
`importlib.util.spec_from_file_location("make_dashboard_fixture", <runner>/scripts/make_dashboard_fixture.py)`,
and run it with `subprocess.run([sys.executable, str(script), str(out)], check=True)`.

| # | Test | AC |
|---|---|---|
| T1 | **Committed equals rebuild.** `build(SOURCE) == FIXTURE.read_text()`. On failure, the message says to edit `scripts/dashboard_fixture/` and run the script. | AC2 |
| T2 | **Twice is byte-identical.** Run the script as a process twice into `tmp_path / "a.json"` and compare the bytes after each run. Also run once into `b.json` and compare `a` with `b`. | AC2 |
| T3 | **The existing file is ignored.** Write `not json` to `tmp_path / "out.json"`, run the script into it, and get `build(SOURCE)`. Do the same with a valid snapshot whose `events` are `[]`. | AC1 |
| T4 | **Nothing is filtered.** The rebuilt `events` equal `events.json` in full. At least one event has `at > 1791472260.0` (the old `CURATED_END`), and `e105` is present. | AC1 |
| T5 | **Key order.** `list(json.loads(build(SOURCE))) == list(SECTIONS)`. | AC1 |
| T6 | **Source mismatch fails and writes nothing.** Copy `SOURCE` to `tmp_path / "src"`, delete `health.json` and add `extra.json`. `load_sections` raises `FixtureSourceError`, and the message holds `health.json` and `extra.json`. `main` with `SOURCE` patched to that copy returns 1 and leaves a pre-written output file unchanged. | AC1 |
| T7 | **Docs say it.** The module docstring holds `never edit it by hand` and `scripts/dashboard_fixture/`. `docs/guidelines.md` and `reference/protocol.md` each mention `scripts/dashboard_fixture/` and `make_dashboard_fixture.py`. | AC3 |
| T8 | **No trailing newline, ASCII only.** The rebuilt text doesn't end in `\n` and encodes as ASCII. | AC2 |

The existing fixture tests (`test_snapshot.py`, `test_s114.py` and so on)
don't change. The fixture's content doesn't change (R6).

## Out of scope

- Generating any section from code (turns, heartbeat sums). Every section is
  now plain data (ADR-0061).
- Changing the fixture's content or shape.
