# s53 design: the PO holds, releases and asks to cancel a story

Story: `.team/stories/s53.md`. No new ADR: this follows the s83 desk pattern (a pure rules
module, plus a small class that does the I/O between steps) and the s51 refusal helper
(`priority.first_refusal`). No new dependency.

## Rules

| # | Rule | AC |
|---|------|----|
| H1 | **A PO hold is its own field.** `StoryState.po_hold: PoHold \| None` (kind, reason, question). It is not the hand-over hold `StoryState.hold`. `continue_story` stays as it is: it clears `hold`, never `po_hold`. | AC1, AC2 |
| H2 | **Hold.** `hold_story(story, reason)` sets `po_hold = PoHold(HoldKind.HOLD, reason.strip())`. It posts nothing to the outbox. On a held story it replaces the reason, and the event's `before` keeps the old one. | AC1 |
| H3 | **A hold skips but doesn't move.** The router skips a story with a `po_hold` in `_movable`, `_escalated` and `_scribable`. `state.order`, `state.pulled` and the tier stay unchanged: `priority.held` does **not** count `po_hold`, so the story keeps its board position. | AC1 |
| H4 | **Board text.** `waits.WAITS` has two new rows at the top. A cancel request reads `cancel requested`, a PO hold reads `PO hold`, and each detail is the reason. `Wait.title` is `"<reason>: <detail>"` for those two rows (`TITLED`) and `str(reason)` for the others. The board pill reads `⏸ {wait.title}`, e.g. `⏸ PO hold: waits on s38`. Because these rows come first, a held story never reads "needs the human". | AC1, AC3 |
| H5 | **Release.** `release_story(story, reason)` sets `po_hold = None` and `hold = None`, sets `status = ACTIVE`, and sets `note = reason` (the next step's brief gets it, as with `pass_tests`). `step` is unchanged. The refusals (H8) make sure only `ACTIVE` or `BLOCKED` stories get this far. So when it succeeds, the story is never still held or blocked. | AC2 |
| H6 | **Request a cancel.** `request_cancel(story, reason)` posts one question, `Note("question", CANCEL_QUESTION, [story])`, and sets `po_hold = PoHold(HoldKind.CANCEL, reason.strip(), question=<mN>)`. Any PO hold it replaces shows in the event's `before`. The question names the story, so `relay.blocked_stories()` already makes the router skip it. | AC3 |
| H7 | **Only the human's answer settles a cancel.** `story_admin.Clerk.settle()` finds each story whose `po_hold.kind is CANCEL` and whose `po_hold.question` is in `relay.answers()`, then applies `OUTCOMES[decision(answer.text)]`. **cancel**: `cancel(state, story)`. **keep**: `po_hold = None`, so the story carries on (its status is unchanged). **unclear** (any other text): `po_hold = PoHold(HOLD, UNCLEAR_ANSWER…)`, so the story stays held for the PO, who can release it or ask again. `story_admin.cancel` is the only code that assigns `StoryStatus.CANCELLED`. No tool calls it, and its one caller is `settle`. | AC3 |
| H8 | **Refusals, in order** (one helper, the rows in `TOOLS[act].checks`; the first refusal wins). Shared checks: unknown story (`UNKNOWN`), then a blank reason (`NO_REASON`), then a finished story (`FINISHED_TEXT`: done or cancelled). **hold**: a cancel request is pending (`CANCEL_PENDING`). **release**: an open question names the story (`ASKED`, which names every id: "answer m12 instead"); the story is `NEEDS_MANAGER` (`MANAGER_WAIT`); no `po_hold` and not `BLOCKED` (`NOTHING_HELD`). **request_cancel**: a cancel request is pending (`CANCEL_PENDING`); the story has commits and the reason says nothing about its code (`CODE_UNSAID`). A refusal changes nothing, saves nothing and emits nothing. | AC2, AC3, AC5 |
| H9 | **Settle before acting.** `Clerk.run` calls `settle()` before it checks anything. `Router._tick` calls `clerk.settle()` right after `desk.apply()`. `Tools.wait_for_answers` calls it after polling, before it reads the answers. So an answered request is settled before any tool can act on that story. | AC3 |
| H10 | **One event per success.** Kind `story-admin`. A tool writes role `product-owner` and data `{"tool", "reason", "question", "before", "after"}`. A settle writes role `None` and data `{"tool": "answer", "reason", "question", "answer", "decision", "before", "after"}`. `before`/`after` = `facts(story)`: `{"status", "step", "sprint", "hold", "po_hold"}`. Each success also saves the state once. | AC5 |
| H11 | **Cancelled is finished.** `StoryStatus.CANCELLED = "cancelled"`. `gates.FINISHED = {DONE, CANCELLED}` replaces the "is it done" test in ranking, queue, plan, pulls, order refusals, `begin_sprint`, `open_ids`, `_in_backlog`, `waits.wait`, and snapshot `tier`/dependency keys. `cancel()` also removes the id from `state.order`, `state.pulled`, `state.human_order` and `state.scribe_due`, and sets `sprint = None`, `po_hold = None` and `hold = None`. It keeps the story file, its commits, `code_commits` and its events. | AC3 |
| H12 | **The router never routes a cancelled story.** `_movable` needs `ACTIVE` and `_escalated` needs `NEEDS_MANAGER`. `_scribable` also checks `po_hold is None`, and `cancel` removes the story from `scribe_due`. `dispatch_refusal` refuses `run_role` on it ("was cancelled by the human"), and `ruling_refusal` refuses a ruling or fault on any finished story. This holds after a resume, because the status is saved. | AC3, AC7 |
| H13 | **Labels.** `backlog.label`: `cancelled` when the status is `CANCELLED` or the legacy hold text starts with `cancelled` (B3 kept). Otherwise `cancel requested` when `po_hold.kind is CANCEL`, then `held` when `priority.held(story)` or `po_hold`, else `""`. The Backlog tab lists cancelled stories in a read-only **Cancelled** group after Backlog, with no move handles. They leave the queue, so they have no position. | AC3 |
| H14 | **AC6's third bullet falls with AC4.** `change_acceptance_delivery` is not built. The PO role file doesn't name it. | AC4, AC6 |

Known limits:
- A story that `depends_on` a cancelled story keeps waiting (`dependencies.waiting_on` still asks for done). The PO edits that story's frontmatter.
- The timeline's folded Done group (s100) folds `done` only. A cancelled story's timeline stays unfolded.
- An unclear answer (H7) uses up the question. The PO asks again with `request_cancel`.

## Texts (exact)

`story_admin.py`:

```python
UNKNOWN = "unknown story {story!r}; open it with open_story"
NO_REASON = "a reason is required"
FINISHED_TEXT = "story {story} is {status}; there is nothing to {verb}"
CANCEL_PENDING = (
    "story {story} already waits on the human's answer to {question} about cancelling it; "
    "answer {question} instead"
)
ASKED = "story {story} has an open question; answer {ids} instead"
MANAGER_WAIT = "story {story} waits on the Manager (round cap or repeated setback); run the manager on it"
NOTHING_HELD = (
    "story {story} has no PO hold and is not blocked; nothing to release "
    "(continue_story releases a hand-over hold)"
)
CODE_UNSAID = (
    "story {story} has commits ({count}); say in the reason what happens to its code "
    "(kept, reverted by a new story, …)"
)
CANCEL_QUESTION = (
    'Cancel story {story} ("{title}")? The PO asks because: {reason} '
    'Answer "cancel" to cancel it or "keep" to keep it.'
)
UNCLEAR_ANSWER = 'the answer to {question} was neither "cancel" nor "keep": {answer}'
CODE_WORDS = ("code", "commit")
ANSWER_STRIP = " \t\n.!\"'"
```

`FINISHED_TEXT`'s `verb` is `TOOLS[act].verb` ("hold", "release", "cancel"). `ASKED`'s `ids` are the open question ids that name the story, joined by `", "`, in outbox order. `CODE_UNSAID` applies when `priority.started(story) or story.code_commits`. `count` is `len({story.commit, *story.code_commits} - {None})`. The reason passes when it contains any `CODE_WORDS` entry, matched case-insensitively.

## Per module

### New `agile_team/holds.py` (pure, no imports from the package)

```python
class HoldKind(StrEnum):
    """What a PO hold is for; the value is the board text."""
    HOLD = "PO hold"
    CANCEL = "cancel requested"

@dataclass
class PoHold:
    """The PO's hold on a story: kind, reason and, for a cancel request, its question id."""
    kind: HoldKind
    reason: str
    question: str | None = None
    def __post_init__(self) -> None: ...      # self.kind = HoldKind(self.kind)
    @property
    def shown(self) -> str: ...               # f"{self.kind}: {self.reason}"
```

### `agile_team/priority.py`

- `key`, `queue`, `plan` and `_pullable` use `story.status in FINISHED` / `not in FINISHED`.
- `order_refusal`: after the done check, refuse cancelled ids with `CANCELLED_IDS = "cancelled stories can't be ordered: {ids}"`.

### `agile_team/dependencies.py`

### `agile_team/waits.py`

- `WaitReason.PO_HOLD = "PO hold"`, `WaitReason.CANCEL_REQUESTED = "cancel requested"`.
- `TITLED = frozenset({WaitReason.PO_HOLD, WaitReason.CANCEL_REQUESTED})`.
- `Wait` gains `title: str` (third field).
- Two `WAITS` rows go first, cancel before hold:
  `WaitRule(CANCEL_REQUESTED, lambda s, a: _po_kind(s) is HoldKind.CANCEL, _po_reason)` and
  `WaitRule(PO_HOLD, lambda s, a: _po_kind(s) is HoldKind.HOLD, _po_reason)`.
  `_po_kind(story) -> HoldKind | None` and `_po_reason(story) -> str` are small helpers.
- `wait`: return `None` when `story.status in FINISHED`. Build the title with `_title(reason, detail) -> str`: `f"{reason}: {detail}"` when the reason is in `TITLED`, else `str(reason)`.

### `agile_team/backlog.py`

- `CANCEL_REQUESTED = "cancel requested"`. `label(story)` follows H13. The checks go into a small `LABELS: tuple[tuple[str, Callable[[StoryState], bool]], ...]` table: the first match wins, else `""`.

### New `agile_team/story_admin.py` (rules pure; `Clerk` does the I/O)

Imports: `from . import priority`, `from .dispatch import Runtime`, `from .events import Event, EventKind`, `from .gates import FINISHED, StoryState, StoryStatus`, `from .holds import HoldKind, PoHold`, `from .relay import Answer, Note`, `from .state import RunState`.

```python
class Act(StrEnum):
    """The three tools; values are the MCP tool names."""
    HOLD = "hold_story"
    RELEASE = "release_story"
    REQUEST_CANCEL = "request_cancel"

class Decision(StrEnum):
    CANCEL = "cancel"
    KEEP = "keep"
    UNCLEAR = "unclear"

DECISIONS = {"cancel": Decision.CANCEL, "keep": Decision.KEEP}

@dataclass(frozen=True)
class Case:
    """One tool call: the act, the story id, the reason, the story (None if unknown) and
    the open question ids naming it."""
    act: Act
    story_id: str
    reason: str
    story: StoryState | None
    asked: tuple[str, ...]

@dataclass(frozen=True)
class Change:
    """What a successful call applies: the stripped reason and the question posted, if any."""
    reason: str
    question: str | None = None

Check = Callable[[Case], str | None]

@dataclass(frozen=True)
class Tool:
    """One row of TOOLS: its checks, the question it posts, its effect, the result status, its verb."""
    checks: tuple[Check, ...]
    note: Callable[[Case], Note | None]
    effect: Callable[[StoryState, Change], None]
    status: str          # "held" | "released" | "cancel requested"
    verb: str            # "hold" | "release" | "cancel"

SHARED: tuple[Check, ...] = (unknown_refusal, reason_refusal, finished_refusal)
TOOLS: dict[Act, Tool]   # HOLD: (pending_refusal,); RELEASE: (asked_refusal, manager_refusal,
                         # nothing_refusal); REQUEST_CANCEL: (pending_refusal, code_refusal)

def refusal(case: Case) -> str | None:
    """H8: the first refusal of SHARED + TOOLS[case.act].checks (priority.first_refusal)."""

def facts(story: StoryState) -> dict[str, Any]:
    """H10: status, step, sprint, hold and po_hold (asdict or None)."""

def hold(story: StoryState, change: Change) -> None: ...          # H2
def release(story: StoryState, change: Change) -> None: ...       # H5
def request(story: StoryState, change: Change) -> None: ...       # H6 (question from change)
def no_note(case: Case) -> Note | None: ...                       # None
def cancel_note(case: Case) -> Note: ...                          # CANCEL_QUESTION, [story]

def decision(text: str) -> Decision:
    """H7: DECISIONS[text.strip(ANSWER_STRIP).lower()], else UNCLEAR."""

@dataclass(frozen=True)
class Settled:
    """An answered cancel request: the story and the human's answer."""
    story: StoryState
    answer: Answer

def answered(state: RunState, answers: dict[str, Answer]) -> list[Settled]:
    """Stories with a CANCEL po_hold whose question has an answer, in state order."""

def cancel(state: RunState, settled: Settled) -> None:
    """H11: the only place a story becomes CANCELLED."""
def keep(state: RunState, settled: Settled) -> None: ...          # po_hold = None
def unclear(state: RunState, settled: Settled) -> None: ...       # HOLD with UNCLEAR_ANSWER

OUTCOMES: dict[Decision, Callable[[RunState, Settled], None]]

@dataclass
class Clerk:
    """Runs the PO's story admin tools and settles answered cancel requests (H7-H10)."""
    runtime: Runtime

    def run(self, act: Act, args: dict[str, Any]) -> dict[str, Any]:
        """Settle, then refuse (dispatch.refused) or apply, post, save and emit once."""

    def settle(self) -> list[str]:
        """Apply every answered cancel request; save and emit per story; the ids settled."""
```

`Clerk.run` flow (no branch per tool):
1. `settle()`, then `case = self._case(act, args)`. `asked` comes from `rt.relay.open_questions()` where `story_id in m.stories`.
2. If `refusal(case)` returns a reason, return `refused(reason)`.
3. `before = facts(story)`. `note = TOOLS[act].note(case)`. `question = rt.relay.post(note).id if note else None`.
4. `TOOLS[act].effect(story, Change(case.reason.strip(), question))`, `rt.save()`, emit the event (H10).
5. Return `{"status": row.status, "story": id, "step": story.step, "story_status": str(story.status), "question": question}`.

`Clerk.settle` reads `rt.relay.answers()` once. For each `Settled`: `before = facts`, then `OUTCOMES[decision(...)](state, settled)`, then emit (H10). It saves once when there was anything to settle. It never marks answers delivered: the router still gives the answer to the PO as a normal human message.

### `agile_team/po_tools.py`

- Import `from .story_admin import Act, Clerk`.
- Three one-line methods on `Tools`, each `return text_result(Clerk(self.runtime).run(Act.X, args))`: `hold_story`, `release_story`, `request_cancel`.
- `wait_for_answers`: after `await self._poll(...)`, call `Clerk(self.runtime).settle()`.
- `SCHEMAS`, three rows after `continue_story`, each with schema `{"story": str, "reason": str}`:
  - `hold_story`: "Hold a story that isn't done or cancelled, with a reason: the router skips it and it keeps its place. No question is asked; holding again replaces the reason. Use this instead of a parked ask_user."
  - `release_story`: "Release your hold, or a blocked story with no open question, to the step it stopped at (status active); the reason goes to its next step's brief."
  - `request_cancel`: "Ask the human to cancel a story: it is held as cancel requested and the human gets one question (cancel / keep). Only their \"cancel\" answer cancels it; \"keep\" releases it. For a story with commits, say what happens to its code."

### `agile_team/roles/product-owner.md` (AC6)

Add a short "Story admin" list near the `continue_story` bullets:
- `hold_story(story, reason)` to park a story. Never park one with an `ask_user` nobody should answer.
- `release_story(story, reason)` to release your hold, or a blocked story with no open question. A refusal naming `mN` means the human's answer is due: relay it.
- `request_cancel(story, reason)` whenever anyone, you included, thinks a story should go. A role or the Manager that says so is telling you to call it. ## Test checklist

Unit, `tests/test_story_admin.py` unless noted:
1. Hold: a story gets `po_hold` (kind `PO hold`, stripped reason). Nothing is added to the outbox (AC7: a hold creates no question). One `story-admin` event and one save. Holding again replaces the reason, and the second event's `before.po_hold.reason` is the first reason.
2. Hold refusals: an unknown id, a blank reason (`"  "`), a done story, a cancelled story, a pending cancel request. Each leaves `state.to_json()` equal to before, with no event and no outbox line (AC7).
3. Release, s4's case: `BLOCKED`, `hold=None`, no question. The result is `released`, and the state shows `status == ACTIVE`, `po_hold is None`, `hold is None`, `note == reason`, and the step unchanged (AC2/AC7).
4. Release refusals: an open question naming the story (the text contains `answer m<N> instead`); `NEEDS_MANAGER`; an active story with no `po_hold`. Nothing changes. Property: for every success, `not (po_hold or hold or status is BLOCKED)`.
5. `continue_story` on a PO-held story leaves `po_hold` set (H1).
6. `request_cancel`: posts exactly one `question` naming the story with the `CANCEL_QUESTION` text, sets a `cancel requested` hold with that question id, and leaves the status unchanged. A story with commits and the reason "out of scope" is refused (`CODE_UNSAID`); the reason "its code stays; s99 replaces it" passes.
7. Settle: the answer `" Cancel. "` → `CANCELLED`, removed from `order`, `pulled`, `human_order` and `scribe_due`, `sprint None`, commits kept, one event with `decision: "cancel"`. The answer `"keep"` → `po_hold None`, status unchanged. The answer `"maybe"` → a `PO hold` with `UNCLEAR_ANSWER`. An unanswered question → nothing.
8. Only the answer cancels: no tool argument reaches `CANCELLED`. Check the `TOOLS` effects with any args, then grep-style: assert `story_admin.cancel` is the only function in the package that assigns `StoryStatus.CANCELLED` (`ast` walk over `agile_team/*.py`).
9. `Clerk.run` settles first: answer the question, then call `release_story`. The story is already cancelled, so the call is refused with `FINISHED_TEXT`.
10. Router (`tests/test_router*.py`): a held in-sprint story is skipped and the next one runs. A cancelled story is never picked after `state.save` + `state.load` (resume, AC7). `_tick` settles before `_news`.
11. `waits.wait`: PO hold → title `PO hold: <reason>`. A cancel request with its open question → `cancel requested: <reason>`, not `needs the human`. Finished → `None`.
12. `backlog.label` table: cancelled status, legacy hold text, cancel requested, PO hold → `held`, blocked → `held`, free → `""`.
13. `priority`: a cancelled story is not in `queue`/`plan`; `order_refusal` names it; a PO-held started story keeps its tier and rank (H3).
14. `state`: a round trip keeps `po_hold` (the kind is the enum); old JSON without `po_hold` loads `None`; `begin_sprint` skips cancelled stories.
15. `gates`: `dispatch_refusal` on a cancelled story; `ruling_refusal` on a cancelled story.
16. Snapshot: `po_hold` and `wait.title` keys; the fixture matches the build keys. `tests/test_snapshot.py::write_run` (owner: unit-tester) rebuilds each story's `po_hold` from the fixture, the same way it rebuilds `hold`: add `po_hold=PoHold(**s["po_hold"]) if s.get("po_hold") else None` to the `StoryState(...)` call (import `from agile_team.holds import PoHold`; `PoHold.__post_init__` turns the kind text back into the enum, as `state._nested` relies on). Without it the PO-held fixture story builds with `po_hold: null` and no wait, and `test_build_matches_fixture_shape` fails. The cancelled story and the `story-admin` event need no helper change: `StoryStatus(s["status"])` and the events file already carry them.
