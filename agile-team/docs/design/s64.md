# s64: A story's delivery must name a configured `[[delivery]]`

Developer: `developer-cli`. No ADR: this adds a refusal to an existing PO tool,
driven by config the runner already loads. No new dependency.

## Problem

`open_story` stores whatever `delivery` string the PO passes. s61 and s62 were
opened with prose ("agile-team runner (checkout guard)"). Nothing checked it
until the acceptance step, where `Config.delivery(name)` found nothing and the
Proxy was refused with `no [[delivery]] is configured for the customer proxy`
(`dispatch.py`, near line 479). The fault surfaced at the end of the pipeline.

## Rules

| # | Rule |
|---|------|
| V1 | One function decides whether a delivery name is acceptable: `Config.delivery_refusal(name)` in `agile_team/config.py`. It returns `None` (accept) or the refusal reason. Every path that sets a story's delivery calls it; none re-implements it. |
| V2 | An empty or missing name (`None` or `""`) is accepted, unchanged from today: at acceptance it still means "the first configured delivery" (`Config.delivery`). Changing that is out of scope. |
| V3 | A non-empty name is accepted only when it equals the `name` of a `Delivery` in `config.deliveries`, exactly: case-sensitive, no stripping, no parsing of the story file's prose. `"cli "` and `"CLI"` are refused when only `cli` is configured. |
| V4 | Refused, with deliveries configured: `UNKNOWN_DELIVERY.format(name=name, names=…)`, where `names` is the configured names in config order joined by `", "`. |
| V5 | Refused, with no `[[delivery]]` configured at all: `NO_DELIVERY.format(name=name)`. It lists no names. |
| V6 | `open_story` checks in this order: the id already exists (today's refusal, unchanged), then V1. A refused call changes nothing: no story in state, no `save()`, no `story-opened` event. The tool returns `refused(reason)` (`{"status": "refused", "reason": …}`). |
| V7 | A valid name (or empty, V2) opens the story exactly as today: same state, same event, same result `{"status": "opened", "step": first}`. |
| V8 | `open_story` is the only setter today. `StoryState(…, delivery=…)` is built in `po_tools.Tools.open_story` only; no CLI command or other tool sets or changes `StoryState.delivery`. Any future setter must call `Config.delivery_refusal` (V1); the reviewer checks this. |
| V9 | The check reads the config the runtime holds (`Runtime.config`); the config is reloaded on resume as today. No list of names is hard-coded anywhere. |

### Exact strings (`agile_team/config.py`, module constants)

```python
UNKNOWN_DELIVERY = "delivery {name!r} is not a configured [[delivery]]; use one of: {names}"
NO_DELIVERY = (
    "delivery {name!r} is not a configured [[delivery]]; .agile-team.toml configures none, "
    "so leave delivery empty or ask the human to add a [[delivery]]"
)
```

Example: `delivery 'agile-team runner (checkout guard)' is not a configured [[delivery]]; use one of: cli, web`.

## Changes per module

### `agile_team/config.py`

Add the two constants above, and a method on `Config` next to `delivery`:

```python
def delivery_refusal(self, name: str | None) -> str | None:
    """Why ``name`` cannot be a story's delivery, or None when it can (s64 V1-V5)."""
```

Sketch (one job, under 8 lines, no flags):

```python
if not name or self.delivery(name):
    return None
names = ", ".join(d.name for d in self.deliveries)
return UNKNOWN_DELIVERY.format(name=name, names=names) if names else NO_DELIVERY.format(name=name)
```

`self.delivery(name)` with a non-empty name is already the exact-match lookup
(V3); reuse it, do not write a second loop.

### `agile_team/po_tools.py`

- `Tools.open_story(self, args)`: replace the inline duplicate check with one
  call to a new private helper and keep the body short:

  ```python
  def _open_refusal(self, args: dict[str, Any]) -> str | None:
      """Why ``open_story`` must refuse ``args``, or None (duplicate id, then s64 V1)."""
  ```

  It returns `f"story {sid} already exists"` (unchanged text) when the id is
  in `state.stories`, else `self.runtime.config.delivery_refusal(args.get("delivery"))`.
  `open_story` returns `text_result(refused(reason))` when a reason comes back,
  and otherwise does exactly what it does today.
- `SCHEMAS["open_story"]` description becomes:
  `"Register a story; it starts in the backlog until start_sprint lists it. "`
  `"delivery must be the name of a configured [[delivery]] (empty = the first one); "`
  `"any other name is refused with the valid names."`
  The argument types stay `{"id": str, "title": str, "delivery": str}`.

No other module changes. `dispatch.py`'s acceptance-time refusal stays as the
backstop for stories already in state (repairing them is out of scope).

### `agile_team/roles/product-owner.md` (developer edits; outside the architect's scope)

How you work, step 2: after "`open_story` each one", add: "Pass `delivery` as
the exact `name` of a `[[delivery]]` in `.agile-team.toml` (or leave it empty
for the first one); prose is refused, and the refusal lists the valid names."

### Docs (architect, this step)

- `reference/protocol.md`: § deliveries ("Stories pick a delivery…") and the

- `SKILL.md`: step 8 states that a story's delivery must be a configured

## Test checklist (unit-tester; FAKE world, `make_runtime` has one delivery `cli`)

1. `Config.delivery_refusal`:
   - `"cli"` with `cli` configured → `None` (V3).
   - `None` and `""` → `None`, with and without deliveries (V2).
   - `"nope"` with `cli` and `web` configured → exactly
     `UNKNOWN_DELIVERY` text naming `cli, web` in config order (V4).
   - `"CLI"` and `"cli "` with `cli` configured → refused (V3).
   - `"cli"` with `deliveries=[]` → exactly `NO_DELIVERY` text; the reason
     contains no `use one of` (V5).
2. `Tools.open_story`:
   - valid `delivery="cli"` → `{"status": "opened", "step": "design"}`, story
     stored with `delivery == "cli"`, one `story-opened` event (V7).
   - no `delivery` key → opened, `delivery is None` (V2, V7).
   - prose delivery → `{"status": "refused", "reason": UNKNOWN_DELIVERY…}`;
     the story is not in state, no event emitted, state not saved (V6).
   - runtime whose config has no deliveries, named delivery → refused with
     the `NO_DELIVERY` text (V5, V6).
   - duplicate id with a bad delivery → the duplicate reason wins (V6 order).
3. Every setter path (AC2): `open_story` is the only one (V8); item 2 covers it.
4. `SCHEMAS["open_story"]` description mentions `[[delivery]]`.

Coverage stays at 95%+; ruff check and format clean.
