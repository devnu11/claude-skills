## Why each bug happens

| AC | today | cause |
|---|---|---|
| AC1 | The Board has a dashed "Backlog" column of every story with `sprint: null`. Its Done column holds every done story of every sprint. | `boardColumns` starts with `["backlog", "Backlog", …]`. ## Rules

### AC1: the Board holds the current sprint only

- **BD1 Membership.** A story is on the Board when
  `s.sprint === view.run.sprint && s.status !== "cancelled"`. Nothing
  else is on the Board: no backlog story, no story of an earlier sprint
  (done ones included), no cancelled story. All of those are on the
  Backlog tab only (its Backlog, Done and Cancelled groups). When
  `view.run.sprint` is null or 0, no story is on the Board. The equality
  alone is not enough: with no sprint, `null === null` would put every
  backlog story on the Board. So `onBoard` first checks
  `Boolean(view.run.sprint)` (design review, round 3).
- **BD2 Columns.** `boardColumns(view)` returns, in order, one column per
  `view.pipeline` step, then `["done", "Done", …]`. There is no `backlog`
  column. A step column holds the members whose `status !== "done"` and
  `step === <that step>`. Done holds the members whose `status === "done"`.
  Each column's predicate includes BD1. Column ids, labels, the `<h3>` count
  `<span>`, the `.empty` class and `storyCard` don't change.
- **BD3 Dead CSS.** Delete the `.col.backlog { … }` rule (`index.html:263`).
  Nothing renders that class any more.

### AC2: the badge counts the cards shown

- **BD4 One source.** Add `boardStories(view)`. It returns the stories the
  Board renders: `boardColumns(view).flatMap(([, , test]) => view.stories.filter(test))`.
  `renderTabs` uses `board: [boardStories(view).length, false]`. So the
  badge always equals the sum of the column counts, and the number of
  `.story` cards in `#board`. That includes a sprint story whose `step` is
  not an enabled pipeline step: it has no column, so it is not counted.
  Don't write a second filter: the badge must come from `boardColumns`.

### AC4: the empty Requirements tab says why

- **RQ1 Snapshot key.** `snapshot._run` gains a last key,
  `"requirements_dir"`. Its value is the requirements directory relative to
  the repo, in POSIX form:
  `(PurePosixPath(config.team.docs_dir) / REQUIREMENTS_DIR).as_posix()`.
  Import `REQUIREMENTS_DIR` from `agile_team.config` and `PurePosixPath`
  from `pathlib`. With `docs_dir = "agile-team/docs"` the value is
  `"agile-team/docs/requirements"`. It is computed, not read from disk, so
  it is there even when the directory doesn't exist. The fixture's `run`
  object gains `"requirements_dir": "docs/requirements"`, after `"backlog"`.
- **RQ2 Text.** Replace the constant `REQ_EMPTY` with a function,
  `reqEmpty(view)`. It returns this one line, character for character:

  ```
  No requirement files yet. They live in <code>${esc(dir)}/REQ-NNN.md</code>; story s1 introduces them.
  ```

  Here `dir = view.run.requirements_dir || "docs/requirements"` (ADR-0006:
  an older snapshot without the key still renders). The words are the
  human's, verbatim (AC4). The path is in `<code>`, as in the AC's
  backticks. `esc` is required (ADR-0005).
- **RQ3 Render.** In `renderRequirements`, the empty branch writes
  `` `<p class="empty">${reqEmpty(view)}</p>` `` to `#reqs`. Everything
  else stays as s5 U5 has it: `#req-tiles` and `#matrix-card` are hidden,
  the badge is 0, and story cards hide "AC x/y traced". With one or more
  requirements, the full view renders and the message is gone.

A sketch of BD1 and BD2. The developer may shape it differently, keeping
functions small:

```js
/** Whether story `s` is on the Board: in the current sprint and not cancelled (s121 BD1). */
const onBoard = (view, s) => Boolean(view.run.sprint) && s.sprint === view.run.sprint && s.status !== "cancelled";

function boardColumns(view) {
  const cols = view.pipeline.map((step) => [step, step, (s) => onBoard(view, s) && s.status !== "done" && s.step === step]);
  cols.push(["done", "Done", (s) => onBoard(view, s) && s.status === "done"]);
  return cols;
}
```
