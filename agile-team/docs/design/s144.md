# s144: A repo CLAUDE.md import that is not UTF-8 text is left out with a note

Story: `.team/stories/s144.md`. ADR: ADR-0073 (amended by s144).
Requirement: REQ-107 (s144/AC1, AC2, AC3). Developer: `developer-cli`.
Follows s142 (`agile-team/docs/design/s142.md`, its "Out of scope" gap).

## Rules

1. Every file the `Inliner` reads (the root `.claude/CLAUDE.md` and each
   import) is decoded as UTF-8 explicitly, on every platform:
   `system.read_bytes(path).decode("utf-8")`. It no longer goes through
   `system.read_text`, which uses the locale's encoding (cp1252 on Windows).
   So "not UTF-8 text" means the same thing on macOS, Linux and Windows.
   Line endings are kept as they are in the file (`\r\n` stays). The model
   reads both the same way, and the import pattern treats `\r` as whitespace.
2. An `@path` import that resolves to a file inside the repo whose bytes are
   not valid UTF-8 is replaced by one line:
   `(left out: @<path> is not UTF-8 text)`, where `<path>` is the import as
   written, the same as for the `OUTSIDE` and `REPEATED` notes. Nothing is
   raised. The text around the import and every other import are handled as
   before.
3. The check order in `Inliner._import` stays the same: outside (or `~`) →
   `OUTSIDE`; not a file → kept verbatim; already seen → `REPEATED`; else
   inline. The UTF-8 check comes last, when the file is read.
4. A file that is not UTF-8 is **not** marked seen. `Inliner.file` reads
   (decodes) the file *before* it adds the file to `seen`. So every import of
   the same binary file gets the `UNREADABLE` note, never
   `REPEATED` ("already included above" would be false).
5. The rule holds at any depth: a binary file imported by an imported file
   gets the note inside that file's inlined text.
6. The root `.claude/CLAUDE.md` itself is out of this story's scope. If it is
   not UTF-8, `repo_instructions` still raises `UnicodeDecodeError` as it
   does today. That file is the human's own, so a broken one should fail
   loudly, not drop every repo rule without a sign.

## Changes per module

### `agile-team/runner/agile_team/instructions.py`

New constant next to `OUTSIDE` and `REPEATED`:

```python
UNREADABLE = "(left out: @{path} is not UTF-8 text)"
```

`Inliner.file(self, path: Path) -> str`: same signature. Read first, then
mark seen, then substitute:

```python
def file(self, path: Path) -> str:
    """``path``'s text (resolved, inside ``root``) with its imports replaced; marks it seen.

    Raises ``UnicodeDecodeError`` (before marking) when the file is not UTF-8.
    """
    text = _utf8(path)
    self.seen.add(path)
    return _IMPORT.sub(lambda m: self._replace(m, path.parent), text)
```

`Inliner._import`: its last line becomes `return self._inline(path, target)`.

New private method:

```python
def _inline(self, path: str, target: Path) -> str:
    """``target``'s inlined text, or the ``UNREADABLE`` note when it is not UTF-8."""
    try:
        return self.file(target).strip()
    except UnicodeDecodeError:
        return UNREADABLE.format(path=path)
```

New module-level private function, after `_target`:

```python
def _utf8(path: Path) -> str:
    """The file's text decoded as UTF-8 on every platform (never the locale's encoding)."""
    return system.read_bytes(path).decode("utf-8")
```

Catch only `UnicodeDecodeError`. An `OSError` (a file that cannot be read)
still raises as before. `repo_instructions` does not change. No other module
changes. `system.py` and `tests/fake_system.py` already have `read_bytes`,
and the fake's `read_text` already decodes UTF-8, so no fake changes.

reusing its `write`, `inlined` and `prompt_for` helpers. Write the binary
file with `system.write_bytes(repo / "docs/logo.png", BINARY)`, where
`BINARY = b"\x89PNG\r\n\x1a\n\xff\xfe"` (`0x89` and `0xff` are not valid
UTF-8). Name each test after its rule. Leave every existing s142 test
unchanged.

- [ ] AC1, rules 2 and 3: `inlined(repo, "a @../docs/logo.png b")` returns
      exactly `"a (left out: @../docs/logo.png is not UTF-8 text) b"`, and
      nothing is raised.
- [ ] AC1, other text still loads: with `docs/a.md` = `"A-TEXT"`,
      `inlined(repo, "@../docs/logo.png\n@../docs/a.md\nTAIL")` contains the
      `UNREADABLE` note, `"A-TEXT"` and `"TAIL"`.
- [ ] Rule 4: importing the binary file twice gives the `UNREADABLE` note
      twice and no `"already included above"` note.
- [ ] Rule 5: `docs/a.md` = `"A-TEXT @logo.png"` imported from the root
      gives `"A-TEXT (left out: @logo.png is not UTF-8 text)"` in the output.
- [ ] Rule 1: a UTF-8 import with non-ASCII text (for example `"café ✓"`)
      is inlined exactly.
- [ ] AC2, a step's prompt is still built: following
      `test_no_settings_are_loaded`, write `.claude/CLAUDE.md` =
      `"INSTR @../docs/logo.png"` and the binary file, then
      `run(make_runtime(q), "architect")` with a `FakeQuery`. The step runs,
      and `q.calls[0]["options"].system_prompt` contains `"INSTR"` and the
      `UNREADABLE` note for `@../docs/logo.png`.
- [ ] Rule 6 (pins today's behaviour): a root `.claude/CLAUDE.md` written
      with `BINARY` makes `instructions.repo_instructions(repo)` raise
      `UnicodeDecodeError`.

## Out of scope

- A root `.claude/CLAUDE.md` that is not UTF-8 (rule 6).
- An import that cannot be read for an OS reason (permissions). It raises
  as before.
- Any other encoding (UTF-16, a BOM-led file decoded otherwise). Only UTF-8
  is text here. A UTF-8 BOM decodes and is kept as `﻿`.
