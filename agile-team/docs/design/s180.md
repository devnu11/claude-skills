## The decision: carry, don't defer

The story leaves the choice open: hold the runner's bookkeeping commits back
until a landing in flight completes, or let them happen and land the merge
under them. **We carry.** When a landing's CI is green and the sprint head
moved past the merge's first parent only by plain, unpushed commits, the
runner pushes the merge as it is. It then replays those commits on top of the
merge and moves the main checkout to the replayed tip. Why not defer:

- Landings run back to back when several stories are open, so a deferred
  intake, share, pick or storyless step could wait without end.
- Deferring has to stop many writers (the intake, the sharer, the PO's
  story-admin tools, storyless steps). One of them already running when
  the landing pushes would still move the head. The carry is one rule at the
  one place that reads the head.

The carry rewrites only commits that were never pushed. The remote sprint
branch only ever moves to a merge that passed landing CI, as before.

## Rules

| # | Rule |
|---|---|
| C1 | **The span.** For a landing merge `M` with first parent `B` and sprint head `H` (`Lander.sprint_head`), the *carried commits* are `git log --reverse B..H`, oldest first. If `B == H`, nothing is carried and the land goes on exactly as today. |
| C2 | **When a carry is refused.** A carry is refused, and the landing gives up its merge as today (`why: sprint head moved`), when any of these holds. The checks run in this order and the first one found is the refusal text. (a) `B` is not an ancestor of `H`: `CARRY_OFF_HEAD`. (b) A carried commit is a merge (`git rev-list --merges B..H`, the first one): `CARRY_MERGE`. (c) The sprint entry's `pushed` is set and is not an ancestor of `B`: some carried commit is already on the remote, `CARRY_PUSHED`. (d) An open story (status not in `gates.FINISHED`) has a `base_sha`, or a queued `rebase.onto`, that is a carried commit: `CARRY_FORKED`, naming the first such story by id order. (e) Replaying the commits onto `M` stops on a conflict: `CARRY_CONFLICT`. |
| C3 | **Replay in the land worktree.** `git worktree add --detach .team/run/land M`, then `git cherry-pick --keep-redundant-commits B..H` there. `--keep-redundant-commits` keeps a commit that becomes empty on top of `M`, so each old commit has exactly one copy. A conflict runs `git cherry-pick --abort` and removes the worktree. The new tip `T` is the worktree's HEAD. The worktree is always removed afterwards. The main checkout is not touched until C4. |
| C4 | **Order under the main lock** (`Lander.push_and_follow`; the lock is already held there). First prepare the carry (C1 to C3). On a refusal, give up the merge (C6) and push nothing. Then push the sprint branch to **`M`**, never to `T`, with `Lease(branch, pushed, M)`, and set `entry.pushed = M`. A refused push goes to `follow_remote` as today. Then move the main checkout: with nothing carried, `advance_to(M)` as today; with commits carried, `Upstream.reset_team_branch(H, T)` (`reset --keep`, refused when HEAD isn't `H`). A failed move halts as `halt_diverged` as today. Then remap (C5) and `record_checkout()`, so `entry.head` becomes `T`. |
| C5 | **Remap and log.** `moved = rewrite.pair(upstream.listing(f"{B}..{H}"), rewrite.Listing(M, upstream.listing(f"{M}..{T}")))`, then `rewrite.remap_state(state, moved)`. That covers `file_commits`, `code_commits`, `commit`, interruptions and the stack's start and end. Then one `landing-carried` event (actor `runner`, the landing story) with `{merge, from: H, to: T, commits: [{old, new, subject}]}`. The rest of the land is unchanged: the sprint PR, the story PR close, `story-landed` with `merge: M`, and `landed.merge == M`. |
| C6 | **Giving up names what moved the head (AC3).** `give_up(attempt, drop)` takes a `Drop`. The `landing-dropped` event gets `moved_by`: one `"<sha7> <subject>"` per commit of `B..H`, oldest first, with no cap. It also gets `refusal`: the carry's refusal text, `""` when there was none. The existing `merge`, `why` and `sprint_head` stay. A refused sprint push (`GIVE_UP_REFUSED`) has `moved_by: []` and `refusal: ""`: there the remote moved, not the local head. |
| C7 | **The drops reach the PO.** Each drop is also added to `attempt.dropped` as `{merge, why, moved_by, refusal}`. The land step's report gets `land.dropped` (the list) when it isn't empty, whatever the verdict. A new hand-over row `landing_dropped` (story scope) shows it, one line per drop: `- <merge12> (<why>); not carried: <refusal>; moved by: <c1>, <c2>`. A part is left out when it is empty. The row is informational: `handover.hold_reason` leaves it out (`UNHELD`), so it never sets `story.hold`. A revert landing's drops are in the `landing-dropped` events only; `refuse_revert`'s texts don't change. |
| C8 | **Resume.** `check_resume` (a pushed landing after a restart, or `continue_story` on a held CI) no longer needs `B == H`. It runs the cheap checks C2(a) to C2(d), with no replay, and gives up (C6) only when one of them refuses. Otherwise the landing waits for CI on `M` again. `push_and_follow` prepares the full carry under the lock later. |
| C9 | **Local mode.** `land_locally` does C4 without the push: under the lock, prepare the carry, give up on a refusal, else move the checkout (C4), remap, `record_checkout`. |
| C10 | **No new fork while a landing runs (keeps C2(d) rare).** The scheduler doesn't start a story `ROLE` step whose story has no worktree yet (`not story.worktree_head`, the same condition as `check_cap`) while a land task or a landing revert task is running. Such a step would fork or replay the story's branch from a head the carry is about to rewrite. It waits with `waits for the running landing before forking its branch` (`WaitReason.LANDING_FORK`). Stories that already have a worktree, storyless steps, the intake and shares don't wait. |
| C11 | **What doesn't change.** Landings stay one at a time. A refused push, a red or held CI, the 5-restart cap and `follow_remote` are as before. `story new` prints no sha: it only queues. A story-file or share commit made during a landing's CI wait can get a new sha when that landing completes. `StoryState.file_commits` holds the new sha, and the `landing-carried` event pairs old and new. The commits carried onto `M` are local until the next landing's push or the sprint end, as the runner's bookkeeping commits always were. |

AC map: AC1 is C1 to C5, C10 and C11. AC2 is the same path: a storyless step
holds the main lock (`Runtime.lock_for`), so `push_and_follow` waits for the
step's commit and then carries it. AC3 is C6 and C7.

## Changes per module

### `agile_team/landing_carry.py` (new)

Module docstring: "Carrying the runner's unpushed commits onto a landing merge
(s180, ADR-0093)." Imports: `Git` from `.git_ops`, `GitError` from `.git_ops`,
`Upstream`, `UpstreamError` from `.upstream`, `ListedCommit`, `list_commits`
from `.story_rebase`, `rewrite`, `FINISHED`, `StoryState` from `.gates`, and
`system`.

Constants (texts):

```python
CARRY_OFF_HEAD = "the sprint head {head} does not descend from the merge's base {base}"
CARRY_MERGE = "{commit} is a merge"
CARRY_PUSHED = "the remote already has {pushed}, which is past the merge's base {base}"
CARRY_FORKED = "story {story} was forked from {commit}"
CARRY_CONFLICT = "carrying {commit} onto {merge} stopped on a conflict in {files}"
CHERRY_PICK_ARGV = ("cherry-pick", "--keep-redundant-commits")
```

`{commit}` is always `format_commit(...)`, and shas are cut to 12 (`{head}`,
`{base}`, `{pushed}`, `{merge}`).

```python
@dataclass(frozen=True)
class CarrySpan:
    """A landing merge, its first parent, the sprint head and what the remote has."""
    merge: str
    base: str
    head: str
    pushed: str

@dataclass(frozen=True)
class Carry:
    """The commits to carry onto the merge and, once replayed, their new tip and pairs."""
    span: CarrySpan
    commits: tuple[ListedCommit, ...] = ()
    tip: str = ""                      # the new sprint head; the merge itself when nothing is carried
    moved: dict[str, str] = field(default_factory=dict)
    refusal: str = ""

@dataclass(frozen=True)
class Drop:
    """Why a landing gave up its merge, and what moved the sprint head (C6)."""
    why: str
    moved_by: tuple[str, ...] = ()
    refusal: str = ""
```

Pure functions:

- `format_commit(commit: ListedCommit) -> str`: `f"{commit.sha[:7]} {commit.subject}"`.
- `find_forked_story(stories: Iterable[StoryState], commits: tuple[ListedCommit, ...]) -> str`:
  C2(d). Returns the refusal text, or `""`. Stories are taken in id order
  (`sorted` by the numeric id, as `requirements` and `landing_queue` sort).
- `build_moved_drop(carry: Carry) -> Drop`:
  `Drop(GIVE_UP_MOVED, tuple(format_commit(c) for c in carry.commits), carry.refusal)`.
  `GIVE_UP_MOVED` moves here from `landing.py`, and `landing.py` imports it.
  Keep the name and the value `"sprint head moved"`.
- `describe_drop(drop: Drop, merge: str) -> dict[str, Any]`:
  `{"merge": merge, "why": drop.why, "moved_by": list(drop.moved_by), "refusal": drop.refusal}`.
- `remove_land_tree(git: Git, path: Path) -> None`: the body of today's
  `Lander.clear_tree`: `worktree remove --force`, then `system.remove_tree`
  if the path still exists. `Lander.clear_tree` becomes
  `await self.run_off(remove_land_tree, self.runtime.git, self.scratch_path)`.

`class Carrier`: git work, run in worker threads by the lander.

```python
class Carrier:
    """Checks, replays and adopts a carry (C2, C3, C4's move)."""
    def __init__(self, upstream: Upstream, tree: Path) -> None: ...
    def list_carried(self, span: CarrySpan) -> tuple[ListedCommit, ...]
    def find_refusal(self, span: CarrySpan) -> str
    def carry(self, span: CarrySpan, commits: tuple[ListedCommit, ...]) -> Carry
    def move_checkout(self, carry: Carry) -> bool
```

- `list_carried`: `()` when `span.base == span.head`, else
  `tuple(list_commits(upstream.git, f"{base}..{head}"))`.
- `find_refusal`: C2(a) with `upstream.is_ancestor(base, head)`. C2(b) with
  `git rev-list --reverse --merges base..head`; for the first merge, the
  subject comes from `git log -1 --format=%s`. C2(c) with
  `pushed and not upstream.is_ancestor(pushed, base)`. Returns `""` when all
  pass. Each check is its own small private method.
- `carry`: C3. Add the worktree at `span.merge`, then run
  `Git(tree).attempt(*CHERRY_PICK_ARGV, f"{base}..{head}")`. On a non-zero
  exit: the files from `diff --name-only --diff-filter=U`, the stopped commit
  from `rev-parse CHERRY_PICK_HEAD` (its subject from `log -1 --format=%s`),
  then `cherry-pick --abort`, and return
  `Carry(span, commits, refusal=CARRY_CONFLICT…)`. On success: `tip` is the
  tree's head, and `moved` is C5's `rewrite.pair`. A `finally` calls
  `remove_land_tree`.
- `move_checkout`: with no `commits`, return `upstream.advance_to(carry.tip)`.
  Otherwise call `upstream.reset_team_branch(span.head, carry.tip)` and
  return `True`. Return `False` on `UpstreamError` or `GitError`.

### `agile_team/landing.py`

- Import `Carrier`, `Carry`, `CarrySpan`, `Drop`, `GIVE_UP_MOVED`,
  `build_moved_drop`, `describe_drop`, `find_forked_story` and
  `remove_land_tree` from `.landing_carry`, and `rewrite`.
- `Attempt` gains `dropped: list[dict[str, Any]] = field(default_factory=list)`.
- `Lander.carrier` (property): `Carrier(self.runtime.upstream, self.scratch_path)`
  (the upstream asserted, as the existing `# type: ignore[union-attr]` call
  sites assume).
- `async def read_span(self, attempt: Attempt) -> CarrySpan`: the base from
  `rev-parse <merge>^1`, `head=self.sprint_head`, and
  `pushed=attempt.entry.pushed if attempt.entry else ""`.
- `async def check_carry(self, attempt: Attempt) -> Carry`: C1 and C2(a) to
  C2(d). It returns `Carry(span, commits, refusal=…)` with no tip, or with
  `tip=attempt.merge` when nothing is carried.
- `async def prepare_carry(self, attempt: Attempt) -> Carry`:
  `check_carry`. When that refused or carries nothing, return it; else
  `await self.run_off(self.carrier.carry, span, commits)`.
- `async def adopt_carry(self, attempt: Attempt, carry: Carry) -> dict[str, Any] | None`:
  `move_checkout` in a thread. On `False`, return
  `await self.halt_diverged(attempt, "")`. Otherwise, when commits were
  carried, `rewrite.remap_state(state, carry.moved)` and emit
  `LANDING_CARRIED` (C5). Then `self.runtime.record_checkout()` and return
  `None`.
- `check_resume(attempt)`: C8. `carry = await self.check_carry(attempt)`; if
  `carry.refusal`, `await self.give_up(attempt, build_moved_drop(carry))`.
- `give_up(self, attempt: Attempt, drop: Drop) -> None`: as today. The event
  data is `describe_drop(drop, merge) | {"sprint_head": self.sprint_head}`,
  and it appends `describe_drop(drop, merge)` to `attempt.dropped`.
- `push_and_follow(attempt)`: C4.

  ```python
  carry = await self.prepare_carry(attempt)
  if carry.refusal:
      await self.give_up(attempt, build_moved_drop(carry))
      return None
  refused = await self.push(Lease(entry.branch, entry.pushed, attempt.merge))
  if refused is not None:
      return await self.follow_remote(attempt)
  entry.pushed = attempt.merge
  return await self.adopt_carry(attempt, carry)
  ```
- `land_locally(attempt)`: C9, the same with no push, under `self.lock`.
  `record_landed` follows as today when `adopt_carry` returns `None` and
  `attempt.merge` is still set.
- `follow_remote`: `give_up(attempt, Drop(GIVE_UP_REFUSED))`.
- `is_on_head` goes: `check_carry` replaces each use. s163's tests that call
  it are rewritten for C1 and C2 (REQ-169 changed).
- `def add_dropped(self, attempt: Attempt, report: dict[str, Any]) -> dict[str, Any]`:
  C7. When `attempt.dropped` isn't empty,
  `report.setdefault("land", {})["dropped"] = attempt.dropped`, then return
  the report. `run_land` builds the attempt once and passes every return path
  through it. The waiting report of `find_wait` has no drops, so it passes
  through unchanged.

  these triggers out, and returns `None` when only they match.
- A new `Rule` at the end of `HANDOVERS`:
  `Rule(Trigger.LANDING_DROPPED, lambda r: bool((r.get("land") or {}).get("dropped")), "{story}: its landing gave up a merge and merged afresh:\n{land_dropped}")`.

  left out. `_land_fields` adds `land_dropped`: the lines joined by `"\n"`,
  only when `land.dropped` is present.
