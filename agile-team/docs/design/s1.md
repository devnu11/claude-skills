# s1: Requirements as structured files, with a design gate that traces every AC

The human re-planned s1 in t80. Requirements become files the runner parses
(`agile_team/requirements.py`). A CLI command checks them and prints the AC
coverage. The `design` gate bounces a story designed from s1 on until each of
its ACs is covered by an active requirement. The architect writes them; the
code reviewer and the Customer Proxy cite them. The dashboard's Requirements
tab already reads these files (s5 U5, s121); it now also leaves pre-s1
stories out of its gaps.

Developer: **developer-cli** (runner Python: a new `requirements.py`, `gates`,
`state`, `reverts`, `cli`, `dispatch`, three built-in role files). The small
`dashboard/snapshot.py`, `index.html` and fixture changes (T14–T16) are part
of the same step; they are a few lines each.

ADR: **ADR-0060** (format, coverage rule, the gate, `StoryState.trace`, the
CLI, brief sections). No new dependency (PyYAML is already used), no new
event kind, no new PO tool.

Seed (AC6): the architect has written `agile-team/docs/requirements/REQ-001.md`
to `REQ-005.md`, covering s1/AC1–AC8. `requirements check` on this repo must
print no problems and show every s1 AC covered.

## Rules

### File format (AC1)

- **T1 Where.** `<docs>/requirements/REQ-NNN.md`, i.e.
  `config.requirements_dir` (exists). Files are found with
  `system.glob(config.requirements_dir, "REQ-*.md")` (the same glob the
  snapshot uses) and handled in natural order of their names
  (`priority.natural` on the stem). A missing folder means no files.
- **T2 Shape.**

  ```markdown
  ---
  id: REQ-001
  title: Requirements are structured files
  status: active            # active | retired
  covers: ["s1/AC1", "s1/AC7"]
  ---

  The requirement in plain words.
  ```

  Other frontmatter keys are ignored. A ref is `sN/<ac id>`, matched in full
  by `REF = re.compile(r"(s\d+)/([A-Za-z][\w-]*)")` (so `s1/AC1`, `s94/A14c`).
- **T3 Checks, per file, in order.** Checks 1, 3 and 4 stop the file's read.
  All the others are reported. A failed 8 skips 9 and 10. Each problem is one
  line, `LINE = "{file}: {problem}"`, `{file}` repo-relative POSIX
  (`agile-team/docs/requirements/REQ-001.md`). `n` is 1-based.

  | # | `Problem` | Check | Text (`PROBLEMS[...]`) |
  |---|---|---|---|
  | 1 | `UNREADABLE` | the file reads (`OSError` → text `None`) | `cannot be read` |
  | 2 | `BAD_NAME` | the name fully matches `FILE_NAME = re.compile(r"REQ-\d{3,}\.md")` | `the file name must be REQ-NNN.md (REQ- and three or more digits)` |
  | 3 | `NO_FRONTMATTER` | `roles.split_frontmatter` finds frontmatter | `no YAML frontmatter; start the file with --- and the keys id, title, status and covers` |
  | 4 | `BAD_YAML` | it parses to a mapping (`RoleError`, `yaml.YAMLError`) | `frontmatter does not parse: {error}` |
  | 5 | `WRONG_ID` | `id` equals the file's stem | `id is {found!r}, not {name!r} (the file name)` |
  | 6 | `NO_TITLE` | `title` is a non-empty string | `title must be a non-empty string` |
  | 7 | `BAD_STATUS` | `status` is `active` or `retired` | `status is {found!r}; use active or retired` |
  | 8 | `BAD_COVERS` | `covers` is a list (may be empty) | `covers must be a list of "sN/ACk" strings` |
  | 9 | `BAD_REF` | item `n` is a string matching `REF` | `covers item {n}: {found!r} is not "sN/ACk"` |
  | 10 | `REPEATED_REF` | item `n` is not an earlier item | `covers item {n}: {ref!r} is listed twice` |
  | 11 | `NO_TEXT` | the body after the frontmatter is not blank | `the body is empty; state the requirement in plain words` |

  `{found!r}` of a missing key is `None`. A file with none of these problems
  gives a `Requirement`.
- **T4 Checks across files.** After every file is parsed:

  | # | `Problem` | Check | Text |
  |---|---|---|---|
  | 12 | `DUPLICATE_ID` | no other file claims the same frontmatter `id` (any file whose `id` is a string, clean or not; text equality) | `id {id!r} is also used by {others}` (`others`: the other files, `", "`-joined, natural order) |
  | 13 | `NO_STORY` | each ref's story has a story file (`<stories_dir>/<story>.md`) | `covers item {n}: {ref!r}: no story file for {story}` |
  | 14 | `UNREAD_STORY` | that story file reads clean (`story_spec.read`) | `covers item {n}: {ref!r}: the story file of {story} has problems ({first})` (`first`: its first problem line) |
  | 15 | `NO_AC` | the story has that AC id | `covers item {n}: {ref!r}: {story} has no AC {ac}; its ACs are {acs}` (`acs`: `", "`-joined, file order) |

  Checks 13–15 run only on files that gave a `Requirement`. A file's lines
  are its own (T3), then 12, then 13–15 in item order.
- **T5 Coverage.** A requirement *counts* when its file has no problem at all
  (T3 and T4) and its status is `active`. AC `sN/ACk` is covered by the
  counting requirements whose `covers` hold it. Retired requirements, and
  requirements with any problem, cover nothing.

### `agile-team requirements check` (AC2)

- **T6 Command.** `COMMANDS` gains
  `Command("requirements", "check the requirement files; print problems and AC coverage as JSON", cmd_requirements, ((("action",), {"choices": ["check"]}),))`,
  placed after `config`. It honours `--repo`, needs no runner and no key.
- **T7 Output.** One JSON object, `json.dumps(..., indent=2)`, keys in this
  order:

  ```json
  {
    "problems": ["agile-team/docs/requirements/REQ-007.md: status is 'draft'; use active or retired"],
    "coverage": {
      "s1": {"AC1": ["REQ-001"], "AC2": ["REQ-002"]},
      "s2": {"AC1": []}
    },
    "unreadable": {"s100": [".team/stories/s100.md: acceptance must be a non-empty list of {id, text, environment}"]}
  }
  ```

  `problems`: every T3/T4 line, files in natural order. `coverage`: every
  story file (`<stories_dir>/*.md`, by stem) that `story_spec.read` reads
  clean, in natural order; inside, each AC id in file order to the covering
  requirement ids in natural order (T5), `[]` when none. `unreadable`: every
  other story file, to its `story_spec` problem lines. Untraced ACs and
  unreadable story files are **not** problems (pre-s1 stories are untraced;
  many old story files have no `acceptance`).
- **T8 Exit.** 1 when `problems` is non-empty, else 0. The JSON is printed
  either way.

### The design gate (AC3)

- **T9 Which stories.** `gates.Trace` (StrEnum): `CHECKED = "checked"`,
  `EXEMPT = "exempt"`. `StoryState` gains a last field
  `trace: Trace = Trace.CHECKED`. So every story opened from now on
  (`open_story`) is checked. Loading `state.json`: a story with a `trace` key
  loads `Trace(value)`; one without (saved before s1) loads
  `_legacy_trace(data)`: `CHECKED` when `data.get("step") == "design"` and
  `not data.get("previous")` (never through a design step), else `EXEMPT`.
  This mirrors `_legacy_implemented`. No tool or role can change `trace`.
  `reverts.reverted_story` keeps it (`trace=story.trace`).
- **T10 When.** The gate runs on a `done` handoff at step `design` when the
  story is reverted (s124 R9, as today) or `story.trace is Trace.CHECKED`.
  `Pipeline._redesign_gate` becomes `_design_gate` (same place in
  `step_gate`'s chain) and calls `Checks.designed(story)`.
- **T11 What.** `Checks.designed(story)` lists **every** reason, in this
  order, and bounces to `design` (`Verdict.BOUNCE`, `Author.ROLE`, a round)
  with the reasons joined by `"\n"`; with none it passes:
  1. reverted and the After revert section missing: today's
     `REDESIGN_MISSING` text (from `redesigned`, unchanged);
  2. `trace is CHECKED`: `self.traced(story.id)` (T12).
- **T12 Trace reasons.** `requirements.design_reasons(checked, story)`
  returns `[]`, or a head line and one `- ` line per reason:

  ```
  s7's ACs must be traced to active requirements in agile-team/docs/requirements/ before design passes:
  - agile-team/docs/requirements/REQ-004.md: status is 'draft'; use active or retired
  - s7/AC2 is covered by no active requirement; add it to an active REQ's covers or write a new REQ-NNN.md
  ```

  Reasons, in order: (a) every problem line of every requirement file that
  *touches* the story (its raw text matches `rf"\b{re.escape(story)}/"`;
  a broken file still has text), files in natural order; (b) when the story
  has no story file: `no story file for {story}`; when its file has problems:
  each of its `story_spec` lines; (c) each AC, in file order, with no
  covering requirement (T5): `{story}/{ac} is covered by no active
  requirement; add it to an active REQ's covers or write a new REQ-NNN.md`.
  A problem in a file that doesn't touch the story is not a reason (it shows
  in `requirements check`).

### Who writes and cites them (AC4, AC8)

- **T13 Briefs.** The runner adds a `## Requirements` section to three
  roles' briefs on a story whose `trace is CHECKED` (none for `EXEMPT`):
  `requirements.BRIEFS = {"architect": design_section, "code-reviewer":
  coverage_section, "customer-proxy": coverage_section}`.
  `Runtime._attach_requirements(plan)`, called last in `_role_set_up`, looks
  the role up, and when found and `plan.story` is checked appends
  `"\n\n" + BRIEFS[role](requirements.load(self.config), plan.story.id)`.
  `coverage_section`:

  ```
  ## Requirements

  The story's ACs and the active requirements that cover them (`agile-team/docs/requirements/`). Cite these ids in your findings.

  - AC1: REQ-001 (Requirements are structured files)
  - AC2: untraced
  ```

  (when the story file has problems, the list is the one line
  `- the story file has problems; see the design gate`). `design_section` is
  `coverage_section` plus:

  ```

  Active requirements (add the story's ACs to one's `covers`, or write REQ-006.md, the next free id):

  - REQ-001 Requirements are structured files: s1/AC1, s1/AC7
  ```

  The next free id is one above the highest number among the files' stems
  (`REQ-001` with none), zero-padded to 3 digits (`next_id`).

  The proxy's section lists **every** AC of the story, the same as the code
  reviewer's (ruled at quality r2, D3). It is a lookup table for ids, not a
  list to try. The list to try stays the s95 `## Criteria for this step`
  section (`acceptance.BRIEF`, "Try only these acceptance criteria"), which
  lists only the ACs of the step's environment. One `coverage_section` serves
  both roles and `BRIEFS` keeps the `(Checked, str)` signature.

### `requirements.py`

```python
FILE_NAME = re.compile(r"REQ-\d{3,}\.md")      # fullmatch
REF = re.compile(r"(s\d+)/([A-Za-z][\w-]*)")    # fullmatch
LINE = "{file}: {problem}"

class Status(StrEnum):            # ACTIVE = "active", RETIRED = "retired"
class Problem(StrEnum):           # the 15 names of T3/T4, values snake_case
PROBLEMS: dict[Problem, str]      # the texts of T3/T4, exactly

@dataclass(frozen=True)
class Ref:
    story: str
    ac: str
    def text(self) -> str: ...                 # "s1/AC1"

def parse_ref(value: Any) -> Ref | None: ...   # None unless a str fully matching REF

@dataclass(frozen=True)
class Source:                     # text None: unreadable
    file: str                     # repo-relative POSIX
    text: str | None

@dataclass(frozen=True)
class Requirement:
    id: str
    title: str
    status: Status
    covers: tuple[Ref, ...]
    text: str                     # the body, stripped
    file: str

@dataclass(frozen=True)
class Parsed:
    source: Source
    claimed: str | None = None            # the frontmatter id when a str (T4 #12)
    requirement: Requirement | None = None  # set when T3 found nothing
    problems: tuple[str, ...] = ()

def parse(source: Source) -> Parsed: ...       # T3, pure

@dataclass(frozen=True)
class StoryAcs:
    story: str
    acs: tuple[str, ...] = ()
    problems: tuple[str, ...] = ()
    @classmethod
    def of(cls, story: str, read: story_spec.Read) -> StoryAcs: ...

@dataclass(frozen=True)
class Found:
    folder: str                           # repo-relative POSIX requirements dir
    sources: tuple[Source, ...]           # natural order
    stories: Mapping[str, StoryAcs]

@dataclass(frozen=True)
class Checked:
    folder: str
    files: tuple[Parsed, ...]             # problems include T4's
    stories: Mapping[str, StoryAcs]
    def problems(self) -> list[str]: ...
    def counting(self) -> list[Requirement]: ...   # T5
    def covering(self, ref: Ref) -> list[str]: ... # ids, natural order
    def touching(self, story: str) -> list[Parsed]: ...

def check(found: Found) -> Checked: ...                    # T4, pure
def coverage(checked: Checked) -> dict[str, dict[str, list[str]]]: ...
def report(checked: Checked) -> dict[str, Any]: ...        # T7
def design_reasons(checked: Checked, story: str) -> list[str]: ...  # T12
def next_id(checked: Checked) -> str: ...
def coverage_section(checked: Checked, story: str) -> str: ...      # T13
def design_section(checked: Checked, story: str) -> str: ...
BRIEFS: dict[str, Callable[[Checked, str], str]]

# the only I/O
def folder_of(config: Config) -> str: ...      # (PurePosixPath(docs_dir) / REQUIREMENTS_DIR).as_posix()
def sources(config: Config) -> tuple[Source, ...]: ...
def stories(config: Config) -> dict[str, StoryAcs]: ...  # glob stories_dir "*.md", story_spec.read each
def load(config: Config) -> Checked: ...
def trace_reasons(config: Config, story: str) -> list[str]: ...  # design_reasons(load(config), story)
```

Keep functions small (house rules); split `parse` into per-check helpers the
way `story_spec` does. `gates` must not import `requirements` (`requirements`
imports `priority`, which imports `gates`): the gate gets `traced` as a
callable, and `Trace` lives in `gates`.

### `gates.py` sketch

```python
def designed(self, story: StoryState) -> Outcome:
    """The design gate: the After revert section (R9) and the AC trace (s1 T11), every reason listed."""
    reasons = [*self._revert_reasons(story), *self._trace_reasons(story)]
    if not reasons:
        return Outcome(Verdict.PASS)
    return Outcome(Verdict.BOUNCE, "\n".join(reasons), "design", author=Author.ROLE)
```

`_revert_reasons` returns `[self.redesigned(story).reason]` when reverted and
that outcome bounces, else `[]`; `_trace_reasons` returns
`self.traced(story.id)` when `story.trace is Trace.CHECKED`, else `[]`.

## Existing tests

A test that drives a `done` design through a real `make_pipeline` on a
scratch repo now meets the trace gate. If one fails for that reason, give the
scratch repo a REQ file covering the story's ACs (or build the story with
`trace=Trace.EXEMPT` when tracing is not what it tests). Neither weakens it.
The fixture-contract test covers the new story key once the fixture has it.

The s95 dispatch test asserts `"- AC2:" not in prompt` for the `cli` proxy.
T13 makes that false on purpose: the proxy's `## Requirements` section now
lists AC2 too. The s95 property is that the **Criteria section** names only
the environment's ACs, so the assertion moves to that section: cut the prompt
from `## Criteria for this step` to the next `## ` heading (or the end) and
assert `"- AC2:" not in` that slice. Don't filter `": untraced"` lines (fixups
2e2a7b6/85fd2bb): that passes only while AC2 is untraced. The handoff that
makes this change cites T13 in `asserts`.
