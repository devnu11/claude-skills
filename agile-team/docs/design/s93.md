# s93 (A14a): "acceptance environment" replaces "delivery"

Story: `.team/stories/s93.md`. Plan: `.team/run/liaison/plans/acceptance-environments.md`.
Developer: `developer-cli`. No new ADR, no new dependency.

A rename with no behaviour change (AC1–AC4), plus one new environment kind,
`document` (AC5). After this story the old word lives in **one constant**,
`config.OLD_ENVIRONMENT_NAME`, and in **one test file**,
`tests/test_s93_environment_alias.py`.

## Rules

- **E1. The section.** The config section is `[[environment]]`
  (`config.ENVIRONMENT_SECTION = "environment"`). The old section name is
  `config.OLD_ENVIRONMENT_NAME = "delivery"`. This is the only place the
  literal appears in the runner.
- **E2. The alias.** `config.RENAMED_SECTIONS = {OLD_ENVIRONMENT_NAME: ENVIRONMENT_SECTION}`.
  `config.renamed(raw)` moves each old section key to its new key. `from_raw`
  builds the `Config` from `renamed(raw)`, so an old file loads the same
  environments as a new one.
- **E3. Both is an error.** If a file has both the old and the new key,
  `renamed` raises `ConfigError(BOTH_SECTIONS.format(old=…, new=…))`:
  `"[[{new}]] and [[{old}]] are both set; move every [[{old}]] into [[{new}]]"`.
  Load fails, as for any `ConfigError`.
- **E4. The warning.** `Config.warnings: list[str]` (default `[]`) holds
  `RENAMED_WARNING.format(old=…, new=…)` for each old key in the raw file:
  `"[[{old}]] is the old name of [[{new}]]; rename the section"`.
  `agile-team config check` prints each one as `warning: {text}` before any
  problems. Warnings never change the exit code: it is 0 when there are no
  problems, and 1 otherwise, as today.
- **E5. Old state loads.** A story in `state.json` with the old key loads into
  `StoryState.environment` (`state.STORY_RENAMES = {OLD_ENVIRONMENT_NAME: "environment"}`,
  applied in `_story`). The next save writes `environment`. If a story has both
  keys, `environment` wins. Downgrading a runner after this save isn't supported.
- **E6. DevOps may migrate.** `dispatch.DEVOPS_SECTIONS` holds
  `"toolchain"`, `ENVIRONMENT_SECTION`, `OLD_ENVIRONMENT_NAME` and `"tool"`.
  So a DevOps edit that renames the section is not quarantined.
- **E7. Reconfigure migrates.** `onboard` in `WriteMode.RECONFIGURE` merges
  the fresh data into `config.renamed(existing)`. That way an old file is
  rewritten as `[[environment]]` and never ends up holding both sections (E3).
- **E8. Wording.** Everything a person reads says "acceptance environment":
  refusal texts, prompts, role files, tool descriptions, the dashboard and the
  docs. The short form "environment" is fine after its first use in a text.
  Identifiers use `environment`. Table E10 lists every text.
- **E9. Repo vs skill.** Environments are the repo's data: names, prepare,
  url, commands, as many as the repo needs. Kinds are the skill's
  (`sandbox.ENVIRONMENT_KINDS`). Each kind decides the proxy's tools and
  sandbox, so the set is fixed: it is the security boundary. Every doc that
  introduces `[[environment]]` says this.
- **E11. The `document` kind (AC5).** It is for ACs with nothing to run
  (prompt, docs or design changes).
  - `sandbox.ENVIRONMENT_KINDS["document"]`: tools `("Read", "Grep", "Glob", "Write")`,
    with no Bash. `Write` is only for the report: the role's own write scope
    stays `.team/acceptance/**`. Foreground start, workdir `SANDBOX`, no MCP.
  - The guidance (exact text): `"Nothing runs for this story: it changes prompts, docs or designs. The presentation's workspace holds the changed files. Read the guide and those files, and judge each criterion against them. Do not ask the human anything."`
  - `presentation.PRESENTATIONS["document"] = Recipe(Need.WORKSPACE)`: guide
    plus files, `Check.FILES`, no service. So the e2e gate wants
    `PRESENTATION.md` and a non-empty `workspace/`, which holds the changed
    files the integration tester copies in.
  - It has no `seeds.DEFAULT_SEEDS` row and no config rule: it needs no url
    and no commands.
  - Nothing is posted to the human. `Dispatcher._manual_question` still posts
    only for kind `"manual"`, so this is unchanged code, pinned by a test.
- **E12. No behaviour change.** Every rename is a rename. Tests change only by
  renaming (identifiers, keys, file names, asserted texts per E10). The new
  tests cover E1–E7 and E11.

## Per-module additions (exact signatures)

`agile_team/config.py`:

```python
ENVIRONMENT_SECTION = "environment"
OLD_ENVIRONMENT_NAME = "delivery"  # the alias (s93 E1); the only place the old name appears
RENAMED_SECTIONS: dict[str, str] = {OLD_ENVIRONMENT_NAME: ENVIRONMENT_SECTION}
BOTH_SECTIONS = "[[{new}]] and [[{old}]] are both set; move every [[{old}]] into [[{new}]]"
RENAMED_WARNING = "[[{old}]] is the old name of [[{new}]]; rename the section"

def renamed(raw: dict[str, Any]) -> dict[str, Any]:
    """``raw`` with old section names moved to their new names (E2); both set is an error (E3)."""

def rename_warnings(raw: dict[str, Any]) -> list[str]:
    """One ``RENAMED_WARNING`` per old section name in ``raw`` (E4)."""

# Config gains: warnings: list[str] = field(default_factory=list)   (last field)
# from_raw: sections = renamed(raw); every section read from `sections`;
#           environments=[_environment(e) for e in sections.get(ENVIRONMENT_SECTION, [])],
#           warnings=rename_warnings(raw)
```

`agile_team/state.py`: `from .config import OLD_ENVIRONMENT_NAME, PIPELINE_STEPS`;
`STORY_RENAMES = {OLD_ENVIRONMENT_NAME: "environment"}`;
`def _renamed(data: dict[str, Any]) -> dict[str, Any]` returns the old keys moved
to new ones, with a new key that is already present winning (E5). `_story` calls it first.

`agile_team/cli.py`: `cmd_config_check` prints `warning: {w}` for each
`config.warnings`, then problems, then `config ok` / `N problem(s)`. The exit
code is unchanged. Keep the function under 8 lines, for example by extracting
`_print_lines(prefix, lines)`.

`agile_team/onboard.py`: the reconfigure merge reads
`merge_keep(config.renamed(tomllib.loads(...)), data)` (E7).

`agile_team/sandbox.py` and `agile_team/presentation.py`: one `"document"` row each (E11).

## Test checklist

New file `tests/test_s93_environment_alias.py` (the only test that may contain the old word):
- [ ] An `[[environment]]` file loads `Config.environments`, and `warnings == []`.
- [ ] An old-name file loads the same environments, and `warnings` holds the `RENAMED_WARNING` text.
- [ ] Both sections in one file make `config.load` raise `ConfigError` with the `BOTH_SECTIONS` text.
- [ ] `agile-team config check` on an old-name, otherwise valid file prints `warning: …` and `config ok`, and exits 0.
- [ ] `config check` on an old-name file that has a problem prints the warning and the problem, and exits 1.
- [ ] `state.load` of a story with the old key gives `StoryState.environment`. After a save, the file has `environment` and not the old key. With both keys, `environment` wins.
- [ ] `config_edit_allowed`: a working config that only renames the old section to `[[environment]]` is allowed.
- [ ] Reconfigure (`onboard`, `WriteMode.RECONFIGURE`) of an old-name config writes `[[environment]]` only and keeps its values.
- [ ] **Grep pin (AC3, runner part).** Walk `agile-team/runner/` files with suffix in `.py .md .toml .html .json .js .css .txt .yml .yaml .sh`. Skip any path with a part in `.venv`, `__pycache__`, `.pytest_cache`, `node_modules` or `htmlcov`. A case-insensitive search for the old word may hit only `runner/agile_team/config.py` (the `OLD_ENVIRONMENT_NAME` line) and this test file. It isn't pinned by this test, so the implement gate doesn't wait on docs. Design records (`docs/design/`) are history and keep the names of their time.
