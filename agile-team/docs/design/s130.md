# s130: Every test passes in any order

Story: `.team/stories/s130.md` · ADR: **ADR-0067** (builds on ADR-0066's
`clock_scan.Tree` split) · Requirements: REQ-026 (AC1, AC2), REQ-027 (AC3).

Developer: `developer-cli`, with **nothing to change**. Every change is a test
file or a `{ci}` file. As in s129, the developer confirms the suite passes and
hands off `done` with no files.

## Why the test failed

`tests/test_presentation.py` (L15-30) and `tests/test_service_presentation.py`
(L57-84, L162) keep the config in a module-level list, `CURRENT`. The `config`
fixture (and `test_make_pipeline_wires_the_trial`) write it, and `story_of()`
reads `CURRENT[0]`. So `story_of()` builds its story from whatever config the
last writer in that **process** left behind. Under `-n auto` that depends on how
xdist splits the tests. If nothing has written the list yet, `CURRENT[0]` raises
`IndexError`. If an earlier test wrote it, the story file goes into that test's
scratch directory. The suite always ran in file order, so nothing else could
expose it.

## How the story moves

1. **tests (unit-tester).** Writes the unit-tester rows. When it finishes, the
   suite is green. Without a source change, no test can go from red to green.
   Once the unit-tester has handed off `done` on a green suite, the PO moves
   the story on with `pass_tests(s130, "test-only story: AC1/AC2 fixes are green
   on write; random order comes from devops's pyproject change
   (design/s130.md)")`.
2. **devops (the PO runs it), only after step 1 lands.** If it ran earlier,
   every gate would run in random order while `CURRENT` still exists.
3. **implement (developer-cli).** Nothing to change. The gate now runs the
   full suite in random order. That is the first of the AC3 runs.
4. **e2e (integration-tester).** Writes the integration-tester rows.
5. A red gate under random order is a real order bug. Its output names the
   seed (`Using --randomly-seed=N`). The gate fix goes to the owner of the
   failing test. That owner replays the order with
   `pytest -q -p randomly --randomly-seed=N <files>`.

## Rules

- **R1 (AC1).** No test helper reads a config, a story or a path from
  module-level state. Helpers take the config as their first parameter.
- **R2 (AC2).** No function in a test file writes to a module-level mutable
  value or declares `global`. `state_scan` (below) is the definition, and it
  has **no exemption list**. A flagged write is fixed by moving the state into
  a fixture or a parameter. If a write can't be fixed that way, the tester
  disputes it. It is never exempted.
- **R3 (AC3).** pytest-randomly is installed in the dev group and is **on by
  default**. `addopts` doesn't change. `-p no:randomly` turns it off.
  `-p randomly` is accepted (it is already loaded). `--randomly-seed=N`
  replays an order.
- **Out of scope:** the unattended runner's suite (ADR-0067). Mutable module
  constants that the code under test mutates are also out of scope, because
  the scan can't see them.

### `tests/state_scan.py` (new, unit-tester)

Module docstring: "Find module-level mutable state that test code writes to
(s130, ADR-0067)." Imports: `ast`, `collections.abc.Mapping`,
`from .clock_scan import TESTS, Tree, tree_of`.

```python
MUTABLE_CALLS = frozenset({"list", "dict", "set", "bytearray", "defaultdict",
                           "deque", "Counter", "OrderedDict"})
MUTATORS = frozenset({"append", "extend", "insert", "pop", "remove", "clear",
                      "update", "setdefault", "add", "discard", "popitem",
                      "sort", "reverse", "appendleft", "extendleft", "popleft"})
HOOK_PREFIX = "pytest_"   # pytest hooks are not tests

def py_sources(tree: Tree) -> dict[str, str]
    """{posix path relative to TESTS: text} for every *.py in `tree`, sorted; no exemptions."""
def mutable_value(node: ast.expr) -> bool
    """List/Dict/Set or a comprehension of one; a Call whose callee's last name
    is in MUTABLE_CALLS (`list(...)`, `collections.deque(...)`); a BinOp where either
    side is mutable (`[...] + [...]`). Tuples, frozensets, constants: False."""
def module_mutables(module: ast.Module) -> frozenset[str]
    """Names bound at the module's top level by Assign / AnnAssign-with-value to
    a plain Name, whose value is mutable_value."""
def root_name(node: ast.expr) -> str | None
    """Follow .value through Subscript/Attribute to the base Name's id; None otherwise."""
def written_name(node: ast.AST) -> str | None
    """The root name a node writes through: a Subscript or Attribute in Store/Del
    context (covers `X[k] = v`, `X[:] = …`, `X[k] += 1`, `del X[k]`, `X[k].a = 1`),
    or a Call of an Attribute whose attr is in MUTATORS (`X.append(1)`,
    `X["a"].update(…)`). Else None."""
def local_names(func: ast.FunctionDef | ast.AsyncFunctionDef) -> frozenset[str]
    """The function's parameters (all kinds) and every Name it stores anywhere in its body."""
def function_hits(func, mutables: frozenset[str]) -> list[tuple[int, str]]
    """(line, name) for each node in ast.walk(func) whose written_name is in
    mutables minus local_names(func), plus (line, name) for each name in each
    `global` statement inside it, whatever the type."""
def write_lines(source: str) -> list[tuple[int, str]]
    """Parse; for every FunctionDef/AsyncFunctionDef at any depth (methods too)
    whose name doesn't start with HOOK_PREFIX, collect function_hits; dedupe, sort."""
def state_hits(sources: Mapping[str, str]) -> list[str]
    """["path:line: NAME", ...] over the .py entries of sources."""
```

Each function stays under about 8 lines. Split a helper out if one grows.
Writes at import time at module level (`X = []` then `X.append(1)`) aren't
flagged: they run once, before any test runs.
