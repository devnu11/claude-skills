# s120: The liaison shares a file with the team, checked by hash

Story: `.team/stories/s120.md`. ADR: ADR-0062 (`.team/adr/0062-liaison-shares-files-by-hash.md`).
Requirements: REQ-007 (AC1, AC4, AC5), REQ-008 (AC2, AC4), REQ-009 (AC3, AC4).
Developer: `developer-cli`.

## Why

`.team/run/liaison/` is outside every role's read scope, so s118's mock had to
be copied by hand. `agile-team share` puts a file where every role can read it,
records its SHA-256 in the story file, and acceptance fails when someone
changed it afterwards.

## Rules

- **S1 Queue, then apply.** `agile-team share <file> --story <id>` never
  touches the working tree or git. It checks the request (S2), then queues
  one file `.team/run/liaison/shares/f<N>.json` holding the story, the file
  name, the bytes (base64) and their SHA-256. It is written whole: a draft,
  then a hard link to the first free `f<N>.json`, as `tell` and the s83
  reorder requests do. It prints
  `queued f<N>: <docs>/design/<id>-<name> (sha256 <first 12 hex>); the runner commits it between steps`
  and exits 0. It works in any run state. A stopped or halted run applies the
  share at its next `start`.
- **S2 Refusals at the command**, checked in this order. The first one wins,
  nothing is written, and the command exits 1:
  1. bad story id (`backlog.STORY_ID` does not match): `no story '<id>'`;
  2. no story file: `no story '<id>': .team/stories/<id>.md does not exist`;
  3. bad file name (the source's base name must match
     `^[A-Za-z0-9][A-Za-z0-9._-]{0,99}$`; `-` (stdin) never matches):
     `file name '<name>' must be letters, digits, '.', '_' or '-', at most 100, starting with a letter or digit; rename it`;
  4. unreadable source: `cannot read <source>: <strerror>`;
  5. empty file: `the file is empty`;
  6. over `MAX_BYTES` (5 MiB): `the file is <n> bytes; the limit is 5242880`.
- **S3 Target path.** `<docs>/design/<id>-<name>`, where `<docs>` is
  `config.team.docs_dir` with any trailing `/` removed. The name is kept
  as given, even if it already starts with `<id>-`.
- **S4 Apply between steps.** Each router tick, right after the s83 reorder
  desk, the runner settles every pending share (an id not yet in
  `state.shares`) in number order. Shares wait while a sprint boundary is open
  (`state.boundary is not None`). Settling a share:
  1. reads the story file. If it is missing, the share is refused (S2's text 2);
  2. builds the new story-file text with the entry `{path, sha256}`. An
     entry with the same path is replaced in place, and a new one is appended.
     If the frontmatter can't be rewritten safely (S5), the share is refused:
     `<file>: cannot record the share; fix its frontmatter (<problem>)`;
  3. when both the target's bytes and the story-file text are already equal,
     records `unchanged`. No write, no commit;
  4. otherwise writes the bytes (making `design/` if needed) and the story
     file, then commits **exactly those two paths** in one commit,
     `chore(<id>): share <name> (f<N>)`, and calls `Runtime.record_checkout()`
     so the checkout guard expects the new HEAD;
  5. records `state.shares[f<N>]` (`applied <12-hex commit>`, `unchanged` or
     `refused: <text>`), saves the state and emits one `share` event (S7);
  6. when the share was applied, tells the PO through `Relay.tell` (S8).
- **S5 The story file's `shared:` list.** It is a top-level frontmatter key,
  written by the runner only:
  ```yaml
  shared:
    - path: "agile-team/docs/design/s118-mock.html"
      sha256: "<64 lowercase hex>"
  ```
  The rewrite removes the old top-level `shared:` block (its line up to the
  next non-indented line of the frontmatter) and appends the rendered block at
  the end of the frontmatter. It leaves every other line alone. The result
  must re-parse with every other key equal, the same body, and a `shared`
  list equal to the intended one. Otherwise the share is refused (S4.2), and
  so is a present but malformed `shared:` list. `story_spec` ignores the key.
- **S6 Reading the list.** `shares.listed(file, meta)` reports each problem as
  `{file}: shared: {problem}` or `{file}: shared item {n}: {problem}`. The
  problems: not a list; an item that is not a mapping; `path` missing or not
  under `<docs>/design/`; `sha256` not 64 lowercase hex; a path listed twice.
  A missing key is an empty list. A missing or unparseable story file is an
  empty list with no problems, because `story_spec` already holds those
  (s94).
- **S7 Event.** `EventKind.SHARE = "share"`, role `liaison`, story `<id>`,
  data `{request, path, sha256, commit, outcome}`. `commit` is null unless
  the share was applied, and `outcome` is `applied`, `unchanged` or `refused`
  (plus a `reason` key when refused).
- **S8 The PO is told.** On `applied`, the runner queues a `tell` message:
  `Runner note: the liaison shared <path> for <id> (sha256 <12 hex>, commit <12 hex>). Every role can read it; acceptance checks its hash.`
  It is delivered like any `tell`.
- **S9 Briefs (AC2).** A story-bound step of a role in
  `shares.BRIEF_NOTES` (`architect`, `customer-proxy`) with at least one
  shared file gets this section:
  ```
  ## Shared files

  The liaison shared these files for <id>. Read them; never edit them: acceptance checks each one's SHA-256.
  <the role's note>

  - `<path>` (sha256 <12 hex>)
  ```
  The architect's note: `Name each path in your design file under ## Shared files; the design gate checks it.`
  The customer-proxy's note: `Where an AC refers to one, judge the product against it.`
  With no shared files, the section is left out.
- **S10 Design gate (AC2).** A `done` design of a story with shared files
  runs `Checks.designed` even when the story is neither reverted nor
  trace-checked. Each shared path that does not appear literally in
  `<docs>/design/<id>.md` adds the reason
  `<design file> does not name the shared file <path>; list it under ## Shared files`.
  The reasons join the revert and trace reasons. The design gate still
  bounces to `design`.
- **S11 Every role can read them.** Shared files live under `<docs>/design/`,
  which every role but the Customer Proxy already reads. The Proxy's scope
  and its OS sandbox gain exactly the story's shared paths: `Order.shared`
  goes to `Prepared.shared`, then to `proxy_read_globs` and `_allowed_reads`.
- **S12 Acceptance hash check (AC3).** At the `acceptance` step's verdict,
  before the s95 round logic and whatever the handoff says, the runner
  checks the story's shared files:
  - a `shared:` problem gives `HOLD` with
    `story_spec.STORY_FILE_HOLD.format(refusal=<problem lines>)`;
  - for every file whose SHA-256 differs from the story file, or that is
    missing, it gives `BOUNCE` to `design_step()`, `Author.ROLE`, with
    reason
    ```
    shared files changed since the liaison shared them:
    - <path>: sha256 <12 hex found> (shared <12 hex recorded>)
    - <path>: missing (shared <12 hex recorded>)
    Restore each to its shared version (the `chore(<id>): share …` commit), or ask the PO to have the liaison share the new version
    ```
  - otherwise the verdict goes on as before.
  A new `share` of the same name updates the recorded hash, so the changed
  file then passes. The hash is SHA-256 of the raw bytes, with no
  normalisation.

## Changes per module

### `agile_team/shares.py` (new; pure, plus read-only I/O through `system`)

```python
MAX_BYTES = 5 * 1024 * 1024
FILE_NAME = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,99}$")
SHA256 = re.compile(r"^[0-9a-f]{64}$")
KEY = "shared"
SHORT = 12
SUBJECT = "chore({story}): share {name} ({id})"
QUEUED = "queued {id}: {path} (sha256 {short}); the runner commits it between steps"
TOLD = "Runner note: the liaison shared {path} for {story} (sha256 {short}, commit {commit}). Every role can read it; acceptance checks its hash."
CHANGED = "shared files changed since the liaison shared them:\n{lines}\nRestore each to its shared version (the `chore({story}): share …` commit), or ask the PO to have the liaison share the new version"
CHANGED_LINE = "- {path}: sha256 {found} (shared {recorded})"
MISSING_LINE = "- {path}: missing (shared {recorded})"
UNNAMED = "{file} does not name the shared file {path}; list it under ## Shared files"
BRIEF_HEAD = "## Shared files\n\nThe liaison shared these files for {story}. Read them; never edit them: acceptance checks each one's SHA-256.\n{note}\n\n"
BRIEF_LINE = "- `{path}` (sha256 {short})"
BRIEF_NOTES: dict[str, str] = {"architect": ..., "customer-proxy": ...}  # S9 texts

class Refused(StrEnum): BAD_ID, NO_STORY, BAD_NAME, UNREADABLE, EMPTY, TOO_BIG, STORY_FILE
REFUSALS: dict[Refused, str]  # S2 and S4.2 texts, with {story} {file} {name} {source} {error} {size} {limit} {problem}

@dataclass(frozen=True)
class SharedFile:
    path: str
    sha256: str

@dataclass(frozen=True)
class Listed:
    files: tuple[SharedFile, ...] = ()
    problems: tuple[str, ...] = ()
    def paths(self) -> tuple[str, ...]: ...
    def unnamed(self, text: str) -> list[str]: ...          # paths not in text (S10)
    def changed(self, found: Mapping[str, str | None]) -> list[str]: ...  # CHANGED_LINE / MISSING_LINE lines (S12)

@dataclass(frozen=True)
class Share:
    id: str           # "" until queued
    story: str
    name: str
    data: bytes
    at: float = 0.0
    def sha256(self) -> str: ...
    def to_json(self) -> str: ...  # {"story", "name", "sha256", "data" (base64), "at"}
    @classmethod
    def from_json(cls, rid: str, text: str) -> Share | None: ...  # None on bad JSON/shape/base64 or a sha256 that does not match the data

@dataclass(frozen=True)
class Check:
    listed: Listed
    changed: tuple[str, ...] = ()

def digest(data: bytes) -> str: ...                       # hashlib.sha256 hex
def target_of(docs_dir: str, share: Share) -> str: ...    # S3
def story_refusal(config: Config, share: Share) -> str | None: ...  # S2 items 1-3 (story id, story file, name); ignores data
def data_refusal(data: bytes) -> str | None: ...                   # S2 items 5-6 (item 4 is the CLI's read)
@dataclass(frozen=True)
class Where:
    file: str          # the story file, for problem lines
    design_dir: str    # "<docs>/design/"; "" accepts any path

def listed(where: Where, meta: dict[str, Any]) -> Listed: ...  # S6
def render(files: tuple[SharedFile, ...]) -> str: ...     # S5 block, ending with "\n"
def with_entry(text: str, entry: SharedFile) -> str | None: ...  # S5; None when unsafe
def brief_section(listed: Listed, role: str) -> str: ...  # S9; "" when no files or role not in BRIEF_NOTES
def listed_of(config: Config, story: str) -> Listed: ...  # reads the story file (I/O)
def check(config: Config, story: str) -> Check: ...       # listed_of + each file's digest (I/O, system.read_bytes; OSError → missing)
```

`listed_of` builds
`Where(story_spec.file_of(config, story), f"{docs}/design/")`. `with_entry`
runs `listed` with a `Where` whose `design_dir` is `""` (any path passes),
because its caller has already built the path with `target_of`.

`with_entry` uses `roles.FRONTMATTER` (renamed from the private
`_FRONTMATTER`, one-line change and its uses in `roles.py`) to split the text.
It re-parses through `roles.split_frontmatter` for the S5 check. A
`RoleError` or `yaml.YAMLError` gives `None`.

### `agile_team/sharing.py` (new; the queue and the runner side)

```python
SHARES_DIR = "shares"                      # under run_dir / relay.LIAISON_DIR
REQUEST_NAME = re.compile(r"^f(\d+)\.json$")

@dataclass(frozen=True)
class Shares:
    run_dir: Path
    @property
    def folder(self) -> Path: ...
    def queue(self, share: Share) -> Share: ...           # S1: draft + hard_link, never overwrites; returns it with its id and time
    def all(self) -> list[Share]: ...                     # readable requests in number order
    def pending(self, settled: Mapping[str, str]) -> list[Share]: ...

@dataclass
class Sharer:
    runtime: Runtime                                      # TYPE_CHECKING import from .dispatch
    def apply(self) -> None: ...                          # S4; returns at once while a boundary is open
```

Private helpers on `Sharer` (one job each, under 8 lines): `_settle(share)`,
`_refuse(share, text)`, `_write_and_commit(share, story_text) -> str` (the sha),
`_record(share, outcome)` (state, save, event), `_tell(share, commit)`.
Mirror `reorders.Requests` for `queue`, `all` and `_publish`. Copying the
pattern is fine; do not refactor `reorders` or `relay` in this story.

### `agile_team/cli.py`

```python
def cmd_share(args: argparse.Namespace) -> int:
    """Queue a file for the team (s120); the runner copies and commits it between steps."""
SHARE_ARGS: tuple[Arg, ...] = (
    (("source",), {"help": "the file to share; its name is kept (no stdin)"}),
    (("--story",), {"required": True, "help": "the story it is for, e.g. s118"}),
)
Command("share", "share a file with the team for a story (hash-checked at acceptance)", cmd_share, SHARE_ARGS)
```
The row goes right after `tell`. `cmd_share` builds
`Share("", args.story, Path(args.source).name, b"")` and calls
`shares.story_refusal` (items 1 to 3). It then reads the bytes with
`system.read_bytes` (an `OSError` is item 4) and calls
`shares.data_refusal` (items 5 and 6). Last, it queues the share with
`Shares(config.run_dir).queue(replace(share, data=data))` and prints
`QUEUED`. Any refusal raises `CliError(text)`, which keeps the S2 order.

`status_report` gains `"queued_shares": [s.id for s in Shares(run_dir).pending(st.shares)]`
and `"shares": st.shares`.

In `make_pipeline`'s `Checks(...)`, add
`shares=functools.partial(shares.check, config)`.

## Test checklist (AC4)

Unit (FakeSystem, no real git):
- [ ] `share` queues `f1.json`. A second share queues `f2.json`. The
      printed line is `QUEUED` with the S3 path and the 12-hex digest.
- [ ] Refusals, one test each, nothing written: bad story id, **unknown
      story** (no story file), bad name (including `-`), unreadable source,
      empty file, too big. The S2 order holds (an unknown story with an
      empty file reports the story).
- [ ] `Share.to_json` / `from_json` round trip. A tampered `sha256` or bad
      base64 reads as `None`.
- [ ] `with_entry`: appends to a file with no `shared:`, replaces the same
      path in place, keeps other keys and the body byte for byte, and gives
      `None` on no frontmatter, bad YAML or a malformed existing list.
- [ ] `listed`: every S6 problem line, and a missing key is empty.
- [ ] `Sharer.apply`: **the copy** (target bytes equal the source), **the
      story-file entry** (path and sha256), **one commit** naming exactly the
      target and the story file with subject `chore(sN): share <name> (fN)`,
      `record_checkout` called, `state.shares` `applied <sha>`, one `share`
      event, one `tell` file.
- [ ] Re-sharing identical bytes gives `unchanged`: no commit, no tell.
      A new version replaces the bytes and the hash (one entry), in a new commit.
- [ ] Apply-time refusal (story file removed after queueing) records
      `refused: …` with no write and no commit. A share waits while
      `state.boundary` is set.
- [ ] Acceptance gate: **pass** with intact files (the s95 round goes on),
      **fail** with a changed file (`BOUNCE` to design with the `CHANGED`
      text) and with a missing file, and `HOLD` on a malformed `shared:`.
- [ ] Design gate: a story with shared files and no trace/revert runs
      `designed`, and bounces when the design file does not name a shared path.
- [ ] Briefs: architect and customer-proxy get `## Shared files` with the
      role's note, other roles don't, and no files means no section.
- [ ] Proxy scope: `proxy_read_globs` and `_allowed_reads` include each shared
      path and nothing more.
- [ ] `status` shows `queued_shares` and `shares`.

E2E (real git, `tests/e2e/`, `set_git_identity`):
- [ ] In a scratch repo with a story file, run `agile-team share mock.html
      --story s1`, then one `Sharer.apply` on a runtime over that repo. Check
      `git log -1 --name-only` lists exactly the two paths, `git rev-list
      --count` grew by one, and the committed file's `sha256sum` equals the
      story-file entry.

## Design review (after implement)

The code matches S1 to S12 (`.team/reviews/s120.md`). The private helper names
in `sharing.py` differ from the list above (for example `_write` rather than
`_write_and_commit`). Those names were never part of the contract, so the code's
names stand.

- **F1, owed by the e2e step.** The real-git E2E test in the checklist above is
  still to be written: `tests/e2e/test_s120_share_e2e.py`. It is part of AC4
  (REQ-007), and the story is not done without it.
- **Accepted for now; follow-up stories proposed.** None of these breaks an AC.
  Each needs a hand-edited story or queue file, which only the runner and the
  CLI write:
  - F2: S6 should also reject a path with a `..` segment, meaning one whose
    `PurePosixPath(path).parent` is not `<docs>/design`. The follow-up should
    tighten S6 to say so.
  - F3: `Share.from_json` should give `None` unless `story` and `name` are
    `str`.
  - F4: `brief_section` should take the story id, as
    `brief_section(found: Listed, story: str, role: str)` would, rather than
    working it out from a path. This needs a parameter object to stay within
    the two-parameter rule, for example a `Brief(story, role)` passed with
    `found`.
  - F5: pull the draft + hard-link numbered queue out into one helper used by
    `relay`, `reorders` and `sharing`.
- **F2, F3 and F4 are done in s133** (`design/s133.md`). Its rules C1 to C6
  replace the S6 path check, the `from_json` contract and the
  `brief_section` signature above. F5 is still open.
