# s167 design: the page's CSS checks scan the page once

Story: [s167](../../../.team/stories/s167.md). Requirements: REQ-176 (AC1, AC3),
REQ-177 (AC2, AC3). No ADR: no boundary, format or dependency changes; the
rule goes into `guidelines.md` (Quality bar).

Developer: `developer-cli`, with **nothing to change**. Every change is in two
test files, written by the unit-tester. The dashboard page
(`agile_team/dashboard/index.html`) does not change.

## Cause

Both checks run a regex over the whole page that starts with a repeated class
of brace-free characters (`[^{}]*` or `[^{}]+`). `re` tries a match at every
position. A start that fails scans on to the end of its brace-free stretch, so
a stretch of length n costs about n²/2. The page's body HTML (3.9 KB) and the
script's short stretches make that 0.17 s for s104 and 0.05 s per `rule()`
call for s127.

## Rule

Anchor the match: put `(?<![^{}])` in front of each of the two patterns. The
lookbehind passes only at the start of the text or right after `{` or `}`, so
each brace-free stretch is scanned once, from its first character.

The anchored pattern finds **exactly the same matches** as the old one, so
neither check changes what it accepts:

- `findall` scans left to right. In a stretch, the old pattern's first try is
  at the stretch's first character, where the anchor passes too.
- If that try fails, a later start in the same stretch sees only a suffix of
  it. The suffix holds no `#flow`/`.fc` the whole stretch lacked, and it ends
  at the same brace, so it fails too. The anchor only skips tries that fail.
- A try at a brace itself fails in both patterns: `[^{}]` can't match a brace,
  and `#flow`/`.fc` doesn't start with one.

Don't narrow the scan to the first `<style>` block (as
`test_s118_page.css_rules` does). That would change which rules the s104 check
sees, for example a rule the script builds in a string. Leave
`test_s118_page.css_rules` as it is: it scans only the style block, whose
stretches are short.

## Changes

### `agile-team/runner/tests/test_s104_flow_page.py`

- Add the module constant, with a one-line comment naming the pitfall:

  ```python
  # Anchored at a brace or the start: an unanchored [^{}]* rescans each stretch (s167).
  FLOW_RULE = r"(?<![^{}])[^{}]*(?:#flow|\.fc)[^{}]*\{[^}]*\}"
  ```

- Add the pure helper, and use it in the existing test:

  ```python
  def flow_css(text: str) -> list[str]:
      """Every CSS rule in ``text`` whose selector names ``#flow`` or a ``.fc`` class."""
      return re.findall(FLOW_RULE, text)
  ```

  In `test_the_flow_is_not_shrunk_to_the_container`, the local becomes
  `rules = flow_css(page())` (renamed so it doesn't shadow the helper). Its two
  asserts stay the same, on `rules`.

### `agile-team/runner/tests/test_s127_page.py`

- Add the module constant, with the same comment:

  ```python
  CSS_RULE = r"(?<![^{}])([^{}]+)\{([^{}]*)\}"
  ```

- Split `rule` into a pure finder and the page wrapper:

  ```python
  def find_rule(text: str, selector: str) -> str:
      """The declarations of the first rule in ``text`` whose selector list holds ``selector``."""
      # the loop and the AssertionError(selector) of today's rule(), over re.findall(CSS_RULE, text)

  def rule(selector: str) -> str:
      """The declarations of the page's first CSS rule whose selector list holds ``selector``."""
      return find_rule(PAGE, selector)
  ```

  Every existing test keeps calling `rule(...)` unchanged.

## Tests (unit-tester)

New tests, in the two files above. They use synthetic text, not the page, so
they pin the rule whatever the page holds. The long-stretch tests have no time
assert: the suite's 1 s unit limit is the bound. With the fix each takes about
a millisecond; with the old pattern it runs for many seconds, so don't run it
against the old pattern except to see it red.

`test_s104_flow_page.py`:

- [ ] `test_a_flow_rule_that_sets_full_max_width_is_found` (AC2): `flow_css`
  of `"<p>text</p>\n#flow .fc-box { max-width: 100%; }"` holds one rule, and
  it contains `max-width: 100%`. Same with `.fc-cell` in place of
  `#flow .fc-box`.
- [ ] `test_full_max_width_on_another_selector_is_not_a_flow_rule` (AC2):
  `flow_css` of `".live-panel { max-width: 100%; }\n.fc { color: red; }"`
  holds the `.fc` rule, and no rule in it contains `max-width: 100%`.
- [ ] `test_a_long_brace_free_stretch_is_scanned_once` (AC1): `flow_css` of
  `"x" * 50_000 + "{}"` is `[]`.
- [ ] The existing `test_the_flow_is_not_shrunk_to_the_container` passes
  unchanged in what it asserts.

`test_s127_page.py`:

- [ ] `test_find_rule_skips_a_long_stretch_and_finds_the_rule` (AC3):
  `find_rule("x" * 50_000 + "}\n.a, .b { c: d; }", ".b")` contains `c: d`.
- [ ] `test_find_rule_names_a_missing_selector` (AC3): `find_rule(".a { c: d; }", ".z")`
  raises `AssertionError` whose message is `.z`.
- [ ] Every existing test in the file passes unchanged.

By hand (the ACs' own checks, run by the reviewer or the PO):

- AC1: `uv run --directory agile-team/runner pytest --durations=0 tests/test_s104_flow_page.py`
  shows `test_the_flow_is_not_shrunk_to_the_container` under 0.02 s. On a copy
  of the page with its body HTML or its script doubled, `flow_css` takes less
  than twice as long.
- AC2: on a copy of the page, adding `#flow { max-width: 100%; }` to the
  style block makes `flow_css` return a rule with `max-width: 100%`; adding
  `.other { max-width: 100%; }` instead does not.
- AC3: `uv run --directory agile-team/runner pytest --durations=0 tests/test_s127_page.py`
  shows each test that calls `rule` under 0.02 s.
