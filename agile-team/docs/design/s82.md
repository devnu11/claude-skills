# s82: Trial leaves the dashboard port in use on Linux

Developer: `developer-cli`. Modules: `agile_team/sandbox.py`, `agile_team/presentation.py`.
Docs: `reference/protocol.md` (service lifecycle) is already updated by this design.
No new dependency. No ADR: this extends ADR-0013 (service lifecycle) and keeps
ADR-0031 G1 (signals only through `process_groups.signal_child_group`).

## Cause (AC1): a real bug. The stop returns before the service exits

This is **not** a test that checks too early. The e2e test checks the port right
after `liveness` returns, and a stop that has returned should mean the service is
gone. The stop does not do that today:

1. **Certain (from the code).** `Prepared.stop()` sends SIGTERM to the group, then
   `self.process.wait(timeout=STOP_WAIT_S)`. `self.process` is only the
   group's **leader**, the `/bin/sh -c "<prepare>"` that `Popen(shell=True)`
   started. Nothing waits for the other processes in the group, and nothing
   waits for the port. After SIGKILL it does not wait at all.
2. **Certain.** The server is not the leader. The dashboard delivery's tree is
   `sh -c` → `uv run` → `python … agile-team dashboard`, all in one session
   (`start_new_session=True`). The listening socket closes only when that
   python process exits.
3. **Probable (why only Linux).** On macOS `/bin/sh` is bash, which `exec`s a
   lone simple command. So the leader is `uv`, which waits for its child before
   it exits, and `wait()` happens to return after the server is gone. On Ubuntu
   `/bin/sh` is dash. A dash leader dies at SIGTERM straight away and does not
   wait for `uv` or python, so `stop()` returns while the server, which got the
   same SIGTERM, is still being torn down. The test then sees the port in use.
   This cannot be proven locally. CI on Linux is the proof (AC4). The fix below
   does not depend on which shell runs.

## Rules

- **Q1 (whole group).** `Prepared.stop()` returns only after the service's whole
  process group has ended: the leader is reaped *and* no process is left in the
  group. Waiting for the leader alone is the bug.
- **Q2 (sequence).** If the leader is still running: SIGTERM the group, then wait
  up to `STOP_WAIT_S` (10 s) for Q1. If the group is still alive at that deadline,
  SIGKILL the group and wait up to `KILL_WAIT_S` (5 s) more. Then wait up to
  `PORT_WAIT_S` (5 s) until the delivery's port refuses connections. Then delete
  the pid file. The worst case is 20 s, and every wait has a deadline (AC3).
- **Q3 (only our group, ADR-0031).** Signals go only through
  `process_groups.signal_child_group`. A leader that had already exited and been
  reaped before `stop()` is **never** signalled, because its pid may have been
  reused (as today). SIGKILL is sent only when Q1 was still false at the
  deadline. That means either our unreaped leader still holds the pid, or the
  group still has members. Either way the pgid cannot have been reused.
- **Q4 (port wait).** The port wait runs whenever `stop()` had a process to stop
  (`self.process` is set), even if the leader had already exited. It is skipped
  when the delivery has no host or port, or when nothing was started
  (`process is None`, e.g. `PortBusy` or a `bare` Prepared). It polls
  `port_in_use(host, port)` every `POLL_EVERY_S` (0.05 s).
- **Q5 (report, AC3).** If the port is still in use at the `PORT_WAIT_S` deadline,
  `stop()` returns `PORT_HELD` filled in (it names the delivery, host and port).
  Otherwise it returns `None`. `stop()` never raises for this.
- **Q6 (trial).** `Trial` turns a returned note into a **hold** (no round, PO
  gets `gate_hold`), the same verdict as `PortBusy`. The reason is
  `STOP_HELD.format(story=…, held=note)`. A `None` note keeps today's PASS reason.
- **Q7 (failed start).** `Preparer._await_answer` adds the note to the `NotUp`
  reason on a new line when there is one. The verdict stays BOUNCE.
- **Q8 (Proxy step).** `dispatch.Plan.stop()` stays `-> None` and drops the note.
  The next start's `_refuse_busy` already holds on that port with the
  `PortBusy` message. No change in `dispatch.py`.
- **Q9 (one clock).** All new waits use `system.monotonic()` and `system.sleep()`
  (s71 seam), so fake-world tests drive them with the fake clock. The stale-stop
  wait `_ends_within` reuses the same `wait_until` (DRY).

## Changes per module

### `agile_team/sandbox.py`

Imports: add `from . import system`. `time` stays imported only if something
still uses it. `_ends_within` no longer does.

Constants (next to `STOP_WAIT_S = 10`, which keeps its name and value):

```python
KILL_WAIT_S = 5
PORT_WAIT_S = 5
POLL_EVERY_S = 0.05
PORT_HELD = ...  # as above
Listening = Callable[[str, int], bool]
```

New public functions:

```python
def wait_until(done: Callable[[], bool], seconds: float) -> bool:
    """Poll ``done`` every POLL_EVERY_S; True once it holds, False at the deadline."""
    deadline = system.monotonic() + seconds
    while not done():
        if system.monotonic() >= deadline:
            return False
        system.sleep(POLL_EVERY_S)
    return True
```

`done()` is checked once more at the deadline, so a port that frees exactly at
the deadline counts as freed.

```python
def port_released(prepared: Prepared, listening: Listening = port_in_use) -> str | None:
    """Wait up to PORT_WAIT_S until nothing listens on the delivery's port (Q4).

    Returns PORT_HELD filled in when the port is still in use, else ``None``.
    """
```

It returns `None` straight away (no wait, no `listening` call) when
`prepared.address()` has no host or no port.

```python
def end_group(process: subprocess.Popen[bytes]) -> None:
    """SIGTERM the child's group and wait for it to end; SIGKILL what is left (Q2, Q3)."""
```

If `process.poll() is not None` on entry, it returns at once (Q3). Otherwise:
`_signal_group(process, SIGTERM)`, then
`wait_until(lambda: _ended(process), STOP_WAIT_S)`. If that is False:
`_signal_group(process, SIGKILL)` and
`wait_until(lambda: _ended(process), KILL_WAIT_S)` (its result is ignored, and
the port wait comes next).

Private helpers:

```python
def _group_alive(pgid: int) -> bool:
    """True while group ``pgid`` has a process we may see (signal 0 sends nothing)."""
    # body: try os.killpg(pgid, 0) / except OSError: return False / return True
```

The call must be spelled `os.killpg(pgid, 0)`, because
`test_no_other_module_calls_killpg` looks for that text in `sandbox.py`.

```python
def _ended(process: subprocess.Popen[bytes]) -> bool:
    """True once the leader is reaped (poll reaps it) and its group is empty."""
    return process.poll() is not None and not _group_alive(process.pid)

def _ends_within(pgid: int, seconds: float) -> bool:   # body replaced
    return wait_until(lambda: not _group_alive(pgid), seconds)
```

The order inside `_ended` matters on Linux: an unreaped leader is a zombie, and
it keeps `killpg(pgid, 0)` succeeding.

`Prepared.stop` (new signature and docstring):

```python
def stop(self) -> str | None:
    """End the service's whole process group, wait for its port and drop the pid file.

    Returns why the port is still in use at the deadline (PORT_HELD), else ``None``.
    """
    held = self._end() if self.process else None
    self.pid_file().unlink(missing_ok=True)
    return held

def _end(self) -> str | None:
    end_group(self.process)
    return port_released(self)
```

`Preparer._await_answer`: replace the last two lines with
`raise NotUp(_joined(reason, prepared.stop()))`, where

```python
def _joined(reason: str, note: str | None) -> str:
    """``reason``, plus ``note`` on its own line when there is one."""
```

`Preparer.listening` is unchanged. It still only guards the start
(`_refuse_busy`).

### `agile_team/presentation.py`

Add `STOP_HELD`. `Trial._try` ends with `return _stopped(prepared, story)` in
place of the current two lines after the `try`:

```python
def _stopped(prepared: sandbox.Prepared, story: StoryState) -> Outcome:
    """PASS once the service is stopped and its port is free; HOLD if the port stays in use."""
    held = prepared.stop()
    if held:
        return Outcome(Verdict.HOLD, STOP_HELD.format(story=story.id, held=held))
    return Outcome(Verdict.PASS, f"{READY}; {prepared.probe_url()} answered")
```

### Not changed

`process_groups.py`, `dispatch.py`, `stop_stale`'s logic (its wait now goes
through `wait_until`), `STOP_WAIT_S`. The e2e test
`test_trial_starts_the_real_dashboard_probes_it_and_stops_it` keeps its

## Test checklist

### Unit tests (unit-tester): new FAKE-world file `tests/test_s82.py` (1 s limit, AC5)

Do not add this file to `LEGACY`. Drive time with the fake clock
(`system.sleep` advances `system.monotonic`). Inject `listening`. Build a
`sandbox.Prepared` directly. Constructing one makes no OS call.

- [ ] `wait_until`: true at once → `True`, no sleep recorded.
- [ ] `wait_until`: true on the 3rd check → `True`, two sleeps of `POLL_EVERY_S`.
- [ ] `wait_until`: never true → `False`. The fake clock moved at least `seconds`
      and less than `seconds + POLL_EVERY_S + 1e-9`. It never hangs.
- [ ] `wait_until`: true only on the check made at the deadline → `True`.
- [ ] `port_released`: the port frees on the 3rd poll → `None`, and `listening`
      was called with `(host, port)` from the delivery url.
- [ ] `port_released`: the port never frees → the exact `PORT_HELD` text
      (delivery name, `127.0.0.1:<port>`, `5s`). The clock moved `PORT_WAIT_S`.
- [ ] `port_released`: a delivery with no url → `None`, and `listening` is never
      called.
- [ ] `KILL_WAIT_S == 5`, `PORT_WAIT_S == 5`, `POLL_EVERY_S == 0.05`, and
      `STOP_WAIT_S` is still 10.
- [ ] `Trial`: a fake prepare whose `stop` returns a note → `Verdict.HOLD`,

## Design review (round 1): code matches; follow-ups out of scope

The code matches Q1–Q9, the exact strings and the signatures above. None of
these block s82. They are for the story that converts `sandbox.py` out of
LEGACY (s76/s77):

- `_group_alive` calls `os.killpg(pgid, 0)` directly. It needs a `system`
  wrapper (a probe-only signal 0, so ADR-0031 G1 still holds) when `sandbox`
  leaves LEGACY.
- `end_group` (a live `Popen`) and `_end_group` (a recorded stale pid) differ
  only by an underscore. Rename the stale one `_end_recorded` when that code
  is next touched.
- The stale path `_end_group` still does not wait after SIGKILL. This was
  already the case before s82, and the next start's `_refuse_busy` holds on the
  port anyway.
