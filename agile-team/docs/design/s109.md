# s109 design: one row per model family

**Story:** `.team/stories/s109.md` · **Developer:** `developer-gui` · **No new ADR** (a view rule over the s96 snapshot; history unchanged).

## Cause

Three sources name the model differently, and the page groups by the raw string:

| Source | `model` holds | Why |
|---|---|---|
| ledger lines (`dispatch.py:965`) | the configured model (`role.model`, an alias like `sonnet`) | the ledger always recorded it |
| `steps[]` (`snapshot._step`) | step-end `data.model` (exact id, e.g. `claude-sonnet-5-5`), else the configured model (ST7 fallback) | step-ends before 10-12 11:37 hold no model |
| PO turns (`turnPieces`) | the PO's configured model | `po-turn` events hold no model |

So "Time by Model" gives `sonnet` (old steps, fallback) and `claude-sonnet-5-5` (new steps) as two rows.

## Rules

- **MF1. Family table.** One table in `index.html`: `MODEL_FAMILIES = ["opus", "sonnet", "haiku"]`. A model's family is the first family that is a whole word of the model, lower-cased and split on every character outside `a-z` (`claude-sonnet-5-5`, `claude-3-5-sonnet-20241022`, `sonnet[1m]` → `sonnet`). No match: the family is the model string itself (`qwen3-coder` → `qwen3-coder`, `opusplan` → `opusplan`, `unknown` → `unknown`, `runner` → `runner`). A missing model (`null`/`undefined`/`""`) has family `unknown`.
- **MF2. Group by family.** "Tokens by", "Spend by" and "Time by" with **Model** chosen key each item by `familyOf(item.model)`. An alias and every exact id of one family make one row. Role and Story groupings are unchanged.
- **MF3. Version of an item.** Each item carries the most exact model id the data holds:
  - step pieces: `versionOf(step.recorded_model)` (MF6);
  - ledger lines: `versionOf(line.model)`;
  - PO-turn pieces: `versionOf(roleInfo(view, PO).model)`;
  - runner-stage pieces: no version (the key is absent; they aren't a model).
- **MF4. Alias is not a version.** `versionOf(model)` is `NOT_RECORDED = "version not recorded"` when the model is missing, is `"unknown"` (`UNKNOWN_MODEL`), or is an alias: the model with one trailing `[...]` removed equals a member of `MODEL_FAMILIES` (`opus`, `sonnet[1m]`). Otherwise it is the model string (`claude-opus-5-5`, `qwen3-coder`).
- **MF5. Versions tooltip.** Each group total gains `versions: {version: subtotal}`, where a subtotal has the same shape as the row total and is summed from that version's items only (items with no version add nothing). In the Model grouping, every tooltip of a row (every segment of a Tokens or Time row, the single Spend bar) ends with
  `<br><span class="k">versions:</span> {v1} {p1} · {v2} {p2} …`
  where `p = fmt.pct(100 * unit.share(sub) / unit.share(t))` (0 when `unit.share(t)` is 0), ordered by share descending, then by version name; names go through `esc`. A row with an empty `versions` map (the `runner` row) gets no line. Role and Story groupings get no line.
- **MF6. Snapshot says what was recorded.** Each `steps[]` object gains `recorded_model`: the step-end's `data.model` as recorded, or `null` (no end yet, or an end with no model). It is appended as the object's last key (after `slept`). `model` keeps its ST7 fallback; nothing else changes.
- **MF7. Flow box.** The model line of every agent box and of the PO box shows `familyOf(info.model)` instead of `info.model` (the ` · {provider}` suffix for local models stays). The live "model …" line of the running step (`liveStep`, health `model_note`) stays the exact id.
- **MF8. History untouched.** No write to `events.jsonl`, the ledger or `state.json`; no migration. The mapping is view-time only.

Out of scope: the Role and Story token tables' "Model"/"Last model" column (not a grouping), the timeline.

## Changes per module

### `agile-team/runner/agile_team/dashboard/snapshot.py`

```python
def _step(files: RunFiles, span: step_times.Span) -> dict:
    """One ``steps`` object; ``model`` falls back to the configured one (ST7); ``recorded_model`` is the end's own (MF6)."""
```
Add one line after the fallback: `step["recorded_model"] = span.model`.

### `agile-team/runner/agile_team/dashboard/fixtures/snapshot.json`

Every `steps[]` object gains `"recorded_model"` as its last key, equal to what the builder gives (the matching step-end's `data.model`, or `null`). `test_s96_snapshot.py::test_the_fixture_steps_are_what_the_builder_gives` pins it. At least one fixture family must hold both an alias step and an exact-id step (the fixture already has `sonnet` and `claude-sonnet-4-5-20250929` steps).

### `agile-team/runner/agile_team/dashboard/index.html`

Place the new names in the "tokens" section, before `totalsBy`. Each function documented, one job, ≤ 8 lines.

| Name | Signature | Job |
|---|---|---|
| `MODEL_FAMILIES` | `["opus", "sonnet", "haiku"]` | MF1 table |
| `NOT_RECORDED` | `"version not recorded"` | MF4 label |
| `familyOf` | `(model) → string` | MF1 |
| `versionOf` | `(model) → string` | MF4 |
| `GROUP_KEYS` | `{ role: (x) => x.role, story: (x) => x.story, model: (x) => familyOf(x.model) }` | MF2 table |
| `groupKeyOf` | `(item, key) → string` | `GROUP_KEYS[key](item) ?? "(no story)"` (not `groupOf`: that name is the Flow phase lookup) |
| `versionsLine` | `(unit, t) → string` | MF5 text, `""` when `t.versions` is empty |

Changed:

- `totalsBy(ledger, key)`: group with `groupKeyOf(l, key)`; each row total gains `versions: {}`; each line also adds into `t.versions[versionOf(l.model)]` (a subtotal of the same shape, without its own `versions`). Keep the add step in one helper (e.g. `addLine(t, l)`) so row and subtotal share it (DRY).
- `stepPieces`: piece gains `version: versionOf(s.recorded_model)`.
- `turnPieces`: piece gains `version: versionOf(roleInfo(view, PO).model)`.
- `stagePieces`: unchanged (no `version` key).
- `timeBy(pieces, key)`: group with `groupKeyOf(p, key)`; row gains `versions: {}`; a piece with a `version` also adds into `t.versions[p.version]` (same helper idea, e.g. `addPiece(t, p)`).
- Tooltips: `mixRow`, `costRow` and `timeRow` append `versionsLine(UNITS[ui.unit], t)` to each tip when `ui.group === "model"` (read the group once in `barRows`/`renderBars` and pass a flag-free value, e.g. a `more` string on the row object, to respect "no boolean parameters").
- `nodeLabel` and the PO box label (`flowGroupLines`, the `Steering` group's `po[...]` line): `familyOf(info.model)` / `familyOf(roleInfo(view, PO).model)`.

## Known limits

- Ledger lines name only the configured model, so for an alias-configured role their versions read "version not recorded" even after step-ends started recording the exact id; pairing ledger lines with step-ends is not attempted.
- A model with no family word (`opusplan`, a future family) is its own row until `MODEL_FAMILIES` gains it.
