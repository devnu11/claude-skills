# s89: the OS guard lets the stdlib read source for a traceback (Python 3.13)

Bug. Extends s71 rules O8 (the audit hook) and O10 (the error). No new ADR, no
runtime change. Only `tests/os_guard.py` and `tests/test_os_guard.py` change.

## Cause

CI on 3.13 (`pytest -n auto --cov`) fails 36 unit tests with
`unit test reached the real OS: open (filesystem)`. Every one formats a real
traceback (`traceback.format_exception`, through `halt.log_traceback` and so on).
`test_s71_seam.py::test_crash_log_entry_has_the_fake_clock_stamp` formats an
exception with no frames, and it passes. So the `open` happens while the stdlib
reads source lines for the frames.

The guard (`os_guard.hook`) charges an audited event to **one** frame: the first
frame outside `PASS_THROUGH` (`_caller()`). It allows the event only when that
frame's module is in `EXEMPT_CALLERS`. On 3.12, source reads come from
`linecache` → `tokenize.open` → `open`. The caller is `tokenize`, which is exempt.
3.13 rewrote this path:

- `linecache` imports `os`, `sys` and `tokenize` inside `updatecache`.
- It prefers `__spec__.loader` for lazy `get_source`.
- It handles `<frozen …>` file names.
- `FrameSummary._set_lines` reads whole line ranges.

On some path, a module that is not in the exempt list now makes the `open`
under `traceback`/`linecache`. No 3.13 interpreter is on the design machine
(only 3.12 and 3.14), so we cannot name the exact frame that opens. The fix
therefore does not depend on knowing it. It fixes the rule itself: the guard
charged a stdlib source read to the wrong frame.

## Rules

| # | Rule |
|---|---|
| T1 | **A source read is the stdlib's.** An audited event is allowed when a frame of a `SOURCE_READERS` module (`traceback`, `linecache`) is on the stack **inside** the nearest guarded frame. "Inside" means between the event and the innermost frame whose module starts with a `GUARDED_CALLERS` prefix (`agile_team`, `tests`). With no guarded frame on the stack, the whole stack counts. The frames of `os_guard` itself never count. |
| T2 | **The opener rule stays.** An event is also allowed when `_caller()` (the first frame outside `PASS_THROUGH` and this file) starts with an `EXEMPT_CALLERS` prefix. This is unchanged. `"traceback"` joins `EXEMPT_CALLERS` because `traceback` opens the source file itself (3.14 SyntaxError suggestions). |
| T3 | **Code under test still fails.** An `open` whose first non-pass-through frame is `agile_team.*` or `tests.*` is refused, even while a traceback is being formatted. Example: a `__str__` that `traceback` calls. That frame is guarded, so T1 sees no reader inside it. |
| T4 | **No new relaxation elsewhere.** Every event refused today is still refused unless T1 applies. Examples: `tmp_path` used in a unit test (`_pytest.tmpdir`, with `xdist.remote` outermost); a stdlib module that opens on behalf of `agile_team`. T1 looks only for the two reader modules. It never allows an event because some other exempt module (xdist, coverage) sits further out on the stack. |
| T5 | **The violation names its caller.** The recorded and raised text becomes `MESSAGE.format(call=…, category=…) + CALLER_NOTE.format(caller=…)`, with `CALLER_NOTE = " (caller: {caller})"`. `caller` is `_caller()`, or `"no python frame"` when that is empty. `MESSAGE` itself is unchanged. If 3.13 CI still fails, the log names the module that needs a table row. |
| T6 | **Patched calls are unchanged.** `_wrapper` still refuses only when `_caller()` starts with `GUARDED_CALLERS`. (`linecache`'s `os.stat` already passes, because its caller is `linecache`.) |

## Changes: `agile-team/runner/tests/os_guard.py`

Imports: add `import itertools`. `Iterator` is already imported from
`collections.abc`.

```python
CALLER_NOTE = " (caller: {caller})"

EXEMPT_CALLERS  # add "traceback" after "tokenize"; update the comment to
                # "(imports, source lines, tracebacks, coverage, xdist)"

# Stdlib modules that read source for a traceback; an audited call beneath them is theirs (s89).
SOURCE_READERS: tuple[str, ...] = ("traceback", "linecache")


def _modules() -> Iterator[str]:
    """Module names on the stack, innermost first, skipping this file's frames."""
    frame = sys._getframe()
    while frame is not None:
        name = frame.f_globals.get("__name__", "")
        if name != __name__:
            yield name
        frame = frame.f_back


def _caller() -> str:
    """The module of the first frame outside the stdlib wrappers and this file."""
    return next((n for n in _modules() if n.split(".")[0] not in PASS_THROUGH), "")


def _reading_source() -> bool:
    """Whether a source reader is on the stack inside the nearest guarded frame (T1)."""
    inside = itertools.takewhile(lambda n: not n.startswith(GUARDED_CALLERS), _modules())
    return any(n.startswith(SOURCE_READERS) for n in inside)


def _allowed() -> bool:
    """An audited call is allowed from an exempt caller (T2) or while the stdlib reads source (T1)."""
    return _caller().startswith(EXEMPT_CALLERS) or _reading_source()


def _violation(call: str, category: str) -> RealOsCall:   # body: append CALLER_NOTE (T5)
    message = MESSAGE.format(call=call, category=category) + CALLER_NOTE.format(
        caller=_caller() or "no python frame"
    )
    ...  # record and return as today


def hook(event: str, args: tuple[Any, ...]) -> None:
    """The audit hook: refuse an audited event unless it is allowed (T1, T2)."""
    category = AUDITED.get(event)
    if category is None or not _guard.on or _allowed():
        return
    raise _violation(event, category)
```

Notes for the developer:

- `_caller()` keeps its contract: same name, same result. It only switches to
  `_modules()`, so the stack walk exists once (DRY).
- `_modules()` skips **every** `tests.os_guard` frame, the generator's own
  frame included. That way `tests.os_guard` (which starts with `tests`) never
  counts as a guarded frame in T1.
- Update the module docstring with one line: "an audited call made while
  `traceback`/`linecache` read source is the stdlib's (s89)".

## Changes: `agile-team/runner/tests/test_os_guard.py`

Add a helper beside `call_audited`. It reuses `as_module`, which compiles code
under a module name:

```python
def call_audited_through(names: tuple[str, ...], event: str) -> None:
    """Fire ``event`` from ``names[-1]``, called by ``names[-2]`` ... called by ``names[0]``."""
```

Build one `go(inner, *a)` relay per outer name with
`as_module(name, "def go(inner, *a):\n    return inner(*a)\n")`. The innermost
name fires `os_guard.hook(event, ())`, as in `call_audited`. Example:
`("agile_team.x", "traceback", "json")` means `agile_team.x` calls `traceback`,
which calls `json`, which fires the event.

As built (design review): the relays are chained with lambdas defined in
`tests.test_os_guard`, so a guarded `tests.*` frame sits between each pair of
relays. Every checklist case still tells allowed from refused correctly. A
future case that needs a reader **two** links from the event will be cut off by
that frame. For such a case, chain relays that close over `inner` in their own
module instead of using the lambdas.

## If 3.13 CI is still red

The failure text now ends with `(caller: <module>)` (T5). If that module is a
stdlib or tool module that reads source with no `traceback`/`linecache` frame
on the stack, add it as a row to `SOURCE_READERS` or `EXEMPT_CALLERS`, with a
guard test like the ones above. If the module is `agile_team.*` or `tests.*`,
the code under test really reaches the OS. Fix it through `system`, not the
guard.
