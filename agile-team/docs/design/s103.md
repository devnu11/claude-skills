# s103: the guard lets a named test run save its output, and no prompt says `timeout`

Story: `.team/stories/s103.md`. Developer: `developer-cli`. No ADR (it
refines s69, s43 and s41; no new dependency, no new state, no new event).

## Causes found

1. **Redirect target counted as a test path (AC1).** `suite_check._positionals_after`
   drops a redirect *operator* word (`>`, `2>`; `REDIRECT`), but not the word
   after it. `shlex.split("pytest tests/test_x.py > out.txt")` gives
   `[…, ">", "out.txt"]`, so `out.txt` is a positional that is not a test,
   and the run is classed `Run.FULL` and denied. `>out.txt` (glued) already
   passes. `… | tee out.txt` already passes the suite check (the pipe makes
   `tee` its own segment); AC1 only needs it pinned.
2. **`timeout` in a prompt and a reason (AC2).** `roles/_shared.md` line 41
   ("run it under `timeout N`") and `guard.WAIT_DENIED` ("run it under
   `timeout N`") tell roles to use a command macOS lacks. No Python brief
   text says it (checked: only docstrings mention `timeout`).
3. **Reasons with no rule name (AC3).** Bash refusals are free text; some
   name an allowed form, some (`may not reference 'x' from Bash`, the API
   key, git env) don't, and none names its rule.

## Rules

- **R1. A redirect's target is not a test path.** In a test-run segment, a
  word that directly follows a bare redirect operator (a whole word matching
  `^\d*(>>?|<)$`: `>`, `>>`, `<`, `1>`, `2>`, `2>>`) is the redirect's
  target, never a positional. A glued redirect (`>out`, `2>err`) is still
  one non-positional word, as today.
- **R2. The kind is decided on what is left.** After R1 the run is
  `TARGETED` only if it names at least one test and every positional is a
  test (unchanged S5). So `pytest > out.txt` and `pytest > tests/test_x.py`
  are still `FULL` (the target is never a test, even when it ends in `.py`).
- **R3. The guard does not path-check the redirect or `tee` target.** Bash
  cannot be path-guarded; as for any Bash write, the post-step audit
  quarantines a changed file outside the role's write scope, and
  `.team/run/**` is ignored by the audit. The role file says to write the
  output inside its scope or under `.team/run/`.
- **R4. No built-in role file contains the text `timeout ` (with the
  space).** The wait rule names the Bash tool's own `timeout` parameter and
  a bounded loop instead. Mentions like ``the `timeout` ini of
  pytest-timeout`` (unit-tester.md) have no space after the word and stay.
- **R5. No Bash refusal reason contains `timeout `.** Same text test as R4,
  over one sample reason per rule (R7).
- **R6. The wait check itself is unchanged.** A loop is still allowed when
  some segment starts with `timeout`/`gtimeout` (`DEADLINES`), so Linux use
  and the existing tests keep working; the reason just no longer suggests it.
- **R7. Every Bash refusal reason has one shape:**
  ``refused by rule `<rule>`: <why>. Allowed: <allowed form>``
  where `<rule>` is a `refusal.Rule` value and the allowed form is never
  empty. "Bash refusal" = every reason `guard.check_bash` can return
  (secret mention, git, allowlist, sandbox path, wait loop, kill, suite).
  Tool-path refusals (`Write`/`Read`/`Grep`/`Glob`) are out of scope; they
  are not commands and the write one already lists the allowed globs.
- **R8. One rule name per refusal row.** Rule names are the `Rule` table
  below; the two `GIT_RULES` rows that share `GIT_OUTSIDE` share one rule.

## Changes per module

### New `agile_team/refusal.py` (pure, stdlib only, imports nothing from `agile_team`)

```python
"""One shape for every Bash refusal: the rule, why, and the allowed form (s103)."""

FORMAT = "refused by rule `{rule}`: {why}. Allowed: {allowed}"

class Rule(StrEnum):
    """The guard's Bash rules, by the name a refusal reason shows (R7, R8)."""
    API_KEY = "api-key"
    ...  # the 14 members of the table above, in that order

@dataclass(frozen=True)
class Refusal:
    """A Bash refusal before its placeholders are filled (R7)."""
    rule: Rule
    why: str
    allowed: str

    def text(self) -> str:
        """The reason in the R7 shape; ``{…}`` placeholders in why/allowed survive."""
        return FORMAT.format(rule=self.rule, why=self.why, allowed=self.allowed)
```

`text()` passes `why`/`allowed` as arguments, so their own `{role}` etc.
survive for the caller's later `.format`.

### `agile_team/roles/_shared.md`

- "Read little", the full-suite bullet: after the `tail -20` example add one
  sentence: ``To keep a named run's output, redirect it inside your scope
  or under `.team/run/`: `pytest -q tests/test_x.py > out.txt` or `… | tee out.txt`.``
- "Never wait without a deadline", replace the second bullet with:
  ```
  - Give every wait a deadline: run the command in the foreground with the
    Bash tool's `timeout` parameter (milliseconds, at most 600000), or loop a
    bounded number of times (`for i in $(seq 60); do …; done`). An open
    `until` or `while` loop with no deadline is denied. macOS has no
    `timeout` command; don't reach for one.
  ```
  The text `timeout ` (with the space) must not occur in the file (R4).
  "`timeout` parameter" and "`timeout` command" are safe: a backtick follows
  the word.

No other role file contains `timeout ` today; R4's test keeps it so.

## Known limits

- `pytest a.py 2>&1 tests/` is split at `&` by the guard, so `tests/` lands
  in a non-launcher segment and the full run passes. Pre-existing (s69);
  not widened here.
- The redirect or `tee` target is not path-checked (R3); the audit is the
  backstop.
