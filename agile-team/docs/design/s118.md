# s118: The Flow chart in HTML, readable at real size

The Flow tab's chart is rebuilt as HTML, CSS and inline SVG from the
snapshot. Mermaid goes. The visual spec for anything the ACs leave open is
mock **variant N**: [`s118-mock.html#n`](s118-mock.html#n), a byte-for-byte
copy of the approved `.team/run/liaison/flow-chart-mock-approved.html`. It
is committed with this design, so developers and reviewers do not need
`.team/run/`. Open it in a browser; it lands on tab N. The functions to read
are `variantN`, `nBox`, `nTool`, `nCols`, `afterN` and `afterK`. The other
tabs (A–M) are earlier drafts and are not part of the spec. The copy is not
edited. Where this file and the mock differ, this file wins, and each
difference is listed under "Differences from the mock".

Developer: **developer-gui**, alone. Most of the work is in `index.html`.
Eight small runner changes feed it (R1–R8, Python). Each is listed with
its exact signature.

ADRs: **ADR-0052** (HTML flow chart, overlay dots; supersedes ADR-0003,
amends ADR-0047), **ADR-0053** (streamed command output and the live test
tally), **ADR-0048 amended** (the open stage row gains `tests`; the board
gains `refresh`). No new dependency. One outside URL goes away (Mermaid).

**Test first, in two kinds.** The unit-tester writes the checklist's unit
tests before the code: R1–R8 and the static page checks (they read
`index.html` as text). The FC behaviour tests run the page in node through
`tests/dashboard_node.py`, which starts a process, so they are e2e tests
(protocol "Unit tests touch no OS"; guidelines "Page tests come in two
kinds"). The integration-tester writes them under `tests/e2e/`; see "Test
checklist" for when. Until then the FC rules below are the developer's
contract and design-review checks the code against them. Tests of removed
Mermaid code move to the rule that replaces them (see "Superseded tests").
That is a design change, not a weakened test.

### Rules

| # | Rule | AC |
|---|---|---|
| FC1 | **Group of a role.** `flowGroup(view, role)`: the `FLOW_GROUPS` entry whose `roles` lists the role. Otherwise, for an unknown role: the first group whose `steps` holds a pipeline step `s` with `view.step_roles[s]` including the role. Otherwise `Leadership`. | AC2 |
| FC2 | **Who is drawn.** The used roles (`r.used !== false`, ADR-0047 FL8). The Product Owner is always drawn. Inside a group: the table's order first, then unknown roles by name. All four stage groups are always drawn, an empty one with its title only, so the layout never shifts. | AC2 |
| FC3 | **Top row.** Left to right: a `You` pill, a two-way arrow, a `Liaison` pill, a two-way arrow, the boxed Leadership group. Its title is written sideways (mock `.h-lead > .h-title`). Leadership is a CSS grid with `grid-auto-flow: column` and three rows: tools above (`align-self: end`), the role box, tools below (`align-self: start`). Each role gets all three cells, an empty `<div>` where it has no tools, so the boxes share row 2 whatever hangs above or below them. | AC2 |
| FC4 | **Stage row.** `.fc-cols` is a flex row: group, gap, group, gap, group, gap, group. A group is `flex: 0 0 var(--group-w)` with `--group-w: 216px`, the one width setting. A gap is `flex: 1 1 var(--gap-min); min-width: var(--gap-min)` with `--gap-min: 24px`, and holds one arrow (`width: 100%`), so the arrows stretch with the window. Below the fit width, `#flow` scrolls sideways (`overflow-x: auto`). Nothing scales: no `transform`, `zoom`, `scale()` or `max-width: 100%` applies to anything inside `#flow`. | AC1, AC2 |
| FC5 | **Arrow height.** After each layout, `alignArrows(root)` sets each gap's `--arrow-y` so its arrow is level with the vertical middle of the first `.fc-box` of the group to its right. Measure with `getBoundingClientRect()` (box middle minus gap top). The arrow is `margin-top: var(--arrow-y, 60px)`. | AC2 |
| FC6 | **Roles in a group.** A role and its tools form one `.fc-unit` (a flex column, `gap: 0`). Units stack without aligning rows across groups. Between units: `border-top: 1px solid color-mix(in srgb, var(--ink) 28%, transparent); margin-top: var(--role-gap); padding-top: var(--role-gap)` with `--role-gap: 20px` (the mock's `.n-unit + .n-unit`). `--role-gap`, `--group-w` and `--gap-min` sit together on `.fc`. | AC2 |
| FC7 | **PO paths.** One SVG path per stage group in the overlay (FC18): from the Leadership box's bottom centre down to the middle of the `.fc-drops` band (`height: 46px`), across, then down to the group's top centre: `M x0 y0 V busY H xg V yg`. `marker-start` and `marker-end` both use one arrowhead marker (`orient="auto-start-reverse"`). ## Role box (AC3, AC4)

`roleBox(m, role)` returns, in this order (mock `nBox`):

1. `<b class="fc-t-name">` the role name.
2. Meta line `.fc-meta`: model family (`familyOf`, s109) plus
   ` · <provider>` when not anthropic; then `.f-tokens` (`fmt.tok`),
   `.f-cost` (`fmt.usd`), `.f-time` (`fmt.dur1` of awake seconds),
   joined by ` · ` (CSS `span + span::before`). A role with no totals in
   the scope and no open step shows `idle` instead of the three numbers
   (ADR-0047 FL4).
3. `.f-bounces` `↩ N bounced`, only when N > 0.
4. `.f-share` the model/tool bar (FC9).
5. `.f-spark` the sparkline row (FC10).
6. The live block, only on the running role (FC11).

| # | Rule | AC |
|---|---|---|
| FC8 | **Numbers.** Tokens and cost: `scopeTotals(view)` (ledger). Awake time: the role's finished steps in scope (`scopeTotals` seconds). Bounces: `flowStats` run over the scoped events: `flowStats({ ...view, events: view.events.filter(inScope(view)) })`. The PO: tokens and cost as today, but `—` in Story scope (its ledger rows have no story); its time is the model plus tool seconds of its `po-turn`s in scope (`turnSplit`), `—` in Story scope. | AC3, AC10 |
| FC9 | **Model/tool bar.** `shareParts({ model, tools })` returns `{ model: p, tools: 100 - p }` with `p = Math.round(100 * model / (model + tools))`, or `null` when `model + tools` is not above 0. Inputs: `stepSplit(view, role)`, and `turnSplit(view)` for the PO. With parts: two spans in `--flow-model` and `--flow-tools` and the caption `model p%` / `tools q%`, each with a 6 px swatch. With `null`: a dashed bar (`repeating-linear-gradient` in `--axis`) captioned `no model/tool timing yet`. | AC3 |
| FC10 | **Sparkline.** `sparkSvg(values, ink)` draws a 96×20 SVG: an area path (SVG attribute `fill-opacity=".16"`, never a CSS rule) and a 1.5 px line, scaled to the series' max, no text. Series: the running role uses `liveStep(view).rate` (R3) in its run colour, with `<b>{fmt.tok(tokensPerMin(role's turns, now))}</b> tokens/min` before it. Every other role uses the `data.rate` of its newest `step-end` in scope (the PO: newest `po-turn` in scope) in `--ink-2`, with `last step` before it. Under 2 points (an older event has no `rate`): `last step · no rate yet`, no SVG. | AC3, AC4 |
| FC11 | **The running role.** The role of `liveStep(view)`. Its box and its group get the class `run1`, `run2` or `run3` (FC14): a 2 px border in the run colour; the box also gets a glow (`box-shadow: 0 0 9px color-mix(in srgb, var(--runN) 60%, transparent)`). The live block (`.fc-live`, `border-top: 1px solid var(--grid)`): line 1 a steady 6 px dot in the run colour (no blink: FC12 bars CSS `opacity`), then `{story} · {step} · {fmt.dur1(awake)} · {run label}`; line 2 `toolLine(view, step)` (the A6a label or the step's tool, s112 LP4). Awake is `awakeSoFar(view, openStep(view, role))`, or the heartbeat step's `started_at` when no step is open in `view.steps`. | AC4 |
| FC12 | **Dimming.** As ADR-0047: in Story scope a role that has not touched the focus story (`touchedFocus`) is dimmed; in Sprint and Run scope a role with no totals and no bounces is. Dimmed is `.fc-box.dim`: `--surface-2` fill and `--ink-2` text. Colour only: no `opacity`, `filter`, `transform` or `mix-blend-mode` on anything in `#flow`. The running role is never dimmed. | AC3 |

### Run number and colour

| # | Rule | AC |
|---|---|---|
| FC13 | **Step run number.** `stepRunNumber(view, step)` for the heartbeat step `{role, story, step}` = 1 + the number of earlier finished runs: `step-start` events with the same role and story, and the same `data.step` when both the event and the step name one (R1; older events have none and match on role and story), whose next `step-end` of that role and story has a status other than `interrupted`. The current run's own start does not count. | AC4 |
| FC14 | **Run look.** `runLook(n)` → `{ cls, label }`: `cls` is `run${Math.min(n, 3)}`; `label` is `first run` (1), `first re-run` (2), `re-run ${n - 1}` (3 on). Tokens: `--run1` green, `--run2` violet, `--run3` amber (FC26). | AC4, AC6 |
| FC15 | **Tool run number.** `toolRunNumber(view, row)` = 1 + the number of `runner-stage` events with the same `data.stage` and the same `story`. For a row without a story, count only events at or after the newest `sprint-start`. | AC6 |

## Runner tools (AC5, AC6)

| # | Rule | AC |
|---|---|---|
| FC16 | **Which role a stage run belongs to.** `stageRole(view, run)` takes `{stage, when, attach, story, step, started_at}` (a `runner-stage` event's `data` plus its `story`, or an open heartbeat row). (1) `attach` is `boundary` or `story`: the Product Owner. (2) `when` is `during`, or the stage is in `FLOW_SKIP_STAGES`: `null` (not drawn; a during stage is a tool call and shows on the live line). (3) `after`: the role of the newest `step-start` with the same story (and the same `data.step` when both have one) whose `at` ≤ `started_at`. (4) `before`: the role of the oldest such `step-start` whose `at` ≥ `started_at`. (5) No match: the first drawn role in `view.step_roles[step]`, else `null`. | AC5 |
| FC17 | **Tool boxes.** `roleTools(view)` → `{ role: { before: [...], after: [...] } }`, one entry per (role, stage) pair that has a `runner-stage` event anywhere in the log or an open row now, in order of first appearance. Each entry: `stage`, `runs` and `seconds` (the sum of `data.seconds`) from the events in scope, and the open row when one is open. Idle box: `<div class="fc-tool f-tools">` with the stage name, then `<span class="f-toolstats"> · ↻ {runs} · {fmt.dur1(seconds)}</span>`. With 0 runs in scope the stats read ` · ↻ 0`. `before` tools stack above the role box, `after` tools below, touching it: dashed `1px var(--axis)` border, `border-radius: 4px`, `padding: 0`, no gap, italic `--ink-2`. | AC5, AC10 |
| FC18 | **The running tool.** For each open row (`openStages(view)`) with a role, the box is `<div class="fc-tool running {cls}">`: solid border in its run colour (FC15), `--ink` text, not italic. Row 1: `▶ {stage} · {run label}` and, right-aligned, `fmt.dur1(stageAwake(view, row))`. With `row.tests` (R5): a 6 px bar of Pass (`--pass`), Warn (`--warn`) and Fail (`--fail`) segments, each `100 * n / total` % wide, zero ones left out; the caption `273 Pass + 32 Warn + 9 Fail / 506 Total` (zero categories left out, numbers in `--ink` after a 6 px swatch in the category colour; `/ N Total` only when `total` is known); then `{pct}% complete` (`Math.min(100, Math.round(100 * ran / total))`, else the last point) and `statusSpark(points, fail_at)`. It carries neither `f-tools` nor `f-toolstats`, so the settings never hide it. The title attribute is the row's `description`. | AC6, AC8 |
| FC19 | **`statusSpark(points, failAt)`.** An 80×18 SVG, y from 0 to 100 %. A green (`--pass`) path through points `0..failAt` (all of them when `failAt` is null) and a red (`--fail`) path from `failAt` to the end. Under 2 points: no SVG. | AC6 |

## Dots and the overlay (AC7)

| # | Rule | AC |
|---|---|---|
| FC20 | **Two layers.** `#flow` (`position: relative`) holds `.fc-chart` (the HTML, rebuilt by `renderFlow` when its string changes) and `svg.fc-overlay` (created once by `ensureOverlay()`, `position: absolute; inset: 0; pointer-events: none; z-index: 3; overflow: visible`). A redraw only ever writes `.fc-chart`'s `innerHTML`; it never removes or replaces the overlay. The overlay holds `<defs>` (the arrowhead marker), `g.fc-paths` and `g.fc-dots`. | AC7 |
| FC21 | **Geometry.** `layoutFlow()` runs after every chart write, on `resize`, after a settings change and when the Flow tab is shown. It calls `alignArrows`, sizes the overlay to `#flow`'s `scrollWidth`/`scrollHeight`, and sets the `d` of each keyed path in place: `po:<group>` (FC7, drawn, `stroke: var(--ink-2)`) and `arrow:<group>` (an invisible track along the arrow into that group, from its left end to its head's tip, `stroke: transparent`). It creates a missing key and removes a key no longer drawn. Coordinates are relative to `#flow`'s box plus its scroll offset. | AC2, AC7 |
| FC22 | **Which dot.** `dotFor(view, e)` for a fresh `step-start` with a story; `null` for any other event. Let `g` be `flowGroup(view, e.role)`; `null` when `g` is Leadership. (1) **Sent back:** walking back from `e` over the same story's events, the first `gate` comes before any `step-start`, and its `data.verdict` is in `BACK_VERDICTS`: `{ key: "po:" + g, look: "back" }`. (2) **Forward:** the same story's newest `step-end` before `e` whose role is not in Leadership is in the group just left of `g`: `{ key: "arrow:" + g, look: "forward" }`. (3) Otherwise `null` (a first step, a jump such as Check → Design for design-review, or the same group). | AC7 |
| FC23 | **Moving a dot.** `runDot(key, look)` appends a `circle r=5` (fill from `DOT_LOOKS`) to `g.fc-dots` and moves it with `requestAnimationFrame` over `look.ms`. **Each frame looks the path up by key** (`[data-key="…"]`) and reads `getTotalLength()`/`getPointAtLength()`, so a redraw or a re-layout moves the dot with the new geometry and never cancels it. When the key is gone the dot removes itself. Reduced motion (`reducedMotion()`): no dot; the keyed path gets class `fc-lit` for `HIT_MS` (lit: `stroke: var(--flow-forward)` or `var(--fail)` by look, 3 px). `flushLive()` plays the last 6 queued fresh events once the chart is drawn, as today. | AC7 |

## Formats, colours and text (AC9)

| # | Rule | AC |
|---|---|---|
| FC25 | **`fmt.dur1(seconds)`.** `r = Math.round(s)`. `r < 60`: `${r}s`. Else `m = s / 60`; if `m.toFixed(1)` is below `60.0`: `${m.toFixed(1)}m`. Else `${(s / 3600).toFixed(1)}h`. So `6s`, `42.0m`, `1.4h`; 59.6 s is `1.0m`; 3599 s is `1.0h`. Negative or not finite: `0s`. Used for every time on the chart. `↻` marks every run count. | AC9 |
| FC26 | **Colour tokens.** Added to every `:root` theme block (light, dark media, dark override): `--run1: #2e9d5b; --run2: #8b5cf6; --run3: #e0901f; --pass: #2e9d5b; --warn: #c9b22c; --fail: var(--critical); --flow-forward: var(--s2); --flow-model: var(--s1); --flow-tools: var(--s4)`. Red (`--fail`, `--critical`) is used only for a test failure, the Fail bar and the sent-back dot and path. No other Flow element uses red. | AC9 |
| FC27 | **Text from one table.** `flowTextCss()` returns one rule per `FLOW_TEXT` kind, `.fc-t-<kind> { font-size: <px>px; color: var(<ink>); }`; boot writes it into `<style id="fc-text">`. Every text-bearing element the chart, the legend and the settings write carries one `fc-t-<kind>` class. No other `.fc` or `#flow-show` CSS rule sets `font-size` or `color` on text. Run, pass, warn and fail colours are used only for borders, bars, swatches, dots and sparklines, never for text. Subtle text is `--ink-2`, never `--muted` (3.6:1 in light). | AC9 |
| FC28 | **Measured.** Every `FLOW_TEXT` size is ≥ 10 px, and nothing in `#flow` is scaled (FC4), so CSS px is rendered px. Every `FLOW_TEXT` ink has a WCAG contrast ratio ≥ 4.5:1 against `--surface` (boxes, pills) and `--surface-2` (groups, dimmed boxes), in the light and the dark tokens. | AC9 |

## Known limits

- The chart's geometry (arrow heights, path ends, nothing cut off) has no
  automated test until A18 adds browser tests; the proxy's screenshots are
  the evidence.
- Live counts come from pytest's progress lines (`-q` and default
  verbosity, with or without xdist). `pytest -v`, jest and other runners
  show elapsed time only. Without a `collected`/`workers [N items]` line
  the total is estimated from the percentage until the run ends.
- The heartbeat file is rewritten at most every 2 s for counts, so the bar
  moves in steps.
- Events written before this story have no `rate` and no `step`: their
  roles show "no rate yet", and their run numbers match on role and story
  only.
