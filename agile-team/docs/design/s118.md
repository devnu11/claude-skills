# s118: The Flow chart in HTML, readable at real size

The Flow tab's chart is rebuilt as HTML, CSS and inline SVG from the
snapshot. Mermaid goes. The visual spec for anything the ACs leave open is
mock **variant N**: [`s118-mock.html#n`](s118-mock.html#n), a byte-for-byte
copy of the approved `.team/run/liaison/flow-chart-mock-approved.html`. It
is committed with this design, so developers and reviewers do not need
`.team/run/`. Open it in a browser; it lands on tab N. The functions to read
are `variantN`, `nBox`, `nTool`, `nCols`, `afterN` and `afterK`. The other
tabs (A–M) are earlier drafts and are not part of the spec. The copy is not
edited. Where this file and the mock differ, this file wins, and each
difference is listed under "Differences from the mock".

Developer: **developer-gui**, alone. Most of the work is in `index.html`.
Twelve small runner changes feed it (R1–R12, Python). Each is listed with
its exact signature.

ADRs: **ADR-0052** (HTML flow chart, overlay dots; supersedes ADR-0003,
amends ADR-0047), **ADR-0053** (streamed command output and the live test
tally; **amended in round 2**: the counts come from a pytest plugin, not
from progress lines), **ADR-0048 amended** (the open stage row gains
`tests`; the board gains `refresh`), **ADR-0052 amended in round 3**
(the snapshot's `stage_descriptions`; the group width's two bounds). No new runtime dependency: the plugin
imports only the stdlib and pytest, and pytest loads it in the repo's own
test environment, never in the runner's. One outside URL goes away
(Mermaid).

| FC2 | **Who is drawn.** The used roles (`r.used !== false`, ADR-0047 FL8). The Product Owner is always drawn. Inside a group: the table's order first, then unknown roles by name. All four stage groups are always drawn, an empty one with its title only, so the layout never shifts. | AC2 |
| FC3 | **Top row.** Left to right: a `You` pill, a two-way arrow, a `Liaison` pill, a two-way arrow, the boxed Leadership group. Its title is written sideways (mock `.h-lead > .h-title`). Each role gets all three cells, an empty `<div>` where it has no tools, so the boxes share row 2 whatever hangs above or below them. | AC2 |
| FC4 | **Stage row.** `.fc-cols` is a flex row: group, gap, group, gap, group, gap, group. A group is `flex: 0 1 var(--group-max); min-width: var(--group-min)` with `--group-max: 236px` and `--group-min: 216px`, one setting per bound (t74). A gap is `flex: 1 0 var(--gap-min)` with `--gap-min: 24px`, and holds one arrow (`width: 100%`). So with room to spare (row width ≥ 4 × 236 + 3 × 24 = 1016 px) the groups are 236 px and only the arrows stretch. With less, the arrows stay at 24 px and the groups shrink, down to 216 px (936 px row). Below that, `#flow` scrolls sideways (`overflow-x: auto`). At a 1024 px window the card's content is 958 px, so the groups are about 221 px and nothing scrolls. Nothing scales: no `transform`, `zoom`, `scale()` or `max-width: 100%` applies to anything inside `#flow`. | AC1, AC2 |
| FC5 | **Arrow height.** After each layout, `alignArrows(root)` sets each gap's `--arrow-y` so its arrow is level with the vertical middle of the first `.fc-box` of the group to its right. Measure with `getBoundingClientRect()` (box middle minus gap top). The arrow is `margin-top: var(--arrow-y, 60px)`. | AC2 |
| FC6 | **Roles in a group.** A role and its tools form one `.fc-unit` (a flex column, `gap: 0`). Units stack without aligning rows across groups. ## Role box (AC3, AC4)

`roleBox(m, role)` returns, in this order (mock `nBox`):

1. `<b class="fc-t-name">` the role name.
2. Meta line `.fc-meta`: model family (`familyOf`, s109) plus
   ` · <provider>` when not anthropic; then `.f-tokens` (`fmt.tok`),
   `.f-cost` (`fmt.usd`), `.f-time` (`fmt.dur1` of awake seconds),
   joined by ` · ` (CSS `span + span::before`). A role with no totals in
   the scope and no open step shows `idle` instead of the three numbers
   (ADR-0047 FL4).
3. `.f-bounces` `↩ N bounced`, only when N > 0.
4. `.f-share` the model/tool bar (FC9).
5. `.f-spark` the sparkline row (FC10).
6. The live block, only on the running role (FC11).

| # | Rule | AC |
|---|---|---|
| FC8 | **Numbers.** Tokens and cost: `scopeTotals(view)` (ledger). Awake time: the role's finished steps in scope (`scopeTotals` seconds). Bounces: `flowStats` run over the scoped events: `flowStats({ ...view, events: view.events.filter(inScope(view)) })`. The PO: tokens and cost as today, but `—` in Story scope (its ledger rows have no story); its time is the model plus tool seconds of its `po-turn`s in scope (`turnSplit`), `—` in Story scope. | AC3, AC10 |
| FC9 | **Model/tool bar.** `shareParts({ model, tools })` returns `{ model: p, tools: 100 - p }` with `p = Math.round(100 * model / (model + tools))`, or `null` when `model + tools` is not above 0. Inputs: `stepSplit(view, role)`, and `turnSplit(view)` for the PO. With parts: two spans in `--flow-model` and `--flow-tools` and the caption `model p%` / `tools q%`, each with a 6 px swatch. With `null`: a dashed bar (`repeating-linear-gradient` in `--axis`) captioned `no model/tool timing yet`. | AC3 |
| FC10 | **Sparkline.** `sparkSvg(values, ink)` draws a 96×20 SVG: an area path (SVG attribute `fill-opacity=".16"`, never a CSS rule) and a 1.5 px line, scaled to the series' max, no text. Every other role uses the `data.rate` of its newest `step-end` in scope (the PO: newest `po-turn` in scope) in `--ink-2`, with `last step` before it. Under 2 points (an older event has no `rate`): `last step · no rate yet`, no SVG. | AC3, AC4 |
| FC11 | **The running role.** The role of `liveStep(view)`. Its box and its group get the class `run1`, `run2` or `run3` (FC14): a 2 px border in the run colour; the box also gets a glow (`box-shadow: 0 0 9px color-mix(in srgb, var(--runN) 60%, transparent)`). Dimmed is `.fc-box.dim`: `--surface-2` fill and `--ink-2` text. Colour only: no `opacity`, `filter`, `transform` or `mix-blend-mode` on anything in `#flow`. The running role is never dimmed. | AC3 |

| FC21 | **Geometry.** `layoutFlow()` runs after every chart write, on `resize`, after a settings change and when the Flow tab is shown. | FC22 | **Which dot.** `dotFor(view, e)` for a fresh `step-start` with a story; `null` for any other event, and `null` when `e` is not in `view.events` (`findIndex` gives −1: guard before slicing). ### The tally plugin (R9)

```python
"""Live test counts for the agile-team runner (s118 AC6), loaded through PYTEST_PLUGINS.

It does something only where AGILE_TEAM_TALLY names a file. Imports nothing from agile_team."""
ENV = "AGILE_TEAM_TALLY"
WRITE_EVERY_S = 0.5
RANKS = {"passed": 1, "skipped": 2, "xfailed": 2, "xpassed": 2, "failed": 3, "error": 3}

def pytest_configure(config: pytest.Config) -> None:
    """Pop ENV; when it names a file, register a Recorder for it (name "agile-team-tally")."""

@dataclass(eq=False)
class Recorder:
    """Counts this session's tests and writes the record to ``path``."""
    path: Path
    config: pytest.Config
    session_id: str = field(default_factory=lambda: f"{os.getpid()}-{time.time():.3f}")  # the record's "session"
    total: int | None = None
    ranks: dict[str, int] = field(default_factory=dict)   # nodeid → worst rank of its reports so far
    done: set[str] = field(default_factory=set)            # nodeids whose teardown report came
    warned: set[str] = field(default_factory=set)          # nodeids that recorded a warning
    written_at: float = -math.inf

    def pytest_collection_finish(self, session) -> None            # total = len(session.items) when above 0 (no xdist)
    @pytest.hookimpl(optionalhook=True)
    def pytest_xdist_node_collection_finished(self, ids) -> None   # total = max(total or 0, len(ids)) (xdist controller)
    def pytest_runtest_logreport(self, report) -> None             # fold the report; on teardown, mark done; write when due
    @pytest.hookimpl(optionalhook=True)
    def pytest_warning_recorded(self, when, nodeid) -> None        # when == "runtest" and nodeid: add to warned; write when due
    def pytest_sessionfinish(self) -> None                         # write now
    def outcome(self, nodeid: str) -> str                          # "failed" | "warned" | "skipped" | "passed"
    def record(self) -> dict[str, Any]                             # {"session", "total", "passed", "warned", "skipped", "failed"}
```

Rules (P1–P7):

- **P1. Active only with a file, and only in the first process.** `pytest_configure` runs `os.environ.pop(ENV, "")`. It also takes `agile_team_tally` out of `os.environ["PYTEST_PLUGINS"]`, deleting the variable when nothing else is left (`unlisted(value) -> str`, a module function). An empty path → nothing is registered and the plugin does nothing. This clean-up matters for two reasons. pytest-xdist workers start after `pytest_configure` and inherit the cleaned environment, so only the controller counts. And a test that starts its own pytest (this repo has such tests) neither loads the plugin nor gets a tally file, so it can't write over the real counts or fail to import the plugin under an environment of its own.
- **P2. Outcome of a report.** `category = config.hook.pytest_report_teststatus(report=report, config=config)[0]`: pytest's own classification, the one its terminal summary uses. Rank `RANKS.get(category, 0)`. A test's rank is the worst of its reports (setup, call, teardown). An empty or unknown category ranks 0.
- **P3. A test counts once, at its teardown report.** Every test gets one (pytest always runs teardown). With xdist the controller receives each worker's reports through `pytest_runtest_logreport`. `done` is "reports received" (AC6).
- **P4. Category of a done test**, which makes the four counts disjoint: rank 3 → `failed`; else in `warned` → `warned`; else rank 2 → `skipped`; else `passed`. Warn is "the tests that recorded a warning". pytest records a test's warnings *after* its teardown report (they are relayed when its protocol ends), so a test first counts as Pass and moves to Warn when its warning arrives. A warning with `when` other than `"runtest"`, or with an empty `nodeid` (collection, config), counts for no test.
- **P5. Total.** Without xdist: `len(session.items)` at `pytest_collection_finish`. On the xdist controller (whose `session.items` is empty) it comes from `pytest_xdist_node_collection_finished`, the hook xdist calls from `worker_collectionfinish`. Each worker collects the whole suite, so take the largest. Both xdist-only hooks are `optionalhook=True`, so a run without xdist (or with pytest < 6, which lacks `pytest_warning_recorded`) still loads the plugin.
- **P6. Writing.** `record()` counts `outcome(n)` over `done` and writes `json.dumps(record)` to `path.with_name(path.name + ".tmp")`, then `os.replace`s it onto `path`, so a reader never sees half a record. Reports and warnings write only when `WRITE_EVERY_S` has passed since `written_at` (`time.monotonic()`). `pytest_sessionfinish` always writes.
- **P7. Never breaks a test run.** Every hook body runs under `contextlib.suppress(Exception)`. An error there would fail the user's pytest session, which is worse than a missing count.

### The tally channel (R10)

`agile_team/tally_watch.py`, "the runner side of the tally plugin (s118 R10)":

```python
PLUGIN = "agile_team_tally"
PLUGIN_DIR = Path(__file__).parent / "pytest_plugin"
TALLY_ENV = "AGILE_TEAM_TALLY"           # the plugin's ENV
TALLY_POLL_S = 0.5
PLUGIN_FAILED = re.compile(r'Error importing plugin "agile_team_tally"')

class Append(NamedTuple):
    """A value added at the end of a list-like environment variable."""
    key: str
    value: str
    sep: str
    def onto(self, base: Mapping[str, str]) -> str:
        """``base[key]``, ``sep`` and ``value``; just ``value`` when ``base`` has none or ""."""

APPENDS = (Append("PYTHONPATH", str(PLUGIN_DIR), os.pathsep), Append("PYTEST_PLUGINS", PLUGIN, ","))

def plugin_env(base: Mapping[str, str], path: Path) -> dict[str, str]:
    """``base`` plus each APPENDS row and the tally file in TALLY_ENV."""
def plugin_failed(output: str) -> bool:
    """True when pytest could not import the plugin (the command then runs again without it)."""

@dataclass(eq=False)
class TallyWatch:
    """Reads the tally file every TALLY_POLL_S on a thread and tells the run each new record."""
    path: Path
    run: stages.Run
    last: str = ""
    stopping: threading.Event = field(default_factory=threading.Event)
    thread: threading.Thread | None = None
    def start(self) -> None          # daemon thread on _watch
    def stop(self) -> None           # set stopping; join the thread for at most TALLY_POLL_S * 4; then _look() once more for the final record
    def _watch(self) -> None         # while not system.wait_event(self.stopping, TALLY_POLL_S): self._look()
    def _look(self) -> None          # text = file text (OSError → ""); when text and text != last: last = text; run.hear(text) (any exception swallowed)

@contextmanager
def watching(run: stages.Run) -> Iterator[dict[str, str]]:
    """A scratch tally file watched for ``run``; yields the command's environment; removes the file after."""
```

Rules (T1–T6):

- **T1. Environment.** `plugin_env` returns `{**base, **{a.key: a.onto(base) for a in APPENDS}, TALLY_ENV: str(path)}`. The repo's own entries come first, so they win.
- **T2. `watching(run)`.** `path = system.scratch_file("agile-team-tally-")`; `watch = TallyWatch(path, run)`; `watch.start()`; yield `plugin_env(system.environ(), path)`. In `finally`: `watch.stop()`, then `system.remove(path)` and `system.remove(` the `.tmp` beside it `)`.
- **T3. New `system.scratch_file(prefix: str) -> Path`**, "A new empty file in the system temp directory; the caller removes it": `tempfile.mkstemp(prefix=prefix, suffix=".json")`, close the handle, return the path.
- **T4. `CommandShell.run`**, still "run `command`; on timeout kill its group and return `TIMED_OUT`": `code, out = self._watched(command)`, then `stages.note(command, code)` as today. New `def _watched(self, command: str) -> tuple[int, str]`, "with the tally plugin when a stage is open": `run = stages.current()` (on the caller's thread: context variables do not reach a new thread). With no run, `return self._run(system.ShellCommand(command, self.repo))`, so nothing is injected outside a stage. With a run: `with tally_watch.watching(run) as env: code, out = self._run(system.ShellCommand(command, self.repo, env))`. Then, if `code != 0 and tally_watch.plugin_failed(out)`, run once more with no plugin and return that result. Otherwise return `(code, out)`. Split it so each function stays under 8 lines.
- **T5. A tally never breaks a gate.** The plugin can't be imported when the command sets its own `PYTHONPATH` (it replaces ours) while `PYTEST_PLUGINS` still names the plugin. pytest then stops with `Error importing plugin "agile_team_tally"`, and T4 runs the command once more without the plugin, under a fresh `limit_s`. A listener's exception and an unreadable file are swallowed (`_look`).
- **T6. What shows.** The `test` and `coverage` commands run through `CommandShell`, inside the stage the caller opened (`gate.tests+coverage`, `gate.tests-red`, `gate.suite-runs`, `boundary.check` …), so any of them that runs pytest shows live counts. Commands that run no pytest (lint, jest) write no record and leave `tests` at `null`. The running tool then shows its elapsed time only.

Heartbeat `stages[].tests` (ADR-0048 as amended by ADR-0053):
`{"passed": int, "warned": int, "skipped": int, "failed": int, "total": int | null, "points": [int], "fail_at": int | null}`.

## Known limits

- The chart's geometry (arrow heights, path ends, nothing cut off) has no
  automated test until A18 adds browser tests; the proxy's screenshots are
  the evidence.
- Live counts come from the tally plugin, so any pytest run (any
  verbosity, with or without xdist) inside a stage has them. jest and
  other runners show elapsed time only.
- A command that sets its own `PYTHONPATH` runs twice when it calls pytest
  (T5): once failing to load the plugin, then without it, with no counts.
  A command that clears the environment (`env -i …`) shows no counts.
- A test whose worker crashed (xdist reports a crash with no teardown
  report) is not counted, so the bar can stop short of the total.
- The plugin writes at most every 0.5 s, the runner reads every 0.5 s, and
  the heartbeat is rewritten at most every 2 s for counts, so the bar
  moves in steps.
- When a stage runs two pytest sessions (`test && test`), the chart shows
  the one that is running. The first session's counts are gone once the
  second reports.
- Events written before this story have no `rate` and no `step`: their
  roles show "no rate yet", and their run numbers match on role and story
  only.
