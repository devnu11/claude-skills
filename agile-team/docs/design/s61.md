# s61: The runner halts when the checkout changes under it

Story: `.team/stories/s61.md`. Developer: `developer-cli`. ADR:
`docs/adr/ADR-008-checkout-guard.md`.

## Idea

The runner keeps one record in `state.json`: the branch it runs on and the
commit it expects there (`checkout`). Only the runner's own git writes move
that record, and they do it right after they write. Everywhere else the
runner compares the live checkout with the record. On any difference it halts
with its own kind (`checkout`), status `checkout-changed`, posts a question,
and leaves the tree alone. The human puts the checkout back, or keeps it with
`agile-team accept-checkout`.

Roles cannot move HEAD (role Bash allows only read-only git, `guard.SAFE_GIT`),
so any move the runner did not make is foreign.

## Rules

- **K1 Record.** `state.checkout` is `{branch, head}` (full sha) or `null`.
  It is written only by:
  1. the first check that passes while it is `null` (K2), which records the
     live branch and HEAD;
  2. `Runtime.record_checkout()`, called right after the runner's own git
     writes: the step/PO commit and quarantine (`settle_tree`), a salvage
     (`save_interrupted`, `recovery.recover_killed`), the sprint-start merge
     (`BoundaryRunner._merge_in`, outcome `MERGED`). s59's boundary rebase
     must call it after it rewrites the recorded story hashes;
  3. `agile-team accept-checkout` (K7).
  The record is saved to `state.json` at once (a crash between a runner
  commit and a later save must not leave a stale record).
- **K2 What is checked.** The checkout matches when all hold:
  - HEAD is attached (`git symbolic-ref` names a branch);
  - no git operation is in progress: none of the `OPERATIONS` paths exists in
    the worktree's own git dir (`git rev-parse --absolute-git-dir`);
  - with a record: the branch equals `checkout.branch` and HEAD equals
    `checkout.head`.
  With no record only the first two apply. The review worktree
  (`.team/run/review/`, s29) has its own git dir, so a cherry-pick in progress
  there is not seen; that is intended.
- **K3 When it is checked.**
  | Where | Code |
  |---|---|
  | `start` and `start --resume`, before kill recovery, preflight or any commit | `cli.cmd_start` → `checkout.Guard.on_start()` |
  | every router tick (before every router step, boundary stage, and on every wait poll) | `Router._tick` → `Runtime.checkout_moved()` |
  | before every PO turn | `PoRun._turn` → `Runtime.checkout_moved()` |
  | before every role step and after it, before every commit or quarantine | `Runtime.settle_tree` (via `settle_po` at the start of `_run_step`, and via `settle` after the step) → `verify_checkout()` |
  | before every gate | `Runtime.gate` → `verify_checkout()`; `Tools.pass_tests` → `checkout_moved()` |
  | before every salvage | `Runtime.save_interrupted` (K5) |
- **K4 Halt.** A mismatch inside a run calls `Runtime.halt_run(Halt(CHECKOUT,
  reason))`: status `checkout-changed`, `status_reason` = reason, one
  `question` note (`Halt.message()`, plus the s47 waits suffix), exit 78 when
  the process ends. Nothing after the check runs: no commit, quarantine,
  gate, step-end event, salvage or further step. The PO's `run_role` gets
  `{"status": "halted", "role": …, "reason": …, "next": "the run is stopping; end your turn"}`.
  The cost of a step that already ran is still ledgered (it was spent). The
  step's uncommitted edits stay in the tree and `in_flight` stays set.
  `CheckoutChanged` is a halt, not a crash: it is not written to `crash.log`.
- **K5 No salvage on a moved checkout.** `save_interrupted` returns `None`
  without touching git when the checkout does not match. This holds for every
  halt kind and for `Cause.ERROR`.
- **K6 Start and resume.** `Guard.on_start()` runs first in `cmd_start`. On a
  mismatch it sets status and reason, saves, posts the question only when no
  open question has the same text (so repeated resumes do not pile up
  questions), and `cmd_start` prints the one stderr line and exits 78. On a
  match it records when unrecorded and answers every open checkout question
  with `restored: <branch> at <sha7>`.
  This applies to every `start`, with `--task`, `--resume` or both: the
  record outlives the run, so a change made between runs halts the next start
  (PO ruling, design review). No `--task` exemption. Only `checkout: null`
  (a repo with no record) skips the record comparison.
- **K7 Accept.** `agile-team accept-checkout`:
  - refuses (exit 1) while a runner is alive (`state.runner_alive`):
    `the runner is running; stop it first`;
  - refuses (exit 1) a detached HEAD or an operation in progress:
    `cannot accept <found>: check out the team branch and finish or abort any git operation first`;
  - otherwise records the live branch and HEAD, sets status `stopped` with
    reason ``checkout accepted: <branch> at <sha7>; run `agile-team start --resume` ``
    when the status was `checkout-changed` (any other status is left alone),
    logs a `checkout` event `{"action": "accepted", "from": <old record or null>, "to": <new record>}`,
    answers every open checkout question with `accepted: <branch> at <sha7>`,
    prints `accepted checkout <branch> at <sha7>` and exits 0.
- **K8 Reason text.** Exactly:
  `checkout changed: expected {expected}; found {found}; last HEAD move: {move}`
  - `{expected}`: `<branch> at <sha7>`, or with no record
    `a branch with no git operation in progress`;
  - `{found}`: `<branch> at <sha7>` or `detached HEAD at <sha7>`, followed by
    ` with a <operation> in progress` when one is;
  - `{move}`: the newest HEAD reflog entry, from
    `git log -g -1 --date=iso --format=%gd %gs HEAD`, stripped; `no reflog entry`
    when git fails or prints nothing.
  Example: `checkout changed: expected feat/agile-team-dashboard at a3cc264; found detached HEAD at 92a38ea; last HEAD move: HEAD@{2026-10-11 16:14:54 +0200} checkout: moving from feat/agile-team-dashboard to 92a38ea`.
  The open checkout questions are those whose text starts with
  `checkout changed: `.
- **K9 Status.** New `RunStatus.CHECKOUT_CHANGED = "checkout-changed"`.
  `RunState.halted()` is true for it (with `done` and `blocked`). The
  dashboard's status pill for it is `critical` (red). `status` JSON gains
  `checkout` (the record or `null`).
- **K10 Budget flow.** The human's budget-raise commit is a foreign commit,
  so `BUDGET_ADVICE` becomes
  ``raise team.budget_usd in .agile-team.toml and commit it, run `agile-team accept-checkout`, then run `agile-team start --resume` ``.

### `agile_team/checkout.py` (new)

Imports: `from .git_ops import Git`, `from .halt import Halt, HaltKind`,
`from . import state as state_mod`, `from .state import CheckoutRecord, RunState, RunStatus`,
`from .relay import Note, Relay`, `from .events import EVENTS, Event, EventKind, EventLog`.
It must not import `dispatch`, `recovery` or `cli` (they import it).

```python
CHECKOUT_HEAD = "checkout changed: "
REASON = CHECKOUT_HEAD + "expected {expected}; found {found}; last HEAD move: {move}"
UNRECORDED = "a branch with no git operation in progress"
DETACHED = "detached HEAD"
IN_PROGRESS = " with a {operation} in progress"
NO_MOVE = "no reflog entry"
MOVE_ARGS = ("log", "-g", "-1", "--date=iso", "--format=%gd %gs", "HEAD")
RESTORED = "restored: {checkout}"
ACCEPTED = "accepted: {checkout}"
ACCEPTED_REASON = "checkout accepted: {checkout}; run `agile-team start --resume`"
NOT_ACCEPTABLE = "cannot accept {found}: check out the team branch and finish or abort any git operation first"
OPERATIONS: tuple[tuple[str, str], ...] = (
    ("rebase-merge", "rebase"),
    ("rebase-apply", "rebase"),
    ("MERGE_HEAD", "merge"),
    ("CHERRY_PICK_HEAD", "cherry-pick"),
    ("REVERT_HEAD", "revert"),
    ("BISECT_LOG", "bisect"),
)


class CheckoutChanged(Exception):
    """Raised after the runner recorded a checkout halt; ``halt`` is that halt."""

    def __init__(self, found: Halt) -> None: ...


class CheckoutError(Exception):
    """``accept-checkout`` cannot accept the live checkout."""


@dataclass(frozen=True)
class Found:
    """The live checkout: branch (``None`` when detached), HEAD, operation in progress."""

    branch: str | None
    head: str
    operation: str | None

    def text(self) -> str:
        """``<branch> at <sha7>`` or ``detached HEAD at <sha7>``, plus IN_PROGRESS (K8)."""


@dataclass(frozen=True)
class Drift:
    """A mismatch: the record, the live checkout and the newest HEAD reflog entry."""

    expected: CheckoutRecord | None
    found: Found
    move: str

    def reason(self) -> str:
        """REASON filled per K8."""

    def halt(self) -> Halt:
        """``Halt(HaltKind.CHECKOUT, self.reason())``."""


def read(git: Git) -> Found:
    """The live checkout (K2)."""

def operation(git: Git) -> str | None:
    """The first ``OPERATIONS`` name whose path exists in the worktree's git dir."""

def last_move(git: Git) -> str:
    """The newest HEAD reflog entry (``MOVE_ARGS`` via ``git.attempt``), or NO_MOVE."""

def matches(expected: CheckoutRecord | None, found: Found) -> bool:
    """K2: attached, no operation, and the recorded branch and HEAD when recorded. Pure."""

def check(git: Git, expected: CheckoutRecord | None) -> Drift | None:
    """``None`` when the checkout matches, else the drift (reads the reflog only then)."""

def recorded(git: Git) -> CheckoutRecord:
    """The live branch and HEAD as a record; callers have checked the checkout (K1)."""

def answer_open(relay: Relay, text: str) -> None:
    """Answer every open question whose text starts with CHECKOUT_HEAD with ``text``."""


@dataclass
class Guard:
    """The checkout check outside a live ``Runtime``: ``start`` and ``accept-checkout``."""

    run_dir: Path
    git: Git

    def on_start(self) -> Halt | None:
        """K6: escalate and return the halt on a mismatch; else record if unrecorded, answer RESTORED."""

    def accept(self) -> CheckoutRecord:
        """K7 (without the live-runner check, which is the CLI's): record, status, event, answers."""
```

`recorded(git)` uses `git.branch() or ""`. An empty branch never matches,
so a record made on a detached HEAD (which K1 never does) halts at the next
check rather than passing.

Escalation in `on_start` (helper, e.g. `_escalate(state, found)`):
`state.mark(found.rule.status, found.reason)`, `state_mod.save`, then
`Relay(run_dir).post(Note(found.rule.note_kind, found.message()))` unless an
open question already has exactly that text.

### `agile_team/dispatch.py` (`Runtime`)

New methods (documented, each short):

```python
def checkout_moved(self) -> Halt | None:
    """K3/K4: halt the run when the checkout drifted; record it when unrecorded and matching."""

def verify_checkout(self) -> None:
    """``checkout_moved``, raising ``CheckoutChanged`` with the halt when it halted."""

def record_checkout(self) -> None:
    """K1: expect the live branch and HEAD; call only after the runner's own git writes. Saves."""
```

Changed:

- `run_role`: add `except CheckoutChanged as moved: return halted_report(request.role, moved.halt)`
  before the generic `except Exception` (no `crash.log` entry; K4).
- `halted_report(role: str, found: Halt)` (was `plan: Plan`); `_step_failed`
  passes `plan.role.name`.
- `settle_tree`: first line `self.verify_checkout()`; after quarantine and
  commit, `self.record_checkout()` when either wrote a commit.
- `gate`: first line `self.verify_checkout()`.
- `save_interrupted`: return `None` at once when
  `checkout.check(self.git, self.state.checkout)` is not `None` (K5); after
  the salvage, `self.record_checkout()` (replaces the plain `save()`).
- `_step_failed` is unchanged: a `CheckoutChanged` from `settle` is not a
  limit, so it calls `save_interrupted(Cause.ERROR)` (K5 makes it a no-op)
  and re-raises to `run_role`.

### `agile_team/router.py`

- `Router._tick`: first `if self.runtime.checkout_moved(): return None`.

### `agile_team/po_tools.py`

### `agile_team/boundary_runner.py`

### `agile_team/recovery.py`

### `agile_team/cli.py`

## Design review (round 0)

The code matches K1–K10 and the module changes. Follow-ups from
`.team/reviews/s61.md`, left for a later story (none breaks an AC):

- **F1** K6 dedups on an exact `Halt.message()`, but an in-run halt posts the
  message plus the s47 waits suffix, so the first resume after it can add a
  second checkout question (both get answered). Better rule for the
  follow-up: skip the post when an open question starts with
  `Halt.message()`.
- **F2** The AC6 rebase test should assert `with a rebase in progress` in the
  reason, and one end-to-end case should leave a merge conflict on the
  recorded branch (HEAD attached, same sha).
- **F3** `Guard.accept` repeats the first test of `matches`; extract one
  `Found` predicate for both.
