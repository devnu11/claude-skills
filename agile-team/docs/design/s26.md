# s26: A presentation must start the delivery, and "presentation ready" passes only if it is up and answering

Developer: **developer-cli** (runner Python: `sandbox.py`, `presentation.py`,
`gates.py`, `dispatch.py`, `handover.py`, `config.py`, `cli.py`; the built-in
roles `integration-tester.md`, `customer-proxy.md` and `product-owner.md`).
Then **devops** for the `dashboard` `[[delivery]]` lines in `.agile-team.toml`
(see "DevOps change"). The Architect updated `reference/protocol.md`,
`SKILL.md`, the README row and `customer/acceptance-presentations.md` in the
design step.

Story: `.team/stories/s26.md`. Builds on [s13](s13.md).

## Root cause (sprint 8, events e451 to e458)

`--repo` defaults to `.`, and `cli` passes `Path(args.repo)` through
unresolved. So `config.repo` is `.`, and the sandbox root is the **relative**
path `.team/run/customer/dashboard`. `Prepared.expand` puts that into the
prepare command:

```text
uv run --directory ./agile-team/runner agile-team --repo .team/run/customer/dashboard/presentation/workspace dashboard …
```

`uv run --directory` changes the cwd to `agile-team/runner` first, so
`--repo` resolves to `agile-team/runner/.team/run/customer/…`. That path does
not exist, hence `.agile-team.toml not found in .team/run/customer/dashboard/presentation/workspace`.
The integration-tester's workspace was fine: the copy in the sandbox holds
`.agile-team.toml`. The same relative path also reached the Proxy's prompt
(s13 E8 asks for an absolute path). The background process's output went
nowhere, and the e2e gate only checked files, so nothing caught it before the
Proxy ran.

## Rules

| # | Rule | AC |
|---|---|---|
| L1 | **Absolute paths.** `cli` resolves `--repo` once (`Path(args.repo).resolve()`) for every command, so `Config.repo` and every path derived from it are absolute. `Prepared.expand` also fills `{repo}` and `{sandbox}` with `.resolve()`d paths, so a prepare command never depends on its cwd, even with a relative `Config`. | AC1 |
| L2 | **Address placeholders.** `Prepared.expand` also fills `{host}` and `{port}` from the delivery's `url` (`urlsplit`; a URL with no port uses the scheme's default from `DEFAULT_PORTS = {"http": 80, "https": 443}`; with no `url`, both are `""`). The port comes from config in exactly one place, the `url`. | AC4 |
| L3 | **Liveness is data.** `presentation.PRESENTATIONS` maps a kind to a `Recipe(need, check)`. `check` is `Check.FILES` (s13's file check only) or `Check.SERVICE` (the file check, then start and probe). Only `web` is `SERVICE`. The *start command* is the delivery's `prepare` and the *probe* is its `url` joined with its new `probe` field (`urljoin(url, probe)`; `""` probes `url` itself). No code branches on a kind or a delivery name. | AC3 |
| L4 | **Start.** For a `Start.BACKGROUND` kind, `Preparer.prepare` (in order): stops a stale service (L7), lays out the sandbox, copies the presentation (s13 E7), refuses a busy port (L8), starts `prepare` with `Popen(…, start_new_session=True)` with stdout and stderr appended to the service log (L6), writes the pid file (L6), then waits for the probe (L5). It returns the `Prepared` with the process still running. A `BACKGROUND` delivery with an empty `prepare` starts nothing, but is still probed (L5, with no process to watch), so a pass always means something answered. `Start.FOREGROUND` kinds are unchanged. | AC1, AC4 |
| L5 | **Probe.** Up to `Preparer.attempts` times (default `PROBE_ATTEMPTS = 120`), with `sleep(PROBE_EVERY_S = 0.25)` between them: if `probe(url)` answers, the service is up. If the process has exited, stop waiting at once. If the service never answers, the runner builds the reason from "Reason strings" (from the process's state *before* it is signalled), then stops the service (`Prepared.stop`), then raises `NotUp` with that reason. *Answers* (`http_answers`) = an HTTP `GET` within `PROBE_TIMEOUT_S = 2` returns status 200, and if the response's `Content-Type` is `application/json` the body parses as JSON. Any `OSError` or `ValueError` is "no answer". For the dashboard, `probe = "api/snapshot"` gives `GET /api/snapshot` → 200 JSON. | AC1, AC2 |
| L6 | **Service files** sit next to the sandbox dir, not inside it (layout wipes the sandbox): `.team/run/customer/<delivery>.pid` (the process group id, as text) and `.team/run/customer/<delivery>.log` (truncated at each start). The Proxy cannot read them: its globs cover only `customer/<delivery>/**`. | AC2, AC4 |
| L7 | **Replace, never reuse.** Before laying out, `stop_stale(root)` reads the pid file. If that pid is still a process group leader (`os.getpgid(pid) == pid`), it sends SIGTERM to the group, waits up to `STOP_WAIT_S = 10` (polling `killpg(pid, 0)`), then sends SIGKILL. It always deletes the pid file. A service left by an earlier step, or by a runner that was killed, is therefore never reused. | AC4 |
| L8 | **Port conflict.** After L7, if something accepts a TCP connection on `host:port` (`port_in_use`, `socket.create_connection` with a 1 s timeout), `prepare` raises `PortBusy` before starting anything. The runner never kills a process it did not start. | AC4 |
| L9 | **Teardown.** `Prepared.stop()` ends the process group (as today) and deletes the pid file. It is idempotent. Every path out of a Proxy step that has prepared a sandbox calls it: the query ends (pass, fail, halt, `CancelledError`) through `_execute`'s existing `finally`, and an exception while planning after `prepare` through a new guard in `Runtime.plan`. The e2e trial (L10) stops its service as soon as the probe answers. | AC4 |
| L10 | **"Presentation ready" gate (s13 E4, extended).** When the pipeline has `acceptance`, an integration-tester `done` at `e2e` passes only if (1) `presentation.missing` gives no reason (s13 E5, unchanged) and (2) for a `Check.SERVICE` recipe, a **trial** succeeds. The trial is `prepare` with the same `Order` the Proxy will get, so it starts the service from the sandbox copy of the presentation, probes it, then stops it. `NotUp` → `BOUNCE` to `e2e` (a round), and the reason holds the command's output. `PortBusy` → `HOLD` (no round, no move; the PO gets a hand-over, L12). A pass is `presentation ready; <probe url> answered`. For `Check.FILES` the pass reason stays `presentation ready`. | AC2, AC3 |
| L11 | **Proxy step (s13 E6, extended).** If the Proxy's own `prepare` raises `NotUp`, the Proxy does not run and nothing is billed. With an `e2e` step, the story goes back to `e2e` with **no round** (`Verdict.RETURN`), through the same path as s13's missing presentation: a `gate` event with `verdict: "return"`, saved, and `{"status": "returned", …}`. With no `e2e` step it is `refused`, as before. `PortBusy` and every other `SandboxError` stay `refused` (an environment problem the PO or human must fix). | AC1, AC5 |
| L12 | **Hold hand-over.** `handover.HANDOVERS` gains a row `Trigger.GATE_HOLD` ("gate_hold"). It applies when the report's gate verdict is `hold` and the handoff status is not `blocked`/`failed` (those already match `STOPPED`). Line: `{story}: {role}'s gate is on hold: {gate_reason}; fix it, then continue_story`. `report_fields` adds `gate_reason` (the gate's `reason`, `""` when there is none). The hold keeps the router off the story until the PO releases it. | AC4 |
| L13 | **Self-contained presentation** (role rule, from the s25 acceptance loop). The integration-tester's prompt says that the Proxy's sandbox can't read repo paths. So the presentation holds no repo paths, only copies of what the customer needs (the ADR, the protocol section, files to try) and captured command output (test and ruff results, with the command and its exit code). The gate doesn't check this; the Proxy judges it. | AC6 |

### Reason strings (tests may assert them exactly)

`<name>` is the delivery name, `<url>` is `urljoin(url, probe)`, `<s>` is
`f"{attempts * PROBE_EVERY_S:g}"`, and `<tail>` is the last
`LOG_TAIL_LINES = 20` lines of the service log (`(no output)` when it is
empty).

| When | Exception / outcome | Text |
|---|---|---|
| process exited before answering | `NotUp` | `delivery '<name>' did not start: the start command exited with code <rc> before <url> answered. Last output:\n<tail>` |
| still running, never answered | `NotUp` | `delivery '<name>' did not answer <url> within <s>s. Last output:\n<tail>` |
| port taken | `PortBusy` | `delivery '<name>' cannot start: <host>:<port> is already in use by a process the runner did not start; stop it or change the delivery's url` |
| e2e gate, trial failed | `Outcome` `BOUNCE` / `HOLD` | `story <id> presentation is not up: <exception text>` |
| e2e gate, trial passed | `Outcome` `PASS` | `presentation ready; <url> answered` |
| Proxy step, `NotUp` | `Outcome` `RETURN` | `<exception text>; run the integration-tester on it` |

The `NotUp` text is what the bounced or returned integration-tester reads in
its brief (the gate reason is the one thing a brief quotes).

## Flow

```mermaid
sequenceDiagram
  participant RT as Runtime
  participant G as Pipeline (e2e gate)
  participant T as presentation.Trial
  participant S as sandbox.Preparer
  participant D as delivery process
  RT->>G: evaluate(story, done) at e2e
  G->>G: presentation.missing? (files)
  G->>T: liveness(story) [Check.SERVICE only]
  T->>S: prepare(config, Order(delivery, source))
  S->>S: stop_stale, layout, copy, port free?
  S->>D: Popen(prepare, start_new_session), log, pid file
  loop up to attempts
    S->>D: GET url+probe
  end
  alt answers
    S-->>T: Prepared
    T->>S: Prepared.stop()
    T-->>G: PASS "presentation ready; … answered"
  else exited / timed out
    S->>D: stop
    S-->>T: NotUp(reason with output)
    T-->>G: BOUNCE to e2e (round)
  else port busy
    S-->>T: PortBusy
    T-->>G: HOLD (hand-over to PO)
  end
  Note over RT,D: later, run_role(customer-proxy)
  RT->>S: prepare (same steps)
  alt NotUp
    RT-->>RT: RETURN to e2e, no round, nothing billed
  else up
    RT->>RT: Proxy query
    RT->>S: Prepared.stop() in finally
  end
```

### `config.py`

- `Delivery` gains `probe: str = ""` as the **last** field. Docstring line in

### `sandbox.py`

| Name | Spec |
|---|---|
| `NotUp(SandboxError)`, `PortBusy(SandboxError)` | Docstrings: "The delivery's service did not come up and answer." / "The delivery's port is taken by a process the runner did not start." |
| `DEFAULT_PORTS`, `PROBE_ATTEMPTS = 120`, `PROBE_EVERY_S = 0.25`, `PROBE_TIMEOUT_S = 2`, `STOP_WAIT_S = 10`, `LOG_TAIL_LINES = 20`, `PID_SUFFIX = ".pid"`, `LOG_SUFFIX = ".log"` | Constants. `Prepared.stop` uses `STOP_WAIT_S` in place of its literal `10`. |
| `Prepared.expand(command)` | L1, L2. Build `{"{repo}": …, "{sandbox}": …, "{host}": …, "{port}": …}` in `_placeholders()` and replace each key. Keep it under 8 lines. |
| `Prepared.address() -> tuple[str, int \| str]` | `(hostname or "", port or DEFAULT_PORTS.get(scheme, ""))` from `urlsplit(delivery.url)`. |
| `Prepared.probe_url() -> str` | `urljoin(delivery.url, delivery.probe)`. |
| `Prepared.pid_file()`, `Prepared.log_file()` | `self.root.with_suffix(PID_SUFFIX)` / `LOG_SUFFIX` (L6). |
| `Prepared.stop()` | As today, then `self.pid_file().unlink(missing_ok=True)` (L9). |
| `stop_stale(root: Path) -> None` | L7. Public, because tests and `Preparer` call it. Helpers: `_group_leader(pid) -> bool` (`getpgid(pid) == pid`, `False` on `ProcessLookupError`/`PermissionError`) and `_end_group(pgid)` (SIGTERM, poll, SIGKILL; reuse `_signal_group`'s suppression). |
| `http_answers(url: str) -> bool` | L5, stdlib `urllib.request` and `json`. |
| `port_in_use(host: str, port: int) -> bool` | L8, stdlib `socket`. |
| `Preparer` | New fields after `popen`: `probe: Callable[[str], bool] = http_answers`, `listening: Callable[[str, int], bool] = port_in_use`, `sleep: Callable[[float], None] = time.sleep`, `attempts: int = PROBE_ATTEMPTS`. All injectable for tests. |
| `Preparer.prepare(config, order)` | `stop_stale(sandbox_root(config, order.delivery))` first, then layout and copy as today. Then a launch table keyed by `kind.start`: `BACKGROUND` → `self._serve(prepared, order.delivery.prepare)`; `FOREGROUND` → today's blocking run when `prepare` is set. |
| `_serve(prepared, prepare)` | Starts the service only when `prepare` is set, then always runs `_await_answer` (L4). |
| `_start(prepared, command)` | `_refuse_busy` (L8), then Popen on `prepared.expand(command)` with `cwd=repo`, `env`, `start_new_session=True`, `stdout=log`, `stderr=subprocess.STDOUT` (the log opened `"wb"` and closed in the parent after Popen), then write the pid file. |
| `_await_answer(prepared)` | L5. On failure, in this order: `reason = _not_up_reason(prepared)`, then `prepared.stop()`, then `raise NotUp(reason)`. The reason picks its row from `prepared.process.poll()`: `None` (or no process) → timed out, otherwise exited with that code. The reason **must** be built before `stop()`, because after the runner signals a real process, `poll()` returns `-15`. Building it after `stop()` would report every hung service as "exited with code -15" (review D1). |
| `_log_tail(path) -> str` | The last `LOG_TAIL_LINES` lines, decoded with `errors="replace"`, or `(no output)`. |

`Prepared` keeps its dataclass fields; the new pieces are methods, so every
existing `Prepared(...)` call still works.

Contract changes, not weakened tests: `need_of` → `recipe_of(...).need`;
`PRESENTATIONS` values are `Recipe`s; a fake `Preparer` for a `web` kind needs
`probe`/`listening`/`sleep` fakes (or `attempts`); assertions on an exact
`Prepared.expand` result now see absolute paths.

1. L1: `expand` with a relative `repo`/`root` gives absolute paths;
   `cli.repo_of` resolves `.`; `Place.of(args).repo` is absolute.
2. L2: `{host}`/`{port}` from `http://127.0.0.1:8799/`, from `http://h/` (80),
   and with no url (`""`).
3. L3: `PRESENTATIONS["web"].check is Check.SERVICE`; every other kind is
   `FILES`; for every kind, `check is SERVICE` ⇔
   `DELIVERY_KINDS[kind].start is Start.BACKGROUND`.
4. L4/L5 start and probe pass: fake `popen` returning a live fake process,
   `probe` true on the 3rd call → `prepare` returns, `sleep` called twice,
   pid file holds the pid, log file created; the copy exists before `popen`
   (s13 E7 still holds).
5. L5 probe fail, two ways: process `poll()` returns 1 → `NotUp` with the
   "exited with code 1" text and the log tail, after one probe; `probe`
   always false with `attempts=3` → `NotUp` "did not answer … within 0.75s".
   Both: `stop` was called and the pid file is gone. Also a **real** hung
   process (`exec sleep 60`, `attempts=2`) → the "did not answer … within
   0.5s" text, never "exited with code" (guards the reason-before-stop order).
   A stale group that traps SIGTERM is ended by SIGKILL (L7). `http_answers`
   on a 204 or 201 → false.
6. L5 `http_answers` against a real stdlib `ThreadingHTTPServer` on port 0:
   200 JSON → true; 200 `application/json` with a bad body → false; 500 →
   false; nothing listening → false.
7. L7 stale: start a real `sleep 60` with `start_new_session=True`, write
   its pid to the pid file, `stop_stale` → process gone, file gone. A pid
   file naming a dead pid → file gone, no error.
8. L8: `listening` true → `PortBusy` with the exact text, and `popen` never
   called. `port_in_use` true for a bound listening socket, false after it
   closes.
9. L9: `Prepared.stop` deletes the pid file and is safe twice. `Runtime`:
   Proxy query raises → `prepared.stop` called; `_fit_role_to_delivery`
   raising after `prepare` → `stop` called and the error propagates.
10. L10 gate: `Checks.presented` with files missing → `BOUNCE`, liveness not
    called; files ok + liveness `PASS` → pass to `acceptance`; `NotUp` →
    `BOUNCE` at `e2e`, round +1, reason starts `story s4 presentation is not
    up: delivery 'dashboard' did not start`; `PortBusy` → `HOLD`, step and
    rounds unchanged. `Trial.liveness` on a `package` delivery never calls
    `prepare`. On a pass it stops the service.
11. L11: Proxy with a fake `prepare_fn` raising `NotUp` → `returned`, story
    at `e2e`, rounds unchanged, `gate` event `verdict: "return"`, no query.
    With no `e2e` step → `refused`. `PortBusy` → `refused`.
12. L12: a report `{"status": "done", "gate": {"verdict": "hold", "reason": "x"}}`
    gives `GATE_HOLD` and the line with `x`. A `blocked` handoff (also a
    `hold`) gives only `STOPPED`.

## Known limits

- A pid file left by a runner that was killed with SIGKILL could name a pid
  that the OS later reuses for an unrelated session leader. L7 would then
  signal that process group. This needs a SIGKILL plus pid reuse plus a
  session leader. Accepted.
- The trial and the Proxy step each start the service, which adds a few
  seconds per Proxy story. Reusing the trial's service would break L7.
- `FOREGROUND` prepare failures still report only the command, not its
  output (out of scope; `cli` was not the failing case).
- `Trial` lets a `SandboxError` other than `NotUp`/`PortBusy` propagate out of
  the gate. Config validation makes this unlikely. If it is ever seen, a
  follow-up should map it in `TRIAL_VERDICTS`.
- `_end_group` on an unreaped child of the runner (a zombie) waits the full
  `STOP_WAIT_S`, because `killpg(pid, 0)` still succeeds. This needs a missed
  L9 teardown first.
- The reason's log tail is read before `stop()`, so anything the service
  prints on SIGTERM is not in it. That is intended: the reason says why the
  service was not up, not how the runner stopped it.
- Readiness is "answers HTTP 200". A `web` delivery whose health needs more
  than one URL is a new `probe` design, not in this story.
