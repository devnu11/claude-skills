# s187 design: a gate fix names its gated commit and tree, and an empty done doesn't count

ADR: [0094](../../../.team/adr/0094-a-gate-fix-that-changes-nothing-does-not-count.md).
Requirements: REQ-257 (AC1), REQ-258 (AC2), REQ-259 (AC3). Developer: `developer-cli`.

## Cause (read at this step's head)

- `router.fix_brief` (`router.py:178`) writes `FIX_HEADING`, `owners.fix_lines` and the
  doc paths. `Fix` (`owners.py:87`) has no sha, so nothing can name the gated commit.
- `Runtime._fix_effects` (`dispatch.py:1583`) pops the head fix on any `done`
  (`fix_outcome` returns `None` for it, `dispatch.py:2298`), commit or not.
- `loops.HISTORY_KINDS` (`loops.py:58`) leaves out `gate-fix`, and no gate event carries a
  sha, so the Manager's `repeated_setback` can't show what a fix committed.

## Rules

| # | Rule | AC |
|---|------|----|
| G1 | **The gated commit.** When `_advance_and_log` settles a story step, it reads the head of the runtime's own tree once (`self.git.head()`: the story's worktree in a story view, else the main checkout). Every fix in the routed outcome whose `gated` is `""` gets that sha. Fixes that already have one keep it (G5 re-queues them). | AC1, AC3 |
| G2 | **Every story gate event carries `head`.** The same sha goes into the event's `result` as `"head"`: on `gate`, `escalation` and `test-dispute` events from `_advance_and_log`, on every verdict. | AC3 |
| G3 | **The brief's `Tree:` section.** A `gate-fix` plan gets, at plan time and in the story's view, a `Tree:` section appended to both `plan.prompt` and `plan.brief`, so `step-start` records it. Its lines come from the pure `owners.format_tree_lines` (texts in G4). The tree is `self.config.repo` (in a view, that is the worktree path). Short shas are the first 12 characters. | AC1 |
| G4 | **Section texts** (`owners.TREE_LINES`, keyed by `TreeState`). Line 1 is always `- The gate ran on commit {gated} in {path}. Your working directory is that tree: run every command there and never cd out of it.`<br>`SAME`: `- Its head is still {gated}.`<br>`MOVED`: `- Its head is now {head}. Commits since the gate, oldest first:`, then one `    - {sha} {subject}` line per commit.<br>`REWRITTEN`: `- Its head is now {head}, which doesn't contain {gated}: its branch was rewritten since the gate ran.`<br>`UNRECORDED` (fix queued before s187, `gated == ""`): line 1 becomes `- The gate's commit wasn't recorded. Your working directory is {path}: run every command there and never cd out of it.`, then `- Its head is {head}.`<br>When `fix.unchanged > 0`, a last line: `- Your last {n} fix step(s) on these items handed off done with no commit, so the items still stand. A done that changes nothing doesn't count as a fix: run the listed tests here, at this head, and fix them. If they pass here, hand off changes_requested and name the commands you ran.` | AC1, AC2 |
| G5 | **An empty done is not a fix.** In `_fix_effects`, a `done` handoff with `plan.commit is None` (no in-scope change was committed; quarantined out-of-scope edits don't count) gives `find_unchanged_fix(story, plan.commit)`: `Outcome(Verdict.ROUTE, FIX_UNCHANGED…, author=Author.ROLE, fixes=[<head fix with unchanged + 1>, *rest])`. It goes through `_advance_and_log` like any setback. `ROUTE` keeps the story at its step, counts no round, and replaces the queue with the same fixes, so the same role runs again. A `done` with a commit pops the head as today. | AC2 |
| G6 | **The reason**, `dispatch.FIX_UNCHANGED`: `"{role}'s gate fix on {files} handed off done with no commit, so the items still stand; the gate ran on {gated}; the fix step runs again"`, with `files` joined by `", "` and `gated` the short sha or `"an unrecorded commit"`. It holds no count, so `loops.normalise` gives the same key both times. | AC2 |
| G7 | **Escalation needs no new code.** `ROUTE` is in `SETBACKS`. The second empty `done` in a row on the same fix has the same key, so `Pipeline._repeat` (with `repeat = 2`) escalates it to the Manager with the G6 reason. The escalation empties the queue, as any escalation does. The Manager's brief is the existing `REPEAT_HEADING`. | AC2, AC3 |
| G8 | **Fix records keep the shas.** `FixRecord` gets `gated` (the fix's) and `head` (the tree's head after the step settled, read in `_record_fix`). The `gate-fix` event gets the same two fields. | AC3 |
| G9 | **The Manager's view.** `loops.HISTORY_KINDS` adds `"gate-fix"`. `manager_view` adds `"fix_rounds": list_fix_rounds(story.fixed)`: the story's fix records grouped by `gated` in first-seen order, `[{"gated": short or "unrecorded", "fixes": [{"role", "files", "commit": short or "none", "head": short or "unrecorded"}]}]`. It uses records, not events, because the first fix's `gate-fix` event comes before the escalation window's first setback. | AC3 |

Not changed: Bash isn't confined to the worktree (the story keeps this out of scope).
`FIX_HEADING`, `REPEAT_HEADING`, the `changes_requested`, `blocked` and `failed` settles,
and the router's offers stay as they are. `fix_brief` makes no git call, so the
scheduler's picking costs nothing more.

## Changes per module

### `agile_team/owners.py`

```python
SHORT = 12  # characters of a sha shown in briefs and the Manager's view

class TreeState(StrEnum):
    """How a gate fix's tree stands against the commit its gate ran on (s187)."""
    SAME = "same"
    MOVED = "moved"
    REWRITTEN = "rewritten"
    UNRECORDED = "unrecorded"

@dataclass(frozen=True)
class Tree:
    """The tree a gate fix step works in, read at plan time (s187 G3)."""
    path: str
    head: str
    state: TreeState
    since: tuple[tuple[str, str], ...] = ()  # (sha, subject) after the gated commit

@dataclass
class Fix:  # + two fields, defaults keep every existing call valid
    gated: str = ""      # full sha the gate ran on (G1)
    unchanged: int = 0   # done handoffs on this fix that committed nothing (G5)

@dataclass
class FixRecord:  # + two fields
    gated: str = ""
    head: str = ""

def format_short(sha: str) -> str:
    """The first ``SHORT`` characters of ``sha``."""

def format_tree_lines(fix: Fix, tree: Tree) -> list[str]:
    """The brief's ``Tree:`` section for one gate fix: G4's lines."""

def mark_gated(fixes: list[Fix], sha: str) -> None:
    """Set ``gated`` to ``sha`` on every fix that has none yet (G1)."""
```

- `TREE_LINES: dict[TreeState, str]` holds the G4 state lines. `format_tree_lines` puts
  `"Tree:"`, line 1, the state line, the `since` lines for `MOVED`, then the `unchanged`
  line. Split it into small helpers as the house rules need.
- `load_fix` passes `gated=data.get("gated", "")` and `unchanged=data.get("unchanged", 0)`.
  `FixRecord(**r)` in `state.py` already takes the new defaults.

### `agile_team/git_ops.py`

```python
def list_after(self, sha: str) -> list[tuple[str, str]]:
    """(sha, subject) of every commit after ``sha`` up to HEAD, oldest first."""
```

`git log --reverse --format=%H%x1f%s <sha>..HEAD`. `log_from` becomes
`[(first, self.subject(first)), *self.list_after(first)]`.

### `agile_team/dispatch.py`

- `FIX_SETUPS[StepKind.GATE_FIX] = Runtime._attach_gate_tree`.
- `def _attach_gate_tree(self, plan: Plan) -> None`: *"s187 G3: append the head fix's
  `Tree:` section to the prompt and the brief."* It builds the text with
  `owners_mod.format_tree_lines(fix, self._read_tree(fix))` and adds `"\n\n" + text` to
  `plan.prompt` and to `plan.brief`.
- `def _read_tree(self, fix: Fix) -> owners_mod.Tree`: `head = self.git.head()`. The state
  is `UNRECORDED` when `not fix.gated`, `SAME` when `head == fix.gated`, `MOVED` when
  `self.git.is_ancestor(fix.gated)` (then `since = tuple(self.git.list_after(fix.gated))`),
  else `REWRITTEN`. `path = str(self.config.repo)`.
- `def _mark_gated(self, outcome: Outcome) -> str`: *"s187 G1: the tree's head, marked on the
  outcome's new fixes."* It reads `self.git.head()`, calls `owners_mod.mark_gated(outcome.fixes,
  head)` and returns `head`. `_advance_and_log` calls it right after `self.pipeline.route(…)`
  and adds `"head": head` to `result` (G2).
- `_fix_effects`: `outcome = fix_outcome(story, handoff) or find_unchanged_fix(story, plan.commit)`.
  The rest stays as it is: `None` pops the head, anything else goes to `_advance_and_log`.
- Module function `def find_unchanged_fix(story: StoryState, commit: str | None) -> Outcome | None`:
  *"s187 G5: the route that keeps an empty done's fix queued, or None when it committed."*
  It returns `None` when `commit` is set. It is reached only for `done`, because
  `fix_outcome` covers every other status. It builds the head fix with
  `replace(head, unchanged=head.unchanged + 1)`, so the story's list isn't changed in place.
- Constant `FIX_UNCHANGED` (G6), next to `FIX_DISAGREES`.
- `_record_fix`: `FixRecord(…, gated=fix.gated, head=self.git.head())`, and the `gate-fix`
  event gets `gated=record.gated, head=record.head`.

### `agile_team/loops.py`

- `HISTORY_KINDS` adds `"gate-fix"`.
- `def list_fix_rounds(records: list[FixRecord]) -> list[dict[str, Any]]`: *"s187 G9: the
