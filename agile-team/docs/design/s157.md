# s157: The house rules gate every story, not just CI

Developer: **developer-cli** (one regex in `owners.py`).
DevOps: **ops-review** writes the config below (`.agile-team.toml` is DevOps's).
ADR: [ADR-0081](../../../.team/adr/0081-house-rules-in-the-team-toolchain.md).
Requirements: REQ-111 (AC1), REQ-112 (AC2, AC3), REQ-113 (AC4), REQ-114 (AC5).

## What changes

Almost everything is configuration. The runner already has the machinery:

| AC | Runner machinery (unchanged) | What feeds it |
|---|---|---|
| AC1 | `stop_checks._lint`: runs every `[toolchain.files] fix` run (exit ignored), then every `lint_files` run. A non-zero `lint_files` refuses the stop with the output tail | house-rules added to `fix` and `lint_files` |
| AC2 | `gates.ROUTED_COMMANDS = ("lint", "static")`: a failing one is parsed by `owners.FINDINGS[Source.LINT]`, and each path goes to its owner as a gate fix. The quality step runs the same commands (`results.py` `"quality"`) | house-rules added to `static` |
| AC3 | `fullcheck` runs `lint` and `static` (exit judged) at the sprint start and end; an end failure becomes DevOps's team-fix step | the same `static` |
| AC4 | the guard's scope audit, the runner's step commit | `fix` restores and shrinks the baseline; `[roles.*] write` |
| AC5 | nothing house-rules-specific in the runner | all of it is in `.agile-team.toml` and `.house-rules.toml` |

One runner change: house-rules prints its warnings in the same
`path:line: …` shape as failures. Today a failing `static` would route every
warning in the repo to that file's owner as a gate fix. Warning lines must not
become items (AC1, AC2: warnings never refuse).

## Rules

- **R1 (the checker).** `uv run --frozen --quiet --project <house-rules/runner> house-rules …`.
  `--frozen` uses the committed `house-rules/runner/uv.lock` as it is.
- **R2 (stop, AC1).** `lint_files` runs `house-rules check {files}` after ruff,
  chained with `&&`, with uv's `--directory {root}` so the root-relative
  `{files}` resolve. house-rules exits 0 on clean, warnings, baselined
  findings and stale entries, and 1 on a new failure. Its failure lines read
  `<repo-relative path>:<line>: fail <rule>: <message>`, so the refusal names
  the file, the line and the rule.
- **R3 (reaching the project from a root).** The templates run under `sh -c`
  with the repo root as the working directory (`commands.Commands.run` →
  `system.ShellCommand(command, repo)`). The shell expands `"$PWD"` before uv
  changes directory, so `--project "$PWD/house-rules/runner"` works from any
  `{root}`, including `.`. No `{repo}` placeholder and no runner code.
  A `{repo}` placeholder was rejected: ops-review runs before the code, so a
  template using it would break every stop until implement landed (ADR-0081).
- **R4 (gates, quality, boundaries; AC2, AC3).** `static` ends with
  `&& uv run --frozen --quiet --project house-rules/runner house-rules check`
  (whole repo, from the root). Routing, the quality step and both boundary
  checks pick it up unchanged.
- **R5 (warnings are advice, AC1/AC2).** A lint line whose message, after
  `path:line[:col]: `, starts with `warn` or `warning` (any case, whole word) is
  not a finding. Applies to every toolchain, not only house-rules.
- **R6 (the baseline only shrinks, AC4).** `fix` ends with
  `git restore --source=HEAD --staged --worktree -- .house-rules-baseline.json && <house-rules> baseline`
  (no `--accept-new`). The restore throws away any edit the step made to
  the baseline. `baseline` then recomputes it from the whole repo and refuses
  to write it if anything would grow (exit 1, ignored by the fix). So a step
  that changes Python leaves the baseline as HEAD's, shrunk by what it fixed,
  in its own commit. HEAD is the commit before the step (the runner commits
  after it).
- **R7 (who may write it, AC4).** Every role that changes Python gets
  `.house-rules-baseline.json` in `write`; DevOps also gets `.house-rules.toml`.
  `[roles.<name>] write` replaces the role's list and applies to that exact
  name only (`roles.Book.resolve`), so each list restates the built-in one and
  each developer specialisation has its own section.
- **R8 (the whole-repo scan, R4/R6).** `house-rules check` with no paths and
  `house-rules baseline` walk every file under the repo root and skip only
  `.git`, `.venv`, caches and the configured `exclude`. The team checkout holds
  untracked copies of the runner under `.team/run/` (review, presentation and
  pin copies), and Claude Code worktrees live under `.claude/worktrees/`.
  Unexcluded, they would fail `static` and make `baseline` always refuse
  growth. `.house-rules.toml` excludes them.
- **R9 (known limit).** A step that edits only `.house-rules-baseline.json`
  and no Python skips the stop's lint check, so R6 does not run for it. A
  hand-added entry there is caught by the code review, not by code. Closing it
  needs house-rules to compare the baseline with a git ref, which is a
  house-rules story (open question to the human).
- **R10 (when it takes effect).** The runner reads `.agile-team.toml` once at
  start. The new commands and scopes apply from the runner's next start (the
  sprint-46 end re-pins and restarts it), not to the steps after ops-review.

## Changes

### `.agile-team.toml` (DevOps, at ops-review)

Replace `static`, add `[toolchain.files]` (it overrides the preset's keys of
the same name; `lintable` still comes from the preset), and add the role
sections. Exact text:

```toml
static = "uv run --directory agile-team/runner ruff format --check . && uv run --directory unattended/runner ruff format --check . && uv run --frozen --quiet --project house-rules/runner house-rules check"

# The stop hook's lint check (s126). Runs under sh from the repo root, so "$PWD"
# is the repo root before uv's --directory (s157, ADR-0081).
[toolchain.files]
fix = "uv run --directory {root} ruff check --fix --exit-zero --quiet {files} && uv run --directory {root} ruff format --quiet {files}; git restore --source=HEAD --staged --worktree -- .house-rules-baseline.json && uv run --frozen --quiet --project house-rules/runner house-rules baseline"
lint_files = 'uv run --directory {root} ruff check --quiet {files} && uv run --frozen --quiet --directory {root} --project "$PWD/house-rules/runner" house-rules check {files}'

# s157: every role that changes Python may write the house-rules baseline.
# A [roles.<name>] write replaces the built-in list, so each restates it.
[roles.developer]
write = ["{source}", "!{tests}", "!{e2e}", ".house-rules-baseline.json"]

[roles.developer-cli]
write = ["{source}", "!{tests}", "!{e2e}", ".house-rules-baseline.json"]

[roles.developer-api]
write = ["{source}", "!{tests}", "!{e2e}", ".house-rules-baseline.json"]

[roles.developer-db]
write = ["{source}", "!{tests}", "!{e2e}", ".house-rules-baseline.json"]

[roles.developer-gui]
write = ["{source}", "!{tests}", "!{e2e}", ".house-rules-baseline.json"]

[roles.unit-tester]
write = ["{tests}", ".house-rules-baseline.json"]

[roles.integration-tester]
write = ["{e2e}", ".team/run/presentation/**", ".house-rules-baseline.json"]

[roles.devops]
write = ["{ci}", "{config}", ".team/baseline.json", ".house-rules-baseline.json", ".house-rules.toml"]
```

Keep `[roles.architect]` as it is. The `lint` command and the CI workflow
`.github/workflows/house-rules.yml` do not change.

DevOps's `tooling` rows: AC1–AC4 `added` (this config), AC5 `automatic`
(the config is reviewable as it stands).

### `.house-rules.toml` (prerequisite, see open question)

No role's scope holds this file today (R7 adds it to DevOps, from the next
start, R10). The human or the liaison adds, before the restart:

```toml
# The team checkout holds untracked runner copies; scan only the real tree (s157).
exclude = [
    "**/.venv/**", "**/build/**", "**/dist/**", "**/node_modules/**",
    ".team/run/**", ".claude/worktrees/**",
]
```

`exclude` replaces house-rules' defaults, so the first line restates them.

### `agile_team/owners.py` (developer-cli)

`FINDINGS[Source.LINT]`, first pattern only. Today:

```python
re.compile(r"^(?P<path>[^\s:]+\.\w+):\d+(?::\d+)?: .*$", re.M),
```

New: the same, with a negative lookahead right after `: `:

```python
# ruff concise, flake8, mypy, eslint unix: path:line[:col]: message.
# A message starting "warn"/"warning" is advice, never an item (s157 R5).
re.compile(r"^(?P<path>[^\s:]+\.\w+):\d+(?::\d+)?: (?!(?i:warn(?:ing)?)\b).*$", re.M),
```

No other module changes. `findings`, `placed`, `split` and the gate are
untouched. No new constant built by a call (no code in the global scope).

## Test checklist

Unit (`tests/test_s92_owners.py` style, a new `tests/test_s157_house_rules_routing.py`):

- [ ] `owners.findings("a/b.py:12: fail function-length: 14 statements\n", Source.LINT)`
      → one finding, path `a/b.py`.
- [ ] `a/b.py:12: warn function-length: …` → `[]`; `a/b.py:3:1: warning: …` → `[]`;
      `a/b.py:3: WARNING x` → `[]`.
- [ ] Ruff codes still count: `a/b.py:3:1: W291 trailing whitespace` → one finding.
- [ ] A word that only starts with "warn" still counts: `a/b.py:3: warnings_off is unused` → one finding.
- [ ] Mixed house-rules output (two fail lines in `x.py`, warn lines in `y.py`,
      a `stale baseline entry:` line, the summary line) → findings only for
      `x.py`; through `owners.placed` one item for `x.py` with the two fail lines.
- [ ] The existing ruff full (`-->`) and `Would reformat:` patterns are unchanged.

e2e (integration-tester; scratch git repo, a fake checker script, no real house-rules):

- [ ] Stop (AC1): `lint_files = '"$PWD/check.sh" {root} {files}'`, where the
      fake `check.sh` at the scratch repo root changes into its first argument
      (as uv's `--directory` does) and prints `<repo-relative path>:<line>: fail <rule>: …`
      with exit 1. A stop with a changed file under a nested targeted root
      (`pkg/runner`) is refused, and the refusal names the path, line and rule.
      The same script printing only `warn` lines with exit 0 lets the stop through.
- [ ] Gate (AC2): a failing `static` whose output has a `fail` line in a file
      another role owns queues one gate fix to that role, and a `warn` line in a
      third role's file queues nothing for it.
- [ ] Baseline (AC4): with a `fix` of the R6 shape and a fake `baseline` that
      drops a fixed entry, a step's commit holds the shrunk baseline; a hand
      edit adding an entry in the same step is gone from the commit.

Acceptance (`cli`, `review`): AC1–AC4 against a scratch repo configured as
above; AC5 by reading `.agile-team.toml` and checking a repo without the
house-rules lines (the preset) runs only ruff.
