# s30: The dispute gate compares content, not commits

Developer: **developer-cli** (runner Python: new `fingerprint.py`,
`gates.py`, `state.py`, `cli.py`, `po_tools.py`, `events.py`, the
dashboard's `index.html` (one `TIMELINE` row), and the built-in role files
`developer.md`, `unit-tester.md` and `product-owner.md`). In this design step
the Architect has already updated `reference/protocol.md`, `SKILL.md`,
`docs/customer/routing.md` and the index in `architecture.md`.

Story: `.team/stories/s30.md`. Builds on s11 (`design/s11.md`) and replaces
its rules T3 (the `base` part) and T6 (the diff check). s27's repeat screen
is unchanged and does the escalation in AC3.

## What went wrong

s11 stored `base = git rev-parse HEAD` when a dispute was raised. At the
gate it ran `git diff --quiet {base} HEAD -- {file}`, where `file` is the
test id up to `::`. The runner commits the step before it gates
(`Runtime.settle`: `settle_tree`, then `_apply`), so the timing was not the
fault. Two things were:

1. **The path.** pytest runs from `agile-team/runner` and prints
   `tests/test_po_tools.py::…`. The diff runs from the repo root, where that
   path does not exist. Git reports "no change" for a missing path and exits
   0, so the gate bounced every time (s24, and very likely s23).
2. **The baseline.** A commit is the wrong baseline. Asking "did HEAD change
   since then?" tells you nothing about what the tester has to fix. A fix
   that is already in the base (s23's 3522ae6) can never "change" again.

The fix: resolve the path when the dispute is raised (and refuse it if it
cannot be resolved), and store a hash of the file's normalised content.
Then compare that hash with the working tree's file at the gate. If the
gate still gets it wrong, the PO gets a code-checked way out
(`pass_tests`).

## Rules

| # | Rule | AC |
|---|---|---|
| F1 | **Resolve at raise.** When `Pipeline.evaluate` raises a dispute (s11 T3), the runner resolves the test file (`test_file(test)`, the id up to the first `::`) to one tracked repo-relative path with `Checks.tracked(file)`. If the id's path is itself tracked, that path is used. Otherwise the runner uses the single tracked file whose path ends with `/{file}`. With no match, or more than one, it gives `None`. | AC1b |
| F2 | **Reject an unresolvable dispute.** If F1 gives `None`, or the resolved file cannot be read from the working tree, the dispute is not raised. The outcome is `Outcome(Verdict.BOUNCE, UNTRACKED, "implement", author=Author.ROLE)`. This is a bounce back to `implement` that counts a round, like a malformed dispute (s11 T2). `story.dispute` and `story.disputes` do not change, and the gate event is a plain `gate`. s27's screen applies as for any bounce. | AC1b |
| F3 | **Baseline.** A raised dispute stores `file` (the resolved path) and `baseline = Checks.content_hash(file)`, the fingerprint (F5) of the working-tree file at that moment. The developer's step is already committed, and its out-of-scope test edits are already quarantined, so this is the content the unit-tester sees. | AC2 |
| F4 | **The gate.** `Checks.dispute_settled(dispute)` at `tests` with a `done` handoff (s11 T6, otherwise unchanged): `confirmed` passes (`dispute confirmed`). An empty `baseline` (a dispute saved before s30) passes with `LEGACY_PASS`. A current `content_hash(dispute.file)` that differs from `baseline` passes (`disputed test changed`). That includes a file that is now gone (`None`). Otherwise the gate bounces to `tests` (round counted) with `_unchanged(dispute)`. No git command runs at the gate. | AC1, AC2 |
| F5 | **Fingerprint.** `fingerprint.of(path, text)` is the sha256 hex digest of `normalise(path, text)`. **Python** (`.py`, `.pyi`): the `tokenize` token stream without `COMMENT` and `NL` tokens, one token per line. `INDENT`, `DEDENT` and `NEWLINE` are written as their token names, every other token as its string. So indentation width, blank lines, spacing inside a line and comments do not count. A changed assertion, a parameter row, a string (docstrings included) or a test name does count. If `tokenize` raises `tokenize.TokenError` or `SyntaxError`, the Python file falls back to the line rule with `#`. **Other files**: the line rule. Collapse each line's whitespace runs to one space and strip the line. Drop empty lines, and drop lines that start with the suffix's marker from `LINE_COMMENTS` (no marker for an unknown suffix). Block comments (`/* */`) and trailing comments in non-Python files do count as changes. | AC2 |
| F6 | **Failure reason.** `_unchanged(dispute)` names the test id, the file and the baseline's first 12 hex digits, exactly as in "Strings". Repeats of one dispute produce the same text. The text starts with s11's words `the disputed test file {file} has not changed`, so the s11 e2e assertion (`tests/e2e/test_dispute_e2e.py`, which only the integration-tester may edit) stays green through `implement`. The integration-tester pins the full text at `e2e` (see "Who changes which tests"). | AC3 |
| F7 | **Repeat escalates.** No new code. A second identical bounce at `tests` matches s27's repeat screen (`repeat = 2`), so the story escalates to the Manager (`needs_manager`, no round) after one counted round. With the defaults (`round_cap = 3`) the round cap is never reached by this bounce alone. The tests pin this. | AC3 |
| F8 | **`pass_tests(story, reason)` PO tool.** It moves a stuck story from `tests` to the next enabled step (normally `implement`). Refusals, first match wins: unknown story (the existing `_story_for` text); empty `reason` → `a reason is required`; `Pipeline.pass_tests_refusal(story)` (F9). On success it calls `Pipeline.pass_tests(story)` (F10) and sets `hold = None` and `note = reason`, so the reason reaches the next brief as a `continue_story` note does. It appends `"{id}: PO passed tests by hand: {reason}"` to `state.manager_due`, saves, and emits `tests-passed` (F11). Result: `{"status": "passed", "story": id, "now_at": step}`. | AC4 |
| F9 | **When `pass_tests` may move a story.** `Pipeline.pass_tests_refusal(story) -> str \| None`, checked in this order: `story.step != "tests"` → `PASS_TESTS_STEP`; the story is not stuck → `PASS_TESTS_NOT_STUCK`; the suite is red → `PASS_TESTS_RED`. A story is stuck when any of these holds: a dispute is open, `status` is `needs_manager` or `blocked`, or `repeated` is set. The suite check runs `commands["test"]` through `Checks.green()`, and it runs last, only for a stuck story. A done story is never at `tests` (except as the last step, where `stuck` is false), so it is refused. | AC4 |
| F10 | **The move.** `Pipeline.pass_tests(story)`: `status = ACTIVE`, then `_clear(story)` (rounds, disputes, dispute, streak, run, repeated, escalated_by), then `_forward(story)`. This covers both s23 (blocked after a runner fault) and s24 (an open dispute on an unresolvable path, or capped). | AC4 |
| F11 | **Event.** `EventKind.TESTS_PASSED = "tests-passed"`, emitted with role `po` (the `PO` constant in `po_tools`) and the story id. Data: `{"from": "tests", "now_at": step, "reason": reason, "test": <the open dispute's test id or None>}`. The dashboard gains a `TIMELINE` row (see Changes). The snapshot fixture does not change. | AC4 |
| F12 | **Legacy state.** A saved dispute with s11's `base` key loads. The loader drops `base`, so `file = ""` and `baseline = ""`, and F4 passes it with `LEGACY_PASS`. Stories without a dispute load as before. | AC2 |

## Strings

```python
# gates.py
LS_FILES_COMMAND = "git ls-files -- {path} {suffix}"   # path, suffix shell-quoted; suffix = "*/" + file
UNTRACKED = (
    "dispute rejected: {file} (from {test}) is not a tracked file at the repo root, "
    "and no single tracked file ends with that path; hand off the dispute again "
    "with the test's path from the repo root"
)
UNCHANGED = (
    "the disputed test file {file} has not changed since the dispute was raised: "
    "{test} still matches its baseline {short} (whitespace and comment edits do "
    "not count); fix the test, or confirm it with changes_requested and "
    "next_role architect"
)
LEGACY_PASS = "dispute raised before content baselines; passed without a check"
PASS_TESTS_STEP = "story {id} is at step {step!r}; pass_tests only moves a story from tests"
PASS_TESTS_NOT_STUCK = (
    "story {id} is not stuck at tests (no open dispute, round cap, block or "
    "repeated setback); let the tests gate decide"
)
PASS_TESTS_RED = "the suite is red; pass_tests needs a green suite. {reason}"
```

`short` is `dispute.baseline[:12]`. `PASS_TESTS_RED`'s `{reason}` is
`Checks.green()`'s bounce reason (`tests fail:\n<tail>`).

**Rescope note.** The first version of this design started `UNCHANGED`
with `the disputed test {test} is unchanged: …`, and `gates.py` and
`tests/test_disputes.py` already use that text. The text above replaces
it. Only the string changes; the `format` keys (`test`, `file`, `short`)
stay the same.

## Changes by module

Every function stays at 8 lines or fewer, with at most 2 parameters and no
boolean flags.

### `agile_team/fingerprint.py` (new, stdlib only: `hashlib`, `io`, `tokenize`, `pathlib.PurePosixPath`)

Module docstring: content fingerprints that ignore whitespace and comments (s30).

- `LINE_COMMENTS: dict[str, str]`: `"#"` for `.sh .bash .rb .pl .r .yaml
  .yml .toml`; `"//"` for `.js .jsx .mjs .cjs .ts .tsx .go .rs .java .kt
  .kts .scala .swift .c .h .cc .cpp .hpp .cs .dart .php`; `"--"` for `.sql
  .lua .hs`.
- `PYTHON = frozenset({".py", ".pyi"})`.
- `def of(path: str, text: str) -> str`: sha256 hex of `normalise(path, text)` (UTF-8).
- `def normalise(path: str, text: str) -> str`: `suffix =
  PurePosixPath(path).suffix.lower()`. Python suffix → `_python(text)`,
  else `_lines(text, LINE_COMMENTS.get(suffix, ""))`.
- `def _python(text: str) -> str`: `_tokens(text)`, falling back to
  `_lines(text, "#")` on `(tokenize.TokenError, SyntaxError)`.
- `def _tokens(text: str) -> str`: `"\n".join(...)` over
  `tokenize.generate_tokens(io.StringIO(text).readline)`, skipping
  `DROPPED = {tokenize.COMMENT, tokenize.NL}`, each token rendered by
  `_shown(token)`.
- `def _shown(token: tokenize.TokenInfo) -> str`:
  `tokenize.tok_name[token.type]` when `token.type in STRUCTURAL`
  (`INDENT`, `DEDENT`, `NEWLINE`), else `token.string`.
- `def _lines(text: str, marker: str) -> str`: per line `" ".join(line.split())`.
  Keep non-empty lines that do not start with `marker` (when `marker` is
  non-empty). Join with `"\n"`.

## Who changes which tests

The `test` command runs the whole suite, `tests/e2e` included. The
`implement` gate needs it green, and the developer may not edit tests or
e2e tests. So no step may leave an e2e test that only a later step can fix.

| Step | Role | Changes | Suite after the step |
|---|---|---|---|
| `tests` | unit-tester | `tests/**` except `tests/e2e/**`: the `UNCHANGED` constant in `tests/test_disputes.py` becomes the new text, plus the checklist below. `tests/conftest.py` already passes `read=` to `Checks`. | red: the unit tests expect the new text, and `gates.py` still has the first-version text, which the e2e assertion does not match either |
| `implement` | developer-cli | `gates.UNCHANGED` becomes the new text, plus anything else in "Changes by module" that is still missing. | green, the e2e test included: its `the disputed test file tests/test_x.py has not changed` is a prefix of the new text, because `tests/test_x.py` is tracked at the fixture repo's root and resolves to itself |
| `e2e` | integration-tester | `tests/e2e/test_dispute_e2e.py`: pins the full text and adds the e2e cases in "E2E checklist". | green |

Nothing in `tests/e2e/` changes before the `e2e` step. If the unit-tester
finds another e2e test that the new code breaks, it hands off `blocked` and
names it. It does not edit the test.

## Test checklist (for the Unit Tester)

Contract changes (these do not weaken tests). In `tests/test_disputes.py`,
`DIFF`, `test_head_is_the_stripped_commit`,
`test_dispute_settled_when_the_file_changed`,
`test_dispute_unsettled_unless_diff_exits_one`,
`test_the_diff_path_is_shell_quoted` and the `"abc123"` positional `base`
pin s11's diff contract, which s30 replaces. Rewrite them against F1–F5 and
do not drop them. `OpenDispute(…, "abc123")` becomes `OpenDispute(test,
rule, reason, file, baseline)`. Wherever a dispute is raised through a
runtime, F2 needs the file to resolve and read. `conftest.make_runtime`
builds `Checks` with a `FakeRunner` and no `read`, so every raise there
would be rejected. Give the fixture `read=partial(gates.read_repo_file,
configured)`, and in each test that raises, script the `git ls-files …`
command on the `FakeRunner` and write the test file into `configured`.
The unit tests' `UNCHANGED` constant is the new text from "Strings". Do not
edit `tests/e2e/`; the integration-tester covers it at `e2e` (see "E2E
checklist").

1. **Fingerprint** (`test_fingerprint.py`):
   - Python: comment-only, blank-line-only, re-indent-only and
     inner-spacing-only edits keep the hash.
   - Python: a changed assertion, a changed `parametrize` row, a renamed
     test and a changed string each change it.
   - Python that fails to tokenize (an unclosed bracket) falls back to the
     line rule: a `#` line edit keeps the hash.
   - `.ts` with `//` lines, `.sql` with `--` lines: comment-line edits keep
     the hash; a code edit changes it.
   - An unknown suffix: whitespace edits keep the hash; a `#` line edit
     changes it.
   - `of` is a 64-char hex digest and deterministic.
2. **Resolution** (`test_disputes.py`, stub `run`):
   - `pick_tracked`: an exact line wins over a suffix match; one suffix
     match is returned; zero or two give `None`; `"x/tests/a.py"` does not
     match `file = "s/a.py"` unless it ends with `"/s/a.py"`.
   - `Checks.tracked` runs exactly `git ls-files -- 'tests/my test.py'
     '*/tests/my test.py'` (quoted), and gives `None` on a non-zero exit.
3. **Raise (F2, F3)**:
   - A dispute whose file resolves stores `file` (the resolved path, e.g.
     `agile-team/runner/tests/test_x.py` for id `tests/test_x.py::t`) and
     `baseline == fingerprint.of(file, content)`.
   - An unresolvable file (no match, two matches, or tracked but unreadable)
     gives `BOUNCE` to `implement`, with the exact `UNTRACKED` text and
     `author ROLE`. `rounds` goes up by 1, `dispute` stays `None`,
     `disputes` is unchanged, and a `gate` event is logged (not
     `test-dispute`).
4. **Gate (F4, F6)**, stub `read`:
   - A real change passes (`disputed test changed`) and the story moves to
     `implement` with the dispute cleared.
   - A cosmetic change (comment and whitespace only) bounces with the exact
     `UNCHANGED` text: test id, file and `baseline[:12]`.
   - No change bounces with the same text.
   - A file now missing (`read` → `None`) passes.
   - `confirmed` passes without calling `read`.
   - An empty `baseline` passes with `LEGACY_PASS` without calling `read`.
   - No command runs at the gate (the stub `run` records no call).
   - **Baseline taken at the dispute**: raise with content A, change the
     file to B before the gate, and it passes. Raise with content B and
     leave it, and it bounces. So the baseline is the content at the raise,
     not HEAD or a later commit.
5. **Repeat (F7)**, through `make_runtime`: two `done` handoffs at `tests`
   with the file unchanged. The first bounces (`rounds == 1`). The second
   escalates (`verdict escalate`, `status needs_manager`, `rounds == 1`),
   and the story never reaches the round cap from this alone.
6. **`pass_tests` (F8–F11)** (`test_po_tools.py` or `test_disputes.py`):
   - Each refusal with its exact text, and the story unchanged: unknown
     story, empty reason, not at `tests`, at `tests` but not stuck, stuck
     but red (`commands["test"]` exits 1; the text includes `tests fail:`).
     The red check is not run for a story that is not stuck.
   - Success for each stuck kind: an open dispute, `needs_manager`,
     `blocked`, and `repeated` set. The story is at `implement`, `active`,
     with `rounds = disputes = 0`, `dispute = None`, `streak = run = []`,
     `repeated = escalated_by = None`, `hold = None` and `note = reason`.
     `manager_due` holds the exact line. One `tests-passed` event carries
     the data shape, with `test` set when a dispute was open and `None`
     otherwise. The result is `{"status": "passed", "story": id, "now_at":
     "implement"}`.
   - `SCHEMAS` has `pass_tests` and `tool_names()` includes it.
7. **State (F12)**: a saved dispute with `base` and no `file` or `baseline`
   loads as `file == "" and baseline == ""`. A new dispute round-trips with
   `file` and `baseline`.
8. **Wiring**: `cli.make_pipeline(config).checks.read("<a tracked file>")`
   returns its text, and a missing path gives `None`.
9. Coverage ≥ 95% (target 100%); `ruff check` and `ruff format --check`
   clean.

## E2E checklist (for the Integration Tester, at the `e2e` step)

In `tests/e2e/test_dispute_e2e.py` (real git through `GitRunner`, the
disputed file committed by `build_rt`):

1. `test_unchanged_test_file_bounces_with_the_reason`: assert the whole
   `UNCHANGED` text, with `file = "tests/test_x.py"`, `test = TEST_ID` and
   `short = fingerprint.of(TEST_FILE, "def test_a(): assert 1 == 2\n")[:12]`.
   Write it as a literal in the test, not as `gates.UNCHANGED.format(...)`.
   Its docstring drops "real git diff exit 0"; no git command runs at the
   gate now.
2. A cosmetic fix (the unit-tester's action adds a comment and blank lines
   only) bounces with the same text.
3. A file under a subdirectory, disputed by its runner-relative id (commit
   `runner/tests/test_y.py` and dispute `tests/test_y.py::test_b`), resolves
   through real `git ls-files`. The story reaches `tests` with
   `dispute.file == "runner/tests/test_y.py"`.
4. An id whose file is not tracked bounces to `implement` with the
   `UNTRACKED` text and a round, and logs no `test-dispute` event.
5. The existing tests keep passing unchanged: upheld, malformed, confirmed,
   free-dispute cap and the rulings.

## Out of scope

- Checking that the disputed test exists in the file or fails.
- Block comments and trailing comments in languages other than Python (they
  count as changes).
- A Manager ruling that moves a story from `tests` to `implement`. The PO
  tool covers AC4, and the Manager reviews each use through `manager_due`.
