# s47: An answer wakes a waiting run; the run says what it waits on

Story: `.team/stories/s47.md`. Developer: `developer-cli`.

## Finding (read first)

The sprint-16 logs show that the router **did** wake on the answer:

| When (local) | Event |
|---|---|
| 03:58 | PO posts question m42 (names s40) and ends its turn; router waits |
| 06:00:40 | `agile-team answer m42 …` writes the inbox entry (`at` 1791716440.86) |
| 06:00:44 | `handover` e1005, triggers `["human_message"]`, stories `["s40"]` |
| 06:00:50 | developer-cli starts on s40 (e1006) |
| 06:05:12 | liaison runs `stop --now` |

The wake took 4 s, which is under one poll (`router.POLL_S` = 5 s). The two idle
hours came before the answer: the liaison's watcher missed m42 (the answer
itself says so). The run was waiting, as designed, but nothing showed *what*
it was waiting on. `status_reason` was `null` and `status` was `running`.

So for AC1/AC2 the wake logic stays as it is. A new driver-level test pins it:
no PO session is running, the answer arrives, and the PO gets the hand-over.
The code change is AC3: while the run waits, and in any halt note, it names
each story and the question ids it waits on.

## Rules

- **W1 Wake (no code change).** While the router waits on open questions, each
  poll (`POLL_S`) reads the inbox first (`Router._news`). A new answer ends the
  wait with a `human_message` pass, and the PO's next turn gets it as a
  hand-over. This holds whether the wait started after a PO turn or on a
  `start --resume` router pass. The PO's own `wait_for_answers` is the
  other path (a PO session is running) and is unchanged.
- **W2 Wait lines.** `Relay.waits()` gives one line per story that an open
  question names: `"{story} waits on {ids}"`, for example `s40 waits on m42`
  or `s41 waits on m42, m43`. Stories come in the order they first appear in
  the outbox. Ids come in outbox order with no duplicates. Open questions that
  name no story come last, as one line: `the run waits on {ids}`. With no open
  question the list is empty.
- **W3 Waiting reason.** While the router waits (`_tick` reaches `_wait`), the
  run's `status_reason` is `waiting on answers: ` followed by the W2 lines
  joined with `"; "`, for example
  `waiting on answers: s40 waits on m42; the run waits on m43`. `status` does
  not change; only the reason is set. State is saved only when the reason
  changes, not on every poll.
- **W4 Wait reason cleared.** When the wait ends with news (`_deliver`) or a
  step (`_step`), a `status_reason` that starts with `waiting on answers: ` is
  cleared (status unchanged) and saved. Any other reason is left alone. A halt
  replaces the reason with its own (`halt_run`). A graceful stop ends the run
  as `idle`, which clears it (`PoRun.run`, unchanged).
- **W5 Halt note.** When the run halts while a question is open, the outbox
  note is `halt_note(...)` followed by `; waiting on answers: <W2 lines joined
  by "; ">`. Example:
  `stopped by stop --now; run \`agile-team start --resume\` to continue; waiting on answers: s40 waits on m42`.
  With no open question the note is unchanged. The stored `status_reason` on a
  halt and the stderr line do not change; unattended reads them for reset times.
- **W6 Stall message.** A `stalled` pass cannot coincide with an open question,
  because the router waits instead (`_idle`). So the stall lines do not change.
  For a run that waits on the human, W3 is its stall message.

## Changes per module

### `agile_team/relay.py`

New constants next to `KINDS`:

```python
WAIT_LINE = "{story} waits on {ids}"
RUN_WAIT_LINE = "the run waits on {ids}"
WAITING_HEAD = "waiting on answers: "
```

New `Relay` methods (documented, each under 8 lines; use helpers if needed):

```python
def waits(self) -> list[str]:
    """One line per story an open question names, then one for questions naming none (W2)."""

def waiting(self) -> str:
    """WAITING_HEAD + the waits joined by "; ", or "" when no question is open (W3, W5)."""
```

Build the story-to-ids map with a `dict[str, list[str]]` in first-seen order.
Do not branch per story.

### `agile_team/router.py`

- `Router._wait` shows the wait, then sleeps:

  ```python
  async def _wait(self) -> None:
      self._show_wait()
      await self.sleep(POLL_S)
  ```

- New `Router._show_wait(self) -> None`: sets `reason = self.runtime.relay.waiting()`.
  If `state.status_reason != reason`, it calls `state.mark(state.status, reason)`
  and `self.runtime.save()` (W3).
- New `Router._clear_wait(self) -> bool`: if `state.status_reason` starts with
  `relay.WAITING_HEAD`, it calls `state.mark(state.status)`. It returns whether
  it cleared a reason. It is the first call in `_deliver`, and the save that
  `_deliver` already makes persists the change, so there is no second save.
- New `Router._end_wait(self) -> None`: calls `_clear_wait()` and, if that
  cleared a reason, calls `self.runtime.save()` (W4). It is the first call in
  `_step`.
  (Design review: the split follows the code, which avoids a double save in
  `_deliver`.)
- Import: `from .relay import WAITING_HEAD, Answer`.

### `agile_team/dispatch.py`

- `Runtime.halt_run`: the posted note becomes
  `halt_note(self.halted_by, saved) + _waits_suffix(self.relay)`.
- New module function:

  ```python
  def _waits_suffix(relay: Relay) -> str:
      """"; " + the run's waiting reason when a question is open, else "" (W5)."""
  ```

  `halt_note`'s signature and its existing callers stay as they are.

### Unchanged

`po_tools.wait_for_answers`, `Router._news`/`_idle`/`_stall_lines`,
`halt.Halt.message`, `cli.status_report` (it already shows `status_reason` and
`open_questions`), the snapshot contract, and unattended.
