# s113 design: the PO box on the Flow chart shows its time

Story: `.team/stories/s113.md`. ADR: [ADR-0063](../../../.team/adr/0063-po-turns-name-the-stories-they-touched.md).
Requirements: REQ-012 (AC1, AC4), REQ-013 (AC2, AC4), REQ-014 (AC3, AC4).
Developer: `developer-gui` (the page is most of the work; the runner change is
one small class and a wrapper in `po_tools.py`).

## Where things stand

s118 rewrote the Flow chart in HTML. Its PO box already shows the PO's awake
time in Sprint and Run scope: `roleNumbers` gives `po.model + po.tools` from
`turnSplit(view)` (FC8). Three things are missing:

1. The PO's waiting on roles (`poSplit(...).waiting`, TM3) is not shown.
2. `po-turn` events name no story, so in Story scope the PO's time reads `—`.
3. Nothing says when a turn was spent on several stories.

## Rules

| # | Rule | AC |
|---|---|---|
| PT1 | **A turn names its stories.** Every `po-turn` event's `data` gets `"stories": [ids]`: the story ids the turn's PO tool calls named, deduplicated, in the order first named. A turn that named none has `[]`. The event's own `story` field stays `null` (a turn may touch several; `test_s98_live` pins it). | AC2 |
| PT2 | **What names a story.** A tool call names the values of its `story` argument (a string) and its `stories` argument (a list of strings), except `open_story`, which names its `id`. The table `STORY_ARGS` says which argument keys a tool's call names; every tool not in it uses `DEFAULT_STORY_ARGS = ("story", "stories")`. Tools whose schema has neither key name nothing. Non-string and empty values are skipped. | AC2 |
| PT3 | **Recorded at the call.** The story is noted when the tool is called, before the tool runs, so a refused or failing call still counts: the PO spent its turn on that story. Unknown ids are kept as given (the dashboard only ever looks up the focus story). Stories in the hand-over prompt that no tool names do not count. | AC2 |
| PT4 | **Also on a failing query.** The event is still emitted when the PO's query raises (as today, `test_a_po_query_that_raises_still_emits_a_po_turn`), with the stories noted up to then. | AC2 |
| PB1 | **A turn's stories on the page.** `turnStories(e)` is `e.data.stories` when it is an array, else `[]` (events from before s113). | AC3 |
| PB2 | **The PO turns in scope.** `scopeTurns(view)`: every `po-turn` event; in Sprint and Run scope those passing `inScope(view)` (unchanged: Run takes all, Sprint takes those inside the sprint's window, since the event has no story); in Story scope those whose `turnStories` include `focusStory(view)`. A turn that touched several stories counts in each one's Story scope. | AC1, AC3 |
| PB3 | **The PO's split.** `turnSplit(view)` sums `poSplit(e.data)` over `scopeTurns(view)` and returns `{ model, tools, waiting, turns, shared }`: the three summed seconds, the number of turns, and whether any of them has two or more stories. | AC1, AC3 |
| PB4 | **The PO's awake time.** `poSeconds(po)` is `po.model + po.tools` (model plus the PO's own tool time, waiting left out, as TM3), or `null` in Story scope when `po.turns` is 0. `roleNumbers` uses it for the PO's `seconds`; `null` renders `—` as before. Tokens and cost of the PO still read `—` in Story scope (its ledger rows have no story). | AC1, AC3 |
| PB5 | **The waiting line.** The PO's box gets one line right under its `.fc-meta` line: `<div class="f-time f-wait fc-t-meta">waiting on roles {fmt.dur1(po.waiting)}{shared}</div>`, where `{shared}` is ` · shared turns` in Story scope when `po.shared`, else empty. No line when `poSeconds(po)` is `null`. `fmt.dur1` is the role boxes' time format. The line carries `f-time`, so the "awake time" switch in the Flow settings hides it with the time (no new `FLOW_SHOW` key; `test_every_show_row_has_a_hide_rule` pins the keys). Only the PO's box has it. | AC1, AC3 |
| PB6 | **Bar and sparkline follow.** `shareHtml` already takes `turnSplit(view)` for the PO, so in Story scope the PO's model/tool bar now shows its touched turns. `rateSeries` for the PO takes the newest of `scopeTurns(view)` (instead of its own `findLast` over `inScope`), so the sparkline follows the same turns. | AC3 |

## Changes per module

### `agile-team/runner/agile_team/po_tools.py`

New, near `Tools`:

```python
STORY_ARGS: dict[str, tuple[str, ...]] = {"open_story": ("id",)}
DEFAULT_STORY_ARGS = ("story", "stories")


def named_stories(name: str, args: dict[str, Any]) -> list[str]:
    """The story ids a call of tool ``name`` with ``args`` names (s113 PT2)."""


@dataclass
class Touched:
    """The story ids one PO turn's tool calls named, first named first (s113 PT1)."""

    ids: list[str] = field(default_factory=list)

    def note(self, name: str, args: dict[str, Any]) -> None:
        """Add the stories this call names that are not noted yet."""
```

`named_stories` reads `args.get(key)` for each key of
`STORY_ARGS.get(name, DEFAULT_STORY_ARGS)`, treats a string as a one-item list,
ignores any other type, and keeps non-empty strings. Use a small private
helper (e.g. `_as_ids(value) -> list[str]`) to keep each function short.

`Tools` gets a field and a method:

```python
    touched: Touched = field(default_factory=Touched)

    def noted(self, name: str) -> Callable[[dict[str, Any]], Awaitable[dict[str, Any]]]:
        """Tool ``name``'s method, noting the stories each call names first (PT3)."""
```

`noted` looks the method up as `getattr(self, METHODS.get(name, name))` and
returns an `async def call(args)` that runs `self.touched.note(name, args)` and
then `return await method(args)`.

`mcp_server(tools)`: build each def from `tools.noted(name)` instead of
`getattr(tools, METHODS.get(name, name))`. Nothing else changes there.

`po_plan` splits so the turn's `Tools` stays reachable (signatures keep two
parameters):

```python
def plan_for(tools: Tools, turn: PoTurn) -> Plan:
    """The PO's step on ``tools``: its MCP tools, its scope, and resume when asked."""


def po_plan(runtime: Runtime, turn: PoTurn) -> Plan:
    """The PO's step with fresh tools (kept for callers that need no stories)."""
    return plan_for(Tools(runtime), turn)
```

`plan_for` is today's `po_plan` body with `runtime = tools.runtime` and
`mcp_server(tools)`.

`PoRun`:

```python
    async def _turn(self, turn: PoTurn) -> StepResult:
        # unchanged guard, then:
        tools = Tools(self.runtime)
        plan = plan_for(tools, turn)
        raw = await self._query(plan, tools.touched)
        # unchanged: priced, _settle, _record, return

    async def _query(self, plan: Plan, touched: Touched) -> StepResult:
        """Run the PO's query; emit its ``po-turn`` event whatever happens (PT4)."""
        try:
            return await self._collect(plan)
        finally:
            self._turn_event(plan.meter, touched)

    def _turn_event(self, meter: live.Meter, touched: Touched) -> None:
        """One ``po-turn`` event per PO query: its time split and the stories it named."""
        data = {**meter.time_split(), **self.runtime.pulse.clocks(), "stories": list(touched.ids)}
        ...  # emit as today, story None
```

`_collect(plan)` keeps its signature and its own `try/finally` for the pulse
and the session, but no longer calls `_turn_event` (the event moves to
`_query`, after the pulse closes, so the order of close then emit is kept).
`test_s44_round1` calls `_collect(plan)` directly and checks the heartbeat
only; it is unaffected.

## Design review (round 1)

The code matches PT1–PT4 and PB1–PB6. Two points the design left open are
settled as built:

- `Tools.__post_init__` is an empty hook that the runner tests' recording
  subclass uses to capture each turn's `Tools`. That is the "recording
  subclass" route of the checklist. It is accepted: it has no behaviour and
  it is documented. A later tidy may drop it, together with the
  `lambda: Touched()` factory (review F2).
- `turnSplit(view)` runs once each for `roleNumbers`, `poWaitHtml` and
  `shareHtml`. That is accepted at today's event counts (review F3).

The page checklist above is still open. The e2e step writes
`tests/e2e/test_s113_po_box_e2e.py` to pin AC1 and AC3 (review F1).
