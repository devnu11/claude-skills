## Rules

| # | Rule | AC |
|---|---|---|
| F1 | **Unit toggle.** The "Tokens by" card (`#mix`, the bars grouped by role, story or model) gets a second segmented control `#unit` with two buttons, `data-unit="tokens"` ("Tokens") and `data-unit="usd"` ("Dollars"), each with `aria-pressed`. The choice is `ui.unit`, default `"tokens"`. Clicking sets `ui.unit` and calls `render()`. | AC1 |
| F2 | **Only that chart.** `ui.unit` is read only by `renderUnit`, `renderBars` and the click handler. The header, the tiles (`renderTiles`), the cumulative spend chart (`renderSpend`) and the tables (`renderTables`) never read it and do not change with it. | AC1 |
| F3 | **Survives live updates.** `ui.unit` changes only on a click. Nothing in `boot`, `connectLive`, `onmessage`, `normalize` or `render` resets it, so every pushed snapshot re-renders in the chosen unit. A page reload goes back to `"tokens"` (not required to persist further). | AC1 |
| F4 | **What each unit draws.** Tokens: the bars as today (stacked by `TOKEN_KINDS`, token legend, end label `fmt.tok(total)`). Dollars: one solid bar per group of `t.cost` in `var(--s1)`, a one-item legend "Cost (USD)", end label `fmt.usd(total)`, tooltip `<b>{group}</b><br>{fmt.usd(cost)} <span class="k">({pct} of spend)</span> · {steps} steps`. Rows sort by the unit's total, largest first. The card title reads "Tokens by" or "Spend by". When every total is 0 (for example only local models in dollars), bars have zero width and nothing divides by zero. | AC1 |
| F5 | **Live config.** Each `snapshot.build` re-reads `.agile-team.toml` from the config's repo. So `run.budget_usd`, `run.manager_every_pct`, `run.round_cap`, `run.cadence` and `pipeline` show the file's current values. If the file is missing or does not parse (`ConfigError`, for example mid-write), the snapshot uses the config the dashboard started with. The role book is still built once, at start (role files and `[roles.*]` edits still need a restart). | AC2 |
| F6 | **Config is watched.** `watched_files(config)` includes `<repo>/.agile-team.toml`, so writing it changes the SSE fingerprint and pushes a fresh snapshot (D12 unchanged). | AC2 |
| F7 | **Board fits the width.** The board never scrolls sideways. It is a flex row: each column has `flex: 1 1 0; min-width: 0`, so the columns share the board's width and none can push the board wider. There is no fixed minimum column width, and the board has no `overflow-x`. At a 1280 px window, even with all 10 columns (Backlog, 8 steps, Done) holding cards, each column is about 116 px wide and Done is in view. | AC3 |
| F8 | **Empty columns collapse.** A column with no cards gets the class `empty` and is a fixed 44 px strip with its heading written vertically (label and `0`). Columns with cards share the rest. 10 empty strips plus gaps need 512 px, well under the board's width. | AC3 |
| F9 | **Cards wrap.** Text in a card wraps rather than overflowing: `.story { overflow-wrap: anywhere; }`, and pills inside a card may wrap (`.story .pill { white-space: normal; }`). `.col { overflow: hidden; }` is the backstop, so nothing inside a column can widen the page. | AC3 |

## Known limits

- The role book (role files, `[roles.*]`) is still built once, at start.
- `watched_files` uses the startup `docs_dir`. Changing `docs_dir` needs a
  restart.
- A wrongly typed value in `.agile-team.toml` (for example `team = 5`)
  makes `build` raise, like the s4 known gap for REQ files. Only a missing
  or unparsable file falls back.
- A file that parses but is incomplete (for example saved half-way, or
  empty) loads with default values until the next save. Only a missing
  or invalid TOML file falls back to the startup config.
- At 1280 px with all 10 columns full, cards are narrow (about 116 px) and
  titles wrap over several lines. In practice most step columns are empty
  and collapse, so the full ones are much wider.
