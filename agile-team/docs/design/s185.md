# s185: done story s159 still behaves as REQ-160 says after s179

Follow-up check. s179 changed REQ-160's resume sentence (commit 2b6f3d79)
and added REQ-193–195. This story checks that s159's AC10 behaviour still
holds under the new wording. **No runner code changes are expected.** The

## Rules

What the code does today. The tests pin it.

- **R1. Resume keep/remove (AC1, REQ-239).** `Runtime.recover_stories`
  → `_prune_worktrees` → `workspaces.find_prune_reason(story, sprint)`, in
  this order: no story → `unknown`; a step in flight → kept; `done` →
  `done`; `cancelled` → `cancelled`; `story.sprint != state.sprint` →
  `not_in_sprint`; otherwise kept. Each removal emits one
  `EventKind.WORKTREE_PRUNED` event (`role` `None`, `story` = id,
  `data = {"worktree": id, "reason": <reason>}`) and clears that story's
  `worktree_head`. A kept worktree emits nothing.
- **R2. Older state (AC2, REQ-240).** `state.load` fills the missing
  story-branch fields with their defaults (`story_branches` False; `branch`,
  `base_sha`, `worktree_head`, `pushed` `""`; `pr`, `landed` `None`;
  `replays` 0). `Workspaces.stored_worktrees` lists directories only, and
  returns `[]` when `.team/run/worktrees/` does not exist. So a story with
  no worktree recorded has nothing to remove, and `recover_stories` raises
  nothing and sets no halt.
- **R3. Switch refusals (AC3, REQ-241).** `Tools.start_sprint` runs
  `_drop_merged_entries()` and then `_switch_refusal(ids)`. With
  `state.story_branches` False, `switchover.list_refusals(read_facts(rt,
  ids))` lists every obstacle at once, joined into `SWITCH_REFUSED`:
  `PAST_DESIGN` (stories in `ids` with `pipeline.is_past_design`),
  `PENDING` (`read_pending`), `STACK` (entries left after the drop), and
  `AHEAD` (`count_ahead` = `Upstream.count_unpicked("HEAD")`, i.e.
  `git cherry` `+` lines). A team-branch commit whose patch main already
  has is not counted. A refusal leaves `story_branches` False.
- **R4. Product Backlog past design (AC3, REQ-241).** `read_facts` checks
  only the started sprint's `ids`, so a Product Backlog story past design is
  no obstacle. Its `step` is untouched. Once `story_branches` is True, its
  next step's `prepare_story` → `Workspaces.ensure` creates
  `<story_prefix><id>` from the sprint head and its worktree, and logs
  `story-branch` `created`.

In a scratch repo (`HOME=$(mktemp -d)`), with story branches on and sprint
N running: one story open in the sprint with no step running, one with a
step running, one done, one cancelled, one moved to the Product Backlog,
and a stray `.team/run/worktrees/sX/` with no story. Put a file in each
open story's worktree under a git-ignored path. Stop the run (`stop
--now`), then `start --resume`. Check:

- the open and running stories' worktrees and their ignored files are still
  there;
- the other four are gone;
- `.team/run/events.jsonl` has exactly four `worktree-pruned` lines, with
  reasons `done`, `cancelled`, `not_in_sprint` and `unknown`.
