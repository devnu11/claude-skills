# s154 Bug: one unit test that reaches the OS in fixture setup breaks its whole worker

ADRs: ADR-0036 (amended by s154: `RealOsCall` is a pytest outcome; temp-dir
fixtures are refused in unit tests), ADR-0080 (gate results keep each failing
test's first error lines). Requirements: REQ-108 (AC1, AC4), REQ-109 (AC2, AC4),
REQ-110 (AC3, AC4). Developer: `developer-cli`.

## Cause (why the fix is what it is)

pytest treats only `TEST_OUTCOME = (OutcomeException, Exception)` as a test
outcome. `FixtureDef.execute` registers a finalizer, then runs the fixture; on a
`TEST_OUTCOME` it caches the error, on any other `BaseException` it leaves
`_finalizers` set and `cached_result` empty. The next test that sets up that
fixture hits `assert not self._finalizers` (`_pytest/fixtures.py`), and so does
every test after it in that worker. `RealOsCall` is a bare `BaseException`, so a
guard hit inside pytest's own `tmp_path` fixture leaves pytest's state broken.

## Rules

- **G1 (AC1).** `RealOsCall` subclasses `pytest.fail.Exception` (pytest's
  `Failed`, an `OutcomeException`). It stays a `BaseException` that is not an
  `Exception`, so `except Exception` in code under test still can't swallow it,
  and pytest now handles it like `pytest.fail` everywhere, its own fixtures
  included. A unit test whose fixture setup reaches the OS errors at setup with
  the guard's message (`unit test reached the real OS: … inject it, or move the
  test to tests/e2e/`); the tests after it in the worker run as usual. Nothing
  else in the guard changes (tables, exempt callers, recorded violations).
- **G2 (AC2).** The temp-dir fixtures are `OS_FIXTURES = ("tmp_path",
  "tmp_path_factory", "tmpdir", "tmpdir_factory")` (`tmpdir_factory` is the
  same class as the three the story names). At collection
  (`pytest_collection_modifyitems`), each unit-world item whose static fixture
  closure (`item.fixturenames`) holds one of them is marked refused, with the
  refusal text in `item.stash[os_guard.REFUSAL]`. The conftest's
  `pytest_runtest_setup` wrapper calls `os_guard.refuse_marked(item)` before it
  yields, so a refused test fails at setup **before any fixture runs** (the same
  point at which pytest's own skip marks act), and every other test runs.
  A real collection error is not used: pytest stops the whole session on one,
  which is the halt this story removes. `tests/e2e/` items are never refused.
  A fixture that asks for a temp dir dynamically (`request.getfixturevalue`) is
  not in the closure; G1 covers it. The conftest's own dynamic
  `getfixturevalue("tmp_path")` calls run only in the REAL world, so they stay.
- **G3 (AC2).** Refusal text, one constant:
  `OS_FIXTURE_REFUSED = "unit test requests {names}, which reach the real OS; use the fake world (the scratch or repo fixture, FAKE_ROOT), or move the test to tests/e2e/"`
  with `names` the sorted fixture names joined by `", "`. It is raised with
  `pytest.fail(text, pytrace=False)`.
- **G4 (AC3).** A JUnit `<failure>` or `<error>` gives its test's **first error
  lines**: the lines of the element's text that start with pytest's error
  marker `E ` (marker and following spaces removed); when it has none, the
  first non-empty lines of its text; when the text is empty, its `message`
  attribute. At most `ERROR_LINES = 5` lines, joined by `"\n"`.
- **G5 (AC3).** Every `Ran` kept from a test-command run (`test`, `coverage`,
  `suite-runs`) records `failures`: failing or erroring test id → its first
  error lines, every failing case of the run's report, in report order.
  A run with no report (reporting off, or no file written) has `{}`. Old result
  files without the key load with `{}`.
- **G6 (AC3).** The brief's `## Runner results` block of a run with failures
  adds, after the fenced tail, a list of the first `FAILURES_SHOWN = 10`
  failing tests with their error lines, and one line counting the rest.
- **G7 (AC3).** A gate event whose verdict is not `pass` carries
  `failures` (the first `FAILURES_SHOWN` entries, merged over the outcome's
  `ran` and `extra_ran`, later runs winning on the same id) and, when more
  exist, `failures_more: <count>`. A passing gate event carries neither (the
  tests gate passes on red tests by design). The dashboard's story timeline
  shows them in the gate entry's body under the reason.
- **G8.** The boundary's full checks (`fullcheck.py`) do not write
  `.team/run/results/`; they are out of scope.

### `agile-team/runner/tests/test_s151_conflict.py`

`scratch(monkeypatch, env)` returning

runs, the developer fixes the code under `design/s151.md`; a test that
contradicts that design is disputed, not changed to pass.
