## The problem

Under s40 P2, an explicit position beats in-progress. `start_sprint` lists
its stories in order, so a story not yet started (s45) that was listed first
ran before s38 (at tests) and s21 (at implement). The human: committed code
is a house of cards for everything built after it, so started stories come
first.

## Vocabulary

- **started**: the story has commits in the tree. The runner records a
  story's first commit in `StoryState.commit` (`dispatch.commit_step`), and
  every later commit of the story is a fixup of it. So started means
  `story.commit is not None`. The design commit counts. A step that ran but
  committed nothing does not. The ranking reads the record only and runs no
  git (it runs on every route and every snapshot).
- **held**: `story.hold is not None`, or `story.status` is `BLOCKED` or
  `NEEDS_MANAGER`. An open relay question alone does not make a story held
  for the ranking, because the ranking reads only `StoryState`. The router
  still skips such a story (s40 P4).
- **pulled**: the PO pulled a not-started story ahead of the started ones,
  with a reason. The ids are in `state.pulled`.
- **group** (`Tier`): `in progress`, `held` or `not started` (G2).
- `order`, **queue** and **position** keep their s40 meanings.

## Rules

| # | Rule | AC |
|---|---|---|
| G1 | **Started** = `story.commit is not None` (see Vocabulary). | AC1, human rule |
| G2 | **Group.** `Priority.tier(story)` is `NOT_STARTED` when the story is neither started nor pulled. Otherwise it is `HELD` when held, else `IN_PROGRESS`. A pulled story is ranked as if started. | AC1, AC4 |
| G3 | **The one ranking rule** (replaces s40 P2) is `Priority.key(story)` = `(done, RANK[tier], listed, natural(id))`. `RANK` is `in progress` 0, `held` 1, `not started` 2. `done`, `listed` and `natural` keep their s40 meanings. So the groups come first, and the PO's order ranks stories within each group. | AC1, AC2 |
| G4 | **A held story keeps its place in `order`** (amends s40 P4). Holds never change `order` or `pulled`. While it is held, a started story ranks after those in progress, so its `#position` changes. Once released, it goes back to its place among them. The router still skips held, blocked and asked stories (`_movable`), so a held story never stops another from routing. | AC4, AC5 |
| G5 | **`RunState.pulled: list[str]`** (default `[]`) is saved in `state.json`. A file without it loads with `[]`. The ranking ignores ids that are unknown, done or started. | AC3 |
| G6 | **What counts as a pull.** `pulls(listed, stories)` returns the not-started ids in `listed` that come before the last started id in `listed`. "Started" here means G1 only: a pulled story does not count. | AC3 |
| G7 | **`prioritise(stories, reason)`** (amends s40 P5). It judges the listed ids only when the list names at least one started story. If it does, each listed not-started id is pulled when it is in `pulls(ids)` and unpulled otherwise. If the list names no started story, it says nothing about the groups, so every pull stays as it was. The new `order` is `with_first(ids)` (G15). | AC3 |
| G8 | **`move_story(story, position, reason)`** (amends s40 P6). It judges the moved story only. The story is pulled when it is in `pulls(board_move(...))`, that is, when it lands before a started story on the board. Otherwise it is unpulled. The new `order` is `with_move(...)` (G16). | AC3 |
| G9 | **A pull needs a reason.** When G7 or G8 pulls one or more stories (`Pull.ahead` is not empty) and `reason.strip()` is empty, the tool is refused with `PULL_NEEDS_REASON` and nothing changes. Earlier refusals (s40 P5 and P6) are checked first. | AC3 |
| G10 | **`start_sprint` never pulls from its list.** Its list orders stories within each group (s40 P8). The one exception keeps s81: when `upstream.ci_bug` names an unfinished story (the list must already start with it), that story is pulled. The sprint event's reason is then `goal + "; " + CI_BUG_PULL.format(story=bug)`. | AC1, AC3 |
| G11 | **Apply a change** (amends s40 P7 and P9). `_reorder` takes `before` = the queue, sets `state.order = change.order` (the new plan from G15 or G16, which keeps the PO's intent for held stories) and `state.pulled = priority.repulled(change.pull, stories)`, then saves. It then takes `after` = the queue from the updated state. The `priority` event's `order` is `after`, and its `moves` is `moves(before, after)`. Its data gains `"pulled": list(change.pull.ahead)`. The tool result is `{"status": "ordered", "order": after}`. | AC3, AC5 |
| G12 | **A move the groups override is kept and noted.** When `move_story`'s story lands at a position other than the one asked for (for example, a started story moved behind not-started ones, or a held story moved to #1), the change is kept, and the result adds `"note": RANKED_ELSEWHERE.format(...)`. The order remembers the place, so it applies once the story's group changes. | AC5 |
| G13 | **`repulled(pull, stories)`** = the current `pulled` minus `pull.judged`, plus `pull.ahead`, de-duplicated (first wins), keeping only ids of unfinished stories that are not started. So a pulled story leaves the list once it has a commit or is done, at the next change. | AC3 |
| G14 | **`story_status`** adds `"pulled": state.pulled`. Its `stories` and `order` follow G3. | AC2 |
| G15 | **A change builds on the plan, never on the queue** (round 1, fixes review D1). The **plan** is `Priority.plan(stories)`: the ids of the unfinished stories ranked by `(listed, natural(id))` alone, with no groups. `with_first(ids)` = the ids that are in the plan, in the order given, then the rest of the plan in plan order. The groups are applied only when ranking (G3), so they are never written into `order`. So a reorder while a story is held, by any tool, leaves the held story's place in `order` as it was, and it ranks back at that place once released (G4). | AC3, AC4 |
| G16 | **`with_move` maps a board position onto the plan.** `position` is the #position on the board (the G3 queue). `board_move(placement)` = the queue without the story, with the story inserted at `position` (s40 P6's queue move). The story's **group** is its tier once the move is applied, that is, `Priority(order, repulled(move_pull(...))).tier(story)`. The new order is the plan without the story, with the story inserted: (1) directly **after** the nearest story **before** it on the board that is in its group; else (2) directly **before** the nearest story **after** it on the board that is in its group; else (3, the story is alone in its group) directly **before** the story after it on the board, or at the **end** when it is last. Rules (1) and (2) land the story at `position` whenever its group's block on the board covers that position. Every other story keeps its place in the plan. | AC3, AC4, AC5 |
| G17 | **One refusal check per tool** (review D3). `priority.first_refusal(checks)` returns the first non-`None` result of the zero-argument checks, called in turn, or `None`. A later check is not called once an earlier one refuses (G9: `set_pull` needs known ids). `prioritise` and `move_story` each call it once and return `refused(...)` once. | — |
| D1' | **Snapshot** (amends s40 D1). Each story replaces `in_progress` with `tier`: the `Tier` value (`"in progress"`, `"held"` or `"not started"`), or `null` when done. `position` is the position in the G3 queue. | AC5 |
| D4' | **Timeline** (amends s40 D4). The `priority` row's label and body are unchanged. Its meta is the moves (as before). When `data.pulled` is not empty, the meta adds ` · pulled ahead: <ids joined ", ">`. An event without `pulled` (from before s51) shows as before. | AC3 |
| D5' | **Fixture.** Each story has `tier` instead of `in_progress`. The fixture holds at least one story of each group, with stories listed in G3 order. The held story (`hold: "questions"`) is started, so its tier is `held`. The `priority` event has `"pulled": ["<id>"]` naming the one story that is pulled, which is in `run`'s state as pulled with tier `in progress` and no commit. | AC5 |

### Worked example (the origin case)

`order = ["s45", "s38", "s21", "s50"]`, `pulled = []`. s45 is at design
with no commit. s38 is at tests and s21 at implement, both with a commit.
s50 is at design with no commit.

- Ranking: s38 (in progress, listed 1), s21 (in progress, 2), s45 (not
  started, 0), s50 (not started, 3). The queue is `s38, s21, s45, s50`, and
  the router runs s38.
- s38 gets a `quarantine` hold. The queue becomes `s21, s38, s45, s50`. The
  router runs s21, and s38 shows `#2 ⏸ held`.
- While s38 is held, `prioritise(["s50"], "")`: the list names no started
  story, so no pull is judged and no reason is needed. The plan is
  `[s45, s38, s21, s50]` (no groups), so `order = [s50, s45, s38, s21]`
  (G15). s38 is still before s21 in `order`. The queue is
  `s21, s38, s50, s45`.
- s38 is released. The queue is `s38, s21, s50, s45`: s38 is `#1` again.
- `move_story("s45", 1, "")` is refused: `board_move` gives
  `[s45, s38, s21, s50]`, where s45 is before a started story, and the
  reason is blank: `pulling s45 ahead of started stories needs a reason;
  give one, or place them after the started stories`.
- `move_story("s45", 1, "the human needs the hotfix today")`:
  `pulled = ["s45"]`, so s45's group is `in progress`. It has no story of
  its group before it on the board, and s38 is the next one after it, so it
  goes directly before s38 in the plan (G16 rule 2). `order` stays
  `[s50, s45, s38, s21]`. The queue is `s45, s38, s21, s50`. The event has
  `pulled: ["s45"]`, `moves: s45 4→1, s38 1→2, s21 2→3, s50 3→4`.
- `prioritise(["s50", "s45"], "")`: no started story is listed, so no
  reason is needed and s45 stays pulled. `order = [s50, s45, s38, s21]`.
  The queue is still `s45, s38, s21, s50`.
- `prioritise(["s21", "s45"], "")`: s45 is listed after the started s21, so
  it is unpulled, with no reason needed. `order = [s21, s45, s50, s38]`.
  The queue is `s21, s38, s45, s50`.
- `move_story("s21", 4, "")`: `board_move` gives `[s38, s45, s50, s21]`.
  s21 is started, so nothing is pulled and no reason is needed. Its group is
  `in progress`, and s38 is the nearest story of that group before it on the
  board, so it goes directly after s38 in the plan (rule 1):
  `order = [s45, s50, s38, s21]`. It ranks `#2` (the queue is
  `s38, s21, s45, s50`), and the result has the note `s21 ranks #2, not #4: …`.
- s38 is held again (queue `s21, s38, s45, s50`), and
  `move_story("s38", 1, "")`: s38 is alone in the `held` group, so it goes
  directly before s21, the story after it on the board (rule 3). `order`
  stays `[s45, s50, s38, s21]`, s38 ranks `#2` with the note
  `s38 ranks #2, not #1: …`, and once released it is `#1`.

## Changes by module

### `agile_team/priority.py` (pure, no I/O)

Module docstring: `"""Story priority (s40, s51): the PO's order within the groups started, held and not started."""`

```python
NO_STORIES, UNKNOWN, DONE, BAD_POSITION    # unchanged
PULL_NEEDS_REASON = (
    "pulling {ids} ahead of started stories needs a reason; "
    "give one, or place them after the started stories"
)
RANKED_ELSEWHERE = (
    "{story} ranks #{landed}, not #{position}: stories in progress come first, "
    "then held started ones, then the rest; its place in the order is kept"
)
HELD_STATUSES = frozenset({StoryStatus.BLOCKED, StoryStatus.NEEDS_MANAGER})

class Tier(StrEnum):          # IN_PROGRESS = "in progress", HELD = "held", NOT_STARTED = "not started"
RANK = {tier: n for n, tier in enumerate(Tier)}

@dataclass(frozen=True)
class Pull:
    """The stories a change judges, and those it pulls ahead of started ones."""
    judged: tuple[str, ...] = ()
    ahead: tuple[str, ...] = ()

@dataclass(frozen=True)
class Reorder:                # change; order; story = None; reason = ""; pull: Pull = Pull()

def started(story: StoryState) -> bool:
    """Has commits in the tree: the runner recorded its first commit (G1)."""

def held(story: StoryState) -> bool:
    """A hold, a block or a needs-manager status (s51 vocabulary)."""

def pulls(listed: list[str], stories: dict[str, StoryState]) -> list[str]:
    """Not-started ids in ``listed`` that come before its last started id (G6)."""

def set_pull(ids: list[str], stories: dict[str, StoryState]) -> Pull:
    """G7: judge ``ids`` only when they name a started story."""
    # Pull(tuple(ids), tuple(pulls(ids, stories))) if any started, else Pull()

def pull_refusal(pull: Pull, reason: str) -> str | None:
    """G9: PULL_NEEDS_REASON (ids joined ", ") when ``pull.ahead`` and a blank reason."""

def first_refusal(checks: Iterable[Callable[[], str | None]]) -> str | None:
    """G17: the first refusal of the checks, called in turn; later ones are not called."""

@dataclass(frozen=True)
class Priority:
    order: list[str]
    pulled: list[str]          # replaces ``first``; in_progress() is removed

    def tier(self, story: StoryState) -> Tier: ...                  # G2
    def key(self, story: StoryState) -> tuple[Any, ...]: ...        # G3, exactly
    def ranked(...), queue(...), move_refusal(...)                  # unchanged
    def plan(self, stories: Iterable[StoryState]) -> list[str]: ...
        # G15: unfinished ids by (listed, natural(id)); share the "listed" index with key()
    def with_first(self, ids: list[str], stories: Iterable[StoryState]) -> list[str]: ...
        # G15: built from plan(), not queue(); docstring "The plan with ``ids`` first, in the order given."
    def board_move(self, placement: Placement, stories: dict[str, StoryState]) -> list[str]: ...
        # G16: the queue with the story at its #position (the old with_move body)
    def with_move(self, placement: Placement, stories: dict[str, StoryState]) -> list[str]: ...
        # G16 rules 1-3; signature now takes the dict (it needs tiers by id)
    def move_pull(self, placement: Placement, stories: dict[str, StoryState]) -> Pull: ...
        # G8: Pull((story,), (story,) if story in pulls(board_move(...), stories) else ())
    def repulled(self, pull: Pull, stories: dict[str, StoryState]) -> list[str]: ...  # G13
```

`with_move` stays short with private helpers, for example one that returns
the moved story's group and one that finds the plan index for rules 1–3
(the house rule: under 8 lines, at most 2 parameters). Rules 1 and 2 scan
`board_move`'s list outwards from the story for the nearest id of the same
tier; rule 3 uses the plain neighbour.

`natural`, `order_refusal`, `moves`, `Change` and `Placement` are
unchanged.

## Out of scope / known limits

- A branch per story, merged on acceptance, is s39.
- An open relay question alone does not move a story to the held group
  (the ranking reads `StoryState` only). The router still skips it.
- The ranking trusts the recorded `commit` and does not check that it is
  still an ancestor of HEAD. s59's remap keeps the record current across
  syncs.
- `agile-team status` keeps creation order (as in s40).
- Moving a **held** story itself (G16) places it among the held stories
  now. Where it ranks once released follows its new place in the plan, next
  to the held neighbour that rule 1 or 2 picked, so it can differ from the
  position asked. When it is the only held story, rule 3 places it before
  its board neighbour, so a move to `#1` gives `#1` once released. Reorders
  of *other* stories never move a held story's place (G15, G16).
