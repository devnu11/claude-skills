# s70: The suite runs in parallel with pytest-xdist

Story: `.team/stories/s70.md`. ADR: `docs/adr/ADR-010-parallel-suite-xdist.md`.
Developer: `developer-cli` (code). DevOps: config, lock, CI (see "Who does what").

## Why it blocks today

xdist starts N workers. Each worker collects the suite, and xdist refuses to run
when the workers' test IDs differ ("Different tests were collected between gw0
and gw1"). `test_process_groups.py::test_stop_stale_never_signals_the_runner`
is parametrized with `os.getpid()` and `os.getpgrp()`, which are evaluated at
collection time, so every worker has its own IDs. The fix: the runner's ids
are **injected** into `sandbox.stop_stale`, and the test passes fixed fakes.

## Rules

| # | Rule | AC |
|---|---|---|
| X1 | **Runner ids are a value.** `process_groups.RunnerIds(pid, pgrp)` holds the runner's own pid and process group. `RunnerIds.current()` reads them at call time (never at import). `RunnerIds.names(pid)` is true when `pid` is either one. | 1 |
| X2 | **`stop_stale` takes them.** `sandbox.stop_stale(root, runner_ids=None)`; `None` means `RunnerIds.current()`. A recorded pid the ids name is never ended, **even when `Recorded.is_ours()` says yes**, and the pid file is still deleted. The ids check runs before `is_ours()` (it is free; `is_ours` runs `ps`). Everything else in `stop_stale` is unchanged; `may_signal_child_group`'s own `os.getpgrp()` check stays as a second wall. | 1 |
| X3 | **The test uses fakes.** The runner test passes `RunnerIds(pid=4242, pgrp=4243)` and labels its cases `pid` / `pgrp`, so its IDs are the same in every worker. It patches `Recorded.is_ours` to `True`, so only X2's check can stop the signal. A control case (pid `4244`, not named) proves the same setup does signal. | 1, 4 |
| X4 | **No test ID holds a live value.** No parametrize value or id may come from a pid, process group, clock, random number, temp path or environment. Use a label or a template, and resolve the live value inside the test body (as `test_kill_check.py::test_runner_targets_are_denied` does with `{pid}`). Guideline in `docs/guidelines.md`. | 4 |
| X5 | **A test checks X4.** `tests/test_s70_ids.py` collects the whole `tests/` dir in two separate Python processes at once and asserts both print the same, non-empty list of node IDs. Two processes have two pids and two clocks, so a live value shows up as a difference, whatever the core count. | 4 |
| X6 | **pytest-xdist is a dev dependency** of `agile-team/runner` (`[dependency-groups] dev`), with `uv.lock` updated. Not a runtime dependency. ADR-010 records it. | 2 |
| X7 | **The runner's commands use xdist.** In `.agile-team.toml`, the agile-team half of `coverage` and `test` adds `-n auto`, and a `[[toolchain.targeted]]` row for `agile-team/runner` runs `-n auto`. CI (`.github/workflows/agile-team.yml`) runs `pytest -n auto --cov`. `addopts` does **not** get `-n`: a named test run from role Bash stays serial (faster for one test), and X5's subprocesses stay plain. | 3 |
| X8 | **Coverage across workers is pytest-cov's job.** pytest-cov combines the workers' data when xdist is active and prints one `TOTAL` line from the controller. `[tool.coverage.*]` is unchanged (no `parallel = true`; pytest-cov sets it). `fail_under = 95` still applies to the combined total. No `.coverage.*` files are left behind. | 3 |
| X9 | **The gate's parsers need no change.** `parse_coverage` reads the `TOTAL` line, which xdist does not alter. `TEST_FAILURES` matches pytest's `N failed` / `N error(s)` summary, which the controller still prints. `hung_test` reads the stack pytest-timeout prints in the failure report, which xdist relays. A gate timeout kills the command's process group, and the xdist workers are in it. | 3 |
| X10 | **unattended stays serial.** `unattended/runner` gets no xdist and keeps its commands. Its own targeted row has no `-n`. | — |

## Who does what

The developer's scope is `{source}` minus tests; `pyproject.toml`, `uv.lock`,
`.agile-team.toml` and the workflows are DevOps's (`{ci}`, `{config}`).

| Step | Role | Files |
|---|---|---|
| tests | unit-tester | `tests/test_process_groups.py` (rewrite #9, add the checks below), new `tests/test_s70_ids.py` |
| implement | developer-cli | `agile_team/process_groups.py`, `agile_team/sandbox.py` |
| config | devops (PO runs it) | `agile-team/runner/pyproject.toml`, `agile-team/runner/uv.lock`, `.agile-team.toml`, `.github/workflows/agile-team.yml` |

**Order matters.** DevOps runs **after the tests step lands**. Before that, the
old test is still collected with live IDs, and an `-n auto` coverage command
would fail every gate. The implement gate passes with or without DevOps's
change, because the serial command still works.

## Changes per module

### `agile_team/process_groups.py`

Add after `in_runner_group`:

```python
@dataclass(frozen=True)
class RunnerIds:
    """The runner's own pid and process group: never a signal target (s70)."""

    pid: int
    pgrp: int

    @classmethod
    def current(cls) -> RunnerIds:
        """The live process's ids, read now."""

    def names(self, pid: int) -> bool:
        """True when ``pid`` is the runner's pid or its process group."""
```

`current()` returns `cls(os.getpid(), os.getpgrp())`. `names` returns
`pid in (self.pid, self.pgrp)`. No other change in this module.

### `agile_team/sandbox.py`

Import: `from .process_groups import Recorded, RunnerIds, signal_child_group`
(extend the existing import line).

```python
def stop_stale(root: Path, runner_ids: RunnerIds | None = None) -> None:
    """End a service an earlier step left (by its pid file) and delete the file.

    A pid the runner's ids name is never ended (s70); ``None`` reads them now.
    """

def _may_end(recorded: Recorded, runner_ids: RunnerIds) -> bool:
    """True when the recorded group is not the runner's and is still ours."""
```

`stop_stale` body: read the pid file as today; when `recorded` and
`_may_end(recorded, runner_ids or RunnerIds.current())`, call `_end_group`;
then `pid_file.unlink(missing_ok=True)`. `_may_end` returns
`not runner_ids.names(recorded.pid) and recorded.is_ours()` (that order).
`Preparer.prepare` keeps calling `stop_stale(sandbox_root(...))` with no ids.
