# s62: Liaison commands in the runner (`tell`, `watch`), resume from a dirty tree, self-hosting pin, frozen and locked uv

Story: `.team/stories/s62.md`. Developer: `developer-cli`.

The liaison's two private scripts (`.team/run/liaison/team-resume.sh`,
`watch-team.sh`) become runner commands. `tell` queues a message for the PO in
a file; the router delivers it as a `human_message` hand-over, as it does an
answer (s47). `watch` is a token-free poll of the run files that exits with one
JSON line. The `stash_leftovers` step of the wrapper is not needed after a kill
(s9 already covers that). It is still needed after a checkout halt (s61 K5
skips the salvage), so R1–R4 close that gap. Self-hosting gets a committed pin
script and `reference/self-hosting.md`. Documented install commands use
`uv run --frozen`, and CI uses `--locked`.

## Findings (read first)

- **AC3: a kill is covered, a checkout halt is not.** After `kill -9`,
  `start --resume` runs `recovery.recover_killed`: shown status
  `interrupted`, then the s9 salvage, then preflight sees a clean tree. A
  halt for any other cause saves the tree in `halt_run`. The gap is the
  s61 halt. `save_interrupted` skips the salvage when the checkout moved (K5).
  After `accept-checkout` the status is `stopped`, or `checkout-changed` when
  the human put the checkout back, so `recover_killed` returns `None`.
  Preflight then refuses the step's (or the PO turn's) leftover edits. That
  is the case the wrapper's stash still covered. R1–R4 fix it.
- **Delivery point.** `Router._tick` reads the inbox before it picks work
  (s47 W1). A queued message joins that check. So it reaches the PO when
  the current role step ends, or within one 5 s poll while the run waits.
  It never needs a stop. While the PO is mid-turn, the message waits for the
  turn to end. `wait_for_answers` is unchanged.
- **Health trigger.** The live meter's health is s44, which has not shipped.
  `watch` triggers are a table (V4). s44 adds its `health` row. This story
  adds no health code.

## Rules

### Tell (AC1, AC6)

- **T1 Command.** `agile-team tell SOURCE`. `SOURCE` is a file path, or `-`
  for stdin. The text is read whole and stored as it is (no strip). A text
  that is only whitespace is refused: exit 1,
  `agile-team tell: the message is empty`. A file that cannot be read gets
  exit 1, `agile-team tell: cannot read <SOURCE>: <strerror>`. On success it
  prints `queued <id> for the PO: <repo-relative path>` and exits 0. The text
  is never placed on a command line by the runner.
- **T2 Store.** Messages live in `<run_dir>/liaison/messages/` (gitignored
  with `.team/run/`). Each is `t<N>.md`, id `t<N>`. `N` is one more than the
  largest number already there (1 when there is none). Files that do not
  match `^t(\d+)\.md$` are ignored, such as this repo's older
  `msg-<epoch>.md`. The text is written first to a draft
  `.draft-<pid>` in the same folder. Then it is hard-linked to
  `t<N>.md` (`Path.hardlink_to`), which fails if the name exists. On
  `FileExistsError` it tries `N+1`, so two concurrent `tell`s never overwrite
  each other. The draft is unlinked in a `finally`. A reader therefore never
  sees a half-written `t<N>.md`.
- **T3 Any run state.** `tell` reads and writes nothing but the messages
  folder and the config. It never touches `state.json`, so it never races
  the runner. It works while the run is running, waiting, halted
  (`checkout-changed` included, AC6), stopped, or never started.
- **T4 Delivered once.** `RunState.told: list[str]` (default `[]`) holds the
  ids already handed to the PO. Unread = `relay.told()` minus `state.told`, in
  number order.
- **T5 Delivery.** At each router tick, after the checkout check and with the
  inbox answers (s47 W1), unread messages end the pass. The pass is
  `Pass([Trigger.HUMAN_MESSAGE], lines, stories)`. `lines` holds the answer
  lines first (unchanged), then one line per message:
  `The human sent you a message ({id}): read {path}.`, with `path`
  repo-relative (e.g. `.team/run/liaison/messages/t3.md`). The text is
  **not** quoted in the prompt. A role's `pkill -f` must never match it, and
  the PO reads the file. Messages add no stories. `state.told` is extended
  and saved in the same `save` as `state.delivered`. A waiting reason is
  cleared first, as today (s47 W4).
- **T6 Resume.** A stopped or halted run delivers unread messages at the first
  router pass of `start --resume`. With no `--task` and no pending interrupted
  steps, that pass is before the PO's first turn. Otherwise it is right after
  that turn (`PoRun._opening`, unchanged). After a checkout halt, the human
  restores or accepts the checkout, then resumes, and the message is
  delivered (AC6).
- **T7 Status.** `status` JSON gains `queued_messages`: the unread ids
  (T4), e.g. `["t3"]`, or `[]`.

### Watch (AC2)

- **V1 Command.** `agile-team watch [--timeout S]`. It blocks, polls the run
  files every `watch.POLL_S` = 2.0 s, and exits 0 after printing exactly one
  JSON line (`json.dumps`, no indent, flushed). It never calls a model, so it
  spends no tokens. Without `--timeout` it waits until a trigger fires.
  Ctrl-C exits 130, as `main` already does.
- **V2 One look.** A poll reads `relay.messages()` (the outbox) and the shown
  status (`state.shown_status(run_dir, state.load(run_dir))`) plus
  `status_reason`. A `json.JSONDecodeError` (an outbox line caught
  mid-append) makes the poll count as "no look". Nothing fires, and the next
  poll retries.
- **V3 Memory.** `<run_dir>/liaison/watch.json` holds
  `{"messages": <outbox entries already reported>, "status": <str|null>, "status_reason": <str|null>}`.
  It is written atomically (tmp + replace) when the watch exits with a line.
  It holds the count of outbox entries at that look, and that look's status
  and reason. A missing or unreadable file means `{"messages": 0, "status": null, "status_reason": null}`,
  so the first watch in a repo reports every outbox entry and the current
  status. Run one watch at a time.
- **V4 Triggers** (a table, `watch.TRIGGERS`, in this order; each is
  `(name, test(seen, look) -> bool)`):

  | name | fires when |
  |---|---|
  | `message` | the outbox has entries after the remembered count. If the outbox has *fewer* entries than remembered (a new run dir), every entry counts as new. |
  | `status` | the look is not quiet and its `(status, status_reason)` differs from the baseline. **Quiet** = status `running` with `status_reason` `null`. |

  s44 adds `("health", …)` for the live meter's health turning red.
- **V5 Status baseline.** At the first look the baseline is the remembered
  status (V3). After every look that fires nothing, the baseline becomes
  that look's status. So `running` then `stopped` fires, `stopped` then
  `stopped` does not, and `waiting on answers: …` then `running` (quiet)
  does not. Covered: halted (`stopped`, `failed`, `checkout-changed`),
  waiting (`running` with a `waiting on answers: …` reason), budget and
  limit (`blocked` with their reasons), `interrupted`, `done`, `sprint-end`,
  `idle` (the runner ended). Every runner halt and every PO `notify_user`
  also posts an outbox entry, which `message` catches. So a status that
  comes back to the reported value between two watches is still seen.
- **V6 Line.** When any trigger fires, the line is:

  ```json
  {"triggers": ["message", "status"], "messages": [{"id": "m7", "kind": "blocked", "text": "…", "stories": [], "at": 1791800000.0}], "status": "blocked", "status_reason": "session limit, resets 9pm (Europe/Berlin)", "was": {"status": "running", "status_reason": null}}
  ```

  `triggers`: the names that fired, in table order. `messages`: the new
  outbox entries (all fields, as in `outbox.jsonl`), else `[]`. `status`,
  `status_reason`: this look. `was`: the status baseline (V5). Its `status`
  is `null` when nothing was remembered.
- **V7 Heartbeat.** With `--timeout S`, the watch ends at the first complete
  look at or after `S` seconds (monotonic clock) when nothing fired. It
  prints the same shape with `"triggers": ["heartbeat"]` and `"messages": []`,
  and saves memory as in V3.
- **V8 Testable pace.** Sleep and clock are injected (`watch.Pace`). Tests
  never sleep for real.

### Resume from a dirty tree (AC3)

- **R1 Unsaved cut.** New `RunState.unsaved: Cause | None = None`.
  `Runtime.save_interrupted(cause)` sets `self.state.unsaved = cause` when it
  skips the salvage because the checkout moved (K5), then returns `None` as
  today. The caller's existing save persists it (`halt_run` saves right
  after).
- **R2 Recover on resume.** `recovery.recover_killed` is renamed
  `recovery.recover_cut(run_dir, git)`. It picks the cause in this order: a
  shown status of `interrupted` gives `Cause.KILLED`, as today. Else a set
  `state.unsaved` gives that cause. Else it returns `None` and touches
  nothing. With a cause it runs `Salvager.save`, clears `unsaved`, records
  the checkout (`checkout.recorded(git)`) and saves state, as today. It still
  runs only for `--resume`, after `Guard.on_start()` passed (s61 K3), so the
  checkout matches.
- **R3 Message.** `cli._recover` prints, when the salvage made a commit,
  `agile-team start: {lead}; {label}'s edits are saved in {sha} (reverted)`.
  `lead` comes from `cli.RECOVERED_LEADS: dict[Cause, str]`, which has
  `{Cause.KILLED: "the last run was killed"}`. Any other cause uses
  `RECOVERED_LEAD = "the last run halted ({cause}) before its edits were saved"`.
  The killed text is unchanged.
- **R4 Stale flag.** `PoRun.run` sets `state.unsaved = None` when a run starts
  (beside `delivered`, before `_set_status(RUNNING)`). A plain `start` passed
  preflight on a clean tree, so the old edits were already dealt with. A
  later resume must never sweep up unrelated edits. A dirty tree with no
  interrupted run behind it is still refused.

### Self-hosting pin (AC4)

- **P1 Script.** `agile-team/runner/scripts/pin-runner.sh <commit>`
  (POSIX `sh`, `set -eu`, run as `sh agile-team/runner/scripts/pin-runner.sh <commit>`
  from anywhere in the repo). It `cd`s to `git rev-parse --show-toplevel`.
  It builds `.team/run/runner-pin/` (the `agile-team/runner` tree at the
  commit, without the `agile-team/runner/` prefix). It writes the full sha
  plus a newline to `.team/run/runner-pin.commit`. Then it prints
  `pinned <sha7> at .team/run/runner-pin; run it with: uv run --frozen --quiet --project .team/run/runner-pin agile-team …`.
- **P2 Refusals** (each prints `pin-runner: <reason>` to stderr, exit 1, and
  leaves any existing pin untouched; checked in this order):

  | check | reason |
  |---|---|
  | not exactly one argument | `usage: pin-runner.sh <commit>` (exit **2**) |
  | not in a git work tree | `not a git repository` |
  | `git rev-parse --verify --quiet "<commit>^{commit}"` fails | `unknown commit: <commit>` |
  | `git merge-base --is-ancestor <sha> HEAD` fails | `<commit> is not on the checked-out branch; pin only accepted code` |
  | `git cat-file -e <sha>:agile-team/runner/pyproject.toml` fails | `<commit> has no agile-team/runner` |
  | `.team/run/runner.pid` names a live process (`kill -0`) | `the team is running; stop it first` |

- **P3 Build.** `rm -rf .team/run/runner-pin.new`. Then
  `git archive <sha> agile-team/runner | tar -x -C .team/run/runner-pin.new --strip-components=2`.
  Then remove the old `.team/run/runner-pin`, move `.new` into its place,
  and write `.commit` last. The script does not build a venv:
  `uv run --frozen --project .team/run/runner-pin` builds it from the pinned
  `uv.lock` on first use. Moving a built venv would break its absolute
  shebangs.
- **P4 Doc.** `agile-team/reference/self-hosting.md` (written in this design
  step) covers why, how to pin and re-pin, and the unattended job's commands.
  `.claude/` stays the human's. The liaison points `.claude/CLAUDE.md` at
  the doc.

### Frozen installs, locked CI (AC7, AC8)

- **F1 Frozen docs.** In `agile-team/SKILL.md`, `agile-team/reference/*.md`,
  `agile-team/docs/customer/*.md`, `unattended/SKILL.md`,
  `unattended/reference/*.md` and `README.md`, every `uv run` command that

  `README.md` and `.github/workflows/unattended.yml`, so the F1/F2 test runs
  whenever a file it reads changes.

### `agile_team/watch.py` (new)

```python
"""``agile-team watch``: block until the run needs the liaison, then say why in one JSON line (s62)."""

WATCH_FILE = "watch.json"          # in run_dir / relay.LIAISON_DIR
POLL_S = 2.0
HEARTBEAT = "heartbeat"

@dataclass
class Seen:
    """Where the last watch left off: outbox entries reported and the run's status (V3)."""
    messages: int = 0
    status: str | None = None
    status_reason: str | None = None

    @classmethod
    def load(cls, path: Path) -> Seen: ...     # missing/unreadable -> Seen()
    def save(self, path: Path) -> None: ...    # atomic tmp + replace, mkdir parents

@dataclass(frozen=True)
class Look:
    """The run as one poll found it (V2)."""
    messages: list[Message]
    status: str
    status_reason: str | None

    def quiet(self) -> bool: ...               # running with no reason (V4)
    def new_since(self, seen: Seen) -> list[Message]: ...   # V4 message rule
    def seen(self) -> Seen: ...                # Seen(len(messages), status, status_reason)

def look(run_dir: Path) -> Look | None:
    """Read the outbox and the shown status; ``None`` when an outbox line is torn (V2)."""

TRIGGERS: tuple[tuple[str, Callable[[Seen, Look], bool]], ...]   # V4 table

def fired(seen: Seen, now: Look) -> list[str]:
    """The trigger names that fire for ``now`` against ``seen``, in table order."""

def line(triggers: list[str], basis: Basis) -> dict[str, Any]: ...
```

`Basis` is a frozen dataclass `(seen: Seen, now: Look)`, so `line` keeps
two parameters. It builds the V6/V7 dict.

```python
@dataclass(frozen=True)
class Pace:
    """How the watch waits; tests pass fakes (V8)."""
    sleep: Callable[[float], None] = time.sleep
    clock: Callable[[], float] = time.monotonic

DEFAULT_PACE = Pace()

@dataclass
class Watcher:
    """Polls one run directory until something needs the liaison."""
    run_dir: Path
    pace: Pace = DEFAULT_PACE

    def until(self, timeout_s: float | None) -> dict[str, Any]:
        """Poll until a trigger fires or ``timeout_s`` passes; save memory; return the line (V1–V7)."""
```

Loop: take a look. On `None`, sleep and retry. If anything fired, or the
deadline has passed, save `now.seen()` and return the line. Otherwise set the
status baseline to `now` (V5) and sleep `POLL_S`. Keep each method under 8
lines with helpers such as `_deadline` and `_next`.
