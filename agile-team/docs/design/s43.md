# s43: Gate commands have a time limit; a hung test is named, not waited on

Story: `.team/stories/s43.md`. Developer: `developer-cli`.

## Why the old code hangs

`dispatch.shell_runner` calls `subprocess.run(..., shell=True, timeout=1800)`.
At the limit, `subprocess.run` kills only the shell. Then it calls
`communicate()` again **with no timeout**. The shell's children (pytest, its
workers, a test's own subprocesses) still hold the output pipe, so that second
read never returns, and `TimeoutExpired` is never raised. So the runner hangs
even with a timeout set. The fix: run each command in its own process group,
kill the whole group at the limit, and give the read after the kill a deadline
too.

## Rules

| # | Rule | AC |
|---|---|---|
| T1 | **Configured limit.** `[gates] command_timeout_s` (seconds, float, default `300.0`) is the limit for each command the runner runs through `shell_runner`. `[gates]` is human-owned: a role's edit to it is quarantined (`dispatch.restrict_config`), so no role can lift the limit. It must be positive: `GATE_RULES` row `"gates.command_timeout_s must be positive"`. | AC1 |
| T2 | **Covered commands.** The limit applies to every call of a `CommandRunner` built by `shell_runner`: the tests gate (`tests_red`, `tests_reworked`), the implement gate (`green`, coverage), the dispute's test run (`test_output`), the git lookups in `Checks` (`tracked`, `landed`) and the boundary full checks (`fullcheck`, through `Runtime.shell`). Each command gets its own full limit. Not covered: `sandbox.run_shell` (a delivery's prepare), the presentation `Trial`, `upstream.command_runner` (it already has `GH_TIMEOUT`) and `git_ops`. | AC1 |
| T3 | **Own process group.** Each command starts with `start_new_session=True`, so its pgid is its pid. stdin is `/dev/null` (a test that reads stdin gets EOF instead of waiting), and stdout and stderr are merged into one pipe (`stderr=STDOUT`, `text=True`, `errors="replace"`). | AC1 |
| T4 | **Kill the group, only it.** At the limit the runner sends `SIGKILL` through s41's `process_groups.signal_child_group(proc.pid, signal.SIGKILL)`. That function always signals the pid as the pgid (`os.killpg(pid, …)`, suppressing `ProcessLookupError` and `PermissionError`) and refuses when the pid is ≤ 1, is the runner's own group, or leads no group of its own (`may_signal_child_group`; a leader that already exited still counts as its own group). Pitfall: never signal the result of `os.getpgid(...)`. The pid **is** the pgid because of T3, and a lookup after the leader died could find the runner's own group. `getpgid` may only be compared against the pid, as s41 does. A process that left the group itself (`setsid`) is not chased. | AC1 |
| T5 | **Read after the kill has a deadline.** After the kill, `communicate(timeout=DRAIN_S)` (`DRAIN_S = 5.0`) collects what the group wrote. Python keeps output already read across `communicate` calls, so nothing is lost. If that read times out too (a process that escaped the group still holds the pipe), the captured output is `""`. | AC1 |
| T6 | **Any other interruption kills the group too.** If waiting raises anything except `TimeoutExpired` (`KeyboardInterrupt`, `CancelledError`, an `OSError`), the runner kills the group (T4), then re-raises. | AC1 |
| T7 | **Timeout result.** A command killed at its limit returns `(TIMED_OUT, report)`. `TIMED_OUT = 124` (GNU `timeout`'s code, so a toolchain command that wraps itself in `timeout` reads the same). `report` is the captured output's lines, then `TIMEOUT_LINE`, then either `HUNG_LINE` or `NO_HUNG_LINE`. The reason goes **last** so `gates.tail` keeps it. | AC1, AC2 |
| T8 | **Naming the hung test.** `hung_test(output)` tries each `HUNG_PATTERNS` row in order. A row's **last** match (the latest stack dump) is formatted with its template. One row today matches a stack frame whose function starts with `test`, in both faulthandler's format (`File "p", line 12 in test_x`) and the traceback format pytest-timeout prints (`File "p", line 12, in test_x`). The result is `{file}::{func} (line {line})`, with the path as printed. A new tool's format is a new row. | AC2 |
| T9 | **Gates bounce on a timeout.** `gates.timed_out(code, output)` gives `Outcome(Verdict.BOUNCE, TIMED_OUT_BOUNCE.format(tail=tail(output)))` when `code == TIMED_OUT`, otherwise `None`. `tests_red` checks it **before** treating a non-zero exit as red, so a hang at `tests` never passes as a failing test. `tests_reworked` returns any `tests_red` result except the green-too-early bounce, so a tests claim cannot rescue a timeout. `green` checks it before "tests fail". `tests_green_and_covered` checks the coverage run with it before parsing the total. The bounce stays at the step (`_retry_here`) and counts a round. The s27 repeat screen applies as for any bounce. | AC1, AC2 |
| T10 | **Other callers need no change.** `test_output`, `tracked` and `landed` treat a non-zero code as today. `fullcheck` says `TIMED_OUT_WHY` instead of `exit 124`, and its tail carries the reason lines. | AC1 |
| T11 | **Role rule.** `_shared.md` gets the section "Never wait without a deadline" (exact text below). It does not repeat the unit-tester's "tests mock time" rule. | AC4 |
| T12 | **Enforced in the guard.** For every role, a Bash command that holds an open wait loop is denied with `WAIT_DENIED`, unless one of its segments starts with `timeout` or `gtimeout`. An open wait loop is a segment (the existing `_SEGMENT_SPLIT`) whose first word is `until` or `while`. One exception: `while` with `read` among the next two words (`while read l`, `while IFS= read -r l`), because such a loop ends with its input. `for` loops are bounded, so they pass. It runs in every view (`_check_view`), like the other checks. | AC4 |
| T13 | **Per-test timeout.** The runner project's pytest config sets a per-test timeout, so a hanging test fails by itself, names itself in the `FAILED` line and the suite goes on. Choice: `pytest-timeout` in the **dev** dependency group (not a runtime dependency, so no ADR), `timeout = 30` in `[tool.pytest.ini_options]`, default `signal` method. `uv.lock` is updated with it. | AC3 |
| T14 | **The s29 test.** `tests/test_router.py::test_a_held_boundary_waits_when_a_question_is_open` injects `sleep` (the fake posts the answer and records `[5.0]`), so it never runs the real wait. It must stay in the suite: no skip or xfail marker, and no `-k` or `--deselect` in `addopts`. Already true at design time; the reviewer checks it is still true. | AC5 |

`_shared.md`, new section after "Read little":

```markdown
## Never wait without a deadline

- Run a test suite in the foreground and let it finish. Don't start it in
  the background and then poll for its output.
- Give every wait a deadline: run it under `timeout N`, or loop a bounded
  number of times (`for i in $(seq 60); do …; done`). An open `until` or
  `while` loop with no deadline is denied.
- If a run hangs, stop it, name the test that hung in your handoff, and fix
  that test (or dispute it). Don't wait on it.
```

## Changes per module

### New `agile_team/commands.py` (stdlib only)

Module docstring: shell commands the runner runs, each in its own process
group under a time limit; a hung test named from its output. It imports
`from .process_groups import signal_child_group` (s41), so there is a single
rule for which groups the runner may signal.

```python
CommandRunner = Callable[[str], tuple[int, str]]
POPEN_OPTS: dict[str, Any] = {
    "shell": True, "stdin": subprocess.DEVNULL, "stdout": subprocess.PIPE,
    "stderr": subprocess.STDOUT, "text": True, "errors": "replace",
    "start_new_session": True,
}

@dataclass(frozen=True)
class HungPattern:
    """A regex for a stack frame of the hung test and how to print its name."""
    regex: re.Pattern[str]
    template: str
    def last(self, output: str) -> str | None: ...   # template filled from the last match

HUNG_PATTERNS: tuple[HungPattern, ...] = (
    HungPattern(
        re.compile(r'File "(?P<file>[^"]+)", line (?P<line>\d+),? in (?P<func>test\w*)'),
        "{file}::{func} (line {line})",
    ),
)

def hung_test(output: str) -> str | None: ...            # first row with a match (T8)
def hung_line(output: str) -> str: ...                    # HUNG_LINE or NO_HUNG_LINE
def kill_group(proc: subprocess.Popen[str]) -> None: ...  # T4: signal_child_group(proc.pid, SIGKILL)
def drain(proc: subprocess.Popen[str]) -> str: ...        # T5

@dataclass(frozen=True)
class CommandShell:
    """Runs shell commands in ``repo``, each in its own process group, under ``limit_s``."""
    repo: Path
    limit_s: float = DEFAULT_TIMEOUT_S
    def run(self, command: str) -> tuple[int, str]: ...            # T3, T6, T7
    def report_timeout(self, command: str, output: str) -> str: ...  # T7 layout

def shell_runner(repo: Path, limit_s: float = DEFAULT_TIMEOUT_S) -> CommandRunner:
    """Run toolchain commands in ``repo`` with a time limit; return exit code and combined output."""
    return CommandShell(repo, limit_s).run
```

How `run` works: open `subprocess.Popen(command, cwd=self.repo, **POPEN_OPTS)`
as a context manager, then `communicate(timeout=self.limit_s)`. On
`TimeoutExpired`, `kill_group`, `drain`, and return
`(TIMED_OUT, self.report_timeout(command, drained))`. On any other
`BaseException`, `kill_group` and re-raise. Otherwise return
`(proc.returncode, out)`. `report_timeout` returns
`"\n".join([*output.splitlines(), TIMEOUT_LINE.format(limit=self.limit_s, command=command), hung_line(output)])`.

## Test checklist

Real timers stay a fraction of a second (unit-tester rule). Every wait in a
test has a deadline.

**commands.py**
1. `shell_runner(tmp)("echo out; echo err >&2; exit 4")` gives `(4, …)` and holds both `out` and `err`. The existing `test_shell_runner` still passes.
2. stdin is `/dev/null`: `cat` returns `(0, "")` at once under a 2 s limit.
3. `CommandShell(tmp, 0.3).run("sleep 30")` gives `TIMED_OUT`. The output's last two lines are `TIMEOUT_LINE` (`timed out after 0.3s, …: sleep 30`) and `NO_HUNG_LINE`. It returns well under 5 s.
4. A command that prints a faulthandler-style frame to stderr, then sleeps, ends with `the hanging test: /x/tests/test_a.py::test_hangs (line 12)`.
5. Killed group: `sleep 30 & echo $! > pid; wait` under a 0.3 s limit. The grandchild in `pid` is gone afterwards (bounded poll, at most 2 s). A `sleep` the test started itself, in its own group, is still alive (terminate it in cleanup).
6. Drain deadline: monkeypatch `commands.DRAIN_S = 0.2`. A background child that calls `os.setsid()` and keeps stdout open does not hang `run`. The result is `TIMED_OUT` with only the two reason lines. Kill the escaped child by its pid in cleanup.
7. Another exception: if `communicate` raises `KeyboardInterrupt`, `kill_group` is called with the process and the exception propagates (monkeypatch either one).
8. `hung_test`: faulthandler format (no comma); traceback format (comma); with two dumps, the last one wins; `in pytest_pyfunc_call` and `in select` frames are ignored; no frame gives `None`.
9. `report_timeout` with empty output gives exactly the two reason lines.

**gates.py**

10. `tests_red` with the runner returning `(124, "…")` bounces with a reason starting `the command did not finish in time:`. It must not pass.
11. `tests_reworked(TestClaim.CHANGED)` on a timeout bounces with the timeout reason. A green run with a claim still passes, and red still passes.
12. `green` on a timeout bounces with the timeout reason, not `tests fail:`. In `tests_green_and_covered`, a green test run then a timed-out coverage run bounces with the timeout reason, not `could not read a coverage total`.
13. `Pipeline.evaluate`: a timeout at `implement` gives bounce_to `implement`, and at `tests` gives bounce_to `tests`.

**config.py / cli.py**

14. The default is `300.0`. `command_timeout_s = 90` is read. `0` and `-1` fail validation with `gates.command_timeout_s must be positive`.
15. `make_pipeline(config).checks.run.__self__.limit_s == 90`, and `make_runtime(...).shell(path).__self__.limit_s == 90` with the configured value.

**fullcheck.py**

16. A check whose runner returns `TIMED_OUT` has why `timed out`, and its tail holds the reason lines.

**guard.py** (through `check_bash` with any scope)

17. Denied, with exactly `WAIT_DENIED`: `until grep -q passed /tmp/run.log; do sleep 5; done`, `while true; do sleep 1; done` and `while ! grep -q x f; do sleep 1; done`. Allowed: `timeout 300 bash -c 'until grep -q x f; do sleep 1; done'`, `for i in $(seq 60); do sleep 1; done`, `cat f | while read l; do echo "$l"; done` and `while IFS= read -r l; do :; done < f`.

**pytest config / AC5**

18. `pytestconfig.getini("timeout")` is `"30"` (the plugin is active).
19. Reviewer check: the s29 test in T14 is present, injects `sleep` and is not skipped or deselected.
