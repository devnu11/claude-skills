# s102 (A6e): runner stages on the Flow chart and in the Time chart

Story: `.team/stories/s102.md`. Plan context: `.team/run/liaison/plans/tool-flow.md`
(sections "A6e" and "Readability"). Builds on s96/s97 (snapshot `steps`, the Time unit,
awake time), s98 (`step-end` and `po-turn` time split), s99 (`runner-stage` events),
s100/s101 (the `TL_TEXT` table, `stepEndOf`), s104 (Flow chart at natural size, `used`
roles, colour-only dimming). No new ADR: it follows the s96 pattern (the page derives
views from raw snapshot data) and the s101 pattern (the heartbeat lists what is open
now). No new dependency.

Developer: **developer-gui**. The page is most of the work. The Python part is small:
`live.py` and `stage_log.py` list open stage runs in the heartbeat, plus a two-line
`dispatch.py` wiring change and two fixture events.

## What changes, in one paragraph

The Flow chart gains four **stage nodes** (hexagons), each in the group where it runs and
joined to its role by a dotted edge: `Prepare env` (before the customer proxy),
`Implement gate` (after the developers), `E2E gate` (after the integration tester) and
`Boundary` (beside the PO). Each shows the last run, the total and the run count for the
chart's scope (Story, Sprint or Run), reads `idle` when there are none, and lights up
while it runs. To know that, the heartbeat gains `stages`: the stage runs open now. Every
agent box, and the PO's, gains a text share bar of model time against tool time for the
scope. The Time unit of "Time by" now counts three sources: agent steps, runner stages
(a `runner` row when grouped by role) and PO turns (three segments: model, tools,
waiting). The legend no longer says "agent steps only". The bar chart is drawn at scale
1 and its text comes from the measured `TL_TEXT` table, so it is at least 12 px.

## Rules

### Stage nodes on the Flow chart (AC1)

| id | rule |
|---|---|
| SN1 | **Table.** `STAGE_NODES` (below) is the only place that says which stages make a node, where it sits and what it joins. A stage not listed draws no node. It is still counted in the Time chart (TM2). |
| SN2 | **Drawn.** A stage node is drawn when the snapshot's `events` has at least one `runner-stage` event whose `data.stage` is in the node's `stages`, or when an open stage row (HB3) is in them. This is run-wide, like `roles[].used` (FL7). The scope never hides a node; it only dims it (SN6). |
| SN3 | **Position.** The node is declared inside its group's subgraph (`subgraph grp<group>`), after that group's role nodes. If the group has no role node, the subgraph is drawn for the stage node alone. Its shape is a hexagon: `<id>{{"<label>"}}`. |
| SN4 | **Edge.** One dotted edge (`-.->`, no label) joins the node to each drawn anchor. `before`: `<stage id> -.-> <anchor id>`. `after`: `<anchor id> -.-> <stage id>`. An anchor is a role in `ringRoles(view)` that equals the node's `anchor` or starts with `anchor + "-"`. The anchor `product-owner` means the node `po`. With no drawn anchor there is no edge. Stage edges come after every labelled edge, so the labelled edges keep their `linkStyle` indices. Each stage edge's `linkStyle` is `stroke-width:1.0px,stroke:<--ink-2>`, which is `weight(0, max)`. |
| SN5 | **Label.** It reads `<label><br/>runner · <stats>`, then the running line (SN7) if any. `<stats>` covers the node's `runner-stage` events that pass `inScope(view)` (by `story` and `at`; a boundary stage has `story: null`, so it is counted in Sprint scope by its time window and never in Story scope). With at least one run, `<stats>` is `last <fmt.age(last)> · total <fmt.age(total)> · <n> run` (`runs` when n ≠ 1). `last` is the `data.seconds` of the newest event in scope, by event order. `total` is Σ `data.seconds`. A missing or non-finite `seconds` counts 0. With none, `<stats>` is `idle`. |
| SN6 | **Dimmed.** A drawn node with no run in scope that is not running gets `class <id> idle`. That is the existing `idleClassDef`, which recolours only (FL1, FL2). |
| SN7 | **Lights up.** A node is **running** when an open stage row (HB3) has a `stage` in its `stages`. A running node gets `class <id> active` (the existing accent 3 px stroke), unless it is already the active node. Its label gains `<br/>⏱ running <fmt.age(awake)>`, with `awake = clockNow(view) − row.started_at − max(0, heartbeat.slept − row.started_slept)`, never below 0. |
| SN8 | **Active node.** `activeNodeId(view)` is the role node of the open step when there is one, else the **first** running stage node in `STAGE_NODES` order, else `po`. So between steps the halo (`markActive`) sits on the gate or boundary that is running, not on the PO. |

```js
const RUNNER = "runner";
const STAGE_NODES = [
  { id: "st_env", label: "Prepare env", group: "Customer", anchor: "customer-proxy", side: "before",
    stages: ["env.prepare"] },
  { id: "st_gate", label: "Implement gate", group: "Build", anchor: "developer", side: "after",
    stages: ["gate.tests+coverage", "gate.route-lint", "gate.dispute-output"] },
  { id: "st_e2e", label: "E2E gate", group: "Verify", anchor: "integration-tester", side: "after",
    stages: ["presentation.trial"] },
  { id: "st_boundary", label: "Boundary", group: "Steering", anchor: PO, side: "after",
    stages: ["boundary.sync", "boundary.check", "boundary.review", "boundary.push", "boundary.ci-wait"] },
];
```

The stage names are exactly `stages.STAGES`' names (s99 RS1). A page test pins that every
name in `STAGE_NODES` is one of `agile-team tools`' built-in names (TC list below).

### The heartbeat's open stages (runner; makes SN7 possible)

| id | rule |
|---|---|
| HB1 | **Listed while open.** `StageLog.open(name)` lists the run's open row (HB2) on its `board` for as long as the stage runs, then removes it. The row is listed inside `stages.entered(run)` and removed before the `runner-stage` event is written. A stage that raises is removed all the same. |
| HB2 | **Row.** `stage_log.open_row(run, start)` → `{"stage", "when", "attach", "story", "step", "started_at", "started_mono", "started_slept"}`, in this order. The values come from `run.stage`, `run.place` and the start `Mark`, the same values as the closing event's data. |
| HB3 | **Heartbeat key.** `Pulse.heartbeat()` gains `"stages"` right after `"calls"`: the listed rows in opening order (outer first), or `[]` once the pulse has ended. Each change writes the heartbeat at once, as `doing()` does. The snapshot passes the heartbeat through unchanged (`live.read_heartbeat`), so there is no snapshot code change. A replay's `heartbeat` is `null` (`asOf`), so nothing lights in a replay. |
| HB4 | **Seam.** The board is a separate small protocol (`StageBoard`, below), not a new `Marker` method. A `StageLog` built without one uses `HIDDEN`, which lists nothing. Only `Runtime` passes the pulse. `HEARTBEAT_VERSION` stays 2, since a new key is additive (as with s101's `calls`). |

### The Time chart (AC2)

| id | rule |
|---|---|
| TM1 | **Sources.** The Time unit totals **time pieces** from three sources, in the table `TIME_SOURCES = [stepPieces, stagePieces, turnPieces]`. |
| TM2 | **Pieces.** `stepPieces`: each finished step (`finished(s)`) whose role is not `product-owner` → `{role, story, model, count: "steps", parts: {work: s.seconds ?? 0}, wall: s.clock === "wall"}`. `stagePieces`: each `runner-stage` event with `data.when !== "during"` and a finite `data.seconds` → `{role: "runner", story: e.story, model: "runner", count: "runs", parts: {runner: seconds}, wall: false}`. A `during` stage (a runner tool) is left out because it is already inside its step's time (TL13). `turnPieces`: each `po-turn` event → `{role: PO, story: null, model: roleInfo(view, PO).model, count: "turns", parts: poSplit(e.data), wall: false}`. |
| TM3 | **PO split.** `poSplit(d)` → `{model: m, tools: max(0, t − w), waiting: w}`, with `m = d.model_s`, `t = d.tool_s` and `w = d.waiting_s`, each 0 when not finite. `tool_s` is the union of every tool call, `po.run_role` included (s98), so `tools` is the PO's own tool time and the three parts add up to the turn (`tool_s + model_s`, as TL13). |
| TM4 | **Totals.** `timeBy(pieces, key)` → `{<group>: {steps, runs, turns, wall, seconds, parts: {work, runner, model, tools, waiting}}}`. The group is `piece[key] ?? "(no story)"`. The piece's `count` field is incremented, its parts are added, `seconds` is Σ parts, and `wall` counts wall-clock steps. So grouped by role there are rows for the agent roles, `runner` and `product-owner`. Grouped by story, a story's row has work and runner time, and PO turns fall under `(no story)`. Grouped by model, runner stages make a `runner` row. |
| TM5 | **Segments.** `timeRow` draws one segment per entry of `TIME_PARTS` with a non-zero value, in table order, as `mixRow` does. The last drawn segment gets the rounded end. Each segment's tooltip reads `<b>role</b><br><part label>: <fmt.span(v)>`. The value text after the bar is `fmt.span(seconds)`. |
| TM6 | **Share.** `UNITS[*].share(t)` is what counts toward "% of" in a tooltip. `barRows` sets `whole = Σ share(t)`. For tokens and dollars, `share` equals `total`. For time, `share(t) = t.seconds − t.parts.waiting`: the PO's waiting overlaps the agent steps it waited on, so it is drawn but not counted twice in a share. Rows are still sorted by `total` and scaled to it. |
| TM7 | **Row tooltip.** The label's own tooltip is gone. The row's summary is on its **first** segment, followed by its part line: `<b>role</b><br><fmt.span(seconds)> (<pct> of time) · <n> steps · <n> runs · <n> turns`, listing only the non-zero counts (singular when 1). Then `· <wall> may include sleep` when `wall > 0`, and `<br>waiting <fmt.span(w)> overlaps the steps (not in the share)` when `waiting > 0`. |
| TM8 | **Legend.** `timeLegend()` reads `Awake time:`, then one swatch and label per `TIME_PARTS` entry. The words "agent steps only" and "see A6" are gone. |

```js
const TIME_PARTS = [
  ["work", "Agent steps", "--s2"], ["runner", "Runner stages", "--s3"],
  ["model", "PO model", "--s1"], ["tools", "PO tools", "--s4"],
  ["waiting", "PO waiting on a step", "--ink-2"],
];
```

### Model and tool share on agent boxes (AC3)

| id | rule |
|---|---|
| SB1 | **Agents.** For a role node: `split = Σ` over `scopeSteps(view)` with that role of the step's `stepEndOf({view}, step).data`: `model += model_s` and `tools += tool_s`. Only steps whose step-end has both values finite count. |
| SB2 | **PO.** For the `po` node: Σ `poSplit` over the `po-turn` events in scope (`inScope(view)`): `model` and `tools`, without waiting (TM3). In Story scope, where the PO's stats read `—`, there is no share line. |
| SB3 | **Line.** When `model + tools > 0`, the node gains `<br/>model <p>% <bar> tools <100 − p>%`. Here `p = Math.round(100 · model / (model + tools))` and `bar = "█".repeat(c) + "░".repeat(SHARE_CELLS − c)`, with `c = Math.round(SHARE_CELLS · model / (model + tools))` and `SHARE_CELLS = 10`. With no split, there is no line. The line comes after the stats line and the `↩ bounced` line, and before the running line. |

Mermaid draws under `securityLevel: "strict"`, which escapes HTML in labels apart from
`<br/>`. So the bar is text, in the node's own font and colour. It is not a drawn rect.

### Readability (AC-R)

| id | rule |
|---|---|
| RD1 | **Flow chart.** It stays at natural size (TR5): `FLOW_FONT_PX` 16, `useMaxWidth: false`, `#flow { overflow-x: auto }`. The new nodes add width and height, never a scale. No new `classDef` sets `font-size`, `opacity`, `filter`, `transform` or `mix-blend-mode`. Stage nodes use only the existing `active` and `idle` classes. |
| RD2 | **Bar chart at scale 1.** `renderBars` draws the `#mix` SVG with `width` and `height` attributes equal to its `viewBox` (`MIX.w`, `h`) and `style="width:<MIX.w>px;height:<h>px;max-width:none"`. That inline style beats `.chart svg { width: 100% }`. `#mix { overflow-x: auto }` lets a narrow screen scroll it sideways. This applies to all three units, since they share the drawing functions. |
| RD3 | **Bar chart text.** Every `<text>` in the bar rows (`oneBar`, `mixRow`, `timeRow`) is built with `tlText`, using two new `TL_TEXT` kinds: `barLabel: { px: 12, ink: "--ink-2" }` and `barValue: { px: 12, ink: "--ink" }`. Inline styles beat `.chart text { font-size: 11px; fill: var(--muted) }`. |
| RD4 | **Legend.** The Time legend is HTML in `.legend`: 12 px, `--ink-2` on `--surface`. It is unchanged. |

## Changes per module

### `agile_team/stage_log.py`

```python
class StageBoard(Protocol):
    """Where open stage runs are listed while they run (HB1); ``live.Pulse`` is one."""

    def showing(self, row: dict[str, Any]) -> AbstractContextManager[None]:
        """List ``row`` for the duration of the ``with`` block."""
        ...


class Hidden:
    """A board that lists nothing (HB4)."""

    def showing(self, row: dict[str, Any]) -> AbstractContextManager[None]:
        """No listing; a ``nullcontext``."""


HIDDEN = Hidden()


def open_row(run: stages.Run, start: Mark) -> dict[str, Any]:
    """The heartbeat's row for a stage run still open (HB2)."""
```

- `StageLog` gains the field `board: StageBoard = HIDDEN`, after `place`.
- `StageLog.open`: `with stages.entered(run), self.board.showing(open_row(run, start)): yield run`,
  inside the existing `try`/`finally` that emits.
- Imports: `from contextlib import AbstractContextManager, nullcontext` (alongside today's
  `contextmanager, suppress`).

### `agile_team/live.py`

- `Pulse` gains `_stages: list[dict[str, Any]] = field(init=False, default_factory=list)`.
- `Pulse.showing(self, row: dict[str, Any]) -> Iterator[None]` (`@contextmanager`): under the lock it
  appends `row`, then calls `write()`. On exit, under the lock it drops that same object
  (`[r for r in self._stages if r is not row]`), then calls `write()`. It is the `StageBoard` method.
- `Pulse.heartbeat()`: `"stages": list(self._stages) if live else []`, right after `"calls"`.

### `agile_team/dispatch.py`

- `self.stage_log = StageLog(self.events, self.pulse, board=self.pulse)` (line ~360).

## Known limits

- Only the four groups the AC names are nodes. The other stages are `checkout.*`, `quality.*`,
  `gate.tests-red`, `gate.tests-rework`, `gate.green`, `presentation.layout` and the runner tools. They
  show in the story timeline (s100) and in the Time chart's `runner` row, but not on the Flow chart.
  Adding a node is one `STAGE_NODES` row.
- The share bar is text (█/░, 10 cells), because Mermaid's strict mode escapes HTML in labels. It is
  one colour.
- A step that ended before s98 has no `model_s`/`tool_s` and is left out of the share. When no step in
  scope has a split, there is no line.
- The Time chart is run-wide, as it is today. It does not follow the Flow chart's scope.
- A stage run whose runner was killed never writes its event, so it is counted nowhere. Its open row
  vanishes with the heartbeat (`beat: ended` or stale health).
