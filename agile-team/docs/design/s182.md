# s182: a story rebase step's settle adds no commit to the rebase branch

Story: `.team/stories/s182.md`. ADR: ADR-0092. Requirements: REQ-217 to REQ-221.
Developer: `developer-cli`.

## Problem

`_settle_step_tree` runs the general `settle_tree` on a finished story rebase.
It commits each in-scope leftover as `fixup! <story subject>` and quarantines
each out-of-scope edit as a commit plus its revert, both on the rebase branch.
Then `story_rebase._find_changed_commits` compares the subjects of
`base..old` with `onto..HEAD`. The runner's own commits are "added" commits,
so the check can never pass. The bounce keeps `story.rebase` queued. A
Manager `advance` moves `story.step`, and the same rebase runs again under
the next step's name, with more runner commits each time. The refusal names
no commit, so nobody could tell who made the extra ones.

## Rules

| # | Rule | AC |
|---|---|---|
| R1 | **A finished story rebase gets its own settle.** When the step kind is `STORY_REBASE` and the rebase did not stop (`_find_rebase_stop` is `None`), the tree is settled by `Runtime._settle_rebase_tree`, never by `settle_tree`. That settle makes no new commit on the rebase branch. There is no step commit (`commit` stays `None`, `plan.commit` stays `None`), no requirement sorting and no hold-back: the rebase's write scope is its conflicting files, which are the conflict's resolution (protocol "Requirement changes"). | AC1, AC2, AC4 |
| R2 | **Out-of-scope edits are set aside off the branch.** Each out-of-scope path (after `restrict_config`) is committed alone with the existing quarantine message. A ref `refs/agile-team/set-aside/<sha>` is pointed at that commit, and the branch HEAD is on goes back to the commit's parent with `git reset -q --keep HEAD^`. The edit leaves the worktree, the branch is where it was, and the edit stays readable at the ref. Refs outside `refs/heads` are shared by every worktree and are never pushed. The `quarantine` event is emitted as today with `sha` and `paths`, plus `ref`. The step report gets `"quarantine": <sha>` and `"set_aside": {"ref": <ref>, "paths": [...]}`. The step is not bounced for it, the same as a quarantine on any other step. | AC2 |
| R3 | **In-scope leftovers are folded into the branch's last commit.** This is the architect's pick for AC1: adopt, not bounce. After R2, if any in-scope path is still changed and the rebase is foldable (R4), the runner stages exactly those paths and runs `git commit --amend --no-edit --no-verify`. The tip keeps its subject, message, trailers and author. The new tip sha is appended to `StoryRebase.made`. The step report gets `"folded": {"sha": <new tip>, "paths": [...]}`. Then the S3 checks run as today and the story adopts the branch. | AC1 |
| R4 | **Foldable** means: no git operation is in progress, HEAD is on `rebase.branch`, `rebase.onto` is an ancestor of HEAD, and HEAD is not `onto` (at least one commit in `onto..HEAD`). A rebase that is not foldable keeps its in-scope leftovers in the worktree. The S3 checks then refuse it as unfinished, off-branch, off-base or dirty (`the worktree has uncommitted changes:` plus `git status --porcelain`, which names the file), never as changed commits. | AC1 |
| R5 | **Order at step end** (unchanged apart from R1): `_settle_head` → `_settle_step_tree` (R1 to R3) → `_apply_rebase`: put back moved branches (s176) → stop/hold → `find_refusal` → `_take_rebase`. | AC1, AC2 |
| R6 | **The commits check names each commit.** `_find_changed_commits` still compares `base..old` with `onto..HEAD` by subject and in order. When the two lists differ, the reason is the header `"{branch}'s commits are not {old}'s commits rebased, by subject and in order:"` and one line per difference, from `difflib.SequenceMatcher(None, wanted_subjects, found_subjects, autojunk=False).get_opcodes()`: `delete` gives a `missing` line for each wanted commit, `insert` gives an `extra` line for each found commit, and `replace` pairs the two sides in order as `changed` lines, with the longer side's rest as `missing` or `extra` lines. A reordered commit shows as one `missing` and one `extra`. Line forms (sha cut to `SHA_WIDTH = 12`): `- extra {sha} {subject} (made by {maker})`, `- missing {sha} {subject} (on {old})`, `- changed {old_sha} {old_subject} -> {sha} {subject} (made by {maker})`. `maker` is `the runner` when the sha is in `rebase.made`, else `the role`. | AC3 |
| R7 | **No `advance` past a queued rebase.** `Pipeline.ruling_move_refusal` refuses `advance` while `story.rebase` is not `None`, with `ADVANCE_REBASE`. The ruling is reported unapplied (as `ADVANCE_LAST` is today): `story.step` does not move, the story keeps its status, and the rebase is not re-checked under another step's name. `upgrade_model` (retry, rounds reset), `rescope`, `revise_design` and `escalate` still apply. The check is placed before the `ADVANCE_LAST` check. | AC3 |
| R8 | **Renumbering inside the replayed commits passes.** Edits that the role commits during the rebase (`git add` and `git rebase --continue`), such as renumbered requirement or ADR ids, are part of the replayed commits. They change no subject, so R6 passes and the story adopts the branch. Neither the settle nor the check reads those commits' contents. | AC4 |
| R9 | **Not covered: the boundary rebase.** `scratch_rebase._commits_changed` is not changed. A `REBASE_FIX` step's git is the team checkout (`REBASE_FIX` is not in `WORKTREE_KINDS`), and its scratch worktree is under the run dir. `settle_tree` never commits into it, so no runner commit can reach the scratch branch. | — |

## Changes per module

### `agile_team/story_branches.py`

- `StoryRebase` gains `made: list[str] = field(default_factory=list)  # s182: tips the runner made by folding`. It loads and saves like `heads`. An old `state.json` without it loads as `[]`.

### `agile_team/guard.py`

- `SET_ASIDE_REF = "refs/agile-team/set-aside/{sha}"`.
- `def set_aside(git: Git, audit: Audit) -> str:` "Commit the out-of-scope paths alone, keep that commit at a ref, and move the branch back off it; return its sha." The body runs `sha = git.commit(audit.out_of_scope, QUARANTINE.format(role=audit.role))`, then `git.run("update-ref", SET_ASIDE_REF.format(sha=sha), sha)`, then `git.run("reset", "-q", "--keep", "HEAD^")`, and returns `sha`. Pitfall comment: `--keep` leaves the other (in-scope) unstaged edits in place. `git.commit` has already unstaged them (`reset -q`), and none of them is in the commit.

### `agile_team/story_rebase.py`

- `SHA_WIDTH = 12`.
- `COMMITS_CHANGED = "{branch}'s commits are not {old}'s commits rebased, by subject and in order:"` (header; the lines follow it, joined with `"\n"`).
- `EXTRA_LINE = "- extra {sha} {subject} (made by {maker})"`, `MISSING_LINE = "- missing {sha} {subject} (on {old})"`, `CHANGED_LINE = "- changed {old_sha} {old_subject} -> {sha} {subject} (made by {maker})"`, `RUNNER = "the runner"`, `ROLE = "the role"`.
- `@dataclass(frozen=True) class ListedCommit:` "One commit of a span: its sha and subject." Fields `sha: str`, `subject: str`.
- `@dataclass(frozen=True) class CommitLists:` "The old branch's commits, the rebased ones, and the runner's own (R6)." Fields `wanted: list[ListedCommit]`, `found: list[ListedCommit]`, `rebase: StoryRebase`.
- `def list_commits(git: Git, span: str) -> list[ListedCommit]:` "The span's commits, oldest first." It reads `git log --reverse --format=%H%x09%s <span>`. It replaces `_list_subjects`.
- `def describe_changed_commits(lists: CommitLists) -> list[str]:` "One line per extra, missing or changed commit (R6)." It maps each non-`equal` opcode through the table `OPCODE_LINES: dict[str, Callable[[CommitLists, Opcode], list[str]]] = {"delete": _list_missing, "insert": _list_extra, "replace": _list_replaced}`. `Opcode = tuple[str, int, int, int, int]`.
- `_list_missing(lists, opcode)`, `_list_extra(lists, opcode)` and `_list_replaced(lists, opcode)` each build their lines. `_list_replaced` zips the two slices as `changed` lines and hands the rest of the longer slice to `_list_missing`/`_list_extra` on a sub-range. `_get_maker(lists, sha) -> str` returns `RUNNER` if `sha in lists.rebase.made` else `ROLE`.
- `_find_changed_commits(git, rebase)` builds `CommitLists(list_commits(git, f"{rebase.base}..{rebase.old}"), list_commits(git, f"{rebase.onto}..HEAD"), rebase)`. It returns `None` when the subject lists are equal, else `"\n".join([COMMITS_CHANGED.format(branch=rebase.branch, old=rebase.old), *describe_changed_commits(lists)])`.
- `def is_foldable(git: Git, rebase: StoryRebase) -> bool:` "R4: the rebase is finished, on its branch, on `onto`, with at least one commit to fold into." It reuses `_find_unfinished`, `_find_off_branch` and `_find_off_base` (all `None`), and `git.head() != git.run("rev-parse", rebase.onto).strip()`.
- `def add_to_tip(git: Git, paths: list[str]) -> str:` "R3: amend the tip with exactly ``paths``, keeping its message; return the new tip." (`fold` and `amend` are not house-rules verbs, so the name uses `add`.) It runs `reset -q`, `add -A -- *paths` and `commit --amend --no-edit --no-verify`, and returns `git.head()`.
- `find_refusal` is unchanged (same order of checks).

### `agile_team/dispatch.py` (`Runtime`)

- `_settle_step_tree(plan, parsed)`: after the stop check, `if plan.kind is StepKind.STORY_REBASE: return self._settle_rebase_tree(plan)`; else `settle_tree(plan)` as today.
- `def _settle_rebase_tree(self, plan: Plan) -> dict[str, Any]:` "R1: set aside out-of-scope edits and fold in-scope ones; commit nothing new." It runs `verify_checkout()`, takes the audit with `restrict_config(guard.audit_step(...))`, then calls `_set_aside(plan, audit)` and `_add_leftovers(plan, audit.in_scope)`, and calls `record_checkout()` when either did something. It returns `{"commit": None, "quarantine": sha_or_None} | set_aside_fields | fold_fields`.
- `def _set_aside(self, plan: Plan, audit: guard.Audit) -> dict[str, Any]:` "R2: set the out-of-scope edits aside off the branch and report them." It returns `{}` when `audit.out_of_scope` is empty. Otherwise it calls `guard.set_aside`, emits `EventKind.QUARANTINE` with `sha`, `paths` and `ref`, and returns `{"quarantine": sha, "set_aside": {"ref": ref, "paths": paths}}`.
- `def _add_leftovers(self, plan: Plan, paths: list[str]) -> dict[str, Any]:` "R3: fold the in-scope leftovers into the rebase tip when foldable." It returns `{}` when `paths` is empty or the rebase is not `story_rebase.is_foldable`. Otherwise it calls `story_rebase.add_to_tip`, appends the sha to `rebase.made` and returns `{"folded": {"sha": sha, "paths": paths}}`.
- `_settle_rebase_tree` merges the dicts so that `quarantine` is `None` when nothing was set aside.

### `agile_team/gates.py`

- `ADVANCE_REBASE = "story {id} has a queued story rebase onto {onto}; advance would only run it again under the next step's name. Rule upgrade_model to retry it, or rescope, revise_design or escalate"`.
- `Pipeline.ruling_move_refusal`: first `if ruling == "advance" and story.rebase is not None: return ADVANCE_REBASE.format(id=story.id, onto=story.rebase.onto)`, then the `ADVANCE_LAST` check as today. Keep the function short: a table or two guard lines.

### `agile_team/roles/manager.md`

- After "`advance` moves the story past a gate no role can satisfy, to the next step.", add: "It can't move a story whose story rebase is queued. Rule `upgrade_model` to retry the rebase."

## Test checklist

Unit (`tests/test_story_rebase.py`, `tests/test_guard.py`, `tests/test_story_rebase_steps.py`, `tests/test_gates.py` or the existing rulings test module), real git in a scratch repo:

- [ ] AC1: a story with a conflicting branch; the step resolves, runs `git rebase --continue`, then edits one conflict file without committing, and hands off `done`. The story adopts the branch. `onto..branch` has the same subjects as `base..old`, the tip holds the edit, the tree is clean, the report has `folded` naming the file, and `rebase.made` held the tip before adoption.
- [ ] AC1/R4: the same leftover on a rebase with no commit over `onto` (or off its branch) is not folded. The bounce reason is the dirty, off-branch or off-base one, names the file, and is never `COMMITS_CHANGED`.
- [ ] AC2: an out-of-scope edit (tracked and untracked) left by a finished rebase step leaves the branch's commits unchanged and the worktree clean. `refs/agile-team/set-aside/<sha>` holds the edit, the `quarantine` event carries `sha`, `paths` and `ref`, the report has `set_aside` with the paths, and the story is adopted.
- [ ] AC2: an out-of-scope edit and an in-scope leftover together give both a set-aside and a fold, with no extra commit.
- [ ] `guard.set_aside` keeps other unstaged edits in the worktree.
- [ ] AC3: an extra commit made by the role gives an `extra … (made by the role)` line with its 12-char sha and subject. A dropped commit gives `missing … (on <old>)`, a reworded one gives `changed … -> … (made by the role)`, and a reorder gives one missing and one extra line. A sha in `rebase.made` reads `made by the runner`.
- [ ] AC3: `advance` on a story with a queued rebase is reported unapplied with `ADVANCE_REBASE`. `story.step` and `story.rebase` are unchanged, and the next work is the rebase at the same step. `upgrade_model` on it still applies. `advance` without a queued rebase is unchanged.
- [ ] AC4: a rebase whose conflict resolution renumbers a requirement id and an ADR id in the conflicting files, committed by `rebase --continue`, with no added commit, passes `find_refusal` and is adopted.
- [ ] A stopped or non-`done` rebase still settles nothing (`commit` and `quarantine` `None`, worktree untouched).
- [ ] `StoryRebase` without `made` in an old `state.json` loads with `made == []`.
