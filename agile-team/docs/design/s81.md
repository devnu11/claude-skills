# s81: The boundary is done only when the PR's CI is green, or a bug story is opened

Story: `.team/stories/s81.md`. Developer: `developer-cli`. No ADR: this extends
the s29 boundary (ADR-0015) by one stage, adds no dependency, and keeps `gh`
behind the existing `Prs` interface and the `system` seam (s71).

s80 (autosquash) was cancelled, so this design builds on the boundary as it is
today (`boundary.py`, `boundary_runner.py`, `upstream.py`).

## Rules

- **CI1 New last stage.** `Stage.CI = "ci"` follows `Stage.PUSH`:
  `STAGES = (SYNC, CHECK, REVIEW, PUSH, CI)` and
  `RESTACK_ONLY = {REVIEW, PUSH, CI}`. The CI stage runs on every boundary
  that pushed: always at an end, and at a start only when it restacks. It
  runs only after `_push_all` pushed every branch. The local, nothing and
  push-rejected paths never reach it.
- **CI2 What is watched.** These stack entries are watched: `mode is
  PrMode.READY` with a `pr` number, in stack order. Normally that is one PR,
  the bottom one. Drafts are not watched, because the repo's workflows skip
  drafts (protocol § Sprint boundaries, "CI"). A draft is watched at the
  boundary where it becomes the non-draft one. With no entry to watch, the
  verdict is `NONE` (CI10).
- **CI3 The wait.** For each watched PR the runner runs
  `gh pr checks <n> --watch`. Its subprocess limit is the time left before
  one shared deadline: `system.monotonic() + [gates] ci_timeout_s` (default
  `1800.0`), set when the stage starts. After the watch ends or times out,
  the runner reads `gh pr checks <n> --json name,state,bucket,link,workflow`.
  It records what that JSON says. The watch's exit code only means "ended"
  or "timed out" (`TIMED_OUT` = 124).
- **CI4 Checks not queued yet.** Right after a push, GitHub may report no
  checks. In that case `gh pr checks --watch` exits at once with "no checks
  reported". When the watch ended and the read gives no checks, or still
  gives pending ones, the runner sleeps `CI_POLL_S = 10` (`system.sleep`)
  and looks again. It looks at most `CI_LOOKS = 12` times (about 2 minutes
  of grace). Both the look count and the deadline bound the loop. No bare
  `while`.
- **CI5 Check buckets.** `gh`'s `bucket` maps to `Bucket`: `pass`, `fail`,
  `pending`, `skipping`, `cancel`. An unknown bucket string becomes `FAIL`.
  That is the safe side, because it is never green.
- **CI6 One PR's verdict** (`verdict_of(checks)`): each bucket maps through
  `BUCKET_VERDICT = {PASS: GREEN, FAIL: RED, CANCEL: RED, PENDING: PENDING}`.
  `SKIPPING` maps to nothing. The verdict is the first of
  `CHECK_ORDER = (RED, PENDING, GREEN)` that is present, else `NONE`. So no
  checks, or only skipped ones, gives `NONE`. One failure among pending
  checks gives `RED`.
- **CI7 The boundary's verdict** (`overall(results)`): the first of
  `PR_ORDER = (RED, PENDING, NONE, GREEN)` among the per-PR verdicts, else
  `NONE`. It is `GREEN` only when every watched PR is green.
- **CI8 Failing lines.** For each check whose bucket is `FAIL` or `CANCEL`,
  the job id is taken from its `link` (`JOB_LINK =
  r"/actions/runs/\d+/job/(\d+)"`). The runner then reads
  `gh run view --job <id> --log-failed`. `failing_lines(log)` strips each
  line's gh prefix (`LOG_PREFIX`: `job<TAB>step<TAB>` and an ISO
  timestamp). It keeps the lines that match `FAILING_LINE` patterns, in
  order, without repeats, and at most `MAX_LINES = 20`. With no match it
  keeps the last `TAIL_LINES = 10` non-blank lines. Some links have no job
  id (a check that is not from Actions). For those, and when the log read
  fails (non-zero exit), there are no lines. A log read never turns a red
  verdict into an error.
- **CI9 Recorded in state and event (AC1).** Each watched entry gets
  `StackEntry.ci = CiResult(pr, url, head, verdict, checks)`. Every check
  carries `name`, `workflow`, `bucket`, `link` and `lines`. The stage's
  event carries `ci` (the overall verdict), `prs` (text) and `checks`
  (text, CI12). It also carries `results` (a list of `asdict(CiResult)`).
- **CI10 Outcomes** (data: `CI_OUTCOMES[verdict]` → `BoundaryRunner`
  method):

  | verdict | boundary | event | human / PO |
  |---|---|---|---|
  | `GREEN` | finishes; `upstream.report = green_report(...)` | `done`, `ci: green` | hand-over `ci_green` (the PO tells the human "ready to merge") |
  | `RED` | held `ci_failed` | `held`, `hold: ci_failed`, `ci: red` | hand-over `ci_failed` |
  | `PENDING` (the deadline passed) | held `ci_pending` | `held`, `hold: ci_pending`, `ci: pending`, `reason` | hand-over `ci_pending`, naming the pending checks |
  | `NONE` | finishes; `upstream.report = CI_NONE_REPORT` | `done`, `ci: none`, `note` | `update` posted to the human (as `_local` does) |

- **CI11 Done only with green or a recorded bug (AC4).** A boundary held
  `ci_failed` ends in one of two ways. (a) `record_ci_bug(story)` names a
  story that exists and is not done. (b) `continue_boundary` reruns the CI
  stage, for when the human re-ran the checks, and that run is green.
  `continue_boundary` never finishes the boundary itself: it only clears the
  hold, and the stage runs again. `record_ci_bug` writes
  `upstream.ci_bug = story` and closes the boundary (END: `closed`,
  `report = CI_RED_REPORT`). It logs a `done` event with `ci: red`,
  `story`, and `note` = the report, which reads "checks failed, story sN
  opened".
- **CI12 "Ready" only from green (AC5).** `READY_PHRASE = "ready to merge"`
  appears in exactly two texts: `CI_GREEN_REPORT` (built only by
  `ci.green_report`, which raises `ValueError` unless every result is
  `GREEN`) and the `ci_green` hand-over line (which applies only to an event
  with `ci == "green"`). Every other text says **NOT ready** and never holds
  `READY_PHRASE`. The texts in question: the pushed note, the local note,
  the none, red and pending texts, and the hand-over lines. The pushed note
  no longer calls the bottom PR "ready". It lists PRs as `open` or `draft`
  (`PR_KIND`).
- **CI13 No PR, no CI (AC6).** Without `gh`, logged out, or with push
  permission `no`, the boundary ends at push as today (`_local`).
  `LOCAL_REPORT` gains the sentence `No CI result exists.`, and the `local`
  event gets `ci: none`.
- **CI14 Bug story first.** While `upstream.ci_bug` names a story that is
  not done, `start_sprint` refuses unless that story is first in its list
  (`CI_BUG_FIRST`). A successful `start_sprint` clears `ci_bug`. If the bug
  story is already done, there is no refusal and `start_sprint` clears it.
- **CI15 Blocking is acceptable.** The CI stage blocks the router up to
  `ci_timeout_s`, like gate commands do. It runs inside `pulse.doing("sprint
  boundary: ci")`, so health stays green (s78 chore). `tell` messages are
  delivered after it. If the run is killed during the wait, resume reruns
  the CI stage: the push stage was saved before it.
- **CI16 Errors.** Unparsable `--json` output raises `UpstreamError`, which
  holds `boundary_error` through the existing `_step` handler. A `gh` call
  that times out returns code 124 with the text `gh timed out after {limit}s`
  (before, it raised `TimeoutExpired`). `_gh` turns that into
  `UpstreamError`, as for any other non-zero exit.

```python
class Bucket(StrEnum):      # PASS="pass" FAIL="fail" PENDING="pending" SKIPPING="skipping" CANCEL="cancel"
class CiVerdict(StrEnum):   # GREEN="green" RED="red" PENDING="pending" NONE="none"

BUCKET_VERDICT = {Bucket.PASS: CiVerdict.GREEN, Bucket.FAIL: CiVerdict.RED,
                  Bucket.CANCEL: CiVerdict.RED, Bucket.PENDING: CiVerdict.PENDING}
CHECK_ORDER = (CiVerdict.RED, CiVerdict.PENDING, CiVerdict.GREEN)
PR_ORDER = (CiVerdict.RED, CiVerdict.PENDING, CiVerdict.NONE, CiVerdict.GREEN)
FAILING = frozenset({Bucket.FAIL, Bucket.CANCEL})
PASSING = frozenset({Bucket.PASS, Bucket.SKIPPING})

@dataclass
class Check:
    """One CI check of a PR as gh reports it, plus its failing lines."""
    name: str
    bucket: Bucket
    workflow: str = ""
    link: str = ""
    lines: list[str] = field(default_factory=list)
    # __post_init__: self.bucket = Bucket(self.bucket)

@dataclass
class CiResult:
    """What CI said about one PR at one head."""
    pr: int
    url: str
    head: str
    verdict: CiVerdict
    checks: list[Check] = field(default_factory=list)
    # __post_init__: verdict -> CiVerdict; dict checks -> Check(**c)

def bucket_of(raw: str) -> Bucket                     # CI5: unknown -> FAIL
def check_of(raw: dict[str, Any]) -> Check            # gh JSON row -> Check (name, bucket, workflow, link)
def checks_of(output: str) -> list[Check]             # NO_CHECKS in output.lower() -> []; else json list; JSONDecodeError -> UpstreamError(output.strip())
def job_of(link: str) -> str | None                   # JOB_LINK group 1
def first_of(order: tuple[CiVerdict, ...], found: Iterable[CiVerdict]) -> CiVerdict  # else NONE
def verdict_of(checks: list[Check]) -> CiVerdict      # CI6
def overall(results: list[CiResult]) -> CiVerdict     # CI7
def failing_lines(log: str) -> list[str]              # CI8
def prs_text(results: list[CiResult]) -> str          # "#14 https://…; #15 https://…"
def check_lines(results: list[CiResult]) -> str       # CI12 text: one CHECK_LINE per check not in PASSING, label "workflow / name" (name alone without workflow), each failing line below it indented 4 spaces; "\n"-joined
def green_report(sprint: int, results: list[CiResult]) -> str   # ValueError unless overall(results) is GREEN and results non-empty
```

`checks_of` raises `upstream.UpstreamError`. Import it inside the
function, or move `UpstreamError` into `ci.py` and re-export it from
`upstream` (preferred: `upstream.py` does
`from .ci import UpstreamError`, and no name changes for callers).

```python
@dataclass(frozen=True)
class CiWatch:
    """Waits for the CI of watched PRs under one deadline (CI3, CI4)."""
    prs: Prs
    limit_s: float

    def results(self, entries: list[StackEntry]) -> list[CiResult]:
        """One CiResult per entry, all under one deadline from now."""
    def _result(self, entry: StackEntry, deadline: float) -> CiResult:
        """Settled checks for the entry's PR, with failing lines, and their verdict."""
    def _settled(self, number: int, deadline: float) -> list[Check]:
        """Watch, read, and look again (CI_LOOKS, CI_POLL_S) while nothing is settled."""
    def _wait(self, number: int, deadline: float) -> bool:
        """False when the deadline has passed or the watch timed out."""
    def _with_lines(self, check: Check) -> Check:
        """A failing check with its failing lines; others unchanged."""
```

`_settled` contract: for each of `range(CI_LOOKS)`, run `ended = self._wait(...)`
and then `checks = self.prs.checks(number)`. Return `checks` when `not ended`
(timeout), or when `checks` is non-empty and none is `PENDING`. Otherwise
`system.sleep(CI_POLL_S)`. After the last look, return the last `checks`.
`_wait`: `left = deadline - system.monotonic()`, then
`return left > 0 and self.prs.wait_checks(number, left)`.

### `agile_team/upstream.py`

- `from .commands import TIMED_OUT` and `from .ci import Check, checks_of, job_of`
  (plus `UpstreamError`, see above).
- `Exec` becomes a Protocol:
  ```python
  class Exec(Protocol):
      def __call__(self, argv: list[str], limit_s: float = GH_TIMEOUT) -> tuple[int, str]: ...
  ```
- `command_runner(repo)`: its inner `run(argv, limit_s=GH_TIMEOUT)` passes
  `limit_s` as `system.Command(..., timeout=limit_s)`. It catches
  `system.TimeoutExpired` and returns
  `(TIMED_OUT, GH_TIMED_OUT.format(limit=limit_s))`, where
  `GH_TIMED_OUT = "gh timed out after {limit:.0f}s"`.
- `Prs` Protocol gains:
  ```python
  def wait_checks(self, number: int, limit_s: float) -> bool:
      """Wait for the PR's checks to finish; False when ``limit_s`` ran out."""
  def checks(self, number: int) -> list[Check]:
      """The PR's checks now ([] when none are reported)."""
  def failed_log(self, link: str) -> str:
      """The failed steps' log of the Actions job at ``link``; "" when there is none."""
  ```
- `NoPrs`: all three raise `UpstreamError(self.why)`.
- `GhPrs`:
  - `wait_checks`: `self.run(["gh", "pr", "checks", str(number), "--watch"], limit_s)[0] != TIMED_OUT`.
  - `checks`: `checks_of(self.run(["gh", "pr", "checks", str(number), "--json", CHECK_FIELDS])[1])`
    where `CHECK_FIELDS = "name,state,bucket,link,workflow"`. Ignore the exit
    code: gh exits 1 or 8 for failing or pending checks.
  - `failed_log`: `job = job_of(link)`. Return `""` when there is no job.
    Otherwise run `["gh", "run", "view", "--job", job, "--log-failed"]` and
    return the output on exit 0, `""` otherwise.

## Test checklist

Unit tests run on the fake. `gh` goes through `system.run`, scripted with
`fake.reply(("gh", "pr", "checks", …), Done(...))`, or with `Hang()` for a
timeout. Boundary-runner tests may use `tests/s29_helpers.FakePrs`, which
gains `wait_checks`, `checks` and `failed_log` driven by scripted results.

`ci.py` (pure):
- [ ] `bucket_of`: each known bucket; an unknown string gives `FAIL` (CI5).
- [ ] `checks_of`: a JSON list; "no checks reported on the 'x' branch" gives `[]`; non-JSON raises `UpstreamError`.
- [ ] `verdict_of`: [] → NONE; all skipping → NONE; pass+skipping → GREEN; pass+pending → PENDING; fail+pending → RED; cancel → RED (CI6).
- [ ] `overall`: [] → NONE; GREEN+NONE → NONE; GREEN+PENDING → PENDING; any RED → RED; all GREEN → GREEN (CI7).
- [ ] `failing_lines`: strips the gh prefix and timestamp; keeps pytest `FAILED …`, `ERROR …::`, go `--- FAIL:` and `N failed` lines in order without repeats; at most 20; with no match, the last 10 non-blank lines (CI8).
- [ ] `job_of`: Actions job link → id; other link → None.
- [ ] `green_report`: raises `ValueError` for any non-green result or for []; the green text holds `READY_PHRASE` (CI12).
- [ ] `check_lines`: lists only non-passing checks, with the workflow / name label, the bucket and the link, failing lines indented below.
- [ ] `CiResult`/`Check` round-trip through `asdict` and back (state reload).

`CiWatch` (fake clock):
- [ ] green on the first look: one watch, one read, no sleep.
- [ ] no checks at first, then checks on the 3rd look: sleeps `CI_POLL_S` twice (CI4).
- [ ] no checks for all `CI_LOOKS` looks: returns [] (NONE), bounded.
