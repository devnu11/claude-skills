# s165: a resume after a cut-off story step

Bug fix. `Runtime._resume_story` built `story.interrupted` with its fields out
of order, so every `start --resume` after a cut-off story step raised
`ValueError: '<brief>' is not a valid Cause`. Traces: AC1 → REQ-174, AC2 →
REQ-175. Refines s159's I1–I3 (REQ-161). No new decision, so no ADR;
ADR-0084 to ADR-0087 stand.

## State of the tree at design

The fix is already in this story's worktree. The story's build only adds
the tests that are still missing.

- `agile_team/dispatch.py:1148` reads
  `story.interrupted = Interruption(flying.role, story.id, flying.brief, cause, None)`,
  in `salvage.Interruption`'s field order `role, story, brief, cause, sha`.
  It matches the storyless path (`salvage.py:120`).
- `docs/design/s159.md` I2 names the same order and cites s165.
- `tests/test_s165_resume_story.py` drives `Runtime.recover_stories` with a
  story in flight. It checks the `stopped` step-end, the `interrupted`
  record, the kept session and worktree edits, and the next step's brief,
  worktree and `resume` session.

Do not change `dispatch.py`. If the build finds line 1148 different from the
line above, stop and hand back to the architect.

## Rules

- R1. `story.interrupted` is always built with keyword arguments, or in
  `Interruption`'s field order. `Cause` is the fourth field, never the first.
- R2. The cause on resume is `Cause(state.halt_kind)` when the run recorded a
  halt kind, and `Cause.KILLED` when it didn't (a reboot or a `kill -9`
  leaves none). This is `cli._recover_stories`, unchanged. Every `HaltKind`
  value is a valid `Cause`.
- R3. `_resume_story` leaves `story.step` unchanged, so the next step on the
  story is at the same step and run by the same role (AC2).
- R4. The brief line is `salvage.WORKTREE_KEPT_LINE`
  (`"{role}'s step was cut off ({cause}); its uncommitted edits are still in this worktree"`),
  given through `salvage.offer(story.interrupted)` because `sha` is `None`.

## Changes per module

None in `agile_team/`. Tests only, in `agile-team/runner/tests/test_s165_resume_story.py`
(extend it; keep its existing four tests as they are):

- **AC1 through the CLI path.** A test that a resume goes through
  `cli._recover_stories(runtime, Start("", StartMode.RESUME))` (imports:
  `from agile_team import cli`, `from agile_team.po_tools import Start, StartMode`).
  Set up a story in flight as `cut_off` does, but call `_recover_stories`
  instead of `recover_stories`:
  - with `rt.state.halt_kind` unset: no exception, and
    `story.interrupted.cause is Cause.KILLED`;
  - with `rt.state.halt_kind = HaltKind.CRASH` (`from agile_team.halt import HaltKind`):
    `story.interrupted.cause is Cause.CRASH`.
  Split `cut_off` into a setup helper and the call if that's needed, keeping
  each helper to one job and at most 2 parameters.
- **AC1 in `state.json`.** After `recover_stories` (which saves), load the
  state back with `agile_team.state.load(rt.config.run_dir)`. The loaded story's `interrupted`
  equals `Interruption(ROLE, "s1", BRIEF, cause, None)`, and its `in_flight`
  is `None`.
- **R2: every halt kind is a cause.** One test:
  `{Cause(k) for k in HaltKind} <= set(Cause)`. This is the guard that
  `_recover_stories` can't raise for any halt kind.
- **R3.** After `cut_off`, `story.step == "implement"`.
