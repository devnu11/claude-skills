# s112: An Activity tab, Markdown in every message, and a live panel

A dashboard story. The page (`dashboard/index.html`) does nearly all of it.
Two small extras: the server serves the packaged fixture so `?mock` works
on a served dashboard (needed for AC6), and two fixture texts gain
Markdown. No new dependency, no ADR, no new event kind, snapshot key or
state field. The snapshot contract is unchanged; only two text values in
the fixture change.

Developer: **developer-gui**, alone.

## Rules

### Activity tab (AC1)

- **AT1 Own tab.** `TABS` gains `["activity", "Activity"]` right after
  `["flow", "Flow"]`. A new `<section id="tab-activity" hidden>` holds the
  Activity card that sits in `#tab-flow` today. Move the card's markup
  unchanged: `<h2>Activity</h2>`, `.tl-tools` with `#tl-filter`, and
  `<ol class="timeline" id="timeline">`. Ids stay the same, so the story
  filter (`ui.story`) and its change listener keep working.
- **AT2 Flow is chart only.** `#tab-flow` keeps only the `.card.flow` card,
  with no `.grid-flow` wrapper. Delete the `.grid-flow` CSS rule, and drop
  `.grid-flow` from the `@media (max-width: 1000px)` selector, which
  becomes `.grid-2` alone. Both tabs are full width (the card fills
  `.wrap`).
- **AT3 Renderers.** `renderFlowTab` no longer calls `renderTimeline`.
  `RENDER.activity = renderTimeline`. Live updates are unchanged: `render()`
  runs `RENDER[ui.tab]` on every snapshot, and rows new since the last
  render keep the `new` class (`data.fresh`). `live.queue` (the flow dots)
  stays in `renderFlowTab`.
- **AT4 Height.** `#tab-activity .timeline { max-height: none; }`. The 640
  px cap was there only so it could sit beside the chart. The row cap stays
  at the newest 120 rows.

### Markdown in every message (AC2, AC3)

- **MD1 Every body through `md()`.** A timeline row's `body` is message
  text and renders through `md()`. A row's `meta`, its time, `from`/`to`
  and `what` pill stay plain (`esc`). Replace `MARKDOWN_KINDS` with the
  opposite table, `PLAIN_BODIES`, for the only two kinds whose body is a
  list of names rather than text:
  ```js
  const PLAIN_BODIES = new Set(["gate-fix", "opinion-act"]); // file names; opinion ids
  const bodyHtml = (kind, text) => (PLAIN_BODIES.has(kind) ? esc(text) : md(text));
  ```
  Any kind added to `TIMELINE` later is Markdown unless it is listed here.
  This covers briefs (`step-start`), handoffs and step ends (`step-end`),
  questions and notes (`message`), answers, threads, opinions, gate
  reasons, sprint goals and the rest.
- **MD2 Questions in bodies, not meta.** `story-admin` puts the cancel
  question in its body, under the reason:
  `body: [e.data.reason, e.data.question].filter(Boolean).join("\n\n"), meta: ""`.
  Every other kind's `meta` already holds only plain fields (ids, counts,
  files, rule names), so it stays as it is.
- **MD3 Questions tab.** It already renders `q.text` and the answer text
  through `md()` (open, raised and answered). Keep that. Ids, times, role
  names and the `agile-team answer` command stay plain.
- **MD4 Load state.** The page records whether the library loaded:
  ```js
  const MD = { LOADING: "loading", READY: "ready", FAILED: "failed" };
  let markdownState = MD.LOADING;
  const MD_NOTICE = "Markdown unavailable: showing plain text";
  ```
  `useMarkdown` sets `MD.READY`. `loadMarkdown`'s `catch` sets `MD.FAILED`,
  keeps its `console.warn` with today's text, and calls `render()`.
- **MD5 Visible notice.** When `markdownState === MD.FAILED`,
  `statusPills` adds `<span class="md-notice" role="status">${MD_NOTICE}</span>`
  after the questions pill (before the manager-due pills). The status row
  shows on every tab. Nothing else changes: `md()` still falls back to
  escaped plain text with line breaks kept.

### Live panel (AC4)

- **LP1 Place.** The header's `.head-right` holds the live panel, then
  the theme button. `#meter` leaves `.head-right` (see BM1). Markup (static,
  filled by JS):
  ```html
  <div class="live-panel" id="live-panel" role="button" tabindex="0" data-live-panel>
    <div class="lp-head" id="lp-head"></div>
    <div class="lp-meta" id="lp-meta"></div>
    <div class="lp-msg" id="lp-msg"></div>
  </div>
  ```
- **LP2 Panel state.** The panel shows one of three states, taken in this
  order from a table, first match wins:
  ```js
  const PANEL_STATES = [stepPanel, stagePanel, idlePanel]; // each: (view) => {kind, head, story} | null
  ```
  | kind | when | `head` | `story` |
  |---|---|---|---|
  | `step` | `liveStep(view)` is a step | `▶ {who(step)} · {step.step}{awake}`, with ` · {step.step}` left out when `step.step` is empty | `step.story ?? ""` |
  | `stage` | `openStages(view)` is not empty | `⚙ runner: {stages joined by ", "}` (each row's `stage`) | `""` |
  | `idle` | always | `● Nothing running: {idleWhy(view)}` | `""` |

  `{awake}` is ` · ⏱ {fmt.span(awakeSoFar(view, open))} awake{sleepNote(open)}`
  where `open = openStep(view, step.role)`. It is `""` when there is no
  open step row. Reuse `awakeSoFar`, `sleepNote` and `openStep` (s97). Don't
  write a new clock.
- **LP3 Why idle.** `idleWhy(view)`: if there are open questions,
  `waiting on {ids}`, with the ids of `openQuestions(view)` in order joined
  by `", "` (for example `waiting on m121`). Otherwise
  `view.health.reason || view.run.status`, the same words the smart pill
  uses.
- **LP4 Latest message.** `latestMessage(view, story)` returns
  `{ e, t }`, the newest event (walking `view.events` from the end) whose
  timeline row `t = TIMELINE[e.kind]?.(e, ctx)` exists and has a body that
  isn't blank. When `story` is not empty, only events with
  `e.story === story` count. It returns `null` if none. `ctx` comes from
  `timelineContext(view)`, which is pulled out of `renderTimeline` so both
  build it the same way (DRY). A row builder that throws counts as no row
  (try/catch, as in `timelineRow`).
  The panel asks for `latestMessage(view, state.story)`: in a `step` state,
  the newest message on the running story, and otherwise the newest of all.
- **LP5 Six lines.** `clip(text)` returns `{ text, cut }`. `text` keeps the
  source up to and including its 6th non-blank line (`CLIP_LINES = 6`),
  with the blank lines between them kept so the Markdown structure stays.
  It is then cut to at most `CLIP_CHARS = 600` characters. `cut` is true
  when anything was dropped. The panel renders `md(clip.text)`, followed
  by `<div class="lp-more">…</div>` when `cut`. CSS also caps
  `.lp-msg .md` at six lines' height (`max-height: calc(6 * 1.4em);
  overflow: hidden`), so a few very long wrapped lines can't grow the
  header.
- **LP6 Meta line.** `#lp-meta` gets the message's plain line (as
  `textContent`): `{fmt.time(e.at)} · {short(t.from)}{ → short(t.to) if t.to} · {t.what}{ · e.story if any}`.
  With no message, `#lp-meta` is empty and `#lp-msg` reads
  `No activity yet.`.
- **LP7 Render and tick.** `renderHeader` calls `renderLivePanel(view)`,
  which fills all three parts, sets `#live-panel`'s `dataset.story`, its
  `aria-label` / `title` (`Open the Activity tab for {story}`, or
  `Open the Activity tab` when the story is `""`), and toggles
  the `running` class when the state's kind is `step`. The once-a-second
  `tick()` calls `renderPanelHead(view)`, which rewrites only
  `#lp-head`'s `textContent`, so the awake time moves on without the
  message being redrawn (focus and selection in it survive).
- **LP8 Click opens Activity.** The panel's story to filter by is
  `state.story || msg?.e.story || ""`, stored in `dataset.story`.
  `openActivity(story)` sets `ui.story` to `story` when it is in
  `data.view.stories`, else to `""` (All stories), then calls
  `showTab("activity")`. The document click handler calls it for a click
  inside `[data-live-panel]` that is not on an `<a>` (a link in the
  message opens the link instead). A `keydown` listener does the same for
  `Enter` or `" "` while the panel has focus, calling `preventDefault()`.
- **LP9 Every tab.** The panel is in the header, so it shows on every tab
  and in mock replay. It updates on every snapshot (SSE) through
  `render()`.

### Budget meter (AC4b)

  ```html

    <div class="meter" id="meter"></div>
  ```

### Readable (AC5)

- **RD1 New text.** Every new text style is at least 12 px and uses only
  `--ink` or `--ink-2` on `--surface` (the header's background). It never
  uses `--muted`, which is below 4.5:1 on `--surface`.

  | selector | font-size | color | on |
  |---|---|---|---|
  | `.lp-head` | 13px, weight 600 | `--ink` | `--surface` |
  | `.lp-meta` | 12px | `--ink-2` | `--surface` |
  | `.lp-msg` | 12.5px | `--ink-2` | `--surface` |
  | `.lp-more` | 12.5px | `--ink-2` | `--surface` |
  | `.md-notice` | 12.5px | `--ink-2` | `--surface` |

  Other panel CSS: `.live-panel { width: 440px; max-width: 100%;
  background: var(--surface); border: 1px solid var(--border);
  border-left: 3px solid var(--grid); border-radius: 8px; padding: 6px 10px;
  cursor: pointer; line-height: 1.4; }`, `.live-panel.running {
  border-left-color: var(--accent); }`, `.live-panel:focus-visible {
  outline: 2px solid var(--accent); outline-offset: 2px; }`,
  `.lp-msg .md > * { margin: 0; }`. `.md-notice` also has `border: 1px
  solid var(--warning); border-radius: 999px; padding: 1px 8px;`.
- **RD2 Code in Markdown.** Activity bodies are now Markdown at 12.5 px,
  and `.md code { font-size: .92em }` would render them at 11.5 px. Change
  it to `font-size: max(12px, .92em)`. Code sits on `--surface-2` in the
  parent's colour, and `--ink-2` on `--surface-2` already passes in both
  themes.

### Checked in a real browser (AC6)

- **FX1 Fixture on the server.** `server.py` gains
  `FIXTURE = Path(__file__).parent / "fixtures" / "snapshot.json"` and a
  route `"/fixtures/snapshot.json": _fixture`, where
  `_fixture(handler)` sends `Body("application/json", system.read_bytes(FIXTURE))`.
  It is a plain GET with no token, like `/`. Now `/?mock&at=end` on a served
  dashboard replays the fixture, which lifts the s4 known limit ("`/?mock`
  served by the server gets 404"). The page already fetches
  `fixtures/snapshot.json` relatively in mock mode.
- **FX2 Fixture texts with Markdown.** These change in
  `dashboard/fixtures/snapshot.json` (text values only, no key changes):
  - event `e42` (`step-start`, architect, s3), `data.brief`:
    `"Design streaming export for `report run --stream`.\n\n- **Memory bound:** stay under 50 MB for 1M rows.\n- Keep the `--format csv` flags.\n- Name the temp-file rule in the design."`
  - message `m3` (question, s3), `text`:
    `"s3 keeps failing the memory bound because sorting needs the whole result.\n\n- **Option A:** spill to a temp file (up to 1 GB) when `--sort` is used.\n- **Option B:** refuse `--sort` with `--stream`.\n\nWhich one?"`

  The customer proxy opens `/?mock&at=end`, filters Activity to `s3`, and
  finds both. The Questions tab shows m3 under Waiting on you or Answered,
  depending on the fixture's answers.

## Known limits

- The six lines are source lines, not rendered lines. A long line wraps,
  and the CSS height cap may then cut it with no `…`.
- Markdown comes from `cdn.jsdelivr.net` (s15). If the proxy's browser
  can't reach it, the page shows the MD5 notice and AC6's Markdown check
  can't pass. Report that as an environment problem, not a page fault.
- The panel is `role="button"` and may contain links from the message. A
  link takes the click (LP8). Screen readers may announce the nested link
  oddly.
- The existing `.tl-meta` (11.5 px, `--muted`) and `.timeline time`
  (`--muted`) styles are not new text and are out of scope here.
