# s112: An Activity tab, Markdown in every message, and a live panel

A dashboard story. The page (`dashboard/index.html`) does nearly all of it.
Two small extras: the server serves the packaged fixture so `?mock` works
on a served dashboard (needed for AC6), and two fixture texts gain
Markdown. No new dependency, no ADR, no new event kind, snapshot key or
state field. The snapshot contract is unchanged; only two text values in
the fixture change.

Developer: **developer-gui**, alone.

**Revised after t68** (round 0, redesign). AC4 and AC4b were rewritten to
the approved header mock `.team/run/liaison/header-mock-approved.html`
(state 1: a role running; state 2: the runner between steps). That mock is
the visual spec. The **Header (AC4b)** and **Live panel (AC4)** sections
below replace the earlier LP and BM rules completely. AT, MD and FX rules
are already built and unchanged (MD5 only moves). Code from the first build
that this revision removes is listed under "Removed".

    `fmt.pct`.

    is not above 0 (guards the loop `renderMeter` had). The ticks are
    `checkPcts(view.run.manager_every_pct)`.
  - `budgetTitle(view, spent)`:
    `{fmt.usd(spent)} of {fmt.usd(budget)} spent ({fmt.pct(pct)}). Ticks mark the manager's budget checks at 25%, 50%, 75%.`
    (the percents from `checkPcts`, each with `%`, joined by `", "`).
    With no ticks the second sentence is left out. So the exact cents,
    the budget, the percent, the bar and the ticks with their meaning are
    all still there (AC4b: nothing removed).

### Live panel (AC4)

- **LP1 Place.** In `.head` between `.head-left` and the theme button
  (HD1), so it is on every tab and in mock replay. Fixed width 380 px.
- **LP2 Panel state.** `panelState(view)` returns the first non-null of
  a table:
  ```js
  const PANEL_STATES = [stepPanel, eventPanel, stagePanel, chorePanel, idlePanel];
  // each: (view) => { kind, who, when, line, story } | null
  ```
  | fn | when | kind | `who` (bold, left) | `when` (right) | `line` (2nd line) | `story` |
  |---|---|---|---|---|---|---|
  | `stepPanel` | `liveStep(view)` is a step | `step` | `{short(role)} · {story} · {step}` (blank parts left out, joined by `" · "`) | `{fmt.age(seconds)} · {runLabel}` | `toolLine(view, step)` | `step.story ?? ""` |
  | `eventPanel` | `view.heartbeat` is null and `activeStep(view.events)` is an event (an old runner, or a mock replay) | `step` | as above, with `step` = the story's `step` from `view.stories` | `{fmt.age(clockNow(view) − act.at)} · {runLabel}` | `""` | `act.story ?? ""` |
  | `stagePanel` | `openStages(view)` is not empty; use its last row (the innermost) | `stage` | `⚙ runner · {row.story \|\| "sprint " + view.run.sprint}` | `{row.stage} · {fmt.age(stageAwake(view, row))}` | `runnerResult(view)` | `row.story ?? ""` |
  | `chorePanel` | `beating(view)` and `view.heartbeat.chore` is set | `stage` | `⚙ runner` | `fmt.age(clockNow(view) − chore.since)` | `chore.what` | `""` |
  | `idlePanel` | always | `idle` | `● Nothing running` | `""` | `idleWhy(view)` | `""` |

  `stepPanel` and `eventPanel` both build through
  `runningPanel(view, run)` with `run = { role, story, step, seconds, line }`
  (DRY). For `stepPanel`, `seconds` is `awakeSoFar(view, open)` when
  `open = openStep(view, step.role)` exists, else
  `clockNow(view) − step.started_at`. Mock state 1 reads
  `developer-cli · s112 · implement` | `4 min · first run`; state 2 reads
  `⚙ runner · sprint 40` | `boundary.sync · 45 s`.
- **LP3 Run label.** `runLabel(view, run)`: `↻ restarted` when
  `act = activeStep(view.events)` has the same role and story and
  `restarted(view.events, act)` (the test `pillText` used); else
  `round {n}` when the story's `rounds` in `view.stories` is `n > 0`; else
  `first run`.
- **LP4 Tool line.** `toolLine(view, step)`: the newest open call of the
  role, `(view.heartbeat.calls ?? []).findLast(c => c.role === step.role)`,
  as `{call.label || call.tool} · {fmt.age(now − call.at)}`; else
  `step.tool` as `{step.tool.name} · {fmt.age(now − step.tool.started_at)}`;
  else `no tool running`. `now = clockNow(view)`. Shown in italics (LP8).
- **LP5 Runner result and why idle.**
  - `stageAwake(view, row)`: the awake seconds of an open stage row,
    pulled out of `stageRunningLine` (which then calls it):
    `max(0, clockNow(view) − row.started_at − max(0, finiteS(hb.slept) − finiteS(row.started_slept)))`.
  - `runnerResult(view)`: the newest event with `e.role === "runner"`
    that has a timeline row, as `{t.what} · {firstLine(t.body)}` (the
    second part left out when blank), else `""`. For a boundary event that
    reads `sprint 10 end · sync: pass · sprint 10 is on the review stack`.
  - `firstLine(text)`: the first non-blank line of `String(text ?? "")`,
    trimmed, or `""`.
  - `idleWhy(view)` (unchanged): `waiting on {open question ids}` when
    there are open questions, else `view.health.reason || view.run.status`.
- **LP6 Latest message, 3 lines.** Only in the `step` state. The message
  is `latestMessage(view, state.story)` (unchanged rule: the newest event
  on that story whose timeline row has a non-blank body; a throwing row
  builder counts as no row). Both `latestMessage` and `runnerResult` walk
  back through `newestRow(view, wanted)`, where `wanted(e, t)` decides
  and the walk is a backwards index loop with no array copy (review n1).
  `#lp-msg` gets `bodyHtml(e.kind, clip(t.body))`, or is left empty when
  there is no message.
  - `clip(text)` now returns a **string**: the source up to and including
    its `CLIP_LINES = 4`th non-blank line (blank lines between them kept),
    then at most `CLIP_CHARS = 400` characters. It only bounds the work.
    It keeps one line more than the clamp, so a cut message always
    overflows and shows the ellipsis.
  - CSS clamps `#lp-msg` to `CLAMP_LINES = 3` rendered lines with an
    ellipsis (LP8). The full text is in the Activity tab. `.lp-more` and
    the six-line rule go.
- **LP7 Render, tick and hover.**
  - `fillPanelText(state)`: sets `textContent` of `#lp-who`, `#lp-when`,
    `#lp-line` from the state, and toggles `#lp-line`'s `tool` class when
    `state.kind === "step"`.
  - `renderLivePanel(view)`: `state = panelState(view)`;
    `fillPanelText(state)`; `#lp-msg.hidden = state.kind !== "step"`, and
    its `innerHTML` is the LP6 message when shown, else `""`;
    `dataset.story = state.story`; `aria-label` = `panelLabel(story)`
    (unchanged); `className = "live-panel h-" + healthLevel(view)`. No
    `title` (the hover tip is used instead).
  - `renderPanelText(view)` = `fillPanelText(panelState(view))`.
    `tick()` calls `safely(renderPanelText, data.view)` instead of
    `renderStatusRow` and `renderPanelHead`, so the clocks move without
    the message being redrawn. (The state row no longer has a clock.)
  - Hover: the existing `mouseover`/`mouseout` listeners on
    `[data-live-details]` now find the panel. `mouseover` shows the tip
    only when `pillDetails(view, now)` is not empty. The click toggle of
    `ui.details` goes.
  - `pillDetails(view, now)` keeps its lines and, for a step, gains a
    first line `{rate}/min {sparkline} · last turn {fmt.age(now − (step.last_turn_at ?? step.started_at))} ago`
    (rate and sparkline as `pillText` computed them). To stay under 8
    lines, the step lines move into `stepDetails(view, now)`, which reads
    `liveStep(view)` and returns `[]` when there is none; `pillDetails`
    is `stepDetails(view, now)` plus the `health:` line for amber or red.
- **LP8 Panel CSS.**
  ```css
  .live-panel { width: 380px; max-width: 100%; box-sizing: border-box; background: var(--surface); border: 1px solid var(--border); border-radius: 8px; padding: 5px 9px; font-size: 12px; line-height: 1.4; cursor: pointer; }
  .live-panel.h-green { border-color: var(--good); }
  .live-panel.h-amber { border-color: var(--warning); }
  .live-panel.h-red { border-color: var(--critical); }

  .lp-head { display: flex; justify-content: space-between; gap: 8px; }
  .lp-who { min-width: 0; font-size: 12px; font-weight: 600; color: var(--ink); white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
  .lp-when { flex: none; font-size: 12px; color: var(--ink-2); white-space: nowrap; }
  .lp-line { font-size: 12px; color: var(--ink-2); white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
  .lp-line.tool { font-style: italic; }
  .lp-msg { margin-top: 3px; padding-top: 3px; border-top: 1px solid var(--border); font-size: 12px; color: var(--ink); display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: 3; line-clamp: 3; overflow: hidden; }
  .lp-msg[hidden] { display: none; }
  .lp-msg .md > *, .lp-msg .md li { margin: 0; }
  .lp-msg .md ul, .lp-msg .md ol { padding-left: 16px; }
  ```
  Pitfall: `display: -webkit-box` beats the `hidden` attribute, so the
  `[hidden]` rule is required.
- **LP9 Click opens Activity.** `openActivity(story)` and the click
  handler are unchanged (`dataset.story` is now `state.story`). The
  `keydown` listener on `#live-panel` returns early when
  `ev.target.closest("a")`, so Enter on a link in the message opens the

## Known limits

- `-webkit-line-clamp` on Markdown with a list clamps rendered lines; a
  very long single word may still be cut without "…" in older browsers.
- Markdown comes from `cdn.jsdelivr.net` (s15). If the browser can't reach
  it, the MD5 notice shows and AC6's Markdown check can't pass: an
  environment problem, not a page fault.
- The panel is `role="button"` and may contain links; screen readers may
  announce the nested link oddly.
- `tick()` redraws only the panel's text lines. If the state's kind
  changes between snapshots (for example, the heartbeat goes stale), the
  message part and border catch up on the next snapshot (review n3).
- In a replay the heartbeat is `null`, so there is no tool line and no
  runner state.
