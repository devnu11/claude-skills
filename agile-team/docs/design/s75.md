# s75: DevOps scopes its test runs to what proves its change

Delivery: cli. Prompt and docs only; no runtime change.
Developer: `developer-cli` (edits `agile_team/roles/devops.md`).
Unit tester: one prompt test in `tests/test_roles.py`.

## Context

s69 (S8) denies the full suite and coverage to every role's Bash except
`devops`, because onboarding asks DevOps to run every toolchain command and
record the coverage baseline. The human (t4 to m63) keeps that exemption but
wants DevOps to scope its runs: normally one named test proves its change,
and the runner's gate produces suite and coverage evidence.

`_shared.md` already tells every role "Never run the full suite or coverage
… a full `pytest` or a `--cov` run is denied". For DevOps the second half is
false (it is exempt), so the DevOps file must say what it does instead.

## Rules

| id | rule |
|---|---|
| D1 | `devops.md` gets a `## Test runs` section (text below) between `## Deliverables` and `## Onboarding sprint`. |
| D2 | The rule: run only what proves the change, normally one named test; never the full suite or a coverage run; the runner's gate does those. |
| D3 | The exemption exists only so the onboarding sprint can record its baseline. `## Onboarding sprint` says it is the one step that runs the full suite and the coverage command. |
| D4 | In a boundary fix, DevOps runs the failing tests the brief names; the runner re-runs the full checks itself. |
| D5 | A change to the test or coverage command itself is proven by the runner's next check; DevOps says so in its summary instead of running the suite. |
| D6 | No code change: `suite_check.SUITE_RULES` keeps `"devops"` in the `FULL` and `COVERAGE` allowed sets (s69 S8 stands). |
| D7 | Docs move with the rule: `reference/protocol.md` (the s69 "Every role but DevOps" bullet), `SKILL.md` (the "Only the runner runs the full suite" rule) and `docs/customer/routing.md` ("Who runs the tests"). Done in this design step. |

## Changes per module

### `agile-team/runner/agile_team/roles/devops.md`

Insert after the `## Deliverables` list (after the "Tools the Manager…"
bullet), before `## Onboarding sprint`, exactly:

```markdown
## Test runs

Run only what proves your change, normally one named test
(`pytest -q --no-header tests/test_x.py::test_y`). Never run the full suite or
a coverage run; the runner's gate does those and puts the results in briefs.
You are exempt from the runner's full-suite and coverage deny only so the
onboarding sprint can record its baseline. In a boundary fix, run the failing
tests the brief names; the runner then runs the full checks again. A change to
the test or coverage command itself is proven by the runner's next check: say
in your summary that it waits on that check.
```

In `## Onboarding sprint`, append one sentence to the paragraph, so it reads:

```markdown
Run every toolchain command, fix the broken ones, and write
`.team/baseline.json` as `{"coverage": <total %>, "lint_warnings": <count>}`
so the gates judge new work, not old debt. This is the one step where you run
the full suite and the coverage command.
```

Nothing else in the file changes. The line wrap may differ; the test
normalises whitespace.
