# s105: A dashboard presentation starts in an empty workspace

Story: `.team/stories/s105.md`. No ADR (extends the s26 presentation/sandbox
pattern with one optional data field; no dependency).
Developer: **developer-cli**. No `.agile-team.toml` edit (human, m100).

## Why it fails today

The `dashboard` delivery's start command is
`agile-team --repo {sandbox}/presentation/workspace dashboard …`. `cli._dashboard_server`
calls `config.load(workspace)`, which raises
`.agile-team.toml not found in …; run agile-team init` unless the
integration-tester wrote one. The gate then bounces with only the log tail.

The fix is data, not a branch on the delivery's name. The runner ships a
**packaged seed directory** (`agile_team/dashboard/seed/`) and a table that
maps a delivery kind to its default seed: `web` → the packaged seed. The
runner copies the seed's files into the presentation workspace where they are
missing. A delivery may set `seed` to use another directory, or `seed = ""`
to turn seeding off. Today's `.agile-team.toml` works unchanged.

## Rules

- **S1. Seed is data, with a packaged default.** `Delivery` gains an optional
  `seed: str | None = None`. Field order is not part of the contract: `seed`
  sits just before `probe`, so `probe` stays last (an existing test pins
  that). The seed directory `seeds.seed_dir(repo, delivery)` resolves as:
  | `delivery` | `delivery.seed` | seed directory |
  |---|---|---|
  | `None` | – | none |
  | any | `None` (key absent) | `seeds.DEFAULT_SEEDS.get(delivery.kind)`: `PACKAGED_SEED` for `web`, none for other kinds |
  | any | `""` | none (seeding off) |
  | any | `"a/b"` | `repo / "a/b"` (an override) |

  The seed files are the regular files directly in that directory (no
  recursion; subdirectories are skipped), read as UTF-8 text.
- **S2. Missing only.** A seed file is written to `<workspace>/<name>` only
  when nothing exists at that path. An existing file (the tester's own config)
  is never overwritten or touched.
- **S3. Two plant points.** (a) `presentation.lay_out` plants into the
  story's source workspace `.team/run/presentation/<story>/workspace/`, so the
  tester's own check sees the same config the Proxy gets. (b)
  `sandbox.Preparer.prepare` plants into the sandbox copy
  `<sandbox>/presentation/workspace/` after the copy and before the start
  command, also when there is no presentation to copy. This covers a tester
  who deleted the seed, and presentations laid out before s105.
- **S4. Seeded files are not content.** `presentation.missing` still reports
  a workspace as missing or empty when it holds only `.git` and seed-named
  files. Seeding must not satisfy the e2e gate's completeness check.
- **S5. The packaged seed.**
  `agile-team/runner/agile_team/dashboard/seed/.agile-team.toml` holds exactly:
  ```toml
  # Seeded by the runner into a dashboard presentation's workspace (s105).
  # The fixed token lets the Customer Proxy use the dashboard's writes (t31).
  [dashboard]
  token = "presentation"
  ```
  "Minimal valid" means `config.load` reads it and `agile-team dashboard`
  serves from it. It need not pass `agile-team check` (the dashboard never
  validates). It is located through the package, never through the repo:
  `PACKAGED_SEED = Path(str(resources.files("agile_team") / "dashboard" / "seed"))`.
- **S6. Checks are a table.** `seeds.CHECKS: dict[str, Check]` maps a seed
  file name to a function `(path) -> str | None` that says why the file in the
  workspace is broken. The only row is `config.CONFIG_NAME → config_problem`.
  A file name with no row is not checked.
- **S7. A failed start names the file and the fix (AC3).** When a `web`
  delivery does not come up (`NotUp`), the reason starts with one line per
  seed problem, then gives the start failure text as before (exit code/wait and
  the log tail). Problems:
  - seed directory set but not a directory → `SEED_GONE` (in practice only
    from an override; the packaged seed ships with the package);
  - a seed-named file in the workspace that its check calls broken →
    `BROKEN`.
  With no problems the reason is unchanged.
- **S8. Exact texts** (in `seeds.py`, unchanged from round 0):
  ```python
  SEED_GONE = (
      "seed directory {source} is missing from the repo; restore it or remove "
      "`seed` from the delivery in .agile-team.toml"
  )
  BROKEN = (
      "workspace/{name} is broken: {error}. Fix it in the presentation's "
      "workspace/, or delete it so the runner seeds a working one"
  )
  ```
  The gate's reason reads e.g.
  `story s7 presentation is not up: workspace/.agile-team.toml is broken: .agile-team.toml: Expected '=' … . Fix it …\ndelivery 'dashboard' did not start: …`.
- **S9. Trial and Proxy share one path.** Both the e2e liveness `Trial` and
  the acceptance step go through `Preparer.prepare`, so both get S3(b) and S7.

## Changes per module

### `agile_team/config.py`

`Delivery` gains one field, placed **between `e2e` and `probe`** (`probe`
stays last):

```python
    seed: str | None = None
```

Docstring line: ``seed``: repo-relative directory whose files the runner
plants in the presentation workspace where missing; absent = the kind's
default (``seeds.DEFAULT_SEEDS``), ``""`` = none (s105). `_delivery` already
passes declared keys through, so no other change. TOML has no null, so `None`
only ever means "key absent".

### `agile_team/seeds.py` (I/O only through `system`)

```python
"""Seed files a delivery's presentation workspace needs; the runner plants the missing ones (s105)."""

from __future__ import annotations
from collections.abc import Callable
from dataclasses import dataclass
from importlib import resources
from pathlib import Path

from . import config, system
from .config import Delivery

SEED_GONE = ...   # S8
BROKEN = ...      # S8
Check = Callable[[Path], str | None]
PACKAGED_SEED: Path = Path(str(resources.files("agile_team") / "dashboard" / "seed"))
DEFAULT_SEEDS: dict[str, Path] = {"web": PACKAGED_SEED}


def config_problem(path: Path) -> str | None: ...   # unchanged


CHECKS: dict[str, Check] = {config.CONFIG_NAME: config_problem}


def seed_dir(repo: Path, delivery: Delivery | None) -> Path | None:
    """The delivery's seed directory per S1: its override, its kind's default, or ``None``."""
```

`seed_dir` body, per the S1 table:
`None` delivery → `None`; `delivery.seed is None` →
`DEFAULT_SEEDS.get(delivery.kind)`; `""` → `None`; else `repo / delivery.seed`.
Pitfall kept: `repo / ""` is the repo itself, so `""` must return `None`
before the join.

`resources.files("agile_team")` (not `"agile_team.dashboard"`) avoids
importing the dashboard package. The runner runs from an unpacked package
(`uv run`), so the `Traversable` is a real path and `Path(str(...))` is safe.
The tests' `FakeSystem` serves it once its `PACKAGE_DATA` lists
`"dashboard/seed/.agile-team.toml"` (a literal name: do not rely on `*`
matching a dotfile).

`Seeds` (`names`, `plant`, `problems`, `_plant_one`, `_problem`) is
unchanged from round 0.

- [ ] `Delivery`'s last field is still `probe` (existing test).
- [ ] `seed_dir`: `None` delivery → None; web, no key → `seeds.PACKAGED_SEED`; package, no key → None; `seed=""` (web) → None; `seed="a/b"` → `repo/"a/b"`.
- [ ] `DEFAULT_SEEDS == {"web": PACKAGED_SEED}` and `PACKAGED_SEED == Path(agile_team.__file__).parent / "dashboard" / "seed"`.
- [ ] `Seeds.names`: None source → []; missing dir → []; direct files sorted; a subdirectory is skipped; `Seeds(PACKAGED_SEED, ws).names() == [".agile-team.toml"]` (under `FakeSystem`).
- [ ] `plant`: writes a missing file with the seed's text and creates the workspace; leaves an existing file byte-for-byte (`token = "mine"` stays); a directory at the name is left alone; None source writes nothing and does not create the workspace.
- [ ] `problems`: seed set but missing → `[SEED_GONE…]` naming the path; unparsable `.agile-team.toml` → one `BROKEN` line starting `workspace/.agile-team.toml is broken:`; `[dashboard] token = 5` → `BROKEN` carrying `DASHBOARD_TOKEN`; good config → []; broken file with no `CHECKS` row → [].

## Known limits

- Seeds are flat text files. Binary or nested seeds are out of scope.
- Only `.agile-team.toml` is checked for "broken". Another seed file is only
  planted.
- Every `web` delivery without a `seed` key gets the packaged
  `.agile-team.toml`, including another repo's web product that is not an
  agile-team dashboard. The file is harmless there (nothing reads it, and S4
  keeps it from counting as content); `seed = ""` turns it off.
- A presentation laid out before s105 gets the seed in its source workspace
  at the next `lay_out`, and in the sandbox at every prepare.
