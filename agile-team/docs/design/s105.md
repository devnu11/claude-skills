# s105: A dashboard presentation starts in an empty workspace

Story: `.team/stories/s105.md`. No ADR (extends the s26 presentation/sandbox
pattern with one data field; no dependency).
Developer: **developer-cli**. DevOps: one config line (see "Who does what").

## Why it fails today

The `dashboard` delivery's start command is
`agile-team --repo {sandbox}/presentation/workspace dashboard …`. `cli._dashboard_server`
calls `config.load(workspace)`, which raises
`.agile-team.toml not found in …; run agile-team init` unless the
integration-tester wrote one. The gate then bounces with only the log tail.

The runner is generic: other repos' products are not agile-team dashboards.
So the fix is data, not a branch on the delivery's name: a delivery may name a
**seed directory** in the repo. The runner copies its files into the
presentation workspace where they are missing. This repo's `dashboard`
delivery seeds a minimal `.agile-team.toml`.

## Rules

- **S1. Seed is data.** `[[delivery]]` gains `seed = "<repo-relative dir>"`
  (default `""`: no seeds). The seed files are the regular files directly in
  that directory (no recursion; subdirectories are skipped), as UTF-8 text.
- **S2. Missing only.** A seed file is written to `<workspace>/<name>` only
  when nothing exists at that path. An existing file (the tester's own config)
  is never overwritten or touched.
- **S3. Two plant points.** (a) `presentation.lay_out` plants into the
  story's source workspace `.team/run/presentation/<story>/workspace/`, so the
  tester's own check sees the same config the Proxy gets. (b)
  `sandbox.Preparer.prepare` plants into the sandbox copy
  `<sandbox>/presentation/workspace/` after the copy and before the start
  command, also when there is no presentation to copy. This covers a tester
  who deleted the seed and presentations laid out before s105.
- **S4. Seeded files are not content.** `presentation.missing` still reports
  a workspace as missing or empty when it holds only `.git` and seed-named
  files. Seeding must not satisfy the e2e gate's completeness check.
- **S5. This repo's seed.**
  `agile-team/runner/agile_team/dashboard/seed/.agile-team.toml` holds exactly:
  ```toml
  # Seeded by the runner into a dashboard presentation's workspace (s105).
  # The fixed token lets the Customer Proxy use the dashboard's writes (t31).
  [dashboard]
  token = "presentation"
  ```
  "Minimal valid" means `config.load` reads it and `agile-team dashboard`
  serves from it. It need not pass `agile-team check` (the dashboard never
  validates).
- **S6. Checks are a table.** `seeds.CHECKS: dict[str, Check]` maps a seed
  file name to a function `(path) -> str | None` that says why the file in the
  workspace is broken. The only row is `config.CONFIG_NAME → config_problem`.
  A file name with no row is not checked.
- **S7. A failed start names the file and the fix (AC3).** When a `web`
  delivery does not come up (`NotUp`), the reason starts with one line per
  seed problem, then gives the start failure text as before (exit code/wait and
  the log tail). Problems:
  - seed directory configured but not a directory in the repo →
    `SEED_GONE`;
  - a seed-named file in the workspace that its check calls broken →
    `BROKEN`.
  With no problems the reason is unchanged.
- **S8. Exact texts** (in `seeds.py`):
  ```python
  SEED_GONE = (
      "seed directory {source} is missing from the repo; restore it or remove "
      "`seed` from the delivery in .agile-team.toml"
  )
  BROKEN = (
      "workspace/{name} is broken: {error}. Fix it in the presentation's "
      "workspace/, or delete it so the runner seeds a working one"
  )
  ```
  The gate's reason reads e.g.
  `story s7 presentation is not up: workspace/.agile-team.toml is broken: .agile-team.toml: Expected '=' … . Fix it …\ndelivery 'dashboard' did not start: …`.
- **S9. Trial and Proxy share one path.** Both the e2e liveness `Trial` and
  the acceptance step go through `Preparer.prepare`, so both get S3(b) and S7.

### `agile_team/seeds.py` (new; I/O only through `system`)

```python
"""Seed files a delivery's presentation workspace needs; the runner plants the missing ones (s105)."""

from __future__ import annotations
from collections.abc import Callable
from dataclasses import dataclass
from pathlib import Path

from . import config, system
from .config import Delivery

SEED_GONE = ...   # S8
BROKEN = ...      # S8
Check = Callable[[Path], str | None]


def config_problem(path: Path) -> str | None:
    """Why ``path`` (an ``.agile-team.toml``) does not load, or ``None`` when it does."""
    # config.load(path.parent); catch config.ConfigError, TypeError, AttributeError,
    # ValueError (a mistyped table raises the last three) and return str(exc).


CHECKS: dict[str, Check] = {config.CONFIG_NAME: config_problem}


def seed_dir(repo: Path, delivery: Delivery | None) -> Path | None:
    """``repo / delivery.seed``, or ``None`` when there is no delivery or it names no seed."""


@dataclass(frozen=True)
class Seeds:
    """One delivery's seed directory and the workspace it seeds."""

    source: Path | None
    workspace: Path

    def names(self) -> list[str]:
        """Names of the regular files directly in ``source``, sorted; [] if it is None or not a dir."""

    def plant(self) -> None:
        """Write each seed file missing from ``workspace`` (S2); create ``workspace`` only if one is."""

    def problems(self) -> list[str]:
        """``SEED_GONE`` when ``source`` is set but not a dir; else a ``BROKEN`` line per failing check."""
```

Pitfall: `seed_dir` must return `None` for `seed == ""`. `repo / ""` is the
repo itself, and `names()` would then list the repo's files.

`plant` reads with `system.read_text` and writes with `system.write_text`. It
checks the target with `system.exists`, not `is_file`, so a directory at the
name also counts as "there" and is left alone. `_problem(name)` is a private
helper: `CHECKS.get(name)`, run on `workspace / name` when the path exists,
formatted with `BROKEN`.

## Test checklist

Unit (`unit-tester`; use `tmp_path` repos and fake configs, never the real repo config):

- [ ] `config`: a `[[delivery]]` with `seed = "x"` loads as `Delivery.seed == "x"`; default `""`.
- [ ] `seed_dir`: `None` delivery → None; `seed=""` → None; `seed="a/b"` → `repo/"a/b"`.
- [ ] `Seeds.names`: None source → []; missing dir → []; direct files sorted; a subdirectory is skipped.
- [ ] `plant`: writes a missing file with the seed's text and creates the workspace; leaves an existing file byte-for-byte (a tester config with `token = "mine"` stays); a directory at the name is left alone; None source writes nothing and does not create the workspace.
- [ ] `problems`: seed set but missing → `[SEED_GONE…]` naming the path; unparsable `.agile-team.toml` → one `BROKEN` line starting `workspace/.agile-team.toml is broken:` with the parse error; `[dashboard] token = 5` → `BROKEN` carrying `DASHBOARD_TOKEN`; a good config → []; a broken file with no `CHECKS` row → [].
- [ ] The shipped seed (`agile_team/dashboard/seed/.agile-team.toml`, located from the package path): `config_problem` → None, and `config.load(...).dashboard.token == "presentation"`.
- [ ] `sandbox.Preparer.prepare` with a seeded delivery and no presentation: the sandbox's `presentation/workspace/.agile-team.toml` exists before the (fake) runner runs. Assert inside the fake runner.
- [ ] `prepare` with a presentation whose workspace has its own config: the copy keeps it.
- [ ] `NotUp` reason with a broken seeded config: the `BROKEN` line comes first, then `did not start: … Last output:`; without seeds the reason equals today's text.
- [ ] `presentation.lay_out` plants the seed in the source workspace for a delivery with `seed`, and plants nothing for one without.
- [ ] `presentation.missing`: a workspace holding only `.git` and the seeded config → the "missing or empty" reason; plus one other file → None.
- [ ] `integration-tester.md` names the seeded config and holds the worked example (a `"the runner seeds the config"` substring assert is enough).

E2E (`integration-tester`, `tests/e2e/test_presentation_seed.py`, after DevOps's line):

- [ ] AC1: load the repo's `dashboard` delivery from the real `.agile-team.toml`. Build a scratch `Config(repo=tmp_path)`; never use the real repo as `Config.repo`, because `prepare` wipes `<repo>/.team/run/customer/dashboard`, which a live run's Proxy may be using. Then `dataclasses.replace` the delivery: `url` on a free loopback port, `prepare` with `{repo}` replaced by the real repo's absolute path, and `seed` made absolute (`str(real_repo / delivery.seed)`; `tmp_path / "/abs"` is `/abs`). Assert `delivery.seed` is non-empty first, which pins DevOps's line. Then: an empty presentation workspace plus `Preparer().prepare` → `/api/snapshot` answers 200; `prepared.stop()` returns None.
- [ ] AC1: a workspace with its own `.agile-team.toml` (`token = "mine"`) → after prepare the file is unchanged and the snapshot still answers 200.
- [ ] AC3: a workspace config `"[dashboard\n"` → `Trial.liveness` (or `prepare`) raises/returns `NotUp` whose text contains `workspace/.agile-team.toml is broken` and `delete it so the runner seeds`.

## Known limits

- Seeds are flat text files. Binary or nested seeds are out of scope.
- Only `.agile-team.toml` is checked for "broken". Another seed file is only
  planted.
- A presentation laid out before s105 gets the seed in its source workspace
  at the next `lay_out` (the next e2e round), and in the sandbox at every
  prepare.
