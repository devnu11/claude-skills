# s142: Every role reads the repo's own CLAUDE.md

**ADR:** ADR-0073 (`.team/adr/0073-roles-read-the-repo-instructions-as-text.md`).
**Requirements:** REQ-056 (AC1, AC4), REQ-057 (AC2, AC4), REQ-058 (AC3),
REQ-059 (AC5).
**Developer:** developer-cli. **Unit tests:** `tests/test_s142_repo_instructions.py`.

The roles run with `setting_sources=[]` (ADR-003), so Claude Code loads no
`CLAUDE.md` for them. A rule the human writes in the repo's `.claude/CLAUDE.md`
never reaches the team, so the charter has to repeat it. After this story the
runner reads that file's **text** itself and puts it in every role's system
prompt (the PO's too: `po_tools.plan_for` goes through the same
`Runtime.finish` → `RoleBook.system_prompt`).

## Rules

1. **Section and order.** `RoleBook.system_prompt` builds, in this order:
   `_shared` (+ addenda) → role body (chain + addenda) → `## Repo instructions`
   → `## Repo charter` → `## Your file scope`. "Repo instructions" holds the
   text of `<repo>/.claude/CLAUDE.md` after imports are handled (rule 3).
2. **Missing adds nothing.** When `<repo>/.claude/CLAUDE.md` is not a file,
   is only whitespace, or resolves (through a symlink) to a path outside the
   repo, the section is left out entirely, as `_section` already does for
   empty text. Only `<repo>/.claude/CLAUDE.md` is read. A root `CLAUDE.md`,
   `CLAUDE.local.md`, `.claude/rules/` and parent directories are not.
3. **Imports.** An import is `@` followed by a non-space run (`@<path>`), at
   the start of a line or after whitespace. So `a@b.com` is not an import.
   Text inside backtick code (inline `` `…` `` or a fenced ```` ``` ```` block)
   is never treated as an import. For each import, in this order:
   | The path | What replaces `@<path>` |
   |---|---|
   | starts with `~` | `(left out: @<path> points outside the repo)`. `~` is **never** expanded and nothing under home is touched |
   | `system.resolve(<importing file's dir> / <path>)` is not inside the resolved repo (an absolute path elsewhere, `../..` out of the repo, a symlink out of it) | the same note |
   | inside the repo but not a file (`@someone`, a directory, `docs/x.md.` with a trailing dot) | left as it is, unchanged text |
   | a file already inlined in this prompt (a repeat or a cycle) | `(left out: @<path> is already included above)` |
   | otherwise | that file's text, stripped, with its own imports handled by these same rules (relative to *its* directory) |
   "Inlined once" means once per prompt: the file set starts with
   `.claude/CLAUDE.md` itself, so an import of it is also a repeat. There is
   no depth limit, because the once-rule ends every chain.
4. **Text only (AC2).** `dispatch` keeps `setting_sources=[]`. No
   `.claude/settings.json`, hooks, permissions, MCP config or output styles
   reach a role. The runner never reads `~/.claude/CLAUDE.md`. Neither
   `system.home()` nor `system.expand_user()` is called on this path.
5. **Filesystem through `system`.** Every read and check goes through
   `system.is_file`, `system.read_text` and `system.resolve`, so the in-memory
   fake world used by the unit tests serves them.

## Changes by module

### `agile_team/instructions.py` (new)

Module docstring: `"""The repo's own Claude instructions (``.claude/CLAUDE.md``) as prompt text (s142, ADR-0073)."""`

```python
INSTRUCTIONS = Path(".claude/CLAUDE.md")
OUTSIDE = "(left out: @{path} points outside the repo)"
REPEATED = "(left out: @{path} is already included above)"
# group "code": a backtick run and its text up to the same run; group "path": an import
_IMPORT = re.compile(r"(?P<code>(`+).*?\2)|(?<!\S)@(?P<path>\S+)", re.DOTALL)


def repo_instructions(repo: Path) -> str:
    """``<repo>/.claude/CLAUDE.md`` with in-repo imports inlined once; "" when missing or outside."""


@dataclass
class Inliner:
    """Inlines one repo's ``@path`` imports, each file at most once."""

    root: Path                                   # the resolved repo
    seen: set[Path] = field(default_factory=set)

    def file(self, path: Path) -> str:
        """``path``'s text (resolved, inside ``root``) with its imports replaced; marks it seen."""

    def _replace(self, match: re.Match[str], base: Path) -> str:
        """A code match unchanged; an import through ``_import``."""

    def _import(self, path: str, base: Path) -> str:
        """What replaces ``@path`` imported from directory ``base`` (rule 3's table)."""


def _target(path: str, base: Path) -> Path | None:
    """The resolved import target, or None for a ``~`` path (never expanded)."""
```

- `repo_instructions`: `root = system.resolve(repo)`,
  `path = system.resolve(repo / INSTRUCTIONS)`. Return `""` unless
  `system.is_file(path) and path.is_relative_to(root)`. Otherwise return
  `Inliner(root).file(path)`.
- `Inliner.file`: add `path` to `seen`, read it, and
  `_IMPORT.sub(lambda m: self._replace(m, path.parent), text)`.
- `_import`: `target = _target(path, base)`. If it is `None` or not
  `target.is_relative_to(self.root)`, return `OUTSIDE`. If it is not
  `system.is_file(target)`, return `f"@{path}"`. If it is in `seen`, return
  `REPEATED`. Otherwise return `self.file(target).strip()`.
- `_target`: `None` if `path.startswith("~")`, else
  `system.resolve(base / path)`. An absolute `path` makes `base / path`
  that absolute path (pathlib), so it needs no separate branch.

The `_IMPORT` comment is the one in-function pitfall worth stating: the code
alternative must come first, so that an `@` inside backticks is consumed as
code.

### `.team/CLAUDE.md`: the liaison edits it, not the team (AC3)

No role's file scope holds `.team/CLAUDE.md`: the architect's is the docs,
the developers' is `{source}`. As with `.claude/CLAUDE.md` in s56, the
liaison makes the edit at a stop, for the human to review. The architect's
handoff carries it as an open question. What goes, because
`.claude/CLAUDE.md` now reaches every role and says it already:

| Charter bullet | `.claude/CLAUDE.md` section that covers it |
|---|---|
| Process is enforced in code, not only in prompts | "Process lives in code" |
| Prefer tables and data over branching (`cli.COMMANDS`, …) | "Process lives in code" |
| Docs move with behaviour (`SKILL.md`, `protocol.md`, README row) | "Docs move with behaviour" |
| ruff check and ruff format clean; the 95% coverage floor | "Python runners" |

What stays, because it is about the team: what the repo is and that the
runner runs *you*; run tools from the repo root through the configured
commands, never `cd`; functions of one job, ≤ 8 lines, ≤ 2 parameters, no
boolean flags; docstrings; coverage is currently 100%; no new runtime
dependency without an ADR, and the dashboard is stdlib only; tests point
`AGILE_TEAM_HOME` at a scratch dir; the domain vocabulary; "Do not touch".
The new charter text (whole file):

```markdown
# Team charter

Every role reads this file, right after the repo instructions
(`.claude/CLAUDE.md`, shown above it as "Repo instructions"). Those rules
apply to the team as written and are not repeated here. This file holds only
what is about the team. Keep it short.

## What this repo is

`claude-skills` holds Claude Code skills. You are working on the
`agile-team` skill: its runner (`agile-team/runner/`, Python, uv) is the
program that runs *you*. Read `agile-team/reference/protocol.md` for how it
works today.

## House rules

- Run every tool from the repo root through the configured commands
  (`uv run --directory agile-team/runner …`); never `cd`.
- Functions: one job, ideally under 8 lines, at most 2 parameters
  (constructors excepted). No boolean parameters or flags; use an enum.
- Docstrings on public functions, brief. Comments inside functions only for
  non-obvious pitfalls.
- Coverage is currently 100%; keep it there.
- No new runtime dependencies without an ADR. The dashboard uses the stdlib
  only (http.server, SSE).
- Docs move in the same story as the code.
- The test suite points `AGILE_TEAM_HOME` at a scratch dir.

## Domain vocabulary

- story: a unit of work in `.team/stories/<id>.md`; AC = acceptance criterion.
- requirement: `agile-team/docs/requirements/REQ-NNN.md`.
- liaison: the interactive Claude session relaying to the human.
- snapshot: the JSON the dashboard renders; its contract is
  `agile-team/runner/agile_team/dashboard/fixtures/snapshot.json`.

## Do not touch

- `install.sh`, `tests/install_test.sh`, `example-skill/`.
- `.claude/` (the human's repo instructions; you read them, never write them).
```

For acceptance, the Proxy checks the charter against this text. If it has not
changed yet, the PO asks the liaison for it. That is not a bounce to a
developer.

## Test checklist (`tests/test_s142_repo_instructions.py`)

Build the repo in the fake world (`repo` fixture). Build the book with
`RoleBook(dict(BUILTIN), {}, {}, repo)`, as `test_roles.book` does, or with
`RoleBook.for_repo`.

- [ ] Order (AC1/AC4): with `.claude/CLAUDE.md` = `INSTR` and
      `.team/CLAUDE.md` = `CHARTER`, the prompt holds `## Repo instructions`
      and `INSTR`. The indices run `SHARED` < role body < `## Repo instructions`
      < `INSTR` < `## Repo charter` < `CHARTER` < `## Your file scope`.
- [ ] Missing (AC1/AC4): there is no `.claude/CLAUDE.md`, so no
      `Repo instructions` heading. The same holds for a whitespace-only file.
      `repo_instructions(repo) == ""`.
- [ ] Inside import inlined once (AC1/AC4): `.claude/CLAUDE.md` holds
      `see @docs/a.md` and `@docs/a.md` again. `docs/a.md` = `A-TEXT`. The
      prompt holds `A-TEXT` exactly once, then
      `(left out: @docs/a.md is already included above)`.
- [ ] Relative to the importing file: `.claude/CLAUDE.md` imports `@rules.md`,
      which resolves to `.claude/rules.md` and is inlined. `docs/a.md`
      importing `@b.md` inlines `docs/b.md` (nested).
- [ ] Cycle: `docs/a.md` imports `@../.claude/CLAUDE.md`. The result has the
      repeat note and the call ends.
- [ ] Outside import left out with its note (AC1/AC4): `@~/.claude/CLAUDE.md`
      → `(left out: @~/.claude/CLAUDE.md points outside the repo)`. So does
      `@../../outside.md`, and so does an absolute path to an existing file
      outside the repo (in the fake world, a file under `FAKE_HOME`). Its
      text is absent.
- [ ] Not a file inside the repo: `ping @someone` and `docs/a.md.` stay
      verbatim. `mail a@b.com` stays verbatim.
- [ ] Code is not imported: `` `@docs/a.md` `` and a fenced block holding
      `@docs/a.md` stay verbatim, and `A-TEXT` is absent.
- [ ] Home never read (AC2/AC4): write `FAKE_HOME/.claude/CLAUDE.md` =
      `HOME-RULE`, and `monkeypatch.setattr(system, "home", <raises>)` and
      the same for `expand_user`. Build the prompt with and without a
      `@~/.claude/CLAUDE.md` import. `HOME-RULE` is absent and nothing raises.
- [ ] No settings (AC2/AC4): the options built for a role step have
      `setting_sources == []`, the same way `test_dispatch.py` L69 builds
      them. A `.claude/settings.json` with a hook in the repo changes neither
      the options nor the prompt.
- [ ] The existing `test_roles.test_system_prompt_order` and
      `test_system_prompt_skips_missing` still pass unchanged.

## Out of scope

- A root `CLAUDE.md`, `CLAUDE.local.md`, `.claude/rules/*.md`, and
  `CLAUDE.md` files in parent or child directories.
- Turning on any Claude Code setting source.
- Editing `.claude/CLAUDE.md`. It is the human's.
