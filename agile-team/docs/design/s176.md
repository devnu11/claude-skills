# s176: a story rebase step moves only its own rebase branch

The story rebase step's git runs with `Allows.LOCAL` (s159 S2). That rule
checks the subcommand and a few flags, not which branch the command would
move. The worktree shares the repo's refs, so `git checkout -B <other>`,
`git rebase <onto> <other>`, or `git reset` while HEAD is on another branch
really moves that other branch, and the S3 checks after the step look only at
the rebase branch.

This story adds two guards. The first is a branch check in the guard, which
refuses the command before it runs. The second is a ref snapshot around the
step, compared when the step ends; any branch the step moved is put back and
the step bounces.

Traces: AC1 → REQ-209, AC2 → REQ-210, AC3 → REQ-211. Decision: ADR-0091.

Developer: `developer-cli`.

## Rules

- **B1. The one branch.** A story rebase step may move only
  `rebase.branch` (`<story_prefix><id>-r<k>`). The runner gives it to the
  guard as `Scope.git_branch`. A scope with `git_branch == ""` (every other
  step) gets no branch check.
- **B2. HEAD at the hook.** For each Bash call of such a step, the guard
  reads which branch HEAD is on in the step's worktree:
  `git -C <workspace> symbolic-ref -q --short HEAD`. Exit 0 gives the
  branch name. Exit 1 means detached (`DETACHED = ""`). Any other exit is
  `HEAD_UNKNOWN = "?"` (`?` can't be in a ref name, so it never matches a
  branch).
- **B3. The branch a git call moves** (`find_moved_branch`). One table,
  `BRANCH_MOVES`, keyed by subcommand. A subcommand that isn't in it moves
  no branch (`DETACHED`).

  | sub | branch it moves |
  |---|---|
  | `checkout`, `switch` | the branch named by a creating option (`CREATES_BRANCH`: checkout `-b`, `-B`, `--orphan`; switch `-c`, `-C`, `--create`, `--force-create`, `--orphan`), else none |
  | `reset`, `commit`, `cherry-pick` | HEAD's branch (B2/B4) |
  | `rebase` | none with an action (`REBASE_ACTIONS`: `--continue`, `--abort`, `--skip`, `--quit`, `--edit-todo`, `--show-current-patch`). Otherwise the `<branch>` operand: the 2nd operand, or the 1st with `--root`. With no `<branch>` operand, HEAD's branch |
  | `stash` | with the action `branch`, the operand after it (`git stash branch <name>`); else none |

  How options are read, using the existing `Flags` and `LONG_PREFIX_MIN`:
  - A long option matches when it has at least `LONG_PREFIX_MIN` characters
    and is a prefix of a listed name, as `_is_denied_flag` does
    (`--force-c` is `--force-create`).
  - A long option's value is after `=`, or else the next word.
  - In a short cluster, the first listed letter takes the rest of the
    cluster as its value (`-Bname`), or the next word when nothing follows
    it (`-fB name`).
  - Operands are the words after the subcommand that are neither options
    nor option values. The value-taking options are `REBASE_VALUES =
    Flags(("--onto", "--strategy", "--strategy-option"), "sX")` and
    `STASH_VALUES = Flags(("--message",), "m")`. So `git rebase --onto X Y
    other` has the operands `Y other`, and it moves `other`.
- **B4. HEAD across one command** (`get_next_head`). The guard checks a
  command's git calls in order, starting from B2's HEAD. Only `checkout` and
  `switch` change the HEAD that later calls in the same command see:
  - a creating option: the created branch;
  - `--detach` (or switch's `-d`): `DETACHED`;
  - checkout with a `--` word, or with no operand: unchanged;
  - any other operand: `HEAD_UNKNOWN`, because it may be a branch, a commit
    or a path.

  No other subcommand changes the tracked HEAD. Any other call that ends on
  another branch has already been checked and allowed only for `git_branch`,
  and a stopped rebase leaves HEAD detached. Both are states where B5
  allows moves.
- **B5. Refused.** A call is refused when it moves a branch that is neither
  `DETACHED` nor `git_branch`. That covers HEAD's branch when HEAD is on
  another branch or `HEAD_UNKNOWN`. The refusal uses the new rule
  `git-own-branch` (`Rule.GIT_OWN_BRANCH`) and names the one branch the step
  may move:

  ```
  GIT_OTHER_BRANCH = Refusal(
      Rule.GIT_OWN_BRANCH,
      "{role} may not run `git {sub}` in {workspace}: it would move {moved}, and this "
      "step may move only its own rebase branch `{branch}`",
      "git that moves only `{branch}`: `git add`, `git rebase --continue`, `--abort` or "
      "`--skip`, `git checkout -- <file>`, and `git reset` or `git checkout -B {branch}` "
      "on `{branch}`",
  ).text()
  ```

  `{moved}` is `` `<name>` `` for a named branch. For `HEAD_UNKNOWN` it is
  ``the branch an earlier `git checkout` or `git switch` in this command left HEAD on``.
  The branch check runs only after every link has passed the existing rules
  (G4 to G7), so `branch`, `update-ref`, `symbolic-ref`, `push` and the rest
  are still refused as today, by `git-local-only`.
- **B6. Still allowed (AC2).** `git rebase --continue`, `--abort` and
  `--skip`; `git add`; `git checkout -- <file>`; and the read-only commands
  move no branch. `git reset …` and `git commit` move HEAD's branch, which
  is allowed while HEAD is on `git_branch` or detached. `git checkout -B
  <git_branch> [<sha>]` moves `git_branch`. A plain `git checkout <other>`
  moves no branch and stays allowed. The S3 check "HEAD is not on {branch}"
  still bounces a step that ends there.
- **B7. The snapshot (AC3).** `story_rebase.read_branch_heads` reads the
  heads in one call: `git for-each-ref
  --format=%(refname:short)%09%(objectname)%09%(worktreepath) refs/heads`.
  It keeps each branch that is not `rebase.branch` and is not checked out
  in another worktree: `worktreepath` is empty or resolves to the step's own
  worktree (`system.resolve`). Git already refuses to move a branch that is
  checked out in another worktree from this one, and `--ignore-other-worktrees`
  stays refused. Every branch the runner moves while a step runs is checked
  out somewhere: other stories' branches in their worktrees, and the sprint
  branch in the main checkout. So none of the runner's own moves land in
  the snapshot (ADR-0091).
- **B8. When it is taken.** `_set_story_rebase_scope` takes the snapshot
  after `story_rebase.prepare`, but only when `rebase.heads` is empty. It
  stores it in the new `StoryRebase.heads`, which the step-start
  `self.save()` writes to `state.json` before the role launches. A step
  that is cut off never reaches its effects, so it keeps its snapshot, and
  the resumed step (s165) compares against the state before the cut-off.
- **B9. The compare.** `Runtime._apply_rebase` checks this first, before
  `_find_rebase_stop`, so it applies whatever the handoff says (`done`,
  `blocked`, `failed`, or none):
  1. `story_rebase.list_moved_branches` re-reads the heads with B7's filter.
     For each branch in `rebase.heads` that is still there with a different
     sha, it yields a `MovedBranch(name, old, new)`. A branch that is gone,
     or that is now checked out in another worktree, is skipped. The guard
     refuses deletion (`branch`, `update-ref`), and the runner may drop a
     branch itself (`revert_story`).
  2. Each moved branch is put back with `git update-ref -m "agile-team: put
     back after the story rebase step" refs/heads/<name> <old> <new>`. The
     `<new>` argument makes the update fail if the branch moved again.
  3. `rebase.heads` is cleared, so the next round takes a fresh snapshot.
  4. If any branch moved, the step bounces to `story.step`
     (`Verdict.BOUNCE`, `author=Author.ROLE`; a round, as the S3 refusals
     do). The reason is one line per branch, joined with `"; "`:
     `BRANCH_MOVED = "the step moved {branch} from {old} to {new}; the
     runner put it back"`, or, when `update-ref` failed, `BRANCH_STUCK =
     "the step moved {branch} from {old} to {new}; it moved again before the
     runner could put it back"`. `story.rebase` stays queued, so the router
     runs the step again (S1). Its `prepare` resumes the worktree.
- **B10. The brief.** `STORY_REBASE_LINES` gains a third line:
  `"Move no other branch: git that would move a branch other than {branch}
  is refused, and the runner puts back any other branch the step moved and
  bounces the step."`

## Changes per module

### `agile_team/refusal.py`

- `Rule.GIT_OWN_BRANCH = "git-own-branch"`, after `GIT_LOCAL`.

### `agile_team/git_check.py` (pure; no I/O)

- Constants: `DETACHED = ""`, `HEAD_UNKNOWN = "?"`,
  `CREATES_BRANCH: dict[str, Flags]` (`"checkout": Flags(("--orphan",),
  "bB")`, `"switch": Flags(("--create", "--force-create", "--orphan"),
  "cC")`), `DETACHES: dict[str, Flags]` (`"checkout": Flags(("--detach",))`,
  `"switch": Flags(("--detach",), "d")`), `REBASE_ACTIONS`, `REBASE_VALUES`,
  `STASH_VALUES`,
  `MOVES_HEAD_BRANCH = frozenset({"reset", "commit", "cherry-pick"})`,
  `GIT_OTHER_BRANCH` (B5).
- `Site` gains `branch: str = ""` and `head: str = DETACHED`, after
  `workspace_allows`.
- `BRANCH_MOVES: dict[str, Callable[[GitCall, str], str]]`. It maps
  `checkout`/`switch` to `_find_checkout_branch`, the `MOVES_HEAD_BRANCH`
  subs to `_get_head_branch`, `rebase` to `_find_rebased_branch` and `stash`
  to `_find_stash_branch`.
- `def find_moved_branch(call: GitCall, head: str) -> str`: the branch
  `call` would move given HEAD's branch `head`, or `DETACHED` (B3).
- `def get_next_head(call: GitCall, head: str) -> str`: the HEAD that later
  calls in the same command see (B4).
- `def find_branch_denial(site: Site, links: Sequence[Link]) -> str | None`:
  B5. It returns `None` when `site.branch` is empty. It walks the links' git
  calls in order from `site.head` and returns the refusal for the first call
  whose moved branch is neither `DETACHED` nor `site.branch`.
- Private helpers (names as written; split further if a body passes 8
  lines): `_find_created_branch(call: GitCall) -> str` (the
  `CREATES_BRANCH` value, or `""`), `_find_checkout_branch(call, head)`,
  `_get_head_branch(call, head)`, `_find_rebased_branch(call, head)`,
  `_find_stash_branch(call, head)`, `_list_operands(call: GitCall, values:
  Flags) -> list[str]`, `_describe_moved(moved: str) -> str`.
- `git_denial`: when `site` is set and no link was denied, return
  `find_branch_denial(site, links)`.

### `agile_team/guard.py`

- `Scope` gains `git_branch: str = ""`. Docstring: "the one branch a story
  rebase step may move (s176); empty: no branch check".
- `_site(scope)`: pass `branch=scope.git_branch` and `head=` the value of
  `_read_head_branch(workspace)` when `scope.git_branch` is set, else
  `git_check.DETACHED`.
- `def _read_head_branch(workspace: Path) -> str`: B2, through
  `system.run(system.Command(("git", "-C", str(workspace), "symbolic-ref",
  "-q", "--short", "HEAD")))`, with a table `{0: name, 1: DETACHED}`; any
  other code gives `HEAD_UNKNOWN`.

### `agile_team/story_branches.py`

- `StoryRebase` gains `heads: dict[str, str] = field(default_factory=dict)`
  (branch → sha at the step's start; B7, B8). Old `state.json` files load
  through the default.

### `agile_team/story_rebase.py`

- `@dataclass(frozen=True) class MovedBranch`: `name: str`, `old: str`,
  `new: str`.
- `BRANCH_MOVED`, `BRANCH_STUCK` (B9), `PUT_BACK_MESSAGE = "agile-team: put
  back after the story rebase step"`, `HEADS_FORMAT =
  "%(refname:short)%09%(objectname)%09%(worktreepath)"`.
- `def read_branch_heads(git: Git, rebase: StoryRebase) -> dict[str, str]`:
  B7.
- `def list_moved_branches(git: Git, rebase: StoryRebase) -> list[MovedBranch]`:
  B9.1.
- `def put_back_branch(git: Git, moved: MovedBranch) -> str`: B9.2. It runs
  `update-ref` through `git.attempt` and returns that branch's reason line,
  `BRANCH_MOVED` when the update worked and `BRANCH_STUCK` when it didn't.
- `STORY_REBASE_LINES` gains B10's line.

### `agile_team/dispatch.py`

- `_set_story_rebase_scope`: after `story_rebase.prepare(...)`, set
  `rebase.heads = rebase.heads or story_rebase.read_branch_heads(self.git,
  rebase)` and `plan.scope.git_branch = rebase.branch`.
- `_apply_rebase`: first, `if why := self._put_back_moved(rebase):` bounce
  with `Outcome(Verdict.BOUNCE, why, story.step, author=Author.ROLE)` through
  `_advance_and_log`, as the `find_refusal` branch does.
- `def _put_back_moved(self, rebase: StoryRebase) -> str`: lists the moved
  branches, puts each back, clears `rebase.heads`, and returns the joined
  reason (`""` when nothing moved).

### `agile-team/reference/protocol.md`

- The "Story rebases" paragraph: the branch rule (`git-own-branch`), the
  snapshot, the put-back and the bounce. (Done by the architect in this
  step.)

## Test checklist

Guard (pure, `tests/test_git_check.py`, with a `Site` whose `workspace_allows=LOCAL`,
`branch="team/story-s1-r1"` and `head` set per case):

- [ ] AC1: refused with `git-own-branch`, and the text names
  `team/story-s1-r1`: `git checkout -B other`, `git checkout -Bother`,
  `git checkout -fB other`, `git checkout -b new`, `git switch -C other`,
  `git switch --force-c other`, `git switch --create=other`, `git rebase main
  other`, `git rebase --onto main base other`, `git rebase --root other`,
  `git stash branch other`; `git reset --hard X` and `git rebase main` with
  `head="other"`; `git commit -m x` with `head="other"`.
- [ ] AC1: within one command, `git checkout other && git reset --hard X`
  is refused (`HEAD_UNKNOWN`) even with `head` set to the rebase branch.
  `git checkout --detach && git reset --hard X` is allowed.
- [ ] AC1: `git branch -f other X`, `git update-ref refs/heads/other X` and
  `git symbolic-ref HEAD refs/heads/other` are still refused by
  `git-local-only`.
- [ ] AC2: allowed with `head` set to the rebase branch, and with
  `head=DETACHED`: `git rebase --continue`, `--abort`, `--skip`, `git add f`,
  `git checkout -- f`, `git checkout HEAD -- f`, `git reset --hard X`,
  `git reset -- f`, `git checkout -B team/story-s1-r1 X`, `git status`,
  `git log`, `git diff`. `git rebase --continue` is allowed with
  `head="other"` too.
- [ ] A site with `branch=""` gets no branch check: `git checkout -B other`
  passes `LOCAL` as before.
- [ ] `find_moved_branch` and `get_next_head` are checked case by case
  against B3 and B4.
- [ ] `tests/test_s103.py`'s per-rule table gains a `Rule.GIT_OWN_BRANCH`
  example.

Guard (`tests/test_guard.py`):

- [ ] `_site` reads HEAD only when `git_branch` is set. Exit 0, exit 1 and
  any other exit map to the name, `DETACHED` and `HEAD_UNKNOWN` (with a fake
  `system.run`).

Snapshot and compare (`tests/test_story_rebase.py`, a scratch repo with two
worktrees):

- [ ] `read_branch_heads` leaves out the rebase branch and a branch checked
  out in another worktree, and keeps a free branch and the step worktree's
  own branch.
- [ ] AC3: a free branch moved during the step gives `MovedBranch(name, old,
  new)`. `put_back_branch` restores it and returns `BRANCH_MOVED`'s text
  with the name and both shas. A branch moved again before the put-back
  gives `BRANCH_STUCK`. A deleted branch, or a branch now checked out
  elsewhere, is not listed.

Dispatch (`tests/test_dispatch*.py` or the story-rebase tests there):

- [ ] AC3: a story rebase step that moved a free branch bounces a round
  (`Verdict.BOUNCE` to `story.step`) with the reason, the branch is back at
  its old sha, `rebase.heads` is cleared and `story.rebase` stays queued.
  The same happens when the handoff is `blocked` (bounce, not hold).
- [ ] `_set_story_rebase_scope` sets `scope.git_branch` and keeps an
  existing `rebase.heads` (resume) rather than reading a new one.
- [ ] An old `state.json` story `rebase` without `heads` loads.
