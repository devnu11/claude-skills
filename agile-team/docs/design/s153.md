# s153: The pieces for the sprint-end rebase conflict path (s151 slice 1)

ADR: [ADR-0076](../../../.team/adr/0076-devops-resolves-sprint-end-rebase-conflicts.md)
(amended by s153: the path lands in two slices). Requirements: REQ-092 to
REQ-096. Developer: `developer-cli`.

This story is "Slice 1" of [s151's design](s151.md#slice-1-the-pieces-new-story-ahead-of-s151-no-boundary-behaviour-change).
s151's rules R13 to R19 and its module sections are the contract for every
signature named here. This file says which of them land now, fills in what
s151 leaves open, and lists this story's tests. Where the two differ, this
file wins for s153.

## Rules

- **P1 No behaviour change (AC6).** Nothing in this story sets a
  `Failure` with `FixCase.REBASE_CONFLICT`, sets `Boundary.rebase_fix`, or
  holds `BoundaryHold.REBASE_CONFLICT`. `boundary_runner._rebase_conflict`
  still holds `sync_conflict`, exactly as today. So `due()` never returns
  `StepKind.REBASE_FIX`, and `ScratchRebase` and `Upstream.adopt` have no
  caller outside tests. Slice 2 (s151's implement step) wires them.
- **P2 The team checkout is never touched by the scratch rebase (AC3).**
  `prepare` and `drop` change only `<run_dir>/rebase`, the scratch branch
  and git's worktree list. The team checkout's HEAD, branch, index and
  working tree stay as they were.
- **P3 `adopt` resets only from the expected head (AC2).** When the team
  HEAD is not `old`, `adopt` raises `UpstreamError(TEAM_MOVED…)` before any
  git command that writes.
- **P4 First reason wins (AC5).** `refusal` runs `SCRATCH_CHECKS` in order
  and stops at the first non-empty reason. The order is s151's R16 step 2.
- **P5 Tests move to their step (AC7).** The AC6 e2e part leaves
  `tests/e2e/test_s151_as_built_end_e2e.py` before this story's implement
  gate. Nothing is weakened: the tests come back at s151's e2e step.
- **P6 Real git lives in `tests/e2e/` (AC8).** Unit tests run in the fake
  world: `os_guard` refuses a real OS call outside `tests/e2e/`. So the
  unit tests pin the git commands and the logic against `FakeSystem`, and
  the real-git tests that AC8 asks for are e2e tests, written at this
  story's e2e step.
- **P7 s151's slice-2 unit tests stay in the tree as s151's pending ids
  (Manager and PO rulings, AC7).** They are the tests that fail until
  s151's implement step: the red tests of `tests/test_s151_conflict.py`,
  `test_s151_end.py::test_ac3_1_a_rebase_conflict_goes_to_devops_not_a_hold`,
  `test_s59_sync.py::test_a_conflict_reports_files_commit_and_subject_and_wakes_devops`,
  the `sync_conflict` case of
  `test_boundary_wiring.py::test_boundary_rows_match_and_format`, and the
  `sync_conflict` handover row of `test_handover.py` if it is red. None of
  them is s153's: no s153 step edits them, and none may become an s153
  pending id. They are never deleted or moved out of the tree (that was
  B1 of the round-2 review).
  Why an s151 step is needed: only the runner writes
  `.team/pending-tests.json`, and a red test joins a story's entry only at
  that story's own tests gate, when the step changed a line between the
  test's line and the next test's line (protocol.md, "Pending tests"). A
  red test that no step touched is a real failure in every gate. A
  constant such as `BOUNDARY_ROWS` is not inside any test's lines, so a
  parametrized case can be touched only by giving it a test of its own.
  So s151's tests step registers them (Step order, step 5) before s153's
  next gate.

### `upstream.py`

```python
REBASE_FLAGS = (
    "-c", "rebase.updateRefs=false", "-c", "rebase.rebaseMerges=false",
    "rebase", "--no-verify", "--no-autostash", "--no-autosquash",
)
REBASE_ARGV = (*REBASE_FLAGS, "--empty=drop")
SCRATCH_REBASE_ARGV = (*REBASE_FLAGS, "--empty=keep")
TEAM_MOVED = "the team branch {team} moved from {old} while DevOps resolved the rebase; nothing was reset"
```

- `Spans` gains a last field `head: str = "HEAD"`. Update its docstring:
  "… the target, and the head that is judged".
- `_lost` becomes public `lost_paths(self, spans: Spans) -> list[str]`:
  "The paths a rebase changed that only one side touched, sorted." It uses
  `spans.head` in both places it used `"HEAD"`. `_check_kept` calls it.
  Behaviour for a clean rebase is unchanged.
- `upstreamed(self, old: str) -> frozenset[str]`: "The shas of
  `target..old` whose patch is already in the target." Run
  `git cherry <target> <old>`; keep the sha of each line that starts with
  `"- "`.
- `adopt(self, old: str, sha: str) -> Rebase`: "Move the team branch to
  `sha` while it is still at `old`; the moved pairs." In order:
  1. `self.git.head() != old` → `raise UpstreamError(TEAM_MOVED.format(team=self.git.branch(), old=old))`;
  2. `target_sha = git rev-parse <target>`; `git reset --keep <sha>`;
  3. return `Rebase(SyncOutcome.REBASED, sha, moved=pair(self.listing(f"{self.target}..{old}"), self._new_listing(target_sha)))`.

  Split it so each function stays under 8 lines (for example
  `_refuse_moved(old)` for step 1).

### New `scratch_rebase.py`

As s151's "New `agile_team/scratch_rebase.py`" section: the module
docstring, the constants `REBASE_DIR`, `REBASE_BRANCH`, `UNFINISHED`,
`OFF_BRANCH`, `DIRTY`, `NOT_ON_TARGET`, `HAS_MERGES`, `COMMITS_CHANGED` and
`LOST_PATHS` with their exact texts, and the frozen dataclass
`ScratchRebase(upstream: Upstream, path: Path, branch: str)`. Imports:
`Git` from `.git_ops`; `Upstream`, `Spans`, `SCRATCH_REBASE_ARGV` from
`.upstream`; `operation` from `.checkout`; `system`. What s151 leaves open:

| Member | Does |
|---|---|
| `tree` (property) | `Git(self.path)` |
| `prepare(head)` | `self.remove()`; in the team repo `worktree add -B <branch> <path> <head>`; in `tree`, `attempt(*SCRATCH_REBASE_ARGV, upstream.target)`, exit code ignored (it stops at the conflict) |
| `remove()` | in the team repo `attempt("worktree", "remove", "--force", str(path))` and `attempt("worktree", "prune")`; then `system.remove_tree(path)` when `system.exists(path)` |
| `drop()` | `remove()`, then `attempt("branch", "-D", branch)` in the team repo |
| `head()` | `self.tree.head()` |
| `refusal(old)` | the first non-empty `check(self, old)` over the module global `SCRATCH_CHECKS`, read at call time (a test patches it), else `""` |

The checks, each `(self, old: str) -> str`, `""` when it passes:

| Check | Fails when | Reason |
|---|---|---|
| `_unfinished` | `operation(self.tree)` is not `None` | `UNFINISHED` (`path`, `operation`) |
| `_off_branch` | `self.tree.branch() != self.branch` | `OFF_BRANCH` (`path`, `branch`) |
| `_dirty` | `tree` `status --porcelain` is not empty | `DIRTY` (`path`, `status` stripped) |
| `_off_target` | `merge-base --is-ancestor <target> <branch>` exits non-zero | `NOT_ON_TARGET` (`branch`, `target`) |
| `_merges` | `rev-list --merges <target>..<branch>` is not empty | `HAS_MERGES` (`branch`, `shas`: each cut to 12, joined `", "`) |
| `_commits_changed` | the stamps of `listing(f"{target}..{branch}")` differ from the stamps of `listing(f"{target}..{old}")` whose sha is not in `upstreamed(old)` (lists, order counts) | `COMMITS_CHANGED` (`branch`) |
| `_lost` | `upstream.lost_paths(Spans(old, old, <target sha>, head=self.branch))` is not empty | `LOST_PATHS` (`branch`, `paths` joined `", "`) |

`SCRATCH_CHECKS = (ScratchRebase._unfinished, ScratchRebase._off_branch,
ScratchRebase._dirty, ScratchRebase._off_target, ScratchRebase._merges,
ScratchRebase._commits_changed, ScratchRebase._lost)`, defined after the
class. Every check except the first three runs in the team repo (worktrees
share refs).

Pitfall: during a stopped rebase the worktree's HEAD is detached, so
`_off_branch` would fail too. `_unfinished` comes first, so the reason
names the real problem.

### `boundary.py` (data only)

- `FixCase.REBASE_CONFLICT = "rebase_conflict"`.

### `state.py`

`_boundary` also loads `rebase_fix`: add
`_rebase_fix(data: dict[str, Any] | None) -> RebaseFix | None`, "A stored
rebase fix with its conflict as a `Failure`; `None` when absent", which
returns `None` for empty data, else
`RebaseFix(**{**data, "conflict": Failure(**data["conflict"])})`. Pass it
into the `Boundary(...)` call next to `failure`. An old `state.json`
without `rebase_fix` or `worktree` loads with `None` and `""`.

### `dispatch.py`

- `FIX_KINDS_SET = frozenset({StepKind.TEAM_FIX, StepKind.REBASE_FIX})`.
- `REBASE_FIX_ENV = {"GIT_EDITOR": "true"}` (module constant).
- Extract `Runtime._confine_to(self, plan: Plan, path: Path) -> None`,
  "Confine the step's git to `path` and set git's ceiling (G2)", from
  `_confine_git`: it sets `plan.scope.git_workspace = system.resolve(path)`
  and `plan.launch.env = {**(plan.launch.env or self.env),
  **git_check.git_env(self.config.run_dir)}`. `_confine_git` calls it with
  `GIT_CONFINED[step](self, plan)`.
- `Runtime._rebase_fix_scope(self, plan: Plan) -> None`, "A rebase fix may
  write only the scratch worktree, and its git is confined there":
  `worktree = self.config.run_dir / scratch_rebase.REBASE_DIR`;
  `plan.scope.write = [f"{worktree.relative_to(self.config.repo).as_posix()}/**"]`
  (it replaces the role's globs); `self._confine_to(plan, worktree)`; then
  `plan.launch.env = {**plan.launch.env, **REBASE_FIX_ENV}`.
- `FIX_SETUPS[StepKind.REBASE_FIX] = Runtime._rebase_fix_scope`.
- `_set_up`'s order stays. `_confine_git` does nothing for `devops`, so it
  does not undo this setup.
