# s78: Health gives no false reds while work runs

Story: `.team/stories/s78.md`. Refines s44's health (`design/s44.md` R1–R15,
H1–H6). Developer: `developer-cli`.

## What happened (evidence)

`turns.jsonl` lines 572→573 show the code reviewer on s71 opening a `Bash`
tool at 1791827956 (12:59:16 CDT). It ran for 294 s, and no other turn came
until 13:04:10. Only one tool was running, not a call every few seconds.
While it ran, nothing wrote `heartbeat.json` for 4 min, although the runner
was alive and the beat thread should write every `beat_s` (20 s). The 12:42
case was the same kind of gap: the implement gate ran inside the
`settling …` chore and the beat was 90+ s late. Both gaps came while a CPU-heavy
pytest run was going, either the role's own or the gate's. During a turn the
main thread writes on every message, so the beat is fresh.

The cause of the late or missing beats cannot be proved from the code. The
thread either died (any non-`OSError` raised in `write` ends it silently) or
the OS delayed it (timer coalescing or starvation under load). The design
deals with both:

1. The beat thread can no longer die silently. It keeps beating and leaves
   one traceback in `crash.log` (H7).
2. Health stops treating a late beat as death while the last beat said
   work was in progress, as long as the machine was awake and the runner's
   pid is alive (R16–R19).
3. Health detects a sleeping machine directly, by comparing wall time with
   monotonic time, so a real sleep stays red (R16).

No new thread and no new config. Gate activity rides the existing chore
mechanism (`Pulse.doing`). Tool activity rides the existing `step.tool` field.

## Rules

- **H7 The beat thread outlives a failed write.** `Pulse.beats` calls
  `_beat()` once per wait. `_beat` runs `write()` and catches any
  `Exception`. The first failure of a pulse is appended to `crash.log`
  through `halt.log_traceback(run_dir, exc)`, and later failures are not.
  An `OSError` from `log_traceback` itself is swallowed. `write` keeps its
  own `except OSError`.
- **H8 Every beat carries a monotonic stamp.** The heartbeat dict gains
  `"mono": self.pace.mono()`, written right after `"at"`.
  `HEARTBEAT_VERSION` becomes `2`. `Pace` gains `mono: Callable[[], float]
  = time.monotonic`. (When s76 deletes `Pace`, this becomes
  `system.monotonic()`.) Both macOS (`mach_absolute_time`) and Linux
  (`CLOCK_MONOTONIC`) give one system-wide monotonic clock that stops during
  sleep, so the reader can compare its own monotonic time with the
  writer's.
- **H9 Gate runs are a chore.** `Runtime.gate` runs `pipeline.evaluate`
  inside `self.pulse.doing(GATE_CHORE.format(step=story.step,
  story=story.id))`, with `GATE_CHORE = "gate: {step} on {story}"`. This
  chore nests inside `settling …`, and `doing` restores the outer chore on
  exit. Its green words read `runner: gate: implement on s71 for 1 min`.
  Boundary stages already run as the chore `sprint boundary: <stage>`, and
  quality checks and named tests are already chores. They stay as they are.
- **H10 Tool calls already refresh the beat.** `Pulse.take` writes when a
  message starts a turn (a tool use is a turn line) and when a tool result
  closes a tracked tool. This does not change. A test pins it (AC1).
- **R16 Sleep.** `Vitals.slept` = `beat_age - (mono - beat["mono"])`, the
  wall seconds since the last beat that monotonic time did not see. It is
  `None` when the reader's `mono` is unknown or the beat has no numeric
  `mono` (a version-1 heartbeat). A beating heartbeat with
  `slept > stale_s` is red: `the machine slept for {age(slept)}`.
- **R17 Excused late beat.** A beat is *stale* when it is beating and
  `beat_age > stale_s`. It is *excused* when all of these hold:
  - work was declared: the shown step has an open `tool`, or a `chore` is
    set;
  - the machine was awake: `slept` is known and not above `stale_s`;
  - `beat_age <= red_quiet_s`.

  The runner pid being alive is already required, because R4 (`runner
  GONE`) still applies and is red.
- **R18 Stale and not excused is red,** as in s44:
  `heartbeat {age(beat_age)} old`. This rule does not apply when R16
  matches, so a sleep reads as a sleep. "Not excused" covers four cases: no
  tool and no chore, a version-1 heartbeat or an unknown reader clock (we
  cannot tell sleep from delay, so we stay safe), and work declared but
  nothing written for more than `red_quiet_s` (10 min).
- **R19 Stale and excused is amber:** `heartbeat {age(beat_age)} old while
  {doing}`. `doing` is the chore's words (`runner: gate: implement on s71
  for 2 min`) when a chore is set, else `{tool name} runs`. A chore wins
  because it is the runner's own work, and it can sit inside a role's tool
  call (named tests).
- **R20 One source.** `agile-team watch` (`health.current`) and the
  snapshot (`_health`) both call `health.judge(health.Vitals.read(config,
  clock))`. Only where the clock comes from differs (see below).
- **Gate overrun.** A gate past `command_timeout_s` is killed by the gate
  (s43). Health has no rule for it. With the defaults (300 s against
  `red_quiet_s` 600 s) the gate kills a hung command before a late beat
  could turn red. If `command_timeout_s` is set above `red_quiet_s` and the
  beat is late for more than `red_quiet_s`, health turns red (R18). That
  is accepted: nothing has been written for 10 min.

The resulting table, in order (only R16, R18 and R19 are new or changed):

| # | Level | When | Words |
|---|---|---|---|
| R2 | red | halted | `halted: {reason}` |
| R3 | red | halted and turns arriving | `turns arriving while the run is {status}` |
| R4 | red | `interrupted`, or beating and pid gone | `the runner is not running (pid N)` |
| R5 | red | quiet over `red_quiet_s` | `no turn for {age}` |
| R16 | red | beating and `slept > stale_s` | `the machine slept for {age(slept)}` |
| R18 | red | stale, not excused, not R16 | `heartbeat {age} old` |
| R19 | amber | stale and excused | `heartbeat {age} old while {doing}` |
| R7 | amber | tool open, quiet over `amber_tool_s` | `no turn for {age} while {tool} runs` |
| R8 | amber | no tool, quiet over `amber_quiet_s` | `no turn for {age}` |
| R9 | green | chore set | `runner: {what} for {age}` |
| R10 | green | step open, no chore | `turns arriving` |
| R11 | idle | otherwise | status words |

Worked cases:

- **13:00 case.** `Bash` has been open 4 min, the beat is 4 min late, the
  pid is alive and the machine was awake. The verdict is amber: `no turn
  for 4 min while Bash runs, heartbeat 4 min old while Bash runs`. With a
  healthy thread it is amber from the R7 rule only.
- **12:42 case.** The `gate: implement on s71` chore is set and the beat is
  100 s late. The verdict is amber: `heartbeat 1 min old while runner:
  gate: implement on s71 for 1 min`. With a fresh beat it is green:
  `runner: gate: implement on s71 for 1 min`.
- **12:47–12:58 sleep.** On wake, before the runner's next beat, a reader
  sees `slept ≈ 660 s`, and the verdict is red: `the machine slept for 11
  min`. After the next beat, R5 (`no turn for 11 min`) is usually red.
- **Dead runner.** Unchanged: R4 is red.

### `agile_team/health.py`

```python
@dataclass(frozen=True)
class Clock:
    """The reader's wall and monotonic time; ``mono`` is ``None`` when unknown (s78)."""
    wall: float
    mono: float | None = None

    @classmethod
    def read(cls) -> Clock:
        """Both clocks now, through the system seam."""
        return cls(system.now(), system.monotonic())

@dataclass(frozen=True)
class Vitals:
    ...                                   # existing fields unchanged, in order
    halt_kind: str | None = None
    mono: float | None = None             # new, last: the reader's monotonic time

    @classmethod
    def read(cls, config: Config, clock: Clock) -> Vitals   # was (config, now: float)
        # now=clock.wall, mono=clock.mono; the rest as today

    @property
    def slept(self) -> float | None        # R16; None unless self.mono and a numeric beat["mono"]
    def slept_over(self, limit: float) -> bool   # slept is not None and slept > limit
    @property
    def stale(self) -> bool                # beating and beat_age > limits.stale_s
    @property
    def busy(self) -> bool                 # tool is not None or chore is not None
    @property
    def excused(self) -> bool              # R17: busy, slept known and not over stale_s, beat_age <= red_quiet_s

def _sleep_words(v: Vitals) -> str        # f"the machine slept for {age(v.slept or 0)}"
def _doing(v: Vitals) -> str              # _chore_words(v) if v.chore else f"{(v.tool or {}).get('name')} runs"
def _late_words(v: Vitals) -> str         # f"heartbeat {age(v.beat_age)} old while {_doing(v)}"

def current(config: Config) -> Health:
    return judge(Vitals.read(config, Clock.read()))
```

## Test checklist

Put new unit tests in `tests/test_s78_health.py`, in the FAKE world
(1 s limit, no real OS). Build `Vitals` directly for the rules. For the
pulse, inject `Pace(now=…, wait=…, mono=…)` and `pid=4242`, and call
`pulse.heartbeat()` (it does no I/O) or replace `pulse.write` on the
instance with a counter. Do not let `write` touch real files.

Rules (AC2, AC3):

- [ ] **Tool activity:** a beating heartbeat 240 s old, step with
      `tool={"name": "Bash", …}`, `quiet_since` 240 s ago, `mono` such that
      `slept == 0`, pid alive. The level is `amber`, the reason contains
      `heartbeat 4 min old while Bash runs`, and nothing is red.
- [ ] **Gate activity:** a heartbeat 100 s old with `chore={"what": "gate:
      implement on s71", "since": now-100}` and `slept == 0`. The level is
      `amber` and the reason is `heartbeat 1 min old while runner: gate:
      implement on s71 for 1 min`.
- [ ] Gate chore with a fresh beat: `green`, `runner: gate: implement on s71
      for …`.
- [ ] **Sleep:** a beating heartbeat 660 s old whose `mono` is only 10 s
      behind the reader's `mono` (`slept == 650`), with a tool open. The
      level is `red` and the reason contains `the machine slept for 10 min`
      and does not contain `heartbeat`.
- [ ] **Dead:** pid gone (fake `pid_alive` false) with an excused-looking
      beat. The level is `red` and the reason contains `the runner is not
      running`.
- [ ] Stale beat, no tool and no chore, awake: `red`, `heartbeat 2 min old`
      (R18).
- [ ] Stale beat with a tool, awake, `beat_age = red_quiet_s + 1`: `red`
      (not excused).
- [ ] Version-1 beat (no `mono`) with a tool, 240 s old: `red`, `heartbeat 4

- [ ] A non-numeric `beat["mono"]` gives `slept is None`.
- [ ] `slept` exactly equal to `stale_s` is not a sleep, and the beat can be
      excused (the boundary is `>`).

Pulse (AC1, H7, H8):

- [ ] **Tool calls write:** feeding an `AssistantMessage` with a
      `ToolUseBlock` calls `write` once. Feeding the matching
      `UserMessage`/`ToolResultBlock` calls it again. A result for an
      unknown id does not.
- [ ] `heartbeat()` has `version == 2` and `mono == pace.mono()`, with the
      key order `version, pid, beat, at, mono, started_at, chore, step`.
- [ ] `beats()` with `write` raising `RuntimeError` on every call and `wait`
      returning `False, False, True`: the thread body returns normally after
      two beats, and the fake's `crash.log` holds exactly one `RuntimeError`
      entry.
- [ ] `_report` when `crash.log` cannot be written (fake `fill_disk()` or
      `deny`) raises nothing.

- [ ] Same verdict from both sources: for one run dir and clock, the
