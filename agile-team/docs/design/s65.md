# s65: A role's git commands never reach the team repo

Story: `.team/stories/s65.md`. Delivery: cli. Developer: `developer-cli`.
No new dependency, no ADR (extends the guard, s41/s43/s69 pattern: a pure
checker module the guard feeds Bash words).

## Problem

During s61 the integration-tester ran git in a demo directory with no `.git`.
Git climbed to the team repo and `checkout -B main` moved the human's `main`.
The guard's git rule (`SAFE_GIT`) did not see it: it looks only at a segment
whose first word is `git`. That misses a script, `X=1 git …`, `env git …` and
`command git …`. It also has no idea of a workspace: every role gets the same
read-only list, so a demo builder cannot use git even inside its own workspace.

## Two layers

1. **Environment (AC1).** Git can't find the team repo from the workspace.
   For a confined step the runner sets `GIT_CEILING_DIRECTORIES` to the run
   dir (`.team/run`, resolved). Git never climbs into it, so from anywhere
   below it (presentation, Proxy sandbox) a directory with no `.git` gives
   "not a git repository". This covers scripts and hooks the guard can't see.
2. **Guard (AC2, AC7, AC10).** The PreToolUse hook reads every git segment,
   decides *where* it works, and looks up a table row for that place.

## Rules

- **G1 Confined steps are a table (AC4).** `dispatch.GIT_CONFINED` maps a
  step to the function that gives the step's git workspace:
  `e2e` → the story's presentation workspace
  `.team/run/presentation/<id>/workspace`; `acceptance` → the Proxy's copy of
  it, `<sandbox>/presentation/workspace`. (The Proxy only ever works on the
  copy, so its copy is its workspace. The source copy is outside its scope.)
  A role fits a row by `gates.role_fits_step`, the same lookup `STEP_SETUPS`
  uses. Every other step is *unconfined*.
- **G2 Confined environment (AC1).** A confined step's launch env gets
  `GIT_CEILING_DIRECTORIES=<resolved run dir>` and
  `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR=1`. The second makes Claude Code
  return Bash to the step's cwd after each call, so the guard's "where" (G5)
  matches the real cwd. Unconfined steps and the runner's own git (`Git`,
  gate commands) get neither (AC3).
- **G3 Prefixes are seen through, every role (AC10).** A segment's command is
  found after skipping, repeatedly:
  - leading `NAME=value` words (`suite_check.ASSIGNMENT`);
  - a wrapper from `git_check.WRAPPERS` with its options, option values,
    assignments and leading operands. These are `env`, `command`,
    `builtin`, `exec`, `nohup`, `nice`, `time`, `timeout` and `gtimeout`
    (see the table below).

  `env -C DIR` / `--chdir=DIR` is kept as the segment's first place (G5).
  `env -S STR` / `--split-string=STR` splices `STR.split()` in where it
  stood. A command word whose basename is `git` (`/usr/bin/git`) is git.
  So `X=1 git commit`, `env git commit`, `command git commit` and
  `timeout 5 git commit` are each checked as `git commit`.
- **G4 Unconfined rule unchanged.** In an unconfined step a git segment
  (after G3) is allowed only when its first word after `git` is in `SAFE_GIT`,
  or is `cherry-pick` with `-n`/`--no-commit`. The denial text is the same as
  today: `` `git {first}` is not allowed; the runner commits for you ``. An
  option in first place (`git -C x status`) is still denied, as today.
- **G5 Where a git segment works (confined).** The guard splits the command
  into *links*: each segment plus the separator after it (`&&`, `||`, `;`, `|`,
  `&`, newline, or `""` at the end). Walking the links, each one gets a
  *base*, the directory it starts in:
  - The first link's base is the step's cwd (`scope.base`, resolved).
  - A link whose words are exactly `cd DIR` or `pushd DIR` moves the base to
    `resolve_in(base, DIR)`. If DIR starts with `-` or holds `$`, `` ` `` or
    `~`, the base becomes *unknown* (`None`).
  - The base carries to the next link only when the separator is `&&`, or
    when the base is still the step's cwd. Any other separator after a moved
    base makes it unknown for the rest of the command. A failed `cd` before
    `;` would leave git in the old cwd, so the guard cannot know where git
    runs. `(cd x) && git …` is not a `cd` link (its first word is `(cd`), so
    the base does not move.

  The git segment's directory **D** is its base, then each *place* applied
  in order. The places are env's `-C`, then every git `-C`. An absolute
  place resets D, so an unknown base followed by an absolute place is known
  again. Its **targets** are:
  - D itself;
  - the values of `--git-dir` and `--work-tree`, resolved against D;
  - the value part of each `-c name=value`, resolved against D;
  - for a subcommand in `PATH_ARGS`, its path arguments, resolved against D.
    `ALL` means every word after the subcommand that does not start with
    `-`, plus the value of every `--opt=value`. `FIRST` means only the first
    such word, the repository of `push`/`fetch`/`pull`, so refspecs with `:`
    pass.
  - A word that names something off the disk is an *outside word*: it holds
    `://`, starts with `!` (a shell alias), or looks like scp (`host:path`,
    a `:` before any `/`). A flag in `OUTSIDE_FLAGS` (`--global`,
    `--system`) is also an outside word.

  The segment's place `Where` is:
  - `UNKNOWN`: D is unknown.
  - `WORKSPACE`: every target is the workspace or below it (resolved paths,
    so a symlink out of the workspace is outside), and there are no outside
    words.
  - `STEP_DIR`: D is the step's cwd and the segment has no place, no
    `--git-dir`/`--work-tree` and no `-c`.
  - `ELSEWHERE`: anything else.
- **G6 One rule table (AC2, AC3, AC7).** `git_check.GIT_RULES` maps
  `Where` → `GitRule(allows, reason)`:

  | Where | Allows | Reason when denied |
  |---|---|---|
  | `UNCONFINED` | `READ_ONLY` (G4) | `GIT_WRITE_DENIED` (today's text) |
  | `STEP_DIR` | `READ_ONLY` (G4) | `GIT_OUTSIDE`, target = D |
  | `WORKSPACE` | `ANY` | (never denied) |
  | `ELSEWHERE` | `NONE` | `GIT_OUTSIDE`, target = first target outside the workspace |
  | `UNKNOWN` | `NONE` | `GIT_DIR_UNKNOWN` |

  `ALLOWS: dict[Allows, Callable[[GitCall], bool]]` gives the predicate for
  each value. So the integration-tester keeps `git status`/`diff`/`log` in
  its cwd (the repo root) (AC3). In the workspace any subcommand runs:
  `git init`, `git -C demo …`, `git clone demo copy`, commit, checkout,
  rebase (AC7). `git -C <team repo> status` and
  `git --git-dir <team repo>/.git log` are `ELSEWHERE` and denied, naming
  the team repo (AC2). `cd <ws> && git checkout -B main` with no `.git` in
  the workspace is `WORKSPACE`, so the guard allows it and git refuses it
  through G2's ceiling (AC9b).
- **G7 Git's environment is locked (confined).** A confined step's Bash
  command may not mention any name in `GIT_ENV_LOCKED`. These are
  `GIT_CEILING_DIRECTORIES`, `GIT_DIR`, `GIT_WORK_TREE`,
  `GIT_DISCOVERY_ACROSS_FILESYSTEM` and `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`.
  Denied with `GIT_ENV_DENIED`. This check runs before G6.
- **G8 Texts** (in `git_check`):

  ```python
  GIT_WRITE_DENIED = "`git {first}` is not allowed; the runner commits for you"
  GIT_OUTSIDE = (
      "{role} may not run `git {sub}` on {target}: in this step git works only "
      "inside {workspace}, and the team repo {repo} is the runner's. Work in the "
      "workspace: `cd {workspace} && git …` or `git -C {workspace}/<dir> …`"
  )
  GIT_DIR_UNKNOWN = (
      "{role} may not run `git {sub}` where an earlier `cd` may not have run; "
      "chain the `cd` with `&&` or give git an absolute `-C` inside {workspace}"
  )
  GIT_ENV_DENIED = "{role} may not set {name}: the runner sets git's environment for this step"
  ```

  `{target}` is the resolved path, or the outside word as written. `{sub}` is
  the parsed subcommand (or `{first}` when none was found). `{repo}` and
  `{workspace}` are resolved absolute paths.
- **G9 The workspace survives a bounce (AC8).** `presentation.lay_out` no
  longer wipes. It creates the story's presentation dir if it is missing.
  For a `Need.WORKSPACE` recipe it creates `workspace/` and runs `git init -q`
  there only when `workspace/.git` does not exist. Existing files are never
  removed: only the integration-tester replaces them. The Proxy's sandbox
  copy is still wiped and recopied each acceptance step (`sandbox.layout`,
  unchanged).
- **G10 Order in `check_bash`.** `_check_view` runs: secret mention, **git**
  (G7, then G3–G6), allowlist, tokens, waits, kills, suite. The git check's
  reason comes first, so the Proxy's `git -C <repo> status` names the team
  repo, not "may not reference".

## Module changes

### New `agile_team/git_check.py` (pure; I/O only through `paths.resolve_in`)

Module docstring: "Which git segments a role's Bash may run, and where (s65)."

```python
from __future__ import annotations
import re
from collections.abc import Callable, Sequence
from dataclasses import dataclass
from enum import StrEnum
from pathlib import Path, PurePosixPath

from . import system
from .paths import resolve_in
from .suite_check import ASSIGNMENT

SAFE_GIT = frozenset({...})          # moved here from guard (guard re-exports nothing; update imports)
NO_COMMIT_FLAGS = frozenset({"-n", "--no-commit"})   # moved from guard
CEILING_ENV = "GIT_CEILING_DIRECTORIES"
KEEP_CWD_ENV = "CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR"
GIT_ENV_LOCKED = (CEILING_ENV, "GIT_DIR", "GIT_WORK_TREE", "GIT_DISCOVERY_ACROSS_FILESYSTEM", KEEP_CWD_ENV)
CD_WORDS = frozenset({"cd", "pushd"})
AND = "&&"
UNSAFE_DIR_CHARS = ("$", "`", "~")
OUTSIDE_FLAGS = frozenset({"--global", "--system"})
SCP_LIKE = re.compile(r"^[^/:]+:")
PLACE_OPTIONS = frozenset({"-C"})
PATH_OPTIONS = frozenset({"--git-dir", "--work-tree"})
CONFIG_OPTIONS = frozenset({"-c"})
GIT_VALUE_OPTIONS = PLACE_OPTIONS | PATH_OPTIONS | CONFIG_OPTIONS | frozenset(
    {"--namespace", "--config-env", "--super-prefix", "--exec-path"}
)


@dataclass(frozen=True)
class Wrapper:
    """A command that runs another: its value-taking options and leading operands (G3)."""
    values: frozenset[str] = frozenset()
    operands: int = 0


TIMEOUT = Wrapper(frozenset({"-s", "--signal", "-k", "--kill-after"}), 1)
WRAPPERS: dict[str, Wrapper] = {
    "env": Wrapper(frozenset({"-u", "--unset", "-C", "--chdir", "-S", "--split-string"})),
    "command": Wrapper(), "builtin": Wrapper(), "nohup": Wrapper(),
    "exec": Wrapper(frozenset({"-a"})),
    "nice": Wrapper(frozenset({"-n", "--adjustment"})),
    "time": Wrapper(frozenset({"-f", "--format", "-o", "--output"})),
    "timeout": TIMEOUT, "gtimeout": TIMEOUT,
}
CHDIR_OPTIONS = frozenset({"-C", "--chdir"})        # env's
SPLIT_OPTIONS = frozenset({"-S", "--split-string"})  # env's


class Args(StrEnum):
    """Which words after a subcommand are paths (G5)."""
    ALL = "all"
    FIRST = "first"


PATH_ARGS: dict[str, Args] = {
    "init": Args.ALL, "clone": Args.ALL, "remote": Args.ALL, "config": Args.ALL,
    "submodule": Args.ALL, "worktree": Args.ALL,
    "push": Args.FIRST, "fetch": Args.FIRST, "pull": Args.FIRST,
}


class Where(StrEnum):
    """Where one git segment works (G5, G6)."""
    UNCONFINED = "unconfined"
    STEP_DIR = "step-dir"
    WORKSPACE = "workspace"
    ELSEWHERE = "elsewhere"
    UNKNOWN = "unknown"


class Allows(StrEnum):
    """Which subcommands a row lets through (G6)."""
    READ_ONLY = "read-only"
    ANY = "any"
    NONE = "none"


@dataclass(frozen=True)
class GitRule:
    """One row of GIT_RULES: what it allows and the reason when it does not."""
    allows: Allows
    reason: str


GIT_RULES: dict[Where, GitRule] = {...}       # the G6 table
ALLOWS: dict[Allows, Callable[[GitCall], bool]] = {...}


@dataclass(frozen=True)
class Link:
    """One Bash segment's words and the separator after it ("" at the end) (G5)."""
    words: tuple[str, ...]
    after: str


@dataclass(frozen=True)
class Stripped:
    """A segment's command words after G3, with env's ``-C`` directory if any."""
    words: tuple[str, ...]
    chdir: str | None = None


@dataclass(frozen=True)
class GitCall:
    """A parsed git segment (G5)."""
    words: tuple[str, ...]        # from "git" on
    first: str                    # the word after "git", "" if none (G4)
    sub: str                      # the first non-option word after global options, "" if none
    places: tuple[str, ...]       # env -C, then each -C, in order
    paths: tuple[str, ...]        # --git-dir / --work-tree values
    configs: tuple[str, ...]      # value parts of -c name=value
    args: tuple[str, ...]         # PATH_ARGS words (G5), "" tuple when sub not in PATH_ARGS
    outside: tuple[str, ...]      # outside words and OUTSIDE_FLAGS found among args and flags

    @property
    def explicit(self) -> bool:
        """Whether the segment names a place, a git dir, a work tree or a config."""


@dataclass(frozen=True)
class Site:
    """A confined step's git context; all paths resolved (G1)."""
    role: str
    repo: Path
    step_dir: Path
    workspace: Path


def strip_prefixes(words: Sequence[str]) -> Stripped:
    """The command words after assignments and WRAPPERS (G3)."""

def parse_git(stripped: Stripped) -> GitCall | None:
    """The git call in a stripped segment, or None when its command is not git (G3, G5)."""

def bases(links: Sequence[Link], start: Path) -> list[Path | None]:
    """The directory each link starts in; None once a moved cwd is uncertain (G5)."""

def where(site: Site, call: GitCall, base: Path | None) -> tuple[Where, str]:
    """The call's Where and the target its denial names (G5)."""

def git_denial(site: Site | None, links: Sequence[Link]) -> str | None:
    """The first reason to deny a git segment in ``links`` (G4-G7); ``site`` None = unconfined."""

def git_env(run_dir: Path) -> dict[str, str]:
    """The confined step's git environment (G2): ceiling at the resolved run dir, cwd kept."""
```

Helpers are private and small (`_skip_wrapper`, `_global_options`,
`_path_args`, `_is_outside_word`, `_next_base`, `_cd_target`, `_inside`,
`_locked_mention`, `_read_only`). Each is under 8 lines with at most two
parameters. `_read_only(call)` is today's `_git_allowed` (on `call.first` and
`call.words`). `where` returns the target string so `git_denial` can format
`GIT_OUTSIDE` without a second pass. `git_denial` with `site=None` uses
`Where.UNCONFINED` for every git link and never calls `bases`.

  (c) `git for-each-ref` and `git rev-parse HEAD` in `<team>` are the same
  before and after.

## Known limits (stated, not fixed here)

- The guard does not parse `bash -c`, `eval`, `xargs`, `$(…)`, `find -exec`,
  or a git alias, hook or script that names the team repo with an explicit
  `-C`/`--git-dir`. The ceiling (G2) stops *discovery* only. The s61
  checkout guard and the quarantine are the backstops.
- Git run with its cwd exactly the run dir (`.team/run`) still climbs, since
  git does not apply a ceiling to the cwd itself. Workspaces are always
  below it.
- `git -C <ws>/demo worktree add <ws>/x` is checked, but files git writes
  outside the workspace through a workspace repo's own config (for example
  `core.worktree` set by a script) are not.
