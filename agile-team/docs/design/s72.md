# s72: A 1 second limit per unit test

Story: `.team/stories/s72.md`. Developer: `developer-cli`. No ADR (no new
dependency: pytest-timeout is already a dev dependency since s43).

## The world decides the limit

s71 put every test in one of two **worlds** (`tests/os_guard.world_of(item)`):
`FAKE` (unit tests: `FakeSystem` installed, guard on) and `REAL`
(`tests/e2e/` and the `os_guard.LEGACY` files). The limit follows the world, so
there is one rule for "is this a unit test" and it is the one s71 already
enforces.

`LEGACY` files are unit-test files that still run on the real OS (real git,
real processes) until s76 (P2) and s77 (P3) migrate them. They keep the
longer limit until then: a real-git test is exactly the slow test this story
waits for s71 to remove. When s76/s77 take a file out of `LEGACY`, the 1 s
limit applies to it with no further change, and when s77 deletes `LEGACY`
AC1 holds for every file outside `tests/e2e/`.

## Rules

| # | Rule | AC |
|---|---|---|
| L1 | **Unit limit, 1 s.** `[tool.pytest.ini_options] timeout = 1` in `agile-team/runner/pyproject.toml` replaces `timeout = 30`. It is the only place the unit limit is written. | 1, 2 |
| L2 | **e2e limit, 30 s, same table.** `e2e_timeout = 30` sits next to `timeout` in `[tool.pytest.ini_options]`. `tests/conftest.py` registers it with `pytest_addoption` (`parser.addini`, type string, no default), so pytest does not warn about an unknown key. A missing or blank value fails at collection (`float("")` raises); there is no fallback number in code. | 1, 2 |
| L3 | **One function picks the limit.** `time_limit.limit_of(item)` returns `float(item.config.getini(LIMIT_INI[os_guard.world_of(item)]))`. `LIMIT_INI` is a table: `FAKE → "timeout"`, `REAL → "e2e_timeout"`. No branching on paths anywhere else. | 1 |
| L4 | **Every item is marked at collection.** `pytest_collection_modifyitems` in `tests/conftest.py` calls `time_limit.mark(items)`, which adds `pytest.mark.timeout(limit_of(item))` to each item. Under xdist each worker collects, so each worker marks. A marker beats `--timeout` on the command line; to debug without a limit, use `-o timeout=0` (unit) or `-o e2e_timeout=0` (pytest-timeout reads 0 as no limit). | 1 |
| L5 | **The message is pytest-timeout's.** Method stays `signal` (the default), and `timeout_func_only` stays unset, so the limit covers setup, call and teardown. A slow test fails with the FAILED line `FAILED <node id> - Failed: Timeout (>1.0s) from pytest-timeout.`: the node id names the test, `>1.0s` the limit. No custom message. | 1 |
| L6 | **No test sets its own limit.** No file under `agile-team/runner/tests/` except `time_limit.py` contains `mark.timeout`, and none sets `timeout_func_only`. A per-test marker would beat L4's (closest marker wins) and lift the limit. | 1, 3 |
| L7 | **A slow test is fixed, not excused.** Fix it with the fake clock (`system.sleep`, `system.now` on `FakeSystem`), a `FakeSystem` reply instead of a real call, or move it to `tests/e2e/` (the unit-tester lists it as `moves to e2e: <test id> (<what it proves>)`). Never skip, weaken, delete it, add a marker, or raise `timeout`. The limit is measured in the gate's own run (`-n auto --cov`), the slowest setting; a test that fails there only is still slow. | 3 |
| L8 | **Docs move with it.** `reference/protocol.md` § Time limits and `docs/guidelines.md` (architect, done in this step) and the unit-tester role text (developer, below) state the limit. | 4 |

Known today: no FAKE-world test does a real wait (a grep for `sleep(`,
`.wait(`, `timeout=`, `Thread(` outside `tests/e2e/` finds only `LEGACY`
files, `system.sleep` on the fake, and `os_guard`'s own `time.sleep(0)`
check). The implement gate shows any FAKE test that still exceeds 1 s; fix it
per L7.

## Changes per module

### `agile-team/runner/pyproject.toml`

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-q"
timeout = 1        # unit tests (s72); e2e and os_guard.LEGACY use e2e_timeout
e2e_timeout = 30
```

No other change (`uv.lock` untouched: no new dependency).

### New `agile-team/runner/tests/time_limit.py`

```python
"""Per-test time limits (s72): 1 s for unit tests, the e2e limit for the real world.

Both numbers live in ``[tool.pytest.ini_options]``; this module only picks one per test.
"""

from __future__ import annotations

from typing import Any

import pytest

from . import os_guard

E2E_LIMIT_INI = "e2e_timeout"

# Which ini key holds each world's limit (L3). "timeout" is pytest-timeout's own key.
LIMIT_INI: dict[os_guard.World, str] = {
    os_guard.World.FAKE: "timeout",
    os_guard.World.REAL: E2E_LIMIT_INI,
}


def limit_of(item: Any) -> float:
    """The time limit in seconds for ``item``'s world, read from the ini."""


def mark(items: list[pytest.Item]) -> None:
    """Give every item a ``timeout`` marker with its world's limit (L4)."""
```

`limit_of` takes `Any` (like `os_guard.world_of`) so a test can pass a stub
with `.path` and `.config`.

### `agile-team/runner/tests/conftest.py`

Add `from . import os_guard, time_limit` (extend the existing import) and two
hooks, each one line of body:

```python
def pytest_addoption(parser: pytest.Parser) -> None:
    """Register the e2e time limit's ini key (s72 L2)."""
    parser.addini(time_limit.E2E_LIMIT_INI, "per-test time limit (s) for tests/e2e/ and LEGACY")


def pytest_collection_modifyitems(config: pytest.Config, items: list[pytest.Item]) -> None:
    """Mark each test with its world's time limit (s72 L4)."""
    time_limit.mark(items)
```

Update the module docstring's world paragraph with one sentence: unit tests
have a 1 s limit, the real world `e2e_timeout`.
