# s168 design: the house-rules e2e scratch repo builds its own venv

Story: `.team/stories/s168.md`. Requirements: REQ-188 (AC1), REQ-189 (AC2).
ADRs: ADR-0081 amended (rule 6, scratch repos never share a tool's state dir
with the checkout).
Developer: `developer-cli`. It has no work: the only file is the
integration-tester's (`{e2e}`; developers' write scopes exclude it). The
integration-tester makes the change at the e2e step.

## Cause, in one line

The `repo` fixture in `agile-team/runner/tests/e2e/test_s157_house_rules_e2e.py`
symlinks the whole `house-rules/` directory. The first `uv run --project
house-rules/runner` in the scratch repo then creates `house-rules/runner/.venv`
*inside the checkout*, with console scripts whose shebangs name the pytest temp
path. Once pytest prunes that temp dir, every script in the checkout's venv
fails.

## Rules

| # | Rule | AC |
|---|---|---|
| R1 | **The scratch repo owns its `house-rules/runner` directory.** `house-rules/` and `house-rules/runner/` are real directories in `tmp_path`. Only three entries in it are symlinks into the checkout's `house-rules/runner/`: `house_rules` (the package), `pyproject.toml` and `uv.lock`. `.gitignore` is a copy (R4). No other part of `house-rules/` is linked or copied (the commands under test need none). | AC1, AC2 |
| R2 | **So uv builds the venv in the scratch repo.** The commands from `.agile-team.toml` are unchanged (`--project house-rules/runner`, `--project "$PWD/house-rules/runner"`). They now resolve to the real scratch directory, so uv creates `tmp_path/house-rules/runner/.venv`. That venv dies with `tmp_path`. The checkout's `house-rules/runner/.venv` is never created, read or changed by this file, whether or not it existed. | AC1 |
| R3 | **The checkout's own source runs, with no reinstall.** uv installs the project editable (hatchling, `packages = ["house_rules"]`), so the scratch venv imports `house_rules` through the `house_rules` symlink. An edit to the checkout's `house-rules/runner/house_rules/` is seen by the next run. | AC2 |
| R4 | **A copied `.gitignore` keeps the venv untracked.** The scratch venv now sits inside the scratch git tree, and `test_ac1_baselined_and_stale_do_not_refuse` and `test_ac4_fixed_entry_leaves_the_baseline_in_the_step_commit` run `git add -A` after a uv run. So `house-rules/runner/.gitignore` is a real file with the checkout's text (`.venv/`, `__pycache__/`, caches), never a symlink: git (2.32 on) doesn't follow a symlinked in-tree `.gitignore`. `.house-rules.toml`'s `EXCLUDE` (`house-rules/**`, `**/.venv/**`) keeps the scan off it too. | AC1, AC2 |
| R5 | **Why not the other shapes.** `UV_PROJECT_ENVIRONMENT` would keep the whole-dir symlink, so any other tool state uv or a later command writes in the project dir would still land in the checkout; it also hides the fix in an environment variable. Copying `house-rules/` without `.venv` gives up R3 (a copy doesn't see edits). R1 is structural: whatever a tool writes beside the project lands in `tmp_path`. | — |
| R6 | **Each test builds its own venv.** No session-scoped venv: each test's `tmp_path` holds its own, so tests share nothing under `pytest -n 2` (guidelines: no shared state, s130). The cost is one cached uv sync per test (about a second), well under `e2e_timeout = 30`. | AC2 |
| R7 | **No other test changes.** Every existing s157 test keeps its asserts. | AC2 |

## Changes per module

### `agile-team/runner/tests/e2e/test_s157_house_rules_e2e.py` (integration-tester)

- New constants beside `REPO`:
  ```python
  HOUSE_RULES = "house-rules/runner"
  LINKED = ("house_rules", "pyproject.toml", "uv.lock")
  ```
- New helper, documented:
  ```python
  def link_house_rules(scratch: Path) -> None:
      """Give the scratch repo its own `house-rules/runner` dir, linking only the project's files.

      uv then builds the venv in the scratch repo, never in the checkout (s168).
      `.gitignore` is copied: git doesn't follow a symlinked one.
      """
      for name in LINKED:
          link = scratch / HOUSE_RULES / name
          link.parent.mkdir(parents=True, exist_ok=True)
          link.symlink_to(REPO / HOUSE_RULES / name)
      ignore = (REPO / HOUSE_RULES / ".gitignore").read_text()
      write(scratch, f"{HOUSE_RULES}/.gitignore", ignore)
  ```
  (Place it after `write`, which it calls. Split it into a link helper and the
  copy if the house rules' function size asks for it; the behaviour is fixed,
  the shape isn't.)
- In the `repo` fixture, replace
  `(tmp_path / "house-rules").symlink_to(REPO / "house-rules")` with
  `link_house_rules(tmp_path)`. Nothing else in the fixture changes.
- Module docstring: "the real house-rules project (symlinked)" becomes "the
  real house-rules project (its package, pyproject and lock linked into the
  scratch repo's own `house-rules/runner`, so uv builds the venv there)".
- New test (R1–R3), after the fixtures:
  ```python
  def test_s168_house_rules_venv_is_built_in_the_scratch_repo(repo) -> None:
      """s168: uv builds house-rules' venv in the scratch repo and runs the checkout's source."""
  ```
  Body:
  1. `code, out = run(repo, ACCEPT)`; assert `code == 0, out` (any real
     house-rules run through uv builds the venv).
  2. Neither `repo / "house-rules"` nor `repo / HOUSE_RULES` is a symlink.
  3. `venv = repo / HOUSE_RULES / ".venv"`; `venv.is_dir()` and
     `venv.resolve().is_relative_to(repo.resolve())`.
  4. `(repo / HOUSE_RULES / "house_rules").resolve() == (REPO / HOUSE_RULES /
     "house_rules").resolve()` (R3).
  5. The checkout's venv names no part of this scratch repo: for every
     `script` in `(REPO / HOUSE_RULES / ".venv" / "bin")` that `is_file()`
     and is not a symlink (skip the dir when it doesn't exist), read its bytes
     and assert neither `str(repo)` nor `str(repo.resolve())` (encoded) is in
     them; the message names the script. This is AC1's `grep pytest-of`,
     narrowed to this test's own temp path so a venv some other run broke
     can't fail it.
  6. `git(repo, "status", "--porcelain")` lists nothing under `house-rules/`
     (R4: the fixture committed the links and the `.gitignore`, and the venv
     is ignored).
