# s184 design: a `done` at a sprint end waits for the boundary and survives a re-pin

Story: `.team/stories/s184.md`. ADR: ADR-0065 (amended by s184). Requirements:
REQ-227 (AC1), REQ-228 (AC2), REQ-229 (AC3). Developer: `developer-cli`.

## Cause

`notify_user(kind="done")` marks the status `done` at once (`po_tools.py`
`notify_user`). A status is a poor place to keep the PO's done while the end
boundary still runs:

1. Without a re-pin, `done` halts the scheduler (`state.halted()`), so the run ends
   as soon as the running stage ends. The rest of the end boundary (push, CI,
   rebase) never runs in that process.
2. With a re-pin, the passing check sets `state.repin`. `cli._repin_or` marks the
   run `idle` ("re-pinning …"), and the new process's `Scheduler.begin` marks it
   `running`. Both overwrite the `done`. The new process finishes the boundary,
   the router sees a complete sprint under `until-blocker` with ready Product
   Backlog stories, and it sends `next_sprint` three times, then blocks.

The fix keeps the PO's done as its own field, outside the status, until the
boundary closes. `_repin_or` and `begin` stay as they are: they set the status,
and a held done is not a status. Both writes are correct for what they do, so
neither needs to know about `done`.

## Rules

| # | Rule | AC |
|---|------|----|
| D1 | **A done waits for a pending boundary.** A boundary is pending when `state.boundary` is set (either edge), or when the sprint is complete and its end boundary has not closed yet (`sprint_complete()` and `sprint_open()`; `open_end` opens it on the next pass). A `notify_user(kind="done")` that is not refused, sent while a boundary is pending, posts its note as today. It stores its reason in `state.held_done` and leaves the status alone. Otherwise it marks `done` at once, as today. The refusal rule (`KIND_REFUSALS["done"]`, s128/s156) does not change. | AC1 |
| D2 | **The tool says so.** A held done's tool result is `{"id": <mNNN>, "held": DONE_HELD}`, so the PO doesn't send it again. | AC1 |
| D3 | **The done lands when the boundary closes.** `BoundaryRunner._close` releases a held done right after it sets `state.boundary = None`: `mark(DONE, reason)` and `held_done = None`. The scheduler's next `tick` sees `state.halted()` and returns before the router runs, so no `next_sprint` (or any other) hand-over is queued. The run ends once nothing is running. `finish_run` leaves `done` as it is. | AC1, AC3 |
| D4 | **A re-pin carries it.** `held_done` is saved in `state.json`, so a re-pin between the check and the close keeps it. The re-pinned process starts (`begin` marks `running`), runs the rest of the boundary with no PO turn of its own (a bare `--resume`, s128), and stops with `done` when the boundary closes. A held done does not stop the re-pin. | AC1 |
| D5 | **The human's new direction drops it.** A `start` with a task (`--task` or `--task-file`, any mode) sets `held_done = None`. The re-pin's `start --resume` has no task, so it keeps it, and so does a human's bare `start --resume` after a stop. A held boundary (failed CI, waiting on push permission) keeps the done held too: the run waits as the boundary rules say, and the liaison can end it with `agile-team stop`. | AC1 |
| D6 | **The liaison sees it.** `agile-team status` adds `"held_done"`: the held reason, or `null`. Once the run has ended, `status` shows `done` and `status_reason` holds the PO's reason, the first line of its note cut to `REASON_CUT`, as today. | AC3 |
| D7 | **The next-sprint hand-over says how a run ends on purpose.** `NEXT_SPRINT_ADVICE` (the last line of `next_sprint`) keeps "start a sprint" and the PR line. It drops the bare "don't notify done". In its place it says that ready stories alone are no reason for done or blocked. If the human or the liaison said to start no further sprint, the PO notifies `done` quoting them, and the run ends. Otherwise only the liaison ends the run, by resuming with `--cadence sprint`. `NEXT_SPRINT_LEAD`, `KEEP_GOING_CAP` and `KEEP_GOING_STUCK` do not change. | AC2 |

## Changes per module

This section describes the code as built (updated at the design review after the
code review's F1/F2). The first draft put the hold in a `RunState.mark_done` with
`po_tools._record_status` and `_format_held`. The developer put the hold in one
`Tools._hold_done` method on the done path instead, with the same behaviour (D1,
D2), so the design now follows the code. No `mark_done`, `_record_status` or
`_format_held` exists.

### `agile_team/state.py`

- `RunState` gains the field `held_done: str | None = None`, placed after `repin`,
  with the comment `# a PO done waiting for the sprint end boundary (s184)`.
  It loads as a plain JSON value; an old `state.json` without it loads `None`.
- Property:

  ```python
  @property
  def is_boundary_pending(self) -> bool:
      """D1: a boundary is open, or the complete sprint's end boundary hasn't closed."""
      return self.boundary is not None or (self.sprint_complete() and self.sprint_open())
  ```

- Method:

  ```python
  def release_held_done(self) -> None:
      """s184: once no boundary is pending, a held done ends the run."""
      if self.held_done is None or self.is_boundary_pending:
          return
      self.mark(RunStatus.DONE, self.held_done or None)
      self.held_done = None
  ```

### `agile_team/po_tools.py`

- Constant:

  ```python
  DONE_HELD = (
      "Your done is held: sprint {sprint}'s end boundary is still open. The run ends done "
      "when it closes; end your turn."
  )
  ```

- `Tools.notify_user`: the refusal and the posting do not change. Right after the
  post, `if kind == "done" and self.runtime.state.is_boundary_pending: return
  self._hold_done(msg.id, args["text"])`. Every other note (a done with nothing
  pending, `sprint-end`, `blocked`, `update`, …) sets its status as before.
- New method `Tools._hold_done(self, msg_id: str, text: str) -> dict[str, Any]`
  (docstring: `"""s184: keep the PO's done until the sprint end boundary closes."""`):
  sets `state.held_done` to the note's first line cut to `REASON_CUT` (`""` for an
  empty note), saves, and returns
  `text_result({"id": msg_id, "held": DONE_HELD.format(sprint=state.sprint)})`.
- Allowed tidy-up (code review F3, not required): `notify_user` and `_hold_done`
  both cut the first line. If a later step merges them, use the module function
  `_get_first_line(text: str) -> str` (docstring: `"""A note's first line, cut to
  REASON_CUT; "" for an empty note."""`). `_hold_done` stores it as is, and
  `notify_user` records `_get_first_line(text) or None`, so the behaviour stays.

### `agile_team/boundary_runner.py`

- `_close(b, report)`: after `self.runtime.state.boundary = None`, call
  `self.runtime.state.release_held_done()`. This is the only place a boundary
  closes, so both edges and a skipped boundary release it.

### `agile_team/cli.py`

- New `_settle_state(runtime: Runtime, args: argparse.Namespace, start: Start) -> None`
  (docstring: `"""Set the cadence, record the task and drop a held done on the loaded
  state."""`): the lines pulled out of `_prepared` as they were (cadence,
  `_record_task`, `repin.drop_unpinned`), with `_drop_held_done` added after
  `_record_task`. `_prepared` calls it after `_recover_stories`.
- New `_drop_held_done(state: state_mod.RunState, start: Start) -> None`
  (docstring: `"""s184: new work from the human cancels a held done."""`):
  if `start.task`, set `state.held_done = None`.
- `status_report`: add `"held_done": st.held_done` after `"status_reason"`.
- `_repin_or` does not change (see Cause).

### `agile_team/scheduler.py`

No change. `begin` marks `running` and `finish_run` changes only a `running`
status, both as today. `tick` already returns before the router when `ended`.

### `agile_team/sprint_end.py`

```python
NEXT_SPRINT_ADVICE = (
    "Don't end your turn without starting a sprint. Ready Product Backlog stories are no "
    "reason to notify done or blocked, and a PR waiting for review or merge does not hold "
    "the next sprint. A run ends on purpose only when the human or the liaison says so: if "
    "they told you to start no further sprint, notify done quoting them and the run ends. "
    "Otherwise the liaison ends it by resuming with `agile-team start --resume --cadence "
    "sprint`, which stops at every sprint end."
)
```

### `agile_team/roles/product-owner.md` (developer)

In `## Cadence`, the `until-blocker` bullet adds this after "Never wait for a PR
to be reviewed or merged.": "When the human or the liaison tells you to start
no further sprint, `notify_user` `done` quoting them. Sent while the sprint-end
boundary runs, the done is held and the run ends when the boundary closes (the
tool's result says `held`). Don't send it again."

## Tests

Put them in a new `agile-team/runner/tests/test_s184_held_done.py`, one test per
line, using the helpers the s128 and s156 tests use for a runtime with a complete
sprint (`test_s128_keep_going.py`, `test_s156_stuck_sprint_backlog.py`).

- [ ] D1: with `state.boundary` set to an END boundary, `notify_user(kind="done", text="Stop after 52\nmore")` returns `{"id": …, "held": DONE_HELD.format(sprint=…)}`. The status is unchanged, `held_done == "Stop after 52"`, and the note is posted.
- [ ] D1: a complete sprint with `upstream.closed < sprint` and no boundary yet: done is held.
- [ ] D1: a START boundary set: done is held.
- [ ] D1: no boundary and the end boundary closed (`upstream.closed == sprint`): done marks `done` with the reason, `held_done` stays `None`, and the result has no `"held"`.
- [ ] D1: a done refused by `KIND_REFUSALS` (a movable Sprint Backlog story under `until-blocker`) sets no `held_done`.
- [ ] D1: `sprint-end` and `blocked` notes during a boundary set their status as today and hold nothing.
- [ ] D3: `release_held_done` with no boundary pending marks `done` with the reason and clears `held_done`. With a boundary pending it changes nothing. With `held_done == ""` the reason is `None`.
- [ ] D3: `BoundaryRunner._close` on an END boundary, with a done held, leaves the status `done`. With nothing held, the status is unchanged.
- [ ] D3: scheduler with an END boundary whose last stage closes it and a done held, under `until-blocker` with ready Product Backlog stories: the run ends with status `done`, and no `next_sprint` pass is queued or handed over (`keep_going_asks` stays 0).
- [ ] D4: a re-pin round trip: a done held during the END check, `state.repin` set, `_repin_or` (with the exec faked) saves status `idle` and keeps `held_done`. `RunState.from_json` of the saved text keeps it. A new `Scheduler.begin` marks `running`, and closing the boundary then ends the run `done` with the PO's reason.
- [ ] D5: `_prepared`/`_drop_held_done`: a start with `--task` clears `held_done`, and a bare `--resume` keeps it. Test helpers pick the start by passing a `cli.StartMode`, never a `bool` (code review F5; the charter's no-boolean-parameter rule).
- [ ] D6: `status_report` has `held_done` (the reason, or `None`). After the D3 run, `report["status"] is RunStatus.DONE` (not only "not running"; code review F4) and `status_reason` is the PO's first line.
- [ ] D7: `NEXT_SPRINT_ADVICE` holds `--cadence sprint` and "notify done quoting them". It no longer holds "don't notify done or blocked while". The existing s128/s156 tests that compare the last line to the constant still pass.
- [ ] `state.json` written before s184 (no `held_done` key) loads with `held_done is None`.

By hand (AC1, AC3): on a pinned runner with ready Product Backlog stories, let the
PO notify done during the end boundary's check. The run re-pins and finishes the
boundary, then stops. `agile-team status` shows `done` with the PO's reason, and
`events.jsonl` has no `next_sprint` hand-over after the re-pin.
