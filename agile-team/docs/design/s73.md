# s73: The sprint-boundary full check runs the suite once

Story: `.team/stories/s73.md`. Requirements: REQ-045 (AC1, AC3, AC5),
REQ-046 (AC2), REQ-047 (AC4). ADR: ADR-0033 amended by s73.

**Developer:** `developer-cli`. **Modules:** `agile_team/fullcheck.py`,
`agile_team/gates.py` (one helper pulled out), `agile_team/stages.py` (one
description), the dashboard fixture's stage-description source (plus tests).
`reference/protocol.md` was already updated in this design step (AC4).

## Problem

`fullcheck.full_checks` picks every set command from `TOOLCHAIN_CHECKS`, so a
boundary runs `test` (about 4 min) and then `coverage` (about 4 min). The
coverage command runs every test too, so its exit code already proves green or
red. s68 made the same change for the implement gate (`Checks.tests_green_and_covered`).

## Rules

| # | Rule | AC |
|---|---|---|
| F1 | When the `coverage` command is set, `full_checks` leaves the `test` check out. The coverage check is the one run that proves green and gives the total. When `coverage` is not set, `test` runs as today (judged by its exit code). | AC1, AC3 |
| F2 | The order of the remaining checks is unchanged: lint, static, (test), coverage, then each environment's e2e. `TOOLCHAIN_CHECKS` keeps its four rows; which ones are left out is data (`SUPERSEDED_BY`), not a branch. | AC1 |
| F3 | Coverage judging, exit 0: unchanged. No total gives `could not read a coverage total`. A total below `required` gives `coverage {total}% is below {required}%`. Otherwise the check passes. | AC1, AC2 |
| F4 | Coverage judging, non-zero exit: when s68's shared helper `gates.coverage_shortfall(out, required)` returns a total, the run stopped only on coverage (pytest-cov `fail_under`, no failing test). The why is then the same shortfall text as F3: `coverage {total}% is below {required}%`. | AC2, AC5 |
| F5 | Every other non-zero exit gives `exit {code}`: failing tests, an error, or a `&&` chain that stopped early. That is today's text for a failing suite. A non-zero exit **never passes**. | AC2 |
| F6 | A timeout is unchanged: `Judging.result` gives `timed out` before any judge runs. | AC2 |
| F7 | One rule, one copy: the "only the total fell short" test (a total below `required`, and `tests_failed(out)` is False) lives only in `gates.coverage_shortfall`. `Checks._failed_run` (the implement gate) and `fullcheck`'s coverage judge both call it. Neither keeps its own copy. | AC5 |
| F8 | The block format is unchanged: `CHECK_FAILED` (`<name> failed (<why>): <command>` plus the tail). A failing suite now gives one block, `coverage failed (exit 1): <coverage command>` plus the tail. Today that same block was printed alongside a `test failed …` block; after this story the `test` block is gone. The `boundary` event's `checks` summary has no `test` row when `coverage` is set. | AC2, AC3 |
| F9 | Pending-test counts move with the run: the coverage check is already built with the report options (`"coverage" in TEST_COMMANDS`), so its result carries `pending (…)` as the `test` check's did. | AC1 |
| F10 | The `boundary.check` stage's description says the suite runs once: `Lint, static analysis, the full suite with coverage, once, and each environment's e2e, on the team branch`. The stage's recorded time (its `runner-stage` events) covers one suite run. | AC3 |

Why F4 needs "no failing test": pytest-cov prints its total and the
`FAIL Required test coverage … not reached` line even when tests failed, so a
low total alone does not mean the tests passed (s68 C4). This repo's coverage
command has `fail_under = 95`, so a shortfall here always exits 1. Today the
boundary reports that case as `exit 1`. After this story it reports
`coverage 93.0% is below 95.0%`, which is the text the boundary already gives
for a shortfall at exit 0. That is the "same text" AC2 means: one shortfall
text, one failing-suite text (`exit N`).

## Changes in `agile_team/gates.py`

Add a module function next to `tests_failed`:

```python
def coverage_shortfall(output: str, required: float) -> float | None:
    """The total when a non-zero coverage run fell short of ``required`` with no failing test (s68 C4), else ``None``."""
    total = parse_coverage(output)
    short = total is not None and total < required
    return total if short and not tests_failed(output) else None
```

`Checks._failed_run` uses it. Its behaviour and texts do not change:

```python
def _failed_run(self, out: str) -> Outcome:
    """Bounce a non-zero run: shortfall text if only the total fell short, else tests fail."""
    pct = coverage_shortfall(out, self.required_coverage())
    if pct is not None:
        return self._coverage_outcome(pct)
    return Outcome(Verdict.BOUNCE, TESTS_FAIL.format(tail=tail(out)))
```

## Changes in `agile_team/fullcheck.py`

Add the data and one predicate next to `TOOLCHAIN_CHECKS`:

```python
SUPERSEDED_BY: dict[str, str] = {"test": "coverage"}  # one coverage run proves green (s73 F1)


def _wanted(name: str, commands: Mapping[str, str]) -> bool:
    """Whether toolchain check ``name`` runs: its command is set and no set command supersedes it."""
    return bool(commands.get(name)) and not commands.get(SUPERSEDED_BY.get(name, ""))
```

(`from collections.abc import Callable, Mapping`.) In `full_checks`:

```python
chosen = [make(n, j) for n, j in TOOLCHAIN_CHECKS if _wanted(n, commands)]
```

The module docstring and `full_checks`' docstring say `test` runs only when no
`coverage` command is set.

The coverage judge splits by exit code and reuses the helper (F3–F5, F7):

```python
def _coverage_why(run: test_reports.TestRun, judging: Judging) -> str:
    if run.code != 0:
        return _failed_why(run, judging)
    return _total_why(gates.parse_coverage(run.out), judging.required)


def _failed_why(run: test_reports.TestRun, judging: Judging) -> str:
    """A run that stopped only on coverage reads as a shortfall (s68 C4); any other is ``exit N``."""
    total = gates.coverage_shortfall(run.out, judging.required)
    return f"exit {run.code}" if total is None else _total_why(total, judging.required)


def _total_why(total: float | None, required: float) -> str:
    if total is None:
        return "could not read a coverage total"
    return f"coverage {total}% is below {required}%" if total < required else ""
```

`JUDGES`, `Judging`, `CheckResult`, `CheckReport`, `run_checks` and
`boundary_runner` are unchanged.

## Test checklist (unit-tester)

New file `tests/test_s73_boundary_once.py`. Use `FakeRunner` from
`tests/conftest.py` and `config_with` as in `tests/test_fullcheck.py`.

1. **F1 / AC1, AC3:** commands `{"lint": "l", "test": "t", "coverage": "cov"}` →
   `full_checks` names are `["lint", "coverage"]`. Run them with a runner
   giving `cov` `(0, "TOTAL 96%")`: the report passes and `runner.calls == ["l", "cov"]`,
   so `t` never runs.
2. **F1:** `{"test": "t"}` with no coverage → names `["test"]`; `{"test": "t", "coverage": ""}` → `["test"]`.
3. **F2:** `SUPERSEDED_BY == {"test": "coverage"}` and `TOOLCHAIN_CHECKS` is unchanged.
4. **F3 / AC2:** coverage exit 0 with `TOTAL 80%` and required 95 → why exactly
   `coverage 80.0% is below 95.0%`. Exit 0 with no total → `could not read a coverage total`.
5. **F4 / AC2:** exit 1 with `TOTAL … 80%`, `FAIL Required test coverage of 95% not reached`
   and `200 passed` → why exactly `coverage 80.0% is below 95.0%`.
6. **F5 / AC2:** exit 1 with `1 failed, 10 passed` and `TOTAL 80%` → why `exit 1`.
   Pin `CheckReport.reason()` for it: exactly
   `boundary.CHECK_FAILED.format(name="coverage", why="exit 1", command="cov", tail=gates.tail(out))`.
   Also exit 1 with `TOTAL 99%` (no failure marker) → `exit 1`, and exit 2 with no total → `exit 2`.
7. **F6:** coverage exit 124 → why `timed out`.
8. **F7 / AC5:** `gates.coverage_shortfall`: `("TOTAL 80%", 95.0)` → `80.0`;
   `("1 failed\nTOTAL 80%", 95.0)` → `None`; `("TOTAL 96%", 95.0)` → `None`;
   `("no total", 95.0)` → `None`. Then patch `gates.coverage_shortfall` with
   `monkeypatch` to a stub that records its arguments and returns `None`. A
   non-zero fullcheck coverage run gives `exit 1`, and a non-zero
   `Checks.tests_green_and_covered` bounces `tests fail`. Both must have called
   the stub, which proves the two callers share the one helper.
9. **F10 / AC3:** `stages.STAGES[Name.BOUNDARY_CHECK].description` equals the F10 text.
