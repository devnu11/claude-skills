# s143: Requirement references accept dotted AC ids

Story: `.team/stories/s143.md`. ADR: ADR-0060 (amended by s143).
Requirement: REQ-069 (s143/AC1, AC2, AC3). Developer: `developer-cli`.

## Rules

1. A `covers` reference is `s<digits>/<ac id>`. The AC id starts with an ASCII
   letter, then zero or more of: word characters (`\w`: letters, digits,
   `_`), `-` and `.`. So `s141/AC1.1`, `s141/AC8.3` and `s2/a-b_c` are refs.
2. The pattern is still matched with `fullmatch`, so nothing may come before
   or after it (spaces, a second slash, `:`, `!`, …).
3. Every ref that parsed before parses to the same `Ref(story, ac)`: the new
   character class is a superset of the old one, and the groups are unchanged.
4. A malformed ref is still `Problem.BAD_REF` with the unchanged text
   `covers item {n}: {found!r} is not "sN/ACk"`.
5. Nothing else changes: story files never restricted AC ids, so
   `StoryAcs`/`Problem.NO_AC` already compare `AC1.1` as a plain string.
