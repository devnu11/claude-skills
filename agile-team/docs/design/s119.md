A dashboard follow-up to s112 (`design/s112.md` stays the base; the rules
here amend it). The spec is `.team/run/liaison/header-mock-approved.html`.
Three real bugs (AC1–AC3), one pinning AC (AC4), one browser check (AC5).

Developer: **developer-gui**, alone. It touches `index.html` and one line
of `stage_log.py`.

ADR: **ADR-0048 amended** (an open stage row in the heartbeat carries the
stage's `description`). No new dependency, event kind, state field or
snapshot key. The fixture is unchanged.

**Test first (t70).** The unit-tester writes every test below before the

## Why each bug happens (read before fixing)

| AC | today | cause |
|---|---|---|
| AC1 | the goal line is blank or shows the human's task | `renderGoal` writes `view.run.task` (the `--task` text, often `""`). The sprint goal is only in the newest `sprint-start` event's `data.goal`. |
| AC2 | `gate.tests+coverage · 45 s` over `sprint 40 start · check: done` | `stagePanel`'s `line` is `runnerResult(view)`: the newest runner event of any age. |

## Rules

### AC1: the sprint goal

- **G1 Source.** `sprintGoal(view)`: `data.goal` of the newest event with
  `kind === "sprint-start"` in `view.events` (walk backwards), as a
  string; `""` when there is none or its goal is blank. The page derives
  it (ADR-0027 S3: no aggregation in Python), so a `?mock&at=…` replay
  shows the goal of that moment.
- **G2 Text.** `goalText(view)` = `sprintGoal(view) || view.run.task || ""`.
  The task is the fallback for a run with no sprint yet (continuous
  cadence, or before the first sprint start).
- **G3 Render.** `renderGoal(view)` sets `#task`'s `textContent` and
  `title` to `goalText(view)`. Markup, id and the `.task` CSS (one line,
  `white-space: nowrap`, `overflow: hidden`, `text-overflow: ellipsis`)
  are unchanged from s112 HD1/HD5. Plain text: the mock's bold
  "Dashboard readability:" prefix is not derived (Known limits).

### AC2: the stage line describes the open stage

- **ST1 Runner.** `stage_log.open_row(run, start)` gains one key,
  `"description": run.stage.description`, placed right after `"attach"`.
  Key order becomes `stage, when, attach, description, story, step,
  started_at, started_mono, started_slept`. The closing `runner-stage`
  event's data is unchanged (no `description`). `live.HEARTBEAT_VERSION`
  stays 2 (an added key in a row; readers ignore unknown keys).
- **ST2 Page.** `stagePanel`'s `line` becomes `stageLine(row)`:
  `String(row.description ?? "").trim()`, so `""` for a row from an older
  runner. `who` and `when` are unchanged (`⚙ runner · {story or "sprint N"}`,
  `{row.stage} · {age}`). The panel text (who, when, line) names only the
  open stage; no event feeds it.
- **ST3 Removed.** `runnerResult` goes (no other caller). `firstLine` and
  `newestRow` stay (other callers).

### AC3: Markdown lists at full width

- **W1 Child combinators.** Every `.timeline` rule that targets the rows
  targets direct children only:
  ```css
  .timeline > li { display: grid; grid-template-columns: 46px minmax(0, 1fr); gap: 10px; padding: 8px 0; border-top: 1px solid var(--grid); }
  .timeline > li.new { animation: flash 1.6s ease-out; }
  .timeline > li > time { color: var(--muted); font-size: 12px; font-variant-numeric: tabular-nums; padding-top: 1px; }
  ```
  and in the `prefers-reduced-motion` block `.timeline > li.new`. Values
  are unchanged. No selector in the page may read `.timeline li` or
  `.timeline time` (descendant) any more.
- **W2 No new list rules.** Bullets come back by themselves: the UA sets
  `list-style-type` on `ul`/`ol`, which beats the inherited
  `list-style: none` from `.timeline`. `.md ul, .md ol { padding-left: 20px }`
  stays.

### AC4: pinned (no code change expected)

- **P1 Manager flag** is s112 HS2 as built: one
  `<span class="pill flag" title="manager due: …">⚑ manager due</span>`.
  The sprint goal may appear in the flag's `title` (the reason
  `sprint N start: {goal} (…)` holds it) but never in any pill's visible
  text.
- **P2 Live panel** is s112 LP2–LP8 as built: `#lp-who`
  `role · story · step`, `#lp-when` `{age} · {run label}`, `#lp-line` the
  newest tool call, `#lp-msg` shown with the clipped message and clamped
  to 3 lines.

If a P test fails on today's code, that is a bug: the developer fixes the
page, not the test.

## Known limits

- The goal comes from the event log; a run whose log lost its
  `sprint-start` line shows the task instead.
- The mock bolds a "Label:" prefix of the goal; goals are free text, so
  the page shows them plain.
- A replay has no heartbeat, so it cannot show state 2; the proxy checks
  state 2 on a live run or reports it as not checkable.
- A heartbeat written by a runner older than s119 has no `description`;
  the stage line is then blank until the runner restarts.
