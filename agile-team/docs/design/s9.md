Decision record: [`../adr/ADR-006-interrupted-step-commit.md`](../adr/ADR-006-interrupted-step-commit.md).

## The problem in one line

A step cut off by an error, a limit, SIGTERM or a kill leaves its edits
uncommitted. Preflight then refuses the dirty tree, the next step on the
story starts from scratch, and `status` still says `running` with no process
behind it.

## Decision: a commit that is reverted at once (AC2)

The edits go into a commit `chore(team): interrupted step by <role> on
<story>`, and the runner reverts that commit straight away, as quarantine
does. No stash. Roles' Bash may run `git cherry-pick -n` but not
`git stash`, so a role can reuse a commit and could not reuse a stash. A sha
also stays reachable on the branch. Stashes can be dropped, and they are
shared by every worktree. See ADR-006.

## Rules

| # | Rule | AC |
|---|---|---|
| I1 | **In flight.** `Runtime._take_off(plan, brief)` replaces the `STEP_START` emit in `_plan_and_run`. It emits `STEP_START` (unchanged data), sets `state.in_flight = InFlight(role, story id or None, brief)` and saves. The brief is the `StepRequest.brief`: the router's standard brief or the PO's own brief, without the runner's added lines. Refused, returned (`_unpresented`, `_not_up`) and sandbox-refused steps never set it. | AC1 |
| I2 | **Landed.** `settle` ends with `_land(plan)` in place of its final `self.save()`. `_land` sets `state.in_flight = None`, sets `plan.story.interrupted = None` when the step has a story, and saves. A settled step clears the work it was offered (I10), whether or not it reused it. | AC1, AC8 |
| I3 | **Save the tree.** `salvage.save_tree(git, cut)`: when `git.changed_paths()` is empty, return `None`. Otherwise commit **every** changed path, in scope or not, with `git.commit(paths, message)`. The message is `chore(team): interrupted step by <label>` plus the body `cause: <cause>`. Then `git.revert(sha)` and return the sha. The tree is clean afterwards and HEAD has moved by two commits. No `QUARANTINE` event is emitted and no `fixup!`/`feat` commit is made. The story's `commit`, step and rounds do not change. | AC2 |
| I4 | **Who was cut off.** `cut.step` is `state.in_flight`. When it is `None`, the edits belong to the PO's own turn and the step is `salvage.PO_TURN = InFlight("product-owner", None, "the PO's own turn")`. `salvage.capture(git, cut)` returns `None` when no step was in flight **and** the tree is clean. Otherwise it returns `Interruption(role, story, brief, cause, sha)`, with `sha` `None` on a clean tree. | AC2 |
| I5 | **Every halt saves (supersedes H15).** `Runtime.halt_run` calls `save_interrupted(Cause(self.halted_by.kind.value))` on **every** call, before it marks and saves the status. On a second call the tree is normally clean and `in_flight` is `None`, so nothing is recorded. The relay note (first call only) is `halt_note(halted_by, saved)` = `halted_by.message() + salvage.note_suffix(saved)`. The stderr line stays `found.message()`, unchanged. | AC2 |
| I6 | **Error in a role step.** `_step_failed`: for a non-limit exception, call `self.save_interrupted(Cause.ERROR)` before `raise exc`. The exception still reaches the PO unchanged (s8 H5 and its test hold). This way the next `settle_po` never quarantines a cut-off role's work as the PO's. | AC2, AC8 |
| I7 | **Record.** `RunState.interrupt(found)`: set `in_flight = None`. Append `found` to `state.interrupted` when `found.cause in salvage.RUN_ENDING` (every cause but `error`, since the live PO already has the error text). Set `stories[found.story].interrupted = found` when the story exists **and** `found.sha` is not `None`. An interruption without a sha never replaces an earlier offer. | AC2, AC4, AC8 |
| I8 | **Salvage never blocks a halt.** `recovery.Salvager.save` catches `GitError` from `capture`, appends it to `crash.log` (`halt.log_traceback`) and returns `None`. The tree is left as it is, the halt goes on, and preflight later refuses the dirty tree as before. On success it emits `EventKind.STEP_INTERRUPTED` (`"step-interrupted"`), attributed to the step's role and story, with data `{"cause": …, "commit": sha or None, "brief": …}`. | AC2 |
| I9 | **Killed outright.** `cmd_start` calls `_recover(config, start)` before `_require_preflight`. With `--resume` and `state_mod.shown_status(run_dir, state) is RunStatus.INTERRUPTED`, `recovery.recover_killed(run_dir, git)` saves the tree with cause `killed` (I3, I4, I7), saves `state.json` and returns the interruption. When it has a sha, cli prints to stderr `agile-team start: the last run was killed; <label>'s edits are saved in <sha> (reverted)`. Any other case does nothing, so a dirty tree with no interrupted run behind it (any status other than `running`, or `running` with a live pid) is refused by preflight exactly as today. A plain `start` (not `--resume`) does not recover. | AC3 |
| I10 | **Offer in the next brief.** `dispatch._story_lines` appends `salvage.offer(story.interrupted)` when it is set, after the dispute and rework lines. Every role's prompt on that story gets it, whether from a standard brief or the PO's own brief, until a step on the story settles (I2). The sha comes from `state.json`. Template (exact): ``Interrupted work: an earlier {label} step was cut off ({cause}). Its edits are saved in commit {sha} and reverted. Reuse them with `git cherry-pick -n {sha}` and check them before you build on them; files outside your write scope are quarantined again.`` | AC8 |
| I11 | **Resume prompt.** `PoRun._opening` takes `salvage.resume_section(state.interrupted)`, clears the list and saves (`_take_interrupted`). The section goes after the opening prompt in every mode: `first_prompt` with no session, and `resume_prompt(task)` with one. With a session, no `--task` and a non-empty section, the PO gets a turn **before** any router pass (today that case starts with a router pass). With an empty section, behaviour is unchanged. | AC4 |
| I12 | **Liveness.** `state_mod.runner_pid(run_dir)` returns the `int` in `runner.pid`, or `None` when the file is missing, does not parse, or holds a value `<= 0` (`os.kill(0, 0)` would signal the process group). `pid_alive(pid)` calls `os.kill(pid, 0)`: `ProcessLookupError` → `False`, `PermissionError` → `True`, no error → `True`. `runner_alive(run_dir)` = pid is not `None` and `pid_alive(pid)`. | AC5 |
| I13 | **Shown status.** `state_mod.shown_status(run_dir, state)` returns `RunStatus.INTERRUPTED` when `state.status is RunStatus.RUNNING` and not `runner_alive(run_dir)`. Otherwise it returns `state.status`. `INTERRUPTED` is never written to `state.json`. `status_report["status"]` and the snapshot's `run.status` both use it, and `status_report["running"]` is `runner_alive(run_dir)`. A stale `runner.pid` is therefore ignored by `status`, the dashboard and `recover_killed`. `start`'s `pid_file` overwrites it. | AC5 |
| I14 | **Status shows the work.** `status_report` gains `"in_flight"` (`asdict` or `None`) and `"interrupted"` (the pending list as dicts), directly after `"running"`. Stories already carry their `interrupted` field through `asdict`. | AC5, AC6 |
| I15 | **Legacy state.** `state.json` without `in_flight`, `interrupted` or a story `interrupted` loads with `None` / `[]`. `Interruption.__post_init__` turns a loaded `cause` string back into `Cause`. | AC1 |

### The `Cause` table

`salvage.Cause(StrEnum)`: the first three values equal `halt.HaltKind`'s, so
`Cause(kind.value)` maps a halt.

| Cause | Where | In `RUN_ENDING` (PO told at resume) |
|---|---|---|
| `error` | `_step_failed`, non-limit exception | no |
| `limit` | `halt_run` | yes |
| `crash` | `halt_run` | yes |
| `sigterm` | `halt_run` | yes |
| `killed` | `recover_killed` on `start --resume` (kill -9, power loss, Ctrl-C) | yes |

### Texts (exact; tests may assert them)

`label`: `"{role} on {story}"`, or `"{role}"` with no story.

| Name | Template |
|---|---|
| `salvage.SUBJECT` | `chore(team): interrupted step by {label}` |
| `salvage.NOTE_SUFFIX` | `; {label}'s edits are saved in {sha} (git cherry-pick -n {sha})` (only with a sha; otherwise `note_suffix` returns `""`) |
| `salvage.OFFER` | see I10 |
| `salvage.RESUME_HEAD` | `## Interrupted steps\n\nThe runner saved each cut-off step's edits in a commit and reverted it.` |
| `salvage.RESUME_ITEM` | `- {label} ({cause}): {saved}\n  Brief: {brief}`, where `saved` is ``edits saved in {sha}; reuse with `git cherry-pick -n {sha}` `` or `no edits`, and the brief's newlines are indented by four spaces |
| `salvage.RESUME_TAIL` | `Re-run each step. On a story, the runner offers the saved commit in the next brief on that story; for any other step, put the cherry-pick line in your brief.` |

`resume_section([])` is `""`. Otherwise it is head, items (one per line) and
tail, joined by blank lines between the three parts.

Example of a limit note:

```text
session limit, resets 2:20pm (America/Edmonton); run `agile-team start --resume` after the reset; developer-cli on s7's edits are saved in 3f2a…e1 (git cherry-pick -n 3f2a…e1)
```

## Flow

```mermaid
flowchart TD
  start[run_role] --> take[_take_off: STEP_START, in_flight saved]
  take --> exec[_execute]
  exec -- returns --> settle[settle ... _land: in_flight=None, story.interrupted=None]
  exec -- limit --> hr[halt_run → save_interrupted cause]
  exec -- other Exception --> err[save_interrupted error → re-raise]
  exec -- CancelledError / crash at top level --> hr
  exec -- kill -9 / Ctrl-C --> dead[(state running, in_flight set, pid dead or gone)]
  dead -- start --resume --> rec[recover_killed: killed]
  hr & err & rec --> sv[Salvager.save: commit all, revert, record, event]
  sv --> brief[next brief on story: offer sha]
  sv --> po[next PO opening: Interrupted steps section]
```

## Known limits

- `stop --now` with a stale `runner.pid` still sends SIGTERM to that pid
  (unchanged; `status` shows `interrupted`, so the liaison can tell).
- The dashboard rebuilds its snapshot when a run file changes. After a
  `kill -9`, nothing changes, so it shows `interrupted` only on its next
  rebuild or reload.
- A pid reused by an unrelated process looks alive: `status` says `running`,
  and `start --resume` refuses the dirty tree. The human can delete
  `runner.pid`.
- If `settle` itself raises midway (for example a git error while
  committing), `in_flight` stays set until the next step overwrites it.
- Plain quarantine of a settled step's out-of-scope edits is unchanged and is
  not offered in briefs. That is not interrupted work. It still reaches the
  PO through the `quarantine` hand-over.
