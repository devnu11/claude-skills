# s124: A sprint ends only when every story in it is done, cancelled or reverted

Story: `.team/stories/s124.md` (ACs from the human's t83 and t84). ADR: **ADR-0057** (new).
Developer: `developer-cli`. It also edits `dashboard/index.html` (two pills, one
`TIMELINE` row) and the built-in `roles/product-owner.md`.

Three parts:

1. **End rule (AC1).** There is one predicate for "the sprint is finished". The end
   boundary opens only when it holds. The PO's `notify_user(kind="sprint-end")` is
   refused while it does not hold, and the refusal names each unfinished story and its step.
2. **Revert (AC2).** `revert_story(story, reason)` is a PO tool. It reverts the story's
   commits in one `revert(sN): <title>` commit and puts the story back in the backlog at
   the step before `tests`. The runner does all the bookkeeping: story file, event, Board,
   PR, briefs, a design check and a notification. A second revert of the same story asks
   the human first.
3. **Keep working (AC3).** When nothing in the sprint can move, the router hands the PO
   the ready backlog stories once (new trigger `ready_backlog`). It does this even while
   a question is open. The PO adds them with `add_to_sprint` (s122).

## Rules

| # | Rule | AC |
|---|------|----|
| E1 | **Finished sprint.** `RunState.sprint_complete()` is `bool(self.sprint_ids()) and not self.unfinished_in_sprint()` (s122 helpers; unfinished = status not in `FINISHED`). A cancelled or reverted story has `sprint = None`, so it never keeps a sprint open. | AC1 |
| E2 | **End boundary.** `BoundaryRunner.open_end()` opens `Boundary(Edge.END, N)` only when there is no boundary, `state.sprint_complete()` holds, and `upstream.closed < N`. `Router._idle` hands over `sprint_end` under the same predicate. Today's inline "all `DONE`" checks are removed (DRY). | AC1 |
| E3 | **Refused end.** `notify_user` with kind `sprint-end` is refused while `state.unfinished_in_sprint()` is non-empty. The text is `END_REFUSED` (below), with each story as `sN at <step>` in sprint order. Nothing is posted and the status is unchanged. Every other kind behaves as today. | AC1 |
| R1 | **Tool.** `revert_story(story, reason)` is a PO tool (a `SCHEMAS` row). It checks in this order and the first refusal wins. A refusal changes, saves, posts and emits nothing. (1) The checkout moved: returns `halted_report` exactly as `pass_tests` does. (2) A boundary is pending: `SPRINT_REFUSAL_BOUNDARY` (via `Tools._boundary_refusal`). (3) Unknown story: `story_admin.UNKNOWN`. (4) Blank reason: `story_admin.NO_REASON`. (5) Done or cancelled: `story_admin.FINISHED_TEXT` with verb `revert`. (6) A cancel or revert question is pending: `story_admin.asked_text(story)`. (7) `story.commit is None`: `NOTHING_TO_REVERT`. (8) A started, unfinished story lists it in `depends_on`: `DEPENDED_ON`. (9) `story.commit` is not an ancestor of HEAD: `NOT_ON_BRANCH`. | AC2 |
| R2 | **Second revert asks.** When the checks pass and `story.reverted` is non-empty, the runner reverts nothing. It posts `REVERT_QUESTION` (kind `question`, naming the story), sets `po_hold = PoHold(HoldKind.REVERT, reason, question_id)`, saves, and emits one `story-admin` event (`tool: "revert_story"`, as the s53 tools do). It returns `{"status": "revert requested", "story", "step", "question"}`. The router skips the story while the hold stands (a new `WAITS` row shows it). | AC2 |
| R3 | **Settling the answer.** A revert question is settled at the same three points as a cancel request: the start of each router tick (right after `clerk.settle()`), in `wait_for_answers` after it polls, and at the start of `revert_story`. The answer is read as in s53: stripped of spaces and `.!"'`, case-blind. `revert`: the runner reverts (R4) with the PO's reason and the question id. If the revert then fails (R1 (7)–(9) or a git conflict), it sets a `PO hold` with `REVERT_FAILED`. `keep`: `po_hold = None`. Any other answer: a `PO hold` with `UNCLEAR_REVERT`. Each settlement emits one `story-admin` event: role `null`, data `{"tool": "answer", "reason", "question", "answer", "decision", "before", "after"}`, plus `"failed": why` when the revert failed. | AC2 |
| R4 | **The revert.** Each step must succeed before the next starts. (a) `runtime.settle_po()` commits the PO's open edits so the tree is clean. (b) The story's commits are `revert_log.story_commits(git.log_from(story.commit), git.subject(story.commit))`: every commit from the first recorded one to HEAD whose subject is the first commit's subject or `fixup! ` + it, oldest first. (c) `git.revert_all(newest first, message)` makes **one** commit, `revert(sN): <title>`, with body `Reverts <short shas>.` and `Reason: <reason>`. On a conflict it aborts, leaves HEAD and the tree as they were, and the tool returns `REVERT_CONFLICT` (state, story file, events unchanged). (d) The story file gets its entry (R5) in a second commit, `chore(sN): record the revert in the story file`; the file can't name its own commit. (e) `runtime.record_checkout()`. (f) The state changes (R6), then a save. (g) One `story-reverted` event (R7). (h) The notification (R10). | AC2 |
| R5 | **Story file entry.** `.team/stories/<id>.md` (`story_spec.file_of`) gets one bullet appended at the end: `- <date>, sprint <N>: <reason> Reverted commits: <short>, <short>. Revert commit: <short>.` Before the first entry, a `## Reverted` heading goes in (a blank line, the heading, a blank line). Dates are UTC `YYYY-MM-DD` from `system.now()`. Short shas are 12 characters. The frontmatter is untouched, so `story_spec.parse` still passes. | AC2 |
| R6 | **State.** `state.stories[id]` is replaced by `reverts.reverted_story(story, Back(...))`. This is a fresh `StoryState` that keeps `id`, `title`, `depends_on`, `developer`, `po_developer` and the old `reverted` list. It appends the new `RevertEntry` and sets `revert_owed` to the roles that worked on the story (R8), `step = back_step(...)` and `sprint = None`. Every other field takes its default: commit, code_commits, rounds, holds, dispute, test_files, files, fixes, tried and so on. `back_step(steps, current)` is the step just before `tests` in `pipeline.steps` (the first step when there is no `tests`, or it is first). The current step is kept when it comes earlier. The id leaves `state.pulled`. `order` and `human_order` are unchanged, so the story keeps its backlog place. | AC2 |
| R7 | **Event.** There is exactly one `story-reverted` event (`EventKind.STORY_REVERTED`, role `product-owner`, story id). Its data: `{"sprint": state.sprint, "reason", "commits": [full shas, oldest first], "revert": sha, "record": sha, "count": len(reverted), "from_step", "step", "roles": revert_owed, "question": id or null}`. | AC2 |
| R8 | **Brief note.** At revert time, the roles that worked on the story are the distinct `role` values of the `step-end` events whose `story` is the id, in first-seen order (`reverts.worked_roles`). When such a role's step on the story is planned, `Runtime.user_prompt` adds `revert_log.brief_section(story.reverted, story.step)`, and `Runtime.plan` then removes the role from `story.revert_owed` and saves. Each role gets the note once per revert. | AC2 |
| R9 | **Design says what changes.** In a brief for the `design` step of a story with `reverted` entries, the section ends with `REDESIGN_LINE`, whether or not the role is owed. The design gate checks the same thing: a `done` at step `design` on a story with `n = len(reverted) > 0` passes only when the design file `{docs_dir}/design/{id}.md` has a line matching `^##\s+After revert {n}\b` (case-blind). Otherwise it is `Outcome(BOUNCE, REDESIGN_MISSING, "design", author=Author.ROLE)`, which counts a round as any role bounce does. | AC2 |
| R10 | **Notification.** `relay.post(Note("update", NOTICE, [id]))`: the story, its title, the sprint, the reason, the reverted commits, the revert commit and the step it is back at. | AC2 |
| R11 | **Board and Backlog.** The snapshot's story dict gains `reverts: len(story.reverted)`. A story with `reverts > 0` shows a pill `reverted (n×)` (tone `warning`, no dot) on its Board card and its Backlog row. Activity gains a `story-reverted` row. | AC2 |
| R12 | **Review PR.** `StackEntry.reverted` (new, default `[]`) holds the ids of stories with a `RevertEntry` whose `sprint == b.sprint`, in state order, filled by `_entry`. `_body` adds a `Reverted:` block after the stories, with one line per such entry: `- sN: <title>: <reason> (reverted <shas>; revert <sha>)`. The block is empty when there are none, which leaves today's body unchanged. Reverted stories have `sprint = None`, so they are not in `stories`. | AC2 |
| K1 | **Ready backlog.** `sprint_end.ready_backlog(stories, queue)` gives the ids, in queue order, of stories with `sprint is None`, status `ACTIVE`, no `hold`, no `po_hold`, and an empty `dependencies.waiting_on`. | AC3 |
| K2 | **Offer once.** `Router._idle` runs in this order. (1) No boundary and `sprint_complete()`: `sprint_end`, as today. (2) The sprint is open (`state.sprint_open()`), no boundary is pending, the sprint has unfinished stories, the ready list is non-empty, and `key = [*unfinished ids, *ready ids]` differs from `state.offered`: set `state.offered = key`, save, and return `Pass([Trigger.READY_BACKLOG], lines, [])`. (3) An open question: wait, as today. (4) Otherwise `stalled`, as today. The offer names no stories, so it holds none. `READY_BACKLOG` is not in `QUIET_AFTER_PO`, so a PO turn that ends with an offer pending gets that offer instead of ending the run. | AC3 |
| K3 | **Offer lines.** `Nothing in sprint N can move.`, then today's per-story stall lines (`_stall_lines`), then `READY_HEAD`, up to `READY_SHOWN = 5` lines `- sN: <title>`, `READY_MORE` when there are more, and `READY_ADVICE`. | AC3 |
| D1 | **Docs and prompt.** The PO role file, `SKILL.md`, `reference/protocol.md`, the README row and `docs/customer/backlog-and-sprints.md` describe the rule (texts below; the Architect has written the docs, and the developer writes the role file). | AC5 |

### `agile_team/git_ops.py` (`Git`)

```python
def is_ancestor(self, sha: str) -> bool:
    """``git merge-base --is-ancestor <sha> HEAD`` exits 0."""
def log_from(self, first: str) -> list[tuple[str, str]]:
    """(sha, subject) of ``first`` and every commit after it up to HEAD, oldest first."""
def revert_all(self, shas: Sequence[str], message: str) -> str:
    """Revert ``shas`` (newest first) in one commit with the trailer; on failure abort and raise GitError."""
```

`log_from`: `[(first, self.subject(first))]` plus `log --reverse --format=%H%x1f%s first..HEAD`, split on `\x1f`. `revert_all`: `reset -q`, then `attempt("revert", "--no-commit", *shas)`. On a non-zero exit, read `diff --name-only --diff-filter=U`, run `attempt("revert", "--abort")`, and raise `GitError(f"conflicts in {paths}")` (or the output when no paths). Otherwise `commit --no-verify -m with_trailer(message)` and return `head()`.
