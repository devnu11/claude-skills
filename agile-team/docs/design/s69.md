# s69: Only the runner runs the full suite

**Developer:** `developer-cli`. **Modules:** new `agile_team/suite_check.py`,
`agile_team/results.py`, `agile_team/runner_tools.py`; changes in `guard.py`,
`gates.py`, `dispatch.py`, `config.py`, `events.py`, `po_tools.py`, and the role
files `roles/_shared.md`, `developer.md`, `unit-tester.md`, `quality-czar.md`,
`code-reviewer.md`, `integration-tester.md`. This design step already updated
`reference/protocol.md`, `SKILL.md`, the README row and `docs/customer/routing.md`.

**Round 1 amendment (review D1, D2):** S1 skips leading `NAME=value` words and
adds `exec`/`command`/`xargs` to `LAUNCHERS`; S4 needs **every** positional word
to be a target; `VALUE_OPTIONS` grows; S10 names `python -mpytest`. Checklist
items 1–2 gain the rows. Order: unit-tester (rows, plus its own fixes: the PO
test helper identifies the PO by its `team` MCP server, and the E501 in
`tests/pipeline_helpers.py`), then developer-cli (`_command_words`,
`_positionals_after`, constants).

**Design review amendment:** the developer's `REDIRECT` constant (redirect words
are not positionals) is adopted into S4 and the constants; the over-deny of a
spaced redirect target is accepted and documented in protocol.md.

## Problem

Agents spend about 62% of their step time in tools, mostly full pytest runs
(`.team/run/liaison/reports/2026-10-12-time-spent.md`). Five roles plus the gate
run the suite in every story pass. The human's rule: **agents never run the full
suite or coverage.** The runner runs them and hands the results to the roles.

## Rules

### Bash denial (AC4, AC5): `suite_check.py`, called by `guard.py`

| # | Rule |
|---|---|
| S1 | A Bash segment (the guard's segments: split on `\|\|`, `&&`, `;`, `\|`, `&`, newline, then shlex words) starts a test run only when its **first command word** is a launcher: `PurePosixPath(word).name` is in `LAUNCHERS`, or starts with `python`. The first command word is the first word that is not an environment assignment (`ASSIGNMENT`: matches `^[A-Za-z_][A-Za-z0-9_]*=`), so `PYTHONPATH=. pytest -q` and `FOO=1 uv run pytest` are seen as `pytest -q` and `uv run pytest` (review D2). `LAUNCHERS` also holds `exec`, `command` and `xargs`, so `exec pytest`, `command pytest` and `… \| xargs pytest` are seen. So `grep -n pytest x`, `rg -- --cov`, `echo pytest` start nothing. |
| S2 | In a segment whose first word is a shell (`SHELLS`: `bash`, `sh`, `zsh`), the word after `-c` is split on whitespace and its words take its place, so `bash -c "pytest -q"` is seen as `bash -c pytest -q`. |
| S3 | `Run.COVERAGE`: the segment holds the word `coverage` followed at once by `run`, or holds a test tool word (`TEST_TOOLS`: `pytest`, `py.test`, by `PurePosixPath(...).name`) and any word that starts with `--cov`. Checked before S4, so `pytest --cov tests/test_x.py` is a coverage run. |
| S4 | Otherwise, with a test tool word: take the **positional words** after the first test tool word, that is every word that does not start with `-` and is not the value of a `VALUE_OPTIONS` option (the word right after one of them; see the constant). `Run.TARGETED` when there is at least one positional word and **every** positional word is a target (S5); else `Run.FULL`. So `pytest tests/test_x.py tests/` and `pytest tests/test_x.py .` are `FULL` (review D1), matching `run_tests`, which checks every id (R2). A value given with a space to an option not in `VALUE_OPTIONS` (`--foo 1`) counts as a positional and makes the run `FULL`: over-deny is the rule for enforcement (s7); the agent writes `--foo=1`. A word that matches `REDIRECT` (`^\d*[<>]`: `>out`, `2>`, `<in`) is not a positional; the guard splits `2>&1` on `&`, which leaves `2>` as a word, so `pytest -q tests/test_x.py 2>&1 \| tail -5` stays `TARGETED`. A redirect target written after a space (`> /tmp/out`, `2> err.log`) is a positional and makes the run `FULL` (accepted over-deny, design review round 1); the agent writes `>/tmp/out` or pipes to `tail`. |
| S5 | `is_target(word)`: the word does not start with `-`; its path part (before the first `::`) ends in `.py` and holds none of `*`, `?`, `[`. So `tests/test_x.py` and `tests/test_x.py::test_y` are targets; `tests/`, `tests/e2e`, `tests/*.py` and `-k foo` are not. |
| S6 | No test tool word and no `coverage run`: no run (`None`). |
| S7 | `SUITE_RULES` is the one table of who may not start which run. The first row whose `run` matches and that `applies(role)` gives the denial, formatted with `role`. A row applies when the role is not in `allowed` and (`EVERY_ROLE` is in `denied` or the role is in `denied`). |
| S8 | Rows: `FULL` and `COVERAGE` are denied to every role but `devops` (it owns the toolchain commands and the onboarding baseline; see Open question). `TARGETED` is denied to `code-reviewer` and `quality-czar`. Every other targeted run passes. |
| S9 | The guard runs the suite check on every view, after the kill check (`_check_view`'s last entry). First denial wins, as for the other checks. |
| S10 | Residual risk (documented in protocol.md): a script or `make` target that runs pytest inside it, `$VAR` commands, `python -mpytest` (no space; `python -m pytest` is seen) and other test tools (`go test`, `cargo test`, `npm test`) are not seen. Another tool is one more row in `TEST_TOOLS`/`SUITE_RULES` later. |

| # | Rule |
|---|---|
| B1 | The tests gate (`Checks.tests_red`, and so `tests_reworked`) and the implement gate (`Checks.tests_green_and_covered`) return their run in `Outcome.ran`: `Ran(name, code, result_tail(out))` with `name` `"test"` or `"coverage"`. |---|---|

### The developer's runner tools (AC2): `runner_tools.py`

| # | Rule |
|---|---|
| R1 | Every developer step (`role_fits_step(role, "implement")`) gets an in-process MCP server `runner` with two tools, `run_tests` and `run_new_tests` (allowed as `mcp__runner__run_tests`, `mcp__runner__run_new_tests`). Other roles get none. |
| R2 | `run_tests({"tests": [...]})` refuses an empty list (`NO_TESTS_NAMED`) and any id that is not a target by S5 (`NOT_A_TARGET`). So no request can run the full suite or a directory. |
| R3 | Each id's file part (before `::`) resolves with `Checks.tracked` (s30: repo-relative, or the one tracked file ending with it). An unresolved id refuses (`UNTRACKED_TEST`). The id is then `located(test, path)`: the repo path plus the id's `::…` rest. |
| R4 | Each located id goes to the `[[toolchain.targeted]]` row with the **longest** `root` that holds its path (`""` holds every path). No row: refuse (`NO_ROOT`); no rows at all: refuse (`NO_TARGETED`). Refusals are checked before anything runs; the reply is `{"status": "refused", "reason": …}`. |
| R5 | One `Batch` per row, rows in first-seen order, ids relative to the row's `root`, each `shlex.quote`d and space-joined into the row's `command` with `str.replace("{tests}", …)` (other braces stay as they are). |
| R6 | `run_new_tests({})` runs the story's `test_files` that match `TEST_FILE_NAMES` (`test_*.py`, `*_test.py`, by file name) and are files in the repo now, through the same path as `run_tests`. No story: refuse (`NO_STORY`); none left: refuse (`NO_NEW_TESTS`). |
| R7 | The runner records `test_files`: when a tests-step role (`role_fits_step(role, "tests")`) commits, every committed path not yet listed is appended, in order. Legacy stories load with `[]`. |
| R8 | The batches run inside one `pulse.doing(TESTS_CHORE)` (a runner chore), each through `await asyncio.to_thread(checks.run, command)` so the SDK stream keeps draining. The gates' `command_timeout_s` applies. |
| R9 | One `tests-run` event per call (`EventKind.TESTS_RUN`), attributed to the plan's role and story: `{"tests": [located ids], "exits": [codes], "seconds": <float, 1 decimal, time.monotonic>}`. Refusals log nothing. |
| R10 | Reply: `{"status": "ran", "runs": [{"command", "exit", "output": result_tail(out)}], "seconds"}`. |

### `agile_team/suite_check.py` (new; pure, no I/O, stdlib only)

```python
class Run(StrEnum):
    """What a Bash segment asks a test tool to do (s69)."""
    FULL = "full"
    COVERAGE = "coverage"
    TARGETED = "targeted"

EVERY_ROLE = "*"
TEST_TOOLS = frozenset({"pytest", "py.test"})
SHELLS = frozenset({"bash", "sh", "zsh"})
LAUNCHERS = frozenset({"uv", "uvx", "poetry", "pipenv", "hatch", "pdm", "timeout",
                       "gtimeout", "env", "nice", "time", "nohup", "coverage",
                       "exec", "command", "xargs",
                       *SHELLS, *TEST_TOOLS})          # plus any name starting "python"
ASSIGNMENT = re.compile(r"^[A-Za-z_][A-Za-z0-9_]*=")   # a leading NAME=value word (S1)
REDIRECT = re.compile(r"^\d*[<>]")                      # a redirect word, never a positional (S4)
# Options whose value may follow as the next word (S4). Every entry takes a value
# in pytest or a common plugin, so skipping the next word never hides a path
# pytest would collect.
VALUE_OPTIONS = frozenset({"--ignore", "--ignore-glob", "--deselect", "-c", "--confcutdir",
                           "--rootdir", "--basetemp", "-k", "-m", "-p", "-o",
                           "--tb", "--maxfail", "--durations", "-W", "-r", "-n",
                           "--timeout"})
NODE_MARK = "::"
GLOB_CHARS = ("*", "?", "[")

@dataclass(frozen=True)
class SuiteRule:
    """Who may not start one kind of test run, and the reason they are told (S7)."""
    run: Run
    denied: frozenset[str]
    reason: str
    allowed: frozenset[str] = frozenset()

    def applies(self, role: str) -> bool:
        """Whether this row denies ``role``."""

SUITE_RULES: tuple[SuiteRule, ...] = (
    SuiteRule(Run.FULL, frozenset({EVERY_ROLE}), FULL_DENIED, frozenset({"devops"})),
    SuiteRule(Run.COVERAGE, frozenset({EVERY_ROLE}), COVERAGE_DENIED, frozenset({"devops"})),
    SuiteRule(Run.TARGETED, frozenset({"code-reviewer", "quality-czar"}), READ_ONLY_DENIED),
)

def is_target(word: str) -> bool:
    """A test file or node id, the thing a targeted run names (S5)."""

def run_kind(words: list[str]) -> Run | None:
    """The kind of test run one Bash segment starts, or None (S1–S6)."""

def suite_denial(role: str, words: list[str]) -> str | None:
    """The first SUITE_RULES reason for ``role`` and this segment, or None (S7)."""
```

## Test checklist (unit-tester)

`suite_check` (pure; feed word lists as the guard makes them):

1. **S4/S5 targeted passes:** `pytest -q tests/test_x.py`, `pytest tests/test_x.py::test_y`,
   `uv run --directory agile-team/runner pytest -q tests/test_x.py` → `Run.TARGETED`,
   and `suite_denial("developer-cli", …)` is None. Also `TARGETED`:
   `pytest tests/test_a.py tests/test_b.py::t`, `pytest --tb short tests/test_x.py`,
   `pytest --maxfail 1 -x tests/test_x.py`, `PYTHONPATH=. pytest tests/test_x.py`.
2. **S4 full:** `pytest`, `pytest -q`, `pytest tests/`, `pytest tests/e2e`,
   `pytest tests/*.py`, `pytest -k test_x.py`, `pytest --ignore tests/test_x.py`,
   `python -m pytest -q`, `uv run pytest -x`, `timeout 600 uv run pytest` → `Run.FULL`.
   **D1:** `pytest tests/test_x.py tests/`, `pytest tests/test_x.py .`,
   `pytest tests/test_x.py -- tests/e2e`, `pytest --foo 1 tests/test_x.py` → `Run.FULL`.
   **D2 (S1):** `PYTHONPATH=. pytest -q`, `FOO=1 uv run pytest`,
   `A=1 B=2 python -m pytest`, `exec pytest`, `command pytest -q`, `xargs pytest` → `Run.FULL`;
   `COVERAGE_FILE=x pytest --cov` → `Run.COVERAGE`; `FOO=1 echo pytest`, `FOO=1` alone → None.
3. **S3 coverage:** `pytest --cov`, `pytest --cov=agile_team tests/test_x.py`,
   `uv run pytest --cov-report=term`, `coverage run -m pytest tests/test_x.py` → `Run.COVERAGE`.
4. **S1/S6 no run:** `grep -n pytest x.py`, `rg -- --cov`, `echo pytest`, `ls tests`,
   `coverage report` → None.
5. **S2:** `bash -c "pytest -q"` → `Run.FULL`; `sh -c "pytest tests/test_x.py"` → `Run.TARGETED`.
6. **S7/S8 table:** FULL and COVERAGE are denied to `developer-cli`, `unit-tester`,
   `integration-tester`, `code-reviewer`, `architect`; allowed to `devops`. TARGETED is
   denied to `code-reviewer` and `quality-czar` (reason starts `code-reviewer reads tests`),
   allowed to the others.
7. **AC4 reasons:** the FULL and COVERAGE reasons equal `FULL_DENIED` / `COVERAGE_DENIED`
   and hold `run_tests` and `run_new_tests`.
8. **S9 guard:** `guard.check_bash(scope("developer-cli"), "cd x && uv run pytest -q 2>&1 | tail -5")`
   returns `FULL_DENIED`; the same with `tests/test_x.py` returns None; the pre-tool hook
   denies with that reason. A command with a `#` comment still denies
   (`uv run pytest -q  # everything`).

`results`:

9. **B3:** `keep` then `latest` round-trips a `Ran`; a second `keep` of the same name replaces it;
   `latest` of a missing or corrupt file is None; files land at `<run_dir>/results/<story>/<name>.json`.
10. **B4/B5:** `shown(story, "quality")` returns coverage, lint, static in that order and skips
    missing ones; `shown(story, "design")` is `[]`; `section([])` is `""`; `section` holds
    `## Runner results`, `### coverage: exit 0 (implement gate, at 1234567)` and the tail in a fence.
11. **B6:** `result_tail` keeps exactly the last 60 lines.

`gates` (fake runner as in `tests/test_gates.py`):

12. **B1:** `tests_red` red and green, and a timeout, return `ran == Ran("test", code, tail)`;
    `tests_green_and_covered` pass, shortfall and `tests fail` return `ran.name == "coverage"`;
    s68's assertions (one `"C"` call, texts) still hold.

`dispatch` (existing runtime fakes):

13. **B2 / AC1:** after an implement gate, `Results.latest(story, "coverage")` has `at` = HEAD
    and `where == "implement gate"`, also when the gate escalates (repeat screen).
14. **AC1 brief:** a developer step's prompt on a story at implement holds the kept `test`
    output under `## Runner results`; a quality-czar step's prompt holds coverage, lint and static.
15. **Q1/Q2:** before a quality-czar step the runner runs `lint` and `static`; it runs
    `coverage` only when the kept one is missing or not at HEAD (count the fake's calls);
    an unset `lint` is skipped.
16. **R1:** a developer plan's options allow `mcp__runner__run_tests` and
    `mcp__runner__run_new_tests` and carry the `runner` server; a unit-tester plan does not.
17. **R7:** a unit-tester commit adds its paths to `story.test_files` once each; a developer
    commit does not; `code_commits` behaviour (s46) unchanged.

`runner_tools`:

18. **R2:** `run_tests({"tests": []})` and `{"tests": ["tests/"]}` refuse with the exact texts;
    nothing runs.
19. **R3/R4:** an id `tracked` cannot resolve refuses `UNTRACKED_TEST`; no rows refuses `NO_TARGETED`;
    a path under no root refuses `NO_ROOT`.
20. **R5:** ids under two roots give two batches; the longest root wins; ids are root-relative
    and quoted; a command with another `{x}` brace keeps it.
21. **R6:** `run_new_tests` runs only recorded `test_*.py`/`*_test.py` files that exist;
    none → `NO_NEW_TESTS`; no story → `NO_STORY`.
22. **R8/R9/R10 / AC2:** a run happens inside `pulse.doing` (the chore text), logs one `tests-run`
    event with `tests`, `exits`, `seconds`, and replies `status: "ran"` with each run's command,
    exit and output. A refusal logs no event.
23. **T1:** a `[[toolchain.targeted]]` row without `{tests}` fails config validation;
    `targeted_for` picks the longest holding root, `""` holds all.

Role files (`tests/test_roles.py` style):

24. **AC3/AC6:** `quality-czar` resolves with tools `[Read, Grep, Glob]`; the role texts hold
    the new sentences (`run_tests` in developer, "re-check red" in unit-tester, "Run nothing"
