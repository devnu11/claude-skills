# s106: a cancelled CI check, its cause, and a re-run path

Story: `.team/stories/s106.md`. Builds on s81 (`ci.py`, CI stage, design
`s81.md` CI1–CI16). No new ADR and no new dependency: `gh run rerun` and
`gh api` come from the same `gh` binary the CI stage already uses.

## What the repo already tells us (AC1, first half)

| Fact | Where | Consequence |
|---|---|---|
| `CI / test (macos-latest)` is the `test` job of **`.github/workflows/ci.yml`**. All it runs is `sh tests/install_test.sh`: 12 shell tests of `install.sh`, a few seconds of work. | `ci.yml` | The runner's pytest suite **does not run** on macOS. It runs in `agile-team.yml` on `ubuntu-latest` only. So the heartbeat tests named in the story **cannot** be the cause. |
| `install_test.sh` reads no stdin, has no network, no `sleep`, and no loop except `install.sh`'s symlink walk, which the tests never make cyclic. | `tests/install_test.sh`, `install.sh` | A hung test is very unlikely. |
| `ci.yml` has no `concurrency:` key. | `ci.yml` | A newer push does **not** cancel the old run. A concurrency cancel is ruled out. |
| No job sets `timeout-minutes`, so GitHub's default of 360 min applies. When a job runs past its limit, GitHub records it as `cancelled`. | all three workflows | A hang would only show up as a cancel after 6 h. The CI stage's 30 min deadline would end first, as `ci_pending`, not red. A cancel inside the 30 min therefore points to the runner side (a lost or never-assigned macOS runner) or a manual cancel. |
| For a cancelled job, `gh run view --job <id> --log-failed` gives nothing (no step *failed*). | `ci._with_lines` reads it for `CANCEL` too | The `ci_failed` hand-over showed the link but **no evidence**. That is why the cause was unknown. |

The leading cause is therefore **runner-side** (GitHub cancelled the macOS
job, or it never got a runner). The developer confirms it (C1).

### Lines (C5)

The input is the `gh api` JSON of one job: a dict with `started_at`,
`completed_at` (ISO 8601 with `Z`, or null), `run_attempt` (int),
`runner_name` (str or null) and `steps` (list of dicts with `number`,
`name`, `status` and `conclusion`, which may be null). Lines, in order:

1. `JOB_RAN.format(seconds=…, started=…, ended=…, attempt=…)` when both
   times are present: `"ran {seconds:.0f} s, {started} to {ended}, attempt {attempt}"`.
   `started`/`ended` are the raw strings. `attempt` is `run_attempt`, or `1`
   when it is missing.
2. `JOB_RUNNER.format(name=…)` = `"runner: {name}"` when `runner_name` is a
   non-empty string, else `NO_RUNNER = "no runner was assigned"`.
3. For each step whose `conclusion` is not in `STEP_FINE = {"success",
   "skipped"}`: `JOB_STEP = "step {number} {name}: {result}"`, where
   `result` is `conclusion`, or `status` when `conclusion` is null. At most
   `MAX_LINES` steps.

An empty string, bad JSON or a non-dict gives `[]`, as today's empty log
does. A missing `steps` gives no step lines. The check line's existing
indent shows these under the check (`_check_text`, unchanged).

New pure functions (docstrings, ≤ 8 lines each, ≤ 2 parameters):

| Signature | Job |
|---|---|
| `run_of(link: str) -> str \| None` | The Actions run id in a check's link (mirrors `job_of`). |
| `cancelled(checks: list[Check]) -> frozenset[str]` | Links of `CANCEL` checks whose link has a run id. |
| `settled(checks: list[Check], stale: frozenset[str]) -> bool` | C4: `bool(checks)` and every check is not `PENDING` and its link is not in `stale`. |
| `cancel_lines(record: str) -> list[str]` | C5 lines from the job JSON; `[]` for "", bad JSON or a non-dict. Built from the three helpers below. |
| `_ran_line(job: dict[str, Any]) -> list[str]` | Line 1, or `[]` when a time is missing. Seconds = `datetime.fromisoformat(ended) - datetime.fromisoformat(started)`, as `total_seconds()`. |
| `_runner_line(job: dict[str, Any]) -> str` | Line 2. |
| `_step_lines(job: dict[str, Any]) -> list[str]` | Lines 3, at most `MAX_LINES`. |

Evidence table (C5). It replaces the bucket test in `_with_lines`:

```python
@dataclass(frozen=True)
class Evidence:
    """Where a not-passing check's lines come from: a reader on Prs and a parser."""
    read: Callable[[Prs, str], str]
    lines: Callable[[str], list[str]]

def _failed_log(prs: Prs, link: str) -> str: return prs.failed_log(link)
def _job_record(prs: Prs, link: str) -> str: return prs.job_record(link)

EVIDENCE = {
    Bucket.FAIL: Evidence(_failed_log, failing_lines),
    Bucket.CANCEL: Evidence(_job_record, cancel_lines),
}
```

(Pitfall: do not use the unbound `Prs.failed_log`, because it would call
the Protocol's stub, not the fake's or `GhPrs`'s method.) `FAILING` stays:
other callers may use it, and it equals `frozenset(EVIDENCE)`.

A watch descriptor, so no method takes more than 2 parameters:

```python
@dataclass(frozen=True)
class Look:
    """One PR's watch: its number, the shared deadline, links a re-run made stale."""
    number: int
    deadline: float
    stale: frozenset[str] = frozenset()
```

`CiWatch` changes (`results` keeps its signature):

| Method | Body |
|---|---|
| `_result(self, entry: StackEntry, deadline: float) -> CiResult` | `look = Look(entry.pr or 0, deadline)`. `checks = self._rerun(look, self._settled(look))`, then `_with_lines` on each, then `CiResult(...)` as today. |
| `_settled(self, look: Look) -> list[Check]` | Today's loop, with `look.number`/`look.deadline`. The exit test becomes `if not ended or settled(checks, look.stale)`. |
| `_wait(self, look: Look) -> bool` | Today's body with `look.deadline`/`look.number`. |
| `_rerun(self, look: Look, checks: list[Check]) -> list[Check]` | C3/C4: `stale = cancelled(checks)`. `reran = {run for run in sorted({run_of(l) for l in stale}) if self.prs.rerun(run)}`. `stale = frozenset(l for l in stale if run_of(l) in reran)`. Return `checks` when `stale` is empty, else `self._settled(replace(look, stale=stale))`. |
| `_with_lines(self, check: Check) -> Check` | `evidence = EVIDENCE.get(check.bucket)`. Return `check` when it is `None` or `job_of(check.link)` is `None`. Else `replace(check, lines=evidence.lines(evidence.read(self.prs, check.link)))`. |

`run_of` returns `str | None`, but `stale` only holds links with a run id,
so `self.prs.rerun` never gets `None`. Type the set comprehension so mypy
and ruff agree (e.g. filter `if run`).

## Known limits

- `gh pr checks` lists the latest check run per check name. If GitHub ever
  listed the old cancelled run beside its re-run, C4 would keep looking
  until `CI_LOOKS` ran out and call it red. That is safe, because it is
  never wrongly green.
- `gh run rerun --failed` re-runs failed **and cancelled** jobs. The gh
  token needs permission to re-run. Without it the re-run is refused and the
  result is today's red.
- GitHub records a job that ran past `timeout-minutes` as `cancelled`. C5's
  run time (≈ the limit) is what tells a timeout apart from a runner-side
  cancel. No separate bucket is made for it.
