# s175 design: a landing that raises keeps its error

Story: `.team/stories/s175.md`. Requirements: REQ-204 (AC1), REQ-205 (AC2),
REQ-206 (AC3). ADR: ADR-0048, amended by s175 (stage `error` field and the
raised-stage detail rule). Developer: `developer-api`.

## Cause

Read at 0e1e0991, and confirmed in this tree:

- `stages.Run.note` keeps the first failing command. A tolerated failure
  (`git worktree remove --force` of an absent directory, code 128) sticks, and
  the gh call that really raised later is noted but never kept.
- `stages.entered` records only the class name, and `stage_log.Timed.data`
  has no message field.
- `GhPrs._gh` raises `UpstreamError(out.strip())`. For GitHub's
  pretty-printed JSON reply the first line is `{`, and `crash_halt` keeps
  only that line.
- `Scheduler.run_work` turns a land's exception into an `error` report and
  never writes `crash.log`. `handover.hold_reason` holds only `"error"`.

## Rules

| # | Rule | AC |
|---|---|---|
| E1 | **The error carries its call.** An exception raised because one command failed carries a `stages.Invocation(command, code)` naming that command. `GitError` from `Git.run` carries `git <args>` and the exit code. Every `UpstreamError` that `GhPrs` raises for a gh call carries `gh <args>` and the exit code (0 when the output was not the expected JSON). Other raises carry none. | AC1 |
| E2 | **A raised stage names the raising call.** When a stage body raises, the run's `raised` is the class name (as now), and its `error` is the exception's first non-blank line, stripped (`""` when there is none). Its `detail` and `code` become the exception's invocation. With no invocation they become `""` and `None`, so no earlier command shows. A stage that returns keeps today's rule (RS5: the first failing command, else the latest). This applies to every stage, not only `story.land`. | AC1 |
| E3 | **Event field.** `runner-stage` data gains `error` right after `raised`: `null` when the stage returned, else the run's `error` masked (`tool_calls.masked`) and cut to `stage_log.ERROR_MAX` = 500 characters. `detail` stays `shown(...)`, at most 80 characters. | AC1 |
| E4 | **crash.log.** A land that raises appends the traceback with `halt.log_traceback(run_dir, exc)` before the exception reaches `run_work`. An `OSError` from the write is suppressed so it can't hide the error. Role steps and boundary steps already log in `dispatch` and `boundary_runner` and are not logged twice. | AC2 |
| E5 | **A gh failure with no readable text names its call.** A body counts as plain text when its first non-blank line doesn't start with `{` or `[`. Plain text keeps today's message, `out.strip()`. Otherwise (empty, or JSON) the message is `GH_FAILED`: `"{command}: exit {code}{status}: {output}"`. `status` is `", HTTP NNN"` when the output holds `HTTP NNN` (gh prints `(HTTP 403)`), else `""`. `output` is the output with whitespace runs collapsed to single spaces, stripped, and cut to `OUTPUT_MAX` = 300 characters, or `"(no output)"` when empty. | AC3 |
| E6 | **Output that isn't the expected JSON.** `GhPrs.find`, `job` and `list_checks` decode through `_read_gh_json`. A `ValueError` from `json.loads` raises `UpstreamError` with the full `GH_FAILED` form (exit 0), chained `from` the decode error and carrying the invocation. | AC3 |
| E7 | **Hand-over and hold.** The `error` report's `reason` stays `crash_halt(exc).reason` (`crashed: <Class>: <first line, ≤200>`), so with E5 the hand-over line carries the message. `hold_reason` writes the `error` trigger as `error: <reason>` when the report has a reason. The other triggers keep their bare names, and the join stays `", "`. This holds for every error report (a crashed role step's hold reads `error: crashed: RuntimeError: boom`). | AC3 |

## Changes per module

### `agile_team/stages.py` (still pure)

```python
@dataclass(frozen=True)
class Invocation:
    """One command line a stage ran and its exit code (s175)."""
    command: str
    code: int


class CommandFailed(Exception):
    """An error raised because one command failed; ``invocation`` names it (s175 E1)."""

    def __init__(self, message: str, invocation: Invocation | None = None) -> None:
        super().__init__(message)
        self.invocation = invocation


def get_error_line(exc: BaseException) -> str:
    """The first non-blank line of ``str(exc)``, stripped; "" when there is none."""
```

`Run` gains `error: str | None = None` after `raised`, and one method:

```python
def record_raise(self, exc: BaseException) -> None:
    """Keep the class, the first line and the raising call of ``exc`` (E2)."""
```

It sets `raised`, `error = get_error_line(exc)`, and `detail, code` from
`exc.invocation` when `exc` is a `CommandFailed` with one, else `("", None)`.
`entered` calls `run.record_raise(exc)` in place of the line that set
`raised`, then re-raises as now. `Run.note` is unchanged.

### `agile_team/stage_log.py`

- `from .tool_calls import awake_gap, masked, shown`
- `ERROR_MAX = 500`
- `def show_error(error: str | None) -> str | None`: `None` for `None`, else
  `masked(error)[:ERROR_MAX]`.
- `Timed.data` adds `"error": show_error(run.error)` right after `"raised"`.
  Nothing else changes; `done` stays `run.code is None and run.raised is None`.

### `agile_team/git_ops.py`

- `class GitError(stages.CommandFailed)`. Its docstring is unchanged.
- `def format_git_command(args: Sequence[str]) -> str`: `f"git {' '.join(args)}"`.
  `Git._exec` notes with it, and `Git.run` raises
  `GitError(f"{format_git_command(args)}: {proc.err.strip()}", stages.Invocation(format_git_command(args), proc.code))`.
  The message text is unchanged.

### `agile_team/ci.py`

- `from . import stages, system`; `class UpstreamError(stages.CommandFailed)`.
  Every existing `UpstreamError(text)` call still works, with no invocation.

### `agile_team/upstream.py`

Add `import re`. Constants: `GH_FAILED = "{command}: exit {code}{status}: {output}"`,
`GH_STATUS = ", HTTP {status}"`, `NO_OUTPUT = "(no output)"`,
`OUTPUT_MAX = 300`, `JSON_STARTS = ("{", "[")`,
`HTTP_STATUS = re.compile(r"\bHTTP (\d{3})\b")`.

```python
def is_plain_text(out: str) -> bool:
    """True when the first non-blank line of ``out`` exists and isn't JSON (E5)."""

def trim_output(out: str) -> str:
    """``out`` on one line, cut to OUTPUT_MAX; NO_OUTPUT when empty (E5)."""

def format_gh_call(invocation: stages.Invocation, out: str) -> str:
    """GH_FAILED for the call: its command, exit code, HTTP status and output (E5)."""

def describe_gh_failure(invocation: stages.Invocation, out: str) -> str:
    """``out.strip()`` when it is plain text, else ``format_gh_call`` (E5)."""

def build_gh_error(argv: list[str], result: tuple[int, str]) -> UpstreamError:
    """The UpstreamError for a failed gh call, carrying its invocation (E1, E5)."""

def build_gh_decode_error(argv: list[str], result: tuple[int, str]) -> UpstreamError:
    """The UpstreamError for gh output that did not decode, with the real exit code (E6)."""
```

`build_gh_decode_error` always uses the full `GH_FAILED` form, even for
plain-text output, because a body that didn't decode is never the gh error
message. (Added at design review: the code is the better answer.)

`build_gh_error` makes `Invocation(" ".join(argv), result[0])`, the same text
`_noted` notes, and returns
`UpstreamError(describe_gh_failure(invocation, result[1]), invocation)`.

`GhPrs`:

- `_gh(*args)`: `raise build_gh_error(argv, (code, out))` with `argv = ["gh", *args]`.
- `close`: `raise build_gh_error(argv, (code, out))` for its own argv. The
  merged-PR check is unchanged, and the error still names the close, not the
  `pr view` that ran after it.
- New `_read_gh_json(self, *args: str) -> Any`: `json.loads(self._gh(*args))`.
  On `ValueError` it raises `build_gh_decode_error(["gh", *args], (0, out))`
  `from` the decode error.
  `find`, `job` and `list_checks` call it in place of `json.loads(self._gh(...))`.

### `agile_team/handover.py`

```python
def describe_hold(trigger: Trigger, report: dict) -> str:
    """The trigger's name; an error's is followed by the report's reason (E7)."""
```

`hold_reason` joins `describe_hold(t, report)` for each trigger. The
rule-table line for `Trigger.ERROR` is unchanged.

### `agile_team/scheduler.py`

- `from .halt import crash_halt, log_traceback`
- `Scheduler.land` calls a new `run_logged_land(story)` in place of
  `land_report(story)`:

```python
async def run_logged_land(self, story: StoryState) -> dict[str, Any]:
    """The land's report; an exception's traceback goes to crash.log first (E4)."""
```

  It wraps `await self.land_report(story)` in `try/except Exception`: inside
  `contextlib.suppress(OSError)` it calls
  `log_traceback(self.runtime.config.run_dir, exc)`, then re-raises.
  `run_work` is unchanged. This story doesn't change how `landings.finish` is
  handled when a land raises.

## Test checklist

Unit tests go in `tests/test_s175_landing_errors.py` unless a module test
file says otherwise. They use no real gh: they use a fake `Exec` and a fake
`Git` exec seam where those tests already have one.

- [ ] E2/E3: a stage whose body notes a failing command (code 128), then a
      passing one, then raises `CommandFailed("boom\nmore", Invocation("gh api x", 1))`
      gives one event with `detail "gh api x"`, `code 1`, `raised "CommandFailed"`,
      `error "boom"`.
- [ ] E2: a body that notes a failing command and then raises a plain
      `RuntimeError("x")` gives `detail ""`, `code null`, `error "x"`.
- [ ] E2: a body raising an exception whose text is empty gives `error ""`,
      and the exception still reaches the caller unchanged.
- [ ] E3: a stage that returns has `error: null`, and its `detail`/`code`
      follow RS5 as before (first failing, else latest). The key order is
      `... detail, code, raised, error, started_at ...`.
- [ ] E3: an error line of 600 characters is cut to 500, and
      `token=abc` in it shows as `token=***`.
- [ ] E1: `Git.run` failing raises `GitError` whose `invocation` is
      `("git <args>", code)`, and whose message is unchanged.
- [ ] E1/E6: through `asyncio.to_thread` (the land's `run_off`), a gh failure
      raised in the worker thread still sets the stage's `detail` to the gh
      command.
- [ ] E5: `_gh` with exit 1 and output `'{\n  "message": "API rate limit exceeded"\n}\ngh: API rate limit exceeded (HTTP 403)'`
      raises `UpstreamError` whose first line is
      `gh api <path>: exit 1, HTTP 403: { "message": "API rate limit exceeded" } gh: …`
      and whose `invocation` is `("gh api <path>", 1)`.
- [ ] E5: exit 1 with empty output gives `gh <args>: exit 1: (no output)`.
- [ ] E5: exit 1 with plain text `"pull request create failed: x"` keeps
      exactly that text (no prefix).
- [ ] E5: output longer than 300 characters is cut to 300 on one line.
- [ ] E5: `close` failing on a PR that isn't merged raises an error naming
      `gh pr close <n> …`, not `gh pr view`.
- [ ] E6: `find` with exit 0 and output `"{"` raises `UpstreamError`
      `gh pr list …: exit 0: {` with invocation code 0, chained from a
      `ValueError`.
- [ ] E4: a land whose lander raises `UpstreamError` appends one
      `--- <stamp> UpstreamError` entry with the traceback to `crash.log`, and
      the error still reaches `run_work`, which reports `status: error`.
- [ ] E4: a role step that crashes still writes exactly one crash.log entry.
- [ ] E4: an `OSError` from the crash.log write doesn't replace the land's
      exception.
- [ ] E7: `hold_reason({"status": "error", "reason": "crashed: UpstreamError: gh …"})`
      is `"error: crashed: UpstreamError: gh …"`. An error report with no reason
      gives `"error"`. Other triggers are unchanged
      (`"stopped, questions, quarantine"`).
- [ ] AC1–AC3 together (in the s175 test file, driving `Scheduler.run_work`): a land through the real `Lander`,
      where a tolerated command fails first (noted with code 128, like
      `git worktree remove --force` of an absent directory) and then a gh call
      through `GhPrs` with a fake `Exec` fails with the rate-limit body.
      The `runner-stage` event for `story.land` names the gh call and its
      `error`. crash.log has the traceback. The story's hold and the PO's
      hand-over line both contain `exit 1, HTTP 403`.
