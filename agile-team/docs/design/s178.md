# s178 design: parallel stories get distinct requirement ids

Story: `.team/stories/s178.md`. Requirements: REQ-190 (AC1), REQ-191 (AC2),
REQ-192 (AC3). ADR: ADR-0090 (requirement ids are reserved per story in
`state.json`). Developer: `developer-cli`.

## The problem in one paragraph

`requirements.next_id` is one above the highest `REQ-NNN.md` in the folder it
is given. A story step reads its own worktree, which starts as a copy of the
sprint head, so every story forked from one head is offered the same id
(sprint 51: s164, s165 and s166 all wrote REQ-174 and REQ-175). Reading other
branches alone isn't enough: two architects briefed before either has written
a file see the same files. So the runner **reserves** a block of ids for a
story when it writes the architect's brief, counts the reservations of the
other open stories, and the design gate refuses an id that other work holds.

## Rules

- **R1. Only with story branches.** Everything below applies when
  `state.story_branches` is true. Without story branches there is one
  checkout and no parallel steps: the architect's brief and the design gate
  stay exactly as they are (`design_section`, `INDEX_HEAD`).
- **R2. Open story.** An *other open story* of story S is a story in
  `state.stories` with `id != S.id`, `sprint == state.sprint` and
  `status not in FINISHED` (the same filter as `Overlaps._find_others`, without
  its past-design condition). Cancelled stories, done stories (their ids are on
  the sprint head once they land) and stories that left the sprint are not
  open (AC3).
- **R3. What an other open story O holds.** Its *numbers* are the union of:
  - the `REQ-*.md` names on its branch: `git ls-tree --name-only <O.branch> --
    <folder>/`, run in the main checkout (`Runtime.main`); nothing when
    `O.branch` is empty or the command exits non-zero (a dropped branch holds
    nothing, AC3);
  - the `REQ-*.md` names in its worktree's requirements folder when that
    folder exists (`config.get_worktree_config(Workspaces(main, config).get_path(O.id)).requirements_dir`).
    This sees files the other architect wrote but the runner hasn't committed
    yet; the gate runs before the step's commit (`_run_pregate`), so without
    it a brief built between another story's gate and its commit would miss
    that story's new ids;
  - its reservation, `list_block(O.req_block)` (R5).

  Its *added* numbers are its branch and worktree numbers minus the numbers
  on `O.base_sha` (`ls-tree` again; nothing added when `O.base_sha` is empty).
- **R4. The sprint head.** The sprint head's numbers are
  `git ls-tree --name-only HEAD -- <folder>/` in the main checkout, which stays
  on the sprint branch (REQ-132). `<folder>` is `requirements.folder_of(config)`.
  A number is taken from the name's stem with `REQ-(\d+)` (as `next_id` does
  today, so a badly named `REQ-12.md` still blocks 12).
- **R5. The reservation.** `StoryState.req_block: int = 0` is the first number
  of the story's block; `0` means no block. A block is `BLOCK_SIZE = 5`
  consecutive numbers, `req_block` to `req_block + 4`. Five covers what a
  story usually adds; a story that needs more takes ids above its block, and
  the gate checks those (R8). The field is saved with the story in
  `state.json` like every other field; an old `state.json` loads it as `0`.
- **R6. Reserving at the brief (AC1, AC3).** Each time the runner writes the
  architect's brief for a checked story (`trace: checked`), it calls
  `RequirementIds(view).reserve(story)`:
  1. *taken* = the sprint head's numbers ∪ every other open story's numbers
     (R3, with reservations).
  2. If the story has a block and no number of it is in *taken*, the block is
     kept. Otherwise `story.req_block = max(taken, default=0) + 1`. A block is
     never moved just because a lower id became free; only a fresh
     reservation (a story with no block, or one whose block clashes) starts
     at the new top. So an id freed by a cancelled story or a dropped branch
     is offered again by the next fresh reservation once nothing open holds it
     and it is above everything that does (AC3).
  3. *own* = the numbers in the story's own worktree folder
     (`view.config.requirements_dir`).
  4. The next free id is the lowest block number not in *own*. When every
     block number is in *own*, it is `max(taken ∪ own ∪ block) + 1`, outside
     the block.
  5. It returns `requirements.Offer(story.id, next_free, first, last)` with
     the ids formatted `REQ-NNN`.

  The reservation lives in the shared in-memory state at once; the run's
  next save persists it. `reserve` is synchronous and runs in `_set_up` on
  the event loop, so two briefs can't interleave inside it.
- **R7. The architect's brief.** In branch mode the architect's
  `## Requirements` section is `requirements.format_offer_section(checked, offer)`:
  the same coverage part and active-requirements index as `design_section`,
  under this head (`OFFER_HEAD`, a Python string, with `\n\n` at its end
  like `INDEX_HEAD`):

  ```text
  Active requirements (add the story's ACs to one's `covers`, or write {next_free}.md, the next free id; this story's ids are {first} to {last}, and an id outside them is checked at the design gate):
  ```

  followed by the index. The phrase "the next free id" stays. The code
  reviewer's and the Customer Proxy's sections don't change and reserve
  nothing.
- **R8. The design gate (AC2).** On a checked story the design gate adds the
  clash reasons to its other reasons (one bounce to `design`, a round, every
  reason listed). `RequirementIds(view).list_clashes(story_id)`:
  1. Returns `[]` when the story is unknown or `story.base_sha` is empty.
  2. *added* = own worktree numbers minus the numbers on `story.base_sha`.
  3. *holders* maps a number to its reason, first writer wins, in this order:
     the sprint head (`{id} is already used on the sprint head`), each other
     open story's added numbers (`{id} is already used by {story}`), each
     other open story's block (`{id} is reserved by {story}`). Numbers inside
     the story's **own** block are left out of the second and third kinds:
     the block is the story's by reservation, and another story that wrote
     one of them is the one its own gate bounces. This ordering means two
     stories never bounce each other over one id.
  4. Each added number found in *holders*, ascending, gives one line
     `- {reason}`, under the head
     `{story} adds requirement ids that other work already holds; renumber
     them from the next free id your retry brief names:`.
     With none, `[]`.

  The bounce returns the story to design; the retry brief runs R6 again, so
  it names a free id (a clashing block is replaced in step 2).
- **R9. Where the gate gets it.** `gates.Checks` gains
  `clashed: Callable[[str], list[str]] = _list_no_clashes` (returns `[]`).
  `Checks._trace_reasons(story)` returns
  `[*self.traced(story.id), *self.clashed(story.id)]` for a checked story and
  `[]` otherwise. `Runtime.get_story_view` sets
  `view.pipeline.checks.clashed = RequirementIds(view).list_clashes` after it
  copies the pipeline, so only story views (branch mode) check clashes; the
  default pipeline built in `cli` keeps `_list_no_clashes`.

## Changes per module

### `agile_team/requirements.py`

- `NUMBER = re.compile(r"REQ-(\d+)")`.
- `parse_numbers(paths: Iterable[str]) -> set[int]`: the REQ numbers among
  the paths' stems (`PurePosixPath(p).stem`, `NUMBER.match`). Works on
  `ls-tree` output lines and on file names.
- `format_id(number: int) -> str`: `f"REQ-{number:03d}"`.
- `list_numbers(folder: Path) -> set[int]`: `parse_numbers` over
  `system.glob(folder, "REQ-*.md")` names; empty when the folder is missing.
- `next_id(checked)` keeps its behaviour, rewritten on `parse_numbers` and
  `format_id`.
- `@dataclass(frozen=True) class Offer`: `story: str`, `next_free: str`,
  `first: str`, `last: str`, docstring "The ids a story's architect brief
  offers (s178)".
- `OFFER_HEAD` (R7's text with `{next_free}`, `{first}`, `{last}`).
- `_format_index(checked: Checked) -> str`: the index lines that
  `design_section` builds today; `design_section` uses it.
- `format_offer_section(checked: Checked, offer: Offer) -> str`:
  `f"{coverage_section(checked, offer.story)}\n\n{head}{_format_index(checked)}"`.

### `agile_team/requirement_ids.py` (new)

Docstring: "Requirement ids across a sprint's open stories: reserve a block
per story, find clashes at design (s178)." Imports: `requirements`,
`workspaces.Workspaces`, `gates.FINISHED`, `gates.StoryState`; `Runtime` only
under `TYPE_CHECKING` (as `overlaps.py`).

- `BLOCK_SIZE = 5`; `ON_HEAD`, `USED_BY`, `RESERVED_BY`, `CLASH_HEAD` (R8 texts).
- `list_block(first: int) -> range`: `range(first, first + BLOCK_SIZE)`, an
  empty range for `0`.
- `class RequirementIds`, `__init__(self, runtime: Runtime)`:
  - `reserve(self, story: StoryState) -> requirements.Offer` (R6).
  - `list_clashes(self, story_id: str) -> list[str]` (R8).
  - private helpers, each one job, e.g. `_find_others(story)`,
    `_read_numbers(ref) -> set[int]` (ls-tree in `runtime.main`, R3/R4),
    `_read_worktree(other) -> set[int]`, `_find_held(other) -> set[int]`
    (branch ∪ worktree), `_find_added(other) -> set[int]`,
    `_find_taken(story) -> set[int]`, `_find_holders(story) -> dict[int, str]`.
    A private helper that takes only `self` and changes nothing is a
    property with a noun name (`_folder`, `_head_numbers`).

Every name above starts with a verb from the house rules (`list`, `parse`,
`format`, `read`, `find`, `reserve`) or is a noun property; keep them as
written.

### `agile_team/gates.py`

- `StoryState.req_block: int = 0` with the comment
  `# s178: first number of the story's reserved requirement ids; 0 = none`.
- `_list_no_clashes(_story: str) -> list[str]` returning `[]`.
- `Checks.clashed` and `_trace_reasons` as R9. `designed` keeps its order;
  the clash lines follow the trace lines.

### `agile_team/dispatch.py`

- `_attach_requirements(plan)`: unchanged condition; the text comes from a
  new `_format_requirements(self, plan: Plan, section) -> str`, where
  `section` is the `requirements.BRIEFS` entry `_attach_requirements` already
  looked up (so the table is read once): when the role is `architect` and
  `self.state.story_branches`, it returns
  `requirements.format_offer_section(checked, RequirementIds(self).reserve(plan.story))`;
  otherwise `section(checked, plan.story.id)`.
  `checked = requirements.load(self.config)` as today. (Design review: the
  code is the better answer here; `section` is typed `Any` in the code where
  `Callable[[Checked, str], str]` would say more, a non-blocking nit.)
- `get_story_view`: R9's binding after `view.pipeline.checks.stages = …`.

### `agile_team/roles/architect.md`

Replace "the active requirements and the next free id." with: "the active
requirements and the next free id. With story branches the runner reserves
ids for your story (the brief names them); use those, because the design
gate bounces an id that the sprint head or another open story holds."

## Not changed

`requirements check`, the dashboard, the snapshot, the s2 change tracking
and the overlap hold (`IGNORED` still skips `{docs}/requirements/**`; ids,
not paths, are what clash).

## Test checklist

`tests/test_requirement_ids.py` is a unit test, so it runs no process
(REQ-108, REQ-109): it scripts `git ls-tree --name-only <ref>` replies on the
fake system (a ref that is gone replies exit 128), writes worktree files in
a scratch folder, and uses a small runtime stand-in with `state`, `config`
and `main`. `tests/test_s178_wiring.py` covers the wiring through a real
`Runtime`: the architect brief's offer and saved `req_block`, parallel briefs
getting different ids, the retry brief after a clash, no reservation for
other roles, and the clash check bound in a story view. (Design review: the
first draft asked for a real git repo here, which a unit test may not use.
No e2e test runs the real `ls-tree`; the argument form is plain git and
follow-up work may add one.)

- [ ] `parse_numbers` takes stems of paths and names, skips non-REQ names,
      counts `REQ-12.md`; `format_id(7) == "REQ-007"`, `format_id(1234) == "REQ-1234"`;
      `list_numbers` of a missing folder is empty; `next_id` tests still pass.
- [ ] `format_offer_section` holds the coverage part, R7's head with the three ids
      and the same index as `design_section`.
- [ ] AC1: head has REQ-001..REQ-010; two stories reserved one after the
      other with no files written get REQ-011 and REQ-016, each block of 5.
- [ ] AC1: an open story without a block whose branch commit adds REQ-011
      makes the next reservation start at REQ-012 (`ls-tree` of the branch).
- [ ] AC1: an uncommitted REQ-011 in another open story's worktree counts.
- [ ] AC1: a kept block survives a second brief; a block that the head or
      another branch now uses is moved above everything taken.
- [ ] AC1: own worktree uses the whole block → next free is above the block
      and everything taken.
- [ ] AC2: own added id on the head → `REQ-011 is already used on the sprint head`;
      on another open branch → `REQ-011 is already used by s2`; inside
      another's block → `REQ-016 is reserved by s2`; head line names the story.
- [ ] AC2: an id inside the story's own block that another branch also adds
      is not reported; no clash → `[]`; empty `base_sha` → `[]`.
- [ ] AC2: `Checks.designed` lists clash lines after trace lines in one
      bounce to `design`; an exempt story never calls `clashed`; the default
      `Checks` reports none.
- [ ] AC2: a story view's `pipeline.checks.clashed` is bound; the architect's
      brief in branch mode carries `format_offer_section`'s head and sets
      `req_block`; after a clash bounce the retry brief names an id no other
      work holds; without story branches the brief is `design_section`'s.
- [ ] AC3: a cancelled story's block and branch ids are free: a fresh
      reservation starts at its old first id; the same for a story moved out
      of the sprint, and for a branch ref that was deleted (`ls-tree` fails).
- [ ] `req_block` round-trips through `state.json`; an old file loads `0`
      (`tests/test_state.py`).
