# s158: the self re-pin puts `--repo` and `--home` before the subcommand

Story: `.team/stories/s158.md` · ADR: ADR-0065 (amended by s158) ·
Requirements: REQ-022 (AC1, AC3), REQ-122 (AC2) · Developer: `developer-cli`

## The fault

`cli.build_parser()` adds `GLOBAL_ARGS` (`--repo`, `--home`) to the top-level
parser only. A subcommand's parser does not know them, so
`agile-team config check --repo X` and `agile-team start --resume --repo X`
exit 2 with "unrecognized arguments". `repin._check_argv` and `repin.start_argv`
both build their argv this way. The config check also passes no `--home`. Every
re-pin therefore failed its check, rolled back, and then the exec of the old pin
exited 2 too, so the run ended. The s128 tests compared the argv to a literal
tuple and never parsed it.

## Rules

| # | Rule | AC |
|---|------|----|
| R1 | **Global options first.** Every argv the re-pin builds for the `agile-team` CLI is `<program> <global options> <subcommand> <subcommand options>`. The global options are `("--repo", str(repo))`, plus `("--home", home)` when the run was started with `--home`. They come from one function, `repin.global_argv`. | AC1, AC2 |
| R2 | **Pin keeps the global options, not a start argv.** `Pin` stores the run's global options as `options`. Both the config check (R3) and the exec (R4) build their argv from it, so the two commands always get the same repo and home. | AC2 |
| R3 | **Config check.** `(<uv>, "run", "--frozen", "--quiet", "--project", <run_dir>/runner-pin, "agile-team", *pin.options, "config", "check")`. It now passes `--home` when the run has one. | AC1, AC2 |
| R4 | **Exec.** `(<run_dir>/runner-pin/.venv/bin/agile-team, *pin.options, "start", "--resume")`. `Pin.exec` is the only exec, so the same argv is used after a clean re-pin (new pin) and after a rollback (restored old pin). | AC1, AC2, AC3 |
| R5 | **Nothing else changes.** The trials table, the timeouts, the marker, `roll_back`, `failed_start`, `confirm`, the `runner-repin` event and the rollback `update` stay as in s128 (P4–P11). With R3 and R4, a clean re-pin execs the new pin, which logs `pinned` (AC1). A failed re-pin execs the old pin, which logs `rolled_back` with the reason, posts the `update`, keeps `runner-pin.failed` and resumes the run (AC3). | AC1, AC3 |

`start_argv`'s signature changes from `(repo, home)` to `(options)`. Its only
caller is `Pin.exec`. Keep every import at module top (ADR-0065: no lazy import
after the swap).

### `agile_team/cli.py`

`cmd_start` line `pin = repin.Pin(place.repo, repin.start_argv(place.repo, args.home))`
becomes `pin = repin.Pin(place.repo, repin.global_argv(place.repo, args.home))`.
Nothing else in `cli.py` changes. Pass `args.home` (the raw string or `None`),
not `place.home`, which falls back to the real home.

## Test checklist (`tests/test_s128_repin.py`, or a new `tests/test_s158_repin_argv.py`)

The s128 tests assert the old, wrong order. They must change to the order in
R3 and R4 (`asserts`: REQ-122, R1). Every new argv assertion also **parses the
argv with the real parser**, `cli.build_parser().parse_args(list(args))`, so a
literal tuple can never hide an order the CLI refuses again.

- [ ] `global_argv(repo, None) == ("--repo", str(repo))`;
      `global_argv(repo, "/h") == ("--repo", str(repo), "--home", "/h")`. (AC2)
- [ ] `start_argv(global_argv(repo, "/h"))` is `("--repo", str(repo), "--home", "/h", "start", "--resume")`.
      Parsed: `command == "start"`, `repo == str(repo)`, `home == "/h"`,
      `mode is StartMode.RESUME`. Without home: no `--home`, and parsed
      `home is None`. (AC2)
- [ ] The check argv's part after `"agile-team"` parses: `command == "config"`,
      `action == "check"`, `repo == str(repo)`, `home` is the run's home (or
      `None`). (AC1, AC2)
- [ ] `test_the_start_pins_checks_and_execs_in_order`: the check argv ends
      `"agile-team", "--repo", <repo>, "--home", <key_home>, "config", "check"`.
      The exec argv is `(exe, "--repo", <repo>, "--home", <key_home>, "start", "--resume")`.
      The marker says `trial`. (AC1, AC2)
- [ ] The same flow with a run started without `--home`: neither argv has
      `--home`. (AC2)
- [ ] A failing check rolls back, and the exec of the restored pin has the same
      argv as R4 (global options first). The marker says `rolled_back` with the
      reason. (AC3; update `start_tuple` and the rollback tests to the new order.)
- [ ] `confirm` after a `trial` marker logs `runner-repin` with outcome `pinned`;
      after `rolled_back` it logs the reason and posts the `update` (existing
      tests stay green unchanged). (AC1, AC3)
- [ ] `Pin(...)` call sites in tests pass global options (e.g.
      `repin.global_argv(configured, None)`) instead of a start argv.
