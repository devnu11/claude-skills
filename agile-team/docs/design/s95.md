# s95 (A14c): acceptance runs once per environment

Story: `.team/stories/s95.md`. Plan: `.team/run/liaison/plans/acceptance-environments.md`.
Builds on s94 (`story_spec.py`: every AC names its environment; a story's environments are its
ACs' distinct values in config order) and s13/s26/s65/s105 (presentation, liveness trial, git
confinement, seeds). Folds in s91 (clearer e2e gate text). ADR-0051 (new) records the round;
ADR-0008 is amended for the per-environment presentation dirs.

s94 SF9 ("one environment until A14c": `story_spec.first_environment`) is **superseded**: every
place that used the first environment now works per environment.

## Rules

- **AE1. One presentation per environment.** A story's presentations are its *showings*: one
  `presentation.Showing(story, environment)` per environment its ACs name, in config order
  (`presentation.showings`). Showing `cli` of `s120` lives at
  `.team/run/presentation/s120/cli/` and holds `PRESENTATION.md` and, unless the kind's
  recipe is guide-only (`manual`), `workspace/` (its own git repo). The story root
  `.team/run/presentation/<id>/` holds only the showing dirs. A story whose file has problems
  has no showings.

- **AE2. Lay-out.** Before every integration-tester step on a story the runner lays out every
  showing (create the dir; for a `WORKSPACE` recipe, `git init` the workspace when `.git` is
  missing and plant that environment's seeds). It never wipes (s65). The tester's prompt gains
  the section `presentation.layout_section` (AE10) naming each dir, its kind and its AC ids.

- **AE3. The e2e gate checks every showing.** `presentation.missing(config, story)` checks each
  showing in config order and returns **every** gap, one line each, joined by `"\n"`, or `None`
  when all are complete (or the story has no showings: the s94 SF7 hold catches a bad file
  before the Proxy). A gap line is
  `story {story} has no presentation for acceptance environment '{environment}': {gap}`, with
  `{gap}` from the `GAPS` table, checked in this order per showing (first gap wins):

  | `Gap` | When | Text (`{path}` repo-relative, posix) |
  |---|---|---|
  | `NO_GUIDE` | `PRESENTATION.md` missing or blank | `{path} is missing or empty; write the customer's guide there` |
  | `NO_WORKSPACE` | `WORKSPACE` recipe, `workspace/` is not a dir | `{path} is missing; put the demo or evidence files the customer tries there` |
  | `EMPTY` | `WORKSPACE` recipe, `workspace/` holds no entry at all | `{path} is empty; put the demo or evidence files the customer tries there` |
  | `HOLLOW` | `WORKSPACE` recipe, `workspace/` holds only `.git` and/or the seed files | `{path} holds only {held}; add the demo or evidence files themselves, for example {path}/DEMO.md` |

  `{held}` lists what is there, `.git` first, then the seed names sorted, joined by `", "`
  (the usual case reads `holds only .git`). The gate bounces to `e2e` with a round, as today.

- **AE4. Liveness per showing.** `Trial.liveness(story)` tries every showing whose recipe check
  is `SERVICE`, in config order, one at a time (start, probe, stop, as s26/s82). The first
  non-`PASS` outcome is the result (its reason as today). All pass: `PASS` with the pass
  reasons joined by `"; "`, or `READY` when no showing is a service. A `manual` or other
  `FILES` showing never calls `prepare` (AC5 "a `manual` environment needs no service").

- **AE5. One Proxy step per environment.** A Proxy step on a story tries exactly one
  environment: the *due* one, `acceptance.Round(names, story.tried).due()` (AE7). Its sandbox
  is prepared from that environment alone, with that showing's dir copied in
  (`<sandbox>/presentation/` holds `PRESENTATION.md` and `workspace/`, as today). The prompt
  gains `acceptance.brief_section(spec, environment)` (AE11), which lists only that
  environment's ACs with their ids. A storyless Proxy step keeps today's fallback (the first
  configured environment, no criteria section).

- **AE6. The round lives on the story.** `StoryState.tried: list[acceptance.Tried]` holds the
  current round's verdicts, at most one per environment, in config order. Only two places
  write it: the acceptance verdict (AE8) and `Pipeline._forward` into `acceptance`, which
  clears it. So every entry into acceptance (after e2e, after any rework or return, after a
  Manager `advance`) starts a fresh round, and **all** environments run again (AC3).

- **AE7. The due environment.** `Round.due()` is the first name in config order with no
  verdict in `tried`. When every name has one (a round already decided, e.g. a bounce whose
  target is `acceptance` itself), the round is over: `due()` is the first name and the next
  verdict starts a new round (`with_try` drops the old ones). Entries for environments the
  story no longer names are ignored and dropped. `None` when the story names none.

- **AE8. The verdict of one Proxy step.** At step `acceptance`, when the story names
  environments, `Pipeline.evaluate` replaces `_handoff_outcome` with `_tried` (after the
  existing checks: `blocked`/`failed` still hold first and record nothing, so after
  `continue_story` the same environment runs again). `_tried`:
  1. `environment = round.due()`.
  2. **Report check.** `.team/acceptance/<id>.md` (read through `Checks.read`) must contain the
     line `## Environment: {environment}` (`acceptance.has_section`). If not:
     `Outcome(BOUNCE, NO_SECTION, "acceptance", author=ROLE)`; nothing is recorded, a round
     is counted, the same environment runs again.
  3. Record `acceptance.tried_of(environment, handoff)` (`done` → `Mark.PASS`,
     `changes_requested` → `Mark.FAIL` with `handoff.failed_acs`, `summary`, `next_role`):
     `round = round.with_try(new)`; `story.tried = list(round.tried)`.
  4. Decide (`round.decision()`, a table):

     | `Decision` | When | Outcome |
     |---|---|---|
     | `NEXT` | some environment has no verdict yet | `Verdict.NEXT`, reason `NEXT_TEXT`, `author=ROLE`: stays at acceptance, no round, no hand-over; the router runs the next Proxy step |
     | `PASS` | every environment has `PASS` | `Verdict.PASS`, reason `PASSED_TEXT`: forward (done) |
     | `FAIL` | every environment has a verdict, one or more `FAIL` | `Verdict.BOUNCE`, reason `FAILED_TEXT`, `bounce_to` = the earliest pipeline step among the failed tries' targets (`step_for_role(next_role)`, else `"implement"`), `author=ROLE`: one bounce, one round |

     Every outcome of step 4 carries `tried=new` (the gate event's fields, AE12).

  A failure in the first environment therefore still runs the second; the story passes only
  when all pass; it bounces once, listing every failed environment and its failed AC ids.

- **AE9. `Verdict.NEXT`.** New member `NEXT = "next"`: "stays at the step, counts no round and
  hands nothing over; the step runs again for the next acceptance environment (s95)". It is
  not a setback (`SETBACKS` unchanged), `Pipeline.advance` has no move for it, `GATE_EVENTS`
  maps it to the plain `gate` event, and no hand-over rule fires on it. The standard brief
  omits the "Previous step" line when the previous verdict is in `router.QUIET_VERDICTS =
  frozenset({"next"})`, so the next environment's Proxy is not told how the last one went.

- **AE10. The tester's section.** `presentation.layout_section(config, story_id)`:

  ```text
  ## Presentations to build

  One presentation per acceptance environment this story's ACs name. Each guide covers only
  that environment's ACs. Except for `manual`, its workspace/ must hold the demo or evidence
  files themselves, not only the empty git repo.
  - cli (package): .team/run/presentation/s120/cli/ (AC1, AC3)
  - dashboard (web): .team/run/presentation/s120/dashboard/ (AC2)
  ```

  `""` when the story has no showings.

- **AE11. The Proxy's section.** `acceptance.brief_section(spec, environment)`:

  ```text
  ## Criteria for this step: acceptance environment cli

  Try only these acceptance criteria; the story's other environments get their own steps.
  - AC1: agile-team export --csv prints one row per story.
  - AC3: …

  Write your findings under the heading `## Environment: cli` in .team/acceptance/s120.md:
  rewrite that section only and keep the other environments' sections. If any of these
  criteria fails, hand off `changes_requested` with "failed_acs": the failed ids.
  ```

- **AE12. One report, and the dashboard.** The Proxy keeps one report,
  `.team/acceptance/<id>.md`, with one `## Environment: <name>` section per environment (the
  `manual` script goes in its section too, and in the final message as today). The gate event
  of a Proxy step with `outcome.tried` gains `environment`, `mark` (`pass`/`fail`) and
  `failed_acs`. The snapshot's story row gains `environments: [{name, verdict}]`
  (`Round.marks()`: `verdict` is `"pass"`, `"fail"` or `""` for not tried in this round); the
  Board card and the Backlog row show one pill per environment (AE13).

- **AE13. Dashboard pills.** `envPills(story)` in `index.html` renders `story.environments` as
  pills via the `ENV_MARKS` table: `pass` → tone `good`, text `<name> ✓`; `fail` → tone
  `critical`, `<name> ✗`; `""` → tone `""`, `<name>`; each with
  `title="acceptance environment <name>: passed | failed | not tried yet"`. It replaces the
  ` · {environment}` text in `backlogRow` and `storyCard`. A snapshot without `environments`
  falls back to today's text (ADR-0006). `OUTCOMES` gains
  `next: { outcome: "tried; next environment", fill: "--s2" }`, `STATUS_TONE` gains
  `next: ""`, and the activity line of a `next` gate reads
  `acceptance · <environment> <mark> → next environment`.

- **AE14. Handoff field.** `Handoff.failed_acs: list[str]` (JSON `"failed_acs"`). Rules (rows in
  `HANDOFF_RULES`): a list of non-empty strings (`failed_acs must be a list of AC ids`); a
  non-empty list needs status `changes_requested` (`failed_acs needs status
  changes_requested`). Ids are kept as given, in order. `handoff_report` adds `failed_acs` only
  when non-empty. A `changes_requested` with no ids lists the environment as `no AC named`.

- **AE15. Git confinement.** The integration-tester's confined workspace (s65 `GIT_CONFINED`
  `e2e`) becomes the story root `.team/run/presentation/<id>/`, so git works in every showing's
  workspace. The root has no `.git` and sits under the ceiling, so git there says "not a git
  repository". The Proxy's stays its sandbox copy (unchanged).

- **AE16. Upgrade.** A story already at acceptance with a pre-s95 flat presentation
  (`<id>/PRESENTATION.md`) has every showing `NO_GUIDE`, so the unpresented check returns it to
  e2e without a round, and the tester builds the per-environment dirs. The old flat files are
  left alone (the tester may delete them).

## Texts (module `acceptance.py`)

```python
REPORT = ".team/acceptance/{story}.md"
SECTION = "## Environment: {environment}"
NO_SECTION = ("the report {file} has no section `## Environment: {environment}`; write it, keep the "
              "other environments' sections, and hand off again")
NEXT_TEXT = "acceptance environment {environment}: {mark}; next: {next}"
PASSED_TEXT = "acceptance passed in every environment: {names}"
FAILED_TEXT = "acceptance failed in {count} of {total} environments:\n{lines}"
FAILED_LINE = "- {environment}: {acs}: {summary}"
NO_AC_NAMED = "no AC named"
```

`{names}` is the names joined by `", "`; `{acs}` the failed ids joined by `", "` or
`NO_AC_NAMED`; `{lines}` the `FAILED_LINE`s in config order. Example:

```text
acceptance failed in 2 of 2 environments:
- cli: AC2: export prints no header row
- dashboard: AC4: the Export button is missing
```

## The new module: `agile_team/acceptance.py` (pure)

```python
"""Acceptance per environment (s95): the due environment, the round's verdicts, the one verdict."""

from collections.abc import Sequence
from dataclasses import dataclass, field
from enum import StrEnum

from .roles import Handoff
from .story_spec import Spec

class Mark(StrEnum):
    PASS = "pass"; FAIL = "fail"

class Decision(StrEnum):
    NEXT = "next"; PASS = "pass"; FAIL = "fail"

@dataclass(frozen=True)
class Tried:
    """One environment's Proxy verdict in the current round."""
    environment: str
    mark: Mark
    failed: tuple[str, ...] = ()
    summary: str = ""
    next_role: str | None = None

def tried_of(environment: str, handoff: Handoff) -> Tried: ...     # AE8 step 3
def load_tried(data: dict) -> Tried: ...                           # state.json: Mark(...), tuple(failed)

@dataclass(frozen=True)
class Round:
    """A story's environments (config order) and this round's verdicts."""
    names: tuple[str, ...]
    tried: tuple[Tried, ...] = ()
    def complete(self) -> bool: ...                 # every name has a verdict
    def due(self) -> str | None: ...                # AE7
    def with_try(self, new: Tried) -> "Round": ...  # AE7: replaces new.environment's entry; a complete round restarts; config order; unnamed dropped
    def failures(self) -> list[Tried]: ...          # FAIL entries, config order
    def decision(self) -> Decision: ...             # AE8 table
    def next_text(self, new: Tried) -> str: ...     # NEXT_TEXT
    def passed_text(self) -> str: ...
    def failed_text(self) -> str: ...
    def marks(self) -> list[dict[str, str]]: ...    # [{"name", "verdict"}], AE12

def report_file(story: str) -> str: ...                            # REPORT.format
def has_section(text: str | None, environment: str) -> bool: ...   # a line equal to SECTION (trailing spaces stripped); None → False
def brief_section(spec: Spec, environment: str) -> str: ...        # AE11
```

`acceptance.py` imports only `roles` and `story_spec` (never `gates`: `gates` imports it).

## Known limits

- Environments run one after another, never in parallel (A15).
- Liveness stops at the first service that fails; the next e2e round shows the next one.
- A `changes_requested` whose `failed_acs` names an id from another environment is listed as
  given; the runner does not check ids against the environment.
- The PO cannot rerun one environment alone: a story re-entering acceptance runs them all
  (AC3, by design).
