# s12: The Customer Proxy cannot leave its sandbox through cd, ~, $VAR or option-glued paths

Story: `.team/stories/s12.md` (narrowed by t101). ADR: ADR-0079.
Requirements: REQ-101 (AC1), REQ-102 (AC2), REQ-103 (AC3).
Developer: `developer-cli`. It has work only if a form gets through (AC2, rule E6).

## Why a test, not a new token check

The Proxy has three read walls (see the `sandbox.py` module docstring): tool globs,
the Bash token hook (`guard._check_tokens`), and the OS sandbox
(`sandbox.os_sandbox_settings`: Seatbelt on macOS, `filesystem.denyRead` on the
repo with `allowRead` for the sandbox, stories, `.team/acceptance`, customer docs
and shared files; `allowUnsandboxedCommands: False`). The s7 review's P1, P2 and P4
(`~`, `$VAR`, `--opt=path`, case) are holes in the **token hook**. The hook reads
the command as text, so it cannot know what the shell will expand. Seatbelt checks
the path at the system call, after the shell has expanded `~`, `$VAR`, `$(…)` and
wildcards and the process has changed directory. So the OS sandbox is the wall
this story proves, and the token hook stays as it is: a best-effort early refusal
with a clear message (ADR-0079).

## Rules

| # | Rule | AC |
|---|---|---|
| E1 | **One table of escape probes.** Each row is a form from the original story, written as a shell command that prints the secret file's marker if the read works. The table is `PROBES` (below), and no form is tested outside it. | AC1 |
| E2 | **Real CLI, real settings.** The probes run as one Bash tool call of the bundled claude CLI, which s58's scripted model drives. The settings come from `sandbox.os_sandbox_settings(config, prepared)`, with `cwd = prepared.workdir`. Nothing is mocked between the settings and Seatbelt. | AC1 |
| E3 | **Every probe is shown to work first.** A control run uses the same settings, but with `sandbox.enabled = False` and the `permissions` key removed. In it, every row's output must contain the marker. A row that does not is a broken probe, and the test fails naming it. This keeps the sandboxed test from passing for the wrong reason. | AC1 |
| E4 | **Refused means no marker and a non-zero exit.** In the sandboxed run, every row must have its section in the tool result, its output must not contain the marker, and its exit code must not be 0. The test asserts the whole `{row: leaked}` map at once, so one failure names every leaking row. "Operation not permitted" is not required, because a wildcard in a denied directory fails as "No such file". | AC1 |
| E5 | **The layout matches a real host.** The CLI's `HOME` is the directory that holds the repo (`tmp_path`, since the `configured` repo is `tmp_path / "repo"`), because the real Proxy inherits the runner's `HOME` and the repo usually lives under it. `CLAUDE_CONFIG_DIR` is `tmp_path / "cli-config"`. The real home is never read (charter). | AC1 |
| E6 | **A form that gets through is fixed in the OS sandbox settings, not the token hook.** The fix goes in `sandbox._sandbox_section` / `_allowed_reads` as data. Known shapes: (a) a path in `allowRead` that covers the secret: narrow `_allowed_reads`; (b) a spelling Seatbelt does not match (a symlinked `/var` against the resolved `/private/var`): `denyRead` lists every spelling of the repo through a new `_repo_spellings(config) -> list[str]` (the path as configured and its resolved form, deduplicated, in that order). The leaking row then passes in the e2e test, and a unit test in `tests/test_sandbox.py` pins the new settings. A leak that fits neither shape (for example, case on APFS, where Claude Code's settings cannot express a case-insensitive deny) is **not** patched by guesswork. The developer hands off `blocked` with the row's control and sandboxed output, and the story returns to design. | AC2 |
| E7 | **One platform table, extended by s60.** `scripted_cli.PROXY_SANDBOX_PLATFORMS = ("darwin",)` lists the platforms whose Proxy OS sandbox the e2e tests run on. The s12 module's `pytestmark` skips on any other platform with `PROXY_SANDBOX_SKIP` as the reason. s60 adds `"linux"` to the tuple when the Proxy gets a working Linux sandbox. Nothing else changes for that. s58's own skip stays separate, because it is about `allowLocalBinding`, not about reads. | AC3 |
| E8 | **The token hook is not changed.** `guard._check_tokens`, `paths.could_climb`/`reaches` and their tests stay as they are. The story's ACs are about the sandbox (t101). | AC1, AC2 |

### Out of scope

- P3 (an installed package's source readable inside the sandbox): it comes with the `package` kind (story notes).
- Pure token tricks (`cd {..,}`, `pushd`, `$'…'`, `$"…"`, glued `;`/`&`/`|`): they only fool the text check. At the system call they become one of the `cd` or absolute-path rows below.
- Symlinks made inside the sandbox: not in the original story.

## The probe table

The secret is `<repo>/src/secret.txt`, holding one line `MARKER = "s12-secret-6c1f"`.
`src/**` is a source glob in `PY_CONFIG`, so `src` is a forbidden root. `R` is
`str(repo)` as the `repo` fixture gives it. `UP` is `len(Path(os.path.relpath(repo,
prepared.workdir)).parts)`, the number of `..` steps from the workdir to the repo.

| Row (`name`) | Form (story) | Command |
|---|---|---|
| `cd-up` | `cd ..` | `cd ..` joined by ` && ` `UP` times, then ` && cat src/secret.txt` |
| `cd-home` | `cd` with no argument | `cd && cat repo/src/secret.txt` |
| `cd-root` | `cd /` | `cd / && cat {R without its leading /}/src/secret.txt` |
| `tilde` | `~` | `cat ~/repo/src/secret.txt` |
| `home-var` | `$HOME` | `cat "$HOME/repo/src/secret.txt"` |
| `env-var` | `$VAR` holding a path (from the environment, as the runner's env would) | `cat "$S12_SECRET_DIR/secret.txt"`, with `S12_SECRET_DIR = R + "/src"` in the CLI's environment |
| `shell-var` | `$VAR` set in the command | `S="{R}/src"; cat "$S/secret.txt"` |
| `command-sub` | `$(…)` | `cat "$(printf %s '{R}')/src/secret.txt"` |
| `wildcard` | wildcard absolute path | `cat {R}/s?c/secret.*` |
| `option-glued` | `--file=/abs/path` | `echo {MARKER} \| grep --file={R}/src/secret.txt` (prints the marker only if grep read its pattern file) |
| `case` | P4, case on a case-insensitive volume | `cat {tmp_path}/REPO/src/secret.txt`. The row is in the table only when `(tmp_path / "REPO" / "src" / "secret.txt").exists()` from the test process. |

`PROBES` is a list of `Probe(name: str, command: str)` built by
`probes(layout: ProbeLayout) -> list[Probe]`. `ProbeLayout` is a frozen
dataclass with `repo: Path`, `home: Path` and `workdir: Path`. Commands are
f-strings over it (quote `R` with `shlex.quote` where it stands bare).

### One script, labelled sections

`probe_script(probes: list[Probe]) -> str` joins one block per row with `; `:

```sh
printf '\n@@ %s\n' NAME; ( COMMAND ) 2>&1; printf '\n@@ exit=%s\n' $?
```

`sections(text: str) -> dict[str, Section]` parses the tool result back into
`Section(output: str, code: int)` per name. A missing section is simply absent
from the dict, and E4 then fails on it. Each row runs in a subshell, so its `cd`
does not reach the next row.

## Changes per module

### New `agile-team/runner/tests/e2e/scripted_cli.py` (integration-tester)

This is a helper module, not a test file. It is s58's scripted-model harness,
moved here so both e2e tests share it (DRY). The module docstring says what it is.
It holds no code at global scope beyond constants (charter): the bundled CLI path
becomes a function.

```python
PROXY_SANDBOX_PLATFORMS: tuple[str, ...] = ("darwin",)
PROXY_SANDBOX_SKIP = (
    "the Proxy's OS sandbox is verified only on macOS (Seatbelt); "
    "s60 adds linux to scripted_cli.PROXY_SANDBOX_PLATFORMS"
)
CLI_S = 600

def bundled_cli() -> Path: ...            # claude_agent_sdk's _bundled/claude
def sse(event: str, data: dict) -> bytes: ...
def message(blocks: list[dict], stop: str) -> dict: ...
def stream(msg: dict) -> bytes: ...
def tool_results(body: dict) -> list[str]: ...
def make_model(command: str, recorded: list[str]) -> type[BaseHTTPRequestHandler]: ...

@dataclass(frozen=True)
class CliRun:
    """One scripted CLI run: settings, working dir, home, config dir, extra env."""
    settings: dict
    cwd: Path
    home: Path
    config_dir: Path
    env: dict[str, str] = field(default_factory=dict)

def run_scripted(run: CliRun, command: str) -> tuple[int, list[str]]:
    """Run the bundled CLI against a model that asks for ``command`` once; return code and tool results."""
```

`run_scripted` behaves like s58's `run_cli`: the same environment keys
(`PATH`, `HOME`, `CLAUDE_CONFIG_DIR`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`,
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`) plus `run.env`, the same flags, the
600 s outer timeout with the output tail on failure, and the 600000 ms Bash
`timeout` in the tool call. The settings file goes in `run.config_dir.parent`.

### `agile-team/runner/tests/e2e/test_proxy_sandbox_e2e.py` (integration-tester)

The s58 helpers are deleted and imported from `.scripted_cli`. `run_cli` keeps

### New `agile-team/runner/tests/e2e/test_s12_proxy_escapes_e2e.py` (integration-tester)

- `pytestmark = pytest.mark.skipif(sys.platform not in PROXY_SANDBOX_PLATFORMS, reason=PROXY_SANDBOX_SKIP)` (E7). A missing bundled CLI is a failure, not a skip.
- Fixture `escape(configured, tmp_path)`: writes `src/secret.txt`, loads the config, takes `c.environments[0]` (the `cli` package environment in `PY_CONFIG`), `prepared = sandbox.layout(c, env)`, and returns the settings, `prepared` and `probes(ProbeLayout(repo, tmp_path, prepared.workdir))`.
- `bare(settings) -> dict`: a deep copy with `["sandbox"]["enabled"] = False` and `permissions` removed (E3).
- `test_every_escape_probe_reads_the_secret_without_the_sandbox`: the control run. Every row's section is present and its output contains `MARKER` (E3).
- `test_the_proxy_sandbox_refuses_every_escape_form`: the sandboxed run. `{name: leaked}` equals `{name: False for every probe}`, where leaked means the section is missing, holds `MARKER`, or has exit 0 (E4).
- Both runs pass `env={"S12_SECRET_DIR": f"{repo}/src"}`, `home=tmp_path`, `config_dir=tmp_path / "cli-config"` (E5).

### `agile-team/runner/agile_team/sandbox.py` (developer-cli, only under E6)

No change while every row is refused. Under E6 (b) only:

```python
def _repo_spellings(config: Config) -> list[str]:
    """The repo as configured and resolved, each once: Seatbelt matches the spelling it sees."""
```

`_sandbox_section` then uses `"denyRead": _repo_spellings(config)`. Nothing else
in the settings changes.

## Test checklist

E2E (integration-tester):

- [ ] Control: all `PROBES` rows show the marker unsandboxed (E3, AC1).
- [ ] Sandboxed: no row leaks, and each is named in the failure map (E4, AC1).
- [ ] The `case` row is present on a case-insensitive volume and absent otherwise (E1).
- [ ] The module skips off `PROXY_SANDBOX_PLATFORMS` with `PROXY_SANDBOX_SKIP`, which names s60 (E7, AC3).
- [ ] s58's two tests pass unchanged on the shared helper.

Unit (unit-tester): no unit tests while every row is refused. These tests prove
existing behaviour, so they may pass at once, and that is expected (story notes:
"A test that passes closes the story"). Under E6 (b), the developer adds to
`tests/test_sandbox.py` a test that `denyRead` holds both spellings when they
differ and one when they are equal.

Gates: coverage stays at 95%+, and `ruff check` and `ruff format` are clean.
