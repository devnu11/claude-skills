# s96: Time per role on the Flow chart, and a Time measure in "Tokens by"

Developer: `developer-gui` (one small pure Python module and one snapshot
section, then the page). No ADR: no new dependency, no new event kind, no
new state. The snapshot gains one list section, `steps`.

## Rules

- **ST1. A step is a start/end pair from `events.jsonl`.** The log is read in
  file order (`RunFiles.events`, the raw log; not the merged `_events`). A
  `step-start` opens the key `(role, story)`. The next `step-end` with the
  same key closes it. A `step-end` with no open start is ignored.
- **ST2. A second start drops the first.** A `step-start` for a key that is
  already open drops the earlier open start, which counts nowhere. Recovery
  always writes the killed step's end before the next start, so this happens
  only in a damaged log.
- **ST3. Wall time.** For a finished step, `seconds = round(max(0, end.at -
  start.at), 1)`.
- **ST4. A killed step has no time.** A step whose end has `data.cause ==
  "killed"` (`salvage.Cause.KILLED`) was closed by recovery at the next
  start, so the span would include the downtime. Its `seconds` is `null`.
  It is still finished (`ended_at` set) and still counts as a step. Ends
  with any other cause (halt, usage limit, `stop --now`) are written when
  the step stops, so their time counts.
- **ST5. A running step.** An open start at the end of the log is running:
  `ended_at`, `seconds` and `status` are `null`, and `at` is its start time.
- **ST6. Sprint.** `sprint` is the `data.sprint` of the last `sprint-start`
  event before the step's start in the log, or `null` before any sprint.
  This is the sprint the step ran in. The page's Sprint scope still uses the
  ledger's rule (ST10), so tokens and time in a box cover the same steps.
- **ST7. Model.** `model` is the end's `data.model`. When that is missing or
  null (a running step, an old log, a step with no turn), the snapshot uses
  the role's configured model (`_role(files, role)["model"]`), else
  `"unknown"`. The snapshot's `model` is never null.
- **ST8. Only agent steps count (AC4).** Gate runs, syncs, presentation
  builds and other runner stages have no `step-start`/`step-end`, so they
  are not counted. Product Owner queries are not steps either: the PO box
  shows no time (left to A6, with the runner's stages).
- **ST9. Duration format.** `fmt.span(seconds)`: `0 min` for 0, `<1 min`
  under a minute, `N min` under an hour, `H h M min` from an hour
  (`3725` → `1 h 2 min`). Minutes are floored. Used by the box totals, the
  running time, the Time bars and their tooltips.
- **ST10. Box time follows the Flow scope (AC2).** Each ring role's box adds
  its total `seconds` over the finished steps in the chosen scope. The scope
  filter is the one the ledger uses today: Story = `story === focus`; Run =
  all; Sprint = the sprint's member stories, or an unstoried row whose `at`
  falls in that sprint's window. One predicate serves both lists.
- **ST11. Running time on the box (AC2).** A role with an open step shows a
  line `⏱ running <fmt.span(clockNow(view) - step.at)>` whatever the scope.
  The page re-renders the Flow chart once a second while the Flow tab is
  shown (`tick`). `renderFlow` redraws only when the Mermaid source changes,
  so with minute granularity the chart redraws about once a minute.
- **ST12. Time is one `UNITS` row (AC3).** `UNITS.time = { label: "Time",
  title: "Time by", totals, total, legend, row }`. Each unit row gains a
  `totals(view, key)` entry, so `barRows` never branches on the unit.
- **ST13. Time bars.** One bar per group (Role, Story, Model, as the group
  toggle chooses) of the summed `seconds` of finished steps, largest first,
  labelled with `fmt.span`. The tooltip gives the group, its time, its share
  of the total time, and the step count: `<b>architect</b><br>1 h 2 min
  <span class="k">(34% of time)</span> · 5 steps`. Killed steps count as
  steps and add no time.
- **ST14. Legend (AC4).** With Time chosen, the legend reads `Step time
  (agent steps only; runner stages: see A6)` with one swatch in `--s2`.
- **ST15. Replay.** In mock replay, `asOf` keeps steps that started at or
  before the cursor. A step whose end is after the cursor is shown as
  running.

## Snapshot contract

New section `steps`, after `ledger`. One object per step, in start order:

```json
{"role": "architect", "story": "s1", "model": "opus", "sprint": 1,
 "at": 1791452316.6, "ended_at": 1791452620.3, "seconds": 303.7,
 "status": "done"}
```

| key | value |
|---|---|
| `role` | the step's role |
| `story` | the story id, or null for a storyless step (Manager, fix steps) |
| `model` | ST7, never null |
| `sprint` | ST6, int or null |
| `at` | the step-start time |
| `ended_at` | the step-end time; null while running |
| `seconds` | ST3; null while running (ST5) and for a killed step (ST4) |
| `status` | the end's `data.status` (`done`, `interrupted`, …); null while running |

The fixture `dashboard/fixtures/snapshot.json` gains `steps`. They are
exactly what `_steps` gives for the fixture's own events and roles. The
fixture's last step (`e`-id of the last `step-start` with no end) is
running.

## Changes per module

### `agile_team/dashboard/step_times.py` (new, pure, no I/O)

```python
"""Wall time of agent steps, paired from the event log (s96)."""

from __future__ import annotations

from collections.abc import Callable
from dataclasses import asdict, dataclass, field, replace
from typing import Any

from ..events import EventKind
from ..salvage import Cause

Key = tuple[str | None, str | None]


@dataclass(frozen=True)
class Span:
    """One agent step: start time, and end, status and wall time once it ends."""

    role: str
    story: str | None
    at: float
    sprint: int | None = None
    ended_at: float | None = None
    status: str | None = None
    model: str | None = None
    seconds: float | None = None

    def as_dict(self) -> dict[str, Any]:
        """The snapshot's object for this step (keys as in the table above)."""


@dataclass
class Pairing:
    """One walk over the log: the steps found, the open ones by key, the running sprint."""

    found: list[Span] = field(default_factory=list)
    open: dict[Key, int] = field(default_factory=dict)   # key → index in found
    sprint: int | None = None

    def start(self, event: dict) -> None:
        """ST1/ST2: open the key, dropping an earlier open start of the same key."""

    def end(self, event: dict) -> None:
        """ST1/ST3/ST4: close the key's open step; ignore an end with none open."""

    def sprint_start(self, event: dict) -> None:
        """ST6: remember ``data.sprint``."""


FEEDS: dict[str, Callable[[Pairing, dict], None]] = {
    EventKind.STEP_START: Pairing.start,
    EventKind.STEP_END: Pairing.end,
    EventKind.SPRINT_START: Pairing.sprint_start,
}


def spans(events: list[dict]) -> list[Span]:
    """Every agent step in start order; open ones are running (ST1–ST6)."""


def closed(span: Span, end: dict) -> Span:
    """``span`` finished by the ``end`` event: ``ended_at``, ``status``, ``model``, ``seconds``."""


def wall_seconds(span: Span, end: dict) -> float | None:
    """ST3, or None for a killed step (ST4)."""
```

Notes for the developer:
- `spans` loops `FEEDS.get(e.get("kind"))` and skips other kinds. No `if`
  chain on the kind.
- Dropping an open start (ST2) removes it from `found`. Removing shifts the
  indexes in `open`, so either rebuild `found` without dropped entries at
  the end (keep a `dropped: set[int]`), or store `None` in `found` and
  filter at the end. Pick one. Either way the order of `found` is start
  order.
- `data` may be absent: read `event.get("data") or {}`.
- `Cause.KILLED` compares as the string `"killed"` (`StrEnum`).

## Known limits

- A killed step counts as a step with no time (ST4).
- A run killed and not yet restarted keeps its open step "running" on the
  box, as the pill's `▶ … · ago` does today.
- PO time and the runner's own stages are not measured (A6).
- The fallback model for an old step is today's configured model, which
  may differ from the one that ran.
