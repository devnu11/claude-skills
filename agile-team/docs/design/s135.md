# s135: The liaison writes stories through a validated CLI; the runner onboards them

Story: `.team/stories/s135.md`. Requirements: REQ-037 (AC1), REQ-038 (AC2),
REQ-039 (AC3), REQ-040 (AC4), REQ-041 (AC5); each also covers AC6 (tests).
ADR: ADR-0070 (new). Developer: `developer-cli`.
Plan: `.team/run/liaison/plans/liaison-writes-stories-clean.md`, story H.
Docs: s136 (story I, `depends_on: [s135]`) rewrites the PO's role prose,
`liaison-template.md`, `SKILL.md`, `protocol.md` and the README row. This
story changes only the PO role file's `write:` list (S2). This design also
updates `architecture.md` and `customer/backlog-and-sprints.md`.

## Why

Today the PO writes `.team/stories/<id>.md` and `open_story` registers it.
The file reaches git inside the PO's `chore(team): product-owner step`
commit, which no story records. The liaison, who knows the ask best, may not
commit in the team's chain: the runner rewrites, reverts and cherry-picks
history, and an outside commit is in no story's record and can race a step.
Now the liaison sends a draft, the CLI checks and queues it, and the runner
commits it as the story's own recorded commit. The PO schedules, and asks
for stories with `request_story`.

## Rules

### Q: the command and the queue (AC1)

- **Q1 Forms.**
  ```
  agile-team story new <file.md> --approved-by human|none [--sprint current|next|backlog] [--after <id>] [--plan <path>]
  agile-team story amend <id> <file.md> --approved-by human|none [--plan <path>]
  ```
  One `Command("story", …)` row with positionals `action` (choices `new`,
  `amend`) and `target` (`nargs="+"`). `new` takes exactly one target
  (`<file.md>`), `amend` exactly two (`<id> <file.md>`). Otherwise it fails
  with `CliError(USAGE)`, where
  `USAGE = "story new takes <file.md>; story amend takes <id> <file.md>"`.
  `--approved-by` is required (choices `human`, `none`). `--sprint` defaults
  to `None`, which `new` treats as `backlog`. `--after` and `--plan` default
  to `""`. `--plan` is this design's addition: it fills the AC3 example
  "approved plan `<path>`" (open question to the PO).
- **Q2 The draft.** UTF-8 Markdown with YAML frontmatter:
  - `title`: a non-empty string;
  - `acceptance`: a non-empty list of `{id, text, environment}`;
  - `depends_on`: optional, a list of story ids;
  - the body: the user story, which must not be blank.

  `id` and `shared` are refused because the runner writes them. Any other key
  is kept as written.
- **Q3 Checks.** All of them run, and every problem is one line:
  1. The file must be readable: `cannot read <file>: <strerror>`. If it
     isn't, items 2 to 4 are skipped and items 5 and 6 still run.
  2. `story_spec.parse` on a `Kind.DRAFT` source (`file` = the path as typed)
     gives the existing problem lines (no frontmatter or bad YAML stop the
     parse; otherwise title, criteria, each AC's id, text and environment
     against `config.environments`), plus one
     `{file}: {key} is written by the runner; remove it` per key in
     `story_spec.RUNNER_KEYS = ("id", "shared")`. The id check is not run.
  3. `depends_on` (only when the frontmatter parsed):
     - not a list of strings: `{file}: depends_on must be a list of story ids`;
     - ids not in `state.stories`:
       `{file}: depends_on names unknown stories: {ids}` (natural order).
  4. A blank body: `{file}: the body must hold the user story`.
  5. Options:
     - `--after` not in `state.stories`: `--after: no story '<id>'`;
     - `--after` naming a story in `gates.FINISHED`:
       `--after: <id> is <status>; name an open story`;
     - `--plan` with `none`: `--plan needs --approved-by human`;
     - `--plan` naming no file: `--plan: no file <path>`.
  6. `amend` only:
     - an unknown target: `no story '<id>'`;
     - a finished target: `<id> is <status>; story amend changes open stories only`;
     - `--sprint` or `--after` given: `--sprint and --after apply to story new only`;
     - a target story file with no readable frontmatter:
       `cannot amend <id>: <file> has no readable frontmatter`.

     When both frontmatters parsed:
     - title differs:
       `{file}: title is '<new>', not <id>'s '<old>'; story amend replaces only the ACs`;
     - `depends_on` differs (a missing key is `[]`):
       `{file}: depends_on is [<new>], not <id>'s [<old>]; story amend replaces only the ACs`;
     - the draft's criteria equal the target's parsed criteria:
       `{file}: the ACs are the same as <id>'s; nothing to amend`.

  Any problem raises `CliError("\n".join(lines))`. The command exits 1 and
  queues nothing.
- **Q4 Queue.** A clean draft is queued as `.team/run/liaison/stories/q<N>.json`
  through `NumberedQueue(folder, "q", ".json")` (ADR-0069). The JSON object
  has these fields, all required, every one a string except `at`, a number:
  `action` (`new` or `amend`), `story` (the amend target, `""` for new),
  `approved_by`, `plan` (repo-relative when it is inside the repo, else as
  typed), `sprint` (`current`, `next` or `backlog` for new, `""` for
  amend), `after`, `file` (as typed), `text` (the draft's full text) and `at`
  (`system.now()`).
  It prints one line, then exits 0:
  - new: `queued q<N>: new story "<title>" (<approved>); the runner gives it an id and commits it between steps`;
  - amend: `queued q<N>: new ACs for <id> (<approved>); the runner commits them between steps and sends <id> back to design; the draft's body is not used`.

  `<approved>` is `approved by the human` or `written by the liaison alone`.
- **Q5** The command never writes `.team/stories/`, never calls git and works
  in any run state. A stopped run onboards the request at its next `start`.

### O: onboarding (AC2, AC3)

- **O1 When.** Each router tick runs `self.intake.apply()` right after
  `self.sharer.apply()`. It settles every request whose id is not in
  `state.story_requests`, in number order. It returns at once while
  `state.boundary` is open, unless `boundary.hold` is in
  `INTAKE_HOLDS = {CI_FAILED, CI_INFRA, MAIN_BROKEN}`: there the PO needs a
  bug story for `record_ci_bug`, and the tree is clean.
- **O2 New story.** Settling a `new` request:
  1. **Check again.** Run Q3 items 2 to 4 against the current config and
     state. Any problem refuses the request (R1) with the lines joined by `; `.
  2. **The id.** `story_drafts.next_id(names)`, where `names` is the
     `state.stories` keys plus the stems of `stories_dir/*.md`. It is
     `s<max N + 1>` over the names that match `^s(\d+)$`, or `s1` when none
     match.
  3. **The file text.** `story_drafts.with_id(text, sid)` puts the line
     `id: <sid>` straight after the opening `---`. `story_spec.parse` (FILED)
     must find no problems in the result. If it does, the request is refused
     with `cannot write <file>: <problems>`.
  4. **The commit.** Write the file and run
     `git.commit_by([file], story_drafts.commit_message(request, Target(sid, title)))`.
     On a `GitError`, remove the file, run `git.attempt("reset", "-q")` and
     refuse with `commit failed: <error>`.
  5. **The record.** Add
     `StoryState(sid, title, pipeline.first(), depends_on=given, file_commits=[sha], files=[file])`,
     save, `record_checkout()`, then emit `story-opened` (E1).
  6. **Placement** (P1 to P4).
  7. **Settle.** Set `state.story_requests[q<N>] = "opened <sid> <sha12>; <placed>"`,
     save, tell the PO (H1) and post to the liaison (H2).
- **O3 Commit message (AC3).**
  ```
  docs(<sid>): created story to <title>

  Human-involvement: <involvement>
  Liaison-request: q<N>
  ```
  `git_ops.with_trailer` adds the usual `Co-Authored-By` trailer. An amend's
  subject is `docs(<sid>): amended story to <title>`. `<title>` has its
  whitespace runs joined to single spaces (`" ".join(title.split())`).
  `<involvement>`:
  - `human` with a plan: ``approved plan `<plan>` ``;
  - `human` without one: `approved by the human`;
  - `none`: `none: written and submitted by the liaison`.

  Author: `human` passes no `--author`, so git uses the repo's configured
  user, the human. `none` passes
  `--author=Claude (agile-team liaison) <noreply@anthropic.com>`
  (`story_drafts.LIAISON_AUTHOR`).
- **O4 Recorded like a step commit.** `StoryState.file_commits` is a list of
  the runner's commits of the story file: the creation and each amend.
  - `rewrite._story` remaps it, so the sprint-start rebase keeps it.
  - `reverts.reverted_story` copies it, so a revert keeps it.
  - The snapshot's story `commits` lists it first.
  - It is **not** `story.commit`. `priority.started` is unchanged, and
    `revert_story`'s R4(b) (subject of `story.commit` or its `fixup!`) never
    picks it, so a reverted story keeps its file and goes back to the backlog
    with it.
  - Review branches are built from each sprint's commit range, so the
    commit rides in the review branch of the sprint it was committed in. For
    `--sprint current`, that is the story's own sprint. No stack code
    changes.

### P: placement (AC2)

- **P1 `current`.** Build
  `Addition([sid], PLACE_REASON, Source.LIAISON, after)`. When
  `SprintAdd.refusal` is `None`, call `SprintAdd.apply`: the story joins the
  sprint, a `sprint-add` event is logged with role `liaison`, and the order
  is `with_after` when `after` is set, else `with_first`. A refusal (no open
  sprint, an unmet `depends_on`, a held boundary) places the story as
  `backlog` instead (P3), and `<placed>` says
  `in the backlog; not added to sprint <n>: <refusal>`.
- **P2 `next`.** The story stays in the backlog. The anchor is the open
  `after`, else the last id in `priority().plan(...)` (without the new
  story) that is in the current sprint. With no anchor it goes first
  (`with_first([sid])`).
- **P3 `backlog`.** The story stays in the backlog. The anchor is the open
  `after`, else the plan's last id (without the new story), which puts it at
  the end. With an empty plan the order is `[sid]`.
- **P4 Reorders.** P2 and P3 call
  `Runtime.reorder(Reorder(Change.MOVE, order, sid, PLACE_REASON, Pull(), Source.LIAISON))`.
  The order comes from `Priority.with_after(After(sid, anchor), stories)` or
  `with_first`. `PLACE_REASON = "placed for the liaison's request q<N>"`. The
  human's-order check (`backlog.human_refusal`) is not run, because the
  liaison acts for the human. An `after` that has finished since it was
  queued is dropped, and `<placed>` gains `; --after <id> dropped: it is <status>`.
- **`<placed>` texts:** `in sprint <n>`, `in the backlog, first for the next sprint`,
  or `in the backlog`, plus ` after <id>` when anchored.

### H: hand-over (AC2)

- **H1 The PO.** `relay.tell(TOLD_NEW)`:
  `Runner note: the liaison's story q<N> is now <sid> "<title>" (<approved>; commit <sha12>), placed <placed>. Read <file>, then schedule it.`
  The router's `_unread` delivers it like any `tell`: this is the hand-over.
- **H2 The liaison.** `relay.post(Note("update", POSTED_NEW, [sid]))`:
  `Runner: story q<N> is <sid>, commit <sha12>, placed <placed>.`
- **E1 Event.** `story-opened`, role `liaison`, story `<sid>`. Its data:
  `{title, step, depends_on, request, commit, approved_by, sprint, after}`,
  where `sprint` and `after` are what was asked. The first three keys are
  what the old PO event had, and the dashboard replays on `step`.

### A: amend (AC4)

- **A1** Settling an `amend` runs Q3 items 2 to 4 and item 6's target and
  frontmatter checks again, against the current state and story file. Any problem refuses the request (R1).
- **A2** `story_drafts.with_criteria(old_text, criteria)` removes the
  top-level `acceptance:` block (`frontmatter.without_key`) and appends the
  rendered block (`render_criteria`) at the end of the frontmatter, leaving
  the body alone. A re-parse must give the same other keys, the same body
  and `acceptance` equal to the new criteria as dicts. Otherwise it returns
  `None`, and the request is refused with
  `cannot rewrite <file>'s acceptance block; fix its frontmatter`. The
  rendered block, ending with `\n`:
  ```
  acceptance:
    - id: "AC1"
      text: "…"
      environment: "cli"
  ```
  Each value is written with `json.dumps`, as `shares.render` does.
- **A3** Write the file and commit it alone, with the amend subject and the
  O3 body and author. On a `GitError`, write the old text back, run
  `git.attempt("reset", "-q")` and refuse with `commit failed: <error>`.
- **A4** Append the sha to `story.file_commits`. Run
  `pipeline.redesign(story)` (below), set `story.note = AMENDED_NOTE`, save
  and `record_checkout()`. Settle it as
  `state.story_requests[q<N>] = "amended <sid> <sha12>"`.
  `AMENDED_NOTE = "The liaison amended the ACs (q<N>); design against the new ACs and trace each to a requirement."`
- **A5 Event.** `story-amended` (`EventKind.STORY_AMENDED`), role `liaison`,
  story `<sid>`. Its data: `{request, commit, approved_by, from_step, step, old, new}`.
  `old` is the old frontmatter's `acceptance` list as written (`[]` when it
  is not a list), and `new` is the new criteria as `{id, text, environment}`
  dicts.
- **A6** Tell the PO:
  `Runner note: the liaison amended <sid>'s ACs (q<N>; <approved>; commit <sha12>). It is back at <step> from <from_step>. Old: <old ids>. New: <new ids>. Read <file>.`
  Post to the liaison:
  `Runner: story q<N> amended <sid>'s ACs, commit <sha12>; it is back at <step>.`
- **`Pipeline.redesign(story)`:**
  - `self._clear(story)`;
  - `story.step = self.design_step()`;
  - `story.hold = None`;
  - `story.tried = []` (every environment is tried again);
  - `story.trace = Trace.CHECKED` (the new ACs must be traced, even on a
    story designed before s1);
  - `NEEDS_MANAGER` becomes `ACTIVE`. `BLOCKED` (an open question) and the
    PO's `po_hold` stay.

### R: refusal

- **R1** A refused request (any O2/A1 to A3 refusal, or a request file that
  is not valid JSON of the Q4 shape) gets:
  - `state.story_requests[q<N>] = "refused: <reason>"`;
  - a `story-refused` event (`EventKind.STORY_REFUSED`), role `liaison`,
    story = the amend target or `None`, data `{request, action, reason}`;
  - `relay.post(Note("update", "Runner: story q<N> was refused: <reason>"))`.

  The PO is not told. A bad file's reason is
  `request_files.bad_request(...)`'s text, as for shares.

- **S5 `request_story(summary, evidence)`.** `SCHEMAS` row:
  `{"summary": str, "evidence": dict}`, with this description:
  `"Ask the liaison to write a story, for a bug the team couldn't fix in its own turns; you can't write story files. summary: what is wrong, in a sentence or two. evidence: {story, step, output, files}: the story and step where it showed (empty for a failure outside any story), the failing output, and the files involved. The liaison writes the story; the runner opens it and tells you its id."`
  Refusals, checked in order; the first wins and nothing is posted:
  1. blank summary: `a summary is required`;
  2. evidence not an object: `evidence must be an object {story, step, output, files}`;
  3. `story`, `step` or `output` present and not a string: `evidence.<key> must be a string`;
  4. a non-empty `story` not in `state.stories`: `unknown story '<id>'`;
  5. a blank `output`: `evidence.output must hold the failing output`;
  6. `files` present and not a list of strings: `evidence.files must be a list of paths`.

  Missing keys count as `""` or `[]`. The output keeps its last
  `MAX_OUTPUT = 6000` characters, headed `[first <n> characters cut]\n` when
  cut. It posts `Note("story-request", REQUEST_TEXT, [story] if story else [])`:
  ```
  The PO asks for a story: <summary>
  Story: <story> at <step>          (or "Story: none")
  Files: <a, b>                     (or "Files: none")
  Failing output:
  <output>
  ```
  It emits `story-request` (`EventKind.STORY_REQUEST`), role
  `product-owner`, story = the story or `None`, data
  `{message, summary, step, files}`. It returns
  `{"status": "requested", "message": <id>, "next": "the liaison writes the story; the runner opens it and tells you its id"}`.
  `relay.KINDS` gains `"story-request"`. It blocks nothing. `watch`'s
  `message` trigger fires on it like any outbox post.

## Changes per module

All paths under `agile-team/runner/agile_team/`.

### `frontmatter.py` (new, pure)

```python
"""Story-file frontmatter helpers shared by shares and story drafts (s135)."""
def parse(text: str) -> tuple[dict[str, Any], str] | None: ...   # roles.split_frontmatter; RoleError/YAMLError/no frontmatter -> None
```

### `request_files.py` (new, pure)

```python
@dataclass(frozen=True)
class Fields:
```

`shares` keeps `REQUEST_FIELDS` and calls `Fields(REQUEST_FIELDS).loaded(text)`.

```python
    DRAFT = "draft"   # a liaison draft (s135): no runner-written key; the runner adds the id
```

### `story_drafts.py` (new; pure)

```python
class Action(StrEnum): NEW = "new"; AMEND = "amend"
class Approval(StrEnum): HUMAN = "human"; NONE = "none"
class Placing(StrEnum): CURRENT = "current"; NEXT = "next"; BACKLOG = "backlog"
LIAISON_AUTHOR = "Claude (agile-team liaison) <noreply@anthropic.com>"
AUTHORS: dict[Approval, str] = {Approval.HUMAN: "", Approval.NONE: LIAISON_AUTHOR}
SUBJECTS: dict[Action, str] = {Action.NEW: "docs({story}): created story to {title}",
                               Action.AMEND: "docs({story}): amended story to {title}"}
APPROVED: dict[Approval, str] = {Approval.HUMAN: "approved by the human", Approval.NONE: "written by the liaison alone"}
REQUEST_FIELDS: dict[str, FieldKind]   # Q4 fields
# texts: USAGE, QUEUED (per Action), TOLD_NEW, TOLD_AMENDED, POSTED_NEW, POSTED_AMENDED, POSTED_REFUSED,
#        PLACE_REASON, PLACED (per Placing), AFTER, NOT_ADDED, AFTER_DROPPED, AMENDED_NOTE, the Q3 lines

@dataclass(frozen=True)
class StoryRequest:
    id: str; action: Action; story: str; approved_by: Approval; plan: str
    sprint: str; after: str; file: str; text: str; at: float = 0.0
    def to_json(self) -> str: ...
    @classmethod
    def from_json(cls, rid: str, text: str) -> StoryRequest | BadRequest: ...  # Fields(REQUEST_FIELDS); bad enum values are bad requests

@dataclass(frozen=True)
class Known:
    """What the checks compare a draft with."""
    environments: tuple[str, ...]
    stories: Mapping[str, StoryState]
    target_text: str | None = None     # the amend target's story file, None when missing

@dataclass(frozen=True)
class Draft:
    spec: story_spec.Spec          # story ""
    depends_on: tuple[str, ...]
    meta: dict[str, Any]

@dataclass(frozen=True)
class Checked:
    draft: Draft | None
    problems: tuple[str, ...] = ()

@dataclass(frozen=True)
class Target:
    story: str
    title: str

def draft_problems(request: StoryRequest, known: Known) -> Checked: ...  # Q3 items 2-4, plus item 6's target and frontmatter checks for an amend
def option_problems(request: StoryRequest, known: Known) -> list[str]: ...  # Q3 item 5 and item 6's --sprint/--after line; --plan file existence is the CLI's
def next_id(names: Iterable[str]) -> str: ...                            # O2.2
def with_id(text: str, story: str) -> str: ...                           # O2.3
def render_criteria(criteria: Sequence[story_spec.Criterion]) -> str: ...  # A2 block
def with_criteria(text: str, criteria: Sequence[story_spec.Criterion]) -> str | None: ...  # A2
def involvement(request: StoryRequest) -> str: ...                       # O3
def commit_message(request: StoryRequest, target: Target) -> Authored: ...  # O3: subject, body, AUTHORS[approved_by]
def criteria_data(criteria: Sequence[story_spec.Criterion]) -> list[dict[str, str]]: ...
```
`draft_problems` is the only check the runner re-runs (O2.1, A1). Its `file`
label is `request.file`. Keep each function under 8 lines; split the Q3
items into one small function each, listed in a `DRAFT_CHECKS` table.

### `story_intake.py` (new; the queue and the runner side)

### `cli.py`

```python
def cmd_story(args: argparse.Namespace) -> int:
    """Check a liaison's story draft and queue it for the runner (s135); never commits."""
STORY_ARGS: tuple[Arg, ...] = (
    (("action",), {"choices": [a.value for a in Action]}),
    (("target",), {"nargs": "+", "help": "new: <file.md>; amend: <id> <file.md>"}),
    (("--approved-by",), {"required": True, "dest": "approved_by", "choices": [a.value for a in Approval]}),
    (("--sprint",), {"choices": [p.value for p in Placing], "default": None}),
    (("--after",), {"default": "", "help": "place it right after this story"}),
    (("--plan",), {"default": "", "help": "the plan the human approved (needs --approved-by human)"}),
)
```
The row goes right after `share`:
`Command("story", "write a story (new) or replace its ACs (amend) from a draft file; the runner commits it", cmd_story, STORY_ARGS)`.
`cmd_story`:
1. Build the `StoryRequest` (`_story_request(args)`; USAGE on a bad target count).
2. Read the draft with `system.read_text`. An `OSError` gives the Q3 item 1 line.
3. Load the config and state, and the target's text for an amend.
4. Collect `draft_problems` (when the file was read) and `option_problems`,
   plus the CLI's own `--plan` file check (`system.is_file`).
5. Raise `CliError` on any problem. Otherwise
   `StoryQueue(config.run_dir).queue(request)` and print `QUEUED`.

`status_report` gains
`"queued_stories": [r.id for r in StoryQueue(run_dir).pending(st.story_requests)]`
and `"story_requests": st.story_requests`.

## Test checklist (AC6)

**Unit** (unit-tester; FakeSystem and the fake git, as `test_s120_sharer.py`
does). Put them in `tests/test_s135_story_cli.py`,
`tests/test_s135_intake.py` and `tests/test_s135_po.py`:

1. `story new` with a clean draft queues `q1.json` with every Q4 field, and
   prints `QUEUED`. `.team/stories/` and git are untouched (no git call).
2. A draft with several problems (no title, an AC with an unknown
   environment, a duplicate AC id, an `id` key, `depends_on` naming an unknown
   story, a blank body, `--after` unknown) is refused with **every** line,
   exits 1, and leaves the queue folder empty.
3. An unreadable file gives its read line plus the option lines. Wrong
   target counts give `USAGE`. `--plan` with `none` and a missing plan file
   are refused.
4. `story amend`: unknown and done targets, `--sprint`/`--after`, a
   different title, a different `depends_on`, and identical ACs are each
   refused.
5. Intake, new story: the next id skips ids in state and in files. The
   file's text is `---\nid: <sid>\n` plus the draft. There is one commit with
   exactly that file, the O3 subject and body, and
   `state.stories[sid].file_commits == [sha]`. The checkout is recorded.
   `story_requests[q1]` starts `opened <sid>`. A `story-opened` event comes
   with role `liaison` and the E1 data, then one tell (H1) and one liaison
   post (H2).
6. Authorship: `none` commits with `--author=<LIAISON_AUTHOR>` and the
   `none: written and submitted by the liaison` line. `human` commits with
   no `--author`, and its line is "approved plan" plus the plan path in
   backticks, or `approved by the human` without a plan.
7. Placement:
   - `current` with an open sprint: in the sprint, first in the plan, a
     `sprint-add` event with role `liaison`;
   - `current` with no open sprint: backlog, with the `not added` text;
   - `next`: right after the sprint's last story;
   - `backlog`: last;
   - `--after s2`: right after s2 in each mode;
   - a finished `--after` is dropped, with its text;
   - the priority events' role is `liaison`.
8. Safe point: nothing is settled while a boundary is open. It is settled
   at a `ci_failed` hold, but not at a `sync_conflict` hold. Each request
   settles once, in number order. A refused re-check (an environment
   removed from the config) gives R1: the state text, a `story-refused`
   event and a liaison post, with no commit and no tell. A bad JSON file is
   refused the same way. On a `GitError` the file is removed and the tree
   is left clean.
9. Amend: the `acceptance` block is replaced and the other keys and the body
   are kept. There is one commit with the amend subject, appended to
   `file_commits`. The story moves from implement to design: rounds reset,
   hold cleared, `tried == []`, `trace == checked`, the note set. A
   `story-amended` event carries `old` and `new`. A frontmatter whose block
   can't be rewritten is refused.
10. `rewrite.remap_state` remaps `file_commits`. `reverts.reverted_story`
    keeps them. `reverts.story_commits` never returns the `docs(sN):
    created story to …` sha (the subject differs). The snapshot's `commits`
    list starts with the file commit.
11. Guard: the PO's `Write` and `Edit` on `.team/stories/s1.md` are refused
    with `RUNNER_ONLY`, even when a test scope's `write` globs include
    `.team/stories/**`. A story-file change in a step's tree is out of
    scope.
12. `request_story`: the six refusals, in order. A good call posts one
    `story-request` outbox message with the S5 text and the story in
    `stories`, emits `story-request`, and returns `requested`. Output over
    `MAX_OUTPUT` keeps its tail with the cut head. `open_story` is not in
    `SCHEMAS` or `tool_names()`.
13. `sprint_add`: the PO's `add_to_sprint` keeps its refusals, texts, event
    and result (the existing tests stay green). `Priority.with_after`
    covers anchor present, anchor missing and story already listed.
14. `story_spec`: a DRAFT source skips the id check and reports
    `RUNNER_KEY` per key. FILED is unchanged.
    `frontmatter.without_key` drops a block whose items sit at column 0.
    The `shares` tests stay green.
