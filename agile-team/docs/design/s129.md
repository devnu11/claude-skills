# s129: No test depends on the real clock

Story: `.team/stories/s129.md`. Source: the human's t94 (open-questions items 1
and 4b). Requirements: REQ-024 (AC1, AC2), REQ-025 (AC3). ADR-0066.

Developer: `developer-cli`. Every change is under `agile-team/runner/tests/`.
No runtime module, snapshot key or CLI changes, so `SKILL.md`, `protocol.md`
and the README stay as they are. `guidelines.md` gets the rule (done at design).

Who does what:
- **unit-tester**: the new scan test `tests/e2e/test_s129_clock_scan_e2e.py`
  and the helper tests (below). The scan is red until the developer's changes
  land.
- **developer-cli**: the new helper `tests/clock.py`, `tests/dashboard_node.py`,
  `tests/e2e/readiness.py`, and every existing test the scan flags. AC3 is the
  rule that lets these assertions change from `==` to `about(...)`. That is not
  a weakening: an exact compare on a computed duration is wrong under AC3.

## Why the test failed

`test_s97_awake_page_e2e.py` pins the page's "now" with
`data.skew = NOW - Date.now() / 1000`. The page's clock is
`nowS() = Date.now() / 1000 + data.skew`, so a millisecond that passes between
setting the skew and calling `awakeSoFar` shows up in the result
(`480.00099… == 480`). Computing the skew from the real clock doesn't pin
anything. The fix is to freeze `Date.now` itself.

## Rules

1. **Only `tests/clock.py` reads the real clock.** No other file under
   `agile-team/runner/tests/` contains a real-clock read (the forms in
   `REAL_CLOCK_READS` below). There is one other exemption: the scan test,
   because it holds those forms as samples. Unit tests keep using the fake
   clock (`FakeSystem`), and the scan makes sure they never use anything else.
2. **e2e tests read the real clock only where a real process compares it with
   its own clock**: stamping events or heartbeats that a live dashboard or
   runner reads, deadlines for waits, and the `system` seam's own e2e test.
   They use `clock.real_now()`, `clock.real_monotonic()` or `clock.Deadline`.
3. **The page's clock is frozen under node.** `dashboard_node.run_page` always
   replaces `Date.now` with a constant before the page script loads. The
   default is the fixture's `generated_at` ("pin now to the fixture"). A driver
   whose `view` is a served snapshot passes that snapshot's `generated_at`. A
   driver with its own timeline passes its own `NOW`. Drivers never set
   `data.skew`: it stays `0`.
4. **Durations are compared with a tolerance.** An `assert` that compares a
   duration with `==` or `!=` uses `about(x)` (or `pytest.approx(x, abs=…)`
   with a comment saying why the default tolerance is not enough). A duration
   is a value whose name is in `DURATION_NAMES`. Formatted strings such as
   `"8.0m"` and ordered comparisons (`<`, `>=`) are already tolerant, so they
   stay.
5. Never add a `noqa`, a skip or an exemption to get past the scan. To allow a
   new real-clock use, add a function to `tests/clock.py`.

## Changes

### `tests/clock.py` (new, developer)

```python
"""The one place tests read the real clock (s129, ADR-0066).

e2e tests that talk to a real process use these; unit tests use the fake clock.
`about` compares durations with a tolerance; `page_clock` freezes the page's clock.
"""

DURATION_TOLERANCE_S = 0.01

def real_now() -> float:
    """Wall-clock seconds, for files a real process compares with its own clock."""

def real_monotonic() -> float:
    """Monotonic seconds, for a real heartbeat's `mono` field."""

class Deadline:
    """A real-time limit for an e2e wait, on the monotonic clock."""
    def __init__(self, seconds: float) -> None: ...   # end = monotonic + seconds
    def left(self) -> float: ...     # seconds until the end, never below 0.0
    def passed(self) -> bool: ...    # left() == 0.0

def about(seconds: float) -> object:
    """Matches a duration within DURATION_TOLERANCE_S: `assert x == about(480)`."""
    # pytest.approx(seconds, abs=DURATION_TOLERANCE_S)

def page_clock(now: float) -> str:
    """JavaScript that freezes the page's `Date.now` at `now` seconds."""
    # f"Date.now = () => {now * 1000!r};\n"
```

### `tests/e2e/test_s129_clock_scan_e2e.py` (new, unit-tester)

This lives in e2e because it reads the real files under `tests/`, as
`test_seam_e2e.py` does.

```python
TESTS = Path(__file__).resolve().parents[1]          # agile-team/runner/tests
EXEMPT = frozenset({"clock.py", "e2e/test_s129_clock_scan_e2e.py"})  # helper; this file's samples
SCANNED = (".py", ".js", ".mjs")
REAL_CLOCK_READS = (
    re.compile(r"\bDate\.now\(\)"),
    re.compile(r"\bperformance\.now\(\)"),
    re.compile(r"\bnew Date\(\)"),
    re.compile(r"\btime\.(time|monotonic|perf_counter)(_ns)?\("),
    re.compile(r"\bdatetime\.(now|utcnow|today)\("),
    re.compile(r"\bdate\.today\("),
    re.compile(r"\bfrom time import\b[^\n]*\b(time|monotonic|perf_counter)\b"),
)
DURATION_NAMES = frozenset({
    "seconds", "slept", "slept_s", "awake", "age", "beat_age",
    "quiet_for", "elapsed", "waiting", "duration",
})
TOLERANT_CALLS = frozenset({"about", "approx"})

def clock_reads(text: str) -> list[str]:
    """`<line>: <match>` for each real-clock read in `text`."""

def scanned_files() -> list[Path]:
    """Every file under TESTS with a SCANNED suffix, minus EXEMPT, sorted."""

def leaf(node: ast.expr) -> str | None:
    """The name a value goes by: `x.attr` → attr, `x["key"]` → key, `name` → name."""

def tolerant(node: ast.expr) -> bool:
    """A call to about/approx (by leaf name of the callee) or the constant None."""

def exact_duration_compares(source: str) -> list[int]:
    """Line numbers of `==`/`!=` compares on a duration inside an `assert`."""
```

What `exact_duration_compares` checks. It walks every `ast.Assert`'s `test`
subtree and looks at each `ast.Compare` pair `(a, op, b)` whose `op` is `Eq`
or `NotEq`. A pair is a violation when:
- (a) `leaf(a) in DURATION_NAMES and not tolerant(b)`, or the same with `a` and
  `b` swapped;
- (b) both sides are `ast.Tuple`/`ast.List` of the same length, and (a) holds
  for some pair of elements at the same position;
- (c) either side is an `ast.Dict` with a string-constant key in
  `DURATION_NAMES` whose value is not `tolerant` (nested dict values are
  checked the same way).

It reports one line number per violation.

Tests:
- `test_no_test_reads_the_real_clock`: collects
  `f"{rel}:{hit}"` over `scanned_files()` and asserts the list is `[]`, with
  the list in the failure message (AC2).
- `test_the_clock_helper_is_the_one_reader`: `clock_reads` of `tests/clock.py`
  is not empty, so the scan isn't vacuous, and `EXEMPT` is exactly the two
  paths above (AC2).
- `test_clock_reads_catches_each_form` (parametrized): `Date.now()`,
  `performance.now()`, `new Date()`, `time.time()`, `time.monotonic()`,
  `time.monotonic_ns()`, `time.perf_counter()`, `datetime.now(tz)`,
  `datetime.utcnow()`, `date.today()`, `from time import monotonic` each give
  one hit (AC2).
- `test_clock_reads_passes_other_time_use` (parametrized): `time.sleep(1)`,
  `time.strftime("%H", time.gmtime(0))`, `new Date(0)`, `Date.now = () => 1;`,
  `import time`, `from time import sleep` give no hit (AC2).
- `test_no_test_compares_a_duration_exactly`: `exact_duration_compares` over
  every `.py` under `TESTS` (no exemption) is empty; the message names
  `file:line` (AC3).
- `test_exact_compares_are_caught` (parametrized, each one violation):
  `assert row["seconds"] == 3.0`, `assert 480 == out["awake"]`,
  `assert p.heartbeat()["slept"] == 9 * BEAT`, `assert v.beat_age != 12`,
  `assert (b["steps"], b["seconds"]) == (3, 180)`,
  `assert out["s"] == {"tokens": 2, "seconds": 0}`, `assert ok and x.slept_s == 5` (AC3).
- `test_tolerant_or_other_compares_pass` (parametrized, none):
  `assert row["seconds"] == about(3.0)`,
  `assert x.awake == pytest.approx(480, abs=1)`, `assert span.seconds is None`,
  `assert row["seconds"] == None`, `assert len(fake.slept) == 3`,
  `assert row["status"] == "ok"`, `assert row["seconds"] < 25`,
  `ok = row["seconds"] == 3` (not inside an assert),
  `assert out["s"] == {"tokens": 2, "seconds": about(0)}` (AC3).

### `tests/e2e/test_s129_clock_e2e.py` (new, unit-tester)

The helpers read the real clock, so their tests are e2e.
- `Deadline(0).passed()` is true and `left()` is `0.0`; `Deadline(60)` has not
  passed and `0 < left() <= 60`.
- `about(480)` equals `480.005` and does not equal `480.02`; `about(0)` equals
  `0.0`.
- `page_clock(100)` contains `100000`.
- Under node (skip without it): `run_page("console.log(JSON.stringify({n: nowS()}))", 100)`
  gives `{"n": 100}`, and with no `now` it gives the fixture's `generated_at`
  (AC1).
- Under node: the clock doesn't move. A driver reads `nowS()`, runs a fixed busy
  loop (`let x = 0; for (let i = 0; i < 5e6; i++) x += i;`), then reads
  `nowS()` again, and the two are equal (AC1).
- This file is **not** exempt from the scan, so no driver here may contain
  the text of a real-clock read. Use `nowS()`, never `Date.now()`.
