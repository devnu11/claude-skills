# s79: E2E tests pass on a CI runner (no git identity, UTC)

Story: `.team/stories/s79.md`. Developer: `developer-tests` (new, see
"Who writes what"). No ADR: no runtime change, no new dependency.

## Root causes

1. **No git identity.** `presentation.lay_out` runs `git init` in the story's
   workspace (`agile_team/presentation.py:_init_workspace`). The test's
   `present_workspace` then runs `cli.main([... "init" ...])`, which commits
   there (`onboard.commit_onboarding`). That repo has no `user.name` or
   `user.email`, so the commit works only when `~/.gitconfig` supplies them.
   The shared `repo` fixture already sets a local identity. The workspace repo
   does not.
2. **Local time string.** `unattended` writes `next_wake` in the machine's
   zone. The test asserts the text `T21:03:00`, which is 21:03 in Chicago only
   when the machine runs in Chicago time. Under UTC the same instant is
   `02:03:00+00:00`.

Runtime behaviour is correct in both cases. Only the tests change.

## Rules

| # | Rule | AC |
|---|------|----|
| G1 | **Every REAL-world test runs git the way a CI runner does.** An autouse fixture (`isolated_git`, `tests/conftest.py`) sets `GIT_ISOLATION` for tests in the REAL world (`tests/e2e/` and `os_guard.LEGACY`, the same world as s71 and s72). `GIT_ISOLATION` means: no global config (`GIT_CONFIG_GLOBAL=os.devnull`), no system config (`GIT_CONFIG_NOSYSTEM=1`) and `user.useConfigOnly=true` through `GIT_CONFIG_COUNT/KEY_0/VALUE_0`, so git never guesses an identity from the host name. The fixture also deletes the ambient identity variables (`AMBIENT_IDENTITY`: `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `EMAIL`). In the FAKE world it does nothing. | 1, 3 |
| G2 | **A repo a test commits in carries its own identity.** One helper, `set_git_identity(repo)`, writes `REPO_GIT_CONFIG` (`user.email=t@example.com`, `user.name=Test`, `commit.gpgsign=false`) into the repo's local config. `_real_repo` uses it (replacing its three `git config` lines), and so does every test that creates or receives a fresh repo and commits in it. That includes the presentation workspace (`present_workspace` calls it right after `lay_out`). | 1 |
| G3 | **The guard is the fixture.** With G1 in place, a commit in a repo without a local identity fails on every machine with git's `no email was given and auto-detection is disabled` (or `no name was given …`), as it fails on CI. A guard test checks this, so the gap cannot come back unseen. Never fix a red test by restoring global config, setting `GIT_AUTHOR_*` in `os.environ`, or adding identity to `GIT_ISOLATION`. Apply G2 to that test's repo. | 3, 4 |
| G4 | **G1 does not change `HOME`.** `uv` keeps its cache and Python installs under `HOME`, so a scratch `HOME` would refetch them in every e2e test that runs `uv`. `GIT_CONFIG_GLOBAL` already stops git reading `~/.gitconfig`. | 1 |
| Z1 | **Compare instants, not local strings.** `test_halt_line_reset_wins_over_po_text` parses `next_wake` with `datetime.fromisoformat`, asserts it is zone-aware, converts it to `ZoneInfo("America/Chicago")` and asserts the time of day is `21:03:00`. The old assertion checked the same fact, but only on a machine in Chicago time. | 2 |
| Z2 | **The test proves zone independence itself.** Parametrize it over the machine zone with static labels `["UTC", "Asia/Kolkata"]` (s70: ids never hold live values). Kolkata adds a half-hour offset and a date on the other side of UTC. The test sets `TZ` with `monkeypatch.setenv("TZ", zone)` before it starts `unattended`, and the child process inherits it. Do not call `time.tzset()` in the pytest process. | 2 |
| Q1 | No test is weakened, skipped or deleted. Z1 is the same fact, now checked in every zone. Coverage of `agile_team` is unchanged, since no source changes. ruff check and ruff format stay clean. | 4 |

## Changes per module

### `agile-team/runner/tests/conftest.py` (unit-tester)

Add these after `git(...)`. `os` is already imported.

```python
# s79 G1: what a CI runner's git sees. No global/system config, no guessed identity.
GIT_ISOLATION: dict[str, str] = {
    "GIT_CONFIG_GLOBAL": os.devnull,
    "GIT_CONFIG_NOSYSTEM": "1",
    "GIT_CONFIG_COUNT": "1",
    "GIT_CONFIG_KEY_0": "user.useConfigOnly",
    "GIT_CONFIG_VALUE_0": "true",
}
# s79 G1: identity a developer's shell may export; it would hide a repo with none.
AMBIENT_IDENTITY: tuple[str, ...] = (
    "GIT_AUTHOR_NAME", "GIT_AUTHOR_EMAIL", "GIT_COMMITTER_NAME", "GIT_COMMITTER_EMAIL", "EMAIL",
)
# s79 G2: the local config every test repo that commits carries.
REPO_GIT_CONFIG: dict[str, str] = {
    "user.email": "t@example.com",
    "user.name": "Test",
    "commit.gpgsign": "false",
}


def set_git_identity(repo: Path) -> None:
    """Give ``repo`` its own commit identity, so no test relies on ``~/.gitconfig`` (s79 G2)."""
    for key, value in REPO_GIT_CONFIG.items():
        git(repo, "config", key, value)


def _isolate_git(monkeypatch: pytest.MonkeyPatch) -> None:
    for name in AMBIENT_IDENTITY:
        monkeypatch.delenv(name, raising=False)
    for name, value in GIT_ISOLATION.items():
        monkeypatch.setenv(name, value)


@pytest.fixture(autouse=True)
def isolated_git(world: os_guard.World, monkeypatch: pytest.MonkeyPatch) -> None:
    """REAL-world tests run git as a CI runner does: no global config, no guessed identity."""
    isolations: dict[os_guard.World, Callable[[], None]] = {
        os_guard.World.FAKE: lambda: None,
        os_guard.World.REAL: lambda: _isolate_git(monkeypatch),
    }
    isolations[world]()
```

`_real_repo`: replace the three `git(path, "config", …)` lines with
`set_git_identity(path)`. Nothing else changes. Autouse fixtures run before
the `repo` fixture, so `_real_repo` already runs isolated.

`GIT_CONFIG_COUNT` needs git 2.31 or later (CI and current macOS have it).
