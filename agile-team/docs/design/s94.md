# s94 (A14b): every AC names its acceptance environment

Story: `.team/stories/s94.md`. Plan: `.team/run/liaison/plans/acceptance-environments.md`.
Depends on s93, which renamed "delivery" to "acceptance environment" (`StoryState.environment`,
`Config.environment(name)`, `Environment`, `sandbox.ENVIRONMENT_KINDS`).

Before this story a story has one environment in state (`StoryState.environment`, set once by
`open_story`). After it, the **story file is the only record**: each AC in the frontmatter
names its environment, and the runner reads the file whenever it needs the environments. No
environment is kept in state, so fixing one is an edit to the file.

A14c (one proxy step per environment) is **not** in this story. Until it ships, the e2e gate
and acceptance use the story's **first** environment in config order (rule SF9).

## Rules

- **SF1. The format.** A story file is `.team/stories/<id>.md` with YAML frontmatter:

  ```yaml
  ---
  id: s120
  title: "Export the board as CSV"
  depends_on: [s83]          # optional, unchanged (s86)
  suite_runs: 3              # optional, unchanged (s107)
  acceptance:
    - id: AC1
      text: "agile-team export --csv prints one row per story."
      environment: cli
    - id: AC2
      text: "The Backlog tab has an Export button that downloads the same CSV."
      environment: dashboard
  ---
  ```

  Other top-level keys and other keys inside an AC are ignored. The body after the
  frontmatter is free text.

- **SF2. The checks, in order.** Reading a file gives either a spec or a list of problems:
  1. the file exists and is readable (`NO_FILE`);
  2. it starts with frontmatter (`NO_FRONTMATTER`);
  3. the frontmatter parses as YAML and is a mapping (`BAD_YAML`);
  4. `id` equals the file's story id (`WRONG_ID`);
  5. `title` is a non-empty string (`NO_TITLE`);
  6. `acceptance` is a non-empty list (`NO_CRITERIA`);
  7. then for each item, in file order: it is a mapping (`NOT_A_MAPPING`); its `id` is a
     non-empty string (`NO_ID`); its `id` is not used by an earlier item (`DUPLICATE_ID`); its
     `text` is a non-empty string after strip (`NO_TEXT`); its `environment` is a non-empty
     string (`NO_ENVIRONMENT`) that names a configured `[[environment]]`
     (`UNKNOWN_ENVIRONMENT`, or `NONE_CONFIGURED` when the config lists none).

  Checks 1–3 stop the read (nothing else can be checked). Checks 4–6 are story-level: all of
  them are reported, and a failed 6 stops before the items. Item checks report every problem of
  every item (an item with no usable id reports only `NOT_A_MAPPING` or `NO_ID`). One read thus
  tells the PO everything to fix.

- **SF3. The refusal names the file, the AC and the problem.** One line per problem, joined by
  `"\n"`, in the order of SF2. Each line is `{file}: {where}{problem}` where `{file}` is the path
  relative to the repo (`.team/stories/s120.md`), `{where}` is `AC {id}: ` for an item with a
  usable id, `item {n}: ` (1-based) for an item without one, and empty for story-level problems.
  The texts are the `PROBLEMS` table below, exactly.

- **SF4. `open_story` reads the file.** `open_story` refuses with SF3's text (prefixed by
  nothing else) when the read has problems. Order of refusals: duplicate id, then the story
  file, then `depends_on` (s86). The `environment` argument is removed from the tool and its
  schema; the PO writes the file first.

- **SF5. The read before acceptance.** Before a customer-proxy step on a story, the runner
  reads the story file again (after `settle_po`, before the s26 unpresented check). A file
  with problems **holds** the story (SF7). A clean file is used as it is now, so an edit made
  since `open_story` takes effect.

- **SF6. No environment in state.** `StoryState.environment` is removed. Loading a
  `state.json` drops the story keys `environment` and `delivery` (the s93 alias) instead of
  renaming them. A story's environments are the distinct `environment` values of its ACs, in
  the order of `config.environments` (not file order).

- **SF7. A bad file at acceptance is a hold, not a fault.** The pre-acceptance read returns
  `Outcome(Verdict.HOLD, STORY_FILE_HOLD.format(refusal=...))` through the same path as the
  s26 unpresented return (`Runtime._returned`), so the step is not run, nothing is billed, and
  the PO gets the existing `gate_hold` hand-over ("… gate is on hold: {reason}; fix it, then
  continue_story"). `continue_story` releases it; the next proxy request reads the file again.
  No new tool and no state edit. The hold is a setback like any other gate hold (the repeat
  rule may escalate the same unfixed hold).

- **SF8. The view reads the file too.** The snapshot's story `environment` key (a string, shape
  unchanged) is the story's environments joined by `", "`, or `""` when the file has problems.

- **SF9. One environment until A14c.** Wherever the runner needs a single environment for a
  story (the e2e recipe, the liveness trial, the seeds, the proxy's sandbox) it uses
  `story_spec.first_environment`: the first of the story's environments in config order, or
  `None` when the file has problems. `None` behaves as today's "no environment" (guide-only
  recipe, liveness passes, no seed dir); the SF5 read holds the story before the proxy runs.
  A storyless proxy step keeps today's fallback, `config.environment(None)` (the first
  configured).

- **SF10. Migration (AC4).** Every story file in `.team/stories/` that is not done gets the
  SF1 format with an `environment` on every AC:
  - a prose file: move its title and ACs into frontmatter; the AC text loses its `[env]` tag
    and `**ACn.**` prefix (the tag becomes `environment`); the body keeps the user story and
    notes;
  - a frontmatter file: add `environment` to each item;
  - drop any top-level `delivery:` or `environment:` key and any `**Delivery:**` body line;
  - choose the environment by where the customer tries the AC: `cli` (the runner's commands
    and behaviour), `dashboard` (anything seen or done on the dashboard page), `unattended`
    (the unattended skill), `review` (prompt, role-file, docs or design changes: nothing to
    run). A story whose ACs were tagged by the liaison keeps those tags.

  The PO converts; the Architect reviews the choices at design review. Done stories are left
  as they are.

- **SF11. The migration test.** A test loads every `s*.md` in the repo's `.team/stories/`
  except the ids in a frozen set `DONE_AT_MIGRATION` (the stories whose status is `done` in
  `.team/run/state.json` when the migration lands, written into the test as literals) and
  expects no problems, against the environments of the repo's own `.agile-team.toml`. A story
  added later is checked by default.

## The module: `agile_team/story_spec.py` (new, pure except `read`)

```python
"""A story file's frontmatter: its ACs and their acceptance environments (s94 SF1-SF9)."""

from enum import StrEnum

class Problem(StrEnum):
    NO_FILE = "no_file"; NO_FRONTMATTER = "no_frontmatter"; BAD_YAML = "bad_yaml"
    WRONG_ID = "wrong_id"; NO_TITLE = "no_title"; NO_CRITERIA = "no_criteria"
    NOT_A_MAPPING = "not_a_mapping"; NO_ID = "no_id"; DUPLICATE_ID = "duplicate_id"
    NO_TEXT = "no_text"; NO_ENVIRONMENT = "no_environment"
    UNKNOWN_ENVIRONMENT = "unknown_environment"; NONE_CONFIGURED = "none_configured"

PROBLEMS: dict[Problem, str] = {
    Problem.NO_FILE: "no story file; write it before open_story",
    Problem.NO_FRONTMATTER: "no YAML frontmatter; start the file with --- and the keys id, title and acceptance",
    Problem.BAD_YAML: "frontmatter does not parse: {error}",
    Problem.WRONG_ID: "id is {found!r}, not {story!r}",
    Problem.NO_TITLE: "title must be a non-empty string",
    Problem.NO_CRITERIA: "acceptance must be a non-empty list of {{id, text, environment}}",
    Problem.NOT_A_MAPPING: "must be a mapping with id, text and environment",
    Problem.NO_ID: "id is missing or empty",
    Problem.DUPLICATE_ID: "id is used by an earlier AC",
    Problem.NO_TEXT: "text is missing or empty",
    Problem.NO_ENVIRONMENT: "environment is missing; use one of: {names}",
    Problem.UNKNOWN_ENVIRONMENT: "environment {name!r} is not a configured [[environment]]; use one of: {names}",
    Problem.NONE_CONFIGURED: "environment {name!r} cannot be checked: .agile-team.toml configures no [[environment]]; ask the human to add one",
}
LINE = "{file}: {where}{problem}"
STORY_FILE_HOLD = "the story file must be fixed before acceptance:\n{refusal}\nEdit the file; no state change is needed"

@dataclass(frozen=True)
class Criterion:      # one AC
    id: str; text: str; environment: str

@dataclass(frozen=True)
class Source:         # what parse reads; text None = the file is missing or unreadable
    story: str; file: str; text: str | None

@dataclass(frozen=True)
class Spec:
    story: str; title: str; criteria: tuple[Criterion, ...]
    def environments(self, order: Sequence[str]) -> list[str]: ...   # SF6: distinct, in `order`

@dataclass(frozen=True)
class Read:
    spec: Spec | None = None
    problems: tuple[str, ...] = ()        # finished SF3 lines
    def refusal(self) -> str | None: ...  # "\n".join(problems) or None

def parse(source: Source, names: Sequence[str]) -> Read: ...        # pure; SF2/SF3; names = configured environment names
def file_of(config: Config, story: str) -> str: ...                  # ".team/stories/<id>.md", posix, relative to config.repo
def read(config: Config, story: str) -> Read: ...                    # the only I/O: system.read_text, OSError -> text None
def environment_names(config: Config, story: str) -> list[str]: ...  # [] when the read has problems
def first_environment(config: Config, story: str) -> Environment | None: ...  # SF9
```

- Imports: `from . import system`, `from .config import Config, Environment`,
  `from .roles import RoleError, split_frontmatter`, `yaml` (for `yaml.YAMLError`). No new
  dependency.
- `parse` keeps to the charter's size: split it into small helpers, e.g. `_meta(source)`
  (checks 1–3), `_story_problems(meta, source)` (4–6), `_item_problems(...)` per item, and a
  check table `ITEM_CHECKS` of `(Item, Names) -> Problem | None` functions for text and
  environment, so adding a check is a row. Choosing `UNKNOWN_ENVIRONMENT` versus
  `NONE_CONFIGURED` is a lookup on whether `names` is empty, not an `if` chain per caller.
- `{names}` is the configured names joined by `", "`, in config order.
- `split_frontmatter` returns `None` meta for a file without frontmatter (→ `NO_FRONTMATTER`),
  raises `RoleError` for a non-mapping and `yaml.YAMLError` for bad YAML (both → `BAD_YAML`,
  `{error}` = `str(exc)`).

### Tests that change because a rule changed

- Tests that build `StoryState(..., environment=...)` or read `story.environment`
  (`test_s64_environment.py`, `test_s93_environment_alias.py`, `test_presentation.py`,
  `test_service_presentation.py`, `test_seeds.py`, `test_dispatch.py`, `test_po_tools.py`,
  `test_snapshot.py`, e2e `test_environment_name_e2e.py`, `test_service_presentation_e2e.py`,
  `conftest.py`) now write a story file instead. A shared helper in `conftest.py`, e.g.
  `write_story(config, story, environments)` writing one AC per environment, keeps them short.
  The rule that makes the old assertions wrong: AC2 ("`StoryState.delivery` goes") and SF6.
- s64's V1–V5 tests of `environment_refusal` are replaced by SF2's `UNKNOWN_ENVIRONMENT` and
  `NONE_CONFIGURED` tests; "empty means the first environment" no longer holds for a story
  (SF2: missing is refused).
- s93's E5 test for story keys ("a new key already present wins") becomes: both
  `environment` and `delivery` are dropped on load (SF6).

## Known limits

- Until A14c, a story with ACs in two environments is presented and tried in its first one
  (config order) only (SF9).
- A repo with no `[[environment]]` cannot open a story (`NONE_CONFIGURED`): every AC must
  name one. Today such a repo already fails at acceptance.
- This repo's `.agile-team.toml` has no `review` environment yet (A14a AC5's edit is the
  human's, at a stop). The migration uses `review`, so the SF11 test fails until it is added.
