## Where the yellow comes from

After a graceful `agile-team stop`, health is `idle` (R15) and no step is
open, so `renderStatusRow` does not show the smart pill at all. The pill
the human sees is the **run-status pill**,
`pill(view.run.status, STATUS_TONE[view.run.status])`, and
`STATUS_TONE.stopped` is `"warning"`. That is the yellow one. `pillText`
and `smartPill` already give `● stopped` / `h-idle` (pinned by
`test_graceful_stop_is_idle_and_silent`). Only the run-status pill is wrong.

## Rules

- **N1 Fallback text.** With no live step (`liveStep(view) == null`), a
  `null` heartbeat and an open step (`activeStep(view.events)`),
  `pillText` returns exactly `` `▶ ${who(act)} · ${fmt.ago(act.at, now)}` ``:
  one space after `▶`. Example: `▶ developer-cli on s29 · 2 min`. That is
  the only change to `pillText`.
- **S1 The run-status pill is neutral for `stopped`.** The run-status pill
  names the status. Its tone is static per status (`STATUS_TONE`). The
  status `stopped` alone cannot tell a graceful stop from `stop --now`, so
  its tone is `""` (plain). Health colour belongs to the smart pill (P2).
  Set `STATUS_TONE.stopped` to `""`. No other entry changes. `stopped`
  occurs nowhere else that reads `STATUS_TONE`: timeline step-end statuses
  are handoff statuses or `interrupted`, and verdicts are
  pass/bounce/hold/return.
- **S2 Forced stops stay red, on the smart pill.** A halt that is not
  graceful (`stop --now` → `stopped` with `halt_kind: "sigterm"`, a limit or
  the budget → `blocked`, a crash → `failed`, a dead runner →
  `interrupted` or a dead heartbeat pid) has health level `red`
  (`health.RULES`, unchanged). So the status row shows the smart pill with
  class `h-red` and the text `● <health.reason>`. `blocked`, `failed`,
  `interrupted` and `checkout-changed` keep their run-status tones.
- **S3 The status row is built by a pure function.** `renderStatusRow`'s
  body, minus the DOM write, moves unchanged into `statusPills(view, now)`.
  That function returns the row's pills as HTML strings, left to right, so
  a node test can read them. `renderStatusRow` writes their join and
  renders the details, as it does today.

## Changes: `agile_team/dashboard/index.html`

1. `STATUS_TONE` (const table near the top of the script): `stopped: "warning"` → `stopped: ""`.
2. `pillText(view, now)`: in the `▶` branch, `` `▶${who(act)} · …` `` → `` `▶ ${who(act)} · …` ``.
3. New function, placed just above `renderStatusRow`. It is the current
   body moved as is:

   ```js
   /** The status row's pills as HTML strings, left to right (P1, S3). */
   function statusPills(view, now) {
     const parts = [connectionPill(), pill(view.run.status, STATUS_TONE[view.run.status] ?? "")];
     if (activeStep(view.events) || liveStep(view) || healthLevel(view) !== "idle") parts.push(smartPill(view, now));
     const open = openQuestions(view).length;
     if (open) parts.push(pill(`? ${open} question${open > 1 ? "s" : ""} waiting on you`, "warning"));
     for (const why of view.run.manager_due ?? []) parts.push(pill(`⚑ manager due: ${why}`, "serious"));
     if (MOCK) parts.push(mockControls());
     return parts;
   }

   /** Draws the status row and the live details under it. */
   function renderStatusRow(view) {
     $("#status-row").innerHTML = statusPills(view, clockNow(view)).join("");
     renderLiveDetails(view);
   }
   ```

Nothing else changes: CSS, the smart pill, `applyAlert`, the snapshot and
the Python side all stay as they are.
