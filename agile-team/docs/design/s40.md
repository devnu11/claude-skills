## The problem

There is no priority anywhere. `Router._story_work` takes the first movable
story in `state.stories` insertion order (creation order), and the board
shows each column in that same order. The order the human and the PO agree
lives in prose, so s29 ran before s30, and s9 (nothing in flight) jumped
ahead of s29 (in flight). A held story sat at the top of its column with no
mark, so the order shown made no sense.

## Vocabulary

- **order**: `state.order`, the PO's explicit list of story ids.
- **ranking**: every story sorted by the one rule, `Priority.key` (P2).
- **queue**: the ids of the unfinished stories in ranking order. A story's
  **position** is its 1-based index in the queue. The board shows it as
  `#n`; `move_story` takes it.
- **in progress**: past the first pipeline step, or a step has already run
  on it (`previous` is set).
- **wait**: why an unfinished story is not moving, and what it waits on (W1).

## Rules

| # | Rule | AC |
|---|---|---|
| P1 | `RunState.order: list[str]` (default `[]`) is saved in `state.json`. A legacy file without it loads with `[]`. Ids in it that are done or unknown are harmless: the ranking ignores unknown ids and puts done stories last. | AC1 |
| P2 | **The one ranking rule** is `Priority.key(story)` = `(done, listed, not in_progress, natural(id))`. `done`: done stories sort last. `listed`: the index in `order`, or `len(order)` when unlisted, so unlisted stories sort after listed ones. `in_progress`: see Vocabulary. `natural(id)`: digit runs compare as numbers, so `s9 < s10`. An explicit position always beats in-progress. In-progress only breaks ties between unlisted stories. | AC1, AC3, AC8 |
| P3 | **Router.** `_story_work` takes the first story in `Priority.ranked(...)` that is `_movable`. `_repeat_work` takes the first escalated story in the same ranking. Creation order plays no part. | AC3 |
| P4 | **A held story keeps its place.** Holds, needs-manager, blocked and open questions never change `order`. `_movable` skips such a story, and it moves again from the same position once it is released. | AC6 |
| P5 | **`prioritise(stories, reason)`** sets the queue to the listed ids, in the order given, followed by every other unfinished story in its current queue order. Duplicates are collapsed (first wins). It is refused (nothing changes) for an empty list, unknown ids or done ids. | AC2 |
| P6 | **`move_story(story, position, reason)`** takes the story out of the queue and puts it back at `position` (1 = next). It is refused for an unknown or done story, or a position that is not a whole number from 1 to the queue's length. | AC2 |

| P8 | **`start_sprint(goal, stories)`** treats its list as an order. After `begin_sprint`, it applies P5 with the sprint's ids (done ids are skipped by `with_first`), so the sprint's stories come first in the order given. Its refusals are unchanged. | AC2 |

| P10 | **`story_status`** returns `stories` in ranking order (a JSON object; insertion order is kept) and adds `"order": [queue]`. | AC2 |

| W2 | The `WAITS` rows are data. s39 (parking) adds a `parked branch` row; it is not built here. | AC6 |

### The `WAITS` table (exact; order matters)

| Row | Reason (`WaitReason` value) | Applies when | Detail |
|---|---|---|---|
| 1 | `needs the human` (`HUMAN`) | `status is BLOCKED` | `_summary` |
| 2 | `manager` (`MANAGER`) | `status is NEEDS_MANAGER and story.repeated` | first line of `repeated` |
| 3 | `round cap` (`ROUND_CAP`) | `status is NEEDS_MANAGER` | `"round {rounds}: the manager must rule"` |
| 4 | `questions` (`QUESTIONS`) | `"questions"` is one of `hold.split(", ")` | `_summary` |
| 5 | `held` (`HELD`) | `hold` is set | `hold`, then `" · " + _summary` when the summary is not empty |
| 6 | `needs the human` (`HUMAN`) | `asking` is not empty | `""` |

`_summary(story)` = `f"{previous.role}: {previous.summary}"` when `previous`
and its summary exist, else `""`.

Worked example (the live s27 case): hold `"questions"`, open question m38
naming s27, previous step `architect` with summary `"Asked which …"` gives
`Wait("questions", ["m38: <question text>", "architect: Asked which …"])`.
The card shows `⏸ questions` and `waits on: m38: … · architect: …`, and s27
keeps its `#` position.

### Worked ranking example

`order = ["s30", "s26"]`, first step `design`. Stories: s9 (design, no
previous), s26 (design), s29 (tests, in progress), s30 (design), s1 (done).
The queue is `s30, s26, s29, s9`, and s1 ranks last with no position. If
s30 is held, the router runs s26. s30 stays `#1`.

## Changes by module

### `agile_team/priority.py` (new; pure, no I/O)

```python
"""Story priority (s40): the PO's explicit order and the one rule that ranks stories."""

from .gates import StoryState, StoryStatus

NO_STORIES = "no stories listed; pass the story ids in the order to work on them"
UNKNOWN = "unknown stories: {ids}; open them with open_story first"
DONE = "done stories have no place in the order: {ids}"
BAD_POSITION = "position must be a whole number from 1 to {count}"

class Change(StrEnum):            # SET = "set", MOVE = "move", SPRINT = "sprint"

@dataclass(frozen=True)
class Placement:                  # story: str; position: Any (validated by move_refusal)

@dataclass(frozen=True)
class Reorder:                    # change: Change; order: list[str]; story: str | None = None; reason: str = ""

def natural(sid: str) -> tuple[Any, ...]:
    """Sort key for an id: digit runs compare as numbers (s9 < s10)."""
    # tuple(int(p) if p.isdigit() else p for p in re.split(r"(\d+)", sid))

def order_refusal(ids: list[str], stories: dict[str, StoryState]) -> str | None:
    """NO_STORIES, UNKNOWN (ids joined ", ", in the order given) or DONE, first match; else None."""

def moves(before: list[str], after: list[str]) -> list[dict[str, Any]]:
    """{"story", "from", "to"} (1-based) for each id in ``after`` whose index changed."""

@dataclass(frozen=True)
class Priority:
    order: list[str]
    first: str                    # the pipeline's first step

    def in_progress(self, story: StoryState) -> bool: ...   # step != first or previous is not None
    def key(self, story: StoryState) -> tuple[Any, ...]: ... # P2, exactly
    def ranked(self, stories: Iterable[StoryState]) -> list[StoryState]: ...
    def queue(self, stories: Iterable[StoryState]) -> list[str]: ...   # unfinished ids, ranked
    def with_first(self, ids: list[str], stories: Iterable[StoryState]) -> list[str]: ...
        # [i for i in ids if i in queue] + the rest of the queue, in queue order
    def with_move(self, placement: Placement, stories: Iterable[StoryState]) -> list[str]: ...
    def move_refusal(self, placement: Placement, stories: dict[str, StoryState]) -> str | None: ...
        # order_refusal([placement.story], stories) or BAD_POSITION when position is not
        # an int (type(p) is int, so a bool is refused) in 1..len(queue)
```

## Test checklist (for the Unit Tester)

Ranking (`priority.py`):
- [ ] `natural`: `s9 < s10 < s100`; `"a" < "b"`.
- [ ] Legacy: `order == []`. An in-progress story beats an older story with nothing in flight (s29 at tests beats s9 at design). Ties are broken by natural id. Done stories rank last.
- [ ] Explicit beats in-progress: a listed story at `design` beats an unlisted one at `tests`.
- [ ] Unlisted stories come after listed ones. Unknown ids in `order` are ignored.
- [ ] `queue` excludes done stories. Positions are 1-based.
- [ ] `with_first` puts the listed ids first, then the rest in queue order. Done ids are dropped.
- [ ] `with_move` to 1, to the end and to the middle.
- [ ] `order_refusal`: empty list, unknown (exact text), done (exact text). `move_refusal`: 0, len+1, `"2"`, `True` and `None` are refused (exact text); unknown and done stories are refused.
- [ ] `moves` lists only the changed stories, 1-based.

State:
- [ ] A `state.json` without `order` loads with `[]`. `order` round-trips.

Router:
- [ ] With an order, the earliest movable story in the order runs, not the first created.
- [ ] A held story is skipped, and the next in the order runs. Once it is released (`continue_story`), it runs before later stories and its position never changed.
- [ ] A story blocked by an open question, or at needs-manager, is skipped the same way.
- [ ] `_repeat_work` picks by the ranking.
- [ ] Existing tests that expect creation order now meet a changed rule (P2, P3). Where an earlier story is not started and a later one is in progress, the later one now runs first. Update such tests to the new rule; do not weaken them. Likewise, a test that expects `start_sprint` to emit only `sprint-start` now also sees a `priority` event.

- [ ] `move_story` moves the story, and the event has `story` = the id and the right `from`/`to`. Refusals change nothing.
- [ ] `start_sprint(["s3","s1"])` puts s3 at #1 and s1 at #2. One `priority` event (`change: "sprint"`) follows `sprint-start`. Its result has `order`.
- [ ] `story_status` returns the stories in ranking order, and the `order` key equals the queue.
- [ ] `SCHEMAS` has `prioritise` and `move_story`, and `tool_names()` includes them.
