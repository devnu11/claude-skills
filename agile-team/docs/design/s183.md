# s183: an END boundary whose sprint is already on the target closes as shipped

Story: `.team/stories/s183.md`. ADR: ADR-0075 (amended by s183).
Requirements: REQ-222 (AC1), REQ-223 (AC2), REQ-224 (AC3).
Developer: `developer-api` (runner internals, no UI).

## The bug in one line

`push-replayed` on the END edge compares HEAD only with the entry's `pushed`
sha. It never asks whether the target already holds HEAD. So it pushes
`-r<k>` and asks GitHub for a PR that GitHub refuses ("No commits between"),
and a rerun then runs `gh pr ready` on a PR that is already merged.

## Rules

1. **Shipped check first.** On the END edge, `push-replayed` fetches the
   remote first, then checks whether the target (`<remote>/<branch>`)
   contains HEAD. It does this before the "unchanged" check and before any
   push. When the target contains HEAD, the sprint is **shipped**:
   - nothing is pushed, no PR is created, and no PR is edited or marked ready;
   - the sprint's PR, if the entry has one and its mode is not `closed`, is
     closed with `SHIPPED_PR_NOTE`. `GhPrs.close` already treats a PR GitHub
     shows as merged as done, with no error and no comment (REQ-174), so a
     merged PR is never touched. When `prs.missing()` gives a reason, no gh
     call is made;
   - the entry's `mode` becomes `PrMode.CLOSED`, with or without a PR;
   - the boundary finishes (`_finish`): `upstream.closed = N`,
     `upstream.report = SHIPPED_REPORT`, `boundary = None`. The `done` event
     carries `note=SHIPPED_REPORT`, `sha=<HEAD>` and `target=<remote>/<branch>`,
     and **no `ci` key**. A `ci: green` key would fire `ci_green` ("ready to
     merge … Tell the human"), which is wrong for a sprint that is already
     merged. The PO's sprint-end hand-over reads `Review: <SHIPPED_REPORT>`
     through the existing `router._sprint_end`, with no change there.
2. **"Contains" means ancestry, not patches.** The target contains HEAD when
   their merge base is HEAD itself. A target that holds only some of the
   sprint, or holds it by patch but not by ancestry, is not shipped, and the
   stage runs as today (AC3). After a replay, a fully patch-merged sprint has
   HEAD equal to the target, so it still counts as contained.
3. **The held-error case needs nothing extra (AC2).** `continue_boundary`
   already clears the `error` hold and reruns `push-replayed`. Rule 1 runs
   first on the rerun, so the entry left half-updated by the failed create
   (`branch = …-r1`, `pushed = HEAD`, `pr` = the old merged PR) closes as
   shipped. The `-r<k>` branch already on the remote is kept, like every old
   branch. No `state.json` edit is needed. With `boundary = None` and
   `closed = N`, the next `start_sprint` opens its START boundary as usual,
   and REQ-170 drops the entry once main holds it.
4. **The gate on green CI still holds (REQ-015).** `push-replayed` comes only
   after `replay`, which refuses to run without green CI on the as-built
   push. So the shipped path never closes a sprint whose CI was not green.
5. **A failed fetch holds `error`, as the replay stage's fetch does.** The
   END boundary already skipped at `sync` when no remote is set, so a remote
   always exists here. The fetch takes no checkout lock. It moves only
   remote-tracking refs, never the checkout, and REQ-171 locks the checkout
   only while git moves it. A due boundary also waits for the running steps
   (REQ-156). (Ruled at design review.)
6. The START edge (`_push_start_replay`) does not change.

## Changes per module

### `agile_team/upstream.py`, class `Upstream`

```python
def is_in_target(self, head: str) -> bool:
    """True when the target already contains ``head``: their merge base is ``head`` itself."""
```

- Runs `git merge-base <head> <target>` through `self.git.attempt` and
  returns `code == 0 and out.strip() == head`.
- Pitfall: don't use `is_ancestor` (an exit-code check) here. The unit tests'
  `FakeSystem` answers exit 0 to any command no test scripted. An exit-code
  check would then read every unscripted HEAD as shipped and silently change
  every existing `push-replayed` test. The equality check needs the output
  to name HEAD.

## Test checklist

Unit tests (new file `tests/test_s183_shipped_end.py`, fakes as in
`tests/test_s159_boundary_replay.py`: `cenv`, `FakePrs`, `entry`, `pushes`).
Script `git merge-base <head> origin/main` to print HEAD for "shipped", and
leave it unscripted (or print another sha) for "not shipped".

- [ ] `Upstream.is_in_target` is True when merge-base prints `head`, False
      when it prints another sha, and False on a non-zero exit (AC1, AC3).
- [ ] AC1: END at `push-replayed`, HEAD ≠ `pushed`, the target contains HEAD:
      no push (`pushes(fake) == []`), no `create` and no `edit` on `FakePrs`,
      `boundary is None`, `upstream.closed == 1`, `upstream.report ==
      SHIPPED_REPORT.format(...)`. The `done` event has `note`, `sha == HEAD`
      and `target`, and no `ci` key. The entry's `mode is PrMode.CLOSED`.
- [ ] AC1: the entry's open PR is closed once, with `SHIPPED_PR_NOTE`. An
      entry without a PR makes no `close` call. With `prs.missing()` set,
      there is no gh call and the mode is still `closed`.
- [ ] AC1: the PO's sprint-end hand-over (`router._sprint_end` lines)
      contains `Review: ` plus the shipped report, and no `ci_green` rule fires
      for the `done` event.
- [ ] AC2: a boundary saved as `stage=push-replayed, hold=error` with the
      entry already on `-r1` (`pushed == HEAD`, `pr` = the old PR, mode
      `ready` or `draft`). `continue_boundary` then one step: the boundary
      closes as shipped, no `edit` (no `gh pr ready`), the entry is `closed`,
      and `start_sprint` for N+1 is accepted and opens a START boundary.
- [ ] AC3: the target lacks HEAD. HEAD ≠ `pushed` still pushes `-r1` and
      creates a ready PR, and HEAD == `pushed` still makes the draft ready
      (the existing tests in `test_s159_boundary_replay.py` and
      `test_boundary_runner.py` pass unchanged).
- [ ] A failed fetch at `push-replayed` holds `error`.

By hand (AC1, AC3, `environment: cli`): in a scratch repo with a bare
remote, fast-forward the remote's main to the sprint head before the END
boundary's replay stage, and check that the boundary closes as shipped with
no `-r1` branch on the remote. Fast-forward main to an earlier commit
instead, and check that `-r1` is pushed.
