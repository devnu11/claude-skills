# s101 (A6d): a step row expands into its tool calls

Story: `.team/stories/s101.md`. Plan context: `.team/run/liaison/plans/tool-flow.md`
(sections "A6d", "The names of the tools are data" and "Readability"). This story extends the s100 timeline
(`docs/design/s100.md`, rules TL1–TL20, TR1–TR5) with the s98 `tools` data (`docs/design/s98.md`,
TC1–TC18). No new ADR: the page derives views from raw snapshot data (s96 pattern), and one read-only GET
route serves a file on demand (the s83 `/api/file` pattern). No new dependency.

Developer: **developer-gui**. Most of the work is in `index.html`. The Python part is small and follows the
s98 shapes: open calls in the heartbeat, plus one GET route for a step's misc calls.

## What changes, in one paragraph

You can now click a step bar or a PO-turn bar on the timeline, or the label of its row, and nested rows open
under that row. They are:

- a `model` row: the bar's time not covered by any tool call;
- one or more `tools` lanes, where each tool call is a strip on the same time axis, and parallel calls
  stack into extra lanes;
- a dashed `misc` box at the end.

Under each strip are two lines: the tool's name (`po.run_role`, `Dev: <reason>`), and below it the
80-character detail in `--ink-2`. When the strip is too narrow, both lines move into the tooltip with the
start and duration.

The strip's colour shows how the call ended:

- `ok` is teal;
- `error` and `timeout` are red;
- `unfinished` is hatched;
- `po.run_role` is a neutral "waiting" strip;
- a call still running is `open`, in `--accent`, and grows to "now".

The heartbeat now lists the calls still open, so the dashboard can see them. The misc box is not placed on
the time axis. Clicking it fetches its calls from the new `/api/misc`, which re-gathers them from
`tools.jsonl`, and lists them under the plot.

## Rules

| id | rule |
|---|---|
| N1 | **Expandable bars and keys.** Every `step` bar (TL5, story and sprint groups) and every `po` bar (TL7) has a `key`. A step's key is `step:<role>:<story ?? "-">:<at>`, with `at` as `tlFixed`. A PO turn's key is `po:<event.id>`. Stage bars have no key. The open keys are `ui.tlOpen`, a `Set` shared by all timelines. A PO turn that touches two stories therefore opens in both groups. |
| N2 | **Which data belongs to a bar.** A **step** bar matches a `tools` group, or a heartbeat call, `g` when all of these hold: `g.role === step.role`, `g.story === step.story`, `g.step !== "po-session"` and `step.at <= g.opened_at < (step.ended_at ?? now)`. Steps of one role and story never overlap, so at most one group matches. The meter opens just after `step-start`, so `opened_at >= step.at`. A **PO** bar matches when `g.role === "product-owner"` and `g.opened_at === turn.event.data.opened_at` (the same `Reading.started_at` value). The bar's calls are the group's `calls`, followed by the matching `view.heartbeat?.calls ?? []` (open calls, N11). |
| N3 | **Nested lines (AC1).** An open bar's nest, in order: one `model` line (`ROW_H`). Then one `tools` lane per stacking level (`NEST.LANE_H`). Then one `misc` line (`ROW_H`), only when `misc.count > 0`. With **no** group and no open calls, the nest is one `none` line instead, labelled `no tool calls`, with nothing drawn in the plot. Nest line rows are named `<key>/model`, `<key>/lane-<i>` (i from 0), `<key>/misc` and `<key>/none`. Their labels are `model · <secondsText(model)>`, `tools` for lane 0, `tools <i+1>` for the others, an empty label for misc, and `no tool calls`. Labels are drawn at `x = 4 + NEST.INDENT` and cut to 20 characters (TR4). A row's nests come right after the row, ordered by the bar's `from`. **With nothing open, the lines are exactly `group.rows` at `ROW_H` each, so the s100 layout and its tests do not change.** |
| N4 | **Stacking (AC1).** `callLanes(bars)`: sort by `(from, call.tool_use_id)`. Put each bar in the first lane whose last `to` is ≤ its `from`, or open a new lane. Two calls that overlap are therefore in different lanes. Calls that only touch (one ends exactly when the next starts) share a lane. |
| N5 | **Call bars and states (AC3).** A call bar is `{kind: "call", row: <lane row>, from: call.at, to: call.ended_at ?? now, call, name: call.label, detail: call.detail, ...look, title}`. `look = TOOL_LOOKS[state]`, where `state = TOOL_WAITING.has(call.label) && (call.status === "ok" || call.status === "open") ? "waiting" : call.status`. An unknown status uses `TOOL_LOOKS.ok`. `TOOL_WAITING` mirrors `tool_calls.WAITING`. `unfinished` fills with the hatch pattern (N9), and the others with `var(<fill>)`. An `open` call ends at `now`, so it grows on every snapshot (TL16). |
| N6 | **Model row (AC1).** The pieces are `tlComplement(<the call bars' [from, to]>, {from: bar.from, to: bar.to})`, each drawn as a bar `{kind: "model", row: "<key>/model", ...MODEL_LOOK}` with the tooltip `model · <secondsText(piece)>`. The label's total is `splitOf(ctx, bar)`, or the measure of the pieces when that is null. For a step, `splitOf` is the `model_s` of the `step-end` event with the same `role` and `story` and `at === step.ended_at`. For a PO bar, it is `bar.event.data.model_s`. A PO turn's `po.run_role` is a call bar, so the PO's model row leaves the wait out (AC4). Misc calls (≤ `collapse_under_s` in total) are not subtracted. |
| N7 | **Labels on a strip (AC2).** A lane line is `NEST.LANE_H` = 44 tall. The strip is a rect at `y = top + 4`, `NEST.STRIP_H` = 8 tall, `x1..x2` clamped like `barSvg`. Under it go `tlText("call", name)` with its baseline at `top + 26` and `tlText("detail", …)` with its baseline at `top + 40`, both at `x1 + 3`, both on `--surface` (TR3). Let `w = x2 - x1`. **Line 1** is drawn only when `name.length × CHAR_EM × TL_TEXT.call.px + 6 <= w`. **Line 2** is drawn only when line 1 is, `detail` is not empty, and `n = floor((w - 6) / (CHAR_EM × TL_TEXT.detail.px)) >= NEST.MIN_DETAIL_CHARS`. Line 2 then shows `tlCut(detail, n)`. The tooltip (`<title>` on the call's `<g>`) is always `<name>\n<detail>\nstarted <fmt.time(at)> · <secondsText(d)> · <state>`, with `d = call.seconds ?? max(0, now - at)`. A `waiting` call adds ` · waiting on the step`. |
| N8 | **`secondsText(s)`** is `` `${Number(s.toFixed(2))} s` `` when `s < 60`, and `fmt.span(s)` otherwise. So 0.042 reads `0.04 s`, and 41.2 reads `41.2 s`. |
| N9 | **The misc box (AC5).** For a nest with `misc.count > 0`: the text is `miscText(misc)` = `misc · <n> call(s) · <secondsText(misc.seconds)>` (`1 call`, `3 calls`). A `<g data-misc="<key>" data-tl-misc="<key>" data-misc-ask="<miscAsk(group)>" style="cursor:pointer">` holds a `<title>`, a rect and `tlText("misc", text)`. The rect is at `x = TL.LABEL_W + 4`, `y = slot.top + 3`, with `width = text.length × CHAR_EM × TL_TEXT.misc.px + 2 × NEST.MISC_PAD` and `height = ROW_H − 6`. Its fill is `var(--surface)`, with `stroke="var(--axis)" stroke-dasharray="3 2"`. The text is at `x = LABEL_W + 4 + MISC_PAD`, `y = slot.top + 15`. The box is drawn **outside** the clip group and has **no** `data-from`/`data-to`, so it stays put when the window zooms or pans. Its title is `MISC_TITLE + "\n" + <tool> <n> · …`, in `misc.tools` order. |
| N10 | **Misc calls on demand (AC5).** Clicking `[data-tl-misc]` toggles its key in `ui.miscOpen`. On opening, when `ui.miscCalls[key]` is undefined, `loadMisc(key, ask)` sets it to `MISC_LOADING`, renders, and fetches `api/misc?<ask>`. An `ok` response stores the parsed JSON array. Anything else stores `MISC_FAILED`. Then it renders. `miscListHtml(model)` goes after the plot `<div>` and before the legend, with one `<div data-misc-list="<key>">` for each open misc key that has a nest in the model, in nest order. Each div has a heading (`tlSpan("call", miscText(misc))` + `tlSpan("detail", "gathered from across the step")`), then: `MISC_LOADING` → `tlSpan("note", "loading…")`; `MISC_FAILED` → `tlSpan("note", "could not load the calls")`; `[]` → `tlSpan("note", "no calls found; tools.jsonl has moved on")`; otherwise an `<ol>` with one `<li data-misc-call>` per call holding `tlSpan("call", label)`, then `tlSpan("detail", detail)` and `tlSpan("detail", "<fmt.time(at)> · <secondsText(seconds)> · <status>")`. `miscAsk(group)` = `new URLSearchParams({role, story: story ?? "", step: step ?? "", opened_at: String(opened_at)}).toString()`. |
| N11 | **Open calls in the heartbeat (runner).** The heartbeat gains `calls`, right after `step`. It lists every open call of **every** open meter: the outer meter first (the PO's `po.run_role`), then the inner one (the role's calls). Each row is `tool_calls.open_row(where, call)`: the TC11 keys up to `slept`, then `"status": "open"`. When the pulse has ended, `calls` is `[]`. `HEARTBEAT_VERSION` is unchanged (the key is additive). |
| N12 | **`GET /api/misc` (runner).** The query is `role`, `story`, `step` and `opened_at`, each taken as its first value or `""`. `tool_groups.ask_key` makes the group key: `story` `""` → `None`, `step` `""` → `None`, and `opened_at` → `float`. The result is `None` when `role` is `""`, or when `opened_at` doesn't parse or isn't finite. A `None` key → 404. Otherwise the route returns 200 with `application/json`: `tool_groups.gathered_calls(rows, key, collapse_under_s)` over the same tail the snapshot reads (`TOOLS_TAIL_BYTES`). That is the rows that `gather` puts in misc for that key, sorted by `at`, each as read from the file (`[]` when none). It is not token-gated, like `/api/file`: it is a read. |
| N13 | **Clicking (AC1).** Every keyed bar's `<rect>` carries `data-tl-keys="<key>"`, `style="cursor:pointer"`, and `data-open="true"` with `stroke="var(--ink)"` while it is open. A row label of a role or `PO` row with at least one keyed bar carries `data-tl-keys="<its keys, space-joined, in from order>"` and `style="cursor:pointer"`. A click on `[data-tl-keys]` sets `ui.tlOpen = toggledKeys(ui.tlOpen, keys)` and renders. `toggledKeys` removes all the keys when every one is already open, and otherwise adds them all. |
| N14 | **Replay.** `asOf` sets `tools: toolsAsOf(snap.tools ?? [], cursor)`. It keeps the groups with `opened_at <= cursor`, and in each one the calls with `at <= cursor`. A call with `ended_at > cursor` becomes `{...call, ended_at: null, seconds: null, status: "open"}`. `misc` is kept as it is (a known limit). The heartbeat is already `null` in replay, so no live calls are added. |
| N15 | **s100 review carry-overs (m4, m5).** `storyGroup` gets its `/** … */` doc. The SVG ids gain the expanded story's id: `tl-<story>-<group>-clip`, `-sleep`, `-arrow` and the new `-unfinished`. `timelineSvg(model, win, now)` takes the story id from `model.story` (set by `timelineModel`), so two open timelines never repeat an id. |

### Readability (AC-R)

TR1–TR5 hold unchanged for every new text. New texts all go through `tlText` / `tlSpan` with the kinds added
to `TL_TEXT` below: all ≥ 12 px, all `--ink` or `--ink-2`, all on `--surface`. The nested row labels use
`label` (13 px). Strips and model bars carry no text (the call's lines sit under the strip, never on it). The
misc box's text sits on its own `--surface` fill. The SVG stays at scale 1 (TR2), and the Flow chart is
untouched (TR5 stands).

## Tables (exact values; tests may assert them)

```js
// TL_TEXT gains:
  call:   { px: 13, ink: "--ink" },  detail: { px: 12, ink: "--ink-2" },  misc: { px: 12, ink: "--ink" },
const NEST = { LANE_H: 44, STRIP_H: 8, INDENT: 12, MIN_DETAIL_CHARS: 8, MISC_PAD: 8 };
const TOOL_WAITING = new Set(["po.run_role"]);                 // tool_calls.WAITING
const TOOL_LOOKS = {
  ok:         { outcome: "ok", fill: "--s3" },
  error:      { outcome: "error", fill: "--critical" },
  timeout:    { outcome: "timeout", fill: "--critical" },
  unfinished: { outcome: "unfinished", fill: "--axis", hatch: true },
  open:       { outcome: "open", fill: "--accent" },
  waiting:    { outcome: "waiting", fill: "--axis" },
};
const MODEL_LOOK = { outcome: "model", fill: "--s4" };
const MISC_TITLE = "misc: gathered from across the step, not placed on the time axis";
const NO_CALLS = "no tool calls";
const MISC_LOADING = "loading", MISC_FAILED = "failed";
```

The hatch pattern `tl-<story>-<group>-unfinished` is
`<pattern width="4" height="4" patternUnits="userSpaceOnUse" patternTransform="rotate(45)"><rect width="4" height="4" fill="var(--axis)"/><rect width="2" height="4" fill="var(--ink-2)"/></pattern>`.
`legendHtml` adds the `TOOL_LOOKS` outcomes and `model` to its swatches. They are deduplicated by outcome
name, as today, with `unfinished` drawn as its fill.

## Known limits

- **Old steps have no tools data.** Steps that ran before s98, or whose rows have fallen out of the 4 MiB
  tail, show `no tool calls`.
- **A running PO turn** still has no bar (s100 limit), so its open `po.run_role` can't be expanded until the
  turn ends.
- **Misc in replay** shows the whole step's misc, not misc as of the cursor. `/api/misc` reads the file as
  it is now.
- **The misc list can drift.** If `collapse_under_s` changed since the snapshot, or the tail moved on, the
  re-gathered list can differ from the box's count. An empty answer says so.
- **Label widths are estimated** (`CHAR_EM`), as in TR4.
- A subagent's (`Task`) inner calls aren't seen (s98 limit). Its `Task` call is one strip.
