# s38: Corrected budget numbers everywhere; the budget ceiling halts the run

Developer: **developer-cli**. The change is in runner Python: `ledger.py`,
`halt.py`, `salvage.py`, `dispatch.py`, `po_tools.py`,
`dashboard/snapshot.py`, plus two built-in role prompts
(`roles/manager.md`, `roles/product-owner.md`). In this design step the
Architect has already updated `reference/protocol.md`, `SKILL.md`, the README
row, `docs/customer/stops-and-resume.md`, `docs/customer/dashboard.md` and
the index in `architecture.md`.

Story: `.team/stories/s38.md`. Decision and why:
[`../adr/ADR-007-budget-correction-and-ceiling.md`](../adr/ADR-007-budget-correction-and-ceiling.md).
Background: [ADR-004](../adr/ADR-004-po-cost-deltas.md), [s25](s25.md).

## Findings

1. **The correction is far larger than $256.93.** ADR-004's $256.93 only
   covered PO lines 46–196. The PO's single session kept running until line
   310: all 47 PO entries from line 46 to 310 rise strictly, and line 312
   (1.65) is the first s25 delta. In this repo's ledger, the PO entries on
   lines 46–310 add up to about **$1,057.35**. The session's real spend is
   the last figure, **$32.49**. So the overcount is about **$1,024.87**, not
   $256.93 (the figures are a hand sum; the live `status` after s38 is the
   check). Corrected spend = raw ledger total − $1,024.87. The PO's "about
   $956" and the Manager's "about 518" both undercount the overcount.
2. **Why the ceiling never stopped the run.** Nothing in the runner compares
   spend with `team.budget_usd`. The budget was a *soft* budget by design
   (`ledger.py` docstring: "hard caps belong to the key's Console
   workspace"). Its only use is `Budget.checkpoint_crossed` in
   `Runtime.record_cost`, which queues Manager reviews every
   `manager_every_pct`. Also, the "104%" was the inflated figure.

## Rules

| # | Rule | AC |
|---|---|---|
| K1 | **Correct when the ledger is read, never rewrite it.** `ledger.jsonl` stays append-only and as written. Corrected entries exist only in memory. | AC1 |
| K2 | **Which entries are corrected.** An entry is *legacy* when `role == "product-owner"` and `at < PO_DELTAS_FROM` (`1791694950.0`, 2026-10-11 05:02:30 UTC). This falls between ledger line 310 (`at` 1791694897.37, the last running total) and line 312 (`at` 1791694982.59, the first s25 delta). Entries at or after the cutoff, and every non-PO entry, pass through unchanged. An entry with no `at` (`0.0`) is legacy. | AC1 |
| K3 | **How a legacy entry is corrected.** Walk legacy entries in file order with one `SessionCost(LEGACY_SESSION, 0.0)`. Each one's own cost is `seen.own_cost(LEGACY_SESSION, raw)`, which is rule C1 of s25: `raw − previous` when `raw ≥ previous`, else `raw` (a drop means a new session). Then set `seen.reported = raw`. Only `cost_usd` changes; tokens, turns, `at`, model and story stay. | AC1 |
| K4 | **One code path.** `ledger.corrected(entries)` is the only place that corrects. `Ledger.entries()` returns `corrected(raw)`, and `dashboard/snapshot._ledger` passes its parsed rows through `corrected`. Every reader of spend goes through one of the two: `Ledger.total`, `totals`, `by_role`, `budget_status`, `insights.spend_by_role`, `long_running_roles`, the budget checkpoint in `record_cost`, the ceiling (B1), `cli.status_report`, the Manager's runner context and the snapshot. | AC2, AC5 |
| K5 | **Raw where the raw figure is meant.** `Ledger.last_cost` (s25 C6 seed) reads the raw entries: the seed needs the running total as written. | AC1 |
| K6 | **The correction is visible.** `budget_status` gains `"po_overcount_usd"`: raw total minus corrected total, rounded to 4 places (`0.0` when nothing is legacy). | AC1, AC5 |
| B1 | **The ceiling.** The run halts when `round(ledger.total(), 4) >= team.budget_usd`. `ledger.total()` is the corrected spend, and the rounding matches `budget_status["spent_usd"]`, so the figure shown is the figure that halts. Below the ceiling nothing happens. At or over it, the run halts. | AC3 |
| B2 | **Where it is checked.** `Runtime.enforce_ceiling()` is called (a) after every role step, at the end of `Runtime.run_role`, once the step has landed (committed, gated, `in_flight` cleared); (b) after every PO query is ledgered, at the end of `PoRun._record`; (c) once at run start, before the PO's opening turn, in `PoRun._turns`. It is never called inside `settle`/`record_cost`: a halt there would salvage the step's edits before they are committed. | AC3 |
| B3 | **The halt is a normal halt.** `enforce_ceiling` calls `Runtime.halt_run(Halt(HaltKind.BUDGET, reason))`. That sets status `blocked` with the reason, saves state, and posts one liaison note of kind `blocked` (the first halt in a process wins, and later calls re-assert it). From then on, `_run_refusal` refuses every `run_role` (`the run is blocked (<reason>); end your turn`), the router's `_ended()` is true, and no further PO query starts (B4). `cli._finish` prints the one stderr line and exits **77**. | AC3 |
| B4 | **No PO query after a halt.** `PoRun._turn` returns `StepResult("", 0.0)` without querying when `runtime.halted_by` is set. This covers the main turn after a renewal turn (compact or handoff) that reached the ceiling. At start, `_turns` skips `_opening()` entirely when `enforce_ceiling()` halts, so `_take_interrupted` does not consume `state.interrupted` unseen. | AC3, AC4 |
| B5 | **Reason and advice (exact strings).** Reason: `budget reached: spent ${spent:,.2f} of ${budget:,.2f}`, for example `budget reached: spent $4.00 of $4.00`. Advice: ``raise team.budget_usd in .agile-team.toml and commit it, then run `agile-team start --resume` ``. The note and the stderr line are `<reason>; <advice>`, as for every halt. "and commit it" is required: `.agile-team.toml` is tracked, and preflight refuses a dirty tree (B9). | AC3 |
| B6 | **A raise takes effect on resume.** Once the raise is committed, `start --resume` passes preflight, loads `.agile-team.toml` afresh, `PoRun.run` resets `halted_by` and marks `running`, and then B2(c) checks against the new figure. If the budget was not raised, the run halts again at once with no query and no spend. The dashboard and `status` already re-read the config on every snapshot or call, so nothing else needs a restart. | AC3, AC4 |
| B7 | **Overshoot is bounded.** The check runs after spend is ledgered, so a run can pass the ceiling by at most the step or PO query in progress when it was reached. It never cuts a step off. | AC3 |
| B8 | **Exit 77, not 75.** 75 means "wait for the reset", and `unattended` resumes on 75 by itself, which would loop on a budget stop. 77 (`EX_NOPERM`: more spend needs the human's permission) ends an `unattended` job as failed, so the human decides. | AC3 |
| B9 | **The clean-tree preflight stays as it is.** The runner does not accept, stage or commit a changed `.agile-team.toml` on the human's behalf. Preflight's clean tree is what lets `save_interrupted` assume that every uncommitted edit belongs to a step, and that state's hashes name the code that ran. A toml-only exception would weaken that gate for one case. Instead, the advice (B5) and the docs tell the human to commit the raise. An uncommitted raise is refused by the existing preflight message (`working tree is dirty (.agile-team.toml); commit or stash first`), and the run stays `blocked` with no query. Committing on the team branch is safe: the runner's history is only ever added to. | AC3 |
| M1 | **Manager totals.** The Manager's runner context already carries `budget = budget_status(...)`. With K4 and K6 it now holds the corrected `spent_usd`, `remaining_usd`, `pct_used`, `by_role`, the ceiling `budget_usd`, and `po_overcount_usd`. `roles/manager.md` describes these fields and says the ceiling halts the run. | AC5 |

Budget checkpoints (`Budget.checkpoint_crossed`) are unchanged: they still
fire only from `record_cost` (role steps), now on corrected spend.

## Changes by module

Every function stays under 8 lines, with at most 2 parameters (besides
`self`) and no flags.

### `ledger.py`

Module docstring: replace "The soft budget ... Console workspace." with:
"The budget is the config's ``team.budget_usd``: a ceiling at which the
runner halts (s38). Readers get corrected entries: PO entries written before
s25 held the session's running total and are turned into each query's own
cost when read (``corrected``, ADR-007)." Keep the `SessionCost` sentence.

New constants (after `USAGE_KEYS`):

```python
PO_ROLE = "product-owner"
PO_DELTAS_FROM = 1791694950.0  # 2026-10-11 05:02:30 UTC; ADR-007
LEGACY_SESSION = "pre-s25"
```

New functions (after `Entry`, before `Totals`; add `replace` to the
`dataclasses` import):

| Signature | Spec |
|---|---|
| `corrected(entries: list[Entry]) -> list[Entry]` | Docstring: "``entries`` with each pre-s25 PO running total turned into that query's own cost (K2, K3)." Body: `seen = SessionCost(LEGACY_SESSION)`, then `return [_own_share(e, seen) for e in entries]`. It never mutates the input entries. |
| `_own_share(entry: Entry, seen: SessionCost) -> Entry` | If `entry.role != PO_ROLE or entry.at >= PO_DELTAS_FROM`: return `entry`. Else `own = seen.own_cost(LEGACY_SESSION, entry.cost_usd)`, `seen.reported = entry.cost_usd`, `return replace(entry, cost_usd=own)`. |

`Ledger` changes:

| Member | Spec |
|---|---|
| `_raw(self) -> list[Entry]` (new, private) | The body `entries()` has today: entries as written. |
| `entries(self) -> list[Entry]` | Docstring: "Entries with the PO overcount corrected (K4)." `return corrected(self._raw())`. |
| `last_cost(self, role: str) -> float` | Reads `self._raw()` instead of `self.entries()` (K5). The docstring gains "as written". |
| `overcount(self) -> float` (new) | Docstring: "What the correction takes off the raw ledger (K6)." `raw = self._raw()`, then return `sum(e.cost_usd for e in raw) - sum(e.cost_usd for e in corrected(raw))`. |

`total`, `totals` and `by_role` do not change; they read `entries()`.

`budget_status`: docstring "Corrected spend against the budget ceiling, for
the PO, the Manager and ``status``." Add the key
`"po_overcount_usd": round(ledger.overcount(), 4)` after `"pct_used"`.
Other keys stay as they are.

`Budget` docstring: "The budget and how often (in percent of it) the Manager
checks in." (drop "soft").

### `halt.py`

- `HaltKind.BUDGET = "budget"` (after `SIGTERM`).
- `HALTS[HaltKind.BUDGET] = HaltRule(RunStatus.BLOCKED, "blocked", 77, BUDGET_ADVICE)`.
- Constants: `BUDGET_REASON = "budget reached: spent ${spent:,.2f} of ${budget:,.2f}"` and
  ``BUDGET_ADVICE = f"raise team.budget_usd in .agile-team.toml and commit it, then {RESUME}"``.
  `RESUME` already holds ``run `agile-team start --resume` ``.
- New function (it is not one of the `DETECTORS`, because no exception
  carries it):

```python
def budget_halt(spent: float, budget_usd: float) -> Halt | None:
    """A ``budget`` halt when ``spent``, rounded as ``budget_status`` shows it, has reached ``budget_usd``."""
    if round(spent, 4) < budget_usd:
        return None
    return Halt(HaltKind.BUDGET, BUDGET_REASON.format(spent=spent, budget=budget_usd))
```

`classify`'s docstring and the module docstring do not change.

```python
def enforce_ceiling(self) -> Halt | None:
    """Halt the run when corrected spend has reached ``team.budget_usd`` (B1, B3)."""
    found = halt.budget_halt(self.ledger.total(), self.config.team.budget_usd)

```

  Use the module's existing way of reaching `halt` (it already calls

## Test checklist (for the Unit Tester)

Build legacy entries with an explicit `at` below `PO_DELTAS_FROM` (for
example `at=1.0`). `Ledger.record` stamps `time.time()` only when `at` is
`0.0`, so pass the `at`, or write the JSONL lines directly.

1. **`corrected`, the worked example above:** the corrected costs match the
   table row by row, and the input list's entries are unchanged.
2. **`corrected` passes through:** non-PO legacy entries; PO entries at or
   after the cutoff, even when they rise; an empty list.
3. **No `at`:** a PO line without `at` (loads as `0.0`) is legacy.
4. **`Ledger`:** `entries()`, `total()` and `by_role()` are corrected;
   `last_cost(PO)` returns the raw last figure; `overcount()` is raw minus
   corrected; with no file all are empty or `0.0`.
5. **`budget_status`:** `spent_usd`, `remaining_usd`, `pct_used` and
   `by_role` use corrected figures; `po_overcount_usd` is present (`0.0` for
   a ledger with no legacy entries).
6. **AC2, one path everywhere:** a run dir whose ledger has inflated legacy
   PO lines plus role lines. These are all equal to the corrected total:
   `cli.status_report(config)["budget"]["spent_usd"]`; the sum of `cost_usd`
   over `snapshot.build(...)["ledger"]`; `budget_status(...)["spent_usd"]`;
   and the `budget.spent_usd` in the Manager's runner context
   (`Runtime._manager_context()`, parse the JSON after `"Runner context:\n"`).
7. **`halt.budget_halt`:** below → `None`; equal → `Halt(BUDGET, "budget
   reached: spent $4.00 of $4.00")`; over; `3.99995` against `4.0` → halts
   (rounding, B1); thousands format `spent $1,213.00 of $1,500.00`.
8. **`HALTS[BUDGET]`:** status `blocked`, note kind `blocked`, exit 77;
   `message()` is ``<reason>; raise team.budget_usd in .agile-team.toml and
   commit it, then run `agile-team start --resume` ``. `Cause("budget")` exists.
9. **`Runtime.enforce_ceiling`:** below → `None`, status unchanged, no note;
   at → status `blocked`, `status_reason` is the reason, exactly one
   `blocked` note; a second call posts no second note.
10. **Role step reaches the ceiling (B2a, B7):** budget 1.0, a role step that
    costs 1.2. The step lands normally: its commit exists and its edits were
    not salvaged (`state.interrupted` empty); then the run is `blocked`. The
    next `run_role` is refused with `the run is blocked (budget reached: spent
    $1.20 of $1.00); end your turn`.
11. **PO query reaches the ceiling (B2b, B4):** the PO turn's ledger entry
    pushes spend to the ceiling. The run halts, and the router runs no
    further step. A renewal turn that halts is followed by no main PO query
    (the fake query's call count proves it).
12. **AC4 sequence, through `cli` with a fake query** (one test or a
    parametrized set). Every `start` / `start --resume` here goes through the
    real entry point (`cli.main([...])` or the same path `start` takes), so
    the config is loaded from disk and the real `Preflight` runs. Fake only
    `which`, as `test_cli.py` and `e2e/test_halt_e2e.py` do
    (`monkeypatch.setattr(cli, "Preflight", partial(preflight.Preflight,
    which=lambda e: e))`). Never change `rt.config` in memory or call
    `cli._run` directly:
    - below the ceiling: `start` runs, exit 0, status not `blocked`;
    - reaches it during the run: exit 77, status `blocked`, reason names
      spend and ceiling, one `blocked` note in the outbox, stderr line
      `agile-team start: budget reached: …; raise team.budget_usd …`;
    - over it at start (`start --resume` with spend already > budget):
      exit 77, **zero** queries, `state.interrupted` left as it was;
    - raise without committing (rewrite `.agile-team.toml` with a higher
      `budget_usd`, leave it uncommitted) then `start --resume`: preflight
      refuses with `working tree is dirty (.agile-team.toml); commit or stash
      first`, **zero** queries, status still `blocked` (B9);
    - raise and commit (rewrite `.agile-team.toml` with a higher
      `budget_usd`, `git add` + `git commit` it) then `start --resume`: the
      PO runs (call count ≥ 1) and the status is not `blocked`;
    - resume without a raise: halts again at once with zero queries.
13. **Checkpoints unchanged:** s25's checkpoint test still passes as
    written.

**Existing tests that may change (contract change, not weakening):** a test
whose role steps spend past its configured `budget_usd` will now halt. Where
the ceiling is not what that test is about, raise the test's `budget_usd` so
that spend stays below it. Name each such test in your handoff.
`test_snapshot.test_build_matches_fixture_values` moves the fixture's ledger
rows past `PO_DELTAS_FROM` and still compares with `==`. Without that, its
rising PO rows would be read as legacy running totals. This is a contract
change, not a weakening.

Coverage stays at 95% or more; ruff check and ruff format are clean.
