# s179: a resume keeps the worktrees of open sprint stories

Bug fix. `Runtime.recover_stories` passed `prune_stale` only the stories with
`in_flight` set, so every `start --resume` removed the worktree of every
other open story (`git worktree remove --force`, then `remove_tree`), and
their git-ignored files (`house-rules/runner/.venv`) went with them. The
next step on each story ran `git worktree add` again.

Traces: AC1 → REQ-193, AC2 → REQ-194, AC3 → REQ-195. REQ-160's resume
sentence now points at REQ-194. Changes s159's I3; ADR-0084 is amended
("Amended by s179").

Developer: `developer-cli`.

## Rules

- **R1. What a resume keeps.** A stored worktree
  (`.team/run/worktrees/<name>/`) is kept when its story is in
  `state.stories` and either has a step in flight, or is not `done` or
  `cancelled` and has `story.sprint == state.sprint`. Blocked, needs-manager
  and at-`land` stories in the sprint are open, so they are kept.
- **R2. What a resume removes, and why.** Every other stored worktree, with
  one `PruneReason`, checked in this order:
  1. no story of that id in `state.stories` → `unknown`;
  2. a step in flight → kept (never removed, whatever its status or sprint);
  3. status `done` → `done`; status `cancelled` → `cancelled`;
  4. `story.sprint != state.sprint` (a Product Backlog story, or one moved
     out) → `not_in_sprint`;
  5. otherwise kept.
- **R3. Scratch dirs.** `.team/run/land` and `.team/run/replay` are removed
  when they exist and are not pinned, with reason `scratch`. `replay` is
  pinned while `state.boundary` is set and `state.boundary.replay` is not
  `None` (as today). `land` is never pinned: a landing builds its merge
  afresh. `.team/run/rebase` is not touched (as today).
- **R4. One event per removal.** Each removal logs one `worktree-pruned`
  event: role `None`, story = the worktree's name for a story worktree and
  `None` for a scratch dir, data `{"worktree": <name>, "reason": <reason>}`.
  No event for a kept worktree.
- **R5. A removed story worktree's record is cleared.** For a removed story
  worktree whose story exists, `story.worktree_head = ""` (as
  `drop_worktree` does), so `count_open` no longer counts it and its next
  step rebuilds it through B1 (replaying a stale base, as for a moved-out
  story). The branch stays.
- **R6. Drift is the next step's business.** The resume reads no worktree's
  HEAD and judges no drift. A kept worktree is checked by the unchanged B5
  path at its story's next step (`Runtime.prepare_story` → `find_drift`):
  a HEAD other than `worktree_head`, another branch, or a git operation in
  progress holds the story as `worktree_drift`. Uncommitted edits are not
  drift (an interrupted step's edits stay, as today).
- **R7. Order.** `recover_stories` prunes first, then resumes each cut-off
  step, then saves, as today. So a cut-off step's `step-end` is still the
  last event the resume writes.
- **R8. A kept worktree is reused.** A kept story's next step finds
  `worktree_head` set and the directory present, so `Workspaces.ensure`
  runs no `git worktree add`. No change in `ensure` is needed.

`_make_workspace` still logs `story-branch` `rebuilt` for every step on a
story that has a branch, even when the worktree was reused. That is
existing behaviour and out of scope; AC1 is checked by the absence of a
`worktree add` call, not by that event.

Reuse `make_runtime` and the `FakeSystem`/`fake` fixtures the s159 and s165
tests use (`tests/test_s159_workspaces.py`, `tests/test_s165_resume_story.py`).

worktree dirs with `system.make_dirs(rt.config.run_dir / "worktrees" / id)`.

- [ ] `find_prune_reason`: `None` story → `unknown`; in flight with status
      `done` and another sprint → `None`; `done` → `done`; `cancelled` →
      `cancelled`; `sprint=None` → `not_in_sprint`; `sprint=2` →
      `not_in_sprint`; active, blocked and at `land` in sprint 1 → `None`
      (R1, R2; AC2).
- [ ] A resume keeps an open sprint story's worktree with no step in flight:
      its directory and an ignored-style file in it (e.g.
      `worktrees/s2/house-rules/runner/.venv/marker`) still exist, no
      `worktree remove` names it, and its `worktree_head` is unchanged
      (AC1, R1).
- [ ] After that resume, the story's next step (`prepare_story`) runs no
      `worktree add` (AC1, R8).
- [ ] A resume removes the worktrees of a done, a cancelled, a
      not-in-sprint and an unknown story, clears `worktree_head` of each
      existing one, and logs exactly one `worktree-pruned` event per removal
      with `story` and `reason` (AC2, R2, R4, R5).
- [ ] `land` and an unpinned `replay` are removed with one
      `worktree-pruned` event each (`story` `None`, reason `scratch`); a
      pinned `replay` stays and logs nothing (AC2, R3, R4).
- [ ] A kept worktree logs no `worktree-pruned` event (AC2, R4).
- [ ] With a story in flight and another to prune, the cut-off step's
      `step-end` is the last event (R7).
- [ ] A kept worktree whose HEAD differs from `worktree_head` survives the
      resume, and its next `prepare_story` returns the drift refusal with
      `story.drift` set (AC3, R6).
- [ ] End to end with real git (`tests/e2e/test_s179_resume_e2e.py`, reuse
      the harness of `tests/e2e/test_s165_resume_e2e.py`): run until a stop
      with s1 at a role step and its worktree made, write an untracked file
      under a gitignored path in s1's worktree, `start --resume`; the file is
