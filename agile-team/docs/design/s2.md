# s2: Requirement change tracking, auto-accept and requirements log

Every requirement change a step commits carries a reason, and the reason is
recorded in git. The runner sorts a step's requirement files into added,
changed and retired. A changed or retired one needs a reason in the handoff.
The reasons become `Requirement-Changed` trailers on the step's own commit,
and each change is a `requirement-changed` event. Other stories that trace a
changed or retired requirement and are past design go back to design without
counting a round. Done ones are reported so the PO asks for a follow-up
story. `agile-team requirements log` reads the trailers back.

Developer: **developer-cli** (runner Python: a new `requirement_changes.py`,
plus `roles`, `git_ops`, `dispatch`, `gates`, `stop_checks`, `stages`,
`handover` and `cli`, and two built-in role files).

ADR: **ADR-0083** (git trailers are the only store, unexplained edits are
held back, the architect's stop check, auto-accept). It builds on ADR-0060
(s1's file format and parser). No new dependency, no new PO tool. The event
kind `requirement-changed` already exists (`EventKind.REQUIREMENT_CHANGED`).

Requirements: REQ-123 to REQ-129.

## Rules

### C1 Which files (AC1)

A step's *candidates* are the paths in `audit.in_scope` (after the
quarantine) whose parent is the requirements folder
(`requirements.folder_of(config)`, repo-relative POSIX) and whose name
matches `REQ-*.md` (`fnmatch`, the same glob `requirements.sources` uses).
With no candidates, nothing below runs and no git command is added. In
practice only the architect has the folder in its write scope, so only
architect steps have candidates. The code has no role check: the scope
decides.

### C2 How they are classified (AC1)

`git diff --name-status --no-renames -z HEAD -- <candidates>` gives a letter
for each tracked candidate. A candidate that the diff doesn't list is
untracked, so its letter is `A`. Then each candidate's two versions are
read: `before` is `git show HEAD:<path>` (`None` for `A`), and `after` is
the file on disk (`None` for `D`). Its `id` is the file stem (`REQ-003`).

| Versions | `Change` |
|---|---|
| `before is None` | `added` |
| `after is None` (file removed) | `retired` |
| `after`'s frontmatter `status` is `retired` and `before`'s is not | `retired` |
| anything else (including retired → active) | `changed` |

`status` and `covers` are read leniently with `frontmatter.parse(text)`. A
version with no readable frontmatter has no status and no covers. The design
gate and `requirements check` report broken files. The classifier never
refuses anything.

`stories` of a change: the story ids of every `covers` item in **either**
version that `requirements.parse_ref` accepts, without duplicates, in
natural order (`priority.natural`). So a requirement that stops covering
`s5/AC1` still affects s5.

### C3 Reasons (AC2)

- The handoff has a new optional field `"requirement_changes": {"REQ-003":
  "why"}`. When it is present it must map strings to strings. If it doesn't,
  the handoff is malformed: `requirement_changes must map requirement ids to
  reasons`.
- A reason is the value with its whitespace collapsed:
  `" ".join(value.split())`. It is one line, because it becomes a trailer.
- An `added` change without a reason gets `NEW_REASON = "new requirement"`.
- A `changed` or `retired` change whose reason is empty is **unexplained**.
- A reason for an id that is not a candidate is ignored.

### C4 Unexplained edits are held back, and the step bounces (AC2)

- The unexplained candidates are held back. They are committed alone and
  that commit is reverted, the same way the quarantine works:
  `HELD_SUBJECT = "chore(team): {role}'s unexplained requirement edits, held
  back"`. The tree then has none of them. Every requirement change that
  stays in the tree has its reason in its own commit. The hold-back sha is
  in the report as `held_back`.
- The step then counts as a bad handoff. The hold-back stores
  `describe_unexplained(held, sha)` in `plan.unexplained`, and `_settle`
  replaces the parsed handoff with `build_unexplained_error(parsed,
  plan.unexplained)`. The texts:

  ```
  UNEXPLAINED = "{explain} (your edits are held back in {sha}; make them again and give each reason in the handoff's requirement_changes)"
  EXPLAIN = "explain change to {id}"     # one per held id, natural order, joined by "; "
  ```

  When the handoff was already malformed, the text is
  `f"{error}; {UNEXPLAINED…}"` (`build_unexplained_error`). From there it goes the way a bad handoff
  goes today. The step-end event says `bad_handoff` with that summary.
  `_apply` bounces to the story's step (`Author.ROLE`, a round) when the
  role fits it. The report has `status: "bad_handoff"` and `reason`. On a
  gate fix step, `_settled` turns it into `failed`, as it does today.
- Explained and added candidates still land in the step commit. Nothing
  else in the step changes.

### C5 The architect's stop check (AC2)

A held-back edit costs a round and the edit itself, so the architect is
stopped first, inside its conversation. There is a new stop check
`StopCheck.REQUIREMENTS = "requirements"` with
`Spec(stages.Name.STOP_REQUIREMENTS)` (every stop, no step), and
`STOP_CHECKS["architect"] = (StopCheck.REQUIREMENTS,)`. It runs on a `done`
handoff, like every stop check. It finds the candidates from the stop hook's
own `guard.audit_step(git, plan.scope)` (C1, C2) and refuses with:

```
STOP_EXPLAIN = "{explain}: add \"requirement_changes\": {{\"<id>\": \"<why>\"}} to your handoff for each changed or retired requirement"
```

It refuses at most 3 times and stays within `stop_check_budget_s`, as today.
Once the stop goes through, C4 still applies.

### C6 Trailers (AC3)

The step commit's message ends with one trailer block. It holds one
`Requirement-Changed: {id}: {reason}` line per landed change (added ones
included, natural order of id), then `Co-Authored-By: …`. All of them sit in
**one** paragraph, so `git log --format=%(trailers…)` reads them.
`git_ops.with_trailer` builds that block. A commit without requirement
changes is byte-for-byte what it is today. The hold-back and quarantine
commits carry no requirement trailers. Git is the only durable store: there
is no new file and no state field.

### C7 Events (AC4)

After the step commit, each landed change, in trailer order, emits
`EventKind.REQUIREMENT_CHANGED` through `Runtime.emit(kind, plan, ...)`, so
`role` and `story` are the step's. Its data is
`{"id", "change", "reason", "sha"}`: `change` is the kind (`added`,
`changed` or `retired`), `reason` is exactly as in the trailer, and `sha` is
the step commit. These are the keys the dashboard's D6 `history` already
reads (s4), so `history[].sha` is no longer `""`. A held-back change emits
nothing.

### C8 Auto-accept (AC5)

After the events, for the landed changes whose kind is `changed` or
`retired`:

- The traced stories (`collect_traced`): the union of their `stories`,
  without the step's own story, in natural order.
- Each traced id that has a `StoryState` and is not `CANCELLED` is handled
  like this:
  - `DONE`: added to `affected_done_stories`.
  - open (not in `gates.FINISHED`) and `pipeline.is_past_design(story)`:
    `pipeline.redesign(story)`. That function exists already (s135 amend).
    It clears the loop state and sets `rounds = 0`, so no round is counted.
    The story's `note` becomes
    `REDESIGN_NOTE.format(by=<step story or "run">, sha=<sha12>, changes=...)`:

    ```
    REDESIGN_NOTE = "Back to design: {by}'s step changed requirements this story traces ({sha}): {changes}. Check the design and its trace against them."
    # changes: "REQ-003 changed: why; REQ-004 retired: why"  (only those that name this story)
    ```

    The router already shows a story's `note` in its next brief
    (`- From the PO: …`).
  - Any other story (at `design` or before): nothing changes.
- `Pipeline.is_past_design(story)`: `story.step in self.steps` and its index
  is greater than the index of `self.design_step()`.
- State is saved once, after the loop.

### C9 The report and the PO (AC5)

The dict that `settle_tree` returns (and so the `run_role` report) gains
these keys, **each only when it is non-empty**. Existing reports keep their
exact shape.

| Key | Value |
|---|---|
| `requirement_changes` | `[{"id", "change", "reason"}]`, the landed changes in trailer order |
| `redesigned_stories` | the ids sent back to design (C8), natural order |
| `affected_done_stories` | the done ids (C8), natural order |
| `held_back` | the hold-back sha (C4) |

There is a new hand-over row, after `QUARANTINE`, so the PO acts on the done
stories:

```
Rule(Trigger.AFFECTED_DONE, lambda r: bool(r.get("affected_done_stories")), AFFECTED_DONE_LINE)
AFFECTED_DONE_LINE = "{story}: {role} changed requirements that done stories trace ({requirement_changes}): {affected_done}. Ask the liaison with request_story for a follow-up story that checks them against the changed requirements"
```

`Trigger.AFFECTED_DONE = "affected_done"`. `report_fields` gains
`affected_done` (`", "`-joined ids) and `requirement_changes`
(`"; "`-joined `"{id} {change}: {reason}"`). The PO never writes a story
(REQ-041). It asks the liaison.

### C10 `agile-team requirements log` (AC6)

- The `requirements` command's `action` choices become `["check", "log"]`.
  `cmd_requirements` looks the action up in a table
  (`REQUIREMENT_ACTIONS`), with no `if`. It needs no runner and no key, and
  it honours `--repo`.
- It runs one git command,
  `git log --reverse --format=%H%x1f%aI%x1f%(trailers:key=Requirement-Changed,valueonly,unfold,separator=%x1e)%x1d -- <folder>`.
  Every trailer commit changes a file in the folder (C6), so the path limit
  loses nothing.
- It prints a JSON list (`print_json`), oldest commit first, and within a
  commit in trailer order:
  `[{"id": "REQ-003", "reason": "why", "sha": "<40 hex>", "date": "<author date, ISO 8601>"}]`.
  The value is split at its first `": "`. A value whose id part doesn't
  fully match `REQ-\d+`, or whose reason is empty, is skipped. Commits with
  no such trailer give nothing. `[]` when there are none.
- Exit 0. A git error (not a repo) exits 1 with `agile-team requirements
  log: <error>` on stderr, the way the CLI reports other git errors.
- The author date is used, not the committer date, because a sprint-end
  rebase keeps it.

### `agile_team/requirement_changes.py` (new)

Module docstring: `"""A step's requirement changes: classify, explain, trailers, auto-accept and the log (s2, ADR-0083)."""`
Imports: `fnmatch`, `re`, `dataclasses`, `enum.StrEnum`, `pathlib.PurePosixPath`,
`collections.abc` (`Callable`, `Mapping`, `Sequence`), `typing.Any`;
`from . import frontmatter, system`; `from .gates import FINISHED,
StoryState, StoryStatus`; `from .git_ops import Git`; `from .priority
import natural`; `from .requirements import parse_ref`; `from .roles
import Handoff, HandoffError`.

```python
GLOB = "REQ-*.md"
TRAILER_KEY = "Requirement-Changed"
TRAILER = "Requirement-Changed: {id}: {reason}"
NEW_REASON = "new requirement"
EXPLAIN = "explain change to {id}"
UNEXPLAINED = "..."      # C4, exactly
STOP_EXPLAIN = "..."     # C5, exactly
HELD_SUBJECT = "..."     # C4, exactly
REDESIGN_NOTE = "..."    # C8, exactly
DIFF_ARGV = ("diff", "--name-status", "--no-renames", "-z", "HEAD", "--")
LOG_FORMAT = "%H%x1f%aI%x1f%(trailers:key=Requirement-Changed,valueonly,unfold,separator=%x1e)%x1d"
LOG_ID = re.compile(r"REQ-\d+")     # fullmatch

class Change(StrEnum):            # ADDED = "added", CHANGED = "changed", RETIRED = "retired"
NEEDS_REASON = frozenset({Change.CHANGED, Change.RETIRED})

@dataclass(frozen=True)
class Versions:                   # one candidate's text at HEAD and on disk; None when absent
    file: str
    before: str | None
    after: str | None

@dataclass(frozen=True)
class Changed:
    id: str
    change: Change
    file: str
    stories: tuple[str, ...]      # C2, natural order

@dataclass(frozen=True)
class Explained:
    changed: Changed
    reason: str                   # "" when unexplained (C3)
    @property
    def trailer(self) -> str: ...            # TRAILER
    @property
    def entry(self) -> dict[str, str]: ...   # {"id", "change", "reason"}

@dataclass(frozen=True)
class Sorting:                    # a step's candidates split by C3
    landed: tuple[Explained, ...]  # added or explained, natural order of id
    held: tuple[Changed, ...]      # unexplained, natural order of id
    @property
    def held_files(self) -> list[str]: ...
    @property
    def trailers(self) -> tuple[str, ...]: ...

@dataclass(frozen=True)
class Affected:
    redesign: tuple[str, ...] = ()
    done: tuple[str, ...] = ()

# pure
def select_candidates(paths: Sequence[str], folder: str) -> list[str]: ...     # C1
def classify(versions: Versions) -> Changed: ...                               # C2 table
def find_reason(changed: Changed, reasons: Mapping[str, str]) -> str: ...      # C3
def sort_changes(changes: Sequence[Changed], reasons: Mapping[str, str]) -> Sorting: ...
def describe_held(held: Sequence[Changed]) -> str: ...                         # EXPLAIN lines joined "; "
def describe_unexplained(held: Sequence[Changed], sha: str) -> str: ...        # UNEXPLAINED, filled in
def build_unexplained_error(parsed: Handoff | HandoffError, text: str) -> HandoffError: ...  # C4
def collect_traced(landed: Sequence[Explained], own: str | None) -> list[str]: ...    # C8, needs-reason kinds only
def find_affected(stories: Mapping[str, StoryState], scope: AcceptScope) -> Affected: ...
def build_redesign_note(landed: Sequence[Explained], target: NoteTarget) -> str: ...
def parse_log(out: str) -> list[dict[str, str]]: ...                           # C10

@dataclass(frozen=True)
class AcceptScope:                # what find_affected needs besides the stories
    traced: tuple[str, ...]
    past_design: Callable[[StoryState], bool]

@dataclass(frozen=True)
class NoteTarget:                 # whose note, written by which step's commit
    story: str
    by: str                       # the step's story id, or "run"
    sha: str

# I/O (git and disk only)
def read_name_status(git: Git, paths: Sequence[str]) -> dict[str, str]: ...  # path -> letter; unlisted -> "A"
def read_versions(git: Git, entry: tuple[str, str]) -> Versions: ...       # (path, letter)
def find_changes(git: Git, paths: Sequence[str]) -> list[Changed]: ...     # candidates already filtered
def hold_back(git: Git, held: HeldBack) -> str: ...                        # commit + revert, returns the held sha
def read_log(git: Git, folder: str) -> list[dict[str, str]]: ...           # C10

@dataclass(frozen=True)
class HeldBack:
    role: str
    files: tuple[str, ...]
```

Notes:
- Every function and method name, public or private, starts with a verb
  from house-rules' list (`house-rules/runner/house_rules/verbs.py`), and
  every property is a noun (REQ-073; see § Renames). Nothing is added to
  `.house-rules-baseline.json` for this story. Private names are the
  developer's choice under the same rule; tests must not call them.
- `Explained.trailer` and `Explained.entry` are properties. They take only
  `self`, return a value and change nothing, so house-rules' query-property
  rule makes them properties. Don't give them dummy parameters to dodge
  that rule. `entry` is a noun, because a property may not start with a
  verb, and `report` is one.
- `read_name_status` parses the `-z` output as letter/path pairs. A letter
  `T` counts as `M`.
- `describe_unexplained(held, sha)` is
  `UNEXPLAINED.format(explain=describe_held(held), sha=sha)`.
- `build_unexplained_error(parsed, text)` returns `HandoffError(text)`. If
  `parsed` is already a `HandoffError`, it returns
  `HandoffError(f"{parsed}; {text}")`.
- `read_log` runs `git log --reverse --format=LOG_FORMAT -- <folder>` and
  returns `parse_log` of its output. It lets `GitError` through.
- `read_versions` uses `git.run("show", f"HEAD:{path}")` and
  `system.read_text(git.repo / path)`.
- `hold_back` is `sha = git.commit(list(held.files),
  HELD_SUBJECT.format(role=held.role))`, then `git.revert(sha)`, then it
  returns `sha`. It mirrors `guard.quarantine`.
- `find_affected` skips ids with no `StoryState` and `CANCELLED` stories. It
  puts `DONE` in `done` and open stories with `past_design(story)` in
  `redesign`. Both are in `traced` order.
- Keep each function under 8 lines with at most 2 parameters (house rules).
  That is why `AcceptScope`, `NoteTarget` and `HeldBack` exist.

### `agile_team/dispatch.py`

- `Plan` gains `reasons: dict[str, str] = field(default_factory=dict)`.
  `_parse` sets it to `handoff.requirement_changes` next to
  `plan.summary`. On a `HandoffError` it stays `{}`. This is how the reasons
  reach `settle_tree`.
- `Plan` gains `unexplained: str = ""`: the C4 text, set by the hold-back
  and read by `_settle`.
- `settle_tree(plan)` keeps its job. Widen its return annotation to
  `dict[str, Any]`. In this order, it:
  1. verifies the checkout;
  2. audits;
  3. quarantines;
  4. **sorts** (`_sort_requirements(self, plan: Plan, audit: guard.Audit) ->
     requirement_changes.Sorting`, empty when there are no candidates);
  5. **holds back** the held files
   (`requirement_changes.hold_back(git, HeldBack(role, files))`), only
   when there are any, and sets `plan.unexplained =
   describe_unexplained(sorting.held, sha)`;
  6. commits the in-scope paths that were not held back, with
     `sorting.trailers`;
  7. **records** (`_record_requirements(self, plan: Plan, sorting: Sorting)
     -> dict[str, Any]`: the events (C7) with `plan.commit` as `sha`,
     auto-accept (C8) and the C9 keys);
  8. calls `record_checkout` when it made any commit, quarantine or
     hold-back.

  Split it into helpers so each method stays short.
- `commit_step(self, plan: Plan, staged: Staged) -> str` with a new
  `@dataclass(frozen=True) class Staged: paths: list[str]; trailers:
  tuple[str, ...] = ()` (docstring: "The paths a step commit takes and the
  trailers its message ends with (s2)."). It commits with
  `self.git.commit_by(staged.paths, Authored(commit_message(plan,
  self._subject(plan)), trailers=staged.trailers))`. `settle_po`'s path
  through `settle_tree` gets `Staged(paths)`.
- `_settle`: after `report |= self.settle_tree(plan)` and before
  `_emit_step_end`, `parsed = _check_explained(parsed, plan)`. The
  module-level helper `_check_explained(parsed, plan) -> Handoff |
  HandoffError` returns `parsed` when `plan.unexplained` is empty, and
  `requirement_changes.build_unexplained_error(parsed, plan.unexplained)`
  otherwise.
- `_record_requirements` returns `{}` and emits nothing when
  `sorting.landed` is empty or `plan.commit` is `None`. The second can't
  happen with a landed change, since landed changes are in the commit.
  `settle_tree` adds `held_back` to the report itself, when it held
  something back. Each event's data is `explained.entry | {"sha":
  plan.commit}`, and the report's `requirement_changes` is
  `[e.entry for e in sorting.landed]`.
- Auto-accept: `requirement_changes.find_affected(self.state.stories,
  AcceptScope(tuple(collect_traced(landed, own)), self.pipeline.is_past_design))`.
  Then, for each `redesign` id, `self.pipeline.redesign(story)` and the
  note (`build_redesign_note(landed, NoteTarget(id, own or "run", sha))`).
  Then `self.save()` once, when any story went back.

functions and the FAKE git seam) and `tests/test_s2_settle.py` (settle_tree,
`_settle`, the stop check, the hand-over and the CLI). Unit tests use the

scripted. They use no real git and no temp-dir fixtures (s154).

that owns `{e2e}` writes them. No existing unit test moves to e2e. The unit
tests for items 13, 21 and 22 (scripted `git log`) stay where they are. The
e2e tests add the real-git read-back on top of them.

Classification (AC1):
1. `select_candidates`: keeps `<folder>/REQ-003.md` and drops
   `<folder>/sub/REQ-1.md`, `<folder>/README.md` and `docs/REQ-003.md`.
2. `classify`: one case per C2 row. A file added already retired is
   `added`. Retired → active is `changed`. Text-only edits are `changed`.
   Removal is `retired`.
3. `stories`: the union of both versions' covers, natural order
   (`s2` before `s10`), bad refs ignored, and a version with no frontmatter
   giving nothing.
4. `read_name_status` on `-z` output: `M`, `D` and `T` (as `M`), plus an
   untracked candidate as `A`.
5. No candidates: `settle_tree` runs no `diff` or `show` (the fake git
   records none), and the report has none of the C9 keys.

Reasons and bounce (AC2):
6. The handoff parses `requirement_changes`. A non-mapping value, or a
   non-string reason, is a `HandoffError` with the exact rule text.
7. `find_reason`: whitespace is collapsed. An added change without a reason
   gets `"new requirement"`. A changed one with `"  "` gets `""`.
8. A changed requirement with no reason: its edit is held back (a commit and
   its revert, `HELD_SUBJECT`), the tree no longer has the edit, the step
   commit doesn't contain the file, and the report has `status:
   "bad_handoff"`, `held_back` and `reason` starting
   `"explain change to REQ-003 (your edits are held back in "`. The step
   bounces to its step with a round, and the step-end event says
   `bad_handoff`.
9. Two unexplained (REQ-004, REQ-003) give `"explain change to REQ-003;
   explain change to REQ-004 (…"`. An added and an explained one in the
   same step still land.
10. A malformed handoff plus a changed requirement: everything that needs a
    reason is held, and the text is `"<error>; explain change to …"`.
11. A reason for an id that is not a candidate is ignored (no trailer, no
    event).
12. Stop check: an architect `done` with an unexplained change is refused
    with `STOP_EXPLAIN`. With the reason it passes. Other roles have no
    `requirements` check (`checks_for`).

Trailers (AC3):
13. `with_trailer("s\n\nb", ["Requirement-Changed: REQ-001: x"])` ends
    `"\n\nRequirement-Changed: REQ-001: x\nCo-Authored-By: …\n"`. Without
    trailers the output is as today.
14. e2e: after a step with an added and a changed requirement,
    `git log -1 --format=%(trailers:key=Requirement-Changed,valueonly)` on
    the step commit lists both, natural order, and the Co-Authored-By
    trailer is still read as a trailer.

Events (AC4):
15. One `requirement-changed` event per landed change, in trailer order,
    with `role`, `story` and data exactly `{id, change, reason, sha}`, where
    `sha` is the step commit. A held-back change has no event.
16. `snapshot.build` on such events gives `history[].sha` equal to the
    commit (s4 D6 unchanged).

Auto-accept (AC5):
17. A changed requirement covering s5 (at `implement`, 2 rounds), s6 (at
    `design`), s7 (done), s8 (cancelled) and the step's own story s9. After
    the step, s5 is at `design` with `rounds == 0` and the note
    `REDESIGN_NOTE`. s6, s7, s8 and s9 keep their step. The report has
    `redesigned_stories == ["s5"]` and `affected_done_stories == ["s7"]`.
18. An `added` requirement covering s5 changes nothing. A requirement that
    drops `s5/AC1` from `covers` sends s5 back (old covers count). A
    `retired` one counts.
19. `is_past_design`: false at `design` and before, true at `ops-review` and
    later, false for a step not in `steps`.
20. Hand-over: a report with `affected_done_stories` gives the
    `AFFECTED_DONE_LINE` with the ids and the changes. A report without it
    gives no such row.

Log (AC6):
21. `parse_log`: two commits, one with two trailers, one with none, give
    three rows in order with `id`, `reason`, `sha` and `date`. A value with
    no `": "`, an id that is not `REQ-\d+`, or an empty reason is skipped.
    A reason containing `": "` keeps it.
22. e2e: `agile-team requirements log` on a scratch repo after two trailer
    commits prints the JSON list, oldest first, and exits 0. With no
    trailers it prints `[]`. Outside a git repo it exits 1 with the stderr
    line. `requirements check` is unchanged.

Docs (AC7, by review):
23. The two role files hold the texts above. `test_s1_gate` checklist 18
    style: assert `requirement_changes` is in `architect.md`, and
    `affected_done_stories` and `request_story` are in `product-owner.md`.

## Renames

Every name this design pins was checked against house-rules' `verb-name`
and `query-property` rules (REQ-073). The test is the first snake_case word
against `house_rules/verbs.py`. `explain`, `redesign`, `reason`, `traced`,
`trailer`, `candidates` and `unexplained` are not on the list, so names
that start with them fail. Nothing is baselined. Each rename is pinned by
this table, and the tests must follow it.

## Out of scope

- The dashboard page. History already renders from the event, and `sha` now
  fills in. Adding `sha` to the fixture's `requirement-changed` events is
  optional. If it is done, it goes through the fixture script (REQ-006).
- Filtering the log by id (`jq` does it).
- Auto-accept for stories not opened in `state.json` (Product Backlog story
  files with no state never got past design).
- Explaining changes made by hand outside a step. The runner sees only step
  commits.
- Folding the shared sort sequence into one helper. `StopChecks._check_requirements`
  and `Runtime._sort_requirements` both run `folder_of` → `select_candidates` →
  `find_changes` → `sort_changes`, as this design told them to (review F2). The copy is
  four lines with different inputs (`handoff.requirement_changes` against
  `plan.reasons`). A later quality story may add one `requirement_changes` helper that
  both call, so the stop check and the hold-back cannot drift apart.
