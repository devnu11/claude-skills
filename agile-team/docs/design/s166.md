# s166 design: a merged PR is closed, and costless running work holds no reserve

Story: `.team/stories/s166.md`. Requirements: REQ-174 (AC1), REQ-175 (AC2).
ADRs: ADR-0084 amended (closing a PR), ADR-0085 amended (the budget reserve).
Developer: `developer-cli`.

## Rules

- **P1. A merged PR counts as closed.** `GhPrs.close(pr, note)` runs
  `gh pr close <pr> --comment <note>` once, as now. When that fails, it reads
  the PR's state (`gh pr view <pr> --json state`). If the state is `MERGED`,
  `close` returns normally. Otherwise it raises
  `UpstreamError(<the close's output, stripped>)`, as today. When the state
  read fails or gives no JSON object with `"state"`, that counts as "not
  merged", and the close's own error is raised.
- **P2. No note on a merged PR.** `gh pr close` refuses a merged PR before it
  posts the comment, and on a PR that is already closed it posts nothing and
  exits 0. So the note goes only to a PR that was open. P1 never posts a note
  by itself (no `gh pr comment` call).
- **P3. One place.** The fix lives only in `GhPrs.close`. Every caller shares
  it and doesn't change: `Lander.complete` (the landed story's PR),
  `story_ci` `_close` (a superseded story PR) and
  `BoundaryRunner._push_replay_branch` (a superseded sprint PR). `NoPrs.close`
  still raises.
- **P4. Why read the state after the failure, not before.** Reading first
  costs a `gh` call on every close and still races: GitHub marks a story PR
  merged a moment after the sprint push. Reading after the failure costs
  nothing on the normal path and sees the state at the moment gh refused.
  The pin's hotfix matched gh's message text. This design reads the state
  instead, so a change in gh's wording doesn't break it.
- **B1. Only work with a role and a model holds a reserve.** `COSTLESS`
  (`{StepKind.LAND, StepKind.BOUNDARY}`, `scheduler.py`) is the set of kinds
  that run as the role `runner`. `Scheduler.check_budget(work)` still returns
  `None` at once when `work.kind in COSTLESS`. Otherwise it reserves for each
  entry of `self.running` whose kind is **not** in `COSTLESS`, plus `work`.
  A running landing or boundary stage adds nothing, and `find_reserve` is
  never called for one. So `roles.resolve("runner")` is never reached.
- **B2. Nothing else changes.** The refusal text, `budget_reserve`'s
  functions and the order of the checks in `can_start` stay as they are.
  `find_reserve` keeps its name and signature. s161 renames
  `budget_reserve.reserve`; whichever story lands second keeps the other's
  name.

## Changes per module

### `agile-team/runner/agile_team/upstream.py`

- `Prs.close` docstring: `"""Close pull request ``pr`` with a comment; one already merged counts as closed."""`
- `GhPrs.close(self, pr: int, note: str) -> None`. Docstring: `"""Close the
  pull request with ``note`` as its comment; a merged one is left as it is
  (P1, P2)."""` Body:
  ```
  code, out = self.run(["gh", "pr", "close", str(pr), "--comment", note])
  if code != 0 and not self._is_merged(pr):
      raise UpstreamError(out.strip())
  ```
- New `GhPrs._is_merged(self, pr: int) -> bool`. Docstring: `"""Whether
  GitHub shows ``pr`` as merged; a failed or unreadable read is False."""`
  Runs `self.run(["gh", "pr", "view", str(pr), "--json", "state"])`
  (not `_gh`, so a failed read doesn't raise). True only when the exit code
  is 0 and the parsed JSON's `"state"` equals `PrState.MERGED`. Output that
  isn't JSON (`json.JSONDecodeError`) or isn't an object counts as False.
  Keep it under 8 lines. A small pure helper is fine, e.g.
  `_state_of(out: str) -> str` returning `""` on bad output.
- No new constants. `PrState` already exists in this module.

### `agile-team/runner/agile_team/scheduler.py`

- `Scheduler.check_budget(self, work: Work) -> str | None`. Same docstring
  and early return. Reserve only over the costly work:
  `reserves = [self.find_reserve(entries, w, floor) for w in self.costly_work(work)]`.
- New `Scheduler.costly_work(self, work: Work) -> list[Work]`. Docstring:
  `"""The running work with a role and a model, then ``work`` (B1)."""`
  Returns `[w for w in (*self.running.values(), work) if w.kind not in COSTLESS]`.
- `COSTLESS`'s line gets no new kinds. A comment on it is fine:
  `# kinds that run as the runner itself: no role, no model, no cost`.

No change to `landing.py`, `story_ci.py`, `boundary_runner.py`, `router.py`
or `roles.py`.

## Test checklist

Put the new tests in `agile-team/runner/tests/test_s166_close_and_budget.py`
(module docstring names s166). Use the fakes the s159 tests already use.
`GhPrs` takes any callable `run(argv) -> (code, out)`, as in
`test_s159_push_safety.py::test_gh_close_comments_on_the_pr_r1`. The
scheduler tests build on `make_runtime` as in `test_s159_scheduler.py`.

AC1 (REQ-174):
- [ ] `GhPrs.close` on a PR whose close fails (`1, "can't be closed because
      it was already merged"`) and whose view returns `{"state": "MERGED"}`
      returns normally. The calls are the close, then the view.
- [ ] The same with any other close message (e.g. `1, "boom"`) and view
      `MERGED` also returns: the state decides, not the text.
- [ ] A failed close with view `{"state": "OPEN"}` (and with `CLOSED`)
      raises `UpstreamError` with the close's stripped output.
- [ ] A failed close whose view fails (`1, "not found"`), or returns
      non-JSON, or a JSON list, raises the close's error, not the view's.
- [ ] A successful close makes exactly one call, the close with `--comment`
      and the note (the existing r1 test stays as it is), and never views.
- [ ] No call is ever `gh pr comment`: a merged PR gets no note.
- [ ] A landing whose story PR GitHub already merged completes. Take the
      landing setup of `test_s159_landing.py::test_the_first_landing_opens_a_draft_sprint_pr_and_closes_the_story_pr_l9`,
      and set `rt.prs.close` to the bound `close` of a `GhPrs` over a fake
      run that fails the close and views `MERGED`. Assert the story is
      recorded as landed (`story.landed` set, report passes), the sprint PR
      was created (`entry.pr` set), and no `UpstreamError` escaped.
- [ ] The superseded story PR close in `story_ci` and the replay's close of
      the old sprint PR go through the same `GhPrs.close`. A unit test on
      `GhPrs.close` covers them; no extra caller tests are needed.

AC2 (REQ-175):
- [ ] With a running `Work("runner", s, "", StepKind.LAND)` in
      `s.running`, `check_budget(work(b))` for a role step returns `None`
      under ample budget and raises nothing. Before the fix this raised
      `RoleError: unknown role 'runner'`.
- [ ] The same with a running `Work("runner", None, "", StepKind.BOUNDARY)`
      under `BOUNDARY_KEY`, for both a story role step and the Manager's
      `Work("manager", None, ...)`.
- [ ] A running landing adds nothing: with budget and reserve chosen so one
      role reserve fits but two don't, a running land plus a new role step
      starts, and a running role step plus a new role step waits
      (`"budget"` in the text).
- [ ] `costly_work` leaves out `LAND` and `BOUNDARY` running work and keeps
      `ROLE`, `TEAM_FIX`, `REBASE_FIX` and `GATE_FIX`, with the new work last.
- [ ] A new costless work still returns `None` at once (existing behaviour).
