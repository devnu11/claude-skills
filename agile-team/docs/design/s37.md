# s37: unattended: no stale `next_wake`, and the reset time from the right text

Story: `.team/stories/s37.md`. Code: `unattended/runner/unattended/` only.
Developer: `developer-cli`.

AC1 (toolchain, scopes, gates, CI, charter) is DevOps work and is already in
`.agile-team.toml`: the two runners share `test`, `coverage`, `lint` and
`static`, and the `unattended/runner/**` globs are in place. The ADR that
records the human's approval and the charter change belong to DevOps, not
this design. AC6 is the PO's hand-off note to the human.

## The two bugs

1. **Stale `next_wake` (AC2).** `Supervisor._mark_waiting` sets `next_wake`,
   and only `_finish` clears it. `_cycle` marks the job `running` and
   `_reconnect` marks it `waiting`, and neither clears it. So after a resume
   and an offline wait, `status` shows the old reset time.
2. **Reset read from the PO's text (AC3, AC4).** For exit 75,
   `command_job._limit` runs `COMMAND_LIMIT_PATTERNS` over the last 50 lines.
   `RESET_NOTE` (`resets <anything>`) takes the last match. agile-team writes
   its halt line to stderr, but the PO's block-buffered stdout is flushed
   after it, so `resets the count) and add AC4b ...` matched last.
   `Waits.after_limit` then found no time and silently used the 5 h
   fallback.

## Rules

- **N1** `next_wake` and `wake_on` are set only by a timed wait (a limit or a
  rate-limit wait). Every other status change clears both. The single place
  for this is `JobState.mark`, which clears both. `_mark_waiting` sets them
  after it calls `mark`.
- **N2** An offline wait has status `waiting`, `next_wake` null and
  `wake_on: "network"`. The resume after it marks `running`, which clears
  both again (N1).
- **R1** For an exit-75 command run, the limit reason comes from the first of
  these sources that gives one (the `REASON_SOURCES` table, in order):
  1. **halt line**: the last line in the tail that matches
     `^agile-team start: (?P<reason>[^\n]+?); run `agile-team start --resume``
     (multiline). The reason is the `reason` group as is, for example
     `session limit, resets 9pm (America/Chicago)`.
  2. **status file**: `<spec.cwd>/.team/run/state.json`, when it parses as a
     JSON object whose `status` is `"blocked"` and whose `status_reason` is a
     non-empty string. The reason is `status_reason` as is. A missing file,
     an unreadable file, bad JSON or the wrong shape gives no reason (no
     error).
  3. **free text**: `find_reason(COMMAND_LIMIT_PATTERNS, text)`, as today but
     with the tightened `RESET_NOTE` (R2).
  4. Otherwise `DEFAULT_LIMIT_REASON`.

  When a source gives a reason, the later ones are not read. So when a halt
  line is present, the PO's text is never read (AC3).
- **R2** `RESET_NOTE` matches only `resets ` followed by a time that
  `RESET_TIME` can read: an optional `Mon D,`/`at` date, then `H[:MM]am|pm`,
  then an optional `(Zone)`. `resets the count`, `resets soon` and
  `resets tomorrow` do not match. Build both from one shared fragment so the
  time grammar is written once (see `limits.py` below).
- **R3** A reason with no time `reset_at` can read is not a stated reset. The
  wait is `now + fallback` with `wake_on: "fallback"` (AC4). A readable
  reset gives `reset + GRACE` with `wake_on: "reset"`. A rate-limit backoff
  gives `wake_on: "backoff"`.
- **S1** `status`, `list` and `wait` report `"wake_on"` (one of `reset`,
  `fallback`, `backoff`, `network`, or null) right after `"next_wake"`. The
  `wait` event carries `"on"` next to `"until"`.
- **L1** A legacy `state.json` with no `wake_on` key loads with `None`.
  A stale `next_wake` in a legacy file is cleared by the next `mark`, which is
  the first thing a re-pinned supervisor does (`_cycle` marks `running`).

Prompt jobs keep `classify` and `LIMIT_PATTERNS` unchanged. Their reasons go
through `Waits.after_limit` too, so R3 reports `fallback` when a reason has
no readable time.

## Changes per module

### `unattended/runner/unattended/limits.py`

```python
class WakeOn(StrEnum):
    """What a waiting job waits for."""
    RESET = "reset"        # the stated reset time plus GRACE
    FALLBACK = "fallback"  # no readable reset: the job's fallback wait
    BACKOFF = "backoff"    # a rate-limit backoff
    NETWORK = "network"    # offline: until the API answers; no wake time

@dataclass(frozen=True)
class Wake:
    """When a timed wait ends (epoch seconds) and why then."""
    at: float
    on: WakeOn
```

- Split the time grammar out of `RESET_TIME`:
  `RESET_CLOCK: str` holds the raw regex from `(?:(?P<month>…` to the
  optional `(?P<zone>…)` group (the current pattern without its leading
  `resets\s+`).
  `RESET_TIME = _pattern(rf"resets\s+{RESET_CLOCK}")` keeps its behaviour.
- `RESET_NOTE = ((_pattern(rf"resets\s+(?P<reset>{RESET_CLOCK})"), "usage limit, resets {reset}"),)`.
  `find_reason` formats with `**groupdict()`, so the extra named groups do no
  harm.
- `Waits.after_limit(self, reason: str, now: float) -> Wake`: returns
  `Wake((at + GRACE).timestamp(), WakeOn.RESET)` when `reset_at` reads a
  time, else `Wake(now + self.fallback, WakeOn.FALLBACK)`. Update the
  docstring.

### `unattended/runner/unattended/store.py`

- Import `WakeOn` from `.limits`.
- `JobState` gains `wake_on: WakeOn | None = None`, placed after `next_wake`.
- `JobState.mark(self, status, reason="")` also sets `next_wake = None` and
  `wake_on = None` (N1). Docstring: "Set the status and why, and clear the
  wake time; a status without a reason clears the old one; a timed wait sets
  its wake after this."
- `from_json` turns a stored `wake_on` string into `WakeOn`, and a missing
  key or null into `None` (L1). Keep `from_json` short: put the conversion in
  a module helper `_wake_on(data: dict[str, Any]) -> WakeOn | None`.

### `unattended/runner/unattended/supervisor.py`

- Import `Wake` and `WakeOn` from `.limits`.
- `wake_after(state, outcome) -> Callable[[float], Wake]`: for a rate limit,
  `lambda now: Wake(now + backoff(state.retries - 1), WakeOn.BACKOFF)`, else
  `Waits(...).after_limit(outcome.reason, now)`.
- `_wait`: `wake = wake_after(state, outcome)(self.clock())`; use `wake.at`
  for `state.progress(...)` and `_sleep_until(...)`; call
  `self._mark_waiting(wake, outcome.reason)`.
- `_mark_waiting(self, wake: Wake, reason: str)`: `st.mark(WAITING, reason)`,
  then `st.next_wake = wake.at` and `st.wake_on = wake.on`. The event is
  `{"until": local(wake.at).isoformat(timespec="seconds"), "on": wake.on}`.
- `_reconnect`: replace the inline `st.mark(...)` lambda with
  `self._mark_offline(reason)`. This new method marks `WAITING` with
  `reason` (which clears `next_wake`, N1), then sets
  `st.wake_on = WakeOn.NETWORK` (N2).
- `_finish`: drop `st.next_wake = None`, because `mark` now does it (DRY).
  `apply` becomes `st.mark(status, reason)`.
- Update the module docstring: an offline wait has no wake time.

### `unattended/runner/unattended/command_job.py`

```python
@dataclass(frozen=True)
class RunOutput:
    """What a finished command left: its output's tail and its working directory."""
    text: str
    cwd: Path

HALT_LINE = re.compile(r"^agile-team start: (?P<reason>[^\n]+?); run `agile-team start --resume`", re.MULTILINE)
STATUS_FILE = Path(".team/run/state.json")
BLOCKED = "blocked"

def halt_reason(output: RunOutput) -> str | None:
    """The reason on agile-team's last halt line in the tail, or None."""

def status_reason(output: RunOutput) -> str | None:
    """agile-team's `status_reason` when its state.json in cwd says `blocked`, or None."""

def text_reason(output: RunOutput) -> str | None:
    """A limit named in free text; `resets` counts only with a readable time."""
    # find_reason(COMMAND_LIMIT_PATTERNS, output.text)

REASON_SOURCES: tuple[Callable[[RunOutput], str | None], ...] = (halt_reason, status_reason, text_reason)

def limit_reason(output: RunOutput) -> str:
    """The first reason a source gives, in `REASON_SOURCES` order, else the default."""
```

- `outcome_for(code: int, output: RunOutput) -> Outcome`. `EXIT_OUTCOMES`
  handlers take a `RunOutput`. `_limit(output)` uses `limit_reason(output)`.
  `_failed(code, output)` reads `output.text`.
- `CommandJob.run_once` returns
  `outcome_for(code, RunOutput(tail(log), Path(state.spec.cwd)))`.
- `status_reason` catches `OSError` and `ValueError` (which covers
  `json.JSONDecodeError`) and treats a non-dict as no reason. Use `.get`, so
  a missing key is not an error.
- Imports: add `json`, `re`; `Callable` is already imported.
- Update the module docstring with the R1 order.
