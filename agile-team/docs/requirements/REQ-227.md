---
id: REQ-227
title: A done the PO sends while a boundary is pending ends the run once the boundary closes, across a re-pin
status: active
covers: ["s184/AC1"]
---

When the PO notifies `done` while a sprint boundary is open, or while a finished
sprint's end boundary has yet to run, the runner holds the done. The run goes on
until the boundary closes and then ends with status `done`. No hand-over follows,
and no `next_sprint` hand-over at all. The held done is kept in the run's state,
so a self re-pin between the end check and the close keeps it. The re-pinned
runner finishes the boundary and then stops `done`. A start that gives the PO a
new task drops a held done. When does the runner refuse a `done`? The same as
before: only while a Sprint Backlog story can move.
