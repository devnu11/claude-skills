---
id: REQ-171
title: The main checkout is locked only while git moves it, and every step that owns it takes the lock
status: active
covers: ["s163/AC5", "s163/AC7"]
---

While a landing waits for CI, the main checkout isn't locked: tells, answers,
story requests, `accept-checkout --story`, storyless steps and PO turns carry
on. The lock is held only while git moves the main checkout (the sprint push,
the fast-forward and recording the checkout), on a resumed landing as on a
first one. Under that lock and just before the sprint push, the runner checks
that the merge's first parent is still the sprint head, and gives up the
merge if it isn't. A storyless step started by the PO's `run_role` takes the
lock, as the scheduler's own steps do.
