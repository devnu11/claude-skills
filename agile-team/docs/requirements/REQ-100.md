---
id: REQ-100
title: A resumed PO session does not count the reconciled spend a second time
status: active
covers: ["s10/AC1"]
---

The PO's session reports a running total that may include the cost of the query a crash
cut off. When a start ledgers that cost from turns.jsonl, the next PO query that resumes
the same session takes the reconciled amount off its own cost, never below zero, so the
same spend is not in the ledger twice.
