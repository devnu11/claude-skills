id: REQ-095
title: The conflict path's data and the DevOps step's scope exist while a sprint-end conflict still holds sync_conflict
status: active
covers: ["s153/AC6"]
---
The boundary's data holds the conflict path: the `rebase-fix` step kind, the
`rebase_conflict` fix case and hold, the DevOps answer (`RebaseFix`) and the
failure's worktree. The state loader reads them back, and an old state file
still loads. A `rebase-fix` step may write only the scratch worktree, and its
git is confined there with no editor. Until s151's second slice, no step of
this kind is ever due: a sprint-end conflict still holds `sync_conflict`.
