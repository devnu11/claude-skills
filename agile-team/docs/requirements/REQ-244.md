---
id: REQ-244
title: A sprint whose pushed head is already in the target closes as shipped, even with bookkeeping commits on top
status: active
covers: ["s188/AC3"]
---

When the target already contains the sprint's pushed head, for example
because the human fast-forwarded main to the sprint PR, the END boundary
closes the sprint as shipped even when bookkeeping commits were made on top
of that head afterwards. The boundary doesn't push those commits, so it
reads CI on the head the PR's checks ran on, and never holds `ci_pending`
for a merged PR's checks.
