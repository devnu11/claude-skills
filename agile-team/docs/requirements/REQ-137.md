---
id: REQ-137
title: A landing's merge passes CI on its own landing branch before the sprint branch moves
status: active
covers: ["s159/AC2.4"]
---

`land` pushes the merge to `<story_prefix><id>-land` and waits for the CI of
that sha. Only this story waits. A head with no check runs at the timeout
is pending, never green.

- **Green:** the sprint branch is pushed and fast-forwarded to the merge.
  The stack entry records it, and a `story-landed` event records both
  parents. The first landing opens the sprint PR as a draft, which is reused
  by its number.
- **Red:** the story goes back to its developer, and the sprint branch is
  untouched.
- **Infrastructure failure:** one re-run, then a `ci_infra` hand-over for
  that story.

The landing branch is deleted afterwards in every case, through a guarded,
leased delete.

A rejected sprint-branch push is never retried. If the remote moved ahead,
the runner fast-forwards to it and lands the story again. Otherwise the run
halts as checkout drift, naming both heads.
