---
id: REQ-107
title: A repo-instructions import that is not UTF-8 text is left out with a note
status: active
covers: ["s144/AC1", "s144/AC2", "s144/AC3"]
---

When the repo's `.claude/CLAUDE.md` imports, with `@path`, a file inside the
repo whose bytes are not valid UTF-8, every role's system prompt has the line
`(left out: @<path> is not UTF-8 text)` in place of the import. Building the
prompt raises no error, and the rest of the file and its other imports are
loaded as before. The files are decoded as UTF-8 on every platform. A test
pins this with a binary file in the repo and shows that a step still runs with
its system prompt built. `reference/protocol.md` ("System prompt order") says
that an import that cannot be read as text is left out with a note.
