id: REQ-036
title: One numbered queue writes tell messages, reorder requests and share requests
status: active
covers: ["s134/AC1", "s134/AC2"]
---

The runner queues three kinds of file in a numbered folder: the human's
`tell` messages (`t<N>.md`), the dashboard's reorder requests (`r<N>.json`)
and the liaison's share requests (`f<N>.json`). All three are written by one
queue: it writes a draft, hard-links it to the first free number, and removes
the draft, so a file appears whole, a number is never reused and no draft is
left. The same queue lists the numbered files in number order. A fix to the
queue is made in one place.

Nothing a user or the team sees changes: the same file names, ids, contents
and order, and the same errors. Each module's existing tests still pass, and
one set of tests checks the queue itself, including that a taken number is
skipped and that no draft is left behind.
