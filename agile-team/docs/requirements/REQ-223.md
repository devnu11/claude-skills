id: REQ-223
title: A boundary held as an error at push-replayed on a shipped sprint closes on continue_boundary
status: active
covers: ["s183/AC2"]
---

A boundary held `error` at `push-replayed` because the target already held
the replayed head closes as shipped when the PO runs `continue_boundary`.
This covers the case where the `-r<k>` branch was pushed but the PR create
was refused. Nobody edits `state.json` by hand. The sprint's merged PR is
recorded as closed and the run marks no PR ready. The next `start_sprint`
then opens its START boundary.
