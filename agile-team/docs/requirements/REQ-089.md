---
id: REQ-089
title: A failing start check holds nothing, and its failing test ids are recorded as the sprint's known failures
status: active
covers: ["s152/AC2.1", "s152/AC2.2"]
---
The sprint start's `check` runs the full checks. When they fail, the start
boundary is not held, no fix step runs and nothing escalates: the sprint
goes on. The failing test ids (or a failed check's name when it has no
test ids) are recorded as known failures on the event that closes the
start boundary, which the sprint start logs.
