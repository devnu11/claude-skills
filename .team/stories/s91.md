# s91: The e2e gate says why a presentation workspace counts as empty

**Folded into s95 (A14c) AC1** (human decision, t33): do not schedule it separately.

**Delivery:** cli (the agile-team runner's e2e gate).

## User story

As the PO, I want the "no presentation" refusal to say what it found in the
workspace, so a workspace that holds only `.git` is told apart from a missing
one and the integration-tester knows what to add.

## Why

s89 and s59 were both refused with "workspace is missing or empty" when
`.team/run/presentation/<id>/workspace` held only `.git` (an empty git repo).
The text hid the cause, and each time it cost a manager ruling and an extra
e2e round.

## Acceptance criteria

1. When the workspace exists but holds only `.git`, the refusal says so
   ("holds only .git") and names a file to add (the demo or evidence file).
2. When the workspace is missing, the refusal says "missing".
3. A test pins each of the two texts.
4. The integration-tester role file says the workspace must hold the demo or
   evidence files themselves, not only an empty repo.
