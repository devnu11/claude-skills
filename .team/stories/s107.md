# s107: Bug: the flaky e2e tests

**Delivery:** cli

## User story

As the team, I want the e2e suite to pass or fail on the code alone, so a red run always means a real bug.

## Acceptance criteria

- **AC1 [cli].** The time-sensitive e2e tests seen failing today pass under load: `test_health_goes_green_amber_red_as_the_step_goes_quiet`, `test_sandboxed_curl_fails_without_local_binding` and the dashboard start in `test_traversal_is_404` (and any like them). They use a fake or monotonic clock, or a readiness wait, and never a fixed sleep or a tight wall-clock bound.
- **AC2 [cli].** No test starts a server without a readiness wait with a timeout. On timeout, the failure message includes the server's output.
- **AC3 [cli].** The runner runs the full suite 5 times in a row with `-n auto`, and all 5 pass. The result is in the handoff, as the runner's own output.
