# s57: Quality pass over the bootstrap code

**Delivery:** agile-team runner (all modules written before the team's process existed).

## User story

As the human, I want the code written while we were bootstrapping brought in line with best practices, so the base the team builds on meets the same rules the team's own code is held to.

## Scope

Roughly everything in the liaison's commits of 2026-10-08 and 2026-10-09: the dashboard mock and fixture script, ledger tokens, events, role layers, the Manager rework. Plus anything the s56 AST check or a house-rules pass flags. If the scope is large, the Architect splits it into small stories by module (open them through the PO) before any code is written.

## Acceptance criteria

1. The Architect lists the bootstrap modules in scope and splits the work into small stories by module if it is large.
2. Each module is checked against the human's rules: SOLID and KISS; DRY but AHA; no boolean parameters or flags; functions under about 8 lines; at most 2 parameters; no code in the global scope; tables over branching; and the repo's `.claude/CLAUDE.md` and team charter.
3. Behaviour stays the same: the existing tests and the snapshot fixture pass unchanged. A test is never weakened to make a refactor pass.
4. Coverage stays at 95%+; ruff check and ruff format clean. Docs change only where behaviour or file names do.

## Origin

2026-10-11, the human: "we were bootstrapping. Probably means we should do a quality pass to improve all that bootstrap code to bring it in line with best practices." Order: after s56.
