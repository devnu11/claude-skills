# s79: E2E tests pass on a CI runner (no git identity, UTC)

Delivery: cli (tests only; no runtime change)

## User story

As the human, I want the e2e tests to pass on any machine, so that CI is green
and PR #14-style reviews are not blocked by tests that depend on my setup.

## Context

Human message t8: CI run 38302118662 fails 4 e2e tests on Python 3.12 and 3.13.
They pass only on the human's machine.

- `tests/e2e/test_service_presentation_e2e.py`:
  `test_trial_starts_the_real_dashboard_probes_it_and_stops_it`,
  `test_a_busy_port_holds_and_is_not_killed`,
  `test_a_stale_service_is_replaced_not_reused` fail with
  `git commit … *** Please tell me who you are`. The CI runner has no global git
  identity.
- `tests/e2e/test_unattended_wake_e2e.py::test_halt_line_reset_wins_over_po_text`
  fails with `assert 'T21:03:00' in '2026-10-13T02:03:00+00:00'`. It depends on
  the machine's time zone; CI runs in UTC.

Priority: ahead of s74. It blocks the merge of PR #14.

## Acceptance criteria

- AC1: The e2e repo setup sets `user.name` and `user.email` in the repo it
  creates and never relies on `~/.gitconfig`. The three service-presentation
  tests pass with no global git identity (run with `HOME` pointing at an empty
  scratch dir and `GIT_CONFIG_GLOBAL=/dev/null`).
- AC2: `test_halt_line_reset_wins_over_po_text` passes in any time zone: it fixes
  the zone inside the test (set `TZ`) or compares instants, not local strings.
  Show it passes under `TZ=UTC` and under another zone.
- AC3: A guard test (or the shared e2e fixture) fails if an e2e test runs `git
  commit` in a repo with no identity set, so the gap cannot return unseen.
- AC4: No test is weakened, skipped or deleted. Coverage stays at 95%+; ruff
  check and ruff format clean.
