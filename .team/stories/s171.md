      `agile-team check` runs the configured `lint`, `static`, `test` and `coverage` commands
      once each, in the repo as it is, and prints one line per gate reading PASS or BOUNCE as
      the pipeline would judge a story ending at that commit; the coverage line also shows the

  - id: AC2
    environment: cli
    text: >-

  - id: AC3

**User story.** As the liaison onboarding a legacy repo, I want to run the gates once before
the team starts and lock the coverage the repo really has, so the team is held to "no new
debt" instead of bouncing every story against a number the repo never met (#54, #59, #60).

**The problem (fact, read at d9495cbf).** `build_config` hard-codes `gates.coverage = 95`
(`onboard.py:117`). `.team/baseline.json` is read once at start (`cli.py:373`,
`gates.load_baseline` `gates.py:457-459`) and used by `required_coverage`
(`gates.py:641-645`, `min(threshold, baseline)`), but nothing in the runner writes it: only
the DevOps prompt in the optional onboarding sprint asks for it (`roles/devops.md:83-88`),
by hand, in a format (`lint_warnings`) the gates don't read. Preflight (`preflight.py:39-41`)
checks a clean tree, the key, executables and providers; it never runs a command. So a 54 %
repo with a 95 % gate starts and bounces every `implement` (#59, #59.1). The bounce reads
"coverage N% is below M%" (`gates.py:717`) and names neither the command nor the baseline
(#59.3).

**Two design answers, the proxy's.** (1) `start` refuses without a baseline rather than
recording one itself: the floor is a number the human should see before it is locked, and it
lands as a reviewable commit; auto-record would run the repo's own commands on a repo nobody
has approved yet. The exception is `start --onboard`, else a repo with a broken `coverage`
command can never get a baseline (AC5). (2) The command is `agile-team check`, not `config
check --run`: `config` means "validate the file", and `check` matches what the scan looks
for (`npm run check`, `make check`). Both are the proxy's calls on 2026-10-23 and the human
can reverse them.

**Lands first: the #60.1 artifact redirect.** AC2 depends on the commands' artifacts
(`.coverage`, `htmlcov/`) going to `.team/run/`. That is #60.1, a liaison fix with no story
id, which lands before this story is pulled; it is not in `depends_on` for that reason.

**Shape (from the plan).** A `check` entry in `cli.COMMANDS`; a dry run reusing
`gates.Checks` with the same `shell_runner` as `make_pipeline` (`cli.py:371-378`); a
baseline writer for `{"sha": "<head>", "coverage": <total>}`; the preflight rule. The
onboarding sprint keeps fixing broken commands, and `roles/devops.md:83-88` stops asking
DevOps to write the file by hand. Lint and static debt counts (the plan's story D) are not
here: they overlap s36 and wait on the human's runner-vs-scripts answer. s35 compares against
the story's base commit and does not read this file; s36 AC1/AC6 (DevOps scripts recording
baselines, `init` creating them) overlap AC3's coverage baseline, so filing C narrows s36 to
lint/static and uncovered lines. That amendment to s36 is the human's call; it is not made
here.

**Placement:** Product Backlog, `--approved-by none`; not for sprint 51. After the #60.1
fix. Closes #59.1 and #59.3. Independent of stories A and B; overlaps s36 AC6 as noted above. It touches `cli.py`,
`gates.py`, `preflight.py`, `roles/devops.md` and `SKILL.md`.

([review](../reports/2026-10-23-review-onboarding-stories.md)); the two design
