# s60: The Customer Proxy can reach the delivery's local service on Linux

**Delivery:** agile-team runner (sandbox settings, e2e gate).

## User story

As a user on a Linux host, I want the Customer Proxy to reach the delivery's local service from inside its sandbox, so stories are judged on the product and not bounced for "connection refused" (as on macOS before s58).

## Acceptance criteria

1. Find out how the Linux sandbox (bubblewrap) isolates the network, and whether `network.allowLocalBinding` (documented for macOS only) has any effect there. Record the finding in the design.
2. If the Proxy cannot curl a local service on Linux, the sandbox section or the way the service is started is changed so it can. The change is table-driven by platform, not a branch scattered through the code.
3. An e2e test curls a live local service from inside the Proxy sandbox on Linux and gets 200, skipped with a stated reason on platforms where the OS sandbox cannot run. A unit test pins the Linux section.
4. Docs move with behaviour (`agile-team/SKILL.md`, `agile-team/reference/protocol.md`).

## Origin

2026-10-11, the architect on s58: Linux hosts are not verified; bubblewrap isolates the network and `allowLocalBinding` is documented for macOS only. The PO's answer: s58 stays macOS-verified and states the limit in its docs; Linux is this follow-up. Priority: backlog; the human's machine is macOS, so this is not urgent.
