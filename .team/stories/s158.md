**User story.** As the human, I want the runner to re-pin itself at a sprint end and carry on in the same run, so the next sprint runs on the code this sprint delivered without a liaison stop.

**What happened (sprint 45, 2026-10-15).**
1. The end boundary's check passed, and the runner started its self re-pin to 5cf89f3 (s128).
2. The new pin's config check ran as `agile-team config check --repo <repo>`. The CLI takes `--repo` and `--home` only before the subcommand (`cli.GLOBAL_ARGS`), so it exited 2 with "unrecognized arguments".
3. The runner rolled back, then exec'd the old pin with `start --resume --repo <repo>`, which has the same fault. The run exited 2, and the unattended job ended `failed`.
4. The liaison re-pinned by hand to 5cf89f3 and resumed.

`repin._check_argv` and `repin.start_argv` both build the arguments this way, and no other builder in the runner does (fact, from a cross-check). The config check also passes no `--home`. `test_s128_repin` asserts the same order against a fake exec, so the fault never showed in a test.

**Note for the sprint this lands in:** that sprint's own end still runs the old code, so it will roll back once more. The liaison re-pins by hand that one last time.

ACs written by the liaison and cross-checked by Fable. The human approved the story and its placement, not the AC text.
