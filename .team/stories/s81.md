# s81: The boundary is done only when the PR's CI is green (or a bug story is opened)

Delivery: cli (runner boundary)

## User story

As the human, I want the sprint-end boundary to wait for the pull request's CI
checks and never report a red PR as ready, so that other agents building on
main never inherit a failing build.

## Context

Human message t11. PR #14 (sprint 21) passed the team's own boundary check but
failed CI on four e2e tests that pass only on the human's machine (s79). Related
to s29 (boundary steps) and s80 (review branch built at the boundary). Runs
after s80.

## Acceptance criteria

- AC1: After the review branch is pushed and the PR opened or updated, the
  boundary waits for the PR's CI checks (`gh pr checks <n> --watch`) under a
  timeout (config `[gates]`, with a default) and records the result in state
  and in an event: per-check name, conclusion, and for failures the job name
  and failing test lines.
- AC2: Green: the boundary completes and a hand-over tells the PO the PR is
  "ready to merge"; the PO passes that to the human.
- AC3: Red: a new hand-over gives the PO the failing checks with job names and
  failing test lines. The PO opens a bug story at once, first in the next
  sprint, and tells the human the PR is **not** ready.
- AC4: Enforced in code: the boundary reaches `done` only with green checks or
  with an explicit recorded outcome "checks failed, story sN opened". The PO
  cannot finish the boundary on its word: until a bug story id is recorded
  (and exists in the story list), the boundary stays held.
- AC5: A red or unfinished PR is never reported as ready: the "ready" wording
  is produced only from a recorded green result. A timeout counts as not ready
  and holds the boundary with the existing boundary hand-over, naming the
  pending checks.
- AC6: When push permission is "no", or `gh` is missing or unauthenticated,
  there is no PR to watch: the boundary behaves as today and says no CI result
  exists (never "ready").
- AC7: Tests on fakes cover: green, red with failing lines, timeout, no PR, and
  the hold until a bug story is recorded. The `gh` call goes through the
  `system` seam (s71) and is faked in unit tests; one e2e test covers the real
  call path with a stub `gh` on PATH. Never touch the real home directory.
- AC8: Docs move with behaviour (`agile-team/SKILL.md`,
  `agile-team/reference/protocol.md`, the boundary hand-over table). Coverage
  95%+; ruff check and format clean.
