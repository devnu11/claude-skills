# s67: `agile-team watch` on a first run treats the current outbox as already seen

**Delivery:** cli (the agile-team runner's `watch` command, `watch.py`).

## User story

As the liaison watching a run, I want my first `agile-team watch` to record the
outbox and status as they stand now and then wait for something new, so that I
am not woken for the whole history I have already seen.

## Why

With no `.team/run/liaison/watch.json` yet, `watch` reports the whole outbox
history (m1 onward) as new. A first run has no earlier position to compare
with, so everything counts as a change.

## Acceptance criteria

1. With no `watch.json`, the first `watch` records the current outbox position
   and status as already seen, writes `watch.json`, and then waits like a
   normal run. It does not report existing messages as new.
2. A message that arrives after that first record is reported as new, with the
   same JSON line as today.
3. Runs with an existing `watch.json` behave as before, and a `watch.json`
   that is unreadable is handled as it is today.
4. An end-to-end test in a scratch repo (never the real home directory) shows
   a first `watch` with a populated outbox waits instead of reporting
   history, then reports a message added afterwards.
5. `SKILL.md`'s command line for `watch` and `reference/protocol.md` say what
   a first run does, in the same story. Do not edit the liaison section of
   `SKILL.md`'s rules or the `.team/run/liaison/` layout text: the liaison
   edits those with the human.
6. Coverage 95%+; ruff check and format clean.

## Scheduling

Schedule after s44, which also changes `watch.py` (health trigger and field).
It touches the same file, so do not run it in parallel with s44.

## Origin

Human message t1, through the liaison.
