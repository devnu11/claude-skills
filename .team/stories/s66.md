# s66: Process-group guard follow-ups (s41 design review round 2)

**Delivery:** cli (the agile-team runner's process-group code and Bash guard).

## User story

As the human running the team, I want the process-group safety code covered by
tests and hardened against bad input, and role Bash denied from signalling its
own parent, so that a role can never kill the agent CLI that runs it.

## Why

The s41 design review (round 2) found the code matches G1–G6 and K1–K5 and
listed three follow-ups outside s41's ACs. See
`agile-team/docs/design/s41.md` § "Design review (round 2)".

## Acceptance criteria

1. A test makes `os.getpgid` raise `PermissionError`; `may_signal_child_group`
   returns `False` and nothing is signalled. `process_groups.py` is back to 100%
   coverage.
2. `leads_own_group` catches `OverflowError` as well as `OSError`, as
   `in_runner_group` does. A test with a pid file holding `99999999999999999999`
   shows `stop_stale` sends nothing and deletes the file.
3. The Bash guard (K4) denies a signal command whose target is `$PPID` or
   `${PPID}`, with a reason that says why (in role Bash it is the agent CLI). A
   test pins the denial and the reason; targets that are ordinary pids are
   unchanged.
4. The rule is a table entry, not a new branch per case.
5. `SKILL.md` and `reference/protocol.md` mention the new deny in the same story.
6. Coverage 95%+; ruff check and format clean.

## Origin

Architect question on s41 (round 2): open a follow-up story for the three items;
item 3 is a new guard rule.
