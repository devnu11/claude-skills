  - id: AC1
    text: "`agile-team story new <file.md> [--sprint current|next|backlog] [--after sN] --approved-by human|none`: reads a story file (frontmatter `title`, `acceptance` with `id`/`text`/`environment`, optional `depends_on`, and the user story as the body); validates it with `story_spec`, plus a check that each `environment` is configured. A bad file is refused with every reason, and nothing is written."
    environment: cli
  - id: AC2
    text: "On success it: assigns the next id and writes `.team/stories/sN.md` in one commit with the subject `docs(sN): created story to <title>`; opens the story in state and places it per `--sprint` and `--after`, through the same code `add_to_sprint` and `prioritise` use; sends the PO a `story-opened` hand-over."
    environment: cli
  - id: AC3
    text: "Authorship: with `--approved-by none`, the commit's author is the liaison; with `--approved-by human`, the author is the repo's git user; either way, the body has a `Human-involvement:` line saying what the human did (\"approved plan <path>\", or \"none: written and submitted by the liaison\")."
    environment: cli
  - id: AC4
    text: "`agile-team story amend sN <file.md> --approved-by …` replaces an open story's ACs through the same validation. The story goes back to design (a changed AC always returns to design), with a `story-amended` event holding the old and new ACs."
    environment: cli
  - id: AC5
    text: "The PO no longer writes stories: `Write` and `Edit` on `.team/stories/**` leave its scope, and the guard refuses them; `open_story` is removed; a new PO tool, `request_story(summary, evidence)`, sends the liaison a `story-request` message with the story, step, failing output and files. This covers bugs the team found but couldn't fix in its turns."
    environment: cli
  - id: AC6
    text: "Tests pin: a valid file; each refusal; placement; both authorship modes; an amend going back to design; the PO's scope refusing a story file; `request_story` reaching the liaison."
    environment: cli

each story and its ACs through a command that validates them, so stories reach
the team exactly as agreed, and the PO schedules instead of rewriting.
