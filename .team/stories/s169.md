**User story.** As the liaison onboarding a legacy repo, I want `init --detect` to read the
repo and propose a config that says where each value came from, so the human approves real
commands and globs instead of a preset's guess (#54).

**The problem (fact, read at d9495cbf).** `onboard.detect` (`onboard.py:56-61`) returns the
first preset in `presets.toml` with a marker file, so a repo with `pyproject.toml` and
`package.json` is reported as Python only. `cli.detection` (`cli.py:194-205`) prints that
preset's `commands` and `globs` verbatim; the globs are the preset's (`presets.toml:34`
`src/**`, `:54` `src/**, lib/**`), whatever the repo's layout. Nothing reads a manifest, a
`Makefile`, a `tox.ini` or an existing `check` script, so a repo with a working `npm run check`
is offered `npx eslint .` and `npx tsc --noEmit` (`presets.toml:50-51`). With no marker,
`detection` returns `{"preset": null, "known": [...]}` and no proposal. The legacy repo in #54
is the motivating case: the scan has to yield something to edit, on any layout.

**Shape (from the plan, `plans/onboarding-scan-54.md`).** The scan is data-driven: per-stack
`manifests` and `aggregate_checks` tables in `presets.toml`, validated on load like today's
`[files]`, and `onboard.scan` evaluating them while keeping evidence. The scan runs nothing
and writes nothing; writing is story B, and running the commands is story C. The output stays
a JSON document that B's `init --from-scan` can consume. A mixed repo's per-stack
`[[toolchain.files]]` for the Stop hook is #55.1 and stays out.

**Placement:** Product Backlog, `--approved-by none`; not for sprint 51. No dependency.
Story B (`init` writes what the scan proposed) follows it. It touches `onboard.py`, `cli.py`
(`cmd_detect`, `detection`) and `presets.toml`.
