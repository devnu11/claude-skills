  - id: AC1
    text: >-
      The runner records the in-flight role step (role, story, brief) in `state.json`
      when the step starts and clears it when the step settles. This way an interrupted
      step is known after a crash or kill.
  - id: AC2
    text: >-
      When a role step is interrupted by an exception or SIGTERM (s8's handling), the
      runner saves the step's uncommitted changes before it exits, so the tree is clean.
      They go either into a commit that is reverted at once (like quarantine; e.g.
      `chore(team): interrupted step by <role> on <story>`) or into a named stash; the
      architect picks one. The sha or stash name is stored in state and included in the
      liaison note.
  - id: AC3
    text: >-
      If the runner was killed outright (state says `running`, and `runner.pid` is
      missing or names a dead process), `start --resume` saves the leftover changes the
      same way, instead of preflight refusing the dirty tree. A dirty tree with no
      interrupted run behind it is still refused, as today.
  - id: AC4
    text: >-
      On resume, the PO's resume prompt names the interrupted step (role, story, brief)
      and the saved sha or stash, so the PO can re-run the step and tell the role how to

      allowed to run).
  - id: AC5
    text: >-

      cleaned up. The dashboard snapshot uses the same rule.

## User story

As the human, I want a crash or a kill mid-step to leave the run in a state
that `start --resume` can pick up, without me stashing files by hand or
wondering whether the team is still running.

## Notes

Observed in the last run: developer-cli on s7 was cut off mid-step. Its edits
(docstrings in guard.py and sandbox.py) stayed uncommitted, `start --resume`
refused the dirty tree, the liaison stashed them by hand (stash@{0}), and
`status` still said `running` with no process.

Human's decision (m3): keep the edits, either as a commit that is reverted at
once (quarantine-style) or as a named stash. Roles' Bash may only run
`git cherry-pick -n`, not `git stash`, so a commit is easier for a role to
reuse. Stash only if the architect has a reason.

Depends on s8 (top-level exception and SIGTERM handling).
