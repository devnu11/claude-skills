    environment: cli
  - id: AC1.4
    text: >-

    environment: cli
  - id: AC2.1
    text: >-
      The PO tool `pick_commits(commits, reason)` asks for a pick of a commit or range

    environment: cli
  - id: AC3.1
    text: >-
      `accept_pick(request)` accepts a request.
    environment: cli
  - id: AC3.2
    text: >-
      `deny_pick(request, reason)` denies it, for any reason: a `pick-denied` event is
      recorded; the reason goes to the liaison and the human; the branch doesn't
      change.
    environment: cli
  - id: AC3.3
    text: >-
      A request the PO hasn't answered stays pending, and shows in `agile-team
      status` and on the dashboard.
    environment: cli
  - id: AC4.1
    text: >-
      `agile-team pick … --force` skips the PO's decision.
    environment: cli
  - id: AC4.2
    text: >-
      `--force` needs a typed confirmation on an interactive terminal: the command
      prints the commits, their subjects and the team branch, and asks the human to
      type the first commit's short sha; with no TTY, or a wrong answer, it refuses
      and nothing is queued. This guards against forcing the wrong commit by mistake.
    environment: cli
  - id: AC4.3
    text: >-
      When a forced pick is applied, the PO is notified with a `pick-forced`
      hand-over: the commits, the reason and the new shas.
    environment: cli
  - id: AC5.1
    text: >-
      At the next safe point between steps, the runner `git cherry-pick -x`s each
      commit of an accepted or forced pick, oldest first. Each is its own commit in
      the team's chain, and no existing hash is rewritten.
    environment: cli
  - id: AC5.2
    text: >-
      It records a `main-pick` event (renamed `pick` event) with: the commits and the
      new shas; the reason and who asked; how it was decided: accepted, forced, or the
      PO's own request; each source commit's state, on `<remote>/<branch>` or not
      yet.
    environment: cli
  - id: AC5.3
    text: >-
      On a conflict in any commit, the whole pick is aborted, the branch is left
      unchanged, and the files are reported to the PO, the liaison and the human.
    environment: cli
  - id: AC6.1
    text: >-
      `revert_pick(pick, reason)` reverts an accepted pick, or the PO's own pick: one
      revert commit, recorded with an event, and reported to the liaison and the

    environment: cli
  - id: AC6.2
    text: >-
      `revert_pick` refuses a forced pick.
    environment: cli
  - id: AC6.3
    text: >-

    environment: cli
  - id: AC7.1
    text: >-

Scope: the agile-team runner (CLI, PO tools, hand-overs, sprint git flow, step gates), the PO role file, docs.

## User story

As the human, I want a commit the team needs now (from main, or from an open PR) cherry-picked into the team branch mid-sprint, with the PO able to decline it and only me able to force it, so the team gets it without a merge or a hash rewrite.
