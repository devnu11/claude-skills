title: The PO can bring one commit from main into the running sprint (cherry-pick)
acceptance:
  - id: AC1
    text: >-
      Two ways to ask, the same rules for both. (1) `agile-team pick <commit>
      --reason "<text>"`, a CLI for the human and the liaison. It validates and
      queues the pick (the same queue pattern as `tell`). The PO can't veto or
      reorder it. (2) The PO tool `pick_from_main(commit, reason)`, for a need the
      team finds itself. In both cases, the runner refuses (with a reason, and
      nothing changes): a commit that isn't on `<remote>/<branch>` after a fresh
      fetch; a merge commit; a commit whose patch is already on the team branch.
    environment: cli
  - id: AC2
    text: >-
      At the next safe point between steps, the runner runs `git cherry-pick -x
      <commit>` on the team branch, as its own commit in the team's chain. No
      existing hash is rewritten. It records the commit, with a `main-pick` event
      naming the commit, the reason and the new sha. On a conflict it aborts, leaves
      the branch unchanged, and tells the PO and the liaison which files conflicted.
    environment: cli
  - id: AC3
    text: >-
      The sprint-end rebase drops the picked commit as already upstream, and the
      review branches don't carry it twice. A test pins this.
    environment: cli
  - id: AC4
    text: >-
      The PO is told after a pick is applied, with a `main-pick` hand-over, so it can
      plan around it, but it isn't asked first. The PO's role file says what the
      tool is for: a fix or rule already on main that the team needs now, never
      whole sprints of work. A test pins that a liaison pick is applied with no PO
      turn in between.
    environment: cli
  - id: AC5
    text: >-
      Tests pin: a pick at a safe point; each refusal; a conflict leaving the branch
      unchanged; the event; the rebase dropping the pick; a CLI pick applied with no PO turn.
    environment: cli
  - id: AC6
    text: >-
      `SKILL.md`, `reference/protocol.md` ("Sprint boundaries", mid-sprint) and the
      README row describe it. Mid-sprint, main reaches the team only by these picks.
    environment: cli

Scope: the agile-team runner (PO tools, sprint boundary git flow), the PO role file, docs.

## User story

As the human, I want a needed fix that lands on main mid-sprint (a test fix, a rule in the charter) to reach the team branch at once as a cherry-pick, so the team works with it without a merge or a hash rewrite.
