---
id: s11
title: Send a story from implement back to tests when a test contradicts the design
delivery: cli
acceptance:
  - id: AC1
    text: >-
      A developer at the implement step can hand off with a status (or a field) that
      says a named test contradicts the design. The runner then moves the story back
      to `tests` instead of bouncing it to `implement`. The handoff must name the
      test id and the design rule it contradicts; without them it is refused as a
      malformed handoff.
  - id: AC2
    text: >-
      That move does not count a round against the developer. It is logged as its
      own event kind (e.g. `test-dispute`), so the Manager and the dashboard can see
      it.
  - id: AC3
    text: >-
      At `tests`, the unit-tester gets the dispute (test id, rule, developer's
      reason) in its brief. It either fixes the test, or confirms the test and sends
      it to the architect. The tests gate in that case requires only that the
      disputed test changed or was confirmed, since the other tests may already pass
      against the existing implementation.
  - id: AC4
    text: >-
      The Manager's `revise_design` (and any other ruling) works at any step, not
      only at the round cap. If a ruling cannot apply to the story's current state,
      the runner says so in the report instead of silently leaving the story where
      it was.
  - id: AC5
    text: >-
      `reference/protocol.md` (pipeline and gates, handoff) and SKILL.md describe the
      new route. Tests cover the route, the round count, the refusal of an
      incomplete dispute and the ruling behaviour. Coverage stays at or above 95%,
      and ruff check and ruff format are clean.
---

## User story

As the human running the team, I want a developer who finds a test that
contradicts the design to be able to send the story back to the unit-tester,
so that a one-line slip in a test table doesn't stall the story or need me to
edit the repo by hand.
