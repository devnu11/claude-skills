title: "A story's tests are pending until its implement gate passes"
depends_on: [s118]
acceptance:
  - id: AC1
    text: "Structured results. Every test run the runner makes writes a structured report, JUnit XML. The toolchain preset gives the option: for python, `--junitxml={report}`, which works with xdist. The runner reads results per test id from the report, never from the text output. The gate's text summary can still be shown to roles."
    environment: cli
  - id: AC2
    text: "Pending comes from the red run. When a story's tests step passes, the runner takes the pending set from that red run's report: the test ids that **failed** and are **new or changed in the tests step's commit** (from its diff). It writes them to `.team/pending-tests.json` (`{story: [test ids]}`) in the step's commit. A failing test that isn't in the step's diff isn't pending: it's a real failure and fails the gate. Only the runner writes the file."
    environment: cli
  - id: AC3
    text: "Leaving pending. At the story's implement gate, the runner reads the report. When every pending id of the story **passed**, they're removed from the registry in the gate's commit. If any still fail, the gate fails and names them. Full runs skip pending ids (the preset gives the option: for python, `--deselect <id>` per id), and count them as \"pending (sN)\" from the report."
    environment: cli
  - id: AC4
    text: "Refactor stays inside the gate. After green, rework steps of the same story (review, quality) keep its tests enabled (it's no longer pending), and any later failure in them fails as usual."
    environment: cli
  - id: AC5
    text: "CI agrees. GitHub CI skips the same files, reading the same registry (DevOps owns the workflow and the hook), so a review PR with a story mid-pipeline is green. The registry is part of the PR."
    environment: cli
  - id: AC6
    text: "The running test tool's caption (s118) shows pending files as a \"Pending\" count, hidden when 0."
    environment: dashboard
  - id: AC7
    text: "Tests pin: adding at the tests step and removing at the implement gate; a boundary run skipping pending files but failing on another red test; a named run executing them; the implement gate enabling only its own story's tests; a hand edit to the registry refused; the registry built from a JUnit report (new failing ids only); an old failing test not made pending; the ids removed only when all pass in the report."
    environment: cli
  - id: AC8
    text: "The docs and the unit-tester's and developers' role files explain pending tests. The rule \"no `skip`/`xfail` by agents\" stays: only the runner's registry skips."
    environment: cli
---

As the team, I want a story's new tests to be red only inside that story's developer cycle, so full runs, boundaries and CI stay green while test-first work is in progress.
