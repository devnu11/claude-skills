acceptance:
  - id: AC1
    text: "The registry. When a story's tests step passes (its new tests proven red), the runner adds those test files to a committed registry, `.team/pending-tests.json` (`{story: [paths]}`), in the step's commit. When the story's implement gate passes, the runner removes them in the gate's commit. Only the runner writes the file: a hand edit is refused at the next gate, with the diff named."
    environment: cli
  - id: AC2
    text: "Full runs skip pending tests. Every full-suite run the runner makes skips the files in the registry: boundary checks, and the implement gate of *another* story. Skipped files are named in the run's event and counted as \"pending (sN)\". Any other failure still fails. The toolchain preset says how a skip is passed. For python: `--ignore=<file>` per file, or a `conftest.py` hook that reads the registry (DevOps chooses, AC5)."
    environment: cli
  - id: AC3
    text: "The developer cycle runs them. The story's own red check, the developer's `run_tests`, and the story's own implement gate run its pending tests: named runs aren't skipped. The implement gate runs the full suite with *this* story's tests enabled, and passes only when they're green."
    environment: cli
  - id: AC4
    text: "Refactor stays inside the gate. After green, rework steps of the same story (review, quality) keep its tests enabled (it's no longer pending), and any later failure in them fails as usual."
    environment: cli
  - id: AC5
    text: "CI agrees. GitHub CI skips the same files, reading the same registry (DevOps owns the workflow and the hook), so a review PR with a story mid-pipeline is green. The registry is part of the PR."
    environment: cli
  - id: AC6
    text: "The running test tool's caption (s118) shows pending files as a \"Pending\" count, hidden when 0."
    environment: dashboard
  - id: AC7
    text: "Tests pin: adding at the tests step and removing at the implement gate; a boundary run skipping pending files but failing on another red test; a named run executing them; the implement gate enabling only its own story's tests; a hand edit to the registry refused."
    environment: cli
  - id: AC8
    text: "The docs and the unit-tester's and developers' role files explain pending tests. The rule \"no `skip`/`xfail` by agents\" stays: only the runner's registry skips."
    environment: cli

As the team, I want a story's new tests to be red only inside that story's developer cycle, so full runs, boundaries and CI stay green while test-first work is in progress.
