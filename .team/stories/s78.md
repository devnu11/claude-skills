# s78: Health check gives false reds while work is running

**Delivery:** cli (the runner's health check and heartbeat; the dashboard shows it, `agile-team watch` reads it).

## User story

As the human watching a run, I want health to be red only when the run is
really stuck or dead, so that a red alert means something and the planned
leadership alerts can trust it.

## Bug report (human, via the liaison, t6)

Health is wrong in two cases (s44's accepted health check):

- **13:00–13:04:** the code reviewer was working on s71 and made tool calls
  every few seconds. `agile-team watch` reported red, "heartbeat 4 min old".
- **12:42:** during the runner's implement gate on s71, health went red,
  "heartbeat 1 min old".
- **12:47–12:58:** the Mac slept; red was correct then and must stay red.

## Acceptance criteria

1. **Tool calls count as activity.** While a role makes tool calls, the heartbeat
   is fresh. It is not refreshed only when a turn ends.
2. **Gate and boundary runs count as runner activity.** While the runner runs a
   gate command or a boundary step, health is not red: it is green or amber, and
   the reason says what the runner is doing (for example "runner: gate").
   A gate that exceeds its own timeout (`command_timeout_s`) stays handled by the
   gate, not by health.
3. **Real stalls stay red.** A runner that is dead, or alive with no activity of
   any kind past the red threshold (a sleeping Mac included), is still red with
   its reason. A test pins each of: tool-call activity, gate activity, sleep/dead.
4. `agile-team watch` and the dashboard show the same state (one source).
5. Docs move with behaviour (`reference/protocol.md` and the health section of
   the dashboard docs); coverage 95%+; ruff check and format clean.
