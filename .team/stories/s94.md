# s94 (A14b): every AC names its acceptance environment

**Delivery:** cli (the runner can't read per-AC environments until this story ships; the [tag] on each AC below is its environment).

Plan: `.team/run/liaison/plans/acceptance-environments.md` (human-approved 2026-10-13).
## User story

As the human, I want each acceptance criterion to say where the customer tries it, so a story that touches the CLI and the dashboard is checked in both.

## Acceptance criteria

- **AC1 [cli].** The runner reads a story's frontmatter: `id`, `title` and `acceptance: [{id, text, environment}]`.
  - Every AC must have a unique `id`, non-empty `text`, and an `environment` that names a configured environment.
  - A missing or unknown environment, a duplicate or missing id, or bad YAML is refused. The refusal names the file, the AC id and the problem.
  - The parsing is pure code in one module, with tests per refusal.
- **AC2 [cli]. The story file is read when the story starts and before acceptance.**
  - `open_story` reads `.team/stories/<id>.md` and refuses with AC1's reasons, so the PO writes the file first.
  - The runner reads the file again before acceptance. If the PO has edited it since, the new file is used.
  - `StoryState.delivery` goes. A story's environments are the distinct `environment` values of its ACs, in config order.
- **AC3 [cli]. Fixing an environment is an edit to the story file.**
  - The PO fixes a wrong environment by editing the story file. No state edit and no new tool are needed.
  - A story whose file fails AC1 at acceptance is held, and the hold names the file and the AC. The PO gets it as a hand-over, not a runner fault.
- **AC4 [review]. Migration.**
  - The 15 prose story files are converted to frontmatter, with an `environment` on every AC.
  - The 27 frontmatter files get an `environment` per AC.
  - A test loads every story file in `.team/stories/` that isn't done and expects no refusals.
  - The PO does the conversion; the Architect reviews the environment choices.
- **AC5 [review].** The PO role file and `reference/protocol.md` give the story file format with one example that has two environments.
