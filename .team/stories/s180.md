**User story.** As the human, I want a landing that is green and waiting on CI to land, so
that the runner's own bookkeeping commits don't cost the sprint another merge, another full
check and another CI run per waiting story.

**What happened (2026-10-20, sprint 51).** s165's landing merge ba111728 was pushed and
green on `team/story-s165-land`. The liaison re-sent s161's amendment as q20; the runner
committed the story file on the sprint branch (50ea583b), which moved the sprint head, and
s165's landing was dropped ("sprint head moved") and had to merge, check and run CI again
(`decisions.md:530-532`). Earlier the same day the same thing followed the DevOps storyless
config commits made for s161 (`decisions.md:528-531`). With parallel stories every such
commit costs each waiting landing a full round.

**Cause (fact, read at 0e1e0991).** `story_intake._commit` writes the story file in the main
checkout and commits it there (`story_intake.py:151-157`), then calls `record_checkout`
(`story_intake.py:200`, `:304`). `record_checkout` records the main checkout's HEAD and
`_follow_sprint_head` sets the sprint stack entry's `head` to it (`record_checkout`
`dispatch.py:1405-1412`, `_follow_sprint_head` `:1414`).
A storyless step's commit takes the same path (`commit_step` `dispatch.py:1727-1731`, then
`record_checkout` from `settle_tree` at `:1664`). The lander compares a pushed landing's first parent with `sprint_head`, which
is the entry's head (`landing.py:166-184`, `:208-211`); on a mismatch `give_up` clears
`landed`, deletes the landing branch and emits `landing dropped` (`landing.py:186-198`), and
the story merges afresh (`run_attempts`, `landing.py:238-247`). s163 AC3 made the "first
parent is still the sprint head" rule deliberately; it did not foresee the runner's own data
commits moving the head.

**Placement:** Product Backlog. It touches `landing.py`, `story_intake.py` and
`dispatch.record_checkout`. It is independent of the refused-push follow-up
(`gap-refused-sprint-push-story.md`), which changes `follow_remote` only; the two can share
a sprint if one team takes both. Design note: AC1 and AC2 imply the runner's bookkeeping
commit is deferred until the waiting landing completes, or lands on top of it, so `story
new`'s printed commit sha and the PO tool's ack change meaning while a landing waits on CI;
the architect decides between deferring the commit and re-parenting the landing.
