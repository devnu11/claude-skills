---
id: s30
title: The test-dispute gate's "test file unchanged" check uses a stale baseline and rejects real fixes
delivery: cli
acceptance:
  - id: AC1
    text: >-
      When a dispute (s11) is open and the unit-tester has changed the disputed test
      file since the dispute was raised, the "test file unchanged" check sees the
      change and passes. Today it compares against a stale baseline, so it bounced s23
      three times with "test file unchanged", even after edits to that file (the
      corrected tests were already in the tree as commit 3522ae6 and the suite was
      green).
  - id: AC2
    text: >-
      The baseline is the file's content (a hash) at the moment the dispute was
      raised, stored with the dispute in state. The check compares the file's current
      content with it, not with `HEAD` or the previous step's commit. A cosmetic edit
      (whitespace or comments only) does not count as a change; a change to an
      assertion, a parameter row or a test name does.
  - id: AC3
    text: >-
      When the check fails, the reason names the disputed test id, the file and the
      baseline hash, so the role bounced to can see what it must change. A repeat of
      the same failure escalates (s27); it never reaches the round cap by itself.
  - id: AC4
    text: >-
      A story stuck by this fault can be advanced by the PO (not only by editing
      state.json by hand): a Manager ruling or a PO tool moves it from `tests` to
      `implement` when the suite is green and the disputed test has been corrected.
      This covers the s24 cases too.
  - id: AC5
    text: >-
      `reference/protocol.md` (disputes) is updated. Tests cover a real change, a
      cosmetic change, no change, a baseline taken at the dispute and the failure
      reason. Coverage stays at or above 95%, and ruff check and ruff format are
      clean.
---

## User story

As the human, I want a corrected disputed test to count as corrected, so that a
story with a green suite is not bounced three times and stranded at the tests
step.

## Notes

Seen in sprint 10. The Manager found that s23 hit the round cap at tests as a
runner fault. The tests were corrected in round 0 (commit 3522ae6 holds the
corrected tests), the suite was green, and the dispute gate still said "test file
unchanged" three times. The human advanced s23 to implement by hand, as for s19.
Related: s11 (disputes), s24 (tests gate with code from an earlier pass), s27
(repeat escalation).
