## User story

As the human, I want to know why the runner and the liaison's dashboard were killed with no traceback, so it does not happen again.

## Cause found (liaison, 2026-10-11)

At 12:20 CDT and again minutes later, during s21's implement and e2e steps, a role ran `pkill -f` with a pattern matching the agile-team dashboard command, to clean up its own test dashboard. `pkill -f` matches every process whose command line fits, so it killed the liaison's dashboard twice (exit 144) and one of the liaison's own shell commands. The 07:30 death during s9 fits the same cause. The 01:13 SIGTERM of s29's developer CLI may be another pattern kill or the sandbox group kill; check that step's transcript. Near miss: the runner was started with the whole liaison message in its command line, which often names the dashboard command, so the same pkill could have killed the runner. The liaison now passes a pointer to `.team/run/liaison/msg-<time>.md` instead.

## Human tightening 2026-10-11

Killing by name or pattern is never acceptable; the human may be running anything in parallel; it has killed the liaison's dashboard four times today. AC8 to AC10 above come from this.
