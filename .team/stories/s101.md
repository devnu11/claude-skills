# s101 (A6d): a step row expands into its tool calls

**Delivery:** dashboard

Plan: `.team/run/liaison/plans/tool-flow.md` (human-approved 2026-10-13, about 02:15). Its sections "The names of the tools are data" and "Readability" are context for the Architect. Each AC's [tag] is its acceptance environment.

## User story

As the human, I want to expand a step in the timeline and see its model time and each tool call nested under it, so I can see why that step took as long as it did.

## Acceptance criteria

- **AC1 [dashboard]. Expanding.** Clicking a step's bar or row expands nested rows under it: one for model time, and the tool calls (A6a, s98) as bars on the same axis. Parallel calls stack. A PO turn expands the same way.
- **AC2 [dashboard]. Labels.** Each tool bar's label is its name on the first line: the named tool, or `Dev: <reason>`. The 80-character detail sits on a second line in a more subtle colour. When a bar is too narrow, both lines go into its tooltip, along with the start and duration.
- **AC3 [dashboard]. States.** Errors and timeouts are red, an unfinished call is hatched, and an open call grows live to "now".
- **AC4 [dashboard]. Tests pin:** the nesting, the stacking of parallel calls, the two-line label, the red and hatched states, and a PO turn's `po.run_role` wait.
- **AC5 [dashboard]. Misc bars.** A misc span (s98 AC6) is one bar labelled "misc · <n> calls, each under <collapse_under_s> s". The combined time and the counts per tool are in its tooltip, not on the bar, so the label never shows a total bigger than the limit. Clicking it expands its calls from tools.jsonl on demand, and they aren't shipped in every live update. A test pins the label and the on-demand expansion.
- **AC-R [dashboard]. Readability.** At 100% browser zoom, every piece of text in the new views is at least **12 CSS px as rendered**: a font size times the scale Mermaid or the SVG applies. That includes the two-line labels, the Flow chart nodes and the axis. Subtle text has a contrast ratio of at least **4.5:1** against its background, in light and dark themes.
  - **Measured:** a node-harness test computes each text element's rendered size and contrast, and fails below the limits.
  - **The Flow chart:** adding nodes must not shrink it below the limit. When it doesn't fit, it scrolls sideways instead of scaling down.
