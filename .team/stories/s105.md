# s105: Bug: a dashboard presentation can't start in an empty workspace (".agile-team.toml not found")

**Delivery:** cli

## User story

As the team, I want a dashboard story's presentation to start without hand-written config, so e2e and acceptance test the story and not the setup.

## Context

At e2e for a dashboard story, the runner starts `agile-team dashboard` against `.team/run/customer/dashboard/presentation/workspace`. That workspace has no `.agile-team.toml` unless the integration-tester remembers to write one, so the start fails with ".agile-team.toml not found … run `agile-team init`". It has happened 13 times across s4, s15, s83, s85 and s96, a round each. It is also why the customer proxy rarely got to use its browser on dashboard stories.

## Acceptance criteria

- **AC1 [cli].** When a presentation workspace for a dashboard-kind environment has no `.agile-team.toml`, the runner seeds a minimal valid one before the start command runs, including the presentation token (t31: `[dashboard] token = "presentation"`). An existing file is never overwritten. A test pins: an empty workspace plus the prepare command answers `/api/snapshot` with 200, and a tester's own config is kept.
- **AC2 [cli].** The integration-tester's role file says what a dashboard presentation needs (only the run data its story's ACs need; the config is seeded), with one worked example.
- **AC3 [cli].** When the presentation still fails to start, the gate's reason names the missing or broken file and the fix, not only the start command's output.
