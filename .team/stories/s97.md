# s97: Step time leaves out machine sleep

**Delivery:** dashboard

## User story

As the human, I want the time shown per role and story to count only while the machine is awake, so a closed lid doesn't make a step look slow.

## Acceptance criteria

- **AC1.** Step-start and step-end events also record the runner's monotonic clock (`time.monotonic()`, read through the `system` seam), as the heartbeat already does (`mono`; `health.Vitals.slept` uses it to detect sleep).
- **AC2.** A step's duration is its monotonic end minus its monotonic start. That's awake time: on macOS and Linux the monotonic clock pauses while the machine sleeps. The snapshot's step durations (s96 AC1) and a running step's elapsed time (s96 AC2) use it. An older event without `mono` falls back to wall time and is marked "may include sleep".
- **AC3.** Windows' monotonic clock keeps counting through sleep. This is a deliberate, tested and documented platform branch: on Windows the duration is wall time minus the sleep the heartbeat saw during the step.
- **AC4.** The Time chart's legend (s96 AC4) says "awake time".
- **AC5.** Tests pin, with a faked clock: a step that spans a sleep counts only its awake time; the fallback for old events; and both platform branches.
