## User story

As a human, I want the checkout guard to post one question per drift, test the rebase case properly, and not repeat a condition, so the guard stays trustworthy and tidy.

## Acceptance criteria

Findings F1-F3 in `.team/reviews/s61.md` ("Design review" section of `agile-team/docs/design/s61.md`):

1. F1: an in-run halt followed by `start --resume` while the same drift remains posts one question, not two, even when another question was open at the in-run halt. A test pins it.
2. F2: the AC6 rebase test asserts the reason contains `with a rebase in progress`, so it fails if rebase detection breaks. One end-to-end case pins the operation check.
3. F3: `Guard.accept` and `matches` share one helper (for example `Found.attached_and_idle()`) instead of repeating `found.branch is None or found.operation`.
4. No behaviour change beyond F1. Coverage 95%+, ruff check and ruff format clean.
