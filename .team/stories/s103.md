# s103: the guard refuses test output to a file, and the prompts tell roles to use timeout

**Delivery:** cli

## User story

As the team, I want to save a named test run's output and never be told to use a command macOS doesn't have, so e2e evidence is real and no step burns retries on refused commands.

## Acceptance criteria

- **AC1 [cli].** The guard allows a role to send a test command's output to a file in its own scope (`pytest <named files> > <file>` and `… | tee <file>`). A whole-suite run is still refused. A test pins each form.
- **AC2 [cli].** No role file or brief tells a role to use `timeout`. Where a time limit is needed, the runner applies it, or the role uses the tool's own timeout parameter. A test fails if `timeout ` appears in a built-in role file.
- **AC3 [cli].** A refused command's reason names the rule and the allowed form, so a role doesn't retry by guesswork.
