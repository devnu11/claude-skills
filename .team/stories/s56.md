# s56: No code in the global scope - refactor the fixture script and enforce the rule

**Delivery:** agile-team runner (scripts, static checks, prompts).

## User story

As the human, I want every module and script to hold only imports, constants and definitions at its top level, with the work in a single entry function, so that no code runs at import time and the code review can rely on a check, not on someone noticing.

## Acceptance criteria

1. `agile-team/runner/scripts/make_dashboard_fixture.py` is refactored: its 68 top-level statements (loops, `with` blocks and calls from line 166 on) move into definitions and one entry function `main` (or `just_do_it`), called from `if __name__ == "__main__": main()`. The regenerated fixture (`agile-team/runner/agile_team/dashboard/fixtures/snapshot.json`) stays byte-identical; a test pins it.
2. DevOps adds a check over `agile_team/`, `scripts/` and `tests/` that fails on any top-level statement except: imports, assignments and annotated assignments, function and class definitions, the module docstring and the `if __name__ == "__main__":` guard. It is an AST script run by the toolchain's static command (or a ruff rule if one fits), so the gates and CI catch it. A test shows it failing on a sample file with top-level code and passing on a clean one.
3. Anything else the check finds is fixed in this story.
4. The rule is added to the repo's `.claude/CLAUDE.md` "Python runners" section and to the code-reviewer's checklist (built-in role file), so the rule exists in code and in the prompts. The `.claude/` directory is the human's: the Architect rules how that edit is made (a note to the liaison if the team may not write there).
5. Coverage stays at 95%+; ruff check and ruff format clean. Docs move with behaviour.
