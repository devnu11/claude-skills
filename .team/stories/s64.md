# s64: A story's delivery must name a configured [[delivery]]

**Delivery:** cli (the agile-team runner's PO tools and state).

## User story

As the PO, I want `open_story` (and any tool or command that sets a story's
delivery) to reject a name that is not a configured `[[delivery]]`, so that a
story cannot reach the Customer Proxy with a delivery that does not exist.

## Why

s61 and s62 were opened with delivery names written as prose ("agile-team
runner (checkout guard)"). Neither is a configured delivery. s61's acceptance
step was refused with "no [[delivery]] is configured for the customer proxy"
and sat blocked for a long time (m58) before the liaison corrected state.json
by hand. The failure surfaced at the end of the pipeline, not at the start.

## Acceptance criteria

1. `open_story` with a `delivery` that is not the name of a configured
   `[[delivery]]` in `.agile-team.toml` is refused. The reason lists the valid
   names.
2. Every other tool or command that sets or changes a story's delivery applies
   the same check with the same reason.
3. A valid name is accepted exactly as today. Matching is exact: the story
   file's prose is not parsed.
4. When no `[[delivery]]` is configured at all, the refusal says so and does
   not list names.
5. The check is one function used by every path (DRY), driven by the loaded
   config, not by a hard-coded list.
6. `SKILL.md` and `reference/protocol.md` state that the delivery must be a
   configured name, and the PO role file's instruction to `open_story` says the
   same, in the same story.
7. Tests cover accept, refuse with names, refuse with no deliveries, and every
   setter path. Coverage stays at 95%+; ruff check and format are clean.

## Out of scope

- Repairing stories already in state with an invalid delivery.
- Changing how deliveries are configured or chosen for a story.
