**User story.** As the human, I want every story checked against the house rules while it's built, with each finding going to the role that can fix it, so that a sprint never reaches CI with a house-rules failure and the baseline only ever shrinks.

**Why.** House-rules runs only in CI. No team step runs it, so sprint 45 reached its sprint-end CI with 59 new findings and the sprint end held. A liaison agent fixed them in PR #32.

**Placement:** the human (2026-10-15): "add the house rules as gates in a standalone sprint". It is the only story in sprint 46.

**How (from a cross-check against the runner; fact):** most of this is configuration, not runner code.
- **AC2 and AC3:** add `&& uv run --frozen --project house-rules/runner house-rules check` to `[toolchain] static`. Its routing goes through `gates.ROUTED_COMMANDS`, and the quality and boundary checks run it too.
- **AC1:** add house-rules to the `[toolchain.files] lint_files` override. If a file template can't reach the house-rules project from a targeted root, the code change is a `{repo}` placeholder.
- **AC4:** add `house-rules baseline` (without `--accept-new`) to the `fix` template. It shrinks the baseline and refuses growth. Then add `.house-rules-baseline.json` to the write scopes of the developer and DevOps through `[roles.*] write`.

ACs written by the liaison and cross-checked by Fable. The human approved the story and its placement, not the AC text.
