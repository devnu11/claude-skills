# s71: Unit tests run no shell commands and touch no OS

**Delivery:** cli (the agile-team runner: a new `agile_team/system.py` seam, the unit-test conftest and the unit tests).

## User story

As the human running the team, I want unit tests to touch nothing real, so that
they are fast, leave nothing behind and can simulate failures a real OS makes
hard.

## Why

The human's rule: any shell command is mocked in a unit test. Git is a
process, a pid is OS state, and `tmp_path` is a loophole (the `repo` fixture
runs real git inside it). The full plan and the table of calls is
`.team/run/liaison/plans/unit-test-isolation.md`. Read it; this story does not
restate it.

## Acceptance criteria

1. **No unit test touches the OS:** no git, no subprocess, no signals, no real
   pid, no clock, no network, and no filesystem, `tmp_path` included. Real files
   and real git live only in `tests/e2e/`.
2. **One seam:** `agile_team/system.py` is the only code that touches the OS. It
   holds thin functions and no logic. Every other module imports it as a module
   (`from agile_team import system`) and calls `system.read_text(...)`. No
   filesystem or process object is passed as a parameter. `from
   agile_team.system import name` is banned (it defeats the swap).
3. An autouse fixture in the unit-test conftest swaps `system`'s functions for the
   repo's own in-memory fake (no new dependency; pyfakefs is not used). The fake
   can record writes and simulate a missing file, an unreadable file and a full
   disk. `git_ops` calls `system.run`, so git is faked too.
4. **Enforced twice:** ruff `TID251` banned-api for OS calls everywhere except
   `system.py`, and an audit hook in `tests/conftest.py`, for every test outside
   `tests/e2e/`, that fails a unit test reaching the real OS. The banned events
   are a table, not branches. The error names the call and says "inject it, or
   move the test to `tests/e2e/`". The "none" rows of the plan (pid, wait,
   signal, sleep, `shutil.which`, `platform`) are patched to raise.
5. Existing `tmp_path` and real-git unit tests move to the fake or to
   `tests/e2e/`, including the pid-file tests in `test_process_groups.py` and
   the `repo`/`configured` fixture users. No test is weakened, skipped or
   deleted; each keeps what it proves.
6. An ADR records the seam. The unit-tester role text and `reference/protocol.md`
   state the rule in the same story.
7. Coverage 95%+; ruff check and format clean.

## Scope split (PO ruling on the architect's ask)

The work is cut into three stories, one per phase in
`agile-team/docs/design/s71.md` ("Phases"). **This story (s71) is P1 only:** the
seam, files and clock; the fake (`tests/fake_system.py`), the guard
(`tests/os_guard.py`), the conftest wiring, `LEGACY` (every pre-s71 test file
not yet migrated), the ADR, the unit-tester role text and `protocol.md`. The
migrations listed for P1 are in scope. Processes, signals and network are
**s76 (P2)**; runtime, cli, `LEGACY` deletion and ruff `TID251` are **s77 (P3)**.

For this story, the ACs apply to the modules and tests P1 converts. AC1 and AC5
for files still in `LEGACY` are completed by s76 and s77. AC4's ruff half lands
in s77; its audit-hook half lands here. Each phase keeps the suite green.

### Rulings on the unit-tester's asks

- `Relay.tell` publishes with `Path.hardlink_to`, which the P1 table omits. The
  developer adds a thin `system` function for it in P1 (and `_publish` calls
  it); the design's table is a minimum, not a limit. The relay tell tests then
  leave `LEGACY` in this story.
- The "at least" P1 files that the tests step left in `LEGACY` (`test_config`,
  `test_roles`, `test_paths`, `test_onboard`, `test_presentation`,
  `test_po_session`, `test_snapshot`, `test_insights`, `test_fingerprint`,
  `test_handover`, `test_providers`, `test_priority`, `test_gates`, `test_s68`,
  `test_s27`, `test_s62_watch`) are **deferred, not dropped**: s76 inherits them
  as its first migrations (see s76 AC2). s71 ships the seam, the fake, the guard
  and the files already migrated, with the suite green.

- **Unconverted P1 modules (code-reviewer's ask).** Source conversions pair with
  the test migrations that reach them (design: "Each phase pairs source
  conversions with the tests that reach them"). The tests for these modules are
  deferred to s76, so their conversions go with them: `results`, `po_session`,
  `onboard`, `presentation`, `paths`, `gates`, `dashboard/snapshot`, `dispatch`,
  `router` (file call only), `checkout`, `stack`, `runner_tools` move to s76 AC1.
  They are not dropped. s71 converts the P1 modules whose tests migrate here;
  the review judges s71 against that scope, and the deferral is not a defect.
