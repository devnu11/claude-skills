**User story.** As the team, I want the test suite to leave each checkout's tools as it found
them, so a gate never fails because an earlier test run broke the venv it runs from.

**What happened (2026-10-20, sprint 51).** Once DevOps added house-rules' own suite to the
gates (commit 5356cf93), s165's and s164's gates failed with
`.venv/bin/pytest: exec: /private/var/folders/.../pytest-197/popen-gw3/test_ac4_fixed_entry_leaves_th0/house-rules/runner/.venv/bin/python: cannot execute: No such file or directory`
(m304, m305). So every later `test` or `coverage` gate in that worktree fails once pytest
prunes the temp dir. `lint` (ruff is a native binary) and `static` (`house-rules check`,
which uv repairs) pass. The liaison first removed the two broken venvs, which only made the
next run recreate them broken; it then rebuilt them with `uv sync`. The main checkout is hit
the same way only when its `house-rules/runner/.venv` is absent before a suite run (a fresh
clone, or after removing it by hand).

**Cause (fact, reproduced at 4acfdf48; see the review).**
`tests/e2e/test_s157_house_rules_e2e.py:67` builds its scratch repo with
`(tmp_path / "house-rules").symlink_to(REPO / "house-rules")`. When the checkout has no
`house-rules/runner/.venv` yet (a new story worktree never has one, and the `test` command
runs this suite before house-rules' own), the first test that runs house-rules through uv
creates that venv through the symlink. Every console script in the checkout's real
`.venv/bin` then starts a python at the pytest temp path. The scripts keep working while that
temp dir exists (pytest keeps the last three), and then fail. A venv that already existed is
left alone. Possible fix shapes, for design to choose: symlink only `house_rules/`,
`pyproject.toml` and `uv.lock`; point `UV_PROJECT_ENVIRONMENT` at a temp venv; or copy
without `.venv`.

**Placement:** the current sprint (sprint 51), because it fails the gates of every new story
worktree. It touches only `tests/e2e/test_s157_house_rules_e2e.py` (the integration tester's
file). No sprint-51 story changes it, and s161 renames nothing this file imports. The PO asked
for `suite_runs: 3` (m305), because it judged the failure a race. It is left out: the review
reproduced the failure deterministically, serially and with `-n 2`, and AC1's by-hand check
starts from a missing venv.
