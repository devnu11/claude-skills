# s73: The sprint-boundary full check runs the suite once

**Delivery:** cli (the agile-team runner's boundary checks, `fullcheck.py`).

## User story

As the human running the team, I want the sprint-boundary full check to run
the coverage command only, so that the boundary costs one test run, not two.

## Why

s68 made the implement gate run the suite once. The architect found that
`fullcheck.py` still runs the `test` command and then the `coverage` command
at the sprint boundary. One full run takes about 4 minutes, so the boundary
pays for a run it does not need.

## Acceptance criteria

1. The boundary full check runs the coverage command once. A green run with
   enough coverage passes; that one run proves green and gives the coverage
   figure.
2. The bounce reasons are unchanged: a failing suite and a coverage shortfall
   each bounce with the same text as today. A test pins each.
3. The recorded stage time shows one command run, not two.
4. `reference/protocol.md` states the boundary check runs the suite once, in
   the same story.
5. It reuses s68's single-run rule (one shared helper), not a second copy.
6. Coverage 95%+; ruff check and format clean.

## Origin

Architect's follow-up candidate on s68. Runs after s68.
