title: Dashboard renders Markdown in questions, notes and handoff text
delivery: dashboard
acceptance:
  - id: AC1
    text: >-
      The Questions tab renders message and answer text as Markdown: headings,
      paragraphs, lists, emphasis, inline code, fenced code blocks, tables and links.
      Line breaks and numbered options such as "(a) … (b) …" stay readable.
  - id: AC2
    text: >-
      Rendering is safe: raw HTML in a message is not executed, every link opens with
      `rel="noopener"`, and nothing from the snapshot can inject script. A test feeds a
      `<script>`/`onerror` payload and checks it appears inert.
  - id: AC3
    text: >-
      The same renderer is used for long text elsewhere in the UI where it helps
      (timeline brief and handoff summaries, notes), with no duplicated rendering code.
  - id: AC4
    text: >-
      The library choice is recorded in an ADR. If it's a browser library, it is
      pinned and loaded the way Mermaid is (one pinned outside URL, no build step),
      with a readable plain-text fallback when it can't load. If it's server-side
      Python, there is no new runtime dependency without that ADR.
  - id: AC5
    text: >-
      The customer dashboard doc mentions Markdown rendering. Tests cover the renderer
      wiring, the fallback and the XSS case. Coverage stays at or above 95%, and ruff
      check and ruff format are clean.
---

## User story

As the human reading the team's questions on the dashboard, I want them shown
with their formatting, so that long messages are readable without the liaison
summarising them for me.

## Notes

Human: "the question tab is good, but any formatting is lost. So its hard to
read that wall of text, your summary was necessary. But if we could allow them
to take md responses. I'm sure there is a python or js library to convert to
html."
