acceptance:
  - id: AC1
    text: >-
      When `.claude/CLAUDE.md` has an `@path` import that points inside the repo at a
      file that is not valid UTF-8 text, `RoleBook.system_prompt` leaves that import
      out with a one-line note, like an import outside the repo, and does not raise
      `UnicodeDecodeError`. The other text and imports are still loaded.
    environment: cli
  - id: AC2
    text: >-
      A test pins this with a binary file inside the repo, and shows that a step's
      system prompt is still built.
    environment: cli
  - id: AC3
    text: >-
      `reference/protocol.md` ("System prompt order") says an import that cannot be
      read as text is left out with a note.
    environment: cli
---

Scope: the agile-team runner, `roles.py` system prompt (the s142 repo-instructions loader).

## User story

As the human, I want a bad `@import` in the repo's `.claude/CLAUDE.md` to cost one line in the prompt, not every step of every story, so one mistaken import cannot stop the team.

## Origin

Follow-up found by the architect in the s142 design: an in-repo `@import` of a file that is not UTF-8 text makes `system_prompt` raise `UnicodeDecodeError`, and every step fails. The PO decided the runner leaves such an import out with a note, as it does for an import outside the repo. Asked by the architect, ACs written by the PO.
