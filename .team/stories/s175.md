**User story.** As the liaison, I want a failed landing to say what failed, so I can repair
the right thing instead of reading a misleading command name and finding `crash.log` empty.

**What happened (2026-10-20 10:11-11:06, sprint 51).** s165's land crashed with
`UpstreamError`. The `runner-stage` event (`events.jsonl:80534`, id e80534) says
`detail: "git worktree remove --force .../.team/run/land"`, `code: 128`,
`raised: "UpstreamError"`, `seconds: 602.7`. `.team/run/land` was absent and clean, the
merge ba111728 was fine, and `crash.log` had no entry (`decisions.md:530`, m298). The PO asked
for the story in m300 (`outbox.jsonl`, 2026-10-20 11:06). The real failure was most likely the
GitHub API rate limit that produced s167's `UpstreamError: {` at 12:25 (`decisions.md:545`),
but nothing recorded it.

**Cause (fact, read at 0e1e0991).** A stage's `detail` and `code` are the first command `stages.note` saw fail, else the
latest (`stages.py:246-250`); `CommandShell.run` notes every shell command
(`commands.py:108-112`), so a tolerated failure such as `git worktree remove --force` of
an absent directory sticks, and the gh call that really raised, made through
`upstream.py` without a note, is never recorded. `stages.entered` records only the exception's class name
(`stages.py:259-267`) and `Timed.data` has no message field (`stage_log.py:117-131`). The
scheduler's `run_work` turns the exception into `{"status": "error", "reason":
crash_halt(exc).reason}` (`scheduler.py:361-366`); `crash_halt` keeps the first message line
(`halt.py:133-138`), which is empty for an empty body, and `run_work` never calls
`log_traceback` (its callers are `boundary_runner.py:295`, `cli.py:577`,
`dispatch.py:938`, `:1299`, `live.py:483`, `recovery.py:36`; none is on the land path).
The hand-over rule still says "details in .team/run/crash.log" (`handover.py:196`).

**Placement:** Product Backlog. Files: `stage_log.py`, `stages.py`, `scheduler.run_work`,
`upstream.py` (the empty-body message). Small and independent; it shares no file with the
other landing gaps except `landing.py` if the failing call is noted there.
