**User story.** As the liaison onboarding a legacy repo, I want `init` to write what the human
approved from the scan, ignore the tools' droppings, and carry the repo's house rules to every
role, so the first sprint starts from the repo as it is (#54, #60).

**The problem (fact, read at d9495cbf).** `build_config` (`onboard.py:99-120`) copies the
preset's commands and globs verbatim; there is no path from a scan to the file.
`gitignore_lines` (`onboard.py:143-152`) adds `.team/run/` only, and no preset lists tool
artifacts, so `.coverage` and `htmlcov/` appear as untracked files after every coverage run and
`guard.ALWAYS_IGNORED` (`guard.py:41`, `.team/run/**` alone) quarantines them step after step
(#60, #60.4). The charter is written as the unfilled template (`onboard.py:37-53`,
`write_if_missing`). Roles read only `.claude/CLAUDE.md` (`instructions.py:11`,
`roles.py:335-344`); a repo whose rules live in a root `CLAUDE.md`, which is where most
Claude Code repos keep them, hands the team nothing.

**Shape (from the plan).** Data in `presets.toml`: per-stack `artifacts` (ignore globs) and
`instruction_files` (`CLAUDE.md`, `.claude/CLAUDE.md`), validated on load. Code: `init`
consuming A's proposal; `ensure_lines` (`onboard.py:155-161`) already writes once under the
`# agile-team` marker and is reused. The config B writes must be one #55.1 (per-stack
`[[toolchain.files]]`) can extend without renaming keys. The key file outside the repo
(#53) is not here: it is a liaison fix that lands on its own.

**Placement:** Product Backlog, `--approved-by none`; not for sprint 51. After story A
(the scan it consumes); if A gets an id before this is filed, name it in `depends_on`.
It touches `onboard.py`, `cli.py` (`cmd_init`, `answers_from`), `presets.toml`,
`instructions.py` and `roles.py`.
