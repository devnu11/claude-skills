  - id: AC1
    text: >-
      The dashboard can answer an open question. The write goes through the same relay
      code as `agile-team answer`, so the rules live in one place. An already-answered
      question is refused with a clear message, so the web and the liaison can't both
      answer it.
  - id: AC3
    text: >-
      The PO's ask tool takes options as data: key, label and a recommended flag. The
      dashboard shows them as buttons plus a free-text box, and the liaison's prompts
      use the same options. A free-text question without options still works.
  - id: AC4
    text: >-
      Dashboard writes are accepted only from localhost (127.0.0.1 or ::1) and only
      with a random token, generated when the dashboard starts and printed in its URL.
      A write that fails either check gets 403. The token never appears in the
      snapshot or the logs. Reads are unchanged, and s4's rule that no directory is
      served stays.
  - id: AC5
    text: >-
      Each answer and message records where it came from (web or CLI) in the inbox
      entry and its event. The dashboard shows the source next to each.
  - id: AC6
    text: >-
      The Questions tab and the new message box are covered by the customer dashboard
      doc. `reference/protocol.md` (the dashboard routes, the token, inbox entries),
      SKILL.md and the README row are updated. Tests cover the answer path, double
      answer, options, the token (accept, reject, missing), a non-localhost write
      (403) and source tagging.

## User story

As the human, I want to answer the team's questions and send the PO messages
from the dashboard, so that I don't need the liaison to relay everything, and a
new request doesn't need a stop and resume.
