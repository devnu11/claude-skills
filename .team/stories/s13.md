acceptance:
  - id: AC1
    text: >-
      Before each customer-proxy step, the runner prepares the Proxy's sandbox as a
      ready-to-use customer workspace for the story's delivery: a git-initialised
      scratch repo with `agile-team init` already run (or the delivery's equivalent),
      so the Proxy never needs `git init` itself. For the `dashboard` delivery, the
      workspace also holds sample run files (state, events, ledger, outbox, inbox),
      so `agile-team dashboard --no-open --port 0` serves a non-empty snapshot.
  - id: AC2
    text: >-
      The Proxy can read and rewrite its own report `.team/acceptance/<story>.md`
      across steps. Today it can create the file but cannot Read it afterwards, so a
      second acceptance step cannot Write it. Nothing else under `.team/` outside
      stories and its own acceptance file becomes readable.
  - id: AC3
    text: >-
      `agile-team init` outside a git repo prints `agile-team init: <message>` and
      exits 1, as the docs promise, instead of a `GitError` traceback.
  - id: AC4
    text: >-
      The Proxy gets a read-only, black-box view of the live run: `agile-team status`
      output (JSON) for the live repo, copied into its sandbox before the step. That
      lets runner features that only show in a live run (sprints, stops, spend) be
      judged from real output. Source and tests stay unreadable, and s7's rules still
      hold.
  - id: AC5
    text: >-
      `roles/customer-proxy.md` tells the Proxy what its workspace holds and that
      internal ACs (coverage, ruff, docs wording) are verified by review, not by it.
      `reference/protocol.md` documents the workspace and the acceptance-file access.
      The customer docs cover the init error.
  - id: AC6
    text: >-
      Tests cover workspace preparation per delivery, the acceptance-file access rule,
      the init error and the status snapshot copy. Coverage stays at or above 95%, and
      ruff check and ruff format are clean.

## User story

As the human, I want the Customer Proxy to be able to actually exercise what
was delivered, so that acceptance means "a customer tried it" and stories don't
stall at the last step.
