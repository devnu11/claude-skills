# s69: Only the runner runs the full suite

**Delivery:** cli (the agile-team runner, its role briefs and the agent sandbox).

## User story

As the human running the team, I want only the runner to run the full test
suite and coverage, and to hand the results to the roles in their briefs, so
that agents stop spending their step time in pytest.

## Why

Agents spend about 62% of their step time in tools, mostly pytest. The human's
rule: agents never run the full suite or coverage. Evidence:
`.team/run/liaison/reports/2026-10-12-time-spent.md`.

## Acceptance criteria

1. The runner runs the full suite, coverage, lint and static checks itself and
   puts the results (test and coverage output, lint, static) in the briefs of
   the roles that need them. A test shows the brief carries them.
2. A developer may ask the runner, through a runner tool, to run individual
   tests or all of the story's new tests. A developer cannot ask for a full run.
   The request's time is recorded as a runner stage.
3. The quality czar judges the runner's lint, static and coverage results and
   runs nothing itself. The code reviewer reads tests and does not run them. The
   unit tester does not re-check red; the runner already does.
4. Enforced in code, not only in role text: the agent sandbox or tool rules
   deny a full pytest run and a coverage run from a role's Bash. A test pins
   the denial and its reason, including how to ask the runner for targeted
   tests. A targeted run of named tests is still allowed.
5. The behaviour is a table (which roles and commands), not a branch per role.
6. Role text changes in the same story: `developer.md` ("Run the test and
   coverage commands ... yourself"), `unit-tester.md` ("Run the tests and
   confirm they fail"), `quality-czar.md` (its mission), and the pytest example
   in `_shared.md`. `SKILL.md` and `reference/protocol.md` change too.
7. Coverage 95%+; ruff check and format clean.
