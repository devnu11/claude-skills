      In the rebase worktree, a git command that would move a branch other than the step's

      `git reset` or `git rebase` while HEAD is on a branch that isn't the rebase branch
      (`branch`, `update-ref` and `symbolic-ref` stay refused as today).
  - id: AC2
    environment: cli
    text: >-
      The commands the rebase needs still run: `git rebase --continue`, `--abort` and
      `--skip`, `git add`, `git checkout -- <file>`, `git reset` and `git checkout -B` on the
      step's own rebase branch, and the read-only commands.
  - id: AC3
    environment: cli
    text: >-
      When the step ends, the runner compares every local branch head with its value at the
      step's start; if any branch but the rebase branch moved, the step bounces a round with a reason
      naming the branch and both shas, and the runner puts the branch back.

**User story.** As the human, I want a rebase step that goes wrong to leave the other
story branches and the sprint branch exactly where they were, so one agent's mistake can't
move work that belongs to another story.

**What happened (2026-10-23, sprint 51).** The runner-fixes review accepted the
"git-local-only" rule for the rebase step with a known residue: "`Allows.LOCAL` still allows
commands that move refs the worktree shares with the main repo, such as `git checkout -B
<other branch>`, `git reset` and `git rebase <x> <other branch>`"
(`reports/2026-10-22-runner-fixes-51.md:136`, `:164`); the follow-up story was agreed at
`plans/mandate-2026-10-22.md:65`. Nothing has gone wrong yet; the sprint-51 rebases were
done by a repair agent, not the step.

**Cause (fact, read at 0e1e0991).** `_set_story_rebase_scope` gives the step
`Allows.LOCAL` (`dispatch.py:750-756`). `_is_local` lets through every verb in
`LOCAL_GIT`, which includes `checkout`, `switch`, `reset` and `rebase`
(`git_check.py:32-38`, `:415-418`), unless a flag in `LOCAL_DENIED_FLAGS` is present, and
that table only denies `rebase -i/-x` and `--ignore-other-worktrees`
(`git_check.py:53-57`). The rule checks the verb and flags, not which ref the command
would move, so `git checkout -B team/story-s164-r1 <sha>` from s165's rebase worktree is
local and allowed. The worktree shares the repo's refs, so the move is real. The runner's
S3 checks after the step look at the rebase branch only.

**Placement:** Product Backlog. Files: `git_check.py` (a branch-target check for the LOCAL
row), `dispatch.py` (the ref snapshot around the step), the git rules table in
`reference/protocol.md`. Independent of the other gaps; batch 1 (issue fixes), which also
edited `git_check.py`, is on main already.
