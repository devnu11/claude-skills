**User story.** As the PO, I want to take a story that never started out of the sprint
myself, so that one crashed story doesn't block the sprint end or need a hand edit of
`state.json`.

**What happened (2026-10-25 22:35-23:40, sprint 54).** The liaison asked for s180 to wait
for s182 and go back to the Product Backlog (t246). s180's design step had crashed before
any commit (`hold: error: crashed: GitError: git branch team/story-s180 ...`,
`events.jsonl` e407490). `revert_story` refused it: "s180 can't be reverted (it has no
commits)". Earlier it had been refused while the start boundary was pending (e407242). The
PO held it (e407490) and asked how to proceed: "I need a way to move it out without starting
a new sprint: start_sprint would number it 55" (m386). The sprint's four other stories
landed, but the PO couldn't end it (m387). The liaison stopped the run, backed up the state
and set s180's `sprint`, `hold` and `po_hold` to null by hand (`decisions.md:579`,
`:581`).

**Cause (fact, read at 14c30be9).**
- `revert_story` refuses a story with no commit and no branch, "story {story} has no commits
  to revert" (`reverts.py:24`, `:220-224`). After its sprint-52 revert dropped the branch
  record (`reverts.py:284-290`, e404665), s180 had neither.
- `start_sprint` is the only tool that moves unlisted stories back to the Product Backlog,
  and it begins a new sprint number with a START boundary (`po_tools.py:335-355`,
  `:428-436`, schema `:812-821`).
- `add_to_sprint` only adds (`po_tools.py:357-367`). `hold_story` keeps the story in the
  sprint. `continue_story` clears any hold, a crash hold too (`po_tools.py:650-658`,
  `continue_refusal` `gates.py:366-372`), but leaves the story in the sprint, where its next
  step runs into the same crash.
- The sprint end refuses while any sprint story is unfinished (`sprint_end.end_refusal`,
  `sprint_end.py:54-60`).

**Placement:** Product Backlog. Files: `po_tools.py` (a new row in `SCHEMAS`, using the
shared refusal helper), the story-admin event, `roles/product-owner.md` (when to use it
instead of `revert_story`) and the PO tools section of `reference/protocol.md`. Whether this
is a new tool or `revert_story` doing the move for a story with no commits is the
architect's call. s53 (hold, release, cancel) and s14 (sprint planning view) don't cover it.
It pairs with `gap-story-branch-exists-story.md`, the crash that left s180 in this state.
