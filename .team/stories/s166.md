**User story.** As the human, I want story landings and boundary stages to run beside other
work without crashing the run, so a story-branch sprint goes from start to end unattended.

**What happened (2026-10-19/20, sprints 50 and 51).**
- s163's landing pushed its merge to `team/sprint-50` (CI green), and then
  `gh pr close 40` failed: "can't be closed because it was already merged". GitHub had
  marked story PR #40 merged as soon as the landing was pushed, because its base is the
  sprint branch. The run halted (m288; the PO asked for this story in m289).
- Sprint 51's start boundary crashed with `RoleError: unknown role 'runner'`.

**Cause (fact, read from the code at d3518fbe).**
- `Landing.complete` calls `prs.close(story.pr, note)` (`landing.py:522-531`, the call at
  `:530`), and `GitHub.close` raises on any `gh` failure (`upstream.py:327-329`). `GhPrs.close`
  is the one implementation, so `story_ci._close` (`story_ci.py:115-117`) and the replay's
  close of an old sprint PR (`boundary_runner.py:926-927`) share it.
- `Scheduler.check_budget` (`scheduler.py:329-337`) skips only when the *new* work is
  costless (`COSTLESS = {LAND, BOUNDARY}`, `:48`). It then reserves for every entry in
  `self.running`, and `find_reserve` resolves the work's role (`scheduler.py:339-342`).
  Both a landing (`router.py:349`) and, since s163 AC6, a boundary stage
  (`boundary_runner.py:190`) run as tasks with the role `runner`, which `roles.resolve`
  doesn't know (`roles.py:281`). The landing case has been latent since s159; sprint 50's
  one story never hit it.

**The live hotfixes.** With the human's approval (2026-10-19, "You and fable work together to
get this going again"; 2026-10-20, "do it"), the liaison patched the pin at d3518fb only:
- `GitHub.close` treats "already merged" as closed;
- `check_budget` leaves costless running work out of the reserves.

The pin's `close` matches gh's message text; the story's fix may instead read the PR's state
(`PrState.MERGED`) before closing. Design decides. The runner re-pins itself at each sprint's
end, and that drops these hotfixes. This story has to land in sprint 51, or sprint 52's
first landing and its first boundary will crash again.

**Placement:** the current sprint (sprint 51), at the human's direction (2026-10-20, "do
it"). It touches `upstream.py`, `landing.py` and `scheduler.py`. s161 renames `sha_checks`
(right above `GitHub.close`), `ended` and `budget_reserve.reserve` (called from
`find_reserve`) in the same files: adjacent hunks, not overlapping. s164 changes
`scheduler.py` (`tick`, `wait_for_change`), in different functions.
