# s110: The product-owner role file states the CI rule

**Delivery:** cli

## User story

As the human, I want the PO role to know when a sprint is done with respect to CI, so a flaky failure is never waved through.

## Acceptance criteria

- **AC1 [cli].** The product-owner role file states the standing CI rule: a sprint is done only when a green CI run is actually present on GitHub. A re-run counts only when it is green, and only when the failed job never ran our code (cancelled with no steps, or no runner available). If a failure could be flakiness in our code, it is a bug story, and the sprint isn't done.
- **AC2 [cli].** SKILL.md and protocol.md carry the same rule wherever they describe the CI boundary (ci_green, ci_failed, ci_pending), in the same story.

## Notes

From the human (t53, decision 2). The PO cannot write role files; this story goes to the owning role. Not a bug: schedule after the bugs, with A14 or in sprint 37.
