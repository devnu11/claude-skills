**User story.** As the human, I want every command the runner starts for a repo to see the
repo's tools, not the runner's, so an acceptance check can't pass or fail because of the
runner's own Python.

**What happened (2026-10-25, sprint 53).** s174's code review (F1, relayed as m371) found that
`sandbox.sandbox_env` (`agile-team/runner/agile_team/sandbox.py:367-372` at ab91c1f2) starts
from the full `system.environ()` and only prepends the environment's `bin` dirs. s174's rule
covers `CommandShell` and `tally_watch` only, so the prepare and start commands for the
Customer Proxy still inherit `VIRTUAL_ENV` and the runner venv's `bin` dir.

**Cause (fact, read in the code at ab91c1f2; s174's helper is not on main yet).**
`sandbox_env` copies the runner's environment unchanged apart from `PATH`'s prefix.

**Placement:** Product Backlog, after s174 lands (it reuses s174's environment helper). Files:
`sandbox.py`. Small.
