title: Customer Proxy sandbox roots too coarse in nested repo layouts
delivery: cli
acceptance:
  - id: AC1
    text: >-
      `sandbox.forbidden_roots` returns the deepest literal directory prefix of each
      source/tests/e2e glob (e.g. `agile-team/runner/agile_team`,
      `agile-team/runner/tests`), not just the top-level directory, so a docs dir that
      shares a top-level parent with the source (e.g. `agile-team/docs/customer`) is not
      covered by the Proxy's `permissions.deny` Read rules.
  - id: AC2
    text: >-
      The Proxy's Bash token check forbids a token when it names a forbidden root as a
      path prefix (the token equals the root or starts with `root/`, after stripping a
      leading `./`), instead of comparing only the first path segment. A bare command
      such as `agile-team status` that matches the repo's top-level directory name is
      allowed; `cat agile-team/runner/agile_team/cli.py` is still denied.
  - id: AC3
    text: >-
      In this repo's configuration, the Proxy can read
      `agile-team/docs/customer/**` and run the installed `agile-team` CLI from its
      sandbox, while it still cannot read or name the source and test directories.
  - id: AC4
    text: >-
      `reference/protocol.md` (Enforcement section) describes the forbidden roots
      precisely.
  - id: AC5
    text: >-
      Tests cover the new code; coverage stays at or above 95%; ruff check and ruff
      format are clean.

## User story

As the human running the team on a repo whose source sits under a nested path
(like this one: `agile-team/runner/agile_team/`), I want the Customer Proxy to
be able to read the customer docs and run the delivered CLI, so that
acceptance can actually run, while the Proxy stays walled off from source and
tests.

## Notes

Found during s3 acceptance: the proxy was blocked because `forbidden_roots`
reduced `agile-team/runner/agile_team/**` to `agile-team`, which also matches
the CLI's name and the customer docs path. Note the running runner keeps the
old guard in memory; the fix takes effect after a runner restart
(`stop` then `start --resume`).
