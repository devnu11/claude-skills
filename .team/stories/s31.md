acceptance:
  - id: AC1
    environment: cli
    text: >-
      Hooks are data in `.agile-team.toml`, validated on load (`config check` reports
      bad ones). Each hook names: a target (a role, a step, or after-commit); when it
      runs (`before`, `after` or `after-commit`); what it runs (a `[toolchain]` key or
      a script in `.team/hooks/`); and `on_fail` (`inform` or `block`). An unknown
      target, key, script or on_fail value is a load error.
  - id: AC2
    environment: cli
    text: >-
      Before-hooks run in the runner (Python), before the agent starts. Their output
      is saved under the run dir and attached to the agent's brief as a
      "## Pre-step checks" section (command, exit code, output tail), so the agent
      doesn't re-run the tools. Examples set up in this repo's config: lint and static
      analysis before the quality-czar; unit tests and coverage before the
      unit-tester.
  - id: AC3
    environment: cli
    text: >-
      `on_fail = "inform"` puts the output in the brief and the agent deals with it.
      `on_fail = "block"` means the step doesn't start; the story bounces to the role
      that owns the fix, with the output, and the bounce goes through s27's repeat
      detection.
  - id: AC4
    environment: cli
    text: >-
      Today's command gates (tests-red at the tests step, tests-green and coverage at
      implement, the s26 probe, and so on) become built-in `after` hooks, so there is
      one mechanism. Their behaviour and gate reasons don't change. The existing
      gate tests still pass.
  - id: AC5
    environment: dashboard
    text: >-
      Every hook run is an event: start and end, hook name, target, when, exit code,
      duration and an output tail. The dashboard snapshot carries them, and the
      Flow view and the timeline show each hook as a script node bracketing its
      agent, with its result. The snapshot fixture is updated.
  - id: AC6
    environment: cli
    text: >-
      DevOps owns the hook definitions and the `.team/hooks/` scripts. A hook change
      goes live only after the step that made it passes review. Hook scripts run with
      the repo as cwd, a timeout from config, and the same environment filtering as
      toolchain commands. A hook can never run with a role's secrets.
  - id: AC7
    environment: review

## User story

As the human, I want DevOps to be able to put scripts around the agents (lint
before the quality-czar, tests before the unit-tester), so that agents read the
results instead of re-running tools, and every tool run is visible.

## Notes

Human, asking whether the system really supports real devops and TDD: "Devops
needs to instrument testing systems and tester needs to code before developer.
The Devops should be able to add code that runs in the python code before an
agent runs ... Also all of these scripts bracketing agents should be visualized
on the dashboard."

Today the gates run only after a step, from fixed `[toolchain]` keys. Their
results don't reach the next agent's brief (roles re-run the tools), and DevOps
can't add code that runs around an agent. This is story A; B (s32) and C (s33)
build on it.
