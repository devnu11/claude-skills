  - id: AC1

  - id: AC2
    text: >-
      There is no double counting: after a normal session end, the PO's ledger entries
      for that session sum to the session's reported `total_cost_usd`, within rounding.
      If interim figures are estimates (e.g. priced from token usage), the entries say
      so, and the final reconciliation replaces or corrects them.
  - id: AC3
    text: >-
      A role step interrupted mid-query has its spend so far recorded too, by the same
      mechanism or by whatever cost the SDK error carries. If none is available, it is
      recorded as a $0 entry marked interrupted, so the step still shows up.
  - id: AC4

## User story

As the human watching spend, I want the PO's own cost (usually the largest
single item, since the PO runs on Opus) recorded as it accrues, so that a crash
doesn't make the ledger under-report what the run cost.

## Notes

Observed in the last run: the ledger showed $7.36, which covered role steps
only. `PoRun._record` writes the PO's entry only after `collect()` returns,
so the crash dropped the whole Opus PO session. The interrupted developer-cli
step on s7 was lost the same way.

Recovering the spend already lost is out of scope.

Today the budget checkpoint is only checked in `Runtime.record_cost` for role
steps (AC4).

Depends on s8 for the crash and SIGTERM paths.
