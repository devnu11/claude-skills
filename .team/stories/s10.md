## User story

As the human watching spend, I want the PO's own cost (usually the largest
single item, since the PO runs on Opus) recorded as it accrues, so that a crash
doesn't make the ledger under-report what the run cost.

## Notes

NARROWED (t101): the human replaced the original ACs with these two. The story
proves the behaviour with an automated test. A test that passes closes the story.
A test that fails is fixed in the same story.

only. `PoRun._record` writes the PO's entry only after `collect()` returns,
so the crash dropped the whole Opus PO session. The interrupted developer-cli
step on s7 was lost the same way.

Recovering the spend already lost is out of scope.
