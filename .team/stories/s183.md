**User story.** As the liaison, I want a sprint the human has already merged to close by
itself at its end boundary. I don't want to back up and hand-edit `state.json` while the
team waits.

**What happened (2026-10-23, sprint 51 to 52).** The liaison had fast-forwarded main to
the sprint head (`decisions.md:556-557`). Sprint 51's END boundary then went: sync pass,
check pass, push `team/sprint-51` @ 39a87690, CI green, and replay `current`
(e360243..e360276). At `push-replayed` it held: "UpstreamError: pull request create
failed: GraphQL: No commits between main and team/sprint-51-r1 (createPullRequest)"
(e360279). The PO could not start sprint 52 (m339: "start_sprint for sprint 52 … is
refused. Sprint 51's end boundary is still pending, in state 'push-replayed, held:
error'"). The liaison closed it by hand at a stop. It backed up the state, set
`upstream.stack[0].mode` to `closed` and `boundary.hold` to `null`, and resumed
(`decisions.md:560`, `plans/mandate-2026-10-22.md:96-97`). The procedure is in
`reports/2026-10-23-close-sprint51-boundary.md`. The rerun then passed "the rebase changed
nothing" and finished `done` (e360302, e360303).

**Cause (fact: read in the code at ab91c1f2 and in the investigation report; the hand fix
was run live).**
- `_push_replayed` (`boundary_runner.py:890-902`) compares HEAD only with the entry's
  `pushed` sha, never with the target. HEAD 0e1e0991 differed from the pushed 39a87690, so
  `_push_replay_branch` (`:914-928`) pushed `team/sprint-51-r1`. It updated the entry first
  (`:921`) and then called `_open_replay_pr`, which "always" creates a PR (`:938-943`). On
  a target that already contains HEAD, GitHub refuses the create.
- `_step` (`:256-265`) turns any exception into `hold=error`.
- `continue_boundary` reruns the stage. HEAD now equals `pushed`, so it calls
  `_report_unchanged` (`:946-950`) and then `_make_ready` (`:930-936`), which runs `gh pr ready` on PR #48.
  #48 was already merged, so that fails too (report §2). No PO tool skips or closes a
  boundary.
- The "already in the target" paths that do exist don't cover this case: `NOTHING_NEW` at
  sync (`:380`), `_leave` at push (`:1100`), and `switchover.find_merged` at the next
  `start_sprint`.

**Placement:** Product Backlog. Files: `boundary_runner.py` (`_push_replayed`,
`_push_replay_branch`, `_make_ready`), the boundary section of `reference/protocol.md`.
Small. It is independent of the other gaps. It happens whenever the human or the liaison
merges a sprint before its end boundary has run.

ACs written by the liaison's drafting agent while the human was away; cross-checked by Fable (`reports/2026-10-25-review-gap-stories-2.md`). The human hasn't seen them.
