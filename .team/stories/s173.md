acceptance:
  - id: AC1
    environment: cli
    text: >-
      After a commit on the main checkout changes `.agile-team.toml` (a storyless DevOps
      step, or an accepted checkout), the next story `new`/`amend`, PO tool call, gate
      command and role step uses the new config without a restart: a story amendment naming
      an acceptance environment that the commit added is accepted, and a gate's test
      command runs with the commit's command line.
  - id: AC2
    environment: cli
    text: >-
      A step that is already running keeps the config it started with until it ends; the
      new config applies from the next step, gate or tool call, and one `config` event
      records the sha and the sections that changed.
  - id: AC3
    environment: cli
    text: >-
      A committed config that fails validation doesn't stop the run: the runner keeps the
      last good config, writes a `config` event with the validation error, and the step that
      committed it (or the PO, for an outside commit) gets the error in its hand-over.

**User story.** As the PO, I want a config change DevOps commits to be live at once, so
that an environment or a command added for a story is usable without the liaison stopping
and resuming the team.

**What happened (2026-10-20, sprint 51).** DevOps committed the `house-rules` acceptance
environment for s161 (5356cf93); the liaison's amendment q19 naming it was refused because
"config loaded before DevOps's house-rules env"; the runner was stopped and resumed to reload
and the amendment re-sent as q20 (`decisions.md:530-531`), which in turn moved the sprint
head and dropped s165's landing (`:532`). Later the same day the `-n auto` to `-n 2` gate
change (4acfdf48) needed another restart (`:537`), and the s94 fix a third (`:541`). Each
restart also pruned the story worktrees (`gap-resume-prunes-worktrees-story.md`).

**Cause (fact, read at 0e1e0991).** `cli._load_config` reads `.agile-team.toml` once per
command (`cli.py:149-153`; `config_mod.load` has no other caller) and the `Runtime` keeps
that object for the run (`config: Config`, `dispatch.py:460`). Story intake reads the environment list
from `runtime.config.environments` (`story_intake.py:126`, `:189`), gates read their
commands from the same object, and nothing watches the file or the commits that change it.

**Placement:** Product Backlog. Size M, not a bug-sized S: AC1 names four consumers (intake, PO tools, gates, role steps), AC2 a per-step freeze, AC3 a validation path. Files: `config.py`, `dispatch.py` (a reload point after the
runner's own commits and `accept-checkout`), `story_intake.py`, `gates.py`, the config
section of `reference/protocol.md`. Independent of the other gaps, but it removes the need
for the restarts that trigger `gap-resume-prunes-worktrees-story.md`, so land either first.
