**User story.** As the liaison, I want a restart to leave story worktrees alone, so that a
resume doesn't throw away every story's venv and cost each one a rebuild and a `uv sync`.

**What happened (2026-10-20, sprint 51).** Each restart of the runner for a config reload
removed the worktrees of the stories without a running step: "resume prunes non-in-flight
worktrees (s166's gone), so new worktrees hit the s157 venv bug" (`decisions.md:538`); after
the next restart "re-synced house-rules venvs in recreated worktrees" (`:541`), "synced
s165's recreated venv" (`:543`), "synced venvs" again (`:547`). Five stories ran in
parallel, so each restart cost five rebuilds plus the by-hand venv syncs.

**Cause (fact, read at 0e1e0991).** `Runtime.recover_stories` keeps only the stories with
`in_flight` set and calls `Workspaces.prune_stale` with that set
(`dispatch.py:1152-1158`). `prune_stale` removes every stored worktree not in `keep`
(`workspaces.py:77-89`) with `git worktree remove --force` and `remove_tree`
(`workspaces.py:53-60`), so ignored files go with it. The story's next step calls
`Workspaces.ensure`, which runs `git worktree add` afresh (`workspaces.py:38-46`). The
docstring says "I3: prune stale worktrees"; with story branches a worktree of an open
sprint story is not stale.

**Placement:** Product Backlog. Files: `dispatch.recover_stories`, `workspaces.py`, the
resume section of `reference/protocol.md`. Independent of the other gaps; land it before the
next sprint that is restarted mid-way.
