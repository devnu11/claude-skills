# s70: The suite runs in parallel with pytest-xdist

**Delivery:** cli (the agile-team runner's test suite and its commands).

## User story

As the human running the team, I want the suite to run in parallel, so that a
full run takes about 1 minute, not 4.

## Why

The liaison measured 233 s to 51 s on 10 cores. One test blocks it:
`test_process_groups.py::test_stop_stale_never_signals_the_runner` is
parametrized with `os.getpid()` and `os.getpgrp()`, so its test ID differs in
every worker and xdist refuses to run. Evidence:
`.team/run/liaison/reports/2026-10-12-time-spent.md`.

## Acceptance criteria

1. The runner's own pid and process group are injected into
   `sandbox.stop_stale`. The test passes fixed fakes, so its test ID is the
   same in every worker. It still proves the runner's own group is never
   signalled.
2. pytest-xdist is a dev dependency, with an ADR (no new runtime dependency).
3. The gate's coverage command and the targeted test runs use xdist. Coverage
   is still measured correctly across workers and stays at 95%+.
4. The suite passes under xdist, and a test or check shows no test ID depends
   on a live value.
5. `reference/protocol.md` and `SKILL.md` name the commands in the same story.
6. Ruff check and format clean.
