# s61: The runner halts when the checkout changes under it

**Delivery:** cli (the agile-team runner's checkout guard).

## User story

As the human, I want the runner to halt at once and escalate to me when anyone else changes the checkout it is running in, so no step, gate or commit ever runs on a tree the team did not make.

## Rule (human, 2026-10-11)

"I think we need the runner to make sure that the tree hasn't changed out from under us at every opportunity. And just halt as soon as we see that someone else is mucking with the code. This would be an immediate escalation to us."

## Acceptance criteria

1. The runner records the branch it runs on and the HEAD commit it expects. It updates them only through its own commits and boundary operations (including the sprint-boundary rebase of s59 and the hash rewrite).
2. It checks at every opportunity: on start and resume, before and after every step, before every gate, and before every commit. HEAD must be attached to the team branch, the branch must point at the recorded commit, and no git operation (rebase, merge, cherry-pick, bisect) may be in progress.
3. Any mismatch halts the run at once with its own halt kind. No further step, gate, commit, salvage or quarantine runs on the changed tree. The halt names what was expected and what was found: branch, commit, and the reflog entry that moved HEAD when there is one.
4. It is an immediate escalation to the human: a question in the outbox, `status` and `status_reason` saying so, and the dashboard showing it red.
5. Resume re-checks and halts again while the mismatch remains. The human can accept the current HEAD deliberately with an explicit command (for example after the liaison rebases the branch), and the runner records that acceptance.
6. Tests in a scratch repo, one per case: detached HEAD, branch switched, branch reset or moved, a foreign commit on the branch, and a rebase in progress. Each case halts before the next step. Never touch the real home directory.
7. Docs move with behaviour (`agile-team/SKILL.md`, `agile-team/reference/protocol.md`). Coverage stays at 95%+; ruff check and ruff format clean.

## Origin

2026-10-11 16:14:54: a dotfiles apply on the human's machine ran `git checkout --detach 92a38ea` in this checkout (a pinned-clone script; the pin had changed that morning). HEAD pointed at old main, which lacks about 230 of the team's commits. The runner did not notice. Every step from 16:14 to 17:11 ran on that old tree: the Quality Czar found s58's code "missing", s58 was rebuilt on old code and accepted at 16:44, and s4 was re-reviewed as unchanged. All of those results are void. The liaison stopped the team, kept the 12 stray commits on `stray/detached-1614`, put the checkout back on feat/agile-team-dashboard, and reset s58 to quality and s4 to implement. Priority: first in the order, ahead of s58.
