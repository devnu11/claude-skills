# s62: Liaison commands in the runner, and self-hosting tooling

**Delivery:** agile-team runner (CLI: `tell`, `watch`; resume; self-hosting script and doc).

## User story

As a human running the team, I want `agile-team tell` and `agile-team watch` in the runner, and a documented way to run the team on a pinned copy of the runner it is changing, so the liaison needs no private shell scripts and any user gets the same tooling.

## Rule (human, 2026-10-11)

Process lives in code, not in private scripts. Put this story right after the checkout guard (s61) and the stories already in progress (s58, s4, s43), which keep precedence. The liaison will use these commands for this very run (dogfood).

## Background

The liaison runs the team with two private shell scripts in the gitignored `.team/run/liaison/`: one resumes the run with a message for the PO, the other wakes the liaison when the PO writes or the status changes. Any human using agile-team needs both. Only one part is specific to this repo: running the team on a pinned copy of the runner it is changing.

## Acceptance criteria

1. `agile-team tell <file>` (or `-` for stdin) queues a message for the PO. The text is stored under `.team/run/liaison/messages/` and never goes on a command line (a role's `pkill -f` once matched a runner command line). A running router delivers it at the PO's next turn without a stop and resume, the way an answer wakes it (s47). A stopped run delivers it on `start --resume`.
2. `agile-team watch` blocks until something needs the liaison, prints one JSON line saying what it was, and exits. Triggers: a new outbox message; a change in the run's status (halted, waiting, budget, limit, interrupted, done); the live meter's health turning red once that story ships. It remembers what it already reported, so nothing is lost between two watches. `--timeout <s>` gives a heartbeat line. It spends no tokens.
3. `start --resume` after an interrupted step works from the dirty tree without any wrapper. If s9's salvage already covers this, test it and say so in the docs. Today the liaison's wrapper stashes leftovers first.
4. Self-hosting, development only, committed: a script (for example `agile-team/runner/scripts/pin-runner.sh <commit>`) that builds a pinned runner copy under `.team/run/` from an accepted commit and writes the commit beside it. Plus `agile-team/reference/self-hosting.md`: why the team must never run on the working copy (it edits the runner it runs on), when to re-pin (only accepted code, with the team stopped), and how an unattended job's resume command uses the pin. `.claude/` stays off limits to the team; the liaison points the human's `.claude/CLAUDE.md` at the doc.
5. SKILL.md's liaison section documents `tell` and `watch`, and an unattended job whose resume command is plain `agile-team start --resume`. Docs move with behaviour (`protocol.md`, README row). Coverage 95%+, ruff check and ruff format clean, and each command is tested in a scratch repo (never the real home directory).
6. `watch` and `tell` must coexist with s61: a message queued while the guard has halted the run is stored and delivered after the human accepts the checkout.

## Done means

The liaison can delete both private scripts. Its `LIAISON.md` shrinks to run state only (job name, decision log, backups); the how-to lives in SKILL.md and self-hosting.md.
