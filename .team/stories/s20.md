title: Quality as code - house rules as linter rules and a lint/static gate at the quality step
delivery: cli
acceptance:
  - id: AC1
    text: >-
      The charter's house rules are machine-checked. Ruff rules cover argument counts
      (at most 2, constructors excepted), boolean positional parameters, docstrings on
      public functions and complexity. A small stdlib check (or a ruff rule, if one
      fits) flags functions longer than the agreed limit. Existing violations are
      either fixed or listed in a baseline file with a reason, so the gate passes
      today.
  - id: AC2
    text: >-
      The runner runs lint and static checks as a gate at the quality step, before the
      quality-czar runs. A failure bounces to the developer with the checker's output.
      The checks are configured in `.agile-team.toml` (toolchain), not hard-coded.
  - id: AC3
    text: >-
      The quality-czar's role rules are cut to judgement calls only: naming, DRY,
      table-versus-branching and docs moving with behaviour. It does not re-run the
      suite or coverage, which the gates already did, and it reads the gate output
      instead.
  - id: AC4
    text: >-
      DevOps owns this story; its role rules include building tooling that makes
      other roles cheaper. `reference/protocol.md` (quality gate) and SKILL.md are
      updated. An ADR records the rule set and any new dev dependency.
  - id: AC5
    text: >-
      Tests cover the gate pass and fail paths and the function-length check.
      Coverage stays at or above 95%, and ruff check and ruff format are clean under
      the new rules.
---

## User story

As the human, I want the house rules checked by tools instead of by eye, so
that the quality step is cheap and consistent and the quality-czar spends
tokens only on judgement.

## Notes

Human's cost review: the quality-czar uses about as many tokens as the
architect, mostly re-running the test suite and checking house rules by eye.
Priority 2. Owner: devops.
