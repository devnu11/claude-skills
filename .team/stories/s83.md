  - id: AC1
    text: >-
      The list. A Backlog tab lists every story that isn't done, in the runner's
      ranking (`state.order`, as the router uses it), in two groups: Current sprint
      (read-only) and Backlog. Each row shows its position, id, title, step, status
      and delivery, plus the hold reason when there is one. Cancelled and held
      stories are labelled; s80, for example, shows "cancelled".
  - id: AC2
    text: >-
      Details on click. A row expands and collapses on click. Expanded, it shows: the
      story file, rendered with story A's renderer (s15); the state fields (sprint,
      step, status, rounds, disputes, hold, developer, delivery, and commits); links
      to the design, review and acceptance files where they exist
      (`agile-team/docs/design/<id>.md`, `.team/reviews/<id>.md`,
      `.team/acceptance/<id>.md`); spend and turns from the ledger; the last 10
      events; open questions naming it.
  - id: AC3
    text: >-
      Safe file reads. Files are served read-only, by story id, only from
      `.team/stories/` and the three folders in AC2. Any other path is refused (s4's
      no-directory rule holds).
  - id: AC4
    text: >-
      Reordering. A backlog story can be moved up, down or to the top, or dragged. A
      current-sprint story has no handle, and a request to move one is refused.
  - id: AC5
    text: >-
      Applied by the runner, through the PO's code. The request: the dashboard queues
      a reorder request (story, position, and the order version it saw) in the run
      directory. Applied by the runner: between steps, using `Priority.with_move` and
      `move_refusal`. It's recorded as a `priority` event with source "human
      (dashboard)", and the PO is told at its next turn. Stale requests: a request
      against a changed order is refused, and the tab says "reload".
  - id: AC6
    text: >-
      The PO keeps the human's order. A PO `prioritise` or `move_story` that changes
      the human's backlog order is refused unless it gives a reason, which is recorded
      in the `priority` event.
  - id: AC7
    text: >-
      Localhost-only writes. Writes are accepted only from 127.0.0.1 or ::1; anything
      else gets 403 (a test pins it). Reads are unchanged.
  - id: AC8
    text: >-
      Tests cover: the ranking shown, and the sprint-story refusal; the stale-order

      expand and collapse under the node harness (`tests/dashboard_node.py`).

## User story

As the human, I want a Backlog tab where I can read every outstanding story in
full and reorder the stories outside the current sprint, so I can steer the
backlog without asking for a report.
