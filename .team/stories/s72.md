# s72: A 1 second limit per unit test

**Delivery:** cli (the agile-team runner's unit-test configuration).

## User story

As the human running the team, I want each unit test to have a 1 second limit,
so that a slow test is a problem the team sees at once.

## Why

The human: a unit test over 1 s is a problem. Today hundreds of git-backed
tests would fail it, so this comes after s71, which removes real git, files and
processes from unit tests.

## Acceptance criteria

1. Every unit test (outside `tests/e2e/`) has a 1 s limit. A test that runs
   longer fails with a message naming it and the limit. `tests/e2e/` keeps its
   own, longer limit.
2. The limit is configuration (one place), replacing the 30 s per-test timeout
   for unit tests only.
3. No test is skipped, weakened or deleted to meet it. A slow test is fixed
   (injected clock or sleep, fake instead of real) or moved to `tests/e2e/`.
4. `reference/protocol.md` and the unit-tester role text state the limit in the
   same story.
5. Coverage 95%+; ruff check and format clean.

## Notes

Runs after s71. Do not start it earlier.

Human message t2, item 5.
