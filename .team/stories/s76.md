# s76: Unit tests touch no process, signal or network (s71 phase P2)

**Delivery:** cli (the agile-team runner: `system.py` P2 rows, the modules that call them, the unit tests).

## User story

As the human running the team, I want the process, signal and network calls
behind the same seam as files, so that unit tests of the sandbox, git and the
dashboard server touch nothing real.

## Why

Second of three phases of the s71 split. The scope, the `system` functions to
add, the modules to convert, the tests to migrate and the e2e rows are the
**P2 row of "Phases" and the P2 checklists in `agile-team/docs/design/s71.md`**.
Do not restate them; read that design. The plan is
`.team/run/liaison/plans/unit-test-isolation.md`.

## Acceptance criteria

1. **Inherited from s71:** the P1 modules s71 left unconverted (`results`,
   `po_session`, `onboard`, `presentation`, `paths`, `gates`,
   `dashboard/snapshot`, `dispatch`, `router` file call only, `checkout`,
   `stack`, `runner_tools`) convert here with the tests of AC2, via the P1
   `system` rows in the design.
   The P2 `system` functions exist (thin, no logic) and the P2 modules call them
   as `system.<name>(...)`: `process_groups`, `commands`, `sandbox`, `kill_check`,
   `live`, `dashboard/server`, `guard`, `git_ops`, `upstream`, and `cli`'s one
   `DashboardServer(...)` call site.
2. **Inherited from s71:** the P1 "at least" test files that s71 left in
   `LEGACY` (list in `.team/stories/s71.md`, "Rulings") migrate here, first.
   Then the P2 unit tests listed in the design run in the fake world and leave
   `LEGACY`; `test_s70_ids`, `test_dashboard_ui`, `test_dashboard_live_ui` and
   `test_docs_commands` move whole to `tests/e2e/`. No test is weakened,
   skipped or deleted; each keeps what it proves.
3. `tests/e2e/test_system_e2e.py` covers each P2 function on the real OS, with
   the P2 moves.
4. s41's G1 holds through the seam (O17): only `system.py` calls `os.killpg`.
5. **Moved from s50 (AC10, human message t9):** a CI check (grep or AST) keeps
   `pkill` and `killall` out of the repo's own code and scripts. The guard's
   test tables (`kill_check` cases) are the only allowed place. One test proves
   the check fails when a file outside those tables uses either word.
6. Docs move with behaviour; coverage 95%+; ruff check and format clean.
