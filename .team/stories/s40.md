## User story

As the human, I want the order in which the team works to be an explicit,
visible list that the router follows, so that the board shows what will run next
and "do s30 before s29" is a rule in code, not a hope in prose.

## Notes

The human: "Board doesn't seem to reflect the order the PO is executing. In the
design column the order is: s27, s29, s30, ... but the architect is working on
s29." Priority is also the thing to use for the human's stated order of work:
gate fixes first (s24, s30, s26, s27, s29), then the bug stories (s37, s38), then
the features.
