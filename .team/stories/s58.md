# s58: The Customer Proxy's sandbox can reach the local service it is asked to accept

**Delivery:** agile-team runner (sandbox settings, e2e gate).

## User story

As the human, I want the Customer Proxy to be able to curl the delivery's local service from inside its OS sandbox, so a story is judged on the product and not bounced for "connection refused".

## Acceptance criteria

1. `os_sandbox_settings` (the section `sandbox._sandbox_section` builds) sets `network.allowLocalBinding: true` for service deliveries (web and dashboard kinds, whatever the delivery table calls a delivery with a local service). Deliveries without a service keep the filesystem-only section.
2. An e2e test curls a live local service from inside the Proxy sandbox, built from the real sandbox section and the runner's bundled claude CLI where the suite can run it, and gets 200. The same test shows that, without the setting, curl fails with exit 7 (so the test would catch a regression). If the OS sandbox cannot run in CI, the test is skipped with a stated reason on that platform only, and a unit test pins the section's `network` key.
3. The `os_sandbox_settings` docstring no longer says the OS sandbox was never verified end to end; it says what the e2e test verifies.
4. The Proxy's service lifecycle is stated in docs: `Trial.liveness` stops its probe service by design and the Proxy relies on `plan()` starting a fresh one (s26). The finding is checked: no step between plan and the Proxy's curl stops the service.
5. Docs move with behaviour (`agile-team/SKILL.md`, `agile-team/reference/protocol.md`). Coverage stays at 95%+; ruff check and ruff format clean.

## Origin

2026-10-11, liaison finding on m53 (s4's repeated "connection refused", curl exit 7 on 127.0.0.1:8799). Reproduced with the bundled claude CLI and the sandbox section the runner builds (filesystem rules only, no `network` key): curl to a live dashboard fails; the same curl outside the sandbox gets 200. Adding `"network": {"allowLocalBinding": true}` returns 200; `"network": {"allowedDomains": ["127.0.0.1", "localhost"]}` does not help. Priority: ahead of s4's next e2e.
