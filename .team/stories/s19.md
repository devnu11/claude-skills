title: Routing in code - the runner moves stories through the pipeline; the PO handles only judgement
delivery: cli
acceptance:
  - id: AC1
    text: >-
      The runner drives each sprint story through the fixed pipeline itself. After a
      step passes its gate, it starts the next step's role with a standard brief that
      points at the story, the design, the review file and the previous handoff,
      without a PO turn.
  - id: AC2
    text: >-
      The runner hands control to the PO only for judgement: a handoff with
      `open_questions`, `blocked` or `failed`; a step that needs a brief beyond the
      standard one (a bounce reason it can't pass on as is, a quarantine to reuse); a
      round cap, which needs a Manager ruling; sprint end; new human messages. The
      rule for when to hand over is a data table, not branching.
  - id: AC3
    text: >-
      On a bounce, the runner passes the gate reason or the reviewer's summary to the
      role the story bounced to, and the review file path, in the standard brief.
  - id: AC4
    text: >-
      The specialisation for developer steps comes from the design (the architect
      names it in a parseable field), with `developer` as the fallback. The PO can
      override it per story.
  - id: AC5
    text: >-
      The scribe runs automatically after each story reaches done, and the Manager
      still runs where the protocol requires it (sprint start, model overrides,
      budget checkpoints).
  - id: AC6
    text: >-
      Once this lands, the product-owner role defaults to Sonnet in its role file.
      `roles/product-owner.md`, `reference/protocol.md` and SKILL.md describe the
      split.
  - id: AC7
    text: >-
      Tests cover automatic advance, each hand-to-PO trigger, bounce briefs, the
      specialisation choice and the automatic scribe run. Coverage stays at or above
      95%, and ruff check and ruff format are clean.

## User story

As the human paying for the run, I want the fixed pipeline routed by code and
the PO used only for judgement, so that the most expensive role stops spending
Opus turns on mechanical routing.
