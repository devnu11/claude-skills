# s98 (A6a): every agent's tool calls are recorded, the PO's included

**Delivery:** cli

Plan: `.team/run/liaison/plans/tool-flow.md` (human-approved 2026-10-13, about 02:15). Its sections "The names of the tools are data" and "Readability" are context for the Architect. Each AC's [tag] is its acceptance environment.

## User story

As the human, I want every tool call an agent makes, the PO's included, recorded with its start, its awake duration and its reason, so I can see where each agent's time goes.

## Acceptance criteria

- **AC1 [cli]. Spans.** When a tool call's result arrives, `live.Reading` writes one span to `.team/run/tools.jsonl`:
  - who: role, story and step (`po-session` for the PO);
  - what: the tool, its `tool_use_id`, the label (AC2) and the detail (AC3);
  - when: the start (wall and monotonic) and the awake seconds;
  - how it ended: ok, error or timeout.

  A step or PO session that ends with calls still open closes them as "unfinished". Parallel calls are separate spans.
- **AC2 [cli]. Labels.**
  - A call to a named tool is labelled with that name: a built-in stage, a repo `[[tool]]`, or a PO MCP tool such as `po.run_role` or `po.open_story`.
  - Any other call is labelled `Dev: <reason>`. The reason is the Bash `description` when given; otherwise it's the tool name and its target (`Dev: Read`).
- **AC3 [cli]. Detail.** The detail is the first 80 characters of the Bash command, file path or pattern. Values of environment variables named like `*TOKEN*`, `*KEY*` or `*SECRET*` are masked, and a test pins this.
- **AC4 [cli]. Model time.** Each `step-end` and `po-session` event gains:
  - `tool_s`: the union of its spans, so parallel calls count once;
  - `model_s`: its awake time minus `tool_s`.

  For the PO, the time inside `po.run_role` (waiting on a whole step) is reported separately as `waiting_s`, so the PO's own model time is clear.
- **AC5 [cli]. Tests pin:**
  - a call to its result;
  - two parallel calls (union, not sum);
  - an unfinished call;
  - a named versus a `Dev:` label;
  - masking;
  - the PO's `waiting_s`;
  - awake time across a faked sleep.
- **AC6 [cli]. Gathering negligible calls.** Every span is still written to tools.jsonl, so `tool_s` and `model_s` stay exact.
  - For each step (and each PO turn), the snapshot takes the step's calls from shortest to longest, and gathers them into one `misc` entry while their combined awake time stays under `[dashboard] collapse_under_s` (default 0.1).
  - The first call that would bring the total to the limit or over, and every call longer than it, is shipped as its own span, in its place on the timeline.
  - Misc gathers calls from anywhere in the step, so it has no start time of its own. It carries its call count, its combined seconds (under the limit by construction) and its count per tool.
  - A test pins: the shortest calls are gathered up to the limit; the next call stays separate; the totals still match tools.jsonl.
