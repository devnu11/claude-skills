# s51: Finish started stories before starting new ones

**Delivery:** agile-team runner (priority, router, dashboard).

## User story

As the human, I want stories already in progress to route before stories not yet started, so work is finished before more is opened and nothing sits half done.

## Acceptance criteria

1. A story in progress (past design, or with steps run this sprint) always routes before a story not yet started. The PO's order ranks stories within each group.
2. This replaces the s40 rule P2 (design `agile-team/docs/design/s40.md`), where an explicit position beats in-progress and in-progress only breaks ties between unlisted stories. The ranking function, its docs and its tests change together.
3. The PO can still pull a not-started story ahead of in-progress ones on purpose, but only with a reason. `move_story` and `prioritise` take that reason and the runner records it as a `priority` event the dashboard shows in the timeline. Without a reason the pull-ahead is refused.
4. A held or blocked in-progress story does not stop a not-started story from routing (it is skipped as before, P4).
5. The board still shows `#<position>` per card, now the position in the new ranking.
6. Coverage stays at 95%+; ruff clean; SKILL.md, protocol.md, the product-owner role file and ADR-0016 updated.
