Asked for by the PO (m202); the cause found by the liaison (2026-10-15 07:10), not the Manager's load or ports guess. ACs written by the liaison.

**What happened.** `tests/test_s151_conflict.py` (s151's unit tests) uses `tmp_path`. In a unit test the OS guard raises `RealOsCall` inside pytest's own `_pytest.tmpdir` fixture. That leaves pytest's fixture state broken (`assert not self._finalizers` in `_pytest/fixtures.py`), so every later test in that xdist worker errors at setup with a bare `AssertionError`. Which 120 to 250 tests fail depends on how tests land on workers, which is why the set changed between runs and the files passed alone. It held s150, s152 and s153 and stopped the run at 04:45. Reproduced by running `tests/test_s151_conflict.py` with `tests/e2e/test_liaison_e2e.py`; the full suite without that file has no setup errors.

## User story

As the human, I want one bad unit test to fail alone, with its real error recorded, so a single test can't halt every story's gate and the cause is visible without digging.
