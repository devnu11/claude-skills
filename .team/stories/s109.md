# s109: Bug: the dashboard splits one model into two rows (an alias and an exact version)

**Delivery:** dashboard

## User story

As the human, I want one row per model family in the charts, so the same model is not counted twice under its alias and its exact id.

## Context

"Time by Model" lists `sonnet` 16 h 54 min and `claude-sonnet-5-5` 6 h 42 min, plus `opus` and `claude-opus-5-5`, and the same for haiku. Step-end events from before 10-12 11:37 record no model, so the chart falls back to the configured alias, while newer ones record the exact id. The ledger records only the alias. The human confirms all of it ran on the 5.5 models.

## Acceptance criteria

- **AC1 [dashboard].** Every chart that groups by model ("Tokens by", "Spend by" and "Time by" Model, and the Flow boxes' model line) groups by model family: `opus`, `sonnet`, `haiku`, or the configured alias for anything else. An alias and every exact id of the same family count as one row.
- **AC2 [dashboard].** A family's tooltip lists the exact ids seen under it, with each one's share. Steps with no recorded model show as "version not recorded".
- **AC3 [dashboard].** History isn't rewritten: events.jsonl and the ledger stay as they are. The family mapping is one table in the dashboard code, with a test pinning alias + exact id = one row, and an unknown model as its own row.
