## Environment: cli

What I had: the demo repo in `presentation/workspace/` and the installed `agile-team` command. The test sources were not in the workspace, so I judged the test criteria from `test-output.txt` (exit code 0, all dots) and the docs.

- **AC1 pass.** Protocol "Pending tests" says every gate and full-check run writes JUnit XML. It says results are read from the report, not the text, and the text is kept for briefs. The documented `[toolchain.report]` option is `--junitxml={file} -o junit_family=xunit1`. The AC names `{report}`, but `{file}` is the path placeholder and `{report:<root>}` marks where the options go, so the behaviour matches. Named runs write no report.
- **AC2 pass.** Protocol: the pending set is the failed ids that are new or changed in the step's diff. Other failures fail the gate with `these tests fail but are not new or changed in this step…`. Only the runner writes `.team/pending-tests.json`, and agent writes are refused. The demo registry `{"s125": ["tests/test_new.py::test_added"]}` has the documented shape.
- **AC3 pass.** Protocol: the implement gate removes ids when all passed. Otherwise it fails with `pending tests of sN still fail: …`. Full runs skip pending ids and count `pending (sN): k`. I ran `agile-team --repo . pending-tests`. It printed `--deselect=tests/test_new.py::test_added` and exited 0.
- **AC4 pass.** Protocol "Afterwards": the story's tests run like any other in review and quality, and a failure fails as usual. This is covered by `test_s125_leaving.py`, which is in the passing run.
- **AC5 pass.** `agile-team.yml` and `unattended.yml` run `agile-team pending-tests` and pass the result as `PYTEST_ADDOPTS`. Both list `.team/pending-tests.json` in `paths`. The protocol says the registry is committed. The demo's `.team/pending-tests.json` is present.
- **AC7 pass.** `test-output.txt` shows the whole run passing with exit code 0 (123 tests), and `ruff-output.txt` is clean. I could not inspect the individual test names because the test sources are not in the workspace.
- **AC8 pass.** `developer.md` has a pending-tests paragraph: its gate runs its own ids, skips others, and the runner removes ids on pass. `unit-tester.md` has a "Pending tests" section that says never write the registry and never mark a test `skip` or `xfail`. The protocol repeats "Agents still never mark a test skip or xfail. Only the registry skips."
