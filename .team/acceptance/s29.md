# s29 acceptance (cli, round 0)

Method: black box. I ran `agile-team --repo workspace status` on the presented upstream-less repo. I read the presentation, the protocol section, the ADR and the captured test and ruff output. A live run against a real remote was not possible; the team says it did not do one either. Most criteria are therefore judged from the documented behaviour plus the captured passing suite (exit 0, 100% of tests passed) and clean ruff (exit 0).

| AC | What I did | Result |
|---|---|---|
| AC1 | Read "Start / sync": fetch, then `git merge --no-edit` of origin/main. No commit if nothing is new. The team branch is never rebased. A conflict is aborted and handed to the PO as `sync_conflict` with the files. | Pass (documented, test-evidenced) |
| AC2 | Read the full-checks and failure rules: lint, static, test, coverage and e2e. A failure becomes a DevOps fix step with the output quoted. A repeat failure escalates to the Manager. | Pass (documented, test-evidenced) |
| AC3 | Read the end-of-sprint review step. It runs in a separate worktree `.team/run/review/`, rebuilt on the latest main, with checks, and nothing is pushed until the checks pass. The team branch is untouched. The branch is built by cherry-picking onto main rather than by `git rebase`. The result is equivalent and drops commits already in main. | Pass |
| AC4 | Read the stack rules: one entry per sprint, rebuilt in order, bottom and newest checked, recorded in `state.json` `upstream.stack`. `status` shows the `upstream` block (empty stack, as expected with no sprint ended). | Pass |
| AC5 | Read the draft and ready rules, the CI draft skip, and retarget on merge. The merged PR is dropped at the next sync. | Pass (documented only; not run live) |
| AC6 | Read the permission rules: `push_permission` is asked once and `set_push_permission` records it. `status` shows `"push": "unasked"`. With "no" the branches stay local. Only review-prefixed branches are pushed, never the team branch, and the only force is a lease. | Pass |
| AC7 | `status` on a repo with no origin returns cleanly with no error. The boundary is documented as skipped with a note when there is no remote or no `gh`. | Pass |
| AC8 | The protocol section and ADR are present. The suite passed and ruff check and format are clean (112 files). I could not view the dashboard stack view, the README row, SKILL.md or the role files from this sandbox. | Pass, with that gap |

Caveat: the multi-sprint, real-remote behaviour (AC3 to AC6) is evidenced only by the team's automated tests, not observed by me.
