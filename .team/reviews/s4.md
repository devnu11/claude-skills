## Nits (do not bounce)
1. **`_stream` catches too narrowly.** On a client disconnect, macOS can raise `OSError(EPROTOTYPE)` and Windows can raise `ConnectionAbortedError`. Neither is caught, so socketserver prints a traceback to stderr. The connection is still closed and the thread still ends, so nothing leaks. Suggestion: catch `ConnectionError` plus `OSError`. In my probe 5 clean disconnects gave no traceback.
2. **Malformed input can crash `build()`.** A hand-edited REQ file with `covers: 5`, or a ledger line with an unknown key, raises `TypeError`. `/api/snapshot` then drops the connection, and every SSE reconnect fails until the file is fixed. `covers: "REQ-1"` doesn't crash but yields a list of single characters. D3/D6 don't cover these cases. A `try` around each section, falling back to its empty value, would harden this. The runner's own ledger reader would fail on the same ledger line, so this is not a regression.
3. **`_stat` catches only `FileNotFoundError`.** `NotADirectoryError` or `PermissionError` on a watched path would end the stream. This is unlikely.
4. **The browser opens the hostname URL.** `webbrowser.open` uses `http://<hostname>:port/`. On hosts where the machine's own name doesn't resolve locally, the tab fails to load. Opening `localhost` while printing the hostname would avoid this. The human reports it works on their setup.
5. **`index.html` packaging is implicit.** It relies on the build backend's default package-data inclusion. That is fine with `uv run`; check it if the runner is ever built as a wheel.
