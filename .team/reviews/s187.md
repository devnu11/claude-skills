## Findings

### F1 (blocking): `tests/e2e/test_s187_gate_fix_e2e.py` does not exist (s187/AC1, AC2, AC3; REQ-257, REQ-258, REQ-259)

The design lists it under "Files" and in the last test checklist item. The story's `## Tooling`
section (lines 88–90) names it for all three ACs: "both run by the test command". It is not in the
tree, and `git diff --stat dfbb75fe..HEAD -- agile-team/runner/tests/e2e` is empty. The Tooling
claim is false as it stands.

The missing test matters most for AC1. The unit test
`test_the_gate_fix_brief_and_prompt_end_with_the_tree_section` checks the brief against
`rt.config.repo`. That runtime is not a story view (story branches are off, and `worktree_of`
is set by hand in the other tests). So no test shows that the path in `Tree:` is the **story's
worktree** and not the main checkout. s181 failed exactly there. The E2E checklist item ("the
`step-start` brief holds the gated short sha and the worktree path") would cover it.

AC3 has the same gap end to end. `manager_view` is tested on a hand-built `StoryState`, but no
test reads `repeated_setback.fix_rounds` from the Manager's context after a real escalation from
two empty `done` handoffs.

Fix: add the E2E test as specified (an implement gate routes an e2e failure to the
integration-tester, then two empty `done` handoffs, then the Manager context's `fix_rounds` with
`commit: "none"`). It should assert that the brief's path is the story worktree's path. Or,
if E2E is out of reach, add a unit test through `get_story_view`/`run_in_worktree` with story
branches on that asserts this, and correct the story's Tooling lines.

### F2 (minor, no AC): a pre-s187 fix gets stamped with a later head after an empty done

`_mark_gated` runs on every routed outcome, including the G5 re-queue. For a fix queued before
s187 (`gated == ""`), the first empty `done` gives the reason "the gate ran on an unrecorded
commit". `_mark_gated` then stamps the fix with the current head, so the next brief says "The
gate ran on commit <head>". That commit is not the one the gate ran on. This only affects fixes
already queued when s187 lands, so it can wait. A fix would be for `find_unchanged_fix`'s fixes to
skip the stamp, or to stamp them with a sentinel.

### F3 (minor, DRY, no AC)
