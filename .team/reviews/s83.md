## Function by function

### `priority.py`

- `Reorder.source` / `Reorder.event_data`: moved from `po_tools._priority_data` and adds `source`. The old helper is deleted, so there is no duplicate. Tested for both sources.

### `dispatch.Runtime.reorder`
Same body as the old `Tools._reorder`, with the role taken from `SOURCE_ROLES`.
It is the one apply path for the PO and the dashboard. Tested
(`test_runtime_reorder_applies_logs_and_returns_the_queue`, and the PO and Desk
event tests).

### `backlog.py` (pure)
- `order_version`, `View.of`, `View.placement`: B1, B10, B13. I checked
  placement by hand on interleaved queues: up, down and top all land on the
  target row's queue slot. Tested, including the version changing when a story
  joins the sprint.
- `label`: B3. It is parametrized over cancelled, the case and whitespace
  variants, held and free.
- `stale_refusal`, `sprint_refusal`, `place_refusal`: B12. `place_refusal`
  rejects `bool`, `str`, `float`, `None`, 0, len+1 and -1. Tested.
- `guarded`, `human_refusal`: B17. Changes outside the guarded projection pass,
  and the moved-ids text is exact. Tested. The defect is S3 above.

### `reorders.py`
- `parse_ask` / `_ask`: B18 shape check. Non-object, missing key, bool
  position, bad id and a version over 64 chars are refused. Tested.
- `Request.to_json` / `from_json`: round trip, and bad JSON or shape gives
  `None`. Tested.
- `Requests.queue` / `_publish` / `all` / `_numbered` / `_read` / `pending`:
  draft plus hard link, moving on to the next N after a clash, and the draft
  removed in `finally`. Tested (numbered files, clash, unreadable files, no
  folder, settled).
- `told_section`: B15 exact. Tested.
- `Desk.apply` / `_settle` / `_refusal` / `_move` / `_told`: B11–B13. The
  refusal order is right, and `first_refusal` is lazy, so `placement` runs only
  after the place check. Tested: the sprint story and stale requests leave the
  order and events unchanged, two requests from one version make the second
  stale, a pull is recorded, number order is kept, a settled request is not
  applied again, and the exact `TOLD` line is written.
  - Note, not a defect: when the tier groups keep a story elsewhere (for
    example, a held story moved to place 1), the `TOLD` line still says "moved
    to backlog place N". `human_order` records the real result, so the rule
    stays sound. The human sees the real place in the next snapshot.
  - Note: `Requests.all()` reads every request file on every tick and in every
    snapshot, and the folder only grows. That is fine at human click rates.
    Pruning settled files later is a possible follow-up.

### `dashboard/story_files.py`, `server.py`, `snapshot.py`
- `FOLDERS`, `_file_of`, `path_of`, `read`, `existing`: B6/B7. The path is
  built only from the table and a checked id. Tested: `..`, absolute path,
  `s1/..`, unknown kind, unknown story, a missing parameter, and a directory
  named `s1.md` all get a 404. A done story is still served.
- `_file`, `may_write`, `_body`, `_reorder`, `do_POST`, `POSTS`,
  `with_token`, `Body.status`, `nosniff`: B18. The order is host, then token,
  then body. Tests prove the body is never read on a 403 (`wire.reads == []`),
  and they cover `::ffff:127.0.0.1`, an empty app token, a non-ASCII token,
  oversize and malformed lengths, and a POST to another path (404). CSRF from a
  browser is also blocked: the custom header forces a preflight that the server
  does not answer.
- Snapshot `_run`/`_story`/`_reorder`/`_reorders`/`watched_files`: tested
  (statuses, the last 20, keys, no token in the snapshot, events, request file
  or crash log). Nit: `_reorder` uses a nested conditional where the charter
  prefers a table. It is optional.
- `test_server.py`: `POST` was dropped from the "method not allowed" list.
  That is legitimate, since POST is now routed, and the 404 for an unknown POST
  path is pinned elsewhere.
