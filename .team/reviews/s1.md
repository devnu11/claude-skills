## Defects

### D1 (must fix, developer-cli): a non-scalar `status` crashes the parser (s1/AC1, REQ-001)
`_status_lines` runs `found in {s.value for s in Status}`. When the YAML is
`status: [active]` or `status: {a: 1}`, `found` is a list or dict, and
`list in set` raises `TypeError: unhashable type: 'list'` (I confirmed this in
Python). A single mistyped requirement file then crashes:
- `requirements check`, which prints a traceback instead of the JSON and a `bad_status` line;
- the design gate inside `Pipeline.evaluate`, for any story that a REQ file touches
  or doesn't touch, because `load` parses every file;
- `_attach_requirements` in dispatch, for every architect, code-reviewer and proxy brief.

AC1 requires that "parse errors name the file and the problem". Fix: compare against a
tuple or list (`found in tuple(Status)`), or check `isinstance(found, str)` first.
Add a test with `status: [active]` (and a dict) that expects the exact `bad_status`
line. The other field checks are safe: `_id_lines` uses `==`, `_title_lines` uses
isinstance, and `_covers_lines` uses isinstance.

### D2 (must fix, unit-tester): `test_a_bounce_counts_a_round` no longer checks a round (s1/AC3, s1/AC7, REQ-003)
Fixup 2e2a7b6 replaced `story.rounds == before + 1` with `verdict is BOUNCE`. That
assertion duplicates `test_checked_story_with_untraced_ac_bounces_to_design`, and
the test's name now claims something it does not check. Design checklist 10 asks
for "a round". The developer's point is valid: `evaluate` doesn't count rounds,
`_bounce` does. The fix is to drive the bounce through the runtime step path that
applies the outcome (as `test_s95_dispatch` does with `step(rt)`) and assert
`story.rounds == 1` and `story.step == "design"`. Don't drop the assertion. As it
stands, nothing pins that a trace bounce costs a round.

### D3 (must fix, unit-tester; architect to confirm): the s95 assertion change names no rule and hides an s95 conflict (s1/AC4, REQ-004)
Fixups 2e2a7b6 and 85fd2bb changed `"- AC2:" not in prompt` to
`not in described(prompt)`, which first drops every line ending in `": untraced"`.
No rule was named. The rule that would justify it is design T13: the proxy's brief
gains `coverage_section`, which lists **every** AC of the story. But that rule also
shows a real conflict. s95 gives the Proxy only the ACs of the environment under
test, and `customer-proxy.md` says "Try only the criteria your prompt lists". The
Proxy for `cli` now reads `- AC2: untraced` (or `- AC2: REQ-00N (…)`) in its prompt.
So the s95 property the test guarded is now false in the product, and the test was
adjusted to stop seeing it.

The filter is also narrow. If AC2 were traced, the line would read
`- AC2: REQ-001 (title)` and the test would fail again. It passes only because the
scratch repo has no requirements. My recommendation is to list only the ACs the
step tries in the proxy's `coverage_section`, or to change the section's line
format so it can't be read as a criterion list. Then restore the original assertion
or name the rule. If the architect decides the full list is intended, the handoff
must cite T13 in `asserts`, and the proxy role text must say which list to try.

### D4 (should fix, integration-tester): the tab's behaviour is untested (s1/AC5, s1/AC7, REQ-005)
`test_s1_tab.py` only greps the page source: `'story.trace === "exempt"' in body`,
`"Boolean(" in body`, and so on. Design checklist 19–21 asked for node-harness
tests (`tests/dashboard_node.py`): an exempt sprint story's untraced AC shows
`designed before s1`, is left out of "Gaps in sprint" and the tab badge, and a
checked story's AC still counts. The module docstring says rendering "moves to e2e",
but no e2e test covers it (`grep "designed before s1|isGap" tests/e2e` finds
nothing). A source grep would still pass if the `exempt` branch in
`coverageStatus` were unreachable. AC7 asks for "the tab with and without
requirements" to be pinned.
