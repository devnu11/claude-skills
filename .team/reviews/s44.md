# Review: s44 Live spend meter and runner health (round 0)

Verdict: **changes requested**. The Python core is solid and well unit-tested.
Two things stop it shipping:

1. A design gap: the PO's blocking tools give **false reds**. The human gets a
   desktop notification and the liaison is woken.
2. The design checklist's **UI (node) and E2E sections are missing**, and they
   are what AC10 asks for.

Scope reviewed: `b0c3cab` (design and docs), `30b7f21` (tests), `ab8e759`
(code), `cdac2c0` (test fixups). The s41, s43 and s62 fixups in between were
left out.

## Defects

### D1 (major, design gap): `wait_for_answers` turns the run red while it rightly waits for the human

`po_tools.wait_for_answers` polls for up to `DEFAULT_WAIT_S = 1800` s. It
runs inside the PO's query, so the PO meter is the innermost open meter. Its
`ToolUseBlock` is the open tool, and there is no chore. So `quiet_for` grows:

- R7 turns the run amber after 3 min: `no turn for 3 min while
  mcp__…wait_for_answers runs`.
- R5 turns it red after 10 min: `no turn for 10 min`.

Red fires the desktop notification, puts `⚠` in the tab title and fires the
`watch` `health` trigger. That happens on *every* question the PO waits on for
more than 10 minutes, which is the normal case. It is the "cry wolf" failure
that makes the alert worthless.

### D2 (major, design gap): a PO `run_role` step longer than 10 min leaves a red window after it

D7 nests meters. While the role step runs, the role meter is shown. Then:

1. `_emit_step_end` closes the role meter.
2. The `settle` chore ends.
3. The PO meter is innermost again. Its `last_turn_at` is the PO turn that
   *issued* `run_role`, before the step started.
4. Once the `ToolResultBlock` arrives, the tool is closed. `Reading` does not
   move `last_turn_at`, so `quiet_for` is now the length of the whole role
   step.
5. R5 is red (`no turn for 25 min`) until the PO's next `AssistantMessage`
   arrives, which takes seconds of model latency.

The server polls `vital_sign` every 1 s and `watch` every 2 s, so both see the
red. The result is the same false notification and the same false liaison wake
as D1.

Both D1 and D2 come from one fact: the quiet clock of an outer meter keeps
running while the runner itself is busy on its behalf. The design has no rule
for this. H5 lists only `settle` and `BoundaryRunner.step` as chores. The fix
is the Architect's to choose. Two candidate rules:

- **(a)** Run the PO's blocking tool bodies as chores, e.g. `pulse.doing("waiting
  for answers to q3")`. Do **not** do this for `run_role`: a chore silences
  the quiet rules and would hide a hung inner step.
- **(b)** Restart a reading's quiet clock when an inner meter closes, or when a
  `ToolResultBlock` closes one of its tools. For example, add a `quiet_since`
  next to `last_turn_at`, and have R5, R7 and R8 read it.

Rule (b) alone fixes D2. Rule (a) alone fixes D1. Each needs a unit test
(nested PO→role close followed by quiet; a wait tool open for 11 min stays
green).

### D3 (major, tests): AC10's UI and E2E tests are absent

The design's test checklist has a "UI (node …)" section and an "E2E
(`tests/e2e/`)" section. No test was added for either:

- `test_dashboard_ui.py` and `tests/e2e/test_dashboard_e2e.py` have no s44
  changes.
- `tokensPerMin`, `sparkline`, `fmt.age`, `restarted`, `pillText`,
  `smartPill`, `pillDetails`, `scopeTotals`, `flowClassLines` and `applyAlert`
  are never run.
- There is no test that a fake step process streaming then going silent goes
  green → amber → red over `/api/stream`.
- There is no test that SIGKILL of that process shows `the runner is not
  running` and then `heartbeat … old`.
- There is no test that the scope totals equal the ledger (F7).

Coverage is 99.6% only because coverage measures Python. The whole AC5, AC6
and AC7 surface is untested. F7 ("box totals match the ledger") is an
acceptance criterion with no test at all.

### D4 (minor): H3 and H5 wiring is not asserted

The `Pulse` unit tests are good, but nothing checks that:

- `cli._po_until_sigterm` calls `pulse.start()` and calls `pulse.end()` in
  `finally`. AC2 requires "marked ended when the runner exits cleanly", and a
  regression there would leave a `beating` file that goes stale and red after
  every clean run.
- `BoundaryRunner.step` runs as a `sprint boundary: <stage>` chore.
- `PoRun._collect` opens a PO meter and closes it, including on `ResultError`
  (D7).

These lines are covered by other tests, but their behaviour is not asserted.

### D5 (minor, ADR-0005): unescaped snapshot field in HTML

`smartPill` builds `class="pill smart h-${view.health.level}"`. The level
comes from the snapshot and is not passed through `esc()`. In practice it is
always one of the four levels, but the house rule is that every snapshot field
placed into HTML is escaped (or mapped through a whitelist, as
`flowClassLines` already does with `level`).

  `_section(cls, raw)` helper.
- `live.estimate` rebuilds the 4-tuple that `live._counts` already returns.

  `ToolUseBlock`. Pass `uses` through instead.
- In `health.RULES`, R5 and R8 have identical `words` lambdas. Name one
  `_quiet_words`.
- In `index.html`:
  - `short(role) + (story ? " on " + story : "")` appears twice in
    `pillText`. It is also in the pre-existing pill code.
  - `≈${cost == null ? "—" : fmt.usd(cost)}` appears in both `pillDetails` and
    `liveLines`.

All of these are small. Fold them in with the D1–D2 fix.

## Checked and fine

- I1 holds. A checkout halt inside settle runs `save_interrupted(CHECKOUT)`,
  then the re-raise runs `save_interrupted(ERROR)`. The second finds no meter,
  so there is exactly one `step-end`.
- The heartbeat is thread safe: all state goes through one lock, and `end`
  joins the thread before it writes `ended`.
- Gates run inside the settle chore, so a long test gate stays green (D2 of
  the design).
- The docs (SKILL.md localhost link, protocol heartbeat section, README row)
  and the fixture keys are present.
- The notification is asked for only after a user gesture and only in a
  secure context. A1 sets the title in every context.

## Note for the PO (not a defect)

`HALTED` includes `stopped`, so a *graceful* `agile-team stop` also turns the
run red and fires a notification. D4 of the design names `stop --now`. If the
human did not mean a deliberate stop to alarm, the Architect can split this
out while fixing D1 and D2.
