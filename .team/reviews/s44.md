`tests/e2e/test_dashboard_e2e.py` has no s44 changes. No other e2e file
touches the heartbeat or health. All six E2E items in the design's test
checklist are open:

5. `agile-team dashboard` prints the two URL lines.

AC10 names items 1, 2 and 4 explicitly. The unit tests prove the rules, but
only the E2E tests prove S6: a killed runner writes nothing, yet the server
still pushes red. **Owner: integration-tester.**

## Checked and fine

- `halt_kind` cannot leak into a later graceful stop. `PoRun` starts with
  `_set_status(RUNNING)` → `mark`, which clears it. The router's
  `_show_wait`/`_clear_wait` also go through `mark`, but only while the run is
  still advancing, never after a halt.
- `accept-checkout` (`mark(STOPPED, …)`) is idle, as R15 says. It is tested.
- A `ToolResultBlock` wakes only when it closes a tool that was open, so a
  stray result cannot hide a quiet model.
- `liveStep` hides the step only when the level is `idle`. With a step, the
  level is `idle` only through `resting`, because R10 is always green with a
  step. So a live step is never hidden by mistake.
