Commits reviewed: 57854d9 (design), d2cc8a4 (tests), 6faacfd (code), and the
fixups 6d598f6, f955cad, 9fa29f0, 9ee3a06 and 986a38a. The runner's coverage run

**Verdict: changes requested.** Most of the code follows the design closely.
These items block shipping:

1. **AC5 is not delivered.** `.agile-team.toml` and `.github/workflows/*.yml`
   are unchanged. Once this runner is pinned, reporting is **on** for this repo,
   because it uses `preset = "python"`. But `test` and `coverage` have no
   `{report:…}` placeholder, so `build` appends one ` {report}` (root `""`) to
   the **last** link of the `&&` chain only. Here is what follows at the next
   tests gate:
   - The agile-team link goes red, the chain stops, and no report is written.
     The gate bounces with `REPORT_MISSING`.
   - If the agile-team link goes green, the report holds only unattended cases,
     and their ids have no `unattended/runner/` prefix.

   As a result, every tests gate in this repo bounces. DevOps's part (design,
   "Not the developer's") has to land before or with this story. **Owner:
   devops.**
2. The design's test checklist is only partly done. P10 (real git), P14, P16 and
   AC6 (node harness) are missing or reduced. See "Test gaps". **Owner:
   unit-tester.**
3. There are three code defects, D1 to D3 below. **Owner: developer-cli.**

## Defects

| # | Where | Defect | Severity |
|---|---|---|---|
| D1 | `git_ops.Git.diff_lines` + `pending_tests.NEW_FILE` | `git diff` uses the human's config. With `diff.noprefix=true`, `diff.mnemonicPrefix=true` (`+++ w/x.py`) or `diff.dstPrefix`, no `+++ b/` line matches. `changed` is then `{}`, every new failing test is "real", and the tests gate bounces `NOT_PENDING` forever. Fix: pass `--src-prefix=a/ --dst-prefix=b/` (or `--default-prefix`) in `diff_lines`. Paths that git quotes (`+++ "b/t\303\251st.py"`, controlled by `core.quotePath`) also fail to match; `-c core.quotePath=false` covers the non-ASCII case. | medium |
| D2 | `pending_tests.changed_lines` | `path` is not reset on `+++ /dev/null` (a deleted file). That file's `@@ -1,n +0,0 @@` hunk is then credited to the **previous** file as `range(0, 2)`. Reset `path` to `""` on any `+++ ` line that is not `b/…`, or on `diff --git`. Low impact today: it can only wrongly touch a test that starts on line 1 of the previous file. | low |
| D3 | `dispatch.set_pending` / `PENDING_WHERE` | The commit subject is `chore(s1): pending tests (tests step)` / `(implement gate)`. The design's text (`PENDING_SUBJECT = "chore({story}): pending tests"`, "tests may assert them exactly") and protocol.md line 1424 say the subject has no suffix. Either drop the suffix or document it in the design and protocol.md. The charter says docs move with behaviour. `test_s125_runtime.py` asserts the suffix, so the unit-tester introduced it at the tests step without a design rule. | low |
| D4 | house rule "at most 2 parameters" | These functions take more than 2 parameters: `fullcheck._result(check, ran, judging, pending="")` (4), `gates.Checks._cleared(outcome, own, left)` (3), `gates._report_missing(outcome, folder, run)` (3). `fullcheck._result`'s defaulted `pending` could come from a small result object. | low |

## Test gaps (unit-tester)

- **P10:** the design asks for `changed_lines` on a real `git diff -U0` from a
  tmp repo (an added test, an edited line, a pure deletion, an untracked file).
  The test only uses a hand-written string. `ChangedFor` and `Git.diff_lines`
  are never run, which is why D1 went unnoticed. Add a real-git test, including
  a deleted file (D2).
- **P14:** add a cancel test and a revert test. Each should drop the entry, in
  one `chore(sN): pending tests` commit.
- **P16:** `Runtime.plan` sets `base` to HEAD; `_gating` serves the plan's story
  and base; the Stop hook's red check (through `_hooked`) sees an uncommitted
  new test file as touched, and its PASS writes no registry.
- **AC6 node harness:** pin no `Pending` for `pending: 0` and for a missing
  key, and the same bar and `% complete` with or without the key.
