## Defects

### D6 (tests): a hedged assertion in the worked example

`test_s51.py`, after `prioritise(["s21", "s45"], "")`:

```python
assert queue_of(t) == ["s21", "s38", "s45", "s50"] or queue_of(t) == [
    "s38", "s21", "s45", "s50",
]
```

The line above already pins `order == ["s21", "s45", "s50", "s38"]` and `pulled == []`, and
s38 has been released. G3 then gives exactly one queue. s21 and s38 are both `in progress`,
and s21 is listed 0 while s38 is listed 3, so the queue is `s21, s38, s45, s50`, as the
design states. The second branch is the queue the design rules out. If the code ranked s38
first here, the test would still pass. A test that accepts either answer pins neither. The
design's checklist item asks for each step "as the design gives them".

**Fix (unit tester):** assert the single queue `["s21", "s38", "s45", "s50"]`. If that fails,
the code is wrong, so send it to the developer rather than widening the assert.
