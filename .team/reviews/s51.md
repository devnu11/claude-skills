## Defects

### D4 (tests, still open): checklist items with no test

Nothing was added since round 1, so the gaps are the same:

1. **`start_sprint` while a started story is held** (checklist, PO tools): there is no test.
   `_begin_sprint` builds its order with `with_first`, so it is the third path for the D1
   bug. Only `prioritise` (line 478) and `move_story` (line 488) are pinned. Add a test like
   them: origin state, s38 held, `start_sprint` with `["s50"]`, then check `state.order`
   keeps s38 before s21, and that s38 is `#1` once released.
2. **The worked example, step by step** (checklist, last ranking item): no test chains the
   design's steps on one runtime. The steps are hold s38, `prioritise(["s50"])`, release,
   refused `move_story("s45", 1, "")`, `move_story("s45", 1, reason)`, two `prioritise`
   calls, `move_story("s21", 4, "")` with its note, then hold s38 and
   `move_story("s38", 1, "")` with the note `s38 ranks #2, not #1`. Check `order`, the queue
   and the notes at each step, as the design gives them.
3. **The `with_move` landing is not checked**: the rule 1, 2 and 3 tests assert only the
   returned order. The checklist also asks for the landing: rank the result with
   `Priority(new_order, pulled).queue(...)` and assert the story is at `position` when its
   group's block covers it. In `test_s51.py`, `.queue(` appears only at lines 105–107, 318,
   332, 485 and 495, and none of them is a `with_move` rule test.
4. **Misnamed test**: `test_a_refused_pull_is_returned_once_and_unknown_ids_are_not_pulled_on`
   (line 498) checks only the refusal text. Either assert what its name says (the result
   holds one refusal, and no `pulled`/`order` change for an unknown id), or rename it to
   what it checks.

**Fix (unit tester):** add tests 1–3, and fix the name or the asserts of 4. No code change
is expected. If a new test fails, send it to the developer.
