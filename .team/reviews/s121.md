## Functions changed

### `onBoard(view, s)` (index.html:2275), new
Tells whether a story is on the Board: `s.sprint === view.run.sprint && s.status !== "cancelled"`.
- **Defect (BD1).** The design says: "When `view.run.sprint` is null or 0, no story is on the
  Board." When `run.sprint` is `null`, every backlog story (`sprint: null`) matches through
  `null === null` and shows on the Board, in its step column or in Done. Design test 4 (set
  `run.sprint` to `null`, then expect no cards and no badge) will fail. Live data hides the bug
  today, because `RunState.sprint` is an int that defaults to 0 and story sprints are `None` or ≥ 1.
  But the rule is explicit, and old or edited snapshots can carry `null` (ADR-0006).
  Fix: guard on the run sprint, e.g.
  `const onBoard = (view, s) => Boolean(view.run.sprint) && s.sprint === view.run.sprint && s.status !== "cancelled";`.
  The design's own sketch has the same hole, so it isn't the developer's invention. The BD1 text
  still governs.
- Tests: `test_board_membership_is_current_sprint_not_cancelled` only checks that the source
  contains the substrings. No test exercises the null case.

### `boardColumns(view)` (2277), changed
Builds one column per pipeline step, then Done. Each predicate goes through `onBoard`. The Backlog
column is gone, and Done is limited to the current sprint (fixes the past-sprint pile-up). This
matches BD2.
- Tests: static substring checks only (`"backlog"` absent, `view.pipeline` and `"done", "Done"`
  present). Column order, the Done membership of story c, and the absence of d, e, f and g are not
  rendered or checked.

### `boardStories(view)` (2284), new

and a story whose step is off the pipeline (g) is correctly left out. It has a JSDoc.
- Tests: static only.
