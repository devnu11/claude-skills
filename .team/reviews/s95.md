## Defects (must fix)

### D3. The dashboard e2e test that the docstring names does not exist (integration-tester)

`tests/test_s95_dashboard.py`'s docstring says the behaviour checks "move to e2e:
test_envpills_render_each_mark_and_fall_back". No such test exists. A grep for `envpills`
across `tests/` finds only this file. What the static checks do not cover:

- `envPills` without `environments`, i.e. the fallback at `index.html:432`: an older snapshot
  shows `· <environment>` or nothing. Grepping source strings cannot check a branch.
- The rendered output for each `ENV_MARKS` row: the tone class, the ✓/✗ mark, the title text,
  and that an unknown verdict falls back to `""`.
- The `next` gate event's activity/timeline line ("tried; next environment").

The repo already has the tool for this. `tests/dashboard_node.py` `run_page(driver)` is used by
ten `e2e/test_s*_e2e.py` files (e.g. `test_s112_activity_page_e2e.py`). Add
`e2e/test_s95_env_pills_e2e.py` with those three checks, or fix the docstring if the Architect
rules them out. A docstring that cites a test that does not exist is worse than having none.
These checks are AC4's customer-visible half ("the dashboard shows the story's environments,
each marked pass or fail").
