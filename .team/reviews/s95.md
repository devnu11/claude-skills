## Defects (must fix)

### D1. Role files not updated (developer)

The design's module table lists `roles/customer-proxy.md` and `roles/integration-tester.md`,
and the story's s91 fold-in requires the tester change explicitly. Neither file changed in
any s95 commit:

- `integration-tester.md:25-35` still says "the runner creates `.team/run/presentation/<story>/`
  with a git `workspace/`". That is the old flat layout, and it now contradicts the prompt's
  "Presentations to build" section. If a tester follows the role file, it builds a flat
  presentation, every showing reports `NO_GUIDE`, and each round is lost. The file must also
  carry the s91 rule: the workspace holds the demo or evidence files themselves, not only an
  empty repo.
- `customer-proxy.md:33` still describes the report as "each criterion, …". The file needs:
  - one `## Environment: <name>` section per environment;
  - Read the report first, rewrite only your own section, keep the others;
  - try only the criteria your prompt lists;
  - for `manual`, the script goes in your section;
  - on any failure, hand off `changes_requested` with `failed_acs` and `next_role`.

  `brief_section` tells the Proxy this per step, but the role file is the standing contract.
  The charter says prompts state the rule. A missing section costs a NO_SECTION bounce and a
  round each time.
- The design's Docs checklist item "Role files: the developer's (module table)" is unchecked.
  `acceptance.py` is a new module and should be listed there.

### D2. Runner, router and dashboard checklist items have no tests (unit/integration tester)

`test_s95_acceptance_runs.py` only exercises `gates.Pipeline`. Coverage is 100% because older
tests run the new lines by accident, not because the new behaviour is asserted. The design's
"Runner" and "Dashboard" checklist items have no test for any of these:

| Behaviour | Code | Test |
|---|---|---|
| A Proxy step prepares the **due** environment alone (Order environment and source dir `<id>/<env>/`), and the 2nd step prepares `dashboard` | `dispatch._environment_for`, `_order` | none |
| The Proxy prompt lists only that environment's AC ids | `dispatch._criteria_section` | none (only the pure `brief_section` is tested) |
| The tester prompt gains "Presentations to build" | `dispatch._lay_out_presentation` | none |
| The gate event carries `environment`, `mark`, `failed_acs` | `dispatch._tried_fields` | none |
| No "Previous step" line after a `next` verdict | `router.QUIET_VERDICTS` | none |
| A `next` verdict hands nothing over and starts no setback | dispatch, hand-over | none |
| `envPills` for each `ENV_MARKS` row, the fallback without `environments`, `OUTCOMES.next`, the `next` activity line | `index.html` | none (no node test) |
| After a rework, the next two Proxy steps are `cli` then `dashboard` | dispatch with gates | only `tried == []` is asserted |

AC2 ("each step's sandbox is prepared from its environment alone; each brief lists only that
environment's ACs") and AC5 ("a rework re-runs both") are the customer-facing claims. They are
exactly the untested parts.
