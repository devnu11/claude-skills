## Round-0 defects: verification

### D1: `hard_link` swap and tell tests (fixed)
- `system.__all__` now lists `"hard_link"`. Because of that,
  `test_fake_implements_every_system_function` and `FakeSystem.install` now
  include it.
- `FakeSystem.hard_link(link, target)` does three things:
  - it checks for a full disk first (ENOSPC);
  - it reads the target, which raises `FileNotFoundError` when the target is missing;
  - it refuses an existing link (`FileExistsError`), then stores the bytes, copies the mode and records the op.

  `test_s71_tell.py` tests each of these behaviours.
- The relay-level tell tests moved from `test_s62_tell.py` to the fake world in
  `test_s71_tell.py`. All 8 removed tests have counterparts there:
  - write whole, unstripped, next-number, told order, no folder, lost race, unread;
  - "draft removed on failure" is now two tests, ENOSPC at write and a hard_link error at publish.

  No assertion was weakened. The lost-race test also checks that t1 is untouched and that the folder lists exactly `t1.md, t2.md`.
- `test_s62_tell.py` stays in `LEGACY`. What remains in it is cli- and
  runtime-level (`configured`, `make_runtime`, `tmp_path` note files), which is
  s76/s77 scope. That matches the PO ruling: the *relay* tell tests had to leave
  `LEGACY`, and they did.

## Non-blocking nits
- **N1:** `FakeSystem.hard_link` copies the bytes instead of sharing them, so a
  later write to one name does not show through the other. The runner removes
  the draft right after linking, so nothing depends on sharing. Worth a line in
  the docstring.
- **N2:** `FakeSystem.hard_link` reads the target through `read_bytes`, so a
  `deny`'d target raises `PermissionError`. A real link needs no read
  permission. This is the same fidelity gap as `replace`, already noted in round 0.
- **N3:** In `test_the_draft_is_removed_when_publishing_fails`, the ENOSPC
  happens at the draft *write*, not at publish, so the name misleads. Its first
  assertion (`isdisjoint`) is also implied by the second. The publish-failure
  case is covered by `test_the_draft_is_removed_after_a_publish_error`.
- The round-0 nits on `expand_user`, `make_dirs` under a file, `remove` of a
  directory, the `test_legacy_names_…` name, and the process-global guard flag
  still stand. None of them blocks.
