## Blocking defects

### D1: `system.hard_link` is missing from `__all__`, so the fake never swaps it, and the PO ruling is not met
`system.py:88` defines `hard_link`, and `Relay._publish` calls it (relay.py:119).
But `hard_link` is not in `__all__`, so:
- `FakeSystem.install` does not swap it, and `FakeSystem` has no `hard_link`.
  `test_fake_implements_every_system_function` cannot catch the gap, because it
  only iterates `__all__`.
- Any fake-world test that calls `Relay.tell` reaches the real `os.link`.
  The guard turns that into `RealOsCall`, and with a FAKE_REPO path it would
  fail anyway.
- The PO ruling in `.team/stories/s71.md` says: "The relay tell tests then
  leave `LEGACY` in this story." `test_s62_tell.py` is still in `LEGACY`, still
  uses `tmp_path`, and still patches `Path.hardlink_to` (line 85).

Fix:
- **Developer:** add `"hard_link"` to `__all__`.
- **Unit-tester:** add `FakeSystem.hard_link(link, target)`. It raises
  `FileExistsError` when `link` exists, `FileNotFoundError` when `target` is
  missing, honours `fill_disk`, and records the op. Also test the relay-level
  tell tests in `test_s62_tell.py` (T1/T2 numbering, never overwriting, the
  `FileExistsError` retry, draft removed on failure) on the fake, and take them
  out of `LEGACY`. The file may be split, as the design allows.

### D2: Twelve P1 modules are not converted
The design's P1 row and the story ("The migrations listed for P1 are in scope")
put these modules in this story: `results`, `po_session`, `onboard`,
`presentation`, `paths`, `gates`, `dashboard/snapshot`, `dispatch`, `router`
(file call), `checkout`, `stack`, `runner_tools`. None of them imports
`system`. A grep for `read_text(`, `write_text(`, `mkdir(`, `is_file()`,
`exists()`, `glob(`, `time.time()`, `resolve()`, `resources.files` and similar
still finds about 50 direct OS calls in them (onboard 12, snapshot 9,
presentation 6, …).

The PO ruling deferred only the *test files* to s76. s76's AC1 lists only the
P2 modules, so as things stand nobody owns these conversions. Either:
- the developer converts them here, as the design specifies module by module
  (the "P1" section of "Changes per module"); or
- the PO moves them into s76's AC1 explicitly (see open question).

My recommendation is to convert them here. Each one is a like-for-like swap
already spelled out in the design.

### D3: `watch.Pace` kept, against O3/O4, and production code branches on it
The design says "`watch.py`: delete `Pace` and `DEFAULT_PACE`; `Watcher` loses
`pace`". The developer kept it instead:
- `Pace` defaults to `time.sleep` / `time.monotonic` at import (an O4
  violation).
- `Watcher.pace` is an OS object passed as a field (an O3 violation).
- `cli.cmd_watch` gains a test-only `pace: watch.Pace | None = None` parameter.
- `Watcher._sleep` / `_clock` add `(self.pace.x if self.pace else system.x)()`
  branches: logic that exists only for tests.

The docstring defers the removal to s76, but s76 does not say so. The design
already covers this case ("in a `LEGACY` file, patch `system.<name>`
instead"). The fix:
- **Unit-tester:** change `test_s62_watch.py` to monkeypatch
  `system.sleep` / `system.monotonic`.
- **Developer:** then delete `Pace`, `DEFAULT_PACE`, `Watcher.pace`,
  `_sleep`/`_clock`, and `cmd_watch`'s `pace` parameter.

### D4: Stray empty module `agile_team/atch.py`
Commit `86c3265` adds an empty `agile-team/runner/agile_team/atch.py`, most
likely a slip of the redirection typing `watch.py`. It ships as an importable
module. **Developer:** delete it.

## Function by function

### `agile_team/system.py` (new)
All the functions are thin one-call wrappers with docstrings (O1). `FileStat`
matches the design. P1 rows are present. Not yet present: `Completed`,
`Command`, `ShellCommand`, `HttpReply`, `TimeoutExpired`, `Process`. Those are
P2, which is fine.
- `hard_link`: an extra row allowed by the PO ruling, but missing from
  `__all__` (D1).
- Coverage of the uncovered wrappers is the e2e step's job
  (`test_system_e2e.py`). Its absence does not block this review, but the e2e
  step must add it together with `test_seam_e2e.py` (O2 by `ast`).

### `state.py`: `load`, `save`, `runner_pid`, `pid_alive`
These are like-for-like swaps (O5). The atomic tmp-then-replace write is kept.
Covered by `test_s71_seam` through the round trip, the ops order, ENOSPC
keeping the old state, and the unreadable file raising. `pid_alive`'s
`PermissionError` branch is covered only from LEGACY files (real `os.kill`).
On the fake, `kill` never raises `PermissionError`. That is a gap in the
fake's fidelity, not a defect.

### `ledger.py`: `Ledger.record`, `_raw`; `events.py`: `EventLog.emit`, `events`
These are swaps. Covered by `test_ledger`, `test_events`, and the seam tests
(append_text ops, fake clock stamp).

### `relay.py`: `tell`, `told`, `_publish`, `post`, `answer`, `_append`, `_read`
The swaps are correct. `told` now goes through `list_dir`. `post` and `answer`
are covered in the fake world. **`tell`, `told` and `_publish` are covered
only in the real world (LEGACY), and are not swappable (D1).**

### `halt.log_traceback`
Builds one entry and makes one `append_text`, as the design says. Covered:
`test_crash_log_entry_has_the_fake_clock_stamp`. START_CLOCK is
2027-01-15T08:00:00Z, and I checked that the stamp is correct.

### `config.read_raw`, `keys` (`resolve`, `mode_ok`, `read_key`, `deny_rules`), `roles` (`user_roles_dir`, `load_dir`, `scaffold`, `_read_optional`)

### `health.current`, `live.read_heartbeat`
One-line swaps, covered.

### `roles/unit-tester.md`
The text matches the design verbatim (AC6).

### `tests/fake_system.py`
Solid overall. Exceptions use the real types, paths are pure `posixpath`, and
package data is snapshotted at import. Gaps:
- No `hard_link` (D1).
- `expand_user`: any text starting with `~` loses two characters, so `~bob/x`
  becomes `FAKE_HOME/b/x` and plain `~` becomes `FAKE_HOME`. The runner only
  passes `~/…`, so this is non-blocking. Handle only `~` and `~/` and leave the
  rest alone.
- `make_dirs` happily creates directories below a path that is a *file*
  (`_add_dirs` does not check ancestors). `_store` under a file parent raises
  `FileNotFoundError` where the OS raises `NotADirectoryError`. Non-blocking.
- `remove` of a directory key silently succeeds, while the real
  `unlink(missing_ok=True)` raises. Non-blocking.
- `replace` reads the source through `read_bytes`, so a `deny`'d source fails
  with `PermissionError`, whereas a real rename does not need read permission.
  Non-blocking.

### `tests/os_guard.py`
Matches O8 to O11: the tables are data, `RealOsCall` is a `BaseException`, a
swallowed violation fails at window close, and the world comes from a dict.
`LEGACY` is exactly the pre-s71 test files minus the five migrated ones (I
checked it against `ls`).

Notes:
- `test_legacy_names_are_test_files_that_exist` does not check existence, only
  the name shape. Rename it, or let the e2e step assert that the names exist
  (that check needs the filesystem). Non-blocking.
- `_guard.on` is process-global. A background thread left behind by a LEGACY
  test (a server or heartbeat) that touches files while a later FAKE test runs
  would put a violation on that unrelated test. This is a flakiness risk to
  watch in s76/s77, not a defect seen so far.

### `tests/conftest.py`
World-picking is done by dicts, and REAL rows get `tmp_path` inside the row,
as the design says. `present` writes through `system` (O15). The three
`pytest_runtest_*` wrappers are identical, but they are required by the hook
names, so that is acceptable.

### Migrated tests: `test_state`, `test_ledger`, `test_events`, `test_relay`, `test_keys`
