### state.py
`told` defaults to `[]`. `unsaved` is a `Cause | None` and is parsed in `from_json`.
A round-trip test and a legacy-load test cover both. State is never reset between starts,
so `told` keeps old messages from being delivered again. No defect.

### recovery.py / dispatch.py / po_tools.py (AC3)
- `_cut_cause`: KILLED comes before `unsaved`, and `None` otherwise. Tests: prefers-killed, no-cause, and live-run.
- `recover_cut`: salvages, clears `unsaved`, records the checkout after the revert, then saves. Tested through both the accept path and the restore path at CLI level.
- `save_interrupted`: sets `unsaved` only when the checkout moved, and `halt_run` persists it. Tested.
  If a later `halt_run` re-asserts an earlier halt of a different kind, `unsaved` takes the first halt's cause. That is acceptable, because the message only names the cause.
- `PoRun.run`: clears `unsaved` before RUNNING. Tested.
  Small test gap: the design's "plain start, then resume refused" is split across two tests (`test_a_plain_start_clears_the_flag` and `test_a_later_resume_refuses_unrelated_edits`, which seeds `unsaved=None` directly). Each half is sound, so this is not blocking.

### cli.py
- `_recover`: uses `RECOVERED_LEADS`, then falls back to `RECOVERED_LEAD`. `Cause` is a StrEnum, so `{cause}` formats as `checkout`. Tested.
- `_message_text` / `cmd_tell`: `OSError` and empty text become `CliError`, which `main` prints with the `agile-team tell:` prefix. The output path is repo-relative. Tests cover file, stdin, empty text, unreadable file, `state.json` never touched, a checkout halt, and registration.
- `cmd_watch`: prints one line, flushed. Tested.
- `status_report`: has `queued_messages`, tested before and after delivery and by default.
- `COMMANDS` / `WATCH_ARGS`: tested.

### scripts/pin-runner.sh
The P2 refusals run in the design's order, and usage exits 2. The build goes to `.new`, which then replaces the old pin, and `.commit` is written last. There is no `pipefail`: if `git archive` fails, the pipe hides it. The sha is verified first, so only an I/O failure could slip through. Acceptable.
Tests cover success, re-pin, running from a subdirectory, every refusal, and a dead pid.
