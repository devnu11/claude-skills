# Review: s144, a repo CLAUDE.md import that is not UTF-8 text is left out with a note (round 2)

Diff reviewed: `git diff d56ff15c~1 HEAD` limited to s144's files
(`instructions.py`, `test_s142_repo_instructions.py`, `protocol.md`). Design:
`agile-team/docs/design/s144.md`. Runner coverage: exit 0, all tests pass.

## Changed functions

### `instructions.UNREADABLE` (constant)
The note text is `(left out: @{path} is not UTF-8 text)`, which matches design rule 2.
`LOGO_NOTE` in the tests pins it exactly. No defect. (s144/AC1, REQ-107)

### `Inliner.file(path)`
It decodes the file through `_utf8` first, then adds it to `seen`, then
substitutes the imports. Because the decode comes first, a `UnicodeDecodeError`
leaves `seen` unchanged (rule 4). The docstring states the raise.
Tests: `test_binary_import_is_never_marked_seen` (two notes, no
"already included above"), plus every existing s142 test for the normal path.
No defect. (s144/AC1, REQ-107)

### `Inliner._import(...)`
Only its last line changed, to `self._inline(path, target)`. The check order
stays outside → not a file → seen → inline (rule 3). The existing s142 tests
cover the earlier branches, and the new tests cover the last one. No defect.

### `Inliner._inline(path, target)` (new)
It returns the inlined text, or the note when the target is not UTF-8. It catches
only `UnicodeDecodeError`, so an `OSError` still raises, as the design says. Each
nested level handles a nested binary import itself, so an outer
`_inline` never swallows an inner one by mistake.
Tests: `test_binary_import_left_out_with_note` (exact output, rule 2),
`test_other_text_still_loads_beside_a_binary_import` (AC1, "other text and
imports are still loaded"), `test_binary_import_inside_an_imported_file`
(rule 5, depth). No defect. (s144/AC1, REQ-107)

### `_utf8(path)` (new)
This is `system.read_bytes(path).decode("utf-8")` (rule 1).
Test: `test_non_ascii_utf8_import_is_inlined_exactly`. Note: the fake system's
`read_text` also decodes as UTF-8, so this test cannot tell the locale path
apart from the explicit-UTF-8 path. A unit test cannot pin the Windows cp1252
difference anyway, and the code reads correctly. Not a defect, only a limit of
the test. (s144/AC1, REQ-107)

### `repo_instructions` (unchanged)
`test_binary_root_instructions_still_raise` pins rule 6: a binary root file
still raises.
