# Review: s128, the team keeps going across sprint ends, and the runner re-pins itself

Reviewer: code-reviewer. Base: `68084c4` (the commit before `27d028b`) up to HEAD. I read the tests
but did not run them. The runner's coverage run passes: 99.56%, with `repin.py`, `router.py`,
`sprint_end.py`, `state.py` and `command_job.py` all at 100%.

**Verdict: changes requested.** There are two blocking items:

- **F1:** the `pin-runner.sh` tests are missing (an AC4 gap). This goes to the integration-tester.
- **F2:** stdout is not flushed before `os.execv`, so the PO's final text is lost at every re-pin.
  This goes to the developer.

The rest of the change matches the design well.

## Findings

### F1 (blocking): `pin-runner.sh` P6/P7 have no test (s128/AC4, AC2; REQ-022)

These parts are new shell behaviour, and no test runs them:

- the `.prev` keep step;
- `--rollback`;
- the `.failed` move;
- the `no previous pin to roll back to` exit 1;
- the new usage line with exit 2;
- the `refuse_if_running` check on `--rollback`.

The story's Tooling line says this is covered "via the existing subprocess test in
tests/e2e/test_liaison_e2e.py", and the design's test checklist has an item for it (the last item
under "Re-pin"). But `test_liaison_e2e.py` still has only the s62 test,
`test_pin_runner_builds_the_copy_and_records_the_commit`. `test_s128_repin.py` only fakes
`--rollback` replies. Python coverage cannot see this gap, because the script is shell.

Tests needed in `tests/e2e/test_liaison_e2e.py`, in a scratch repo like the s62 test:

- A second pin leaves `runner-pin.prev` and `runner-pin.prev.commit` holding the first pin.
- `--rollback` restores them, moves the current pin to `.failed`, and prints `rolled back to <sha7>`.
- `--rollback` with no `.prev` exits 1.
- Two arguments exit 2 with `usage: pin-runner.sh <commit> | --rollback`.

**Owner:** integration-tester.

### F2 (blocking): output is lost at the exec (s128/AC2; REQ-022)

At the end of `cmd_start`, `_run` calls `_finish`, which runs `print(result.text)` (the PO's last
text). `_repin_or` then calls `pin.repin`, which ends in `system.exec_replace`, and that calls
`os.execv`.

`os.execv` does not flush Python's stdio buffers. Under the unattended job, stdout is a pipe or a
file (`output.log`), so it is block-buffered. Whatever is still buffered, at least the PO's final
text, is lost at every re-pin. The same happens to rollback re-execs.

Fix: `system.exec_replace` should flush `sys.stdout` and `sys.stderr` before `os.execv`. It is the
one place every exec goes through. A unit test can't easily see the real buffer, so a short comment
there naming the pitfall is the right level, plus a test that `exec_replace` flushes (monkeypatch
`os.execv` and a stream).

**Owner:** developer-cli.

### F3 (non-blocking): duplicated `state.json` read in `command_job.py` (s128/AC3; REQ-023)

`agile_status` repeats `status_reason`'s `try: json.loads((output.cwd / STATUS_FILE).read_text())
except (OSError, ValueError)` block word for word. A `_state(output) -> dict | None` helper would
serve both (DRY). Worth doing with F2.

### F4 (note): the ask count survives a resume (s128/AC1; REQ-021)

`keep_going_asks` is reset only by `begin_sprint` and `add_to_sprint` (design K4). After the cap,
the `KEEP_GOING_STUCK` text tells the human to `tell` the PO and then `start --resume`. The count is
still at 3 on that resume. So if the PO's resume turn doesn't start a sprint or add stories, the
next pass blocks again with no hand-over. The PO gets one turn, not three.

This is consistent with the design as written, so it is not a defect. If the Architect intends the
human's resume to restore the full allowance, the fix is to reset the count on a start. That is a
design question, so I am not requesting it.

### F5 (note): an empty first line (s128/AC3; REQ-023)

In `notify_user`, `args["text"].splitlines()[0]` turns a text that starts with a newline into
`status_reason = ""` rather than its first non-empty line. This is cosmetic.

I read the script logic and it is correct:

- `cd "$root"` runs before the dispatch.
- The ancestor and `pyproject` checks apply only to `<commit>`.

- The pid check happens before the swap.

rule:

- `test_halt_e2e.py` and `test_wake_e2e.py`: a quiet end stores IDLE with the hand-over line. Design
  S1 says this, so the old `status_reason is None` is wrong.
- `test_s112_activity_page_e2e.py`: the status row grows to 6 parts with `pin ` second. Design P12
  says `pinPill` goes right after `statePill`. The added `runner-repin` sample is P12's `TIMELINE`
  row.

`test_halt.py` was changed outside the gate, in commit `f039acf`.

- `test_resume_clears_status_and_is_not_refused` now expects the S1 line. S1 supports this.
- `test_resume_after_cli_limit_stop` dropped its `status_reason` check. That is a little weaker, but
  S1 makes the old `None` wrong, and the test's subject (a resume after a limit stop) is still
  asserted.

I accept both.
