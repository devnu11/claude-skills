## Changed code

### `owners.FINDINGS[Source.LINT]`, first pattern (`agile_team/owners.py:37`)

- **What it does.** Matches `path:line[:col]: message` lint lines. Lines whose message
  starts with the whole word `warn` or `warning`, in any case, are no longer findings.
- **Matches the design (R5)?** Yes, but written differently. The design scoped the
  case-insensitive flag inline (`(?i:…)`). The code sets `re.I` on the whole pattern.
  The two are equivalent: outside the lookahead the pattern has only character classes
  (`[^\s:]`, `\w`, `\d`, `\s`) and punctuation, which case-folding does not change.
- **Against the real house-rules output** (`house_rules/report.py:26-45`; levels in
  `model.py` are `"warn"` and `"fail"`):
  - `path:line: fail rule: msg` is a finding.
  - `path:line: warn rule: msg` is not.
  - `suppressed path:line …` is not: a space comes before any `:`.
  - `stale baseline entry: …` is not: it has no `.ext`.
  - The summary `house-rules: N files, …` is not.

  So a failing `static` routes only the fail lines (s157/AC2, REQ-112). A clean stop,
  or one with only warnings, is not refused (s157/AC1, REQ-111).
- **Tests** (`tests/test_s157_house_rules_routing.py`). They cover every item in the
  design's unit checklist:
  - a fail line is a finding;
  - `warn`, `warning:` with a column, `WARNING` and `Warn` are not;
  - ruff `W291` still counts;
  - a word that only starts with `warn` (`warnings_off`) still counts;
  - mixed output finds only the failing file, and `placed` gives one item holding both
    fail lines;
  - the ruff-full (`-->`) and `Would reformat:` patterns still match.

  Corner cases are covered well.
- **Defects.** None.
- **Nit (fits no AC):** the test helper `paths` has no docstring. Other test helpers in
  the suite often have none either, so this does not block.
- **Note (R5, fits no AC; not a regression):** eslint's `unix` format puts the severity
  at the end (`… [Warning/rule]`), so eslint warnings still become items. The same was
  true before this story, and R5 limits itself to messages that *start* with `warn`.
