### SC13 detail

The new `DigestGit` tests replace `run` with a fixed table. They pin the
digest's own logic: listing order doesn't matter, a new untracked file
changes it, a blob change changes it, a deleted file is marked `-`, the base
is part of the hash, and a clean tree makes no `hash-object` call. The
`hash-object` fake reads `args[2:]`, which matches `run("hash-object", "--",
*paths)`. These tests are good and should stay.

They can't pin the property that makes the reuse safe: **the digest is the
same before and after the step's commit.** That depends on git's semantics:
`git diff --name-only base` compares `base` with the working tree, so it lists
both committed and uncommitted changes. With `--cached`, or with `HEAD` in
place of `base`, the fake tests would still pass, but a commit would change
the digest. In the worst case, a stale run would be reused. Only a real repo
proves this.
