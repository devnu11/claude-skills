## Changed functions

### `BoundaryRunner._push_replayed` (boundary_runner.py)
- **What it does:** START edge goes to `_push_start_replay` as before. END edge: `_fetch()`,
  then `Upstream.is_in_target(HEAD)`. If true, `_close_shipped`; otherwise `_push_end_replay`.
- **Tests:** shipped path (s183 AC1 tests), not shipped (AC3 parametrised over an unscripted
  merge-base and another sha), failed merge-base (`test_a_failed_merge_base_is_not_shipped_ac3`),
  failed fetch holds `error` (`test_a_failed_fetch_at_push_replayed_holds_error`).
  `_push_rebased = _push_replayed` is an alias, so it inherits the same behaviour.
- **Defect:** none. Note N1 (lock) is below.

### `BoundaryRunner._close_shipped`
- **What it does:** builds `SHIPPED_REPORT`, closes the PR, then `_finish`es with
  `note`/`sha`/`target` and no `ci`. `_close` stores the report as `upstream.report`, which is
  the PO's `Review:` line.
- **Tests:** event fields and no `ci` key (`…_has_note_sha_target_and_no_ci_ac1`). The
  `closed`/`report`/`mode` checks are in `…_finishes_with_the_report_ac1`. The PO hand-over
  text is `…_po_hand_over_says…_ac1`, and no `ci_green` is `…_no_ci_green_rule_fires…_ac1`.
  This covers s183/AC1 and REQ-222 (event and hand-over wording).
- **Defect:** none.

### `BoundaryRunner._close_shipped_pr`
- **What it does:** closes a recorded, not-yet-closed PR with `SHIPPED_PR_NOTE` when `gh` is
  available, and always sets `mode = CLOSED`.
- **Tests:** open PR closed once with the note, no PR, `gh` missing (no gh call), and a PR
  already closed. In the real incident, closing the merged PR #48 depends on
  `GhPrs.close`, which already treats a PR GitHub shows as merged as done
  (upstream.py `close`/`_is_merged`). That path existed before this story and is not
  re-tested here, which is acceptable (s183/AC2, REQ-223).
- **Defect:** none. When `gh` is missing, the entry is recorded `closed` even though nothing
  was closed upstream. That is a choice, not a bug: the target holds the sprint, so the
  PR has nothing left to do.

### `BoundaryRunner._push_end_replay`
- **What it does:** the old END body, moved unchanged (unchanged HEAD → `_report_unchanged`,
  otherwise push `-r<k>`, then reject or report). The `type: ignore`s are gone because `own` is now typed.
- **Tests:** AC3 tests plus the existing s159/boundary_runner tests (s183/AC3, REQ-224).
- **Defect:** none.

### `Upstream.is_in_target` (upstream.py)
- **What it does:** `git merge-base HEAD <remote>/<branch>`. It is true only on exit 0
  with output equal to `head`.
- **Tests:** three unit tests: equal, other sha, non-zero exit. They also check the argv
  ends with `(head, "origin/main")`, so it compares against the fetched remote ref and not a
  stale local `main`. That matters for the incident.
- **Defect:** none. Note N2 (duplication) is below.

### Constants `SHIPPED_REPORT`, `SHIPPED_PR_NOTE` (boundary.py)
They match the wording in `reference/protocol.md` step 6 and in the tests.

## Minor notes (non-blocking)

- **N1 (no AC; robustness).** The new `_fetch()` at `push-replayed` runs outside
  `runtime.checkout_lock`. `_sync` and `_replay` call `remote.missing()` (a `fetch --prune`)
  inside the lock. The stage ran unlocked before, and a fetch does not touch the working
  tree. The worst case is a "cannot lock ref" race with a concurrent landing fetch, which
  holds `error` and now clears on `continue_boundary`. Worth matching the other stages
  some time.
- **N2 (no AC; duplication).** `is_in_target` asks the same question as
  `is_ancestor(head, self.target)`, which `classify_in_target` already uses. The comment
  says the merge-base form was picked because unscripted fake commands exit 0. So
  production code was shaped around a test fake. It is correct either way, but there
  are now two idioms for "target contains head" in one class.
- **N3 (s183/AC2; test fidelity).** `held_after_failed_create` sets
  `boundary.failure` to a plain string. A real `_error` hold leaves `failure = None`, and
  `failure` is otherwise a `Failure` with a `.case`. The test passes because
  `continue_boundary` clears it, but the state it builds is one the runner never produces.
- **N4 (no AC; weak test).** `test_the_start_edge_never_asks_for_the_shipped_check`
  asserts only `boundary is None or boundary.edge is Edge.START`, which is almost always
  true. It does not check that no `merge-base`/`fetch` was issued for the START edge, which
  is what its name claims. START behaviour is still covered by the existing
  boundary tests.
