## Per changed function (this round)

- `_moves_by_rebase` / `_find_rebase_branch`: every operand after the upstream (from 0 with
  `--root`, now matched by `_is_long`), plus HEAD. More than one named candidate gives
  `REBASE_UNCLEAR`, and none gives DETACHED. Matches B3 steps 3-4. An unknown option can only
  add a candidate. No defect. Tests cover only the plain and `-s` cases (R5-1).
- `_is_rebase_valued`, `REBASE_VALUED_SHORT/LONG`: a short option counts only as an exact word.
  A long one counts by abbreviation, and only without `=`. `-S` is gone. All the listed options
  take a required value in git, so none can wrongly skip an operand. An ambiguous
  abbreviation (`--s`) is rejected by git itself. No defect. Untested (R5-1).
- `find_moved_branch` / `_updates_refs`: `OTHER_REFS` for any `-c` or a rebase `--update-refs`.
  `--no-update-refs` doesn't prefix-match. No defect. Untested (R5-2).
- `find_branch_denial`, `BRANCH_DENIALS`, `_is_own_or_detached`: a table lookup for the
  refusal text, which replaces a conditional. No defect. `REBASE_UNCLEAR` and `OTHER_REFS`
  texts are never formatted in a test (R5-1, R5-2).
- `_list_positions`: HEAD follows a link only while it is own or detached (R4). No defect.
  Untested (R5-5).
- `_locked_mention`: adds `GIT_CONFIG` to the locked names when the site has a branch. It is a
  substring match, so `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL` and the others are covered as
  well. No defect. Untested (R5-3).
- `REBASE_FIX_ENV`: three entries pin `rebase.updateRefs=false`. The constant is tested, the
  launch env is not (R5-4).
- `story_rebase.read_branch_heads` / `_is_free`: compare resolved paths. No defect. Untested
  (R5-6).
- `dispatch._put_back_moved`: the record is cleared whenever the compare runs. No defect.
  Untested (R5-7).
