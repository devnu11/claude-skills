## Findings (none blocking)

- **F1 (s176/AC2, REQ-210): over-refusal through prefix matching.** `_is_long("--force",
  CREATES["switch"].long)` matches `--force-create`, so `git switch --force <other>` (git's
  alias for `--discard-changes`) is refused as if it created `<other>`. Git's parse-options
  prefers an exact option name over a prefix of a longer one. The cost is a false refusal of a
  command the rebase never needs, so it is safe. A later fix: exact names first in `_is_long`.
- **F2 (s176/AC1, REQ-209): `git reset -- <file>` with HEAD on another branch is refused**,
  although a path reset moves no ref. AC1 asks for "`git reset` … while HEAD is on a branch
  that isn't the rebase branch" to be refused, so this follows the AC as written. It is a
  note, not a defect.
- **F3 (s176/AC3, REQ-211): a stale snapshot across a long cut-off.** By design (B8), a
  resumed step compares against the snapshot taken before the cut-off. Suppose the human moves
  a free branch (for example `main`) while the run is halted. When the resumed step ends, the
  runner puts that branch back. The checked `update-ref` doesn't stop this, because `<new>` is
  the human's sha. The design accepts this, and it is rare. Worth a line in `protocol.md` if it
  ever happens.
- **F4 (s176/AC2, REQ-210): any `git -c …` is refused, read-only commands included**
  (`git -c color.ui=never log`). `protocol.md` documents this, and plain read-only commands
  still run. Note only.
- **F5 (no AC): weak test.** `test_the_runtime_module_exposes_the_put_back_step` only checks
  `hasattr`. The behaviour tests beside it already cover the method, so the test adds nothing.
- **F6 (no AC): no check against real git.** The guard tables test parsed strings, and
  put-back runs on `FakeSystem`. No test runs `git checkout -B other` in a real worktree and
  sees it refused, or sees a branch put back. The story's Tooling section asked for unit
  tests only, and it names `test_git_check.py` and `test_story_rebase.py`, but the tests went
  into `test_s176_*.py`. That mismatch is harmless.
