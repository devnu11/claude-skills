### `git_check._find_plain_next_head`
It splits at the first `--`. If there are paths after `--`, or no branch is named before it,
it returns HEAD unchanged. If a branch is named (counting `-`), it returns `HEAD_UNKNOWN`.
I checked it by hand against each form:
- `checkout -` / `switch -`: before `["-"]`, after `[]` → `HEAD_UNKNOWN`. Right (fixes F1).
- `checkout other --`: before `["other"]`, after `[]` → `HEAD_UNKNOWN`. Right (fixes F2).
- `checkout other -- f`, `checkout -- f`, `checkout HEAD -- f`: after is non-empty → head.
  Right.
- `checkout --` (nothing else): → head. Right, since it does nothing.
- `checkout -q other`, `checkout HEAD~1`: → `HEAD_UNKNOWN`. That is conservative (the
  second case actually detaches). It still refuses rather than lets through, so it is
  safe for AC1.

No defect. Tests: none for `-` or a trailing bare `--` (R2-1).

### `git_check._split_dashes`
Splits a word list at the first `--`. No defect. Tests: reached indirectly through
`checkout -- f`. There is no case for a bare `--` with nothing after it (R2-1).
