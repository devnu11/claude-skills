## Changed functions

### `sandbox.sandbox_env(environment, root)`

- **What it does:** it starts from `runner_venv.get_command_environ()`, which returns a
  fresh dict with no `VIRTUAL_ENV` and with the runner venv's `bin`/`Scripts` removed
  from `PATH`. Then it puts `root / b` for each `environment.bin` (in order) in front
  of that filtered `PATH` and drops empty parts. `layout` (`sandbox.py:509`) builds
  `Prepared.env` from it once. Prepare (`run_shell`, :346) and the web start
  (`Preparer._start`, :444) both pass `prepared.env`. This meets s186/AC1 (REQ-232) and,
  through design R4, s186/AC2 (REQ-233).
- **Order (R2, REQ-232 "never dropped"):** filtering happens before prepending, so an
  environment's own `bin` is never stripped.
- **Tests:**
  - `test_sandbox_env_hides_the_runners_venv` checks that `VIRTUAL_ENV` is gone, that the
    runner's bin is dropped, that two bins come first in their configured order, and
    that other variables are kept (s186/AC1, REQ-232).
  - `test_sandbox_env_keeps_other_venvs_on_path` checks that only the runner's own venv
    dir is stripped (REQ-232).
  - `test_sandbox_env_without_a_runner_venv_is_unchanged` covers the branch with no
    `VIRTUAL_ENV`.
  - The existing `test_sandbox_env` (empty `PATH`), `test_sandbox_env_is_a_copy` and the
    prepare test at line 36 (the `ShellCommand` carries `p.env`) still hold. Together
    they cover the prepare wiring.
  - AC2's `uv` warning and `sys.prefix` checks are by hand, per the story's Tooling
    section. The no-`VIRTUAL_ENV` assertion covers their cause.
- **Defects:** none.

## Advice (not blocking; fits no AC)

- A1: three items in the design checklist have no test of their own:
  - a `PATH` that holds only the runner's bin, with env bins set (no trailing separator);
  - a `bin = ["venv/bin"]` case;
  - the web start `ShellCommand` carrying `prepared.env` (`sandbox.py:444`; nothing in
    `test_sandbox.py` asserts the spawned command's env).

  The first two run code that is already covered (the `if p` filter, and a scratch path
  whose parent can never be the runner's venv). The third is unchanged code that reads
  the same dict that the prepare test already checks. The risk is low, so this is not
  worth another round.
- A2: the new tests write `PATH` with a literal `:`, unlike `test_sandbox_env`'s
  `os.pathsep`. That matches `test_runner_venv.py`, and the runner suite does not run on
  Windows in CI, so this is not a defect today.
