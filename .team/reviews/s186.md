### `test_prepare_sees_its_own_venv_not_the_runners` (e2e)

- **What it does:** sets a fake runner `VIRTUAL_ENV` and puts its `bin` first on `PATH`,
  then runs a real `Preparer().prepare`. The prepare shell runs `uv venv` and
  `uv pip list`, and records `$VIRTUAL_ENV`, `$PATH` and the new venv's `sys.prefix`.
- **Coverage, s186/AC1 (REQ-232):** strong. `VENV=[]`, no `runner-venv` in what the
  command saw, and `PATH` starts with `<root>/bin:`. This is the real prepare path
  (`run_shell` → `Prepared.env`), so it closes round-1 advice A1 item 3 for prepare. The
  web start is still checked only through the shared `Prepared.env` (unchanged plumbing).
- **Coverage, s186/AC2 (REQ-233):** partial, but the story names the by-hand check as
  AC2's proof, so this is acceptable:
  - `"does not match" not in uv_out` and `"runner-venv" not in uv_out` are meaningful.
    With the old code, `uv pip` would have aimed at the nonexistent `VIRTUAL_ENV` and
    said so.
  - `str(prepared.root / ".venv") in seen` is close to a tautology: the command calls
    `.venv/bin/python` by explicit path, so its `sys.prefix` is `.venv` whatever the
    environment holds. It does not show a start command resolving `python` through
    `PATH` to the environment's venv (AC2's wording). Advice A3 below.
- **Gate fix 7a70129:** it only adds uv's directory (found with `shutil.which` before the
  monkeypatch) to the test's `PATH`. No assertion changed, as the brief says. Correct:
  CI's uv need not be in `/usr/bin` or `/opt/homebrew/bin`.
- **Defects:** none blocking.

## Advice (not blocking)

- A3 (s186/AC2, REQ-233): make the prepare use `bin = [".venv/bin"]` and call bare
  `python -c ...`. The `sys.prefix` assertion would then prove PATH resolution reaches
  the environment's venv instead of restating the explicit path. It would also cover
  round-1 A1's "env bin inside a venv" item.
- A4 (fits no AC): when uv is missing, the `or "/usr/bin/uv"` fallback makes the test
  fail with a confusing assertion instead of a clear skip or error. uv is always present
  where this suite runs (`uv run`), so this is low risk.
- A2 from round 1 still applies here too: literal `:` and POSIX paths. The runner suite
  does not run on Windows. Not a defect today.
