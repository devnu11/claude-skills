## Changed functions

### `sandbox.sandbox_env(environment, root)`

- **What it does:** it starts from `runner_venv.get_command_environ()`, which drops
  `VIRTUAL_ENV` and removes the runner venv's `bin` from `PATH`. Then it puts
  `root / b` for each `environment.bin` in front of the filtered `PATH` and drops empty
  parts. `Prepared.env` (`sandbox.py:506`) is built from it, and both prepare
  (`run_shell`, :346) and start (`Preparer._start`, :441) use it. So s186/AC1 (REQ-232)
  and s186/AC2 (REQ-233) are met by design rules R1, R2 and R4.
- **Order is right (R2):** filtering happens before prepending, so an environment bin
  such as `venv/bin` is never stripped, even when it sits in a venv.
- **Tests:**
  - `test_sandbox_env_hides_the_runners_venv` checks that `VIRTUAL_ENV` is gone, that the
    runner bin is dropped, that bins come first in order, and that other variables are
    kept (AC1).
  - `test_sandbox_env_keeps_other_venvs_on_path` checks that only the runner's venv dir
    is stripped.
  - `test_sandbox_env_without_a_runner_venv_is_unchanged` covers the no-`VIRTUAL_ENV`
    branch.
  - The existing `test_sandbox_env` (empty `PATH`) and `test_sandbox_env_is_a_copy` still
    hold.
  - Corner cases are covered. AC2 (no uv warning, `sys.prefix`) is by hand, as the
    story's Tooling section says. The cause of the warning is covered by the
    no-`VIRTUAL_ENV` assertion.
- **Defect F1 (s186/AC1, REQ-232; design "Changes per module"):** the docstring was not
  changed. It still says "The current environment with the environment's `bin` dirs
  prepended to PATH". That is no longer true: the base is now the filtered command
  environment. The design calls for
  `"""``get_command_environ()`` with the environment's ``bin`` dirs first on PATH."""`.
  It is a one-line fix in `sandbox.py:368`, owned by `developer-cli`.
