Reviewer step, round 0. Diff: `8eb97cf9..e1a322b6`, plus the integration-tester gate fix
(no commit, no assertion change: nothing to review). Runner results: coverage 98%, all green.

Verdict: **changes requested** (architect). The behaviour is right and well tested. One doc
states an API that does not exist (F1), and the design no longer matches the code (F2).

I traced the scenario (s184/AC1, REQ-227). The PO's done during the END check gets held
and saved. The check sets `repin`. `_repin_or` sets `idle` and `begin` sets `running`, and
neither touches `held_done`. The new process finishes the boundary, `_close` marks `done`,
`_step` saves, and `tick` sees `halted()` before the router runs, so no `next_sprint` goes
out. `test_a_repin_round_trip_keeps_the_held_done` and
`test_the_run_ends_done_with_no_next_sprint_hand_over` cover this path. By hand on a pinned
runner is still the PO/liaison's job, as the AC says.

## Findings

**F1 (defect, docs). s184/AC1, REQ-227.** `agile-team/docs/architecture.md` names
`RunState.mark_done` in both the s184 story-index row and the `state.py` module row.
That method doesn't exist: the developer put the hold in `Tools._hold_done` instead. Fix
both rows to describe what was built (`is_boundary_pending`, `release_held_done`, and
`Tools._hold_done` in po_tools). The repo rule "docs move with behaviour" makes this
blocking: a reader looking for `mark_done` won't find it.

**F2 (design drift). s184/AC1, REQ-227.** `docs/design/s184.md` specifies `mark_done`,
`_record_status`, `_format_held` and a different `DONE_HELD` text. None of these were
built. The code got the same behaviour another way, which is fine, but the design is the
contract and should match. Either update its "Changes per module" section to the code, or
add a short note that the developer simplified it. Same owner as F1.

**F3 (minor, DRY). No AC.** `po_tools.notify_user` and `Tools._hold_done` both compute the
reason with `text.splitlines()[0][:REASON_CUT] if text else …`. The two differ only in the
empty value (`None` vs `""`). One helper, e.g. `_first_line(text) -> str`, would keep the
cut rule in one place. Not blocking.

**F4 (minor, test). s184/AC3, REQ-229.**
`test_status_shows_done_and_the_reason_after_the_run_ends` asserts
`status != "running" and != "blocked"`. That also passes for `idle` or `interrupted`. AC3
says `status` shows `done`, so it should assert `report["status"] is RunStatus.DONE`. Other
tests already show the state goes `DONE`, so this isn't a coverage gap, but the AC3 test
should say what AC3 says. Tester or developer can fix it alongside F1.

**F5 (minor, house rule). No AC.** The test helper `start_of(*, task, resume: bool)` takes
a boolean parameter. The charter says "No boolean parameters or flags; use an enum". Pass
`cli.StartMode` directly instead.

## Not defects (checked)

- A done held during a START boundary, or while the run is blocked (`tick` returns before
  `open_end`), waits until that boundary opens and closes. That matches D1/D5.
- A held boundary (failed CI) keeps the done held. That is intended by D5, and the liaison
  can still `stop`.
- No top-level code in the changed modules or in `test_s184_held_done.py`.
- No other copied blocks in the diff besides F3.
