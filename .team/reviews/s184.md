## New findings

### R1 (blocking): s184/AC1, REQ-227: the F1 fix has no regression test

`is_boundary_pending` now has the `sprint_complete() and sprint_open()` conjunct. But no test
puts a done on a sprint that is open and **incomplete**. Every D1 test uses `ended_sprint`
(a complete sprint). The START-boundary test (`test_done_during_a_start_boundary_is_held`,
line 69) also uses `ended_sprint`. Branch coverage can't see the missing conjunct because a
boolean `and` isn't a branch. So if the round-1 code came back, every test would still pass.
That is how F1 got through round 1.

Add these two tests (the ones round 1 asked for):
- a `done` (cadence `sprint`, or `until-blocker` with every Sprint Backlog story left
  blocked) on an open, incomplete sprint with no boundary returns `{"id"}` and marks `done`
  with the reason at once, with nothing held;
- a done held during a START boundary on an open, incomplete sprint is released by
  `BoundaryRunner._close`: the status is `done` and `held_done` is `None`.

### R2: copy/paste: the reason cut is written twice (no AC; minor, not blocking)

`text.splitlines()[0][:REASON_CUT] if text` appears in both `notify_user` and `_hold_done`.
A `_reason(text)` helper would remove the copy. This was reported in round 1 and is still
there.

### R3: s184/AC2, REQ-228: the resume command is abbreviated (minor, not blocking)

`NEXT_SPRINT_ADVICE` says "resuming it with `--cadence sprint`". Design D7 gives the full
command, `agile-team start --resume --cadence sprint`. The PO relays this to the liaison, so
the full command is easier to act on. It is optional.
