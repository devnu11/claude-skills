## Findings

### F1 (blocking): s184/AC1, REQ-227: a done sent mid-sprint is held forever

`po_tools._end_pending` returns `state.boundary is not None or state.sprint_open()`, and
`RunState.release_held_done` returns early on `self.boundary or self.sprint_open()`.
Design D1 says a boundary is pending only when `boundary` is set **or**
(`sprint_complete()` **and** `sprint_open()`). The code drops `sprint_complete()`.

What goes wrong: `sprint_open()` is true for the whole sprint, from its start until its
end boundary closes. Now take a `done` that is not refused while the sprint is still
incomplete:
- under cadence `sprint` (or any cadence other than `until-blocker`),
  `keep_going_refusal` never refuses (`sprint_end.py:108`);
- under `until-blocker`, when every Sprint Backlog story left is blocked (the s156
  stuck case).

That done is held. `open_end` opens the end boundary only when `sprint_complete()`
(`boundary_runner.py:200`), so `_close` never runs for this sprint and nothing releases
the done. The status stays `running`, and the run does not end. Before s184, the same
call marked `done` and halted the run. The same omission also keeps a done held across
a START boundary: after `_close` of a START boundary, `sprint_open()` is true, so the
release does nothing (design D1/D3 expect the release there).

No test covers this. All D1 tests use `ended_sprint`, where the sprint is complete. The
missing tests:
- a done on an open, incomplete sprint with no boundary marks `done` at once;
- a done held during a START boundary on an incomplete sprint is released by `_close`.

Fix: put the design's `is_boundary_pending` predicate on `RunState` and use it in both
places (see F2).

### F2: DRY. The "pending" predicate is written twice (s184/AC1, REQ-227)

`po_tools._end_pending` and `RunState.release_held_done` each write their own copy of
the pending check. The design had a single `RunState.is_boundary_pending`, used by
`mark_done` and `release_held_done`. Having two copies is how F1 got into both places.
`_end_pending` also has no docstring. It is private, but the predicate is a rule, so it
belongs on `RunState` with D1 in its docstring.

### F3: s184/AC2, REQ-228: the hand-over weakens s128's rule and drops the design's text

`NEXT_SPRINT_ADVICE` now opens "Don't end your turn without being ready to start a
sprint while Product Backlog stories are ready". Before s184 it said "Don't end your
turn without starting a sprint". AC2 says s128's rule is unchanged, and the design
(D7) keeps "start a sprint". "Being ready to" reads as permission to end the turn
without starting one. It also drops D7's "Ready Product Backlog stories are no reason
to notify done or blocked", and it gives the resume command only as `--cadence sprint`,
where the design has `agile-team start --resume --cadence sprint`.

The D7 test (`test_next_sprint_advice_says_how_a_run_ends`) checks only for
`--cadence sprint` and "quoting them", so it passes either way. Use the design's text,
or add an assertion that the advice still says "start a sprint" without the hedge.

### F4: s184/AC1, REQ-227: the PO role prompt is not updated

The design lists `agile_team/roles/product-owner.md` (the `## Cadence` `until-blocker`
bullet: notify done when told to start no further sprint; a held done says `held`;
don't send it again). The diff doesn't touch it. The tool result's `held` text covers
part of this. But the role prompt still says nothing about ending on the human's word,
and the repo rule "docs move with behaviour" applies.
