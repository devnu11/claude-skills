## Findings

**F4 (defect, test). s184/AC3, REQ-229.**
`test_status_shows_done_and_the_reason_after_the_run_ends` (line 284) asserts
`report["status"] != "running" and report["status"] != "blocked"`. That also passes for
`idle` or `interrupted`, which is the class of bug this story fixes (the status was
overwritten to `idle`). AC3 says `status` shows `done`, and the design's D6 test line now
says `report["status"] is RunStatus.DONE`. Assert exactly that. Owner: tester.

**F5 (defect, house rule). No AC (charter: "No boolean parameters or flags; use an enum").**
`start_of(*, task: str, resume: bool)` (line 237) takes a boolean. The design's D5 test line
now says helpers pass a `cli.StartMode`. Pass the mode in (or drop the helper and build
`Start(task, cli.StartMode.RESUME)` directly). While there: D5 says a task drops the held
done "in any mode", and both call sites pass `resume=True`, so the `WORK` path of
`_drop_held_done` is untested. One case with `StartMode.WORK` closes that. Owner: tester.

**F6 (minor, design drift). s184/AC2, REQ-228.** The design says its "Changes per module"
section describes the code as built, but its `NEXT_SPRINT_ADVICE` block is not the shipped
text. The code says "If the human's instructions say to start no further sprint" and
"resuming it with `--cadence sprint`". The design says "the human or the liaison" and gives
the full `agile-team start --resume --cadence sprint`. `protocol.md:2269` follows the design
("or the liaison told the PO"), and `product-owner.md:286` follows the code. AC2 is met either
way (the test checks the key phrases), so this doesn't block. The architect should make the
design block match the code at the next touch.

**F3 (minor, DRY). No AC.** Unchanged from round 0; optional per the design.
