## Minor findings (do not block)

- **m1 (docs drift):** the snapshot contract row in `docs/architecture.md` (~line 1086) still
  says `environment` is `story.environment or ""`. Per SF8 it is now
  `", ".join(story_spec.environment_names(...))`, or `""` when the file has problems. The
  Architect should fix it at the next touch.
- **m2:** `read` catches only `OSError`. A story file that isn't UTF-8 raises
  `UnicodeDecodeError`. That becomes a runner fault at acceptance instead of an SF7 hold, and
  it breaks the snapshot. This is unlikely (the PO writes UTF-8), but catching `ValueError`
  too, or reading with `errors="replace"`, would close it.
- **m3:** a file hold's report says `"status": "returned"` because it reuses `_returned`. The
  gate verdict says `hold`, so nothing breaks. Only the label is loose.
- **m4:** `test_a_storyless_proxy_keeps_the_first_configured_environment` checks
  `config.environment(None)`, not `Runtime._environment_for` with `plan.story is None`.
  Coverage reaches that branch elsewhere, but a direct test would pin SF9's storyless rule.
- **m5:** every snapshot now parses the YAML of every story in state (~110 files). That is
  fine today; cache by mtime if the dashboard gets slow.
- The SF7 test checks the hold reason and `story.hold == "gate_hold"`, not the rendered PO
  hand-over line. The existing `gate_hold` row formats that same reason, so this is fine.
