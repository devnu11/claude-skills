The integration-tester should add `tests/e2e/test_s120_share_e2e.py` as the design describes: `agile-team share mock.html --story s1`, one `Sharer.apply`, then `git log -1 --name-only` == the two paths, `rev-list --count` +1, and the committed file's sha256 == the story-file entry. |
| F2 | low | s120/AC2, s120/AC3, REQ-008, REQ-009 | **`listed` accepts `..` in a path.** `_item_problem` checks only `path.startswith(where.design_dir)`, so `agile-team/docs/design/../../.team/run/liaison/x` passes S6. The path then goes into the Proxy's `proxy_read_globs` and OS-sandbox `_allowed_reads` (`str(repo / p)`, not resolved), and `check` hashes it. The runner writes the list itself, and `target_of` can't produce `..` because `FILE_NAME` forbids `/`. So a role would have to hand-edit a story file's frontmatter to exploit this. Even so, S6 says "not under `<docs>/design/`", and that path is not under it. Suggested fix (follow-up story): reject any path with a `..` segment, or one whose `PurePosixPath` parent differs from `<docs>/design`. Add a test row to `test_each_problem_is_reported_with_its_prefix`. |
| F3 | low | s120/AC1, REQ-007 | **`Share.from_json` doesn't check field types.** A request file with `"story": 1` (or `"name": null`) reads as a `Share`. `Sharer._settle` → `story_refusal` → `STORY_ID.match(1)` then raises `TypeError` inside the router tick, on every tick, because nothing records it as settled. Only `agile-team share` writes these files, so this needs a hand-edited or corrupt queue file. Suggested fix: return `None` unless `story` and `name` are `str`, and add a case to `test_bad_json_shape_or_base64_reads_as_none`. |
| F4 | low | s120/AC2, REQ-008 | **`brief_section` gets the story id from the first file's base name** (`_story_of`: the text before the first `-`). That is right for every path `target_of` builds. Passing the story id (as `_attach_shares` already has it) would be exact. Not a blocker. |
| F5 | info | no AC | **Copy/paste:** `sharing.Shares.queue/_numbered/_publish/_read` is the third copy of the draft + hard-link numbered queue (`relay`, `reorders.Requests`). The design allows this explicitly ("Copying the pattern is fine; do not refactor `reorders` or `relay` in this story"). I suggest a follow-up story that extracts one `NumberedQueue`. |
| F6 | info | s120/AC1, REQ-007 | `Sharer._write` writes the target and the story file before `git.commit`. If the commit raises, both edits stay in the tree and `state.shares` isn't recorded, so the share is retried next tick. Retrying is the safe behaviour, and the checkout guard covers a broken HEAD. Noting it only. |
