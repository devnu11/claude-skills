# s10 code review: a start ledgers the spend a crash cut off

Reviewed: `c6f01a69` (code), `fad9dc5a` + `ea8e1463` (tests) against design
`agile-team/docs/design/s10.md` and ADR-0078. Tests were read, not run; the runner's
coverage run passed at 99.54%.

**Verdict: changes requested (unit-tester).** The code matches the design and I found
no defect in it. One test gap is blocking: nothing checks that a **start** reconciles.
That is the "on the next start" in AC1, and RC1 depends on the order of calls.

## Per changed function

### `ledger.SessionCost.own_cost` (+ field `reconciled`)
- What it does: returns the query's own share of the session's running total. A
  same-session delta is now reduced by `min(reconciled, delta)` (RC7).
- Behaviour: I checked it against the old one-line form. Fresh session, other session
  and counter restart all still return `reported`. With `reconciled == 0` the result is
  the old delta. Correct.
- Tests: `test_po_cost.py::test_own_cost_after_a_reconcile` covers the four rows the
  design lists (net, capped at 0, other session, restart), and `test_session_cost_defaults`
  covers the default. The existing `test_own_cost` rows are unchanged.
- Minor (s10/AC1, REQ-100, not blocking): the parametrised test works out `base` with
  `5.0 if reported < 1.0 and resumed == "s" else 1.0`. A test should not hold branching.
  Put `base` (or the whole `SessionCost`) in the parameter table, as the design's
  checklist did.

### `live.Turn.from_line`
- What it does: parses one turns.jsonl line. Bad JSON, a non-object or a missing or
  extra key raises ValueError, TypeError or KeyError.
- Tests: round trip with `None` cost and id, plus five bad lines. Good.

### `reconcile.reconcile_ledger`
- What it does: returns `[]` while a runner is alive. Otherwise it ledgers one row per
  key with uncovered turns, then nets the PO part into `po_cost`.
- I checked the clocks: turn lines (`live._line`, `news.now`) and ledger rows
  (`Ledger.record`, `system.now()`) use the same wall clock, so RC3's `>` comparison is
  sound. `runner.pid` is written in `_run` (`pid_file`), which comes after `_prepared`.
  So the starting process does not see itself as a live runner. Correct.
- Tests: crash then reconcile (AC1), second reconcile writes nothing (RC5), live and dead
  pid (RC1). Good.

### `reconcile._net_po_spend`
- What it does: adds the PO rows' cost to `state.po_cost.reconciled` and saves. It does
  nothing when the cost is 0 or `po_cost` is `None`.
- Tests: PO row noted; a role row leaves the state alone; `po_cost None` is not
  rewritten. There is also a full resumed-query test showing the next PO query ledgers
  only `x` and resets `reconciled` to 0 (REQ-100). Good.
- Note (s10/AC1, REQ-100, design-level, not a defect in this diff): with `po_cost None`
  the next query seeds its baseline from `ledger.last_cost(PO)`, which is now the
  *reconciled row* (this query's estimate, not a session running total). That only
  happens with a pre-s25 `state.json`, or when the first PO query ever crashes. In the
  first-crash case `po_session` is still `None`, so the next query is fresh and nothing
  is subtracted. The design accepts this as C6, and I agree it is out of scope.

### `reconcile.read_turns` / `_parsed`
- What they do: return the parseable lines in file order. A missing file gives `[]`.
- Tests: blank, whitespace, torn, `[1, 2]`, `3`, a missing-key object, non-JSON, and a
  torn last line. Good.
- Minor (s10/AC1, REQ-099, RC6, not blocking): a line that parses but has a wrong-typed
  field is still accepted. Examples: `"cost_usd": "x"`, `"at": "..."`, a list as `role`,
  or string token counts. That line then raises TypeError later in `sum_turns` or
  `find_uncovered` and stops the start, which breaks RC6's "Reconcile never stops a
  start". The runner writes this file itself, so the risk is low. Worth a follow-up:
  type-check in `from_line`, or catch the error per key.

### `reconcile._latest` / `find_uncovered`
- What they do: find each key's latest row `at`. A key's turns after that time are
  uncovered. Keys come out in order of their first uncovered turn.
- Tests: covered vs uncovered by role, the latest row only (RC3), `at` equal to the
  row's time counts as covered, a separate key per story (RC2), and row order (RC4).
  Good.

### `reconcile._turn_count` / `sum_turns` / `told_line`
- Tests: `null` cost counts 0, distinct ids and `null` ids, last line's model, summed
  tokens, `at` stamped at start, and the RC8 text with and without a story. Good.

### `cli._reconcile` and its call in `cli._prepared`
- What it does: reconciles, then prints one RC8 line per row to stderr. It is called
  after `_require_preflight` and before `make_runtime`, as RC1 requires.
- **Defect in the tests (s10/AC1 and s10/AC2, REQ-099; RC1), blocking.**
  `test_the_next_start_ledgers_and_says_so` calls `cli._reconcile(rt.config)` directly.
  No test drives `cli._prepared` or `cmd_start` after a crash. Two consequences:
  1. If someone removes the `_reconcile(config)` line from `_prepared`, every test still
     passes, and coverage stays the same because other start tests cover that line. AC1
     ("On the next start, the ledger includes that turn's cost") is not proven for a
     start.
  2. RC1's order is load-bearing. If `_reconcile` ran after `make_runtime`, the runtime
     would already hold the old `state.json`, and its next save would wipe
     `po_cost.reconciled`. The PO's cut-off cost would then be counted twice (REQ-100).
     Nothing pins that order.
  - Fix (unit-tester): add a test that crashes a PO turn (as `crash()` does) and then runs
    `cmd_start` (or `_prepared`) with a query that ends at once. Assert that the ledger has
    the reconciled PO row once, that stderr has the RC8 line, and that the runtime's
    loaded `state.po_cost.reconciled` equals that row's cost. The design's checklist
    already asked for this ("`cli._prepared` (or `cmd_start` …)").

# Round 2 (after `1b0b5b85`)

**Verdict: done.** The blocking gap is closed.

## `tests/test_reconcile.py::test_cmd_start_reconciles_before_make_runtime` (new)
- What it does: writes two uncovered PO turn lines ($1 each), wraps `cli.make_runtime`
  in a spy that counts PO ledger rows at the moment the runtime is built, runs a real
  `cli.cmd_start` with a `FakeQuery`, and checks exit 0, `seen == [1]`, and the RC8 line
  (`ledgered $2.00 for product-owner`) on stderr.
- Covers s10/AC1 and s10/AC2 (REQ-099; RC1, RC8): a start, not a direct `_reconcile`
  call, ledgers the cut-off spend. It also pins the order:
  - if the `_reconcile(config)` line is removed from `_prepared`, `seen == [0]` and the
    stderr assertion fails;
  - if it moves after `make_runtime`, `seen == [0]`.
  `seen == [1]` also shows one row, not two, at the point the runtime loads state.
- Not asserted: the loaded `state.po_cost.reconciled` (there is no `po_cost` on disk in
  this test). That is acceptable. The order this test pins, together with the unit tests
  of `_net_po_spend` and the resumed-query test, covers REQ-100. Not blocking.
- It imports `any_tool` and `start_args` from `test_cli`. That couples two test modules.
  A conftest helper would be cleaner. Minor; fits no AC.
- Top-level code: none added. OK.
