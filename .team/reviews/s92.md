## Where `route` runs (design departure, does not block)
The design puts `pipeline.route(...)` inside `_evaluate`'s `pulse.doing(GATE_CHORE)`. The code calls it first thing in `_advance_and_log` instead. I checked the results:
- R1 still holds. Only `tests_green_and_covered` (the implement gate) sets `output`, and only the implement dispute path makes `DISPUTE`. The other callers of `_advance_and_log` (`_returned`, `_bounce`, `_fix_effects`) pass outcomes with no `output` that are not disputes, so `route` hands them back unchanged.
- Health is fine. `_settle` already wraps the whole step in `pulse.doing("settling …")`, so the lint runs are not chore-less. The only cost is a vaguer label: "settling" where it could say "gate: implement on sN".
- The cost: `self.owners(story)` (one `scope_for(resolve(role))` per pipeline step) is built on every advance, including returns and fix setbacks. That is cheap. If someone touches this code again, moving the call into `_evaluate` as designed would make it both cheaper and better labelled (m2).
