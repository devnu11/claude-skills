# Review: s179 (resume keeps open sprint worktrees), round 0

Reviewed `git diff 52f53bf7..89ef6321` (story created → last fixup) against
`agile-team/docs/design/s179.md`. Runner: coverage passes (97.89%,
`workspaces.py` 100%). No gate fixes changed assertions: fixup 5ef69279 only
replaced a `SimpleNamespace` boundary with a real `Boundary`, and 89ef6321
added the in-flight guard.

**Verdict: changes requested (developer-cli).** The main fix is right: an
open sprint story's worktree is no longer removed (AC1). But AC2 is only
partly met. The code also doesn't follow the design's R2–R5, and the docs
already written (protocol.md, ADR-0084 amendment, REQ-191, architecture.md)
describe behaviour the code doesn't have. The design's e2e test is missing.

## Functions

### `workspaces.find_prune_reason(story, sprint)` (new)
Returns `"not in the sprint"` when the story is missing, has no sprint, or
is in another sprint; returns the status string when it is done or
cancelled; otherwise `None`.

- **D1 (s179/AC2, REQ-191; design R2). An unknown story is not reported as
  unknown.** `None` returns `"not in the sprint"`. R2.1 says `unknown`,
  and protocol.md, REQ-191 and the ADR say the event names the reason.
  The test `test_a_worktree_with_no_story_is_pruned_as_unknown` asserts
  `"not in the sprint"`, so its name contradicts its assertion.
- **D2 (s179/AC2, REQ-191; design R2 order). The order of the checks is
  wrong.** The sprint check comes before the status check. So a done or
  cancelled story from an earlier sprint (the common case after a boundary)
  is reported as `"not in the sprint"`, not `done`/`cancelled`. R2 checks
  the status first. No test covers a done story with `sprint != state.sprint`.
- **D3 (design R2, protocol.md). The reason strings don't match the
  design and docs.** The code uses `"not in the sprint"`; protocol.md
  documents `not_in_sprint`. The design's `PruneReason` StrEnum (with
  `UNKNOWN`, `NOT_IN_SPRINT` and `SCRATCH`) and `FINISHED_REASONS` table
  were not built. A free-text string in an event field breaks the repo's
  "tables over branching" and "data is validated" rules.
- The return type is `str | None`; the design says `PruneReason | None`.
- Tests: open, needs-manager, blocked, done, cancelled, out of sprint and
  unknown are covered. Missing: an in-flight story (handled by the caller,
  see D6), a done story from another sprint (D2), and a story at `land`.

### `Runtime.recover_stories(cause)` (changed)
Builds `keep` as the stored worktrees minus the stale ones, plus `replay`
when it is pinned, then calls `prune_stale`, then resumes the cut-off steps.

- **D4 (s179/AC2, REQ-191; design R3, R4). Scratch removals write no
  event.** `land` and an unpinned `replay` are removed by `prune_stale`, but
  no `worktree-pruned` event is written. AC2 says "each removal writes one
  event"; REQ-191 and protocol.md say the scratch dirs get reason `scratch`.
  `test_land_and_replay_scratch_dirs_are_still_removed_ac2` checks only the
  removal count, not the events. `Workspaces.stored_scratch` (design, and
  listed in architecture.md's component row) does not exist.
- **D5 (REQ-191; design R5). A removed story's `worktree_head` is not
  cleared.** REQ-191 ("A removed story worktree's recorded head is
  cleared"), protocol.md and the ADR all say it is. The code never touches
  it. So `count_open` keeps counting a removed story's worktree, and
  `ensure` sees a `worktree_head` with no directory. No test checks it.
- The pinned check is still the old inline expression; the design's
  `_pinned_scratch` property and `_prune_worktrees`/`_find_pruned`/
  `_log_pruned` split were not built. That's acceptable on its own, but
  `recover_stories` now does three jobs (pick, prune, resume) in one
  function.
- **D6 (design R2.2, test list; s179/AC2). The in-flight guard has no
  test.** Fixup 89ef6321 added `not (story and story.in_flight)`, but no
  s179 test sets `in_flight` on a done or out-of-sprint story to check that
  it is kept. Also missing: the design's R7 test (the cut-off step's
  `step-end` is the last event when there is also a removal).

### `Runtime._note_stale_worktrees(spaces)` (new)
Emits a `worktree-pruned` event per stale story worktree and returns their
ids.

- **D7 (s179/AC2, REQ-191; design R4, protocol.md). The event data has
  no `worktree` key.** The data is `{"reason": ...}` only; R4 and
  protocol.md say `{"worktree", "reason"}`.
- It emits the event *before* `prune_stale` removes the worktree. A
  removal that raises midway leaves an event for a removal that didn't
  happen. That's minor (prune runs in the same call), but the design logs
  after.
- The name says "note", but the function also decides what is stale
  (a query and a command in one). A small point; the design split them.

### `EventKind.WORKTREE_PRUNED` (new)
Fine. Covered by the event tests.

## Tests vs design

- **D8 (s179/AC1, REQ-190). The e2e test is missing.** The design's
  `tests/e2e/test_s179_resume_e2e.py` (real git, a gitignored file survives
  `start --resume`) does not exist. The story's Tooling section says AC1 is
  "automatic today: tests/e2e/test_s179_resume_e2e.py". The unit tests only
  check with the fake system that a directory exists; nothing checks that a
  real ignored file survives a real `start --resume`.
- AC3 (REQ-192): `test_a_kept_worktree_with_a_moved_head_is_drift_at_the_next_step_ac3`
  covers drift at the next step with no removal. OK.
- AC1 no-`worktree add` test: OK.
- The design's `cli._recover_stories` docstring change was not made. That's
  minor, but the design lists it.
