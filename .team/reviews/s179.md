## Findings

1. **s179/AC1, REQ-190: the e2e test is missing (blocking).** Two documents
   say this test exists:
   - The design (Tests, last item, and its Files list) requires
     `agile-team/runner/tests/e2e/test_s179_resume_e2e.py`, with real git,
     an ignored file in s1's worktree, and `start --resume`.
   - The story's `## Tooling` section says AC1 is "automatic today" through
     that file.

   The file does not exist. `tests/e2e/` holds `test_s165_resume_e2e.py`
   but no s179 file, and the only file that greps for s179 is the unit
   test. The unit tests use `FakeSystem`, so nothing proves that a real
   `git worktree prune` plus a real `ensure` leave a git-ignored file in
   place. That proof is the heart of AC1. The tester must add the e2e test
   as the design describes, or the Tooling line must be corrected. The
   e2e test is the right fix.
2. **No AC (design, `cli.py` section): the docstring was not updated.**
   `cli._recover_stories` (cli.py:538) still says "prune stale worktrees".
   The design asks for "prune the worktrees no open sprint story needs …".
   This is minor, but it is exactly the wording that caused the bug. The
   developer (developer-cli) should fix it.
3. **s179/AC3, REQ-192: covered.** The test
   `test_a_kept_worktree_with_a_moved_head_is_drift_at_the_next_step_ac3`
   checks three things:
   - the worktree survives the resume;
   - `prepare_story` refuses;
   - no `worktree add` runs.

   It also asserts `drift == ["a.py"]`, so it mixes a moved HEAD with a
   dirty file. A test with only a moved HEAD and a clean tree would show
   more directly that HEAD drift alone is caught. This is optional.
4. **s179/AC2, REQ-191: covered.** The tests check one event per removal
   and that kept worktrees log no event. The test named
   `test_a_cut_off_step_end_is_the_last_event_of_a_resume_ac2` really
   tests R7, which belongs to no AC. The name is slightly misleading, and
   this is not a defect.
