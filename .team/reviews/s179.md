## Functions

### `workspaces.PruneReason`, `FINISHED_REASONS` (new)
A StrEnum of the five reasons and a status→reason table. They match design R2/R3
and protocol.md. No defect.

### `workspaces.find_prune_reason(story, sprint)` (new)
Returns `UNKNOWN` for a missing story, `None` for an in-flight story, `DONE`/`CANCELLED`
from the table, then `NOT_IN_SPRINT` unless `story.sprint == sprint` and `sprint` is set.
The order follows R2. Corner case: `state.sprint is None` (no sprint running) prunes
every idle story worktree as `not_in_sprint`. That fits R1 (no sprint means no open
sprint story) and is the same as before the fix.

- Tests cover: open, needs-manager, blocked, done, cancelled, `sprint=None`, `sprint=2`,
  unknown, and in flight + done + other sprint.
- **T1 (s179/AC2, REQ-191; design R2 order and test list).** No test covers a *done*
  (or cancelled) story **from an earlier sprint** that has no step in flight. This is
  exactly the round-0 D2 regression: swap the two checks and every test still passes,
  because the only test with both conditions is in flight. Add
  `find_prune_reason(story("s1", status=DONE, sprint=0), 1) == DONE`.
- **T2 (s179/AC2, REQ-190; design test list "at `land` in sprint 1 → None").** The
  at-`land` case the design names is not tested. That's minor, since `land` is not in
  `FINISHED_REASONS`, but the design asks for it.

### `Workspaces.stored_scratch` (new)
The `land`/`replay` dirs that exist, in `SCRATCH_DIRS` order. Covered by the scratch
and pinned-replay tests. No defect.

### `Runtime.recover_stories(cause)` (changed)
Prunes, then resumes each cut-off step, then saves (R7). Covered by the R7 test.
No defect.

### `Runtime._prune_worktrees()` (new)
Builds `keep` as every stored worktree plus `SCRATCH_DIRS`, minus the ones to remove.
It calls `prune_stale(keep)`, then logs one event per removal. The events are written
after the removal, as the design says. Story ids and scratch names share one name
space in `keep` and `gone`. They can't clash in practice (story ids are `sNNN`), and
`prune_stale` already mixed them before this story. No defect.

### `Runtime._find_pruned(space)` (new)
Maps each stored worktree to its `find_prune_reason`, plus each unpinned existing
scratch dir to `SCRATCH`. Covered (story reasons, scratch, pinned replay). No defect.

### `Runtime._pinned_scratch` (new property)
`{REPLAY}` while `state.boundary.replay` is set, else empty. That's the same rule as
before. Covered by `test_a_pinned_replay_dir_is_kept_ac2` and, as the empty case, by
the scratch test. No defect.

### `Runtime._log_pruned(name, reason)` (new)
Clears `worktree_head` of a removed existing story (R5) and emits `worktree-pruned`
(role `None`, story = name or `None` for scratch, data `{worktree, reason}`) (R4). This
is one function for two of the design's rules, which the design names together in R4,
R5. The unknown-story branch (`story is None`, not scratch) is covered by the unknown
test. No defect.

### `EventKind.WORKTREE_PRUNED` (new)
Fine.

## Tests vs ACs

- **E1 (s179/AC1, REQ-190; design test list and Files; story Tooling). The e2e test
  is still missing.** `agile-team/runner/tests/e2e/test_s179_resume_e2e.py` does not
  exist (no e2e file in the diff). AC1 is about git-ignored files surviving a real
  stop and `start --resume`. The unit tests use the fake system and check only that
  the directory still exists. So the AC's main claim, that a real ignored file
  survives the real `start --resume` path through `cli._recover_stories`, is checked
  by nothing. The Tooling line that says it is checked is false as written. Fix:
  add the e2e test as the design describes, reusing the `test_s165_resume_e2e`
  harness. If it can't be built, the PO must change the Tooling line to "by hand",
  and the design's Files list must drop it.
- **T3 (s179/AC1, REQ-190; design test list).**
  `test_a_resume_keeps_the_worktree_of_an_idle_open_story_ac1` doesn't do what the
  design's test does. It writes no ignored-style file (e.g.
  `worktrees/s2/house-rules/runner/.venv/marker`), and it doesn't check that
  `worktree_head` is unchanged. Add both. The head check is cheap and guards R5
  against clearing a kept story's head.
- AC1, no `worktree add` at the next step (R8): covered.
- AC2: removals and one event per removal (story, worktree, reason, role `None`),

- AC3 (REQ-192): a kept worktree with a moved HEAD survives and is refused as drift

- `test_a_cut_off_step_end_is_the_last_event_of_a_resume_ac2` tests R7, not AC2. The
