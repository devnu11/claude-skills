## Non-blocking (fix while the file is open)

### N1. The one-of-each AC1 test asserts only the events (s185/AC1, REQ-239)

`test_a_resume_keeps_open_sprint_worktrees_and_removes_the_rest_ac1` checks the
set of `worktree-pruned` (story, reason) pairs and nothing else. The design's
checklist also asks for these checks:

- dirs s1, s2 and s3 exist, and s4–s7 are gone;
- `worktree_head` is `""` for s4–s7 and unchanged for s1–s3;
- no `worktree remove` names s1, s2 or s3.

If code removed a kept worktree without writing an event, this test would still
pass. That is exactly the s179 bug this follow-up re-checks. The second AC1 test
covers some of this, for s1 and s4 only. The blocked story (s2) and the
in-flight one (s3, done and out of sprint) are never shown to keep their dir.
"one each" is also not pinned, because the assertion compares a set, which
would hide a duplicated event. Compare a sorted list, as the second test does.

### N2. AC2 resume uses `Cause.CRASH`, the design says `Cause.KILLED` (s185/AC2, REQ-240)

`test_an_older_state_resumes_without_removing_or_halting_ac2` passes
`Cause.CRASH`. The design asks for `Cause.KILLED`, which is the stop-then-resume
path AC2 describes. Either use KILLED or parametrise over both.

### N3. `refusal` bypasses `start_sprint` without saying why (s185/AC3, REQ-241)

The design asks for the "every obstacle" test to go through
`Tools.start_sprint`. It allows calling `_drop_merged_entries` and
`_switch_refusal` directly only if `start_sprint` refuses earlier, and then
"say so in the docstring". The docstring describes the two calls but gives no
reason. So nothing tests that `start_sprint` actually calls them in that order
and returns `SWITCH_REFUSED` (REQ-241: "`start_sprint` refuses and lists").
Either drive `start_sprint` in the all-obstacles test, or write down why it
can't be driven.

### N4. Next-start test doesn't check the worktree path (s185/AC3, REQ-241)

`test_that_storys_next_start_makes_its_branch_and_worktree_ac3` accepts any
`worktree add`. The design asks for `…/worktrees/s8`. Assert that the argv
names `worktrees/s8`.

### N5. House rules in the test helpers (no AC)

- `set_scene` takes five keyword parameters, three of them booleans. The
  charter allows at most 2 parameters and no boolean flags. A small scene
  dataclass, or an `Obstacle` enum set, would fit the parametrised table
  better.
- `SwitchUpstream`'s three public methods and the module helpers
  `older_runtime` and `with_product_backlog_story` have no docstrings.
