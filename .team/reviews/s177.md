`follow_remote` is gone. The two changed s163 tests and the one changed s180 test used
`remote == HEAD` to mean "gives up and starts again". s177/AC1 (REQ-267) turns that case
into a hold, so moving them to a remote that has moved on is justified. They still check
the s163 rules (G4, R2) and the s180 rule (C6). No assertion was weakened.

## Findings by AC

- **s177/AC1 (REQ-267).** The behaviour is correct. The tests assert the hold, that the
  refusal text is in the reason, that only one merge is made, that `landed` is kept, that
  the landing branch is not deleted, that no drop is logged, and that a retry pushes the
  same merge.
  - T1 (minor): the exact reason prefix `pushing the sprint branch <branch> was refused:`
    is not asserted, only that the reason contains `REFUSAL`. Also, AC1 says `entry.head`
    stays unchanged, but only `entry.pushed` is checked.
  - T2 (minor): `test_a_retry_pushes_the_same_merge_again_ac1` checks neither that the
    retry deletes the landing branch (design checklist, R4) nor that it lands with
    `ci: green`.
  - T3 (minor): `assert BRANCH  # the story branch name is untouched by the hold` asserts a
    module constant, so it can never fail. Its comment claims a check that isn't made. It
    should be removed or replaced with a real check.
  - The tests resume through a second `land`, not through `continue_story` /
    `release_story`. R2 says those need no change because they reach the same
    `run_land` resume path, so I accept this.
- **s177/AC2 (REQ-268).** Correct and well covered: the PASS verdict, that `pushed` and
  `head` both equal the merge, the `--ff-only` to the merge, `story-landed` with
  `ci: green`, no drop, and one merge.
  - D1 (minor, copy/paste): both AC2 tests repeat the same four reply lines. A helper such
    as `remote_has_merge(fake)` would remove the repeat.
- **s177/AC3 (REQ-269).** Correct. The heads are distinct by construction (R5): each
  followed head becomes `pushed`, so a repeat is classified UNMOVED. That is what
  `test_a_repeated_remote_head_holds_before_max_restarts_ac3` shows.
  - T4 (minor): the KEPT_MOVING test checks that each head is in the reason but not that
    they are in order (oldest first), and it matches `"the sprint branch kept moving"`
    against `str(report)`, not against the reason.
  - T5 (minor): two items on the design checklist are covered only at unit level, through
    `find_restart_hold` with hand-set counters. They are "4 moved remotes, then a refused
    carry, then success: lands" and "5 carry refusals: HEAD_KEPT_MOVING". The line
    `restarts += 1` runs in other tests, but no end-to-end test mixes the two causes.
- **Fits no AC.** I found no new top-level code in the source or the tests. The docs
  (`protocol.md`, ADR-0084, REQ-169) were updated in the same story, and the
  "A refused sprint push" section matches R1 to R4.
