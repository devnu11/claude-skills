## Function by function

### `process_groups.py` (new)
- **`leads_own_group(pid)`**: true for a live pid > 1 that is not the runner's pgrp and leads its own group. Tested with a new-session child, a same-group child, `getpid()` and a reaped pid. *Minor:* `os.getpgid(10**30)` raises `OverflowError`, which `except OSError` does not catch (verified). So `stop_stale` would crash on a pid file holding a huge number. `in_runner_group` already catches `OverflowError`. The old `stop_stale` had the same gap, and only the runner writes the pid file (`sandbox.py:359`), so I am not blocking on it.
- **`may_signal_child_group(pid)`** (G2): refuses pid ≤ 1 and the runner's pgrp. It allows a group leader, or a lookup that raises `ProcessLookupError`. Every other `OSError` refuses. *Gap:* the refusal on any other `OSError` (lines 32–33) is the only uncovered code in s41. A test that patches `getpgid` to raise `PermissionError` and asserts nothing is sent would pin it.
- **`signal_child_group(pid, sig)`**: sends `killpg(pid, sig)`, never `getpgid(...)`, and suppresses lookup and permission errors. Tests 1, 2 and the suppress test cover this, including `sandbox._signal_group` with a same-group child and with the runner's own pid.
- **`in_runner_group(pid)`**: tested with the runner itself, a same-group child, a new-session child, a reaped pid and an overflowing pid.
- **`parse_etime(text)`**: covers the four design examples plus whitespace, `""`, `abc`, four parts and a bad day value. The body is 9 lines, just over the "ideally < 8" guide, which is acceptable.
- **`_elapsed` / `started_at`**: tested with a fresh child (within 3 s), a reaped pid, `TimeoutExpired`, `OSError` and a non-zero exit.
- **`Recorded.is_ours()`**: checks the cheap condition first and runs `ps` only after it. Tested: true for a fresh child; false for a reused pid (written an hour ago), a same-group child, the runner's pid, and when the start time is unknown.

### `sandbox.py`
- **`_signal_group`**: now delegates to `signal_child_group`, with the same signature (G6).
- **`_recorded`**: catches `OSError` and `ValueError` and returns `None`. Tested with an unreadable pid file.
- **`_ends_within`**: polls `killpg(pgid, 0)` with a monotonic deadline, and any `OSError` counts as "gone". This matches the design. The only use of signal 0 outside `process_groups` is intended, and `test_no_other_module_calls_killpg` pins it.
- **`_end_group`**: sends SIGTERM, waits, then re-checks `is_ours()` before SIGKILL (G5) and reads `STOP_WAIT_S` at call time. Both branches are tested: no SIGKILL once the group stops being ours, SIGKILL while it is still ours. The existing SIGTERM-ignoring escalation tests still pass.
- **`stop_stale`**: signals only when `is_ours()`, and always deletes the file. Tests cover a reused pid (left alive), the runner's pid and pgrp (nothing sent), a real recorded group (ended by SIGTERM), and an unreadable file.

### `commands.py`
- **`kill_group`**: now `signal_child_group(proc.pid, SIGKILL)`, and the unused imports are gone. A same-group proc gets nothing; a new-session proc gets SIGKILL. The s43 timeout and group-kill tests stay green.

### `kill_check.py` (new)
- **`kill_denial(words)`**: checks K1 (by name), then K2 (the first `kill` word), then a `xargs` feeder, then each target. Tests cover all denial strings with exact text, the prefixes `sudo`, `/bin/kill` and `-s TERM`, and the allowed forms in checklist 16.
- **`kill_targets` / `_option_width`**: all five checklist examples are tested.
- **`target_denial` / `_protected`**: covers run-time marks, `0`, `-1`, `-<pgrp>`, a same-group pid and the runner's pid. A new-session pid and a reaped pid pass.
- Over-deny, acceptable under the s7 policy: any segment holding the word `kill` gets its later words checked. So `grep -rn kill $(git ls-files)` is denied as a run-time target, and `grep pkill .` is denied by name. A role can rephrase these.

### `guard.py`
- **`_check_kills`**: added last in `_check_view`. Test 18 pins the order: the git reason is reported first. The module docstring has the bullet.

### `roles/_shared.md`

## Copy/paste search
- The `next((r for r in map(f, xs) if r), None)` idiom appears in `kill_denial`, `_check_kills` and (as a variant) `_check_view`. These are one-liners and not worth a helper.
- There is no duplicated block between `sandbox.py` and `process_groups.py`. The old `_group_leader` was deleted rather than left beside `leads_own_group`.
- In the tests, the `sent`, `same_group` and `own_group` fixtures are local to `test_process_groups.py`, and `test_kill_check.py` has its own `same_group` and `own_group`. That is small duplication; a shared `conftest` fixture would be tidier but is not required.

## Non-blocking follow-ups
1. Test `may_signal_child_group` when `getpgid` raises `PermissionError` (it refuses). That restores 100% on `process_groups.py`.
2. Catch `OverflowError` in `leads_own_group`, as `in_runner_group` does, with a pid-file test holding `99999999999999999999`.
3. Consider denying `kill $PPID` (and `kill $$`'s parent forms). They are not chosen at run time, and `$PPID` in a role's Bash is the agent CLI, in the runner's group. This is outside the design's K4. It is a residual-risk note for the Architect, not a defect.
