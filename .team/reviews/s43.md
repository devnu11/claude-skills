## Non-blocking notes (follow-ups, not defects against the design)

- **N1 (guard reach).** The guard only checks the first word of each segment, as T12
  says. So a loop after `do`, `then`, `(` or `{`, or inside `bash -c '…'`, is not seen.
  Any unrelated `timeout` segment also lets a whole command through (`timeout 1 true;
  until …`). A false positive is also possible: a newline inside a quoted `python -c`
  script that starts `while True:` is denied. This is enough to catch the s29 accident,
  but it is not airtight. If loops keep slipping through, a follow-up could skip the
  keywords `do`/`then`/`else`/`(`/`{` before reading the first word.
- **N2.** The test helper `alive()` could reuse `state.pid_alive`.
- **N3.** A command that really exits with 124 for some other reason now counts as a
  timeout. The design chose this deliberately (it matches GNU `timeout`), so it is noted
  only.

## Changed functions

| Function | What it does now | Tests | Defects |
|---|---|---|---|
| `commands.kill_group` | Calls `process_groups.signal_child_group(proc.pid, SIGKILL)`. That signals the pid as the pgid, and refuses for pid ≤ 1, the runner's own group, or a pid that leads another group. It treats a reaped-lookup (`ProcessLookupError`) as its own group, which is right here because the `Popen` has not been reaped yet. It never signals a `getpgid` result, which matches T4 as revised. | `test_s43::test_only_the_group_is_killed`, the e2e group test, and `test_process_groups` for the refusals | none |
| `CommandShell.run` (unchanged) | Re-checked against revised T4: both the timeout and `BaseException` paths go through `kill_group`. | as in round 0 | none |

## E2E tests (`test_command_timeout_e2e.py`)

- **Real pytest hang.** A real pytest child runs with `faulthandler_timeout=0.5` under a
  3 s limit. The test checks `TIMED_OUT`, a wall clock under 15 s, the name
  `test_hang.py::test_hangs`, and that `tests_red` bounces with the timeout reason. This
  covers AC1 and AC2 end to end. Weakness (E1): the gate assertion only checks the reason
  prefix, not that the test name survives into the bounce reason through `tail`. The unit
  tests in `test_s43` already pin the layout (reason last), so this is not a gap in
  coverage.
- **No nameable test.** `sleep 30` under 0.3 s: the last line is `NO_HUNG_LINE`, the line
  before it has the limit and the command, and `timed_out` bounces. This covers AC2's
  fallback.
- **Group kill.** The background grandchild dies, and a foreign `start_new_session`
  process survives. `finally` cleans up the foreign process. This covers AC1 "only that".
- **Guard.** It covers the s29 `until grep` loop and `while true` (denied) and a bounded
  `for` loop (allowed). This covers AC4.

## Copy/paste search

- `alive(pid)` now exists three times: `test_sandbox._alive`, `test_s43.alive`, and the
  e2e `alive` + `_ps_state`. The e2e version is the most careful one because it treats a
  zombie as dead. This is N2 from round 0, grown by one copy. A shared helper in
  `tests/conftest.py` (or reuse of `state.pid_alive` plus a zombie check) is a follow-up.
  It is not a blocker.
- The e2e file does `import subprocess` inside two functions instead of once at module
  top. This is style only, and ruff accepts it.

## Non-blocking notes (new)

- **E1.** Assert that the bounce reason contains `test_hang.py::test_hangs`, so that AC2's
  "the bounce reason names the hanging test" is pinned through the gate, not just the
  runner's output.
- **E2.** The `hanging_suite` docstring says "pytest-timeout suite", but the suite relies
  on `faulthandler_timeout`, not pytest-timeout. The wording is misleading, and the
  behaviour is right.
- **E3.** On Linux `/proc/<pid>` exists for a zombie, so `alive` would report a zombie as
  alive there. In practice init reaps the orphaned `sleep` at once, so the test should
  not flake. Worth noting if CI moves to Linux.

Round 0 notes N1–N3 stand. There are no defects against the design or the ACs.
