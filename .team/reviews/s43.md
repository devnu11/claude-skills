## Non-blocking notes (follow-ups, not defects against the design)

- **N1 (guard reach).** The guard only checks the first word of each segment, as T12
  says. So a loop after `do`, `then`, `(` or `{`, or inside `bash -c '…'`, is not seen.
  Any unrelated `timeout` segment also lets a whole command through (`timeout 1 true;
  until …`). A false positive is also possible: a newline inside a quoted `python -c`
  script that starts `while True:` is denied. This is enough to catch the s29 accident,
  but it is not airtight. If loops keep slipping through, a follow-up could skip the
  keywords `do`/`then`/`else`/`(`/`{` before reading the first word.
- **N2.** The test helper `alive()` could reuse `state.pid_alive`.
- **N3.** A command that really exits with 124 for some other reason now counts as a
  timeout. The design chose this deliberately (it matches GNU `timeout`), so it is noted
  only.
