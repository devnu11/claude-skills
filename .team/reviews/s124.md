# Review: s124, a sprint ends only when every story in it is done, cancelled or reverted

Reviewer step, round 0. Diff `6f2a99b..c0d22b9`: the architect's commit 9d4c25b, then fixups f40cd9f, 46445d0, 6963bb9, d12b878 and c0d22b9.
Runner: coverage passed at 99.55% (exit 0). Lint is clean.

**Verdict: changes requested. Next: integration-tester.** The code matches the design, and I found no defect that would break a run. But two things the design requires are not tested:
- the Board and Backlog `reverted (n×)` pill (R11, part of AC2; design test 14);
- real git for `revert_all`.

The tests' own docstrings say the e2e tests cover these, but no e2e test does.

## Blocking (integration-tester)

1. **R11 Board and Backlog pill: no test anywhere.**
   - `revertPill`, `storyCard` and `backlogRow` changed in `index.html`, but `grep "reverted ("` finds nothing in `tests/`.
   - d12b878 added a `story-reverted` sample to the s112 Activity e2e. That covers only the Activity row.
   - Design test 14 asks for `tests/e2e/test_s124_reverted_e2e.py`, modelled on `test_s122_activity_e2e.py`. It should seed a story with one revert and a `story-reverted` event, then check that:
     - the Backlog row shows `reverted (1×)`;
     - the Board card shows `reverted (1×)`;
     - a story with `reverts: 0` shows no pill.
   - Add a snapshot-level assertion too: a `StoryState` with one `RevertEntry` gives `"reverts": 1`. Today `test_snapshot.py` only checks `0`.
2. **`Git.revert_all` and `Git.log_from` have no real-git test.**
   - `test_s124_helpers.py` scripts the git argv through `FakeSystem`. `ScriptGit` in `test_s124_sprint_end.py` replaces the methods entirely. Its module docstring says "the real git behaviour of `revert_all` … is the e2e tests'", but no such test exists.
   - The conflict path rests on an untested git detail: `git revert --no-commit <one sha>` must leave `REVERT_HEAD` on a conflict, or `git revert --abort` fails silently (`attempt` ignores its exit) and leaves conflict markers in the tree while the tool says "nothing was reverted".
   - Pin it with a scratch repo (design tests 4 and 12):
     - s1's `feat` and `fixup!` commits around another story's commit; after `revert_all`, there is one new commit, s1's changes are undone and the other story's change is kept;
     - a later commit edits the same lines: `GitError` names the path, HEAD is unchanged and `git status --porcelain` is empty. Do this both with one sha and with two.

## Non-blocking (developer, here or in a follow-up)

3. **Copy/paste between `reverts.py` and `story_admin.py`.** The design prescribes the parallel shapes, but the bodies are duplicated nearly line for line:

   | reverts.py | story_admin.py | Same? |
   |---|---|---|
   | `decision` | `decision` | identical apart from the table |
   | `Settling` | `Settled` | identical dataclass |
   | `settle()` (list comprehension) | `answered()` + `Clerk.settle` | same, `HoldKind` differs |
   | `_settle_one` data dict | `Clerk._settle_one` data dict | identical 5 keys |
   | `_do_keep` | `keep` | identical |
   | `_do_unclear` | `unclear` | identical apart from the template |
   | `_admin` | `Clerk._emit` | identical |

   `reverts._shorts` also duplicates `revert_log._shorts` exactly.

   Suggested fix: `answered(state, answers, kind)`, a shared `answer_data(asked, answer, decided)`, and an `unclear(template)` factory. Make `revert_log.shorts` public. This is DRY in the charter's sense, but it does not change behaviour.
4. **A refused revert can still commit the PO's edits.** `Reverter.revert` calls `settle_po()` before `revert_all`, so a conflict refusal can leave a new PO commit. R1 says "a refusal changes … nothing", and R4 (a) needs a clean tree. 6963bb9 changed the conflict test's setup to settle first, which hides this. It is harmless, since settle_tree records the checkout, but the docs or the `REVERT_CONFLICT` text could say so.
5. **A missing story file leaves the run half reverted.** `_record` reads the story file after the revert commit exists. If the file is missing, `read_text` raises: HEAD has the revert, the state is not reset and the checkout is not recorded, so the next guard halts. Stories normally have files, so the risk is low. Checking that the file exists before `_undo` would close it.
6. **The brief tests don't check the prompt that was actually sent.** The helper `prompt()` in `test_s124_sprint_end.py` calls `rt.user_prompt(rt.plan(...))`. That re-renders the prompt after `plan()` has already built `plan.prompt` and removed the role from `revert_owed`. Assert on `plan.prompt` instead. That is the text the role receives, and the once-only rule (R8) would then be pinned with no doubt about the order. I could not reconcile `test_after_the_note_a_later_step_has_none` with this order by reading alone, though the runner reports it green.
7. **`test_the_wait_shows_a_revert_request` checks only enum values.** The WAITS row's order is pinned in `test_priority.py` (c0d22b9), but nothing checks that a story with a `REVERT` po_hold gets `WaitReason.REVERT_REQUESTED` with its reason as the title.
