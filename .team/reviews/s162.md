## Findings

### D1 (s162/AC1 and AC2, REQ-186 and REQ-187; copy/paste): two end-to-end test files for one story. Blocking.

The story now has two e2e files:

- `agile-team/runner/tests/e2e/test_s162_unattended_time_left_e2e.py` was added in
  `4e77f8fb`. It is the file listed in `design/s162.md` under Files, and the one reviewed
  in round 3. It seeds five DONE jobs and covers every AC1 shape through `status`, `list`
  and `wait`, plus AC2's unchanged files and unchanged output.
- `agile-team/runner/tests/e2e/test_s162_time_left_e2e.py` was added in `f6e8c86f`, by a
  second integration-tester step after the re-run. It covers the same ground again:
  `23h41m`, `0m`, `null`, `overdue`, `list`, `wait`, and `state.json` unchanged. It has
  its own `Unattended` wrapper, which duplicates the first file's `uv`/`cli` helpers.

Fix: keep one file. Delete `test_s162_time_left_e2e.py`, or merge anything it adds into the
designed file. The only thing it adds is `overdue` reached by real time passing; the first
file seeds a deadline that has already passed. If you keep the second file instead, update
`design/s162.md` Files.

Further reasons to drop the second file rather than the first:

- **It is less stable.** It starts real supervisors running `sleep 300`, then checks
  `state.read_bytes() == before` around a `list` while the supervisor is still live. Any
  state write by the supervisor during that window fails the test, and the test has no
  reason to need a live job. The first file uses DONE jobs and doesn't have this race.
- **It ignores exit codes.** `Unattended.run` never checks the exit code, so a failed
  `start` only shows up later as a JSON parse error.
- **It is slower.** It adds about ten more `uv run` calls and live supervisors to the e2e
  wall time for no added coverage.
