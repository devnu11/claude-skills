## Functions

### `limits.format_time_left(deadline, now)` (s162/AC1, REQ-174)
- What it does: returns `None` when there is no deadline, `"overdue"` when `deadline <= now`,
  and otherwise `span(whole_minutes * 60)`, or `"0m"` under a minute.
- Correctness: `int((deadline-now)//60)*60` is a whole number of minutes, so `span` never
  writes a seconds part and its `round()` has no effect. The boundary `deadline == now` gives
  `overdue`, which matches design rule 2 (the same test `_future` uses).
- Tests: `test_limits.py::test_time_left` covers all 8 cases: None, equal, past, 59 s,
  rounding down (41m59s gives 41m), 23h41m, a whole hour, and past a day (`1d2m`). Complete.
- Defect: none. Note: the design specified the name `time_left` and an `OVERDUE` constant.
  The developer renamed the function to `format_time_left` because of the verb-name rule
  (fixup f512dd34), and the literal `"overdue"` is used once. That's acceptable. See D1 for
  the docs.

### `cli.build_status_limits(bounds, now)` (s162/AC1, s162/AC2, REQ-174, REQ-175)
- What it does: builds `limits_report`, then rebuilds the dict with `time_left` right after
  `deadline`. `limits_report` is unchanged, so the `extend` event is unchanged.
- Tests: `test_report_time_left_beside_the_deadline` checks the key position and that
  `deadline` is unchanged. `test_extend_event_has_no_time_left` checks that the event has no
  `time_left`.
- Defect: none. The design named it `timed_limits_report` (see D1).

### `cli.report(job, now)` (s162/AC1, s162/AC2, REQ-174, REQ-175)
- What it does: the job report as before, with `time_left` measured at `now`. It writes
  nothing.
- Tests: these tests cover overdue, no deadline and the key order:
  `test_report_time_left_overdue`, `_without_a_deadline`, and
  `test_report_keeps_its_other_fields_in_order`.
  `test_status_writes_nothing` compares `state.json` and `events.jsonl` byte for byte.
- Minor gap (s162/AC2, REQ-175, not blocking): the field-order test checks key order but not
  the values of the other fields. The values are unchanged by construction (`limits_report`
  is untouched), so the risk is low.

### Callers: `detach`, `foreground`, `cmd_status`, `cmd_list`, `_waited`, `cmd_extend` (s162/AC2, REQ-175)
- Each passes `time.time()` when the command runs. `cmd_list` reads the clock once for the
  whole list, as the design asks.
- Tests: `test_status_list_and_wait_print_time_left` uses `now + 5430` s (90.5 min). It
  expects `1h30m`, which holds through up to 30 s of drift, so the test is not flaky.
  `extend` output has no dedicated `time_left` assert, but it goes through the same
  `report`.
