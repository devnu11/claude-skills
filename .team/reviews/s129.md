## Blocking finding

1. **s129/AC3, REQ-025: the duration scan misses dict literals inside a list or tuple, so two exact
   compares get through.** `_pair_violation` checks a dict only when the dict is a whole side of the
   compare (`_dict_violation(a) or _dict_violation(b)`). `_sequence_violation` checks list elements only
   through `_one_sided`, which never looks inside a dict. So `assert rows == [{"seconds": 0}]` is not
   flagged. That is the usual shape for snapshot rows. An AST pass over the unit tree finds two sites:
   - `tests/test_s100_sleeps.py:60`:
     `assert lines(fake) == [{"from": start, "to": start + 6 * BEAT, "slept": 5 * BEAT}]`. This `slept`
     is computed by the pulse. Lines 71 and 92 of the same file already compare that same quantity with
     `about(...)`. This one was missed only because the scan can't see it.
   - `tests/test_s100_sleeps.py:131`: `... == [{"from": 1, "to": 9, "slept": 4}]`. By the scan's own
     definition (rule 4, a key in `DURATION_NAMES`) this is a duration compare. Convert it to `about(4)`.

   Fix (unit-tester, inside the design's intent: checklist "including tuple, list and dict-literal
   compares"):
   - Make the list/tuple check also run the dict check on each element. Two ways: have
     `_sequence_violation` apply `_dict_violation` to each element, or have `_dict_violation` recurse
     through `ast.List`/`ast.Tuple` elements.
   - Add `assert rows == [{"seconds": 0}]` and `assert rows == ({"slept": 1},)` to
     `test_exact_compares_are_caught`, and `assert rows == [{"seconds": about(0)}]` to
     `test_tolerant_or_other_compares_pass`.
   - Convert the two sites above. This also keeps the gap out of the e2e scan, which reuses
     `clock_scan`.
