# Review: s175 (step review, round 0)

Diff: `git diff 0c8c007a^ HEAD` (feat + two fixups). Design: `agile-team/docs/design/s175.md`
(E1–E7). Verdict: **changes requested** (developer). The code implements a much smaller
approach than the design. That approach repeats the incident's bug on the real landing path
and leaves AC3's hold reason unchanged.

## Changed functions

### `stages.Run.note` (stages.py)
It now also stores `last = (command, code)` on every note. Its returned-stage behaviour
(RS5, first failure else latest) is unchanged and covered by
`test_a_failure_in_a_stage_that_ends_well_is_still_the_first_failure`. The design says
"`Run.note` is unchanged" and puts the raising call on the exception instead (E1
`Invocation`).

### `stages.Run.fail` (stages.py), new
It sets `raised`, sets `error` to the first line cut to 500 characters, and if anything was
noted sets `detail, code = last`.

- **D1, s175/AC1, REQ-204 (blocker).** "The last command noted" is not "the call that
  raised". On the real land path, cleanup runs after the raising call:
  `Lander.finish_pushed` (landing.py:448) deletes the landing branch in a `finally` after
  `wait_ci`/`OUTCOMES` raise, and `drop_merge`/`clear_tree` run
  `git worktree remove --force` (landing.py:271), which is the tolerated command from the
  incident. In both cases `last` is the cleanup command, so the event again names a
  tolerated or unrelated command. That is the bug the story reports. `GhPrs.close`
  (upstream.py:364) has the same problem: on a failed close it runs `gh pr view` before it
  raises, so `detail` names the view with code 0. The design's E1/E2 fix this by having the
  exception carry its `Invocation`.
- **D2, s175/AC1, REQ-204.** When an exception has no command (a plain `RuntimeError`, a
  `KeyError` in landing code), `detail`/`code` still show the last noted command, e.g.
  `git fetch`, 0. Design E2 and the updated `protocol.md` both say `""` and `null`
  ("or `""` when no command raised it, even if an earlier one failed"). So the code
  contradicts the doc written in the same story. No test covers this (design test plan,
  second E2 item).
- **D3, s175/AC1, REQ-204.** `error` takes the first line, not the first non-blank line:
  `"\nboom"` gives `""`. Design E2 and protocol.md say "first non-blank line". Untested.
- **D4, s175/AC1, REQ-204.** `error` is not masked. `Timed.data` writes `run.error` raw,
  while design E3 and protocol.md say `masked`. A git or gh error line can hold a token
  URL (`https://x-access-token:…@github.com`), which would then land in `events.jsonl` and
  the dashboard unmasked. Untested.
- `ERROR_CHARS` sits in `stages.py`. The design puts `ERROR_MAX` in `stage_log.py` with
  `show_error`. Minor, but it follows from D4.

### `stage_log.Timed.data`
Adds `"error"` after `"raised"`. The key order is covered (test_s99, test_s118, s175 test).
See D4 on masking.

### `upstream.GhPrs._gh` / `upstream.describe_failure`, new
It builds `"gh <args> (exit N): <output collapsed>"` and then calls `.rstrip(": ")`.

- **D5, s175/AC3, REQ-206.** `rstrip(": ")` strips a character set, not a suffix, so any
  output ending in `:` or a space loses those characters (`"error:"` becomes `"error"`).
  It also hides the "no output" case: the design's `"(no output)"` marker (E5) is missing.
  There is no HTTP status (`, HTTP 403`, E5), so a rate limit and a refused push are told
  apart only if gh's text happens to say so. There is no output cap (`OUTPUT_MAX` = 300),
  and only `crash_halt`'s 200-character cut limits it. Plain-text bodies no longer keep
  today's `out.strip()` message (E5), though that part is arguably harmless.
- **D6, s175/AC3, REQ-206.** `GhPrs.close` still raises `UpstreamError(out.strip())`, so an
  empty body still gives an empty message (design E5 names `close`). Non-JSON output on
  exit 0 (`find`, `job`, `list_checks` → `json.loads`) still raises a bare
  `JSONDecodeError` that names no command (design E6). Neither is done or tested.
- Tests: `test_an_empty_or_non_text_body_still_names_the_command_and_code` and
  `test_the_raw_output_is_trimmed_to_one_line` cover `_gh`. The assertion
  `"1" in text.replace(RAISING, "")` is weak: any digit 1 passes it. Assert the exact
  string instead.

### `scheduler.Scheduler.run_work`
It calls `log_traceback` on every exception.

- **D7, s175/AC2, REQ-205.** A crashed role step is now logged twice. `Runtime.run_here`
  (dispatch.py:950) already calls `log_traceback` and re-raises into `run_work`. Design E4
  says role and boundary steps "are not logged twice" and puts the log on the land path.
  No test covers a role-step crash writing one entry.
- **D8, s175/AC2, REQ-205.** `log_traceback` sits inside the `except` without suppressing
  `OSError` (E4). If `crash.log` can't be written, `run_work` raises, `report_back` is
  never called, and the story's step is lost silently, which is worse than before.
  Untested.
- The AC2 test (`test_a_raising_landing_logs_its_traceback_to_crash_log`) covers the
  happy path and is fine.

### `handover.hold_reason`: not changed
- **D9, s175/AC3, REQ-206 (blocker).** The AC requires that "the story's hold reason for a
  landing error carry the error's message." `hold_reason` still returns the bare trigger
  name `"error"` (handover.py:398). Design E7 (`error: <reason>`) is not implemented, and
  the protocol.md row the story added ("the story's hold reads `error: <reason>`") is false.
  `test_the_report_reason_carries_the_error_message` checks only the report's `reason`,
  never the hold. The design's E7 tests and its end-to-end test (a tolerated 128 then a
  raising gh call through a real `story.land` stage, then the hold and hand-over) are
  absent.

## Tests vs design test plan
`tests/test_s175_land_error.py`: the design names `test_s175_landing_errors.py`, which is
minor. The missing plan items are: E1 (`GitError`/`UpstreamError` carry an invocation), E2
(no invocation gives `""`/`null`), E3 masking, E5 HTTP status / `(no output)` / 300 cap /
`close`, E6 JSON decode, E4 OSError and no double log, E7 hold reason, and the end-to-end
land. The AC1 tests note commands by hand in the order that suits `last`. None runs
cleanup after the raise, which is the case the real lander produces (D1).
