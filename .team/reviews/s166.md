## New in round 2

### `tests/e2e/test_s166_close_budget_e2e.py` (s166/AC1 REQ-174, s166/AC2 REQ-175)

**What it does.** It puts a POSIX `sh` stub `gh` first on `PATH`, and environment variables
script the stub's close exit code, its close message and the state that view returns. Then it
drives a real `GhPrs(command_runner(...)).close`, so the subprocess path is exercised end to
end and not just the injected `run` fake.
- `test_ac1_a_merged_story_pr_closes_without_error`: the close fails "already merged" and
  view says MERGED. It returns, with one close and then one view (AC1: merged is not an error).
- `test_ac1_any_other_failure_is_still_reported`: the close fails "boom" and view says OPEN.
  It raises `UpstreamError` matching "boom" (AC1: other failures are reported as before).
- `test_ac1_an_open_pr_closes_with_the_note_and_no_view`: the close succeeds. The note follows
  `--comment` and no view runs (AC1: an open PR gets the note).
- `test_ac2_a_running_landing_does_not_halt_the_budget_check`: a running `LAND` work with the
  role `runner` plus a new `developer-cli` step gives `None` and no `RoleError` (AC2).

**Coverage of corner cases.** The e2e level checks one case per behaviour. The corners are in
the unit file reviewed in round 0: unreadable views, CLOSED, view exit codes, BOUNDARY
beside a role step and beside the Manager, and the budget arithmetic. The e2e file runs only
`LAND` for AC2, not `BOUNDARY`. The sprint-51 crash was the boundary case, but the unit tests
cover it through the same `costly_work` filter, so it adds no risk.

**Stub correctness.** `gh pr close 40 --comment landed` puts `close` in `$2`, and
`gh pr view 40 --json state` puts `view` in `$2`, so the `case` dispatch is right. The
`echo "$@" >> "$GH_LOG"` line gives the log the assertions read. The stub has no bashisms.

**Top-level code.** Only the docstring, imports and constants (`sched = Late("scheduler")`,
`STUB`), then functions. Clean.

**Nit N4 (no AC; house rules).** `gh_on_path(tmp_path, monkeypatch, close, state)` takes four
parameters, and the charter allows at most two. The static gate passed, so test helpers are
evidently not checked. A small dataclass for the scripted gh (`close`, `state`) would bring it
to three. It is cosmetic, and it does not block.

**Copy/paste.** The stub-on-PATH setup is local to this file. I found no matching
helper elsewhere that it should reuse.

## Round-0 findings (code unchanged since then)

- `GhPrs.close(pr, note)` (s166/AC1, REQ-174): one `gh pr close --comment`. On failure it

  never posts a separate comment. The landing, `story_ci._close` and the replay all share it.
  Tests cover every design checklist item, plus the l9 landing end to end. No defects.
- `GhPrs._is_merged(pr)` (s166/AC1, REQ-174): uses `run`, not `_gh`. It is True only on exit

  accepted.
- `Scheduler.check_budget` / `costly_work` (s166/AC2, REQ-175): costless new work returns
  at once, and reserves count only running work outside `COSTLESS`, so `roles.resolve` never
  sees `runner`. The tests prove a landing adds no reserve (budget 10, reserve 6). No
  defects. N3 is accepted.
