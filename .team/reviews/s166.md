## `GhPrs.close(pr, note)` (s166/AC1, REQ-174)

**What it does.** Runs `gh pr close <pr> --comment <note>` once. If that fails, it reads the
PR's state. If the state is `MERGED`, it returns. Otherwise it raises
`UpstreamError(<close output, stripped>)`, the same error `_gh` raised before.

**Against the design.** Matches P1–P4. The fix is only in `GhPrs.close`, so
`Lander.complete`, `story_ci._close` and the replay's close of a superseded sprint PR all get
it with no change of their own (P3). Nothing posts the note by its own call: there is no
`gh pr comment`, so a merged PR gets no note (P2; this depends on gh refusing the merged PR
before it comments, as the design says).

**Tests.** They cover every case on the checklist:
- close fails, then the view says merged: returns, and the calls are close then view;
- any close message with the view merged: returns (the state decides, not gh's text);
- view OPEN or CLOSED: raises the close's stripped text (`"  boom\n"` → `"boom"`);
- the view fails, isn't JSON, is a list, is an object without `state`, or is empty: raises
  the close's error, not the view's;
- the view exits non-zero while printing MERGED: still raises (the exit code is checked);
- a successful close: one call, the note after `--comment`, no view;
- no `comment` call on either path;
- end to end: the l9 landing setup with a real `GhPrs` over a fake gh that refuses the close
  and views MERGED. The story is landed, the gate passes and the sprint PR is set.

**Defects.** None.

## `GhPrs._is_merged(pr)` (s166/AC1, REQ-174)

**What it does.** Runs `gh pr view <pr> --json state` through `run`, not `_gh`, so a failed
read doesn't raise. It is True only on exit 0 with `state == "MERGED"`. `ValueError` (which
includes `JSONDecodeError`) and `AttributeError` (JSON that isn't an object: a list, string or
number) count as False.

**Tests.** Covered by the unreadable-state parametrisation above, including `[]` (the
`AttributeError` path) and `""`/`"not json"` (the `ValueError` path).

**Nit N1 (s166/AC1).** The design gives `_is_merged` a docstring ("Whether GitHub shows
``pr`` as merged; a failed or unreadable read is False."), and the code has none. The method
is private, so the house rule doesn't require one, but the `except` hides a pitfall
(`AttributeError` stands for JSON that isn't an object) that a line would explain.

**Nit N2 (s166/AC1).** The design changes the `Prs.close` protocol docstring to "…one already
merged counts as closed". It is still "Close pull request ``pr`` with a comment."
(`upstream.py:173`). The contract other `Prs` implementations must keep is now only in
`GhPrs` and `protocol.md`.

## `Scheduler.check_budget(work)` and `Scheduler.costly_work(work)` (s166/AC2, REQ-175)

**What they do.** `check_budget` still returns `None` at once for costless new work. Then it
reserves only over `costly_work(work)`: running work whose kind is not in `COSTLESS`
(`LAND`, `BOUNDARY`), then `work`. `find_reserve` is never called for a `runner` work, so
`roles.resolve("runner")` is never reached (B1). The refusal text, `budget_reserve` and
`find_reserve` are unchanged (B2).

**Against the design.** The design filters `work` too
(`[w for w in (*running, work) if w.kind not in COSTLESS]`). The code always appends `work`.
Inside `check_budget` this makes no difference, because costless `work` returned earlier. The
test fixes the code's behaviour ("new work last", and the new work is kept). Accepted.

**Tests.**
- a running LAND plus a new role step: `None`, no `RoleError`;
- a running BOUNDARY under `BOUNDARY_KEY` plus a role step, and plus the Manager: `None`;
- reserve 6 with budget 10: a running LAND plus a new step starts, and a running role step
  plus a new step waits with "budget" in the text. This proves a landing adds nothing, not
  just that nothing crashes;
- `costly_work` drops LAND/BOUNDARY, keeps ROLE/TEAM_FIX/REBASE_FIX/GATE_FIX in order, with
  the new work last;
- new costless work with the reserve over budget still returns `None`.

**Nit N3 (no AC; house rules).** `costly_work` carries
`# house-rules: allow verb-name -- name fixed by the s166 tests`. The name comes from the
design, not the tests, and the signature is split over four lines only to hold the comment.
That is cosmetic, and the same pattern is used elsewhere (`system.py:391`, `landing.py:186`).
