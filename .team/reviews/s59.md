## Notes (none block shipping)

- **N1, stopped rebase on a non-conflict failure.** When git stops mid-rebase with a non-zero exit and no `U` files, `_failed_rebase` raises `GitError` without `rebase --abort`. An example is "untracked working tree file would be overwritten" on the 3rd commit. The branch is then left detached mid-rebase under an `error` hold. R3 asks for exactly this, and not aborting protects a rebase the human already has in progress. The integration-tester or architect may want an e2e case, or a design note telling the human to run `git rebase --abort`.
- **N2, extra commits in a hand rebase.** If the human's hand rebase adds a commit that is not in `old` (for example a separate resolution commit), the cursor in `pair` stops at it. Every later old commit then maps to the earlier kept copy, so the mapping is stale but still reachable. This case is not in the design's Known limits; the architect should add it.
- **N3, fixture edge.** Fixture e93 has `"edge": "end"` with `"outcome": "rebased"`, but R12 says the end edge never rebases. The design asked for this change, but the contract fixture now shows an impossible event. The architect should consider changing e93's edge to `start`.
- **N4, misleading test name.** `test_the_push_refuses_the_team_branch_and_leases_a_review_branch` never checks a lease. Its last assertion is about `Rebase.moved`. The lease is covered in `test_upstream.py:92`, so this is cosmetic.
- **N5, small style issues in `rewrite.py`.** `_story(story, …)` and `_interruptions(items, …)` have no type hints, `_moved` is computed twice per value, and the repeated swap/count pattern is noted above.

## Defects

- **D1. The R2 save is unconditional (`boundary_runner.py:252`).** R2: "When `sync_from` is already set, it is not saved again." The design also asks for a guard clause, e.g. a `_pin_sync_from(b)` helper that returns early when `b.sync_from` is set, and otherwise sets it and saves. The code saves on every run of the sync stage, including each `continue_boundary` rerun. Nothing breaks, but the code does not match the contract, and the inline comment hides the rule instead of the structure showing it.
- **D2. No test for R2's ordering.** The design checklist says: "when `sync_from` is empty, it is set and `runtime.save()` runs **before** `rebase_onto` is called (record the call order). When it is already set, there is no extra save before `rebase_onto`." Neither test exists, so deleting line 252 would still pass the suite. This was the main point of fix 1: a crash between the rebase and R6's save must not lose `old`. Add both tests. For example, record `save` and `rebase_onto` calls in one list, as `test_s59_sync.py` already does for remap/record. The second test fails against the current code until D1 is fixed.
- **D3. N4 is not fixed.** `test_s59_rebase.py:210` `test_the_push_refuses_the_team_branch_and_leases_a_review_branch` still claims a lease check it does not make. Rename it, or add the lease assertion.
- **D4. N5 is not fixed (`rewrite.py:70–95`).** `_story(story, …)` and `_interruptions(items, …)` still have no type hints. `_changed(x, _moved(x, moved)); x = _moved(x, moved)` is still repeated four times (lines 82–83, 89–90, 92–95), with `_moved` computed twice per value. The design asks for a `_swap(obj, attr, moved) -> int` helper.
