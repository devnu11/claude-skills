## Function-by-function

### `gates.StoryState.sprint` (B1, B8; s3/AC1)
- **What it does:** adds `sprint: int | None = None` as the last field, after `delivery`. Positional construction still works. Legacy `state.json` loads through the dataclass default, so no migration code is needed.
- **Tests:** `test_story_sprint_defaults_to_backlog` and `test_state.py::test_legacy_story_without_sprint_loads_into_backlog`. The second asserts that step, rounds, status, commit and run sprint are kept. `test_story_sprint_round_trips` covers the round trip.
- **Defects:** none.

### `gates._backlog_refusal` / `dispatch_refusal` (B7; s3/AC3)
- **What it does:** returns exactly `story sN is in the backlog; add it to a sprint` when `sprint is None`. In `dispatch_refusal` it runs after `_status_refusal` and before `_step_refusal`. Ungated roles (`manager`, `scribe`) return early, and story-less roles return before any story check, so neither is affected. `dispatch.Runtime._story_refusal` already ends in `dispatch_refusal`, so it needed no change, as the design says.
- **Tests:**
  - Exact string at the gates level and the dispatch level (`test_backlog_story_is_refused_for_story_bound_roles`).
  - Manager/scribe on a backlog story at both levels.
  - Story-less architect at the gates level.
  - Ordering, where a done, round-capped or blocked backlog story gets its status refusal first (`test_status_refusal_beats_backlog_refusal`).
- **Defects:** none.

### `state.RunState.unknown_stories` (B6)
- **What it does:** returns the ids that are not opened stories, keeping their order.
- **Tests:** order is kept, and an empty list returns an empty list.
- **Defects:** none.

### `state.RunState.begin_sprint` (B3, B4, B5)
- **What it does:** bumps `sprint`. Every story that is not done gets `N+1` if it is listed and `None` otherwise. Done stories are never touched, including legacy done stories whose sprint is `None`. It is 5 lines.
- **Tests:** `test_begin_sprint_replaces_scope` and `test_begin_sprint_never_moves_done_stories` cover the cases:
  - listed
  - unlisted unfinished
  - done in a sprint
  - legacy done with `None`
  - backlog
  - carry-over
- **Defects:** none. `StrEnum` compares equal to the raw `"done"` string that the po_tools tests assign, so that path works too.

### `po_tools.Tools.start_sprint` / `_sprint_refusal` / `_begin_sprint` (B3–B6; s3/AC2)
- **What it does:**
  - Dedupes the ids and keeps their order.
  - Refuses before any mutation, with the exact design strings for an empty or missing list and for unknown ids (all of them, in order).
  - Otherwise it calls `begin_sprint`, sets RUNNING, appends `sprint N start: goal (ids)` to `manager_due`, saves, and emits `SPRINT_START` with `{"sprint","goal","stories"}`, which matches the snapshot fixture.
  - Result: `{"sprint","stories","next"}`.
- **Tests:**
  - A parametrised refusal test compares state JSON, the on-disk state file and the event count before and after each refusal (missing key, empty list, mixed known and unknown ids). That is the full side-effect check B6 asks for.
  - Other tests cover deduping, scope replacement, carry-over, listing a done story, the `manager_due` text, the event payload and the result shape.
- **Defects:** none.

### `po_tools.Tools.story_status` and `cli.status_report` (B9; s3/AC4)
- **What it does:** `story_status` gains a top-level `sprint`, and each story's sprint comes through `vars(s)`. `status_report` needed no code change because it already used `asdict`.
- **Tests:** `test_story_status_shows_sprint`, `test_open_story_starts_in_backlog` and `test_cli.py::test_status_shows_story_sprints`.
- **Defects:** none.

### `SCHEMAS` (s3/AC2)

## Non-blocking notes (optional follow-ups, not required to ship)

1. **A bare string for `stories` is accepted.** If a model passes `stories="s1"`, `dict.fromkeys` iterates its characters and the refusal reads `unknown stories: s, 1`. Nothing changes on refusal and the schema says `list`, so this is cosmetic only.
2. **One dispatch test assertion is weak.** `test_backlog_story_still_allows_manager_and_scribe` only checks that "backlog" is absent from the reason. A positive assertion would be stronger, e.g. that manager/scribe `status != "refused"`, or that the refusal comes from another cause.
3. **Story-less coverage is gates-only.** Checklist item 7 ("a story-less architect step is not refused") is tested at the gates level only, not through `run_role`. That is enough because dispatch passes `None` straight through.
