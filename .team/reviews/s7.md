### D2 (blocking): a backslash-newline line continuation gets past W1, W2 and W6

shlex in POSIX mode treats `\` + newline as an escaped newline and keeps the
newline in the word. bash and zsh delete `\` + newline, outside quotes and
inside double quotes. So the hook checks a different word from the one the
shell runs.

| command (`⏎` = newline) | HEAD | pre-s7 | real shell |
|---|---|---|---|
| `cat agile-team/runner/agile_\⏎team/cli.py` | **ALLOW** | deny | bash, zsh: prints the file |
| `cat agile-team/runner/agile_team\⏎/cli.py` | **ALLOW** | deny | same |
| `cat agile-team/run\⏎ner/agile_team/cli.py` | **ALLOW** | deny | same |
| `cat agile-team/runner/tes\⏎ts/conftest.py` | **ALLOW** | deny | same |
| `cat \⏎agile-team/runner/agile_team/cli.py` | **ALLOW** | allow | same |
| flat: `cat s\⏎rc/x` | **ALLOW** | allow | same |
| `cat .\⏎./.\⏎./.\⏎./.\⏎./agile-team/runner/agile_team/cli.py` | **ALLOW** | allow | climbs 4 levels from `.team/run/customer/cli` to the repo root |
| `ls .\⏎.` | **ALLOW** | allow | lists the parent |

Why this blocks:
- It is inside the design's own property ("denied when the shell could
  expand it to a forbidden root… any under-deny inside this property is a
  defect"), and it is a trivially equivalent spelling of the AC2 example
  `cat agile-team/runner/agile_team/cli.py`.
- The first four rows are a **regression against pre-s7**, which denied
  every word that starts with `agile-team/`.
- The climb rows defeat W2's `..` rule, which protocol.md states without
  exception ("Denied: a `..` segment anywhere"). Relative words really do
  resolve from the sandbox cwd, so this is the one bypass that reaches the
  source *without* also needing `cd`, `~` or `$…`. The only thing left is the
  OS sandbox, which protocol.md itself says is "not verified end to end yet".
- It isn't in s12: s12 covers `$VAR`/`$(…)`/`~`, cd/pushd, `=`/`<`/`>`
  splitting and case in absolute paths.

**Fix (small):** delete line continuations before anything is parsed. In
`guard`, add one step, e.g. `LINE_CONTINUATION = "\\\n"` and
`command.replace(LINE_CONTINUATION, "")`. Apply it once where the Bash
command enters the checks (`_check_bash` or `_tokens`), so the shlex path
and the W1 fallback (`command.split()`) both see the joined text. Deleting
it inside single quotes too, where the shell keeps it literally, can only
join two halves of a literal and over-deny, so that is safe.
- Architect: add the step to W1 in architecture.md and to step 1 of
  protocol.md Enforcement ("a `\` followed by a newline is deleted first, as
  the shell does"), plus N/F table rows for it.
- Unit-tester: deny rows for every D2 row above (nested and flat), including
  the `.\⏎.` climb. Allow row: `cat agile-team/docs/customer/x\⏎.md`.

### B1 (blocking, regression): `/./` inside a wildcard token bypasses the check

| command | ae1a46a | literal form at ae1a46a | pre-s7 (`head in roots`) |
|---|---|---|---|
| `cat agile-team/./runner/agile_*/cli.py` | **ALLOW** | deny | deny |
| `cat agile-team/runner/./agile_*/cli.py` | **ALLOW** | deny | deny |
| `cat ./agile-team/./runner/agile_t*/cli.py` | **ALLOW** | deny | deny |

Cause: `_glob_reaches` normalises the prefix with `re.sub(r"/+", "/", …)`,
which collapses `//` but not `/./`. The literal branch uses
`posixpath.normpath`, and protocol.md says tokens are normalised
(`a//b`, `a/./b` → `a/b`). So the guard now has two normalisations that
disagree, which also breaks DRY. Fix: give both branches one helper, e.g.
`paths.normalise_token(token)` = `posixpath.normpath(token.lstrip("./"))`,
and run it on the prefix. It's safe on a partial last segment:
`normpath("agile-team/runner/./agile_")` is `agile-team/runner/agile_`, and a
trailing `/` that gets dropped still overlaps through `root.startswith`.

### B2 (blocking): a leading wildcard or brace gets past the check

| command | ae1a46a | pre-s7 |
|---|---|---|
| `cat {,}agile-team/runner/agile_team/cli.py` | **ALLOW** | allow |
| `cat */runner/agile_team/cli.py`, `cat */*/agile_*/cli.py` | **ALLOW** | allow |
| `cat ?gile-team/runner/agile_team/cli.py`, `[a]gile-team/…` | **ALLOW** | allow |

The docstring says "An empty prefix (`*.txt`) is not an overlap: it names no
path." That's true for `*.txt`, but not for these tokens. Brace expansion
generates words whether or not the files exist, so `{,}` in front of any
denied path gets past the check. Without a fix, AC2/AC3 ("cannot name the
source and test directories") are only met on paper: three characters bypass
every literal denial. pre-s7 had the same hole (it was P5's leading-wildcard
case), but s7 is the story that decided how wildcard tokens are handled, and
it wrote down a rule that is wrong.

Suggested fix (the developer chooses): when the prefix is empty and the token
has more than one `/`-segment, compare it segment by segment against each
root. Deny when every paired segment could match. A segment holding `{` or
`**` matches anything; otherwise use `fnmatch.fnmatchcase(root_seg, tok_seg)`
(stdlib). Single-segment tokens (`*`, `*.txt`, `?`) stay allowed, since they
list the sandbox cwd. Must deny: the three rows above, plus flat `*/x` and
`{,}src/x` with root `src`. Must still allow: everything in the "ALLOW ✓" rows
above.

## Blocking defect

### D1: glob tokens get past the forbidden-root check (`guard._names_forbidden_root`)

`_names_forbidden_root` normalises the token and then tests
`under_root(path, root)`. The shell expands wildcards, so the guard sees the
pattern and the shell sees the paths it matches. Probe results with this repo's
config:

| command | s7 hook | before s7 (`head in roots`, roots = `agile-team`) |
|---|---|---|
| `cat agile-team/runner/agile_*/cli.py` | **ALLOW** | deny |
| `cat agile-team/runner/agile_tea?/cli.py` | **ALLOW** | deny |
| `cat agile-team/runner/agile_tea[m]/cli.py` | **ALLOW** | deny |
| `cat agile-team/*/agile_team/cli.py` | **ALLOW** | deny |
| `cat agile-team/runner/agile_team{,}/cli.py` (brace expansion) | **ALLOW** | deny |

AC2 and AC3 say the Proxy "still cannot ... name the source and test
directories". A glob that the shell expands to the source dir names it.

How exploitable is it? The Proxy's Bash cwd is the sandbox, so a relative glob
resolves there and finds nothing. But the hook is the layer that is verified.
The OS sandbox is the other layer, and its docstring and protocol.md both say
it is "not verified end to end". The hook lets the Proxy get to the repo root
with `cd ~/code/claude-skills` (see P1 below). After that, the s7 hook allows
`cat agile-team/runner/agile_*/cli.py`; the old hook did not. With the old
hook, the same `cd` followed by that `cat` was denied.

Suggested fix (the developer chooses): when a token holds `*`, `?`, `[` or `{`,
take its literal prefix (the same `takewhile(_is_literal, …)` logic as
`literal_root`, with `{` added) and deny the token when that prefix and a root
overlap in either direction: `under_root(prefix, root) or under_root(root, prefix)`.
Tokens with no wildcard keep the exact check, so `agile-team status` still
passes. `agile-team/*` would be denied, which is correct: it expands into
`agile-team/runner`, and a later glob could reach the sources from there.
Reuse `paths` helpers; don't add a second copy of the literal-prefix logic.

Tests the fix needs. They belong in `test_nested_bash_tokens`, with
`test_flat_layout_parity` for the flat cases:
- deny: `agile-team/runner/agile_*/cli.py`, `agile-team/runner/agile_tea?/x`,
  `agile-team/runner/agile_tea[m]/x`, `agile-team/*/agile_team/x`,
  `agile-team/runner/agile_team{,}/x`, `agile-team/**`, flat `s*/x`, `src*`.
- allow: `agile-team/docs/*.md`, `agile-team/docs/customer/*`, `*.txt`,
  `agile-team status`.

Protocol.md Enforcement must then say how wildcard tokens are handled.

## Pre-existing gaps (not introduced by s7, not blocking; for the backlog)

- **P1:** `~` and `$VAR` bypass `_names_repo`. Example:
  `cat ~/code/claude-skills/agile-team/runner/agile_team/cli.py` is allowed,
  and so is `cd ~/…`. The old hook allowed these too.
- **P2:** `--opt=path` tokens are not split on `=`. Example:
  `cat --x=agile-team/runner/agile_team/cli.py` is allowed, same as before.
- **P3:** the `package` delivery installs the runner into
  `<sandbox>/venv/lib/python*/site-packages/agile_team/`, so the Proxy can read
  the installed source inside its own sandbox (`cat venv/lib/…/cli.py` is
  allowed). This is inherent to a package delivery; the PO and human should
  decide whether it matters.
- **P4:** `_names_repo` compares absolute paths case-sensitively, but macOS
  APFS is case-insensitive by default.
- **P5:** flat layouts have the same wildcard hole as D1 (`cat s*/x`). The D1
  fix closes it as well.
