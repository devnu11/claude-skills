## Defects in the tests (must fix, unit-tester)

**T1. Design checklist item 8 (AC1 end to end) is missing.** No `test_router.py`
test drives a story through review → `revise_design` → design → tests
(`"tests": "confirmed"`, green) → implement → onward with no hand-over. The
twin case is also missing: no claim bounces once at `tests`, and
`REWORK_UNCLAIMED` shows in the next brief's "Sent back" line. AC1 is about
the router no longer stranding a story, and only an end-to-end test proves
that. The gate unit tests don't.

**T2. Dead step in `test_other_steps_bounces_and_returns_do_not_count`.** The
first two lines (`st = story("design"); settle(st, done())`) assert nothing.
`st` is reassigned straight away, so "a pass at another step doesn't count"
is never checked. Add `assert st.implemented == 0` (and the step moved to
`tests`) before the reassignment.

**T3. Checklist item 2 is incomplete.** No test shows that a `DISPUTE` verdict
or a ruling (`revise_design`, `rescope`) leaves `implemented` unchanged. G1
says "nothing resets it", which is the property that makes AC1 work after a
ruling. Pin it, for example by parametrizing over the rulings on a story with
`implemented=1`.

**T4 (minor). G8 "saves".** The tests check the in-memory story only. Reload
`state.json` (or check `rt.save` ran) after `continue_story` on a done story.

## Verdict

`changes_requested`. The production code is shippable, but T1–T3 leave AC1's
real claim and part of G1 unpinned. When the unit-tester adds these tests they
should pass against the current code; no developer change is expected.
