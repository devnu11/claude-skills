## Likely 3.13 cause (supports the fix)

On 3.13, `linecache.updatecache` uses the lazy `__spec__.loader.get_source` first. Test modules are loaded by pytest's `AssertionRewritingHook`, whose `get_data` calls `open` itself. So `_caller()` is `_pytest.assertion.rewrite`, which is not exempt. The stack at that point is `_pytest.assertion.rewrite` ← `linecache` ← `traceback` ← `tests.*`/`agile_team.*`. That is exactly the shape T1 allows, and the checklist row `("tests.test_x", "linecache", "_pytest.assertion.rewrite")` tests it. `agile_team` modules load through `SourceFileLoader` → `io.open_code`, whose caller is `importlib._bootstrap_external`, which is already exempt. I did not verify this on a 3.13 interpreter. If it is wrong, T5's `(caller: …)` note will name the frame.

## Notes (non-blocking)

1. `call_audited_through` chains relays with lambdas defined in `tests.test_os_guard`, so a guarded `tests.*` frame sits between each relay pair. All current cases still discriminate correctly; I traced each one. But a future case that relies on a reader *two* links out would be cut off by the lambda frame and fail confusingly. Building the chain with relay modules that close over `inner`, or documenting the interleaved frame in the docstring, would make the helper faithful. The `# noqa: E731` is also avoidable.
2. No test has a `tests.*` frame as the *only* boundary with a reader outside it. A bug that dropped `"tests"` from the boundary would go unnoticed. This is low risk, since `GUARDED_CALLERS` is shared with `_wrapper`.
3. `_allowed` walks the stack up to twice per audited event, and `_violation` walks it once more. This is fine for a test-only guard.
