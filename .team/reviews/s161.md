## Defects

### D1: the house-rules docs and the architect's write scope are missing (s161/AC2, REQ-180; repo rule "Docs move with behaviour")

The design's W2 and W5 (`docs/design/s161.md:208-227, 274-289`) are not done:

- `.agile-team.toml` `[roles.architect]` `write` does not include
  `house-rules/SKILL.md` or `house-rules/reference/**` (W2, DevOps).
- `house-rules/reference/rules.md` has no `suppression-excuse` row or section,
  no `excuses` row in the Settings table (lines 188-201), and the
  `query-property` "Changes nothing" paragraph (lines 124-130) still says
  nothing about tuple targets (Q1) or changes made through the class's own
  methods (Q2, REQ-179).
- `house-rules/SKILL.md` point 2 does not mention the refusal.

REQ-180 says a repo can extend the patterns in `.house-rules.toml`; today no
doc tells a user that the `excuses` key exists. **Fix:** DevOps adds the scope
(W2), then the architect writes the docs (W5).

### D2: `suppression-excuse` can be suppressed by the excuse comment itself (s161/AC2, REQ-180)

`checker.py:69` drops every finding on a line whose suppression names the
rule. `suppression-excuse` reports on the suppression's own line, so

```python
def area(x):  # house-rules: allow verb-name, suppression-excuse -- name fixed by the tests
```

hides both `verb-name` and the excuse finding, and the check passes. That is
exactly the comment AC2 says house-rules refuses. The only intended way to opt
out is the repo-level `disable = ["suppression-excuse"]` (design line 145),
which a reviewer sees in `.house-rules.toml`. A per-line opt-out lets the s159
waiver happen again with one more word. **Fix (developer):** the suppression
rules (`suppression-excuse`, and `suppression-reason`, which has the same
hole) must not be silenced by a line suppression. Add a test with the comment
above. Unit-tester adds the failing sample.
