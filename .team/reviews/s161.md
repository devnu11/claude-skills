## Findings

1. **[defect, s161/AC2, REQ-180] `Settings.is_excuse` does not strip a trailing `:`.**
   Design E2 (`design/s161.md:136-138`, repeated at 377 and 468) says:
   `reason.split("#", 1)[0].strip().rstrip(".;:!").strip()`. The code
   (`house-rules/runner/house_rules/config.py`, `is_excuse`) does
   `.strip().rstrip(".;! ")`. It has no `:`, so `# house-rules: allow verb-name -- name fixed
   by the tests:` gets through as a real reason. The design's test checklist (line 468) asks
   for the `:` case, but `test_config.py::test_an_excuse_reason_is_refused` covers only
   `.`, `;`, `!` and `. `, so nothing caught it.
   *Fix:* unit tester adds `"name fixed by the tests:"` to the refused cases; the developer
   (developer-cli, owner of `config.py`) adds `:` to the stripped characters.
2. **[defect, docs, s161/AC2, REQ-180] `house-rules/reference/rules.md` is stale.** Its
   `### suppression-excuse` section says the reason is "stripped of one trailing `.`". After
   the amendment the code strips any run of trailing `.`, `;`, `:` and `!`. The list of
   default examples also leaves out the active forms the amendment added ("a test fixes the
   name", "test file fixed the name"). Docs move with behaviour (repo rule).
   *Fix:* the developer who owns `house-rules/reference/` updates that bullet with the
   finding 1 fix.

  `test_ac2_excuse_refused_with_file_line_rule` (real CLI: file, line, rule, reason) cover
  it. No defect.
- `rules.list_changing_methods`, `extend_changing`, `calls_changing`, `list_self_calls`,
  `list_target_leaves` (REQ-179): `extend_changing` is a fixed-point loop bounded by the
  number of methods, and `calls_changing` checks only the method's own class. Tests cover

  another class, and calls on another object. No defect.
