# Review: s190 (taken story-branch name is adopted or held)

Reviewed `git diff dfbb75fe..fed3c8dd`, checked against `agile-team/docs/design/s190.md` (T1–T7).
Runner results: the suite passes, and the touched modules have 100% coverage.

Verdict: **ship**. I found no defect in the code. Notes and minor items are below.

## Changed functions

### `story_branches.BranchAction` (new enum)
- It names the four `story-branch` actions this path uses. The test pins the values.
- s190/AC1, REQ-247. No defect.

### `story_branches.TakenBranch` (new frozen dataclass)
- `is_at_base`: compares the full sha with the sprint head as strings (T2). The tests cover an
  equal sha, a different sha and a 12-char prefix. No defect.
- `aside_branch`: `<branch>-kept-<tip[:12]>` (T5). Covered. No defect.
- `reason`: fills `BRANCH_TAKEN` with the story, branch, tip, base and the `git branch -m` way
  out, with both shas cut to 12 characters. The tests check every part and the cut (the 13th
  character is absent). s190/AC2, REQ-248. No defect.
- `event_data`: the five keys, with full shas. Tested for exact equality. s190/AC1, AC3,
  REQ-247, REQ-249. No defect.

### `workspaces.Workspaces.find_taken_branch` (new, T1)
- Returns None for a story that already has a branch record, and makes no git call. Otherwise
  it runs `rev-parse --verify --quiet refs/heads/<name>`. The tests cover a recorded story, a
  free name, a taken name with its tip stripped, and the `-r1` name that follows `replays`.
  s190/AC1, REQ-247/248. No defect.

### `workspaces.Workspaces.describe_branch_start` (new, T2)
- Returns `rebuilt`, `created`, or `adopted` with `why`. All three are covered.
- Note (minor, s190/AC1): it returns `adopted` for any taken name and doesn't check
  `is_at_base`. It is correct only because `prepare_story` runs `_check_taken` first. The
  docstring states the "call before ensure" order, but not that it depends on `_check_taken`.
  Not a defect today; it is a coupling to keep in mind.

### `workspaces.Workspaces._get_fork_branch`, `_read_tip` (new helpers)
- They are covered through the callers. `_read_tip` maps a non-zero exit to `""`. No defect.

### `workspaces.Workspaces._fork` (changed, T2)
- Skips `git branch` when the leftover's tip is the sprint head, and still records `branch` and
  `base_sha`. The tests cover both the fork and the adoption. No defect.
- Note: a leftover at any other tip would still make `git branch` raise here. Only `ensure`
  calls `_fork`. `prepare_story` guards it, and the other caller (`replay.StoryReplay.run`)
  always has a branch record, so it never forks. Fine as designed.

### `dispatch.Runtime.run_in_worktree` (changed)
- Adds the request's `role` to a `prepare_story` refusal, so the hand-over line reads
  `"<id>: <role> was refused: <reason>"`. Covered, including `handover.report_lines`. This also
  improves the existing drift refusal. s190/AC2, REQ-248. No defect.

### `dispatch.Runtime.prepare_story`, `_check_drift`, `_check_taken` (refactored and new)
- `_check_drift` is the old inline drift check, extracted. Its behaviour is unchanged, and the
  existing B5 tests still pass.
- `_check_taken` emits `taken` and returns `refused(reason)`. It changes no story field and runs
  no `git branch` or `worktree add`. The tests check all of that, plus a repeated refusal that
  emits a second event, and the continue_story → `created` path after the rename (T6).
  s190/AC1, AC2, AC3, REQ-247–249. No defect.
- The test for continue_story sets `hold = "refused"` by hand. Whether the scheduler holds on
  this refusal rests on the existing refused path (`NOTED_BY_RUNNER`), which the drift tests
  already exercise. Acceptable.

### `dispatch.Runtime._make_workspace` (changed)
- The action now comes from `describe_branch_start`, read before `ensure`. The event still
  carries `branch`, `base_sha` and `replays`. Covered for `adopted` and `created`. No defect.

## Coverage of the ACs
- s190/AC1, AC2: the unit tests cover every checklist item in the design.
- s190/AC3, REQ-249: the unit tests show only that the runner never moves, renames or deletes
  the leftover. The real-git check (the old tip equals `git rev-parse <aside>`, and an adopted
  branch's tip is unchanged) is in the design's
  `tests/e2e/test_s190_taken_branch_e2e.py`. That file **does not exist yet**. It belongs to
  the e2e step, which comes after review. The story's Tooling section already says it is
  "automatic today", which is not true at this commit. The integration-tester must write it to
  the design's two e2e checklist items, or the Tooling line must be corrected.

## Possible edge (no AC; not blocking)
- If the leftover branch is checked out in the main checkout and sits at the sprint head,
  adoption's `git worktree add` fails with "already checked out", and that failure is not
  turned into a hold. Before this story, the same case crashed at `git branch`, so this is no
  regression. If it is ever seen, raise a follow-up story.

## Copy/paste
- No repeated blocks in the source. `describe_branch_start` and `_fork` each read the tip
  again: one start makes up to three `rev-parse` calls. That is cheap, and the reads happen
  under the writer, so it is acceptable.
- Tests: `StoryState(id="s1", …, branch=NAME, base_sha=HEAD)` appears twice. Nit only.
