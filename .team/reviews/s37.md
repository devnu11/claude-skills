## Per function

### `limits.py`
- **`RESET_CLOCK` / `RESET_TIME` / `RESET_NOTE`**: the time grammar is now
  written once, and both patterns are built from it (R2, DRY). `RESET_TIME` is
  unchanged byte for byte, and the existing `reset_at` cases still pass.
  `RESET_NOTE` now needs `H[:MM]am|pm`. *Tests:*
  `test_reset_note_needs_a_readable_time` (`the count`, `soon`, `tomorrow`) and
  `test_reset_note_with_a_date`. Covered.
- **`WakeOn`, `Wake`**: plain data. `test_wake_on_values` pins the
  serialised values.
- **`Waits.after_limit`**: returns `Wake(reset+GRACE, RESET)`, or
  `Wake(now+fallback, FALLBACK)` (R3). *Tests:* grace, fallback, and the live
  case (17:26 → 21:03 America/Chicago, AC5). Covered.

### `store.py`
- **`JobState.mark`**: clears `next_wake` and `wake_on` (N1). This is now the
  only place they are cleared, so `_cycle`, `_finish`, the CLI's `_restart`
  (cli.py:406) and the crash paths all get the fix. *Test:*
  `test_mark_clears_the_wake`.
- **`_wake_on` / `from_json`**: a missing key or null loads as `None` (L1),
  and a string loads as `WakeOn`. `StrEnum` serialises through `json.dumps`.
  *Tests:* round-trip and legacy. Covered.

### `supervisor.py`
- **`wake_after`**: a rate limit gives `BACKOFF`, otherwise `after_limit`.
  *Tests:* `test_wake_on_backoff` and `test_wake_on_fallback` (exact values),
  and `test_wake_on_reset`.
- **`_wait`**: uses `wake.at` for the bounds check and for the sleep. The
  existing bound and deadline tests still pass.
- **`_mark_waiting`**: calls `mark`, then sets both wake fields, and the event
  carries `on`. *Test:* `test_wait_event_carries_why`.
- **`_mark_offline`** (new): `WAITING`, `next_wake` null, `wake_on=network`
  (N2). *Test:* `test_no_stale_wake_after_a_limit_then_an_offline_wait` reads
  the state inside `run_once` and inside the `online` probe. It would have
  failed before the fix, because `_cycle`'s `mark(RUNNING)` did not clear
  `next_wake`. This is AC5's second test.
- **`_finish`**: now a single `mark` call (DRY). Behaviour is unchanged,
  because `mark` clears the wake.

### `command_job.py`
- **`RunOutput`**: carries the tail and the cwd. `run_once` passes
  `Path(state.spec.cwd)`. *Test:* `test_run_once_passes_cwd_to_the_status_file`
  runs a real subprocess.
- **`halt_reason`**: the last `HALT_LINE` match. I checked it against
  agile-team: `cli.py:572` prints `agile-team {command}: {exc}`, and

## Non-blocking notes
1. `HALT_LINE` is anchored at `^`. If the PO's block-buffered stdout leaves a
   partial line just before agile-team writes its halt line to stderr, the
   halt line starts mid-line and does not match. R1's second source
   (`state.json` `status_reason`, set by the same halt) covers this case, so
   the fix still holds. This is worth knowing if the reason ever appears as a
   `usage limit, …` form.
2. `test_wake_on_reset` only checks `> START`. The exact value is pinned in
   `test_limits.py`, so I am not asking for a change.
3. AC6 (the fix takes effect only after merge and re-pinning the live
   supervisor) is the PO's hand-off note to the human. I could not verify it
   in code.
