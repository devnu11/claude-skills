## Round 1 findings

- **F1 (s173/AC1, REQ-262; s173/AC2, REQ-263; s173/AC3, REQ-264): fixed.** The new e2e
  file runs on real git through `cli.make_runtime`, so `live_for` is the real
  `build_live_config` and `make_pipeline`:
  - `test_ac1_an_amend_naming_a_committed_environment_is_accepted` replays q19. It
    commits `house-rules`, ticks, then checks for one `story-amended`, no `story-refused`,
    and that the story file names the environment (F1.1, F1.4).
  - `test_ac1_a_changed_test_command_reaches_the_gate_and_a_new_role_is_known` checks that
    `pipeline.checks.commands["test"]` is the committed command line. It also checks that
    `refusal(StepRequest("qa", ...))` stops saying "unknown role" (F1.2, F1.3). It reads the
    pipeline's command and does not run a gate. That is enough, because the gate takes its
    command from that table.
  - `test_ac2_one_config_event_records_the_sha_and_changed_sections` ticks twice and finds
    one event. Its `sha` matches the commit and its `blob` matches `git rev-parse`. This is
    the real-git check of `read_blob`, `find_last_change` and the start-up `config_blob`
    that round 1 asked for.
  - `test_ac3_a_broken_commit_keeps_the_last_good_config_and_tells_the_po` covers the
    outside-commit path: the config stays the same object, the event carries the error, and
    a `config_invalid` pass is queued. The committing-step path (the error lands in that
    step's own report) is covered by the unit test
    `test_a_step_that_committed_the_bad_config_gets_it_in_its_report_s173`.

  Small gap, not blocking: no test shows a *story view* built after the swap using the new
  pipeline (`get_story_view`). The code reads `pipeline_for(view.config)` there, so it is
  right today.
- **F2 (s173/AC2, REQ-263): still open.**
  `test_the_sections_table_covers_every_config_field_s173` (`test_config_reload.py:134`)
  checks three entries and two pairs. If someone adds a `Config` field and leaves it out of
  `SECTIONS`, the test still passes, and a change to that section is never listed in the
  `config` event's `sections`. That breaks REQ-263 without any test failing. Fix: compare
  `{f for f, _ in SECTIONS}` with `{f.name for f in dataclasses.fields(Config)}` minus the
  fields that are not sections (`repo`, `run_home`, `warnings`, or whatever `Config` has).
- **F3 (s173/AC1, REQ-262): still open.** No assertion checks `_apply_live`'s
  `if "upstream" in sections` branch. Coverage reaches it, but nothing asserts that an
  `[upstream]` commit gives a new `Upstream` and that a change to another section keeps the
  old one. Add one test for each case.
- **F4 (no AC): still open, and now worse.** See F5.
