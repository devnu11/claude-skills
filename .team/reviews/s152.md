## Functions changed

### `boundary_runner.BoundaryRunner._start_sync` (s152/AC1.1, REQ-088)
It skips the rebase when nothing is pinned and `behind() == 0`. Otherwise it pins
`sync_from`, calls `rebase_onto`, and passes the outcome to `START_REBASES`. This matches
S1. The fetch comes from `_sync` → `remote.missing()`, which runs `git fetch --prune`, so
the end's extra `_fetch()` isn't needed here.
Tests: `test_ac1_1_a_start_sync_rebases_and_remaps_the_hashes`, `…_already_on_the_target_is_left_alone`,
`…_pinned_sync_from_still_rebases_when_not_behind` and `…_finds_nothing_to_do_says_current`
cover each branch, but all of them replace both `upstream.behind` and `upstream.rebase_onto`
with stubs. See F1.

### `_start_current` (AC1.1)
It emits `current` with `START_CURRENT` and `behind=0`, then advances. Covered, and
`test_boundary_runner.test_start_with_nothing_new_is_current_with_no_commit` was updated
to match (design S1.1 backs that assertion change). It has no docstring; it is private
and trivial, so this is acceptable.

### `_start_conflict` / `_start_conflict_text` (design S2, no AC: the design adds it under AC1.1)
`rebase_onto` has already aborted. The method posts `START_CONFLICT`, emits `conflict`
with no hold, unpins and advances. Covered by `test_ac1_1_a_start_conflict_holds_nothing_and_tells_the_liaison`
(exact text, no hold, HEAD unchanged, relayed). Defect F3 (DRY, minor).

### `_check` → `CHECK_FAILURES[b.edge]`, `_team_fix`, `_known_failures` (AC2.1, AC2.2, REQ-089)
- `_team_fix` is the same two lines as before. `test_ac2_1_a_failing_end_check_still_asks_for_a_team_fix`
  guards against a regression, and the existing team-fix, escalation and streak tests in
  `test_boundary_runner.py` and `test_s123_boundary_hold.py` were moved from `Edge.START` to

- `_known_failures` posts `KNOWN_FAILURES_NOTE` and finishes with one `done` event that

## Findings

- **F1 (s152/AC1.1, AC3.1; REQ-088, REQ-091), test gap, blocking, unit-tester.** No test
  runs the start sync against real git. The design checklist says "AC1.1's rebase uses a
  real scratch git repo whose `origin` is a bare clone", and the story's `## Tooling` says
  `test_ac1_1_*` uses "real scratch git repos". Every `test_ac1_1_*` replaces `behind` and
  `rebase_onto`, so the check `not [c for c in fake.commands if "rebase" in c.argv]` in
  `…_left_alone` can't fail (`calls == []` already says it). Two real paths go untested:
  (a) `_sync` → `missing()` fetch → real `behind()` → real `rebase_onto` → `_settle_rebase`
  remapping a story's `commit` to the rebased copy, with HEAD then on `origin/main`
  (`merge-base --is-ancestor`); and (b) the start's usual case, where the previous sprint's
  PR was rebase-merged, so main holds copies of every team commit and `--empty=drop` drops
  them all. The second case never arises at the end, which runs before the merge. Add one
  real-git test for each, using `tests/e2e/test_s59_rebase_e2e.make_world` or the
  scratch-repo helpers of `test_upstream.py`.
- **F2 (no AC; charter "functions ≤ 8 lines"), minor, developer-cli.** `_known_failures` is
  about 20 lines, and the design asked for under 8. Splitting out the note text the same
  way `_start_conflict_text` does fixes it.
- **F3 (no AC; DRY), minor, developer-cli.** `_start_conflict` copies
  `data = {"files": list(result.files), "commit": result.commit[:12]}` from
  `_rebase_conflict`, and `_start_conflict_text` cuts `commit[:12]` a second time. A shared
  `_conflict_data(result)` helper would remove both copies. No other repeated blocks were
  found in the diff.
- **F4 (s152/AC2.1; REQ-089), minor, developer-cli.** `_known_failures` uses
  `self.mine.team_branch or self.remote.team_branch()`, which the design doesn't call for.
  `remote.team_branch()` raises `UpstreamError` on a detached HEAD, and that would make a
  start-check failure *hold* the boundary as `error`, against AC2.1. `_sync` always sets
  `mine.team_branch` first, so drop the fallback (or use `boundary_data`'s `team_branch`).
  No test covers the fallback.
- **F5 (s152/AC2.3; REQ-090), cosmetic.** The PO's `KNOWN_LINE` shows the full 40-char
  `sha`, while the liaison's note cuts it to 12. The test checks `FAKE_HEAD[:12] in line`,
  which passes either way.
- **F6 (s152/AC2.2; REQ-089), open question.** The AC says the ids are recorded "in the
  `sprint-start` event". Design S6 / ADR-0077 §6 records them on the start boundary's
  closing `done` event instead, for good reasons (the event log is append-only, and a
  second `sprint-start` would split the sprint on the dashboard). The AC text was never
  amended, so the liaison should confirm the change or amend the AC.
- **F7 (no AC), cosmetic, integration-tester at the e2e step.** The docstring of
  `tests/e2e/test_s108_start_e2e.py` still says the start sync "changes nothing". Its tests
  pin only `Upstream.behind()`, so they are still correct.
