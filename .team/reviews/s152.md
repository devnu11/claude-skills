## Functions changed since round 2 (747c78ba)

### `BoundaryRunner._known_failures` (s152/AC2.1, AC2.2; REQ-089)
It does the same thing as before: it posts the note and closes the start boundary with one
`done` event that carries `known_failures`, `sha`, `reason` and `checks`. It is now about
12 lines, down from 20. Its behaviour did not change, and the AC2.1/AC2.2 tests still cover
it. No defect.

### `BoundaryRunner._known_failures_text(b, ids, head)` (new; s152/AC2.2, REQ-089)
It formats `KNOWN_FAILURES_NOTE` and cuts the sha to 12 characters.
`test_ac2_2_the_note_counts_the_failures_and_goes_to_the_liaison` covers it through
`_known_failures`. Defect F8 below: it takes three parameters besides `self`.

### `_conflict_data(result)` (new module function; no AC, DRY)
It returns `files` and `commit[:12]` for a stopped rebase. Both `_start_conflict` (S2) and
s151's `_rebase_conflict` now use it. The S2 unit test and s151's conflict tests cover it.
This closes F3. `_start_conflict_text` still cuts `commit[:12]` on its own, but that one
cut is harmless.

Every other changed function (`_start_sync`, `_start_current`, `_start_conflict`, `_check`
→ `CHECK_FAILURES`, `_team_fix`, the tables, `fullcheck.failing_ids` / `_failed_ids`,
`handover.KNOWN_FAILURES` / `_known_fields`, the `stages.py` descriptions and
`roles/product-owner.md`) is unchanged since the round-1 analysis (39bc805b).

## Findings

- **F1 (s152/AC1.1, AC3.1; REQ-088, REQ-091), test gap, blocking, unit-tester. Still
  open (third round).** Add these tests in `tests/test_s152_start.py`, named
  `test_ac1_1_*`. Use `tests/e2e/test_s59_rebase_e2e.make_world` or the scratch-repo helpers
  in `test_upstream.py`, and do not stub `behind` or `rebase_onto`:
  (a) Main has moved by one commit, and a story's `commit` is a team commit. After one start
  `sync` step, HEAD must be on `origin/main` (`merge-base --is-ancestor`) and the story's
  `commit` must be the rebased copy. There must be a `rebased` event with `rewritten >= 1`,
  `sync_from` must be empty, and the stage must be `check`.
  (b) Main has not moved. HEAD keeps its sha, a `current` event carries `START_CURRENT`, and
  HEAD's reflog has no rebase entry.
  (c) The usual start: the previous sprint's commits are already on main as rebase-merged
  copies, so they are dropped. HEAD must end on `origin/main` with no conflict and no hold.
  Without these tests, nothing shows that `Upstream.rebase_onto` with the start's pinned
  `sync_from` works on a real repository. Today it is checked only against stubs.
- **F2 (no AC; charter "functions under 8 lines"). Fixed** in 747c78ba.
- **F3 (no AC; DRY). Fixed** in 747c78ba with `_conflict_data`.
- **F4 (s152/AC2.1; REQ-089). Accepted, closed.** The developer kept the
  `self.remote.team_branch()` fallback because the AC2.2 tests drive `_check` without a
  sync. Line 327 (`_add_entry`) already uses the same pattern, so the fallback is
  consistent with the existing code. The detached-HEAD risk remains in theory only, since
  `_sync` always records the branch first. Not blocking.
- **F5 (s152/AC2.3; REQ-090), cosmetic, still open.** `KNOWN_LINE` shows the full sha, while
  the liaison's note shows 12 characters.
- **F6 (s152/AC2.2; REQ-089), open question for the liaison, still open.** The AC says the
  ids are recorded "in the `sprint-start` event". Design S6 / ADR-0077 §6 puts them on the
  start boundary's closing `done` event instead. The AC text has not been amended.
- **F7 (no AC), cosmetic, integration-tester, still open.** The docstring of
  `tests/e2e/test_s108_start_e2e.py` still says the start sync "changes nothing".
- **F8 (no AC; charter "at most 2 parameters"), minor, developer-cli. New.**
  `_known_failures_text(self, b, ids, head)` takes three parameters. Either pass `ids`
  alone and read the head inside, or pass `(b, report)` and derive both. It also has no
  docstring. The function is private, but its neighbour `_start_conflict_text` is equally
  short and documents itself.
