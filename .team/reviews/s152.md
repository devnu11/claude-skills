## Findings

- **F1 (s152/AC1.1, AC3.1; REQ-088, REQ-091), test gap, blocking, unit-tester. Still open.**
  No test runs the start sync on real git. The design's test checklist requires one ("AC1.1's
  rebase uses a real scratch git repo whose `origin` is a bare clone"), and the story's
  `## Tooling` now claims one exists, so the record is false. Add, in
  `tests/test_s152_start.py` (named `test_ac1_1_*`) and using
  `tests/e2e/test_s59_rebase_e2e.make_world` or the scratch-repo helpers in
  `test_upstream.py`, with no stub on `behind` or `rebase_onto`:
  (a) main moved by one commit and a story whose `commit` is a team commit. One start
  `sync` step must leave HEAD on `origin/main` (`merge-base --is-ancestor`), the story's
  `commit` set to the rebased copy, a `rebased` event with `rewritten >= 1`, `sync_from`
  empty and the stage `check`.
  (b) main not moved. HEAD keeps its sha, a `current` event carries `START_CURRENT`, and
  HEAD's reflog has no rebase entry.
  (c) the usual start: the previous sprint's commits are already on main as rebase-merged
  copies, so `--empty=drop` drops them all. HEAD must end on `origin/main`, with no conflict
  and no hold. This case never comes up at the end, so it is the one most likely to
  surprise.
- **F2 (no AC; charter "functions under 8 lines"), minor, developer-cli. Still open.**
  `_known_failures` (`boundary_runner.py:372-391`) is 20 lines. Move the note text into a
  `_known_failures_text(b, ids)` helper, the way `_start_conflict_text` does.
- **F3 (no AC; DRY), minor, developer-cli. Still open.** `_start_conflict` (line 289) copies
  `data = {"files": list(result.files), "commit": result.commit[:12]}` from
  `_rebase_conflict` (line 527), and `_start_conflict_text` cuts `commit[:12]` again
  (line 299). A shared `_conflict_data(result)` would remove the copy.
- **F4 (s152/AC2.1; REQ-089), minor, developer-cli. Still open.**
  `_known_failures` falls back to `self.remote.team_branch()` (line 375). That call raises
  `UpstreamError` on a detached HEAD, which would turn a failing start check into an
  `error` hold, against AC2.1. `_sync` always sets `mine.team_branch`, so the fallback is
  dead code that only adds risk. Drop it. No test covers it.
- **F5 (s152/AC2.3; REQ-090), cosmetic. Still open.** `KNOWN_LINE` shows the full 40-character
  `sha`, while the liaison's note cuts it to 12.
- **F6 (s152/AC2.2; REQ-089), open question for the liaison. Still open.** The AC says
  "recorded … in the `sprint-start` event". Design S6 / ADR-0077 §6 records the ids on the
  start boundary's closing `done` event instead, for sound reasons. The AC text has not been
  amended to match.
- **F7 (no AC), cosmetic, integration-tester.** The docstring of
  `tests/e2e/test_s108_start_e2e.py` still says the start sync "changes nothing".
