`design/s180.md:448` onward and the Files list at `:502`. Round 2's own note says "the
checklist gains … the required real-git file (F2)". The story's `## Tooling` section, which
the 2fdc3030 rewrite touched again, still says "AC1/AC2/AC3: automatic today:
tests/e2e/test_s180_carry_e2e.py …". It now also claims "the REQ-191 hold-window restart
case". That is false.

Every lander test still runs on fake git with scripted replies. The behaviour that AC1, AC2
and AC3 describe is git behaviour, and nothing checks it:

- `cherry-pick --allow-empty --keep-redundant-commits base..head` in a detached land worktree
  gives the copies in order, and `carry_commits`' old/new pairing matches what git really made
  (REQ-190);
- `reset --keep` moves the main checkout to the carried tip, and `git log --first-parent` of
  the sprint branch shows the story-file commit right above `merge(s1): …`, at the same merge
  sha (AC1's own by-hand check);
- a storyless-style commit is carried the same way (AC2);
- a real merge in the span gives `MERGED`, and `moved` lists each commit's `%h %s` (AC3,
  REQ-192);
- the restart hold window from F1 (REQ-191).

**Fix:** the integration tester adds the file with the design's cases, so that the Tooling
section is true. If the team decides not to write them, the Tooling section and the design
must say so instead, and that needs the PO's call. Today the docs claim coverage that
