### N1 (should fix, doesn't block; integration-tester): the AC3 e2e asserts loosely (s180/AC3, REQ-236)

REQ-236 asks for *every* commit of `B..H`, *oldest first*, as `<sha7> <subject>`, plus the
reason the carry was refused. The test checks less than that:

- `any("side: work" in s …) and any("merge side" in s …)` doesn't check order or that
  nothing else is listed. `moved_by == [f"{side[:7]} side: work", f"{mergesha[:7]} merge
  side"]` would, with the shas read via `git rev-parse` in the hook.
- `all(s[:7].isalnum() …)` passes for any 7 alphanumerics, not just the commit's short sha.
- `assert dropped.data["refusal"]` only checks the refusal is non-empty. For this scene it
  should equal `CARRY_MERGE.format(commit=<merge sha12>)`.
- Line 108 `[line for line in dropped.data["moved_by"]]` is a copy that does nothing.

Why this doesn't block: `landing_carry` builds each line as `sha[:7] + subject` from
`story_rebase.list_commits` (`git log --reverse`). `test_landing_carry.py` and
`test_s180_landing.py:123-130` assert that format and order exactly. The e2e adds proof on
real git, and it is only weaker on details the unit tests already fix. AC3's other half, the
PO's hand-over line, is checked in `test_handover.py:387-424` and not in the e2e. That fits
the tooling note in the story.
