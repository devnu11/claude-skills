## New finding

### D1 (must fix, architect): the docs don't list the "first parent can't be read" refusal (s180/AC3; REQ-236; design C2)

The behaviour: when `rev-parse <merge>^1` fails, `Lander.check_carry` refuses before any
other check. The landing gives up with `why: sprint head moved`, the refusal reads
`the first parent of the merge <sha12> can't be read`, and `moved_by` is empty because there
is no `B..head` to list. Three docs leave it out:

1. `agile-team/reference/protocol.md:3241-3246` ("Carrying the runner's commits") lists the
   refusals "checked in this order". Add the new one as the first check. Also say at
   `:3265-3267` that `moved_by` is empty in that case too, not only after a refused push.
2. `agile-team/docs/architecture.md:157`: the parenthesis "(off head, a merge, pushed, a
   forked story, a conflict)" needs the new case.
3. `agile-team/docs/design/s180.md` C2 (line 51 onward): the ordered list needs it as
   check zero.

REQ-236 (lines 8-16) says the event "lists every commit between the merge's first parent and
the sprint head". When that parent can't be read there are no commits to list. Either add a
sentence for that case, or decide that this fail-safe falls outside REQ-236. The architect
picks which.
