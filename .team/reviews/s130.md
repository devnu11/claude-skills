## Findings (non-blocking)

1. **s130/AC2, REQ-026: nested scopes leak into the outer function's
   `local_names`.** `function_hits(f)` walks the whole of `f`, nested `def`s and
   lambdas included, but `local_names(f)` holds only `f`'s own parameters.
   - False positive: `X = []\ndef f():\n    def g(X):\n        X.append(1)\n`
     reports `(4, "X")` from `f`'s walk, although `X` is `g`'s parameter. The
     same happens for `lambda X: X.append(1)`. This fails safe: a tester
     would have to dispute a red scan.
   - False negative: if a nested `g` stores a name `X`, then `X` counts as local
     to `f` as well, so a write `X.append(1)` in `f`'s own body is missed. The
     same holds for a comprehension variable named `X`. This is rare and unlikely
     in this tree.
   - Fix if wanted: collect locals per scope, so the walk doesn't descend into
     nested function and lambda bodies. Add the two samples above to
     CAUGHT/PASSED. A follow-up is enough.
2. **s130/AC2, REQ-026: shapes the scan doesn't see.** It doesn't see
   tuple-unpacked bindings (`A, B = [], []`), class-level containers
   (`class C: seen = []` then `C.seen.append`), or mutable objects such as
   `SimpleNamespace()` and `itertools.count()`. The design limits the scan to
   plain-Name bindings and puts other mutable objects out of scope, so this is
   only a note. A grep of the unit tree found no class-level containers that
   tests write to.
3. **No AC: duplication.** `story_of`/`story_on` are near-identical in the
   two presentation modules (they differ only in `story_id` versus `step`).
   The design prescribes this, and the two are small. They could move to
   `conftest.py` later. I found no other repeated blocks in the diff.
4. **No AC: style.** `test_s130_module_state.py` imports `importlib.util`
   and `ast` inside test functions. Top-level imports would match the house
   style. This is cosmetic.
