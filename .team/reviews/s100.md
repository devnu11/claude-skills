# Review: s100 (A6c) story timeline, round 1

**Verdict: changes requested → developer-gui.** There is one visible drawing bug (D1) and two cheap misses against the design contract (D2, D3). The model logic follows TL1–TL20 closely and the Python side is clean.

## Defects (must fix)

- **D1: bounce arrows are not clipped to the window.** `arrowSvg` maps `arrow.from` and `arrow.to` with `plot.x` and never checks `tlSeen` or clamps. `barSvg`, `segmentSvg` and `sleepSvg` all do both. When the human zooms or pans, `plot.x` returns an x below `TL.LABEL_W` (or above `TL_WIDTH`) for an arrow outside the window. The curve is then drawn across the row-label column, over the label text that TR3 says must stay readable. An arrow that lies entirely outside the window is still drawn. Fix: skip an arrow when `!tlSeen(win, from, to)`, and clip the plot area. The cleanest way is a `<clipPath>` on the plot rect for bars, arrows and marks. Clamping the endpoints alone would bend the curve. Add a page test (integration-tester): with a window after the verdict, every `data-arrow` path has x ≥ 150, or there is none.
- **D2: 19 functions have no doc.** The design says "Every function gets a one-line `/** … */` doc and does one job." These are missing one: `stepState`, `stepTitle`, `stageBar`, `otherLabel`, `mergePieces`, `groupLayout`, `barSvg`, `markSvg`, `arrowSvg`, `segmentSvg`, `sleepSvg`, `groupDefs`, `rowLabelsSvg`, `groupSvg`, `axisSvg`, `nowSvg`, `tickLabel`, `toolbarHtml` and `tlChange`.
- **D3: the time-to-x mapping is copied three times.** `TL.LABEL_W + ((t - win.from) / (win.to - win.from)) * TL.PLOT_W` appears in `timelineSvg` (`plot.x`), `axisSvg` and `nowSvg`. Make it one helper, e.g. `tlX(win, t)`, or pass `plot` to `axisSvg` and `nowSvg`. In the same spirit, `tlClip(sleepWaits(ctx).map((w) => [w.from, w.to]), range)` appears in both `storyGroup` and `modelTotals`. Make that `sleepIntervals(ctx, range)`.

## Minor (fix while there; does not block on its own)

- **m1:** TL14 says the header is `<id> · <title>` with the **title** cut at 80. `groupSvg` cuts the whole string instead: `tlCut(id + " · " + title, 80)`.
- **m2 (performance):** `touches` rebuilds the `messages` Map and scans every event for each PO turn. It runs from `poBars` and again from `otherWaits` for every story, and Sprint scope multiplies that by the number of stories. On top of that, every wheel tick builds the whole model twice: once in `tlTarget` for the range, then again in `render()`. The real run already has 4,292 events, and `po-turn` events will add up over a run. Suggest building the Map once per `ctx` and having `tlTarget` compute only the range (`modelRange`).
- **m3:** `nowSvg` fills in the height by `.replace("__H__", h)`. Passing `h` as a parameter is simpler.

## Note for the architect (design, not code)

- TL15 makes a sideways wheel pan the timeline (`preventDefault`). TL16 says narrow screens scroll the plot natively. On a narrow screen a trackpad swipe over the plot now pans instead of scrolling, so the overflow can only be reached through the scrollbar. The code follows the design. Decide whether that is what you want.
