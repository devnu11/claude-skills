## Findings by AC

- **s131/AC1 (REQ-028)**: met. The record is written and committed before
  `_advance_and_log`. Two tests pin this from different angles: the step at
  commit time, and the last commit at the time of the advance.
- **s131/AC2 (REQ-029)**: met. A failed commit gives a hold at ops-review
  with no round, the story file is restored, the tree is clean (both the
  staged and unstaged cases), and the reason names the git error.
- **s131/AC3 (REQ-028, REQ-029)**: met. The order is pinned, and the commit
  failure is faked only for the Tooling subject, so `commit_step` is not
  affected (the design's pitfall).
- Docs: the protocol.md ops gate row, the ADR-0059 amendment and the s115
  "resolved" note all move with the behaviour. SKILL.md and the README need
  no change (the design says why).
