## Blocking items

- **D1. `record_ci_bug` and the bug-first rule are untested (AC4, AC7 "the hold until
  a bug story is recorded", CI11, CI14).** No test calls `Tools.record_ci_bug`,
  `_bug_refusal`, `BoundaryRunner.settle_bug` or `_bug_first`. Missing, per the
  design checklist (po_tools): the three refusals (`NO_CI_HOLD` with no boundary or
  another hold, `UNKNOWN_BUG`, `DONE_BUG`). Also the accepted case: boundary
  `None`, `upstream.closed == sprint`, the report holds "checks failed, story sN
  opened", `ci_bug == sN`, and a `done` event with `ci: red, story: sN`. And
  `start_sprint`: refused with `CI_BUG_FIRST` when the open bug is not first;
  accepted when it is first, with `ci_bug` cleared; a done bug story gives no
  refusal and is cleared.
- **D2. The boundary runner's non-green CI outcomes are untested (AC7: red with
  failing lines, timeout, no PR).** The only runner test that reaches `_ci` is
  `test_permission_yes_pushes_branches_and_opens_pull_requests` (green).
  `FakePrs.check_list` is one fixed list, so it cannot script "pending, then
  green" or red with a log. Missing from the checklist:
  - red → `held` `ci_failed`, `ci: red`, `checks` holds the job and failing lines,
    the `ci_failed` hand-over holds them, and the sprint stories wait;
  - timeout → `held` `ci_pending` with `reason`, then `continue_boundary` reruns CI
    and green finishes;
  - continue after red, still red → held again, never `done`;
  - no checks, and no non-draft PR → `done`, `ci: none`, an `update` with
    `CI_NONE_REPORT`;
  - permission `no` and `gh` missing → the `local` event carries `ci: none` and the
    stage never reaches `ci` (`test_pushed_and_local_notes_never_say_ready` checks
    only the constant);
  - plain start skips `ci`, a restacking start runs it;
  - `UpstreamError` from `checks` → `boundary_error` hold (CI16);
  - `entry.ci` is set and saved (CI9);
  - the AC5 sweep: on every non-green path, no posted note, hand-over line or
    `upstream.report` holds `READY_PHRASE`.
- **D3. The e2e test is missing (AC7: "one e2e test covers the real call path with
  a stub `gh` on PATH").** There is no `tests/e2e/test_s81_ci_e2e.py`. The design
  specifies it: a stub `gh` in `tmp_path/bin` first on `PATH`, then
  `CiWatch(GhPrs(command_runner(tmp_path)), 30).results([entry])` gives RED with
  the `FAILED tests/x.py::test_y` line, and the stub's recorded argv is checked.
- **D4. No state round-trip.** Nothing tests that a legacy `state.json` without
  `ci`/`ci_bug` still loads, or that a saved `StackEntry.ci` comes back as a
  `CiResult` through `state._upstream_state`.
  `test_result_round_trips_through_asdict` covers only the dataclass, not the
  loader.

## Non-blocking nits

- **N1.** `_ci_pending`'s reason always says "still running after {ci_timeout_s}s".
  It is also reached when all `CI_LOOKS` looks end with pending checks before the
  deadline (rare: `--watch` normally returns only when the checks are done). In that
  case the text overstates the wait.
- **N2. Timeout with no checks.** When the deadline passes before any check is
  queued (reachable only if `ci_timeout_s` is under about 2 minutes), the verdict
  is `NONE` and the boundary finishes with the NOT-ready text instead of holding.
  This matches CI6/CI10, but it differs a little from AC5 ("a timeout … holds the
  boundary"). It is safe, because nothing is called ready, so I note it only.
- **N3.** `upstream.py` adds `__all__ = ["UpstreamError"]` only to mark the
  re-export. It also declares the module's whole public API to be that one name.
  `from .ci import UpstreamError as UpstreamError` would say the same without
  that side effect.
- **N4.** `FakePrs.wait_checks(number, seconds)` names its parameter differently
  from the Protocol's `limit_s`.
- **N5.** `command_runner` returns `out + err`. If `gh pr checks --json` writes a
  warning to stderr, `checks_of` fails to parse it and holds `boundary_error`. This
  is pre-existing behaviour, and it fails safe.
