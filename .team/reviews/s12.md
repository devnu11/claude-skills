## Findings

### F1: the escape e2e test does not exist (s12/AC1, REQ-101). Blocker

The design gives `tests/e2e/test_s12_proxy_escapes_e2e.py` to the integration-tester:
the `PROBES` table (11 rows, E1), `probes(ProbeLayout)`, `probe_script`, `sections`,
the `escape` fixture, `bare(settings)`, the control test (E3) and the sandboxed test
asserting the whole `{name: leaked}` map (E4), with `HOME=tmp_path` and
`S12_SECRET_DIR` in the env (E5). None of this exists. The story's Tooling section
says AC1 is "automatic today" through this file, which is not true at HEAD.

### F2: the shared harness `scripted_cli.py` does not exist (s12/AC1, AC3; REQ-101, REQ-103). Blocker

`tests/e2e/scripted_cli.py` with `PROXY_SANDBOX_PLATFORMS = ("darwin",)`,
`PROXY_SANDBOX_SKIP` (naming s60), `bundled_cli()`, `CliRun` and `run_scripted` is
missing. `test_proxy_sandbox_e2e.py` still holds its own copy of s58's helpers, so the
DRY move in the design has not happened either.

### F3: AC3's platform table and skip are missing (s12/AC3, REQ-103). Blocker

Without F2's tuple and the s12 module's `pytestmark` skip, nothing marks the escape
tests to run on Linux once s60 lands. The ubuntu CI job cannot show the skip with
the s60 reason the Tooling section points to.

### F4: AC2 is unproven (s12/AC2, REQ-102)

E6 says the developer has work only if a probe leaks. With no sandboxed run, nobody
knows whether any form gets through, so AC2 can't be closed as "nothing to fix".
This finding goes away once F1's sandboxed test runs green on the macOS gate. If a
row leaks, follow E6: fix (a) or (b) plus a `test_sandbox.py` unit test, or hand off
`blocked`.
