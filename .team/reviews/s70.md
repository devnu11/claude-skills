## Function by function

### `process_groups.RunnerIds` (X1)
- Frozen dataclass `(pid, pgrp)`, placed after `in_runner_group` as designed.
- `current()` reads `os.getpid()` / `os.getpgrp()` at call time, never at import.
  Covered by `test_runner_ids_current_reads_the_live_process`, which reads the
  live values in the test body.
- `names(pid)` returns `pid in (self.pid, self.pgrp)`. Covered by
  `test_runner_ids_names_its_pid_and_group` (both true cases and the false case).
- Defects: none.

### `sandbox._may_end(recorded, runner_ids)` (X2)
- Returns `not runner_ids.names(pid) and recorded.is_ours()`. The free check runs
  first, so `is_ours` (which runs `ps`) is skipped when the ids name the pid.
- The order is pinned by `test_is_ours_is_not_asked_when_the_ids_name_the_pid`:
  `is_ours` raises if called.
- Defects: none.

### `sandbox.stop_stale(root, runner_ids=None)` (X2)
- `None` means `RunnerIds.current()`. The pid file is always unlinked. The only
  caller, `Preparer.prepare` (line 338), still passes no ids, as designed.
- Tests:
  - #9 parametrized over `FAKE.pid` / `FAKE.pgrp` with ids `pid` / `pgrp`.
    `is_ours` is forced `True`, so only X2 can block the signal. It asserts no
    signal and the file is gone.
  - Control case (4244) signals SIGTERM.
  - Default case (live `os.getpid()` in the body, no ids) sends no signal.
  - `may_signal_child_group`'s own `getpgrp` wall is unchanged.
- `runner_ids or RunnerIds.current()`: a dataclass is always truthy, so `or` is
  safe here.
- Defects: none.

### `tests/test_s70_ids.py` (X5)
- `node_ids(output)` keeps the lines that contain `::`. It is small and has a
  docstring.
- `_start_collect(home)` runs `python -m pytest --collect-only --no-cov -p
  no:cacheprovider tests/` with `AGILE_TEAM_HOME` set to scratch. Two collectors
  run at once, each with `communicate(timeout=25)`. The test asserts both exit 0,
  both lists are equal, and the list is non-empty.
- Nit (non-blocking): the design's command has `-q`, but the code leaves it out
  and relies on `addopts = "-q"`. Without `-q`, pytest 9 prints a tree with no
  `::` lines. If `addopts` ever loses `-q`, the test fails loudly at
  `assert first`, so it is safe, but an explicit `-q` would be clearer.
- Note: under `-n auto`, two full collections start inside a busy worker. 25 s
  should be plenty (collection takes a few seconds), but watch for a slow-machine
  flake once DevOps turns xdist on.
- I found no parametrize in `tests/` that evaluates `os.getpid()`,
  `os.getpgrp()` or `time.time()` (grep).
