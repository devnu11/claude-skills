## Blocking

### D1. The dashboard fixture was hand-edited, not regenerated (SC11)

`agile_team/dashboard/fixtures/snapshot.json` still holds the Scribe's step:
events `e40`/`e41` (`step-start`/`step-end`, `role: "scribe"`, "Record s1
decisions." / "ADR 0003: csv module over pandas.") and two more `role: "scribe"`
entries (lines ~2642, ~2998). Commit 9cb368e then hand-edited that step's
`model` from `haiku` to `"unknown"` so `test_s96_snapshot` would pass.

The script (`scripts/make_dashboard_fixture.py`) no longer emits that step, so
the committed fixture is not what the script produces. The design says
"Regenerate … with the script; do not hand-edit it". The fixture is the
snapshot contract (charter), so it must match its generator.

Fix (developer-cli): run the script as its usage line says and commit what it
writes. Check the result has no `"scribe"` anywhere and that the `"unknown"`
model is gone. If a later event relied on the Scribe step, give it to
`architect` as the design says.

## Should fix (non-blocking)

### N1. The role-text test regex matches `describe` (unit-tester)

`test_s114.py::test_no_builtin_role_mentions_the_scribe_or_briefs_dir` uses
`re.search(r"(?i)scribe", text)`, which matches "describe" and "prescribe".
That is why d9ed413 changed `architect.md` ("describe it" → "put it") and
`product-owner.md` ("prescribe" → "dictate"), which the design did not ask for.
Every later role file that says "describe" will fail this test. Use
`r"(?i)\bscribe\b"`. The wording changes themselves are harmless.

### N2. The fixture test only checks `roles[]`

`test_fixture_has_no_scribe_role` checks only `snapshot["roles"]`, which is how
D1 got through. Assert that no event or step in the fixture has
`role == "scribe"` either (unit-tester).

Line 17 reads "…sends a story back with the gate's reason, runs the manager
when one is due." The "and" the design specified is missing. Item 5 now
starts a sentence in lowercase ("continue_story also clears…"). Both lines
are left unwrapped. These are cosmetic.

## D1 resolved: the fixture was filtered, and that is the only way to remove the step

The round 1 fix ("run the script") does not work. `make_dashboard_fixture.py`
`starting_point()` returns the existing file whenever it has an `upstream`
key, and the committed fixture has one. `add_live()` then rebuilds only the
live tail (events after `CURATED_END`, turns, heartbeat, health, tools).
Running the script would have kept the Scribe's curated events. The design
step's "regenerate, do not hand-edit" was wrong for this fixture. Removing
the curated entries by hand is the only option short of rewriting the script.

What I checked in 9009227:
- No `scribe` is left anywhere in `snapshot.json` (`grep -ci` gives 0), and the
  hand-set `"model": "unknown"` is gone with the step.
- Only whole entries were removed: events e40/e41, one ledger line and one
  steps row. The event ids now skip from e39 to e42. Nothing refers to them,
  and the UI doesn't need ids to be contiguous.
- Nothing aggregated drifts. The Scribe ledger line cost $0 (`qwen3-coder`),
  `run` holds no spend total, and `roles[]` already had no Scribe.
- The file has no trailing newline. That matches `json.dump` in the script,
  so a future run of the script leaves no diff.
