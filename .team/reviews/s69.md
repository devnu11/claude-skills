# Review: s69 Only the runner runs the full suite (round 2)

Diff: `87ad533~1..HEAD` (6 commits). Verdict: **changes requested.** The runner
side (results, gates, quality pre-run, runner tools, role text, docs) is sound
and well tested. The Bash denial (AC4) has two holes that let a role run the
full suite by accident, and both are plausible commands for an agent to write.

## Defects

### D1 (blocking, rule S4): one named target unlocks a whole-suite run

S4 says a segment is `TARGETED` when *any* word after the test tool is a
target. A command that names one file **and** a directory, or `.`, runs the
whole tree and passes. I checked `suite_check.run_kind` (pure, no test run):

| command | `run_kind` |
|---|---|
| `pytest tests/test_x.py tests/` | targeted (runs all of `tests/`) |
| `pytest tests/test_x.py .` | targeted (runs everything) |

That breaks AC4 ("deny a full pytest run"). The runner tool is safe here:
`run_tests` checks *every* id with `is_target`. The Bash check should match it.
Suggested rule: `TARGETED` only when there is at least one target and every
positional word after the tool (one that does not start with `-` and is not
the value of a `VALUE_OPTIONS` option) is a target. Otherwise `FULL`. This
over-denies `--maxfail 1` (the agent can write `--maxfail=1`), which is the
house rule for enforcement (s7: when unsure, deny).

### D2 (blocking, rule S1): a leading env assignment hides the run

S1 checks only the first word, so a `NAME=value` prefix slips through:

| command | `run_kind` |
|---|---|
| `PYTHONPATH=. pytest -q` | None |
| `FOO=1 uv run pytest` | None |

Agents write `PYTHONPATH=.` and `COVERAGE_FILE=…` prefixes often. Fix: skip
leading `NAME=value` words (an identifier before `=`) before the launcher
check. `env` is already a launcher, so `env FOO=1 pytest` is caught today.

Other ways past the check that I found: `exec pytest`, `command pytest`,
`xargs pytest`, `python -mpytest`. They are less likely. List them in the S10
residual risk in protocol.md, or add `exec`/`command`/`xargs` to `LAUNCHERS`
(this costs one word each).

Both D1 and D2 change design rules S1/S4 and the pinned checklist items 1–2.
The **architect** should amend the design. Then the unit-tester adds the rows
(`pytest tests/test_x.py tests/` → FULL, `PYTHONPATH=. pytest -q` → FULL) and
the developer changes `_targets_after`/`_launcher`.
