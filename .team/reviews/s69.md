## Round 2 defects: verified

### D1 (S4): every positional must be a target — fixed
`_positionals_after(words, index)` collects the words after the tool that do not
start with `-`, are not the value of a `VALUE_OPTIONS` option and are not
redirects. `_targeted_or_full` returns `TARGETED` only when that list is non-empty
and every word in it is a target. This now matches `run_tests` (R2). Pinned:
`tests/test_x.py tests/`, `tests/test_x.py .`, `-- tests/e2e` and
`--foo 1 tests/test_x.py` are all FULL. `--tb short` and `--maxfail 1 -x` are
TARGETED. I also checked by hand (no tests run): `pytest -r tests/` gives FULL
(no positional left), `--deselect tests/` and `--rootdir .` are skipped as
values, and `nice -n 5 pytest tests/test_x.py` gives TARGETED.

`VALUE_OPTIONS` grew by `--tb --maxfail --durations -W -r -n --timeout`. Each of
these takes a separate value in pytest or xdist/pytest-timeout, so skipping the
next word never hides a path pytest would collect. OK.

### D2 (S1): leading assignments, more launchers — fixed
`_command_words` drops leading `NAME=value` words. `run_kind` calls it before
`_launcher`/`_expanded`. `exec`, `command` and `xargs` are now in `LAUNCHERS`.
Pinned: `PYTHONPATH=. pytest -q`, `FOO=1 uv run pytest`,
`A=1 B=2 python -m pytest`, `exec pytest`, `command pytest -q` and `xargs pytest`
are FULL. `COVERAGE_FILE=x pytest --cov` is COVERAGE. `FOO=1 echo pytest` and
`FOO=1` alone give None. Manual check: `exec env FOO=1 pytest tests/` gives FULL.
protocol.md S10 now lists `python -mpytest` as a residual risk. OK.

## Non-blocking notes

- **N1 (design drift):** the developer added `REDIRECT` (`^\d*[<>]`). It is
  needed because the guard splits `2>&1` on `&`, which leaves `2>` as a word, and
  without `REDIRECT` the pinned guard row would be FULL. But the design
  (S4 and its constants) does not mention it. The Scribe or architect should add
  one line to S4 next time they touch the design.
- **N2 (over-deny):** a redirect with a space before its target
  (`pytest tests/test_x.py > /tmp/out`, `2> err.log`) counts the target as a
  positional, so the run is FULL. Written without the space (`>/tmp/out`), the
  run is TARGETED. This is consistent with the s7 rule (when unsure, deny), and
  the denial reason points to `run_tests`. It could be tightened later by
  skipping the word after a bare redirect.
- From round 2, still open: the `rstrip("/") + "/"` repeat in
  `config.Targeted`, and `run_tests` given a string instead of a list (refused
  safely, but the reason names one character). The coverage misses the quality
  czar listed (99%, all outside s69's lines) are still not confirmed as older
  than s69.
