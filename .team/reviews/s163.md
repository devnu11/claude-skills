### D5 (minor, new; from the D2 fix): an unawaited coroutine on every start_sprint without heads or upstream. s163/AC4, REQ-170 (design S2)

```python
find = system.in_thread(switchover.find_merged, rt.upstream, heads)
merged = await find if heads and rt.upstream else {}
```

`in_thread` is an `async def`, so line 1 always creates a coroutine. When the stack has no heads, or
there is no upstream, that coroutine is never awaited. Python then emits
`RuntimeWarning: coroutine 'in_thread' was never awaited` on every such `start_sprint`, which is the
common case. It is a resource leak and log noise, and it fails any test run with
`-W error::RuntimeWarning`. The no-upstream crash itself is gone.

**Fix:** create the coroutine only when it will be awaited, for example a guard
`if not (heads and rt.upstream): merged = {}`, or a small `_find_merged(heads)` helper that
returns `{}` early. Then add a test: no upstream and a stack entry with a `head`, and
`start_sprint` drops nothing and does not raise (S2).
