# Code review: s163 (serial landing queue, overlap hold, sprint-49 fixes)

Reviewed: `git diff f29f695b..24663978` (the story's first commit to HEAD), against
`agile-team/docs/design/s163.md`. I read the tests and did not run them; the runner's coverage
run passed at 97.36%.

**Verdict: changes requested (tester).** The code follows the design, and I found no
blocking logic defect in it. The tests are the problem. Most of design §7's checklist for
AC3 to AC8 has no test, and these ACs are exactly the sprint-49 fixes (B1, B2, M1, M2, M4). The
story's `## Tooling` section says every AC is "automatic today" with named tests. For AC4,
AC5 and AC6 those tests don't exist. New code in `switchover.py` (lines 87, 94-95) is
uncovered, which breaks the charter's "coverage is 100%; keep it there".

## Blocking findings

### T1. AC3 / REQ-169: the B2 scenario and G1/G4 have no tests
`tests/test_s163_landing.py` has 4 tests (K2 on-head, K2 off-head, R1, G4 refused gives up).
These items from design §7 AC3 are missing:
- The B2 e2e: s1's CI holds with `landed.pushed` set, s2 lands, s1 is continued, gives up
  (`why: "sprint head moved"`), merges afresh on s2's merge and lands with no halt. This is
  the bug the story exists to fix, and nothing exercises `Lander.check_resume` (G1). Grep finds no
  test naming `check_resume`, `is_on_head` or a resumed landing that gets dropped.
- A resume whose merge is still on the head reads CI at the same sha with no new merge (L11).
- `give_up` deletes the landing branch under its lease, and an already-deleted branch is not
  an error (G3).
- G4's three branches in `move_to_remote`: the remote equals `pushed` (re-land, no halt), the
  remote moved ahead (fast-forward, `head == pushed == R`, merge afresh on `R`), and a remote
  that doesn't descend from `pushed` (halt with `landed` cleared). The one G4 test only asserts that a
  `landing-dropped` event exists.
- The fake upstream doesn't check, on every sprint push, that the pushed merge's first
  parent is the sprint head.

### T2. AC8 / REQ-173: R2 has no test
Nothing asserts `entry.head == entry.pushed == R` after a followed remote, or that the next
lease's `expect` is `R`. `move_to_remote` has no test of its own. R1 is covered
(`test_pushed_names_the_merge_even_when_the_fast_forward_fails_r1`).

### T3. AC4 / REQ-170: no test drops a stack entry
Grep finds no test that names `stack-dropped`, `STACK_DROPPED`, `find_merged` or
`drop_entries`. The two `start_sprint` tests in `test_s163_scheduler.py` only show that
nothing is looked up with no upstream or an empty stack. Missing:
- a contained entry dropped with `why: "contained"`, and a rebased (patch-equivalent) entry
  dropped with `why: "patch-equivalent"`, on real git in a scratch repo;
- an entry with a commit main lacks stays, and the switch is refused;
- the sprint-49 case (a rebase-merged entry plus a rebased team branch switch with no state edit);
- a failed fetch (`missing()` gives a reason) drops nothing, and a `GitError` keeps the
  entry. Both are S2, and the coverage run shows them uncovered (`switchover.py` 87, 94-95).

`test_s163_unpicked.py` covers `count_unpicked` and `why_in_target` against the fake system,
which is good, but nothing tests the `start_sprint` wiring (`Tools._drop_merged_entries`).

### T4. AC5 / REQ-171: none of the lock tests exist
No test blocks a landing's CI wait and checks that `main_lock` is free, that a tell, answer, story
request or `accept-checkout --story` is applied, that a storyless step starts, or that a PO turn
settles (K1). No test uses a lock probe to check that the fast-forward and `record_checkout` run under
the lock, on a first landing or a resumed one (K2). No test makes a story-admin commit during the CI
wait and checks that the merge is given up (K6). Local mode's on-head check and lock (K3) and
`land_revert`'s missing outer lock (K4) aren't asserted.

### T5. AC6 / REQ-172: none of the boundary tests exist
Grep finds no test that names `call_from_thread`, `run_follow`, `follow_task`,
`may_apply_queues` or `checkout_lock`. Missing from design §7 AC6:
- a PO turn, a writer drain and a story-CI poll during a blocked CHECK and a blocked CI wait;
- SYNC holds the lock, and CHECK and CI don't;
- a REPLAY checkpoint goes through `call_from_thread` with no `WrongWriter`, and `b.replay`
  holds the last checkpoint after a crash;
- the request queues wait while a stage task runs, and are applied after it;
- `run_follow` fast-forwards under the lock.
The old boundary tests do still run `step()` through `asyncio.run` (B7).

### T6. AC1 / REQ-167: the scheduler-level checklist items are missing
The pure and `LandingQueue` tests are thorough (`test_s163_landing_order.py`,
`test_s163_queue.py`). These are missing:
- two stories at `land`: the smaller lands first, and the other waits with `waits to land after <id>`;
- a held land rejoins by size after `continue_story`, not at its old place, and a
  bounced one rejoins by size;
- `RunState.landing` survives a save and a load, and the interrupted landing goes first;
- an older `state.json` with `land_queue` loads. `test_s114` only checks that `RUN_DROPPED` names it.

### T7. AC2 / REQ-168: the hand-over, continue refusal and replay after a lift are untested
`test_s163_overlap_hold.py` covers screen, lift and release well. Missing:
- the hand-over is `overlap`, not `gate_hold`, and only that story waits. Grep finds
  no test naming `Trigger.OVERLAP` or `overlap_text`, and `_find_overlap_fields` and the
  `_gate_held` exclusion have no direct test;
- `continue_story` on an overlap hold is refused with `OVERLAP_CONTINUE` (F8). No test
  names it;
- after a lift, the next step replays the branch onto the current sprint head (a `story-branch`
  `replayed` event).

## Non-blocking findings

- **N1 (s163/AC1, no requirement: test hygiene).** `test_s159_scheduler.py:78,87` still sets
  `rt.state.land_queue = [...]`, a field that no longer exists (Q8). The assignment only
  adds a stray attribute, so `test_only_the_head_of_the_land_queue_lands_l2` passes only
  because both stories are size 0 and `s1` sorts first. Its name and setup describe the removed
  rule. It should be rewritten against `next_up()` or removed in favour of the s163 tests.
  (The gate fix b9d7440b removed the same lines from the e2e file but missed this one.)
- **N2 (house rule, no AC).** Two new functions take 3 parameters besides `self`, and the charter
  allows 2: `LandingQueue._accept(placement, order, smallest)` and
  `BoundaryRunner._run_replay(b, tools, progress)`. Several new functions also run well past
  8 lines (`Lander.move_to_remote`, `push_and_follow`, `LandingQueue.place`).
- **N3 (DRY, AC1/AC3).** The test `any(call.story_id == x for call in
  self.runtime.revert_queue)` is written out in `LandingQueue._is_live` and `_get_span`, and
  `_queued_ids` is a third form of it. Deleting the landing branch
  (`landing_branch(...)` + `run_off(upstream.delete, Lease(branch, merge, ""))`) is
  duplicated in `Lander.give_up` and `finish_pushed`. `_run_replay` and `_resume_replay`
  repeat the deepcopy, `save` hook, run and assign steps. The test file repeats the
  `LANDING_DROPPED` event filter three times.
- **N4 (s163/AC3 / REQ-169, design-sanctioned).** When K2 step 1 gives up a merge, it deletes the
  landing branch under the lock, and then `finish_pushed`'s `finally` deletes it a second time.
  The second delete is refused harmlessly. This costs one extra network call, and the first one
  holds the lock.
- **N5 (s163/AC6 / REQ-172, design-sanctioned, B4).** REPLAY holds the main lock for its
  whole stage, so the rebase-fix path holds it through a full check run in the scratch tree
  (`_checks_refusal`). This follows B4 as written, but it is longer than "locked only while git
  moves it" (REQ-171). The ADR should record it as a known limit.
- **N6 (s163/AC6 / REQ-172).** `start_boundary` doesn't check `follow_task`, so a stage
  task can start while an R9 follow runs. Both write `b.stage`/`b.hold` and the sprint entry.
  The follow runs only on a CI hold, when no stage should be due, so the window is small. A
  guard or a test would close it.
- **N7 (s163/AC2 / REQ-168).** `Overlaps._read_theirs` runs
  `git show f"{other.branch}:…"` even when `other.branch` is `""`. That becomes
  `git show :path`, which reads the main checkout's index, not "nothing". The diff half is
  already skipped when there is no branch. The show half should be too.
  `_read_changed_files` splits on whitespace, so a path containing a space becomes two paths.
- **N8 (s163/AC1 / REQ-167).** `Q4`: after a crash, `state.landing` names the interrupted story,
  and `next_up()` keeps returning it while it stays at `land`. If the PO then holds that story,
  every other landing waits until it is continued. This edge case is not covered by the design.
- **N9 (docs, no AC).** `protocol.md`, `SKILL.md` and `README.md` are unchanged. Design §9
  gives them to the architect at design-review, so this is expected, but that step must do it.
