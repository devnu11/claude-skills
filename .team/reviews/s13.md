## Focus areas

### Proxy stays walled off from source and tests (s7 holds)

- `proxy_read_globs` adds only `.team/acceptance/**`. `_allowed_reads` adds
  only `<repo>/.team/acceptance`. `denyRead: [repo]` is unchanged, as are
  `forbidden_roots`, `bash_forbidden` and `bash_allowed`. The source copy of
  the presentation (`.team/run/presentation/<story>`) is **not** readable by
  the Proxy. Only the copy under its sandbox root is.
- A symlink in the copied presentation does not escape. `copytree(symlinks=True)`
  keeps the link. The guard maps every Read, Grep or Glob path through
  `resolve_in` (`Path.resolve()`, which follows links), so
  `presentation/workspace/peek.py -> src/app.py` resolves to `src/app.py` and
  is denied. The OS sandbox checks the real path for Bash. Ripgrep does not
  follow links by default.
- The Proxy's write scope is unchanged: its sandbox plus the role's
  `.team/acceptance/**`. `Read` is added to `web`, `harness` and `manual`.
  `_fit_role_to_delivery` intersects the kind's tools with the role's tools,
  and the role has `Read`, so `Read` survives. This is what AC5 needs.
- Only `integration-tester` gains `.team/run/presentation/**`.
  `test_other_roles_may_not_write_the_presentation` covers the others.

### e2e gate (E4/E5)

- `Pipeline._done_gate` applies only when the step is `e2e`, the handoff is
  `done` and `"acceptance" in steps`. It runs through `_retry_here`, so a
  missing presentation bounces to `e2e` and counts a round. `changes_requested`
  still goes to `_handoff_outcome`. Stopped handoffs still HOLD first.
- s11's `_gate_for` keeps it intact: the dispute gate is only for `tests`, and
  `_command_gate(...) or _done_gate(...)` is unchanged.
- `presentation.missing` is the single definition, used by both the gate and
  `unpresented`. The reasons match the design strings exactly. The guide is
  checked before the workspace, a workspace holding only `.git` counts as
  empty, and `manual` or no delivery needs only the guide. All of these are
  tested in `test_presentation.py`.
- `make_pipeline` wires it with `functools.partial(presentation.missing, config)`
  (`test_pipeline_checks_the_story_presentation`).

### No-round return to e2e (E6) for s4, s5, s8

- `run_role` → `refusal` → `settle_po` → `_unpresented` → plan. The refusals
  come first, so backlog, done, blocked, needs-manager and wrong-step stories
  are still refused. `_step_refusal` ensures the Proxy only reaches
  `_unpresented` on a story at `acceptance`, so a return can only move
  `acceptance → e2e`.
- `Verdict.RETURN` → `_return` sets `story.step` only. Rounds and status are
  untouched, and it never escalates at the cap
  (`test_return_at_the_cap_does_not_escalate`). No `plan` runs, so there is no
  sandbox, no prepare and no query, and nothing is billed. A `gate` event is
  emitted through the shared `_advance_and_log`, and the state is saved.
- The report is `{"status": "returned", "role", "reason", "gate"}`. It is not
  in `NOT_NOTED`, so `note_step` records it as the previous step with verdict
  `return`. The next integration-tester brief therefore says why
  (`test_a_return_is_recorded_as_the_previous_step`). s19's router keys on the
  story's step, so it routes the integration-tester next. The dashboard tones
  `return` as a warning and shows "back to".
- For s4, s5 and s8 (at `acceptance`, with no presentation dir), `missing`
  returns the guide reason, they return with no round and s5 keeps 2 of 3.
  `test_returned_story_is_presented_then_reaches_acceptance` covers the full
  round trip.

### init outside git (E11)

- `Git.is_repo` returns `repo.is_dir() and rev-parse --git-dir == 0`. The
  `is_dir()` check comes first, so a missing path never reaches `subprocess`
  with a bad cwd. `_require_init_inputs` checks it before `is_clean` and
  before the preset and delivery answers. `--detect` is unaffected. Tests use
  `GIT_CEILING_DIRECTORIES`. A plain dir and a missing dir both give the exact
  stderr line and exit 1, with no files written.

## Non-blocking notes (follow-ups, not a bounce)

1. **Test gap:** `test_prepare_keeps_a_symlink_in_the_copy_a_link` only
   asserts that the link survives. No test asserts that `Read` of
   `presentation/workspace/peek.py` (linking to `src/app.py`) is denied. The
   code does deny it (`resolve()`), but this is exactly the s7 guarantee E7
   relies on. A one-line `use(scope, "Read", …)` assertion would pin it.
2. `prompt_section` reads the guide unguarded. With no `e2e` step but a stale
   presentation dir that has no `PRESENTATION.md`, `plan` raises
   `FileNotFoundError` (only `SandboxError` is caught). This can only happen
   after someone changes the pipeline config, so it is unlikely.
3. If `git init` fails in `lay_out`, it raises `GitError` from `plan`. That is
   not converted to a refusal like `SandboxError` is. The router turns it into
   an error report, and the PO tool path surfaces it as a tool error. This is
   rare.
4. `_unpresented` calls `self.resolve(request.role)` twice in one line. Hoist
   it to a local variable.
5. `_copy_presentation` uses a deferred import to break the
   `presentation ↔ sandbox` cycle. It works and the comment explains it, but
   injecting the copy (or moving `copy_into` into `sandbox`) would remove the
   cycle.
6. Design text: E8 says the `web` Proxy "has no Read access to the sandbox
   files it serves", but E9 gives `web` `Read`. The code follows E9, which is
   fine. The Architect should fix the wording in E8.
