## Functions

### `instructions.repo_instructions(repo)` (new)
- **What it does:** resolves the repo and `<repo>/.claude/CLAUDE.md`. It returns `""` unless the file exists and resolves inside the repo. Otherwise it returns `Inliner(root).file(path)`.
- **Tests:** a missing file (`test_missing_file_adds_nothing`) and a whitespace-only file (`test_whitespace_file_adds_nothing`, emptied by `_section`'s strip) are covered. Rule 2's "a symlink that resolves outside the repo" has no test, but the fake world may not model symlinks. The branch is covered by the missing-file case. Not blocking.
- **Defects:** none.

### `Inliner.file(path)` (new)
- **What it does:** marks `path` as seen, reads it, and replaces its imports. The base directory is the file's own directory.
- **Tests:** nesting and relative resolution (`test_imports_resolve_relative_to_the_importing_file`) and cycles (`test_cycle_ends_with_the_repeat_note`) are covered.
- **Defect (minor, s142/AC1, REQ-056, not blocking):** `system.read_text` on an in-repo import that is not UTF-8 text raises `UnicodeDecodeError` (for example `@docs/logo.png`). It is raised inside `RoleBook.system_prompt`, so every role's step fails until the human edits `.claude/CLAUDE.md`. That is unlikely but has a large impact. Suggestion for a follow-up story: treat an unreadable file like "not a file" and leave the token verbatim. Rule 3 as written does not cover this, so it is not a deviation from the design.

### `Inliner._replace(match, base)` (new)
- **What it does:** returns a code match unchanged and passes an import to `_import`.
- **Tests:** the line is covered (the fenced case matches the code alternative). **The behaviour is not pinned.** See finding 1.

### `Inliner._import(path, base)` (new)
- **What it does:** implements rule 3's table in the design's order: `~` or outside the repo → OUTSIDE note; not a file → verbatim; already seen → REPEATED note; otherwise the file's text, stripped and inlined.
- **Tests:** these cases are pinned by tests that bite: OUTSIDE for `~`, for `../../` and for an absolute path to an existing file (`test_outside_import_left_out_with_note`), REPEATED (`test_inside_import_inlined_once`, cycle), and the inlined text. The "not a file" row bites only for `ping @someone` and `a@b.com`. See finding 2.
- **Defects:** none in the code.

### `instructions._target(path, base)` (new)
- **What it does:** returns `None` for a `~` path (never expanded). Otherwise it returns `system.resolve(base / path)`.
- **Tests:** pinned by the `~` case and by `test_home_instructions_are_never_read`, which patches `system.home` and `system.expand_user` to raise (s142/AC2, REQ-057).

### `RoleBook.system_prompt` (changed)
- **What it does:** adds `_section("Repo instructions", …)` between the role body and the charter.
- **Tests:** `test_order` checks the full index order (s142/AC1, AC4, REQ-056). The existing `test_roles` prompt tests are unchanged.

## Findings

1. **Blocking: the code-span rule is not pinned (s142/AC1, REQ-056; design rule 3 "Text inside backtick code … is never treated as an import").**
   `test_code_is_not_imported` writes `docs/a.md` but imports `@docs/a.md` from `.claude/CLAUDE.md`. Imports resolve relative to the importing file (design rule 3), so the target is `.claude/docs/a.md`. That file does not exist, so the token stays verbatim whatever the code does. In the inline case, `` `@docs/a.md` `` also cannot match, because the `(?<!\S)` lookbehind sees the backtick. If you delete the `(?P<code>…)` alternative from `_IMPORT`, both cases still pass.
   Fix: use `@../docs/a.md`, i.e. a path that would really inline `A-TEXT`. Use a space-led inline span (`` ` @../docs/a.md` `` or `` `see @../docs/a.md` ``) so that only the code rule keeps it out. Assert `A-TEXT` is absent, as the checklist says.
2. **Blocking (same cause): two "not a file inside the repo" cases do not test what they name (s142/AC1, REQ-056; rule 3 row 3).**
   In `test_not_a_file_stays_verbatim`, `"see @docs/a.md."` and `"@docs"` resolve under `.claude/`, where nothing exists. They do not exercise the trailing dot next to a real file, or a real directory.
   Fix: use `@../docs/a.md.` (`docs/a.md` exists) and `@../docs` (a directory that exists).
3. **Note (s142/AC3, REQ-058):** `.team/CLAUDE.md` is not changed yet. By the design this edit belongs to the liaison and does not bounce to a developer. The PO should ask the liaison before acceptance.
4. **Note, fits no AC:** `test_s56_fixture_script.script_tree` now reads through `system.read_text` and asserts a non-empty tree. `fake_system.SKILL_DOCS` serves the script. The unit-tester says this came from the Manager's question. It strengthens the test and weakens nothing. It is fine, but it is outside s142's ACs.
