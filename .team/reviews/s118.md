## Blocking

### C1. FC11 `sleepNote` is not implemented (developer-gui)

Design line 37 (B3) and line 223 restore s97 AC2: a running step timed by
wall clock ends its live line with `(may include sleep)`. `liveBlock` still
prints only `fmt.dur1(awake)`. The FC11 e2e checklist item (design line 504)
will fail against this code. The developer-gui's handoff does not mention
FC11.

### C2. FC21: still two layouts per changed render (developer-gui)

Design line 240 says `renderFlow` writes `.fc-chart` and calls
`applyFlowShow`, "nothing else". Line 241 says `renderFlowTab` runs
`renderFlow`, `layoutFlow`, `flushLive` in that order. The code still has
`layoutFlow()` inside `renderFlow` and `flushLive()` at the end of
`renderFlow`. So `flushLive` plays dots before the paths are laid out, and
the checklist item "one `renderFlowTab` call runs `layoutFlow` once"
(line 507) fails.

### C3. FC22: `dotFor` has no guard for a missing event (developer-gui)

If `e.id` is not in `view.events`, `findIndex` returns -1, and
`slice(0, -1)` takes every event but the last. That can produce a wrong dot.
The design now says this case returns `null`.

### C4. `agile_team/stage_log.py.bak` is committed (developer-gui)

6e1acf1 added a 168-line backup of `stage_log.py` inside the package
(`packages = ["agile_team"]`, so it ships). Delete it. If backups are part of
how you work, consider adding `*.bak` to `.gitignore`.

### C5. s86 test and s125 prose (PO, then integration-tester)

This is unchanged from round 1 (B4), and the design now confirms that s86
AC4 stands. First the PO rewords s125 line 34 ("It depends on s118 because
…", e.g. "It needs s118 because …"). Then the integration-tester removes
`_declared` and restores the test. The s97 running-line assertion (design
line 448) comes back after C1.
