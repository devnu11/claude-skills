## Non-blocking

### N1. FC21: layout runs only when the HTML changed

The design says `renderFlowTab` runs `renderFlow`, `layoutFlow`,
`flushLive`, and that `renderFlow` does "nothing else". The checklist
(line 507) says `layoutFlow` runs once per `renderFlowTab` "whether the HTML
changed or not". The code instead lays out inside `renderFlow`, and only
after a write. That matches the existing e2e test
`test_s104_flow_e2e.py::test_hidden_then_shown_draws_once_with_natural_size`
(`laid == 1` after two identical renders). The design's Superseded-tests row
for s104 doesn't list that test, so the developer had to choose between the
test and the design.

I see no user-visible defect. When the HTML doesn't change, the geometry
doesn't either, and resize, settings changes and showing the tab each run
`layoutFlow` themselves. The dot-ordering bug that C2 was really about is
gone. **integration-tester:** for line 507, keep the s104 test's contract
(one layout per chart write, none on an unchanged render) and say so in
your handoff, rather than asking the developer for a change that only
matters on paper. The `renderFlow` docstring ("then lay out and play dots")
describes the code as it is.
