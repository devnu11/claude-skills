## Equivalence of the anchored patterns (s167/AC2, AC3; REQ-177)

Both old patterns can only match inside one brace-free stretch that ends at `{`. If a match
starts at position q inside a stretch, a match also starts at the stretch's first character,
because the leading `[^{}]*` / `[^{}]+` takes in the prefix. `findall` returns the leftmost
match, and every match ends at `}`, so the next search starts at a stretch boundary. So the
old patterns only ever matched at stretch starts. `(?<![^{}])` lets a match start only at
the start of the text or right after a brace, so the new patterns find exactly the same
matches and the same groups. That holds for nested rules too (`@media x { .fc { … } }`):
the inner stretch starts after `{`, so the lookbehind passes.

## Observations (not blocking)

- **Linearity bound (REQ-176), fits no AC as a defect.** `FLOW_RULE` is linear in the
  stretch length only while a stretch has few `#flow`/`.fc` occurrences. If a stretch holds
  k occurrences and ends at `}` instead of `{`, the second `[^{}]*` rescans it once for each
  occurrence, which is O(k·L). The real page has nowhere near enough occurrences for that to
  matter, so I accept it.
- **Copy/paste.** Both files carry the same comment and the same `(?<![^{}])` prefix.
  They are two constants with different bodies, so they don't need a shared helper.
  `test_s118_page.css_rules` keeps the unanchored `([^{}]+)\{([^{}]*)\}`. The design
  leaves it that way on purpose: it scans only the style block, which the new guideline
  ("over a whole file") does not cover.
- **Style.** `test_a_flow_rule_that_sets_full_max_width_is_found` loops over two selectors.
  `pytest.mark.parametrize` would report each one on its own, but the loop is correct.
- **Top-level code.** Neither file has any: they hold only constants, functions and
  imports.
