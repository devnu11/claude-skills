## Findings

1. **Minor, docs (s158/AC2, REQ-122): the docs use a name the code doesn't have.**
   The developer renamed `global_argv` to `build_global_argv` for the verb-name
   rule, and the tests followed. `agile-team/docs/architecture.md` (s158 row) and
   `docs/design/s158.md` still say `repin.global_argv`. Behaviour isn't affected,
   and protocol.md doesn't name the function. The architect should fix the
   architecture.md row in a later docs pass. This doesn't block the story.
2. **Nit, tests (no AC):** `check[check.index("agile-team") + 1 :]` is repeated
   (twice in `test_a_clean_repin_execs_the_new_pin`, once in the in-order test).
   A small `cli_part(argv)` helper would remove the repetition. Not a defect.

## Checklist

- No top-level code: the new module-level items are constants (`START_COMMAND`,
  `CHECK_COMMAND`) and functions. The test file adds only functions.
- Copy/paste: no repeated blocks in the source. The only repetition is the test
  nit above.
- Gate fixes: none changed assertions outside the design's R1/REQ-122 reorder.

## Verdict

I would ship it. Every argv is now checked against the real parser, so the old
fault (a literal tuple hiding an order the CLI refuses) can't come back unseen.
