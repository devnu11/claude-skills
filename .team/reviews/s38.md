# Review: s38 — corrected budget numbers and the budget ceiling (round 0)

Verdict: **changes requested** (one blocking defect, D1). Diff reviewed: `379d95f~1..HEAD`.

## Defects

### D1 (blocking, AC3): following the halt's advice makes `start --resume` refuse to run

The advice (B5) and `docs/customer/stops-and-resume.md` tell the human to "raise
team.budget_usd in .agile-team.toml, then run `agile-team start --resume`".
`.agile-team.toml` is a tracked file (onboarding commits it; it is tracked in this repo,
`git ls-files .agile-team.toml`). Editing it makes the tree dirty. `cli._require_preflight`
then runs `Preflight.clean_tree()` (`git status --porcelain --untracked-files=all`) and refuses:

```
preflight failed:
  working tree is dirty (.agile-team.toml); commit or stash first
```

So the exact steps the runner prints do not resume the run. AC3 says "A raise takes effect
on resume without a restart of anything else". The human can work it out (commit, then
resume), but the dogfooding path in the story's Notes hits this every time.

The tests miss it because `test_raise_then_resume_runs_and_no_raise_halts_again` changes
`rt.config.team.budget_usd` in memory and calls `cli._run`. That skips both the config
reload and preflight. The design's checklist 12 asked for "rewrite `.agile-team.toml` …
then `start --resume`".

Fix (the design pins the exact advice string, so this is the Architect's call):
- either change the advice and docs to say to commit the raise (for example
  "raise and commit team.budget_usd in .agile-team.toml, then run …"),
- or have the runner accept or commit a change that touches only `.agile-team.toml` on
  `start --resume`.

Whichever is chosen, add a test that writes the toml, goes through the real
`start --resume` entry point (preflight included), and checks that the PO runs.

## Test notes (not blocking on their own)

- `test_snapshot.test_build_matches_fixture_values` was changed: the fixture's ledger rows
  are moved past `PO_DELTAS_FROM` and compared with `==`. This is not a weakening, because
  the assertion is still exact. It does contradict the design's line that "the snapshot-fixture
  tests do not change". The fixture's rising PO rows would otherwise be read as legacy totals.
  The change is fine; the Scribe may want to note it.
- Checklist 11 says "the router runs no further step". This is only implied by
  `len(q.calls) == 1`; no test asserts that a story step was pending and did not run.
  Consider asserting it.
- `test_s38.PO = "product-owner"` repeats the literal. Importing `ledger.PO_ROLE` would keep
  one name, as the design did for `dispatch.PO`.

## Observations (no change asked)

- `PO_DELTAS_FROM` is a global wall-clock cutoff. In another repo whose runner was upgraded
  to s25 after 2026-10-11 05:02 UTC, PO running totals written between the cutoff and the
  upgrade stay inflated. A legacy session that starts higher than the previous one ended is
  also under-counted (rule C1). The design and ADR-007 accept both.
- When halted at start, `cli._finish` prints `result.text` (empty), so stdout gets one blank
  line. This is harmless.
