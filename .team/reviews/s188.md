### What changed

- `boundary_runner._finish_green` (`:1012-1014`): the `if not results:` branch is gone, as the
  design says (`design/s188.md:143`). It builds the green report from the CI results and finishes
  with `ci=green` and the PR fields. If it ever gets an empty list, `ci.green_report` raises
  `ValueError` ("a PR is called ready only when every watched PR is green", `ci.py:320-324`). So
  a missing CI read now fails loudly; it doesn't quietly finish without telling the PO the PR is
  ready. **D2 fixed** (s188/AC2, REQ-243).
- `tests/test_s188_bookkeeping_tail.py::at_tail` now sets `own.ci = CiResult(pr, url, H, GREEN)`.
  That is the state the REPLAY gate (`get_rebase_refusal`) requires, so the fixture can now
  happen in production.
- `test_a_chore_tail_finishes_the_boundary_with_the_ff_for_h_ac1` asserts that the final event
  has `ci == "green"` and that `"#74"` is in `prs`. With `test_handover.py`'s rule (`ci_green`
  only on `outcome done` + `ci green`), this shows the sprint 53 path tells the PO once, naming
  #74. `test_ci_green_fires_once_and_names_the_pr_held_ac2` covers "exactly once" end to end on
  the sprint 54 path. **T1 fixed** (s188/AC1 + AC2, REQ-242 / REQ-243). The sprint 53 test
  doesn't count `ci_green` triggers itself. It doesn't need to: only the finish event carries
  `ci: green` there.

### Remaining

  gone, the `else []` arm only turns a missing CI read into the `ValueError` above. That is

- **N1 (nit, no AC, still open).** The two added lines in `agile-team/SKILL.md` (`:384`, `:396`)
  are still 88 and 110 columns wide. The developer couldn't fix them: the file is outside their

### D2 (still open, s188/AC2, REQ-243; s188/AC1, REQ-242): the branch guards a test fixture, not a production path

- In production, `own.ci` is always set when `_report_unchanged` runs. The REPLAY stage calls
  `get_rebase_refusal(own)` (`boundary_runner.py:580`). It refuses unless `own.ci` is green on
  `own.pushed`, and it sends the boundary back to CI. `test_boundary.py:266`,
  `test_s151_end.py:361` and `test_s151_end.py:400-408` test this: a `continue_boundary` after the
  refusal re-runs the CI stage, so CI is read before any replay. W4 and W7 of the design rely on
  this ("`_finish_green` with the entry's CI").
- The test depends on the branch only because its fixture is wrong. `at_tail`
  (`test_s188_bookkeeping_tail.py:57-65`) starts the boundary at PUSH_REPLAYED with
  `own.ci = None`, which the runner can't produce. So the branch is dead code in production.
- The branch also hides a defect. On the sprint 53 path, the test now finishes with
  `"Sprint 1 is pushed."`, **no `ci` field and no `ci_green`**. A test that passes there shows the
  opposite of AC2 ("The PO is told a sprint PR is ready to merge once, when the END boundary has
  finished"). If the branch is ever reached, the PO is never told the PR is ready, and nothing
  says so.
- The design says `_finish_green` doesn't change (`design/s188.md:143`). The branch is still not
  in the design.

**Fix.**
1. unit-tester: make `at_tail` match the real state. Set `own.ci = CiResult(..., H, CiVerdict.GREEN, ...)`,
   as `test_s151_end.py:72` does. Then add T1's assertions to the AC1 finish test: the last event
   has `ci == "green"`, its `prs` names #74, and `ci_green` is raised once.
2. developer-cli: remove the `if not results:` branch from `_finish_green`
   (`boundary_runner.py:1013-1014`), as the design says. A reachable no-CI path would need the
   architect to put it in the design and a test that pins it. Nobody has named such a path.
