## Findings

### F1 (blocking): the dispatch wiring has no test (s178/AC1 REQ-190, s178/AC2 REQ-191)

Design checklist item (design/s178.md:228-231):
"a story view's `pipeline.checks.clashed` is bound; the architect's brief in branch mode
carries `format_offer_section`'s head and sets `req_block`; after a clash bounce the retry
brief names an id no other work holds; without story branches the brief is
`design_section`'s."

None of this is tested:

- `Runtime.get_story_view` (dispatch.py:534) binds `checks.clashed`. If this line is deleted,
  every test still passes and the design gate never checks for clashes (AC2 is lost silently).
- `Runtime._format_requirements` (dispatch.py:683-690) has two branches: the architect in
  branch mode gets the offer, and every other case gets `section(...)`. No test asserts that
  an architect brief says "this story's ids are REQ-x to REQ-y". No test asserts that
  `plan.story.req_block` is set on the story in `state.stories` and survives the save, or
  that the code reviewer's and Customer Proxy's briefs reserve nothing (R7). The 100% line
  coverage of these lines, if they have it, comes from unrelated tests that assert nothing
  about them.
- AC2's "the brief for the retry names the next free id" is tested only by calling
  `reserve` directly (`test_clash_retry_brief_names_a_free_id`). No test covers it through a
  bounce and a re-brief.

Needed: tests in `test_dispatch.py` (or `test_s1_gate.py`) that cover the four checklist
points above. The most important are a branch-mode architect brief with the offer head and
a persisted `req_block`, a story view's design gate bouncing with a `REQ-… is already used
by sN` line, and a non-branch architect brief that is unchanged.

### F2 (minor): tests use a scripted `ls-tree`, not real git (s178/AC1 REQ-190, s178/AC3 REQ-192)

The design (design/s178.md:202) asks for a real git scratch repo. The tests script
`git ls-tree` on the fake system instead, so the pathspec form
`ls-tree --name-only <ref> -- <folder>/` is never run for real. I checked it by hand on
this repo. It lists the folder's files, and a missing ref exits 128. So the command is
right, but no test proves it. Acceptable if the tester adds one real-git case, for example
in F1's dispatch test. Not blocking on its own.

### F3 (nit, no AC): small repetition in `requirement_ids.py`

`fmt = requirements.format_id` is aliased in both `reserve` and `_find_holders`, while
`_find_holders` also calls `requirements.format_id` directly for `ON_HEAD`. Using one style
would be cleaner. `OFFER_HEAD` repeats the start of `INDEX_HEAD` (requirements.py:447-455).
The design specified it this way, so this is acceptable.

### F4 (nit, no AC): `_format_requirements(self, plan, section: Any)`

The design gave it one parameter (`plan`). It now takes the `section` callable, typed `Any`.
The two-parameter limit is still met. `Callable[[Checked, str], str]` would be a better
type than `Any`.
