## Blocking defects

### N11. Parallel gates share and wipe one report folder (s159/AC6.2, REQ-153; and every command gate's verdict)
Each story's pipeline gets `reporting=reporting_of(config)` (cli.py:395). That is
`config.run_dir / "reports"`. `Config.at_worktree` keeps `run_dir` at the main checkout
(config.py:305), so every story's gate uses the same folder. `test_reports.run` calls
`_emptied` (test_reports.py:87–96) first, which **deletes the folder**. Then the report
files are numbered from `1.xml` for each build.

Before R1b, gates ran one at a time on the loop, so nothing collided. Now two stories'
gates run in threads at once. When reporting is on:

- Story B's gate starts and deletes the folder while story A's coverage run is writing to
  it. A then reads no report, or a partial one, and its gate holds or bounces with "the test
  command wrote no report".
- Both runs write `reports/1.xml`. A can read B's cases, so A's gate lists B's failures, or
  passes on B's green run.

Fix: give each story's pipeline its own report folder, e.g. `run_dir/reports/<story>`. It
could be built in `Runtime.at` or from `config.repo`'s worktree name. Then test that two
stories' builds get different folders, and that emptying one leaves the other alone.

### T2. No test covers N9, R1b or R3, and the one edited test is now vacuous (s159/AC6.2, AC6.4, AC6.8; REQ-153, REQ-154, REQ-156)
`test_the_story_push_runs_through_in_thread_r1` now stubs `push_off_loop` out. Nothing
calls `system.in_thread` any more, so `assert "after_step" not in calls` holds whatever the

1. two stories' `apply_settled` driven at once, checking that the sprint branch is pushed

2. a PO turn or a second story's task advancing while a gate's run is pending (R1b);
3. `main_lock.locked()` being true while the Manager's settle runs once story branches are

None of these was written. `push_off_loop`, `_open_sprint_branch_off`, `_open_draft_off`,
`settle_lock` and `_pregate` have no direct test. The charter's 100% coverage rule (S1)
fails on exactly these lines.

## Should fix

- **N12. A cancel during the threaded gate leaves a half-settled step** (s159/AC11.2,
  REQ-161). `_run_planned` (dispatch.py:1063–1073) catches `CancelledError` and calls
  `save_interrupted`. Before R1b, `settle` was synchronous, so a cancel could not land inside
  it. Now it can land at `await self._pregate(...)`. By then `_settle_head` has already
  committed, recorded the cost and session, and emitted `STEP_END`, but `_apply` has not
  advanced the story. On resume the step runs again: a second `STEP_END`, and a second
  ledger row for the same step. Meanwhile the gate's thread keeps running. Either shield
  the settle (`asyncio.shield` around head plus gate plus tail) or have the interruption
  record that the step had already settled. Add a test for whichever you choose.

  story steps. The gate's own `GATE_CHORE` still shows, but the commit and quarantine phase
  shows nothing. Wrap the head and tail the same way.

## Copy/paste

The fix adds three sync/async twins in `story_ci.py`: `after_step` and `push_off_loop`,
`_open_sprint_branch` and `_open_sprint_branch_off`, and `_open_draft` and
`_open_draft_off`. Each pair runs the same decision with the call made directly or through
`in_thread`. The only sync caller left is `push_replayed`, at the boundary. Either make that
path async too and delete the sync twins, or have one body take the call runner as an
argument. `_pregate` also repeats `_apply`/`_effects`' routing (`_settled`, the
`HandoffError` check, `MANAGER`, `KIND_EFFECTS`, `STORY_EFFECTS`). Because of that, the
effect is now applied in two places, guarded by `gated is None`. One routing function that
both call would keep the two in step. This finding fits no AC; it breaks the DRY rule.
