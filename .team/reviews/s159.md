## New findings

### T3. The two-story sprint-push test passes without the lock (s159/AC6.4, AC2.17; REQ-154, REQ-148)

`test_two_stories_open_the_sprint_branch_once_n9` gathers two `push_off_loop` calls. Its fake
`in_thread` runs `fn(*args)` and never suspends, and an uncontended `asyncio.Lock` doesn't
suspend either. So the first coroutine runs to the end before the second one starts. The
second then sees `entry.pushed` already set. Delete the `async with
self.runtime.sprint_push_lock:` line in `story_ci._open_sprint_branch_off` and the test still
passes. Round 4 also asked that **both PRs open**, and the test doesn't check that.

Fix: make the fake yield (`await asyncio.sleep(0)` before `return fn(*args)`), so both stories
are inside the sprint push at once. Then assert one sprint push, both story pushes, and
`story.pr` and `other.pr` both set to different numbers.

### T4. Nothing checks that the Manager's settle holds the main lock (s159/AC6.8, AC1.3; REQ-156, REQ-132)

The R3 tests check what `settle_lock` returns. They don't check that `settle_work` uses it.
Delete the `async with self.settle_lock(plan):` in `dispatch.settle_work` and every test still
passes. Round 4 asked for `main_lock.locked()` to be true *while* the Manager's settle runs.
Fix: stub `rt.settle` to record `rt.main_lock.locked()`, run
`settle_work(plan_of(None, role=MANAGER), None)` with `story_branches = True`, and assert
`[True]`. Then the same with a developer plan, asserting `[False]`.
