## Blocking finding

### F1: the e2e test `tests/e2e/test_s154_guard_e2e.py` does not exist (s154/AC1, AC2, AC4; REQ-108, REQ-109)

The design's only e2e item is missing. The unit-tester wrote it, but it was out of the
unit-tester's scope, so the runner quarantined it (`6109dccb`) and then reverted it
(`83e7cec3`). Nothing in HEAD holds it. `git ls-files tests/e2e | grep s154` is empty,
and only a stale `__pycache__/test_s154_guard_e2e…pyc` is left behind. The story's
`## Tooling` section says it exists ("automatic today: tests/e2e/test_s154_guard_e2e.py"),
which is false.

What is now unpinned:

- **AC1's core claim.** A guard hit inside pytest's own `tmp_path` fixture fails on its own,
  and the tests after it in the same worker pass. The unit test only checks the class
  hierarchy (`issubclass(RealOsCall, pytest.fail.Exception)`). That is necessary, but it
  does not show that pytest's `_finalizers` state survives. That claim is the whole bug.
- **AC2's "before any fixture runs".** No test shows that the conftest wiring
  (`pytest_collection_modifyitems` → `mark_refusals`, `pytest_runtest_setup` →
  `refuse_marked` before `watching`) refuses a real collected item, or that the failure
  text is the refusal and not `RealOsCall`. The unit tests drive `refuse_marked` and
  `mark_refusals` on `SimpleNamespace` stubs only.
- AC4 ("tests pin each AC") therefore fails for AC1 and AC2.

Fix: the integration-tester writes `tests/e2e/test_s154_guard_e2e.py` as the design's
E2e checklist says (four files in this order, `-n 1`, junit report read through
`junit.parse`; assert (1) failed with `unit test reached the real OS`, (2) failed with the
`OS_FIXTURE_REFUSED` text and not the `RealOsCall` text, (3) and (4) passed, and no
detail holds `_finalizers`). Correct the story's Tooling line if the path changes.
