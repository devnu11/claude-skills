# Review: s112, An Activity tab, Markdown in every message, and a live panel (redesign, round 0)

Reviewed after the t68 redesign: 2afb45a (design and docs), 9828401 (static
tests), a982c9c (code), cbd6ebd (unit-tester gate fix), a14f511
(integration-tester gate fix). The runner's gate passes (99.53%, lint
clean). That coverage is **Python only**. The node e2e file is the only
thing that runs the page's JavaScript.

**Verdict: changes requested (integration-tester).** The code follows the
redesign closely, and I found no blocking code defect. The first review's
B2 (docs) is closed: protocol.md, architecture.md and customer/dashboard.md
were updated in 2afb45a. But most of the redesign's new behaviour has no
behavioural test. The design's test checklist names each of these items,
and only static "the function exists" checks cover them. The budget pill in
particular is new arithmetic and formatting with a loop guard, and nothing
runs it.

## Blocking

### B1. Checklist items with no behavioural test: integration-tester

`tests/test_s112_activity_page.py` checks only that names and strings exist.
`tests/e2e/test_s112_activity_page_e2e.py` doesn't cover these checklist
items:

- **HS1** `statePill`: `live · running` with `tone-accent` inside
  `class="live"`; `connecting · running` with `tone-warning`; exactly one
  state pill in `statusPills` and no `pill smart`. The only coverage is
  s74's `"· stopped" in row`.
- **HS2** `managerFlag`: two reasons give exactly one `⚑ manager due` pill
  whose `title` holds both reasons (escaped); none gives no flag.
- **HS3** `budgetPill`, `budgetTitle`, `checkPcts`, `fmt.dollars`: spent
  608.05 of 1500 with `manager_every_pct` 25 gives `$608`,
  `of $1,500 · 41%`, three `budget-tick`s at 25/50/75%, and a title holding
  `$608.05 of $1500.00` and `25%, 50%, 75%`. `checkPcts(0)` must be `[]`.
  That guard is what stops the infinite loop the old `renderMeter` had, and
  nothing runs it.
- **HS4** the `statusPills` order: state, flag, budget, questions, then the
  notice.
- **HD2** `#task.title === view.run.task` after `renderHeader`/`renderGoal`
  (static only).
- **LP2**: `eventPanel` with a `null` heartbeat should give `line: ""`. The
  s74 test checks only `who`. `chorePanel`: with a chore and no stage,
  `who: "⚙ runner"` and `line` is `chore.what`. Neither is tested.
- **LP3** `runLabel`: `round 2` for `rounds: 2`; `↻ restarted` after an
  interrupted step-end of the same role and story. The current test accepts
  any of the three labels by regex, so it pins nothing.
- **LP4** `toolLine`: an open call gives its label and age; no call but
  `step.tool` gives the tool name; neither gives `no tool running`.
- **LP5** `runnerResult`: a `boundary` event reads
  `sprint 10 end · sync: pass · …`; with no runner event it is `""`.
  `stageAwake` (now shared with `stageRunningLine`) isn't tested directly.
- **LP7** `pillDetails` for a step: its first line holds `/min` and
  `last turn`.
- **RD1/AC5**: the e2e `RD1` table has only the five `lp-*`/`md-notice`
  rows. `.brand small`, `.task`, `.budget`, `.budget small` and `.pill.flag`
  are missing. The static test checks size and colour for four of them, but
  not `.pill.flag`, and the colour pairs are measured only by accident of
  other rows. Add all ten design rows, with `.pill.flag` measured against
  `--surface-2` (the design's "on" column).

## Minor findings (not blocking)

- **m1. Markup names differ from HD1.** HD1 says `class="lp-head"` and
  `data-live-details`. The code uses `.lp-top` and `data-live-tip`. HD1's
  own test rule ("`live-details` appears nowhere in the page") contradicts
  the HD1 markup, so the rename is a sensible fix. The design text should
  say so, though (architect, cheap). Otherwise the next reader will "fix" it
  back.
- **m2. `firstLine` was merged.** The old timeline `const firstLine`
  returned the raw first line. The new function returns the first
  *non-blank* line, trimmed. That changes the gate-reason suffix (line
  ~2635) and the hold labels (line ~2723) for reasons that start with a
  blank line or whitespace. It's an improvement and good DRY, but the design
  doesn't mention it and no test pins it.
- **m3. Copy/paste.**
  `budget ? Math.min(100, (100 * spent) / budget) : 0` appears in both
  `budgetPill` and `budgetTitle`. One `budgetPct(view, spent)` would remove
  the duplicate. `view.stories.find((s) => s.id === …)` is repeated in
  `roundLabel` and `eventPanel` (a small `storyOf(view, id)` would do).
- **m4.** `renderHeader` changed but still has no doc comment. The design
  asks for one on each new or changed function.
- **m5.** `stagePanel` reads `"sprint " + view.run.sprint`. With no
  sprint, that shows `sprint 0`/`sprint null`, while the brand row says
  `backlog`.
- **m6. Stale test text.**
  `test_activity_is_its_own_tab_and_meter_sits_in_the_status_bar` (and its
  docstring's "BM1") names the meter, which this design removed. The AC3
  test calls `statusPills(view2, 0)` with the dropped `now` argument. That's
  harmless, but it's stale.
