# Review: s151, round 0 (slice 2: the DevOps conflict path)

Scope: the slice-2 code in `3daca0de` (`boundary_runner.py`, `handover.py`,
`po_tools.py`) and the test fixups after it (`9118810d`, `ce3fa432`,
`667c6ed7`). AC1 to AC5 (R1 to R12) and slice 1 (s153) were reviewed in
their own steps. The runner's coverage run is green (99.70%).

Verdict: **changes requested**. There are two code defects (D1, D2) and one
missing role-file deliverable (D3, AC6.5).

## Defects

### D1 (s151/AC6.4, REQ-086): a crashed DevOps step crashes the runner

`BoundaryRunner._keep_rebase_fix` reads `report["status"]` and
`report["summary"]`. A step that crashes reaches `after_fix` through
`router._error_report` (router.py:192), which builds
`{"status": "error", "role": …, "reason": …}`. That dict has no
`summary`, so `after_fix` raises `KeyError` outside the router's
`try` (router.py:328-332), and the runner dies. The design's R15 text says
`report["summary"]`, but R17 expects `notes` to be "DevOps's summary, or
`none`", so a missing summary is an expected case. The shared candidate
patch used `report.get(...)`. The expected behaviour: a crashed or
handoff-less DevOps step stores status `error` and empty notes, and the
next `rebase` step holds `rebase_conflict` with `FIX_NOT_DONE` and notes
`none`.

**Fix (developer):** read both keys with `.get(…, "")`. **Test
(unit-tester):** `after_fix({"status": "error", "role": "devops",
"reason": "boom"})` on a conflicted boundary keeps a `RebaseFix`, and the
next step holds `rebase_conflict` with notes `none`. No test covers this
today.

### D2 (s151/AC6.3, REQ-085): `TEAM_MOVED` loops forever

`_move_to_fix` calls `remote.adopt`. When the team HEAD moved during the
DevOps step, `adopt` raises `UpstreamError` and the boundary holds `error`.
That much matches R16. But `b.rebase_fix` stays set, and `continue_boundary`
clears `rebase_fix` only at a `rebase_conflict` hold (po_tools.py:422). So
every `continue_boundary` runs `_adopt` again. Each time it runs the scratch
refusal checks and **the full checks** in the worktree, then raises
`TEAM_MOVED` again, because `sync_from` is still the old head. The boundary
cannot move on, and every retry pays for a full-check run. R17 also promises
that "if the human rebased the team branch by hand meanwhile, the rebase is
`current` or `rebased` as today". That is the most likely way HEAD moves,
and it is exactly the case that gets stuck.

`test_s151_devops_conflict_ac6_3_a_moved_team_branch_holds_error_and_resets_nothing`
stops at the first hold, so it does not show the loop.

**Fix:** the design leaves this open, so the developer needs the
architect's or the PO's ruling. Two options:

- On `TEAM_MOVED`, hold `rebase_conflict` with the reason. Its
  `continue_boundary` already clears `rebase_fix` and reruns the rebase.
- Clear `rebase_fix` and unpin `sync_from` before the `error` hold.

Either needs a test that a `continue_boundary` after a moved HEAD reruns the
rebase from the new HEAD, without adopting again. A cheaper related fix: call
the `HEAD == sync_from` check before the full checks, not after.

### D3 (s151/AC6.5, REQ-087; design R19): the built-in role files lack the AC6 texts

- `agile_team/roles/devops.md` "Boundary fixes" (lines 90-102) still lists
  only "Checks failed on the team branch". The design's paragraph ("The
  sprint-end rebase stopped on a conflict: you own it…", with the flow's
  order) is missing. AC6.5 requires it. `.team/roles/devops.md` already has
  it (lines 16-28, the liaison's part), so a DevOps role run from the
  built-in file alone would not know it owns these conflicts.
- `agile_team/roles/product-owner.md` has no `rebase_conflict` hold entry.
  R19 requires: "DevOps could not settle the sprint-end rebase; the
  liaison has the conflict, DevOps's notes and the scratch branch.
  `continue_boundary(note)` runs the rebase and DevOps again with your
  note." The R19 addition under `ci_failed` (the liaison already got the
  failing checks) is also missing. Lines 122-123 cover only the legacy
  `sync conflict`.

The design's slice-2 table lists both files. The implement commit didn't
touch them. **Fix:** developer. The design suggests a unit test that
`roles/devops.md` names the sprint-end rebase conflict. None exists.
