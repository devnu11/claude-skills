# Review s53, round 1: PO story admin (hold, release, request_cancel)

Diff: `3e0891a..c178e40` (feat c9e8830 plus four fixups). Coverage 99.52%, ruff clean (runner).
Design: `agile-team/docs/design/s53.md` (H1–H14).

**Verdict: changes requested.** The Python rules (H1–H13) match the design closely and are well
tested. But two parts of the design that customers see are missing: the page (`index.html`) and
the PO role file (AC6). The three `Tools` entry points also have no tests.

## Defects (block)

- **D1. `dashboard/index.html` is untouched (AC1, AC3, H4, H13; design § index.html).**
  - Line 1856 still renders `` `⏸ ${s.wait.reason}` ``, so a PO hold reads `⏸ PO hold` with no reason. AC1 requires `⏸ PO hold: <reason>`. The snapshot already carries `wait.title`, but the page never reads it.
  - `WAIT_TONE` (l.354) has no `"PO hold"` or `"cancel requested"`. They fall back to "warning", so a cancel request isn't shown as "serious".
  - `LABEL_TONE` (l.1412) lacks `"cancel requested"`.
  - `backlogGroups` has no `cancelled` group, and the Backlog tab has no read-only Cancelled group (H13, AC3 "Backlog tab labels it cancelled"). Cancelled stories leave the queue, so today they vanish from the tab instead of showing as cancelled.
  - `TIMELINE["story-admin"]` is missing, so the new event has no timeline row.
  - Owner: developer (page).
- **D2. `agile_team/roles/product-owner.md` has no "Story admin" list (AC6; design § roles).**
  - Nothing tells the PO to use `hold_story` instead of a parked `ask_user`, or to use `request_cancel` whenever anyone thinks a story should go.
  - Nothing says "never treat a story as cancelled until a `story-admin` event shows the human's cancel".
  - Line 72 ("a blocked story: `continue_story` refuses it. Run the manager…") is now incomplete: `release_story` is the tool for s4's case.
  - Owner: developer.
- **D3. `Tools.hold_story`, `Tools.release_story` and `Tools.request_cancel` have no tests** (`po_tools.py` lines 390, 394 and 398 are the only misses in the module).
  - Every story_admin test goes through `Clerk` directly. Nothing proves that the MCP methods wrap the right `Act` and return `text_result`. Swapping `Act.HOLD` and `Act.RELEASE` would still pass the suite.
  - Wanted: one test per tool through `Tools(rt).<name>({...})`, decoding the text result, with `status` and `story_status` checked.
  - Owner: unit-tester.

## Minor (don't block)

- **m1.** `test_schemas_rows` (l.418): `assert set(...) == {...} if len(...) > 1 else True` is a conditional expression around the comparison. It always takes the first branch today, but it reads as a guard that could silently pass. Make it a plain assert.
- **m2.** Checklist item 8 (an `ast` walk proving only `story_admin.cancel` assigns `CANCELLED`) moved to e2e under the OS guard (unit-tester note in 0c505b7). This is the code check behind AC3's "no tool argument or role step can do it". `test_no_tool_effect_cancels` covers only the TOOLS effects. Keep it on the integration-tester's P1 list.
- **m3.** `waits._po_kind(s) is HoldKind.CANCEL` and `backlog._cancel_requested` are the same predicate. A `PoHold`/`StoryState` helper (e.g. `holds.kind_of(po_hold)`) would serve both. This is small, so it doesn't block.
- **m4.** `story_admin.unclear`: the `asked.question if asked else ""` branch can't be reached, because `answered()` only yields stories with a CANCEL `po_hold`. Drop the fallback or assert it.
- **m5.** `EventKind.STORY_ADMIN` is the first member of the enum. It would read better appended near the other PO-driven kinds. This is cosmetic.
- **m6.** Edge: the PO can `hold_story` a `NEEDS_MANAGER` story. `release_story` then refuses it (`MANAGER_WAIT` comes before `NOTHING_HELD`), and `_escalated` skips it because of `po_hold`. The way out is `run_role manager` (dispatch doesn't check `po_hold`). That works, but the PO role file (D2) should say so.
- **m7.** `dispatch_refusal` doesn't refuse `run_role` on a PO-held story. The design doesn't ask for it (H3 only covers the router), but it means a hold only stops the router, not the PO. This is worth one line in the role file.
- **Docs** (protocol.md, SKILL.md, README, customer backlog doc) are listed under "Docs at ship (architect)" and are not in this diff. That is expected at this step.
