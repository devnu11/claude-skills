## Required changes (unit-tester)

**D1: AC4 "one event per stage run, with its when and attachment" through the real call sites.**
This is design checklist item 12, the AC's own bullet, and it is missing entirely.
Using fake shell/git and a real `Runtime`, pin at least:
- implement gate → exactly one `gate.tests+coverage` event (`after`, `step`), with `story` and `data.step` set from the request;
- tests gate → `gate.tests-red`; reworked tests gate → one `gate.tests-rework` and **no** `gate.tests-red`;
- quality step → `quality.lint`, `quality.static`, `quality.coverage`, all `before`;
- Customer Proxy step → `env.prepare`; integration-tester step → `presentation.layout`; e2e done → `presentation.trial`;
- router tick → `checkout.guard` with story `null`; settle/gate → `checkout.verify`;
- each boundary stage → its `boundary.*`, `attach` boundary, story `null`;
- `run_tests` with two batches → one `runner-tool.run_tests` (`during`); a refused `run_tests` → none;
- `pass_tests` → `gate.green` with the story set.

**D2: choke points not pinned** (checklist item 13): `sandbox.run_shell` notes `(command, code)`.
`Preparer._serve` notes `(prepare, 0)` on an answer, and `(prepare, NOT_UP)` on `NotUp`, which
must be re-raised. `command_runner` notes 127 for a missing binary.

## Notes (do not block)

- **N1:** `StageLog.place` is shared mutable state, not a ContextVar. It is shared on
  purpose, so that runner-tool calls (served in another task) pick up the step's place.
  But if the PO ever issues two tool calls at the same time (`run_role` with `pass_tests`),
  the places would mix. Nothing in the package runs steps at the same time today. If it
  can happen, it is worth a line in Known limits.
- **m1:** in `gates.Checks`, the field `stages` shadows the module name inside the class
  body. It works because it is the last field and the methods resolve `stages` globally.
  A field added after it that uses `stages.` would break.
- **m2:** `_tools` assumes every `tool` entry is a table. `tool = ["x"]` raises
  `AttributeError`, not `ConfigError`. Same as the existing `_delivery`.
- **m3:** `stages.B/A/D/STEP/STORY/BOUND` are public one-letter module names. `_`-prefixing them would be cleaner.
- Docs (protocol.md, SKILL.md, customer config page) are deferred to "Docs at ship (architect)" in the design. The architect must do them before ship (charter).
