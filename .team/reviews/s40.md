## Defects

**D1 (must fix): a move that changes nothing shows `#undefined → #undefined`.**
P9 emits the event even when `moves` is empty. That happens whenever `move_story` puts a story
at the position it already holds, for example `move_story(s1, 1)` while s1 is already #1.
`priorityLabel` then does `e.data.moves.find(...)`, gets `undefined`, and renders
`#${m?.from} → #${m?.to}`, which reads `#undefined → #undefined` in the timeline.

Fix: when no move is found for `e.story`, fall back to a label such as `#n (unchanged)` or
`order unchanged`. The position can be taken from `e.data.order.indexOf(e.story) + 1`. Add
the chosen fallback string to the page-source test.

## Test gaps

**T1 (should fix): an answered question must not count as a wait.**
Add a snapshot test with an outbox question naming the story and an inbox answer with the same
id. The story should then get `wait` = `None` (or the `held` row only, if it has a hold).
Without this test, a regression in the `answered` filter would go unnoticed: the board would
mark stories as "needs the human" after the human had already answered.

## Copy/paste and DRY

- `_asking` repeats the "open questions" rule that already exists in `relay.open_questions`
  and in the page's `openQuestions`. The snapshot reads raw JSONL rather than going through
  `Relay`, so some repetition is understandable. Note that `_asking` re-reads `inbox.jsonl`
  and `outbox.jsonl` once per story, and `_position` recomputes the queue once per story.
  That makes every snapshot O(stories²), with 2×stories file reads. It is fine at today's
  size, but computing the open questions and the queue once in `_stories` would be both
  simpler and cheaper. This is not blocking.
- No other repeated blocks were found. The two router loops were merged into one
  `_first_ranked`, and `_sprint_refusal` reuses `priority.UNKNOWN`.
