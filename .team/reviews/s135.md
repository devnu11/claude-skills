## Blocking findings

### F1: the E2E file for design items 15–18 is missing (s135/AC6, AC3, AC2; REQ-038, REQ-039). Owner: integration-tester

The design's test checklist names `tests/e2e/test_s135_story_e2e.py`, which
should run with real git:

- 15: `story new` plus one tick shows `docs(s1): created story to …`, the author for each mode, and the `Human-involvement:` line;
- 16: the story survives a real `revert_story`;
- 17: the story survives a review-stack rebuild (`Rebuilder.build`);
- 18: an amend works end to end.

The file does not exist. AC6 says, word for word, "the onboarded story
commit surviving a story revert and a review-stack rebuild with its story".
What tests exist today:

- `test_a_reverted_story_keeps_its_file_commits` and
  `test_story_commits_never_picks_the_file_commit` are pure unit checks on
  `reverted_story` and `story_commits`. No revert actually runs.
- Nothing tests the review stack. O4's claim that "the commit rides in the
  sprint range" holds today (`stack.py` picks with `rev-list`/`log` over a
  span), but no test pins it.
- AC3's `--author` is checked only against the fake git. Nothing proves that
  git accepts `Claude (agile-team liaison) <noreply@anthropic.com>` and
  records it as the author.

### F2: the dashboard part of the design is not implemented (s135/AC2, AC4; REQ-038, REQ-040). Owner: developer

The design's "`dashboard/index.html`" section asks for three changes:

- the `story-opened` row shows `from: "liaison"` when `e.role === "liaison"`;
- a new `story-amended` row, `old ids → new ids`;
- `replayStories` applies `story-amended` (`step: e.data.step, rounds: 0`).

`index.html` is not in the diff. Line 1908 still renders every
`story-opened` as from the PO. A `story-amended` event has no row at all.
After an amend, the replayed board keeps showing the story at its old step.
Every story the runner onboards is mislabelled on the timeline.

### F3: an unreadable amend draft drops the target refusals (s135/AC1, Q3 item 1 and item 6; REQ-037). Owner: developer

Design Q3.1 says: "If it isn't [readable], items 2 to 4 are skipped and
items 5 and 6 still run." The item 6 target checks are "unknown target" and
"finished target". They live in `story_drafts._target_problems`, which runs
only inside `draft_problems`. When the draft can't be read,
`cli._story_checks` skips `draft_problems` completely
(`Checked(None, (unread,)) if unread else …`). So
`agile-team story amend s999 missing.md --approved-by none` prints only
`cannot read …`, and `no story 's999'` is missing. AC1 asks for "every
reason". Fix: split the target-status lines (unknown, finished) out of
`_target_problems` so they run with the option checks. Add a test next to
`test_an_unreadable_file_gives_its_line_plus_the_option_lines`, using
`amend`.

  `PLACE_REASON.format(id=…)` three times. `_place` could call
  `_reorder_backlog`'s builder with the placing. Low.

  is built in `cli._story_known`, `Intake._known` and
  `Intake._filed_problems`. Reading the target story file is duplicated
  between `cli._story_known` and `Intake._text_of`. Low; a `Known.of(config, state, story)`
  constructor would remove both.
