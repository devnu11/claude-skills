**D1 (s56/AC1, REQ-048), must fix: the test bypasses the unit-test OS guard.**
`tests/os_guard.py` (s71, ADR-011) fails a unit test that reads a real file
("inject it, or move the test to tests/e2e/"). It exempts audited calls made
inside `traceback`/`linecache` only so that the stdlib can render tracebacks
(s89). `script_tree` calls `linecache.getlines` for exactly that reason. Its
docstring says so: "(the guard allows that)". That turns a stdlib exemption
into a back door around a rule the charter says is enforced in code.

The workaround also hides failures. `linecache.getlines` returns `[]` for a
missing or unreadable file. `ast.parse("")` then gives an empty module, so
`test_fixture_script_has_no_top_level_code` **passes vacuously** if the script
is moved or renamed. Only the guard test's `body[-1]` IndexError would catch
that. `linecache` also caches by path, so the test could see stale source
within a session.

Fix (unit-tester), using either of the two routes the repo already uses:
- read through the injected seam, as `test_s73_boundary_once.py:156` does
  (`system.read_text(PROTOCOL)`); or
- move the two script-reading tests (`test_fixture_script_has_no_top_level_code`,
  `test_fixture_script_guard_calls_main`) to `tests/e2e/` and use
  `SCRIPT.read_text()`, next to `test_dashboard_fixture_e2e.py`. The pure
  `stray_statements` tests and the role-body test stay in the unit file.

Whichever route is taken, the script test must fail if the file is missing
(e.g. assert that the parsed body is non-empty, or let the read raise). Drop
`import linecache`. If the story file's Tooling line names the test path, it
must still be right after the move. No assertion changes.

The new test module itself conforms to the rule. Its top level holds a
docstring, imports, constants, functions and a decorated test.
