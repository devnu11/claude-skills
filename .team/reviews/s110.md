## Findings (minor, do not block)

- **m1.** The ci_failed test slices a fixed 900-character window
  (`text[start : start + 900]`) rather than up to the next bullet
  (`**ci_pending**`). Today the three phrases only occur in the ci_failed
  bullet, so the test is correct, but a phrase moved into a later bullet
  within 900 chars would still pass. Slicing to `text.index("**ci_pending**")`
  would pin it exactly. Tidy at next touch.
- **m2.** `SKILL_DIR` is computed twice (fake_system and the test) by
  different routes. Small duplication; the test could import it from
  `fake_system`.
- **m3.** protocol.md puts the full rule in its own paragraph right after
  **Ready.** rather than inside it (CR3 wording). The pointers say "under
  **Ready.**", which is true; acceptable.

## Known limit (carried from design)

The rule is prompt-only: the runner does not refuse `continue_boundary` at a
`ci_failed` hold whose lines show our code ran. The charter prefers process
enforced in code; the design raises this as an open question for a follow-up
story. Not a defect of this story, whose ACs are about the role file and docs.
