## Notes

- **N1 (docs accuracy, minor):** `customer/dashboard.md` says that while the
  file "is half-saved … the page keeps showing the settings from when the
  dashboard started". That is only true when the half-saved file fails to
  parse. An empty or truncated file that still parses (for example `""`, or
  only the `[team]` table) loads with defaults, so for one push the page can
  show the default budget. The next write fixes it, and the design's F5 only
  promises a fallback for missing or unparsable files. No change is needed
  now. A future story could say "missing or not valid TOML".
- **N2 (process):** commit `2bfb897` added an assertion "so the file differs
  from the committed version". The assertion itself is valid (`fresh is not
  config`). But writing a test change to satisfy the dispute gate's
  `git diff` check rather than for coverage is a smell, and the Manager
  should look at it (s11 dispute settle rule).
- The new JS functions (`renderUnit`, `costRow`, `tokenLegend`,
  `costLegend`) have no doc comments, unlike `barRows`. That matches most of
  the surrounding script, so it is not blocking.
